# 07. 高级特性

> 本章涵盖 Subtree、LinkedAsset、Utility Selection、ScheduledTick、Run Parallel Task 等高级特性。

## 一、Subtree 与 Linked State

### Subtree 是什么

Subtree 是 StateTree 内部可被复用的子树。本质上是一种特殊的"State"，类型为 `Subtree`。

**用途**：
- 同一个 StateTree 内复用某段逻辑
- 把复杂状态拆分成更小的、可命名的子树
- 让 StateTree 编辑器更清爽

### 创建 Subtree

```
1. 在 StateTree 编辑器右键 → Add Subtree
2. 给它取个名字（比如 "Combat_Subtree"）
3. 在 Subtree 内部正常构建状态
```

### 使用 Linked State

要用 Subtree，需要在某个普通 State 上：
1. 把 Type 改为 `Linked`
2. Linked Subtree 选 `Combat_Subtree`
3. Subtree 的参数会出现在 Linked State 的 Parameters 中

```
Root
├── PeacefulBranch
└── DangerBranch (Linked → Combat_Subtree)
     └── Parameters:
         └── EnemyDistance = 500

Subtree: Combat_Subtree
├── Parameters:
│   └── EnemyDistance (float)
├── Approach
├── Attack
└── Retreat
```

执行时，DangerBranch 表现得就像 Combat_Subtree 一样，但参数是 DangerBranch 提供的。

### 数据流

```
Linked State (传入参数)
        │
        ▼
   Subtree (用参数运行)
        │
        ▼
   各个 Task 通过 Binding 读取参数
```

## 二、Linked Asset（外部链接）

### 与 Linked State 的区别

| 特性 | Linked State | Linked Asset |
|------|--------------|--------------|
| 引用对象 | 同一资产内的 Subtree | 另一个 StateTree 资产 |
| 跨资产复用 | 否 | ✅ |
| 适合场景 | 资产内部复用 | 跨多个 AI 共享行为 |
| Schema 兼容性 | 自动一致 | 需要兼容（否则编译失败）|

### 创建 Linked Asset State

```
1. 添加普通 State
2. Type 改为 Linked Asset
3. Linked StateTree 选另一个 .uasset
4. 参数自动列出，可填值
```

### 历史 Bug 警告

**5.4 及之前**：Linked Asset 中的 Tasks 有时会忽略 `bShouldStateChangeOnReselect`，需要手动重新编译子树才生效。

**5.5+**：大幅修复。如果你还在用 5.4 或更早，参考社区的 workaround：

```cpp
// 在 Task 的基类中手动检查
EStateTreeRunStatus EnterState(...) const override
{
    if (!bShouldStateChangeOnReselect 
        && Transition.ChangeType == EStateTreeStateChangeType::Sustained)
    {
        // 已知 bug，手动跳过
        return EStateTreeRunStatus::Running;
    }
    // ... 正常逻辑
}
```

### Linked Asset 的层级嵌套

每个 Linked Asset 会创建一个新的 **Frame**（`FStateTreeExecutionFrame`）。激活链的 8 状态限制是**单 Frame 内**的，所以 Linked Asset 可以无限嵌套（理论上）。

## 三、Utility Selection（5.5+）

### 什么是 Utility Selection

传统状态选择是基于"顺序 + Enter Condition"的硬选择。Utility Selection 引入"打分"机制：每个候选状态算一个 Utility Score，选最高分的（或加权随机）。

类似 GOAP 或一些游戏 AI 的"效用系统"。

### 选择行为枚举

源码：
```cpp
UENUM()
enum class EStateTreeStateSelectionBehavior : uint8
{
    None,
    TryEnterState,
    TrySelectChildrenInOrder,                       // 默认
    TrySelectChildrenAtRandom,
    TrySelectChildrenWithHighestUtility,            // ⭐ Utility 模式 1
    TrySelectChildrenAtRandomWeightedByUtility,     // ⭐ Utility 模式 2
    TryFollowTransitions,
};
```

### 配置 Utility

每个 State 可以挂一组 **Utility Considerations**（考量），每个 Consideration 输出一个 [0,1] 范围的分数，最终通过表达式（And/Or/Multiply）组合成总分。

```
State: Fight
└── Utility Considerations:
    ├── EnemyClose       (距离越近分越高)
    ├── HasWeapon        (有武器则高)
    └── HighHealth       (生命值越高越愿意打)

State: Flee
└── Utility Considerations:
    ├── EnemyVeryClose   (距离越近分越高 → 想跑)
    └── LowHealth        (生命值越低越想跑)

ParentState
├── Selection Behavior: TrySelectChildrenWithHighestUtility
├── Fight (utility 算出 0.4)
└── Flee  (utility 算出 0.7) ← 选这个
```

### Consideration 的 C++ 实现

```cpp
USTRUCT()
struct FSTConsider_Distance : public FStateTreeConsiderationCommonBase
{
    GENERATED_BODY()

    using FInstanceDataType = FConsiderDistanceData;

    virtual float GetScore(FStateTreeExecutionContext& Context) const override
    {
        const FInstanceDataType& Data = Context.GetInstanceData(*this);
        const float Dist = (Data.A->GetActorLocation() - Data.B->GetActorLocation()).Size();
        return FMath::Clamp(1.0f - Dist / Data.MaxDistance, 0.0f, 1.0f);
    }
};
```

### 使用 Curve 调整分数

Consideration 可以挂一个 Float Curve 把原始 [0,1] 映射成最终分数，实现非线性曲线（比如"距离接近 30% 时威胁感最大"）。

### Utility Selection 的优势

- **自动决策**：不需要手写 if-else
- **平滑过渡**：随着输入变化分数渐变
- **可调性**：策划改 Curve，不需要改代码

### 何时用 Utility？

- 需要"软决策"的 AI 行为
- 多个候选行为需要根据环境动态选择
- 想做 GOAP 风格的智能 AI

## 四、Run Parallel Task（5.5+）

### 问题背景

之前提到，StateTree 的"并行"是同状态内多 Task 并行，但有限制（任一完成就触发 Transition）。如果想要**真正独立的并行行为**怎么办？

### Run Parallel StateTree Task

5.5+ 引入 `FStateTreeRunParallelStateTreeTask`：在某个 Task 上运行**另一个完整的 StateTree**，与主树并行。

```cpp
// 内置 Task：FStateTreeRunParallelStateTreeTask
// 作为 Task 添加到任何 State 上

UPROPERTY(EditAnywhere, Category = "Parameter")
TObjectPtr<UStateTree> StateTreeAsset;  // 要并行运行的子树
```

### 行为

```
主 StateTree
└── State X
    ├── Task: RunParallelStateTree (StateTreeAsset = SubBehavior)
    │   ↓
    │   完全独立的 SubBehavior 在后台跑
    │   不会阻塞主树
    │
    └── 其他 Task (主树继续选择子状态、过渡)

Sub Behavior (并行运行)
├── Wander
├── Look Around
└── Sit Idle
```

### 用途

- AI 一边追敌人一边播放语音
- 主行为 + 装饰性副行为
- 多个独立的子模块组合

### 注意事项

- Sub StateTree 不能让主树过渡（独立的）
- 主 State 退出时，Sub StateTree 也会停止
- 性能开销 = 主 + 子，要权衡

## 五、ScheduledTick（5.5+）

### 背景

默认 StateTree 每帧 Tick。但很多状态其实不需要每帧检查 —— 等事件就行了。

### 启用方式

源码注释：
```cpp
/** 
 * If true, the StateTree allows scheduled tick.
 * The next tick will be calculated based on the active states and tasks.
 */
bool bAllowScheduledTick;
```

### 工作原理

源码 `GetNextScheduledTick` 函数返回三种状态：

```cpp
struct FStateTreeScheduledTick
{
    static FStateTreeScheduledTick MakeEveryFrames(...);  // 每帧
    static FStateTreeScheduledTick MakeNextFrame();        // 下一帧
    static FStateTreeScheduledTick MakeSleep();             // 睡眠（直到事件）
    static FStateTreeScheduledTick MakeCustom(float Time);  // 指定秒数后
};
```

### 决定 Tick 频率的因素

```
ScheduleNextTick 决策树：
  if Tree已停止: → Sleep
  elif 任何 Task: bShouldCallTick = true && bConsideredForScheduling = true:
       → EveryFrame（最高频率）
  elif 任何 Transition: 类型是 OnTick:
       → EveryFrame（OnTick 必须每帧检查）
  elif 任何 State 设置了 CustomTickRate:
       → 按那个频率 Tick
  elif 在等 Event/Delegate:
       → Sleep（事件来了才唤醒）
  else:
       → Sleep
```

### 自定义 Tick Rate

每个 State 可以设置自己的 `CustomTickRate`（秒）：

```
Patrol State
├── CustomTickRate = 0.5  (每 0.5 秒 Tick 一次)
├── Task: PatrolMove
└── Task: ScanEnvironment
```

适合**不需要高频反应**的状态，比如静态巡逻、远程感知等。

### 性能影响

- 普通 AI：30%-70% Tick 时间节省
- 静态/不活跃 AI：90%+ 节省
- 大规模 AI 场景：可能从不可玩变流畅

## 六、Multi-Frame（多帧）

### Frame 是什么

`FStateTreeExecutionFrame` 是 StateTree 内部表示"一段独立 StateTree 执行栈"的结构。一个 Frame 对应一段：
- 一棵 StateTree 资产
- 一条激活状态链

正常情况下只有一个 Frame（主 StateTree）。**Linked Asset** 会创建额外 Frame：

```
ActiveFrames:
├── Frame 0: Main StateTree
│   └── ActiveStates: [Root, A, B]
│       └── B 是 Linked Asset → 跳到 Frame 1
│
└── Frame 1: Sub StateTree (linked asset)
    └── ActiveStates: [SubRoot, X, Y]
```

### 跨 Frame 行为

- ExitState 顺序：从最后 frame 的叶子，依次到 frame 0 的根
- EnterState 顺序：相反
- Transition 评估：先评估当前 frame，向上冒泡
- 各 Frame 有独立的 InstanceData 区域

## 七、Async Execution Context

异步任务（如等待网络响应、加载资源）需要在 Tick 之外完成 Task。

### 使用 FStateTreeWeakExecutionContext

```cpp
class FMyAsyncTask : public FStateTreeTaskCommonBase
{
    EStateTreeRunStatus EnterState(FStateTreeExecutionContext& Context, ...) const override
    {
        // 保存弱引用
        FStateTreeWeakExecutionContext WeakContext = Context.MakeWeakExecutionContext();

        AsyncOperation([WeakContext, this]()
        {
            // 异步完成时
            FStateTreeStrongExecutionContext StrongContext = WeakContext.MakeStrongExecutionContext();
            if (StrongContext.IsValid())
            {
                StrongContext.FinishTask(*this, EStateTreeFinishTaskType::Succeeded);
            }
        });

        return EStateTreeRunStatus::Running;
    }
};
```

源码：`StateTreeAsyncExecutionContext.h`

### Strong vs Weak Context

- **Weak**：保存对 Owner 和 InstanceData 的弱引用，不会延长它们的生命周期
- **Strong**：从 Weak 转换而来，保证在使用期间 Context 有效

异步操作必须用这套机制，不能直接保存 `FStateTreeExecutionContext&`（它的生命周期只在 Tick 内）。

## 八、Multiple StateTrees on Same Owner

一个 Actor 可以挂多个 StateTreeComponent，跑不同的 StateTree：

```
MyAIPawn
├── Component: StateTreeAIComponent (主行为)
│   └── ST_Combat
├── Component: StateTreeComponent (附加行为)
│   └── ST_Dialogue
└── Component: StateTreeComponent (动画驱动)
    └── ST_Animation
```

### 通信方式

- **Events**：跨 StateTree 发送（通过 SharedEventQueue）
- **PropertyRef**：共享 Parameters
- **Delegates**：监听对方的 Event Bus

源码：
```cpp
FStateTreeStartParameters StartParams;
StartParams.SharedEventQueue = SharedQueue;  // 多个 StateTree 共享事件队列
ExecutionContext.Start(StartParams);
```

## 九、StateTree 与 Mass Framework

Mass 是 UE5 的 ECS 风格大规模实体系统。StateTree 是 Mass 实体的主要 AI 行为框架。

### 使用差异

- Schema：用 `FMassStateTreeSchema`
- Task 基类：用 `FMassStateTreeTaskBase`
- 数据访问：通过 Mass Fragment 而不是 Actor Component
- 生命周期：批量执行，不是单个 Tick

### 推荐资料

如果你做大规模 AI（NPC 城市人群、僵尸潮等），推荐看官方 Sample：
- `MatrixAwakens` 的 City Sample
- Lyra Game Sample

## 十一、StateTree Debugger

### 启用

打开 StateTree 资产 → 工具栏 → "Debug" 按钮

### 功能

- **Active States 可视化**：实时高亮当前激活链
- **Transition 历史**：每次 Transition 触发的源、目标、时刻
- **Task 状态**：每个 Task 的 Status（Running / Succeeded / Failed）
- **Event Queue**：当前队列中的事件
- **Bindings 数值**：每个绑定属性的实时值
- **Trace Recording**：录制完整运行轨迹，可回放

### 控制台变量（功能开关，非调试）

5.7 源码中只有 5 个 StateTree 相关 CVar，都是用于版本迁移的功能切换，不是调试开关：

```
StateTree.CopyBoundPropertiesOnNonTickedTask 0/1
StateTree.TickGlobalNodesFollowingTreeHierarchy 0/1
StateTree.GlobalTasksCompleteOwningFrame 0/1
StateTree.SetDeprecatedTransitionResultProperties 0/1
StateTree.TargetStateRequiresTheSameEventForStateSelectionAsTheRequestedTransition 0/1
```

**真正的调试方法**：
- 开启详细日志：`log LogStateTree Verbose`
- StateTree Trace（Unreal Insights）：启动参数加 `-trace=default,statetreedebug`
- StateTree Debugger：资产编辑器内 Debug 按钮

## 十二、自定义 Schema

如果默认 Schema 不满足需求（比如你的项目有特殊的 Context 数据），可以自定义：

```cpp
UCLASS()
class UMyStateTreeSchema : public UStateTreeSchema
{
    GENERATED_BODY()

public:
    virtual TConstArrayView<FStateTreeExternalDataDesc> GetContextDataDescs() const override
    {
        return ContextDataDescs;
    }

    // 限制可用的 Task 基类
    virtual bool IsStructAllowed(const UScriptStruct* InScriptStruct) const override
    {
        return InScriptStruct->IsChildOf(FMyTaskBase::StaticStruct());
    }

private:
    UPROPERTY()
    TArray<FStateTreeExternalDataDesc> ContextDataDescs;
};
```

让你的 StateTree 资产强制只能用某些 Task，且自动提供特定 Context。

## 十三、序列化与版本兼容

StateTree 资产是序列化的 USTRUCT 树，引擎会做编译期的优化（变成 `FCompactState...`）。

### 资产升级

UE 升级版本时：
- StateTree 资产可能需要重新编译（点 Asset Editor 的 Compile）
- 删除/重命名 Property 会丢失绑定
- 删除/重命名 State 会丢失 Transition 目标

### 最佳实践

- 项目早期定型 Schema 和 Task 接口
- 用 `meta = (DeprecatedProperty)` 标记弃用字段而不是直接删
- 大改时用 Linked Asset 拆分，降低单文件复杂度

## 十四、性能调优清单

1. **使用 ScheduledTick**：让不需要每帧 Tick 的状态睡眠
2. **关闭不需要的 Tick**：`bShouldCallTick = false`
3. **关闭不需要的 Property Copy**：`bShouldCopyBoundPropertiesOnTick = false`
4. **拆分 StateTree**：复杂 StateTree 用 Linked Asset 拆分，便于裁剪
5. **避免昂贵 Condition**：On Tick 的 Condition 每帧执行，避免 LineTrace、容器遍历
6. **批量 AI 用 Mass**：超过 100 个 AI 强烈建议迁移到 Mass + StateTree
7. **用 Stat 命令分析**：`stat StateTree`、`stat statetree_async`
