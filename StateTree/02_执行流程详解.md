# 02. 执行流程详解（含源码）

> 本章基于 UE5.7 源码 `StateTreeExecutionContext.cpp`（约 8400 行）逐步讲解。
> 关键文件路径：`E:\UnrealEngine\Engine\Plugins\Runtime\StateTree\Source\StateTreeModule\Private\StateTreeExecutionContext.cpp`

## 一、整体生命周期

```
StateTreeComponent::BeginPlay
    │
    ▼
ExecutionContext::Start()
    │
    ├─ 初始化 InstanceData
    ├─ 启动 Global Tasks / Evaluators (TreeStart)
    ├─ Tick 一次 Global Evaluators
    ├─ SelectState(Root)              ← 状态选择
    └─ EnterState(选中的链)            ← 进入状态
    │
    ▼
每帧（直到停止）：
ExecutionContext::Tick(DeltaTime)
    │
    ├─ Phase 1: TickUpdateTasks         ← 更新所有活动 Task
    ├─ Phase 2: TriggerTransitions      ← Task 主动触发的过渡（少见）
    ├─ Phase 3: ApplyTransitions        ← 评估并应用 Transition
    │           （含 Tick / Event / Completion 三类）
    │           最多迭代 5 次（MaxIterations）
    └─ ScheduleNextTick                  ← 计算下一帧 Tick 频率
    │
    ▼
ExecutionContext::Stop()
    │
    ├─ ExitState（叶子→根的顺序）
    ├─ 停止 Global Tasks (TreeStop)
    └─ 清理 InstanceData
```

## 二、状态选择流程（State Selection）

### 入口：`SelectState`

源码位置：`StateTreeExecutionContext.cpp` 的 `SelectState` 函数及其辅助函数。

### 核心算法（深度优先，找到第一个可进入的叶子）

```
SelectState(从某个状态开始):
  1. 检查当前状态的 Enter Condition
     - 失败 → 返回失败，让父尝试下一个兄弟
     - 通过 → 继续

  2. 如果当前状态是叶子（无子状态）：
     → 选中它！返回成功

  3. 如果当前状态有子状态：
     根据 SelectionBehavior 决定如何处理：
       • TrySelectChildrenInOrder    : 按顺序遍历子状态（默认）
       • TrySelectChildrenAtRandom   : 随机遍历
       • TrySelectChildrenWithHighestUtility   : 按 Utility 分数
       • TrySelectChildrenAtRandomWeightedByUtility : 加权随机
       • TryEnterState               : 即使有子状态也直接选中此状态（5.3+）
       • TryFollowTransitions        : 不选中状态，转而尝试 Transition
       • None                        : 不能直接选中

  4. 对每个子状态递归调用 SelectState
     第一个成功返回的子状态决定了选中链
     全部失败 → 当前状态选择失败
```

### 关键源码：状态选择行为枚举

```cpp
// StateTreeTypes.h
UENUM()
enum class EStateTreeStateSelectionBehavior : uint8
{
    None,                                       // 不可被选中
    TryEnterState,                              // 即使有子，直接选中
    TrySelectChildrenInOrder,                   // 按顺序选子（默认）
    TrySelectChildrenAtRandom,                  // 随机选子
    TrySelectChildrenWithHighestUtility,        // 选 Utility 最高的子
    TrySelectChildrenAtRandomWeightedByUtility, // 按 Utility 加权随机
    TryFollowTransitions,                       // 不选自己，跟随 Transition
};
```

### 完成后做了什么

选中链 `[A, B, C]` 后（C 为叶子）：

```
1. UpdateInstanceData         ← 分配每个 Task 的实例数据
2. CaptureNewStateEvents       ← 捕获选择时附带的事件
3. EnterState(链)              ← 调用每个 Task 的 EnterState
   顺序：A → B → C（从根到叶）
```

### 关于"中间状态不能直接被选中"

这是一个**默认行为**，原话来自源码注释和官方文档：

> "By default, StateTree will only ever transition to a valid leaf state and never stop at an intermediate state in the tree."

如果你想让中间状态可以被选中（比如它有 Tasks 但没有合适的子），用 `TryEnterState` Selection Behavior。

## 三、Tick 流程（核心！）

### Tick 的三个阶段

源码 `FStateTreeExecutionContext::TickPrelude` + `Tick` + 各种内部函数构成完整流程：

```cpp
// 简化伪代码（基于源码）
EStateTreeRunStatus FStateTreeExecutionContext::Tick(float DeltaTime)
{
    // === Phase 1: 数据更新 + Task Tick ===
    SetUpdatePhaseInExecutionState(Exec, EStateTreeUpdatePhase::TickStateTree);

    // 1.1 Tick Global Evaluators 和 Global Tasks
    TickGlobalEvaluators(DeltaTime);
    TickGlobalTasks(DeltaTime);

    // 1.2 Tick 所有活动状态的 Tasks（从根到叶顺序）
    for (frame in Exec.ActiveFrames)
        for (state in frame.ActiveStates)  // [A, B, C]
            for (task in state.Tasks)
                if (task.bShouldCallTick || (task.bShouldCallTickOnlyOnEvents && hasEvents))
                {
                    if (task.bShouldCopyBoundPropertiesOnTick)
                        CopyBindings(task);
                    EStateTreeRunStatus Status = task.Tick(*this, DeltaTime);
                    UpdateTaskCompletion(task, Status);
                }

    // === Phase 2: TriggerTransitions（少见，仅 bShouldAffectTransitions=true 的 Task） ===
    for (task in 所有活动Task)
        if (task.bShouldAffectTransitions)
            task.TriggerTransitions(*this);  // 主动调用 RequestTransition

    // === Phase 3: ApplyTransitions（评估并执行所有过渡） ===
    static constexpr int32 MaxIterations = 5;  // ← 关键限制！
    for (int Iter = 0; Iter < MaxIterations; ++Iter)
    {
        if (TriggerTransitions())  // 内部评估所有 Transition
        {
            BeginApplyTransition(...);
            ExitState(旧链);                  // 子→父顺序
            EnterState(新链);                  // 父→子顺序
            // 如果 EnterState 又导致状态完成，循环继续
        }
        else
            break;  // 没有 Transition 命中，结束
    }

    return Exec.TreeRunStatus;
}
```

### 重要细节 1：MaxIterations = 5

源码（`StateTreeExecutionContext.cpp` 约 1860 行）：

```cpp
// The state selection is repeated up to MaxIteration time. This allows failed EnterState() to potentially find a new state immediately.
// This helps event driven StateTrees to not require another event/tick to find a suitable state.
static constexpr int32 MaxIterations = 5;
for (int32 Iter = 0; Iter < MaxIterations; Iter++)
{
    if (TriggerTransitions())
    {
        ExitState(...);
        EnterState(...);
        if (LastTickStatus != Running)
            StateCompleted();
    }
    if (Exec.LastTickStatus == EStateTreeRunStatus::Running)
        break;
}
```

**这是什么意思？**
- 单次 Tick 内，状态切换可以连续发生最多 5 次
- 比如 EnterState A 立即 Failed → 触发 Transition → Enter B 又 Failed → ... 最多 5 次
- 5 次还没找到 Running 状态，本帧就停下，等下一帧

**这个限制重要吗？**
- 通常不需要担心
- 但如果你写的逻辑导致频繁立即完成，可能撞到这个限制 → 状态会"卡住"等下一帧

### 重要细节 2：Task Tick 的开关

并不是所有 Task 都会被 Tick，受这两个标志位控制：

```cpp
// FStateTreeTaskBase 中
uint8 bShouldCallTick : 1;             // C++ Task 默认 true（5.7 源码确认）
uint8 bShouldCallTickOnlyOnEvents : 1; // 默认 false
```

**重要更正**：网上很多旧资料说"C++ Task 默认 `bShouldCallTick = false`"，但**在 UE5.7 源码中默认值是 `true`**：

```cpp
// StateTreeTaskBase.h（源码片段）
FStateTreeTaskBase()
    : bShouldStateChangeOnReselect(true)
    , bShouldCallTick(true)              // ← 默认 true！
    , bShouldCallTickOnlyOnEvents(false)
    ...
```

如果你不想 Tick（性能考虑），需要在子类构造函数里**显式关闭**：
```cpp
FMyTask()
{
    bShouldCallTick = false;
}
```

### 重要细节 3：Tick 的顺序

**根 → 叶**。激活链 `[A, B, C]`，Tick 顺序是 A 的 Tasks → B 的 Tasks → C 的 Tasks。

这样设计的目的是：父任务可以先完成数据计算，子任务能读到最新数据（通过 Binding）。

## 四、Transition 评估流程（最关键的部分）

### 何时评估 Transition？

Transition 评估发生在每次 Tick 的 Phase 3，以及每次 Task 完成后。具体来说，以下情况会触发评估：

| 触发场景 | 来源 |
|---------|------|
| Task 返回 `Succeeded` / `Failed` | Tick 阶段后 |
| 外部调用 `Context.FinishTask` | 立即标记，下一次评估时处理 |
| `On Tick` 类型 Transition 的条件 | 每帧评估 |
| `On Event` 类型，匹配事件到达 | 事件入队后 |
| `On Delegate` 类型，委托被广播 | 广播后 |
| 外部 `RequestTransition` | 立即处理（如果在 Direct 模式） |

### 评估顺序（核心算法）

```
触发 Transition 评估
    │
    ▼
取出 [所有活动状态]，从叶子向根排列: [C, B, A, Root]
    │
    ▼
for state in [C, B, A, Root]:
    for transition in state.Transitions（按编辑器从上到下顺序）:
        ① 检查 Trigger 是否匹配本次事件
           （如 Task 完成只匹配 OnStateCompleted/Succeeded/Failed；Tick 帧匹配 OnTick；等等）

        ② 检查 Transition Condition
           （所有条件全部通过才算命中）

        ③ 检查目标状态链能否被成功选中
           （递归 SelectState 到叶子）

        ④ 如果以上都成功 → 采用此 Transition，停止所有评估！

无任何 Transition 命中 → 保持当前状态
```

### 关键点：第一个命中即采用

```
C 上的 Transition: T1, T2
B 上的 Transition: T3, T4
A 上的 Transition: T5

评估顺序：T1 → T2 → T3 → T4 → T5
任何一个命中即停止，后面的都不再评估！
```

### 优先级（TransitionPriority）

源码定义：

```cpp
UENUM(BlueprintType)
enum class EStateTreeTransitionPriority : uint8
{
    None UMETA(Hidden),
    Low,
    Normal,    // 默认
    Medium,
    High,
    Critical,
};
```

**优先级如何工作？**

注意：**优先级不改变评估顺序**！它的作用是：当多条 Transition 在同一时刻被请求（比如多个 Task 同时完成 + 外部 RequestTransition），引擎会取**优先级最高**的那一条。

源码中 `Exec.RequestedTransition` 只保留一个，新请求来时会比较优先级，更高的会替换它：

```cpp
// 简化逻辑
if (NewRequest.Priority >= CurrentRequest.Priority)
    CurrentRequest = NewRequest;
```

### 状态切换的细节

当 Transition 命中后，从 `[A, B, C]` 切换到 `[A, B, D, E]`（共同父是 `[A, B]`）：

```
1. ExitState 阶段：
   顺序：C → B → A 反向遍历，但只到共同父之上
   → 实际只调用 C.Tasks.ExitState()
   → B 和 A 的 Tasks 不会 Exit（因为它们仍在新链中）

   ⚠️ 但默认情况下 B 和 A 仍会收到 Sustained 类型的 ExitState/EnterState 事件
      除非 bShouldStateChangeOnReselect = false

2. SelectState 阶段：
   从 B 开始向下选 → D → E

3. EnterState 阶段：
   顺序：D → E（按层级从根到叶）

4. StateCompleted 阶段（如果旧链中有 Task 完成）：
   ⚠️ 反向调用：从根到叶依次调用每个 Task 的 StateCompleted
   实际是反向（leaf → root），见源码注释
```

源码中关于 StateCompleted 的注释：

```cpp
/**
 * Called right after a state has been completed, but before new state has been selected.
 * StateCompleted is called in reverse order to allow to propagate state to other Tasks
 * that are executed earlier in the tree.
 */
virtual void StateCompleted(...)
```

## 五、激活链的最大长度限制：8

源码定义：

```cpp
// StateTreeExecutionTypes.h
USTRUCT(BlueprintType)
struct FStateTreeActiveStates
{
    static constexpr uint8 MaxStates = 8;  // ← 硬限制！
    ...
};
```

**这意味着**：你的激活链 `Root → A → B → C → D → E → F → G` 最多 8 层，超过会出错。

实战中很少会撞到这个限制（嵌套 8 层意味着 UI 已经很难看了），但用 Linked Asset 时要注意，每个链接资产会"展开"成一个新 frame，frame 内部仍然受这个限制。

## 六、TickRate 调度（5.5+）

5.5 加入了 **Scheduled Tick** 系统，可以让 StateTree 不必每帧 Tick。

源码 `StateTreeExecutionContext.cpp` 的 `GetNextScheduledTick` 函数：

```
ScheduleNextTick 计算逻辑：
  1. 如果 TreeRunStatus != Running → 永久 Sleep
  2. 如果有 Task 标记 bShouldCallTick && bConsideredForScheduling → 每帧 Tick
  3. 如果有 Task 在等待 Event 或 Delegate → 按需 Wake
  4. 如果有 State 设置了 CustomTickRate → 按那个频率 Tick
  5. 否则 → Sleep，等事件
```

这是一个非常重要的性能优化，特别适合事件驱动的 StateTree。

可以通过 `FStateTreeReadOnlyExecutionContext::GetNextScheduledTick()` 查询下一次该什么时候 Tick。

                 一帧 Tick（DeltaTime = 0.016s）
═════════════════════════════════════════════════════════════

Frame Begin

    ▼

└─────────────────────────────────────────────────┘
    │
    ▼

    │
    ▼

│                                                  │
│      // TriggerTransitions 内部：                │
│      //   从叶子→根遍历 active state             │

│      //   第一个命中的 transition 被采用         │
│                                                  │
│      ExitState(旧链)         ← 叶→根             │
│      SelectState(新目标)     ← 选叶子            │

## 八、几个常见疑问的源码答案

### Q1: 父状态的 Task 和子状态的 Task 同时 Tick 时，谁先？

**A**: 父先。Tick 顺序严格遵循"根 → 叶"，源码中 `for(stateIdx = 0; stateIdx < ActiveStates.Num(); ++stateIdx)` 是正向遍历。

### Q2: 一个 Task Failed 了，下一个 Task 还会 Tick 吗？

**A**: 是的。一帧内所有标记为 active 的 Task 都会 Tick 完毕，再统一进入 Transition 评估阶段。Failed 不会立即"退出"。

### Q3: 我在 Task A 中调用 `FinishTask`，Task B 同帧还会 Tick 吗？

**A**: 会。`FinishTask` 只是设置一个 flag（`bHasPendingCompletedState`），不会立即停止本帧的 Tick。所有 Task Tick 完后才统一处理 Transition。

### Q4: 同一帧多个 Task 同时完成，谁触发 Transition？

**A**: 所有完成的状态都会被标记，然后从叶子向根评估 Transition。**先评估到的命中先赢**，与"哪个 Task 先完成"无关。

### Q5: 状态切换时，新链中复用的状态会重新 Enter 吗？

**A**: 默认会发"Sustained"事件（即 EnterState/ExitState 都会被调，但 ChangeType 是 Sustained 不是 Changed）。如果不想要这个事件，关闭 Task 的 `bShouldStateChangeOnReselect`。

### Q6: 切换状态时数据绑定（Binding）会在什么时候更新？

**A**: 取决于具体阶段：
- ExitState 前：`bShouldCopyBoundPropertiesOnExitState = true`（默认）会复制
- Tick 前：`bShouldCopyBoundPropertiesOnTick = true`（默认）会复制
- EnterState 前：总是会复制（这是必须的）

## 九、读完这一章你应该理解的

1. ✅ Tick 分三个阶段：Tick Tasks → TriggerTransitions → ApplyTransitions
2. ✅ ApplyTransitions 单帧最多迭代 5 次（防无限循环）
3. ✅ 激活链最多 8 层（硬限制）
4. ✅ Tick 顺序：根→叶；ExitState 顺序：叶→根；EnterState 顺序：根→叶
5. ✅ Transition 评估：从叶子向根冒泡，同一状态内从上到下，第一个命中即采用
6. ✅ Priority 不影响评估顺序，只影响多个并发请求时谁胜出
7. ✅ Task 的 Tick 默认开启（5.7+），但可以通过 `bShouldCallTick = false` 关闭
