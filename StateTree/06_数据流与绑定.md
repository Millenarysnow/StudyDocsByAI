# 06. 数据流与绑定

> 本章讲解 StateTree 中数据如何在节点之间流动 —— Parameters、Context、Bindings、PropertyRef 等机制。

---

## 一、StateTree 中的"数据"种类

源码 `EStateTreeDataSourceType` 列出了所有数据源类型：

```cpp
UENUM()
enum class EStateTreeDataSourceType : uint8
{
    None,
    GlobalInstanceData,           // 全局任务、求值器的数据
    ActiveInstanceData,           // 活动状态任务的数据
    SharedInstanceData,           // 条件、考量、绑定函数共享数据
    ExecutionRuntimeData,         // 节点的持久化运行时数据
    ContextData,                  // Schema 提供的上下文数据
    ExternalData,                 // 节点声明的外部依赖
    GlobalParameterData,          // 全局参数
    SubtreeParameterData,         // 子树参数
    StateParameterData,           // 状态级参数
    TransitionEvent,              // 转换事件
    StateEvent,                   // 状态选择事件
    ExternalGlobalParameterData,  // 外部提供的全局参数
};
```

实际开发者主要打交道的有：

1. **Parameters**（树级 / 状态级 / 子树级参数）
2. **Context Data**（Schema 提供的上下文）
3. **External Data**（任务声明的外部依赖）
4. **Bindings**（任务间的属性绑定）
5. **PropertyRef**（可读写引用）

---

## 二、Parameters（参数）

### 1. 全局参数（Global Parameters）

在 StateTree 资产的 Asset Details 面板可以定义。所有地方都能访问。

#### 创建

打开 StateTree 资产 → Asset Details → Parameters → 添加变量。

#### 在外部设置

```cpp
// 启动 StateTree 时传入
FStateTreeStartParameters StartParams;
StartParams.GlobalParameters = MyParameters;  // FInstancedPropertyBag

ExecutionContext.Start(StartParams);
```

#### 在 Task 中读取

```cpp
// 通过 Binding 读取（最常见）
USTRUCT()
struct FMyTaskData
{
    UPROPERTY(EditAnywhere, Category = "Input")
    float SomeGlobalValue;  // 在编辑器中绑定到 Parameters.MyValue
};
```

#### 运行时修改

5.4 之前蓝图无法修改全局参数（C++ 可以）。5.5+ 蓝图支持但需要 PropertyRef。

```cpp
// C++ 修改全局参数
ExecutionContext.SetGlobalParameters(NewParameters);
```

### 2. 状态级参数（State Parameters）

针对单个 State 的参数，在 State 的 Details 面板配置。

主要用于 **Linked / LinkedAsset** 状态向被链接的 Subtree 传参。

```
Subtree "Patrol"
├── Parameters: PatrolRadius (float)

Linked State "Wander"
├── Type: Linked
├── Linked Subtree: Patrol
├── Parameters:
│   └── PatrolRadius = 1000  ← 在这里设置
```

### 3. Subtree Parameters（子树参数）

Subtree 状态可以声明自己的参数，被 Linked 状态传入。结构同上。

## 三、Context Data（上下文数据）

Context Data 由 **Schema** 决定。每种 Schema 提供不同的上下文数据。

| Schema | Context Data |
|--------|-------------|
| StateTreeComponentSchema | Owner Actor |
| StateTreeAIComponentSchema | Owner Actor + AIController |
| MassStateTreeSchema | Mass Entity Handle, World |

### 在 Task 中使用

```cpp
USTRUCT()
struct FMyTaskData
{
    GENERATED_BODY()

    // 自动绑定到 Context Actor
    UPROPERTY(EditAnywhere, Category = "Context")
    TObjectPtr<AActor> ContextActor;

    // 自动绑定到 AIController（如果 Schema 支持）
    UPROPERTY(EditAnywhere, Category = "Context")
    TObjectPtr<AAIController> ContextAI;
};
```

`Category = "Context"` 让 StateTree 自动尝试绑定。如果有多个 Context 类型可选，会显示链条图标，可以手动覆盖。

## 四、External Data（外部数据）

C++ Task 可以声明它需要哪些外部 Subsystem 或 Component。

### 声明

```cpp
USTRUCT()
struct FMyTask : public FStateTreeTaskCommonBase
{
    GENERATED_BODY()

    // 声明依赖
    TStateTreeExternalDataHandle<UNavigationSystemV1> NavSysHandle;

    // 在 Link 中绑定
    virtual bool Link(FStateTreeLinker& Linker) override
    {
        Linker.LinkExternalData(NavSysHandle);
        return Super::Link(Linker);
    }

    virtual EStateTreeRunStatus EnterState(...) const override
    {
        // 使用
        UNavigationSystemV1& NavSys = Context.GetExternalData(NavSysHandle);
        // ...
    }
};
```

### 可选 vs 必需

```cpp
// 必需（默认）
TStateTreeExternalDataHandle<UNavigationSystemV1, EStateTreeExternalDataRequirement::Required> NavSysHandle;

// 可选
TStateTreeExternalDataHandle<UNavigationSystemV1, EStateTreeExternalDataRequirement::Optional> NavSysHandle;
```

必需依赖在编译时检查，缺失会失败。

## 五、Bindings（属性绑定）

这是 StateTree 数据流的**核心机制**。任何 Property 都可以绑定到另一个数据源。

### 绑定的源

一个 Property 可以绑定到：

1. **全局参数** (Tree Parameters)
2. **状态参数** (State Parameters)  
3. **上下文数据** (Context Data)
4. **求值器输出** (Evaluator Output)
5. **全局任务输出** (Global Task Output)
6. **同状态或父状态中前序任务的输出** (Task Output)

### 在 Task 中暴露 Output

```cpp
USTRUCT()
struct FRandomLocationTaskData
{
    GENERATED_BODY()

    UPROPERTY(EditAnywhere, Category = "Context")
    TObjectPtr<AActor> ContextActor;

    UPROPERTY(EditAnywhere, Category = "Parameter")
    float Radius = 500.0f;

    // ⭐ Output 可被其他 Task 绑定
    UPROPERTY(VisibleAnywhere, Category = "Output")
    FVector Location;
};

// 在 Task 中写入
EStateTreeRunStatus EnterState(...) const
{
    FInstanceDataType& Data = Context.GetInstanceData(*this);
    
    FNavLocation RandomLoc;
    if (NavSys.GetRandomPointInNavigableRadius(
            Data.ContextActor->GetActorLocation(), Data.Radius, RandomLoc))
    {
        Data.Location = RandomLoc.Location;
        return EStateTreeRunStatus::Succeeded;
    }
    return EStateTreeRunStatus::Failed;
}
```

### 在另一个 Task 中绑定

```cpp
USTRUCT()
struct FMoveToTaskData
{
    GENERATED_BODY()

    UPROPERTY(EditAnywhere, Category = "Context")
    TObjectPtr<AAIController> ContextAI;

    // 在编辑器中绑定到 RandomLocationTask.Location
    UPROPERTY(EditAnywhere, Category = "Input")
    FVector Destination;
};
```

### 绑定的可见性规则

源码注释：
> "Tasks can bind to common data, and previous tasks in the **same state and all parent states**."

**所以**：
- 你可以绑定到**当前状态及所有父状态**中**前面**的 Task 的 Output
- 不能绑定到**子状态或同状态的后续 Task**（因为它们还没运行）
- 不能绑定到**兄弟状态**的 Task

### 示例：父任务输出 → 子任务输入

```
ParentState
├── Task: GetTarget (Output: TargetActor)
│
└── ChildState
    └── Task: AttackTarget (Input: TargetActor ← 绑定到 GetTarget.TargetActor)
```

## 六、Binding 的复制时机

源码标志位：

```cpp
uint8 bShouldCopyBoundPropertiesOnTick : 1;        // 默认 true
uint8 bShouldCopyBoundPropertiesOnExitState : 1;   // 默认 true
```

**EnterState 前**：总是会复制（这是必须的）

**Tick 前**：如果 `bShouldCopyBoundPropertiesOnTick = true`，每次 Tick 前都复制 → 这意味着 Binding 是**动态更新**的

**ExitState 前**：如果 `bShouldCopyBoundPropertiesOnExitState = true`，ExitState 前最后复制一次

### 性能优化

如果你的 Task 不在乎运行时绑定值变化（比如只在 EnterState 时用一次），可以关闭：

```cpp
FMyTask()
{
    bShouldCopyBoundPropertiesOnTick = false;  // Tick 不复制，省 CPU
}
```

## 七、Bindings 的本质：值传递（Value Copy）

**这是最重要的事实**：Bindings 是按值复制的，不是引用！

```
Source: SomeActor->CurrentLocation  (FVector)
            ↓
        每次 Tick 复制
            ↓
Target: TaskInstance.BoundLocation  (FVector)
```

如果 `SomeActor->CurrentLocation` 在 Tick 之间变化：
- 下一帧 Tick 前会重新复制 → Target 拿到新值
- **但同一帧内 Tick 完成后 SomeActor 又变化** → 这一帧的 Target 仍然是旧值

### 为什么这么设计？

1. **线程安全**：StateTree 可能跨线程跑（特别是 Mass）
2. **可预测性**：避免 Source 变化导致 Task 中途数据混乱
3. **回滚便利**：状态回滚时数据是稳定的

### 对结构体特别坑

```cpp
struct FMyData
{
    int32 X;
};

UPROPERTY()
FMyData Data;  // ← 这是值，不是指针！

// 你在 Task 中读取的是副本
// 即使外部改了原始 Data.X，Task 拿到的还是旧值（直到下次复制）
```

## 八、PropertyRef（可读写引用）

5.4+ 引入的**真正引用绑定**。突破值传递的限制。

### C++ 版：FStateTreePropertyRef

```cpp
USTRUCT()
struct FMyTaskData
{
    GENERATED_BODY()

    // 引用一个 FVector，可读可写
    UPROPERTY(EditAnywhere, Category = "Output")
    FStateTreePropertyRef<FVector> LocationRef;
};

void FMyTask::Tick(...) const
{
    FInstanceDataType& Data = Context.GetInstanceData(*this);

    // 读取
    if (const FVector* Location = Data.LocationRef.GetPtr(Context))
    {
        UE_LOG(...);
    }

    // 写入！
    if (FVector* Location = Data.LocationRef.GetMutablePtr(Context))
    {
        *Location = NewValue;  // 直接修改外部变量
    }
}
```

### 蓝图版：FStateTreeBlueprintPropertyRef

5.5+ 蓝图也能用，但功能受限：
- 5.5：只能读不能写（？版本相关）
- 后续版本：完整支持

```cpp
UPROPERTY(EditAnywhere, Category = "Output")
FStateTreeBlueprintPropertyRef LocationRef;

UPROPERTY(EditAnywhere, Category = "Output", meta = (BPType = Vector))
FStateTreeBlueprintPropertyRef VectorRef;
```

### PropertyRef 的用途

1. **写回到 Parameters**：让 Task 修改全局参数（值传递做不到）
2. **共享可变状态**：多个 Task 协作修改同一个变量
3. **类似 Blackboard Key**：BT 用户最熟悉的模式

## 九、Evaluator（求值器）vs Global Task

### Evaluator（旧）

```cpp
USTRUCT()
struct FMyEvaluator : public FStateTreeEvaluatorCommonBase
{
    GENERATED_BODY()

    virtual void TreeStart(FStateTreeExecutionContext& Context) const override;
    virtual void TreeStop(FStateTreeExecutionContext& Context) const override;
    virtual void Tick(FStateTreeExecutionContext& Context, const float DeltaTime) const override;
};
```

每帧 Tick，可以在所有状态选择前更新数据。

### Global Task（新，5.4+ 推荐）

继承 `FStateTreeTaskCommonBase` 但放在 Asset Details 的 "Global Tasks" 部分，而不是某个 State 上。

**优点**：
- 拥有 Task 的全部能力（EnterState/ExitState/Tick）
- 比 Evaluator 更灵活
- 5.5+ 官方推荐用 Global Task 取代 Evaluator

**用法**：
- 时间系统：维护"当前游戏时间"
- 感知系统：维护"当前可见敌人列表"
- 健康监控：监控生命值变化并发事件

### 何时用 Evaluator vs Global Task？

5.5+ 基本只用 Global Task 即可。Evaluator 现在主要是为了向后兼容。

## 十、State Events（状态事件）

某些 Transition 触发时会附带 Event Payload，State 可以"捕获"这个事件并暴露给其 Tasks 使用。

### 配置

State 的 Details 面板可以设置 "Event Data"，类型是某个 USTRUCT。

### 使用

```cpp
// Task 可以在 EnterState 中通过 Binding 读取触发本次进入的 Event 数据
UPROPERTY(EditAnywhere, Category = "Input")
FMyEventPayload EventPayload;
// 在编辑器中绑定到 ContextState.EventData
```

这适合"Event 携带参数"的场景，比如"敌人发现"事件携带敌人 Actor 引用，状态进入后可以直接拿到。

## 十一、数据流的可视化

```
═════════════════════════════════════════════════
              StateTree 数据流向
═════════════════════════════════════════════════

外部世界
  │
  ├── Schema Context Data
  │   (Owner Actor, AIController, ...)
  │
  ├── Global Parameters
  │   (传入的 InstancedPropertyBag)
  │
  └── External Data
      (Subsystem, Component refs)
                │
                ▼
   ┌────────────────────────────────────────┐
   │       Global Tasks / Evaluators         │
   │       (在所有状态之上运行)              │
   │       Output: TimeOfDay, EnemyList      │
   └────────────────────────────────────────┘
                │
                │ Bindings
                ▼
   ┌────────────────────────────────────────┐
   │    Active State Chain: [Root, A, B, C]  │
   │                                          │
   │    Root.Tasks                            │
   │       Output: PathPlanning              │
   │           ↓ Bindings                     │
   │    A.Tasks (parent)                     │
   │       Output: TargetSelected            │
   │           ↓ Bindings                     │
   │    B.Tasks (parent)                     │
   │       Output: SmartObjectClaimed        │
   │           ↓ Bindings                     │
   │    C.Tasks (leaf)                       │
   │       Input: 上面所有的 Output           │
   │       (实际执行动作)                     │
   └────────────────────────────────────────┘
                │
                │ PropertyRef (双向)
                ▼
        修改 Global Parameters
        触发 Events / Delegates
        修改外部 Component
```

## 十二、最佳实践

### 1. 数据流方向：Top-Down

让父状态的 Task 计算共享数据，子状态绑定使用。**反方向（子→父）做不到**。

### 2. Output 类型选择

- 简单值（int/float/bool）：直接 UPROPERTY
- 结构体：直接 UPROPERTY（按值复制）
- 对象引用：直接 UPROPERTY (TObjectPtr)
- 需要可读写的：用 PropertyRef

### 3. Performance Tip

如果某个 Task 不需要每帧更新 Bindings：
```cpp
bShouldCopyBoundPropertiesOnTick = false;
```

### 4. 调试 Bindings

打开 StateTree Debugger，可以看到每个 Task 的 Bindings 在每帧的实际值。

### 5. 不要过度依赖 Bindings

复杂的数据流应该用：
- **Subsystem**（共享状态）
- **Events**（异步通知）
- **Delegates**（结构化回调）

而不是层层 Bindings。

### 6. Context vs Input vs Parameter

- **Context**：自动绑定（如 Owner Actor）
- **Input**：必须手动绑定（编译期检查）
- **Parameter**：可选绑定，有默认值
