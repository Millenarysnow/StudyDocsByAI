## 4.4.1 直觉：递归级联爆栈

回顾 4.1.4：`level.setBlock(pos, newState, UPDATE_NEIGHBORS)` 同步触发 6 邻居的 `neighborChanged`。每个 neighbor 的回调可能再调 `setBlock` → 再触发更多 neighbor → 递归。

**朴素实现**（1.18 之前的 `InstantNeighborUpdater`）：

```java
public void neighborChanged(BlockPos pos, Block sourceBlock) {
    BlockState state = level.getBlockState(pos);
    state.handleNeighborChanged(level, pos, sourceBlock, ...);
    // ↓ 这一调用可能内部 setBlock → 递归 neighborChanged
}
```

**问题**：

```
玩家放红石线
  → setBlock 触发 neighbor.neighborChanged
    → 邻居红石线 neighborChanged → setBlock 自己（强度变化）
      → 触发邻居.neighborChanged
        → 邻居红石线 setBlock
          → ⋯
```

一根 100 格红石线触发 100 层递归调用栈。Java JVM 默认栈 ~500 KB（约 1000-5000 帧深）。**100 格 OK，但 1000 格会爆**。某些复杂 redstone 机器（万格电路）100% 爆 StackOverflowError。

**解法**：把递归改成**广度优先 BFS** ——队列驱动而不是调用栈驱动。

## 4.4.2 NeighborUpdater 接口

打开 `net.minecraft.world.level.redstone.NeighborUpdater`：

```java
public interface NeighborUpdater {
    Direction[] UPDATE_ORDER = new Direction[]{WEST, EAST, DOWN, UP, NORTH, SOUTH};

    void shapeUpdate(Direction dir, BlockState state, BlockPos pos, BlockPos neighborPos, int flags, int recursion);
    void neighborChanged(BlockPos pos, Block sourceBlock, @Nullable Orientation orientation);
    void neighborChanged(BlockState state, BlockPos pos, Block sourceBlock, @Nullable Orientation orientation, boolean movedByPiston);
    
    default void updateNeighborsAtExceptFromFacing(BlockPos pos, Block sourceBlock, @Nullable Direction except, @Nullable Orientation orientation) {
        for (Direction dir : UPDATE_ORDER) {
            if (dir != except) {
                this.neighborChanged(pos.relative(dir), sourceBlock, null);
            }
        }
    }
    
    static void executeShapeUpdate(LevelAccessor level, Direction dir, BlockPos pos, BlockPos neighborPos, BlockState neighborState, int flags, int recursion) {
        BlockState state = level.getBlockState(pos);
        if ((flags & 128) == 0 || !state.is(Blocks.REDSTONE_WIRE)) {
            BlockState newState = state.updateShape(level, level, pos, dir, neighborPos, neighborState, level.getRandom());
            Block.updateOrDestroy(state, newState, level, pos, flags, recursion);
        }
    }
    
    static void executeUpdate(Level level, BlockState state, BlockPos pos, Block sourceBlock, @Nullable Orientation orientation, boolean movedByPiston) {
        try {
            state.handleNeighborChanged(level, pos, sourceBlock, orientation, movedByPiston);
        } catch (Throwable throwable) { ... }
    }
}
```

**接口提供 4 个 abstract 方法 + 2 个静态执行入口**。

**`UPDATE_ORDER`** 是 6 邻居的固定顺序：

```java
WEST, EAST, DOWN, UP, NORTH, SOUTH
```

**为什么不能改**：红石电路里某些"BUD 现象"（block update detector）依赖这个顺序。社区基础设施依赖它。Mojang 至今保留。

**两个实现**：

- **`InstantNeighborUpdater`**（旧）：直接调 `executeUpdate` 同步执行 → 递归。只在 worldgen 期使用（worldgen 不会有深红石电路）。
- **`CollectingNeighborUpdater`**（新，1.19+）：BFS 队列。运行期默认。

## 4.4.3 InstantNeighborUpdater：朴素递归

```java
public class InstantNeighborUpdater implements NeighborUpdater {
    private final Level level;

    public InstantNeighborUpdater(Level level) {
        this.level = level;
    }

    @Override
    public void shapeUpdate(Direction dir, BlockState neighborState, BlockPos pos, BlockPos neighborPos, int flags, int recursion) {
        NeighborUpdater.executeShapeUpdate(this.level, dir, pos, neighborPos, neighborState, flags, recursion);
    }

    @Override
    public void neighborChanged(BlockPos pos, Block sourceBlock, @Nullable Orientation orientation) {
        BlockState state = this.level.getBlockState(pos);
        this.neighborChanged(state, pos, sourceBlock, orientation, false);
    }

    @Override
    public void neighborChanged(BlockState state, BlockPos pos, Block sourceBlock, @Nullable Orientation orientation, boolean movedByPiston) {
        NeighborUpdater.executeUpdate(this.level, state, pos, sourceBlock, orientation, movedByPiston);
    }
}
```

**只是一个 thin wrapper** —— 直接转给 `executeUpdate`。**用于 worldgen 期**（chunk 生成期间不需要 BFS，因为 worldgen 不构造 redstone 电路）。

## 4.4.4 CollectingNeighborUpdater：BFS 队列

打开 `net.minecraft.world.level.redstone.CollectingNeighborUpdater`（行 16-90）：

```java
public class CollectingNeighborUpdater implements NeighborUpdater {
    private final Level level;
    private final int maxChainedNeighborUpdates;
    private final ArrayDeque<NeighborUpdates> stack = new ArrayDeque<>();
    private final List<NeighborUpdates> addedThisLayer = new ArrayList<>();
    private int count = 0;

    public CollectingNeighborUpdater(Level level, int maxChainedNeighborUpdates) {
        this.level = level;
        this.maxChainedNeighborUpdates = maxChainedNeighborUpdates;
    }

    @Override
    public void neighborChanged(BlockPos pos, Block sourceBlock, @Nullable Orientation orientation) {
        this.addAndRun(pos, new SimpleNeighborUpdate(pos, sourceBlock, orientation));
    }

    private void addAndRun(BlockPos pos, NeighborUpdates update) {
        boolean isReentrant = this.count > 0;     // 已经在 runUpdates 中
        boolean overLimit = this.maxChainedNeighborUpdates >= 0 && this.count >= this.maxChainedNeighborUpdates;
        this.count++;
        
        if (!overLimit) {
            if (isReentrant) {
                this.addedThisLayer.add(update);     // 当前层级添加
            } else {
                this.stack.push(update);              // 顶层 push
            }
        } else if (this.count - 1 == this.maxChainedNeighborUpdates) {
            LOGGER.error("Too many chained neighbor updates...");
        }
        
        if (!isReentrant) {
            this.runUpdates();      // 顶层入口才驱动 runUpdates
        }
    }

    private void runUpdates() {
        try {
            while (!this.stack.isEmpty() || !this.addedThisLayer.isEmpty()) {
                // 把 addedThisLayer 倒序压入 stack
                for (int i = this.addedThisLayer.size() - 1; i >= 0; i--) {
                    this.stack.push(this.addedThisLayer.get(i));
                }
                this.addedThisLayer.clear();
                
                NeighborUpdates current = this.stack.peek();
                while (this.addedThisLayer.isEmpty()) {
                    if (current.runNext(this.level)) {
                        // 该 update 还有下一步要做（如 multi-neighbor 的下一个方向）
                        // 退出本 inner loop，把 addedThisLayer 中新添加的处理掉
                    } else {
                        // 该 update 完成
                        if (this.stack.peek() == current) this.stack.pop();
                        if (!this.stack.isEmpty()) {
                            current = this.stack.peek();
                        } else {
                            break;
                        }
                    }
                }
            }
        } finally {
            this.stack.clear();
            this.addedThisLayer.clear();
            this.count = 0;
        }
    }
}
```

**核心机制**：

1. **顶层入口驱动**：第一次调 `neighborChanged` 时（`isReentrant == false`）立刻进入 `runUpdates` 循环。
2. **递归 → 添加到 addedThisLayer**：如果在 runUpdates 中调用 `neighborChanged`（递归），不进入新栈帧——而是 `addedThisLayer.add(update)`。
3. **runUpdates 循环**：从 stack 取一个 update 处理；处理过程中产生的新 update 进 addedThisLayer；当前 update 处理完后把 addedThisLayer push 进 stack 继续。
4. **结果**：BFS 风格——一层处理完再处理下层。Java 调用栈深度 ≤ 几层（不是几千层）。

**`maxChainedNeighborUpdates`** 默认 1000000（百万级）。如果某 setBlock 触发的级联超过 100 万次 → 跳过剩余 + 报错。

## 4.4.5 NeighborUpdates 接口

```java
private interface NeighborUpdates {
    boolean runNext(Level level);     // 返回 true 表示还有下一步
}
```

**4 个具体实现**：

```java
record SimpleNeighborUpdate(BlockPos pos, Block sourceBlock, @Nullable Orientation orientation) implements NeighborUpdates {
    public boolean runNext(Level level) {
        BlockState state = level.getBlockState(this.pos);
        NeighborUpdater.executeUpdate(level, state, this.pos, this.sourceBlock, this.orientation, false);
        return false;     // 一次性 update
    }
}

record FullNeighborUpdate(BlockState state, BlockPos pos, Block sourceBlock, @Nullable Orientation orientation, boolean movedByPiston) implements NeighborUpdates {
    public boolean runNext(Level level) {
        NeighborUpdater.executeUpdate(level, this.state, this.pos, this.sourceBlock, this.orientation, this.movedByPiston);
        return false;
    }
}

class MultiNeighborUpdate implements NeighborUpdates {
    private final BlockPos pos;
    private final Block sourceBlock;
    @Nullable private final Direction skipDirection;
    @Nullable private final Orientation orientation;
    private int idx = 0;

    public boolean runNext(Level level) {
        Direction dir = NeighborUpdater.UPDATE_ORDER[this.idx++];
        if (dir != this.skipDirection) {
            BlockPos neighborPos = this.pos.relative(dir);
            BlockState state = level.getBlockState(neighborPos);
            NeighborUpdater.executeUpdate(level, state, neighborPos, this.sourceBlock, this.orientation, false);
        }
        return this.idx < 6;     // 还有未处理的方向
    }
}

record ShapeUpdate(...) implements NeighborUpdates { ... }
```

**MultiNeighborUpdate** 是关键——它代表"对 6 个邻居各发一次 neighborChanged"。**每次 runNext 处理一个邻居方向**，最多 6 次。这让多邻居 update 不一次性占据 stack——可以与其他 update 交替执行。

## 4.4.6 Level.neighborUpdater 选择

```java
// Level 构造（简化）
public Level(...) {
    this.neighborUpdater = isClientSide 
        ? new InstantNeighborUpdater(this)        // 客户端用 instant（不 tick）
        : new CollectingNeighborUpdater(this, 1000000);
}
```

- **Client side**：用 InstantNeighborUpdater——客户端不跑 redstone，简单递归足够。
- **Server side**：用 CollectingNeighborUpdater + 限额 100 万。

**1.21 实验性红石**（features feature flag `experimental_redstone`）有不同的 maxChainedNeighborUpdates 配置 + 不同的 RedstoneWireEvaluator。

## 4.4.7 Orientation：1.21 红石信号方向系统

打开 `net.minecraft.world.level.redstone.Orientation`：

```java
public class Orientation {
    private final Direction up;
    private final Direction front;
    private final Direction side;
    private final Orientation.SideBias sideBias;
    private final int index;
    private final List<Direction> neighbors;
    private final List<Direction> horizontalNeighbors;
    private final List<Direction> verticalNeighbors;
    
    private Orientation(Direction up, Direction front, SideBias bias) {
        this.up = up;
        this.front = front;
        this.sideBias = bias;
        // 计算 side、neighbors 等
    }
}
```

**Orientation = 一个 redstone 信号"流动方向"的描述**——up + front + side bias 共 48 种组合。

**意义**：1.21 实验性红石更新算法引入。每次 redstone 信号传播时携带 Orientation——告诉接收方"信号从哪来、往哪去"。让信号传播规则更确定、更易优化。

**vanilla 1.21 红石仍用旧的 `DefaultRedstoneWireEvaluator`**——Orientation 是给 `experimental_redstone` 用的 `ExperimentalRedstoneWireEvaluator`。

详见 Module 5（红石）。

## 4.4.8 整体调用链

```
玩家放置一个红石火把
  ↓
ServerLevel.setBlock(pos, redstone_torch, UPDATE_ALL)
  ↓
LevelChunk.setBlockState(pos, ...)
  ↓
return to Level.setBlock
  ↓ (UPDATE_NEIGHBORS in flags)
this.neighborUpdater.updateNeighborsAtExceptFromFacing(pos, redstone_torch, null, null)
  ↓
CollectingNeighborUpdater.addAndRun(pos, MultiNeighborUpdate(pos, redstone_torch, null, null))
  ├── count == 0 (顶层入口)
  ├── stack.push(multi_update)
  ├── runUpdates() 进入主循环
  │   ├── current = multi_update
  │   ├── current.runNext(level): 处理 WEST 邻居
  │   │   ├── BlockState state = level.getBlockState(westPos)
  │   │   ├── state.handleNeighborChanged(level, westPos, redstone_torch, null, false)
  │   │   │   ↓ 调到 westBlock.neighborChanged
  │   │   │   ├── 假设是 redstone_wire
  │   │   │   ├── 计算新强度 → setBlock 改 POWER 属性
  │   │   │   │   ↓ 又触发 multi_update（递归进入 addAndRun）
  │   │   │   │   ├── count > 0 → addedThisLayer.add(...)
  │   │   │   │   └── (NOT runUpdates—— 等当前层处理完)
  │   │   │   └── return
  │   │   └── return true (还有 EAST/DOWN/UP/NORTH/SOUTH)
  │   ├── 处理 EAST 邻居
  │   ├── ⋯ 6 方向都处理完 → runNext returns false → pop
  │   ├── stack 还有 addedThisLayer 中的 redstone_wire 引发的新 update
  │   ├── 把 addedThisLayer 倒序 push 到 stack
  │   ├── 继续处理新的 update（可能再产生更多）
  ├── stack 空 + addedThisLayer 空 → 退出 runUpdates
  └── count = 0
```

**整个过程 Java stack 深度 ≤ 5 层**——不会 StackOverflow。

## 4.4.9 `executeUpdate` 的崩溃报告

回顾 4.4.2：

```java
static void executeUpdate(Level level, BlockState state, BlockPos pos, Block sourceBlock, ..., boolean movedByPiston) {
    try {
        state.handleNeighborChanged(level, pos, sourceBlock, orientation, movedByPiston);
    } catch (Throwable t) {
        CrashReport report = CrashReport.forThrowable(t, "Exception while updating neighbours");
        CrashReportCategory cat = report.addCategory("Block being updated");
        cat.setDetail("Source block type", () -> ...);
        CrashReportCategory.populateBlockDetails(cat, level, pos, state);
        throw new ReportedException(report);
    }
}
```

**捕获所有异常 + 包装成带上下文 ReportedException**——崩溃日志会显示：

- 是哪个 block 在 neighborChanged 内崩了。
- pos 坐标。
- BlockState 详情（属性值）。

这是 Mojang 的标准崩溃报告 idiom——**用户提交 crash 时 Mojang 能看出是 mod 引起还是 vanilla bug**。

## 4.4.10 shapeUpdate vs neighborChanged

`NeighborUpdater` 还有 `shapeUpdate` API。它和 `neighborChanged` 区别：

- **`neighborChanged`**：邻居方块**类型**变化时调用——给红石、活塞这种"信号传播"用。
- **`shapeUpdate`**：邻居方块**形状**变化时调用——给栅栏、玻璃板、楼梯这种"连接形状"用。

具体方块通常重写其中一个：

- 栅栏只重写 `updateShape`：邻居变了 → 重新计算"我和邻居连不连"。
- 红石线只重写 `neighborChanged`：邻居变了 → 重新计算信号强度。

`shapeUpdate` 也通过 CollectingNeighborUpdater 路由，使用 `ShapeUpdate` record。

## 4.4.11 性能

```
单次 setBlock:
- 顶层 addAndRun: ~100 ns
- 6 邻居 runNext: ~3-30 微秒（视方块复杂度）
- 简单方块（dirt、stone、wood）：~6 微秒
- 红石线：可能链式触发数十次邻居更新：~100-500 微秒
- 极端 redstone 机器：~10-100 ms
```

**maxChainedNeighborUpdates = 1M**：理论上 100 万次更新最坏 ~10 秒（不可接受），所以 Mojang 之前做了多种红石引擎优化（Carpet Mod 的 fastBlockUpdate 等）。**1.21 实验性红石就是为了根本性减少 update count**。

## 4.4.12 内存预算

```
CollectingNeighborUpdater:
- stack (ArrayDeque): ~200 字节空 + ~100 字节/entry
- addedThisLayer (ArrayList): 类似
- 每 NeighborUpdates record ~50-100 字节

正常运行 stack + addedThisLayer 总量 < 100 entries → ~10 KB
极端场景：~10 MB（红石爆炸）
```

## 4.4.13 C++ 移植

```cpp
namespace mc::redstone {

class NeighborUpdater {
public:
    static constexpr std::array<Direction, 6> UPDATE_ORDER = {
        Direction::WEST, Direction::EAST, Direction::DOWN,
        Direction::UP, Direction::NORTH, Direction::SOUTH
    };
    
    virtual ~NeighborUpdater() = default;
    virtual void neighborChanged(BlockPos pos, Block* sourceBlock, std::optional<Orientation> orientation) = 0;
    virtual void neighborChanged(const BlockState& state, BlockPos pos, Block* sourceBlock, std::optional<Orientation> orientation, bool movedByPiston) = 0;
    virtual void shapeUpdate(Direction dir, const BlockState& state, BlockPos pos, BlockPos neighborPos, int flags, int recursion) = 0;
    
    void updateNeighborsAtExceptFromFacing(BlockPos pos, Block* sourceBlock,
                                            std::optional<Direction> except,
                                            std::optional<Orientation> orientation) {
        for (Direction dir : UPDATE_ORDER) {
            if (!except || dir != *except) {
                neighborChanged(pos.relative(dir), sourceBlock, std::nullopt);
            }
        }
    }
    
    static void executeUpdate(Level& level, const BlockState& state, BlockPos pos, Block* sourceBlock, std::optional<Orientation> orientation, bool movedByPiston);
};

class InstantNeighborUpdater : public NeighborUpdater {
    Level* level_;
public:
    void neighborChanged(BlockPos pos, Block* source, std::optional<Orientation> orient) override {
        const BlockState* state = level_->getBlockState(pos);
        executeUpdate(*level_, *state, pos, source, orient, false);
    }
};

class CollectingNeighborUpdater : public NeighborUpdater {
    Level* level_;
    int maxChainedNeighborUpdates_;
    
    struct NeighborUpdate {
        virtual ~NeighborUpdate() = default;
        virtual bool runNext(Level& level) = 0;
    };
    
    struct SimpleNeighborUpdate : NeighborUpdate { ... };
    struct MultiNeighborUpdate : NeighborUpdate { ... };
    struct ShapeUpdate : NeighborUpdate { ... };
    
    std::deque<std::unique_ptr<NeighborUpdate>> stack_;
    std::vector<std::unique_ptr<NeighborUpdate>> addedThisLayer_;
    int count_ = 0;
    
public:
    CollectingNeighborUpdater(Level* level, int maxChained = 1000000)
        : level_(level), maxChainedNeighborUpdates_(maxChained) {}
    
    void neighborChanged(BlockPos pos, Block* source, std::optional<Orientation> orient) override {
        addAndRun(pos, std::make_unique<SimpleNeighborUpdate>(pos, source, orient));
    }
    
    void addAndRun(BlockPos pos, std::unique_ptr<NeighborUpdate> update) {
        bool isReentrant = count_ > 0;
        bool overLimit = maxChainedNeighborUpdates_ >= 0 && count_ >= maxChainedNeighborUpdates_;
        count_++;
        if (!overLimit) {
            if (isReentrant) {
                addedThisLayer_.push_back(std::move(update));
            } else {
                stack_.push_front(std::move(update));
            }
        }
        if (!isReentrant) runUpdates();
    }
    
    void runUpdates() {
        try {
            while (!stack_.empty() || !addedThisLayer_.empty()) {
                // 把 addedThisLayer 倒序 push 到 stack
                while (!addedThisLayer_.empty()) {
                    stack_.push_front(std::move(addedThisLayer_.back()));
                    addedThisLayer_.pop_back();
                }
                NeighborUpdate* current = stack_.front().get();
                while (addedThisLayer_.empty()) {
                    if (current->runNext(*level_)) {
                        // 还有下一步
                    } else {
                        if (stack_.front().get() == current) stack_.pop_front();
                        if (stack_.empty()) break;
                        current = stack_.front().get();
                    }
                }
            }
        } catch (...) {
            stack_.clear();
            addedThisLayer_.clear();
            count_ = 0;
            throw;
        }
        count_ = 0;
    }
};

}
```

## 4.4.14 一句话总结

`NeighborUpdater` 接口有两实现：worldgen 期 `InstantNeighborUpdater`（直接递归）和运行期 `CollectingNeighborUpdater`（BFS 队列防爆栈）；后者用 `addAndRun` + `runUpdates` 把同步递归改造成"顶层入口驱动 + 当前层完成后处理 addedThisLayer"的层级 BFS；Java stack 深度 ≤ 5 层；`maxChainedNeighborUpdates = 1000000` 上限超出报错跳过；`UPDATE_ORDER = {WEST, EAST, DOWN, UP, NORTH, SOUTH}` 是固定 6 邻居顺序，红石电路 BUD 现象依赖这个；1.21 引入 `Orientation`（48 种 up+front+sideBias 组合）让信号传播携带方向信息——给实验性红石用，vanilla 默认 redstone wire 仍走旧 evaluator。
