# 4.6 setBlock flag

## 4.6.0 你将在本节学到什么

读完这一节你应当能闭着眼睛回答：

1. `Level.setBlock(pos, state, flags)` 的 `flags` 是个位掩码——8 个 flag 位各自做什么？
2. `UPDATE_ALL` = 3 是哪两个 flag 组合？最常用的是哪几个组合？
3. `UPDATE_NONE = 4` 居然不是 0 ——这意味着什么？
4. 一段代码用 `setBlock(pos, state, 67)` 是什么意思？拆位看是什么组合？
5. flags 影响 `LevelChunk.setBlockState` / `Level.markAndNotifyBlock` / `neighborUpdater` 的具体行为。

## 4.6.1 8 个 flag 位

回顾 1.1.2 节看过的 `Block` 类常量（行 76-86）：

```java
public static final int UPDATE_NEIGHBORS = 1;                   // 0b00000001
public static final int UPDATE_CLIENTS = 2;                     // 0b00000010
public static final int UPDATE_INVISIBLE = 4;                   // 0b00000100
public static final int UPDATE_IMMEDIATE = 8;                   // 0b00001000
public static final int UPDATE_KNOWN_SHAPE = 16;                // 0b00010000
public static final int UPDATE_SUPPRESS_DROPS = 32;             // 0b00100000
public static final int UPDATE_MOVE_BY_PISTON = 64;             // 0b01000000
public static final int UPDATE_SKIP_SHAPE_UPDATE_ON_WIRE = 128; // 0b10000000

public static final int UPDATE_NONE = 4;                        // = UPDATE_INVISIBLE
public static final int UPDATE_ALL = 3;                          // = UPDATE_NEIGHBORS | UPDATE_CLIENTS
public static final int UPDATE_ALL_IMMEDIATE = 11;              // = UPDATE_ALL | UPDATE_IMMEDIATE
```

**逐位含义**：

### bit 0：`UPDATE_NEIGHBORS = 1`

**触发周围 6 邻居的 `neighborChanged` 回调**。

清除（=0）：setBlock 改完数据**不**通知邻居。
设置（=1）：通过 NeighborUpdater 调用周围 6 邻居的 neighborChanged。

**典型用法**：99% 的 setBlock 都设这个——除非你**确定**邻居不会受影响。

### bit 1：`UPDATE_CLIENTS = 2`

**通知客户端 BlockUpdate**。

清除：方块改了但客户端不会立刻知道（客户端可能从其他 mechanism 知道，如 chunk 重发）。
设置：把 BlockUpdate 加入 ChunkMap 的"出包队列"，下次 broadcast 发 `ClientboundBlockUpdatePacket` / `ClientboundSectionBlocksUpdatePacket`。

**典型用法**：99% 的玩家可见改动都设——除非你做"只改服务端数据"的内部状态。

### bit 2：`UPDATE_INVISIBLE = 4`

**别更新视觉、声音、粒子**。

清除：触发"块改变"的视觉效果（粒子、声音）。
设置：跳过——纯数据改动。

**注意**：`UPDATE_NONE = 4` 实际就是这一位。Mojang 给了它一个语义别名"什么都不做"。

### bit 3：`UPDATE_IMMEDIATE = 8`

**立刻渲染重编译**——客户端收到 update 后立刻重画 chunk，不等下一帧。

清除：客户端在下一帧的 chunk render queue 里再处理。
设置：立刻 dirty chunk render。

**典型用法**：命令系统（`/setblock`）—— 玩家输完命令希望立刻看到结果。

### bit 4：`UPDATE_KNOWN_SHAPE = 16`

**跳过 shape update**——如果你确定形状已经知道。

清除：触发 `updateShape` 调用——栅栏 / 玻璃板等连接性方块重新计算自己的形状。
设置：跳过——节省时间。

**典型用法**：批量 setBlock（如结构生成）—— 调用方明确知道每个方块都已"完整设置"，不需要 reshape。

### bit 5：`UPDATE_SUPPRESS_DROPS = 32`

**替换原方块时不让它掉落物品**。

清除：被替换的方块（如箱子）会按 loot table 掉落物品。
设置：直接消失，不掉落。

**典型用法**：强制替换（如玩家用 `/setblock` 命令）。

### bit 6：`UPDATE_MOVE_BY_PISTON = 64`

**标记"被活塞推动产生的更新"**。

清除：普通 setBlock。
设置：传给 `neighborChanged` 钩子的 `movedByPiston` 参数 = true。某些方块（如盔甲架、弱方块）对此特殊处理。

**典型用法**：piston 推动 chain 中的 setBlock。

### bit 7：`UPDATE_SKIP_SHAPE_UPDATE_ON_WIRE = 128`

**对 redstone wire 跳过 shape update**——1.21 实验红石专用优化。

清除：默认行为。
设置：当 setBlock 触发 redstone wire 邻居的 shape update 时跳过——优化大型 redstone 电路的更新数量。

**典型用法**：1.21 ExperimentalRedstoneWireEvaluator 内部使用。

---

## 4.6.2 常用组合

| 组合 | 值 | 用途 |
|------|----|----|
| `UPDATE_ALL` = 3 = `UPDATE_NEIGHBORS \| UPDATE_CLIENTS` | 3 | **99% 的玩家可见改动**：触发邻居 + 客户端同步 |
| `UPDATE_ALL_IMMEDIATE` = 11 | 11 | UPDATE_ALL + 立刻重渲染。命令系统、玩家立即反馈场景 |
| `UPDATE_NONE` = 4 = `UPDATE_INVISIBLE` | 4 | 纯数据改动——不通知邻居、不通知客户端、不视觉 |
| `UPDATE_CLIENTS \| UPDATE_INVISIBLE` | 6 | 同步给客户端但不触发视觉 / 邻居（罕见，特殊场景） |
| `2 \| 16` | 18 | 同步客户端 + 跳过 shape update（结构生成内部用） |
| `UPDATE_ALL \| UPDATE_MOVE_BY_PISTON` | 67 | 活塞推动产生的 setBlock |

## 4.6.3 setBlock 实现拆解

简化后的 Level.setBlock：

```java
public boolean setBlock(BlockPos pos, BlockState newState, int flags, int recursion) {
    // 1. 先调 LevelChunk.setBlockState 改数据
    LevelChunk chunk = this.getChunkAt(pos);
    BlockState oldState = chunk.setBlockState(pos, newState, (flags & UPDATE_MOVE_BY_PISTON) != 0);
    
    if (oldState == null) return false;     // chunk 不可写或 oldState 与 newState 相同
    
    // 2. heightmap / lighting 已在 chunk.setBlockState 内处理
    
    // 3. 通知客户端
    if ((flags & UPDATE_CLIENTS) != 0) {
        if ((flags & UPDATE_INVISIBLE) == 0 || !this.isClientSide) {
            this.sendBlockUpdated(pos, oldState, newState, flags);
        }
    }
    
    // 4. 触发 onPlace / onRemove 钩子
    if (oldState.getBlock() != newState.getBlock()) {
        oldState.onRemove(this, pos, newState, (flags & UPDATE_MOVE_BY_PISTON) != 0);
        newState.onPlace(this, pos, oldState, (flags & UPDATE_MOVE_BY_PISTON) != 0);
    }
    
    // 5. 触发 neighborChanged
    if ((flags & UPDATE_NEIGHBORS) != 0) {
        this.updateNeighborsAt(pos, newState.getBlock());
    }
    
    // 6. 触发 shape update（如果不是 KNOWN_SHAPE）
    if ((flags & UPDATE_KNOWN_SHAPE) == 0) {
        this.updateNeighbourShapesAt(pos, newState, recursion - 1);
    }
    
    return true;
}
```

每个 flag 位决定**一个**步骤是否执行。组合起来表达"我要做哪几步"。

## 4.6.4 LevelChunk.setBlockState 内部

```java
public BlockState setBlockState(BlockPos pos, BlockState newState, boolean movedByPiston) {
    int sectionIdx = this.getSectionIndex(pos.getY());
    LevelChunkSection section = this.sections[sectionIdx];
    BlockState oldState = section.setBlockState(pos.getX() & 15, pos.getY() & 15, pos.getZ() & 15, newState);
    if (oldState == newState) return null;     // 没变化
    
    // 1. 维护 heightmaps（4 个 in run-time）
    this.heightmaps.get(Heightmap.Types.MOTION_BLOCKING).update(...);
    this.heightmaps.get(Heightmap.Types.OCEAN_FLOOR).update(...);
    this.heightmaps.get(Heightmap.Types.WORLD_SURFACE).update(...);
    this.heightmaps.get(Heightmap.Types.MOTION_BLOCKING_NO_LEAVES).update(...);
    
    // 2. 处理 BlockEntity（如果 newState 是 EntityBlock）
    if (newState.hasBlockEntity()) {
        BlockEntity be = ((EntityBlock)newState.getBlock()).newBlockEntity(pos, newState);
        if (be != null) this.setBlockEntity(be);
    }
    if (oldState.hasBlockEntity() && !newState.is(oldState.getBlock())) {
        this.removeBlockEntity(pos);
    }
    
    // 3. 标 chunk dirty
    this.unsaved = true;
    
    return oldState;
}
```

**heightmap / BlockEntity / unsaved 维护是 LevelChunk 的责任**——不依赖 flags。Level.setBlock 只关心后续的 neighbor / client / shape update。

## 4.6.5 实战例子

### 例 1：玩家放方块

```java
serverPlayer.gameMode.useItemOn(player, level, hand, hitResult);
  ↓ 内部最终调
level.setBlock(pos, blockItem.getStateForPlacement(...), UPDATE_ALL | UPDATE_INVISIBLE);
//                                                       ★ flags = 3 | 4 = 7
```

flags = 7 拆位：

- `UPDATE_NEIGHBORS = 1` ✓ —— 触发邻居更新
- `UPDATE_CLIENTS = 2` ✓ —— 通知客户端
- `UPDATE_INVISIBLE = 4` ✓ —— **跳过粒子声音**

奇怪—— `UPDATE_INVISIBLE` 在玩家放方块时居然设了？因为客户端**已经放过这个方块的视觉版本**（客户端预测）—— 服务端 setBlock 只是确认数据，客户端不需要再播一遍粒子。

### 例 2：玩家挖方块

```java
level.removeBlock(pos, false);
  ↓ 等价于
level.setBlock(pos, AIR.defaultBlockState(), UPDATE_ALL | UPDATE_INVISIBLE);
```

类似——客户端已预测，服务端只是确认。

### 例 3：活塞推动

```java
level.setBlock(targetPos, pushedBlockState, UPDATE_ALL | UPDATE_MOVE_BY_PISTON);
//                                          ★ flags = 3 | 64 = 67
```

flags = 67 = UPDATE_NEIGHBORS + UPDATE_CLIENTS + UPDATE_MOVE_BY_PISTON。

目标方块的 `neighborChanged` 钩子收到 `movedByPiston = true`，可以特殊处理（如盔甲架接受推动而不掉落）。

### 例 4：命令系统 /setblock

```java
serverLevel.setBlock(pos, newState, Block.UPDATE_ALL_IMMEDIATE);
//                                  ★ flags = 11 = 3 | 8
```

flags = 11 拆：

- UPDATE_NEIGHBORS ✓
- UPDATE_CLIENTS ✓
- UPDATE_IMMEDIATE ✓（立刻 chunk render dirty）

玩家输完 `/setblock` 立刻看到结果，无 1 帧延迟。

### 例 5：worldgen 期 Feature 写方块

```java
level.setBlock(pos, oakLog, 19);
//                          ★ flags = 19 = 16 | 2 | 1
```

flags = 19 拆：

- UPDATE_NEIGHBORS ✓ ——但 worldgen 期"邻居更新"被 `WorldGenRegion` 转化为简单更新（不真触发 redstone）
- UPDATE_CLIENTS ✓ ——但 worldgen 期没有客户端在监听，实际无效
- UPDATE_KNOWN_SHAPE ✓ ——跳过 shape update（worldgen 已知形状）

worldgen 用 19 是个习惯——明确表达"我已知道形状不需要 reshape"。

### 例 6：纯数据修改

```java
level.setBlock(pos, internalState, Block.UPDATE_NONE);     // = 4
```

flags = 4：

- UPDATE_NEIGHBORS ✗ —— 不通知邻居
- UPDATE_CLIENTS ✗ —— 不通知客户端
- UPDATE_INVISIBLE ✓ —— 不视觉

这是"完全静默修改"——**只在内部数据治理时用**。例如 mod 修复一个数据 inconsistency。普通玩家逻辑很少用。

## 4.6.6 注意 setBlock 的 recursion 参数

```java
public boolean setBlock(BlockPos pos, BlockState newState, int flags) {
    return this.setBlock(pos, newState, flags, 512);     // 默认 recursion = 512
}

public boolean setBlock(BlockPos pos, BlockState newState, int flags, int recursion) {
    // ...
    if ((flags & UPDATE_KNOWN_SHAPE) == 0 && recursion > 0) {
        this.updateNeighbourShapesAt(pos, newState, recursion - 1);
    }
}
```

**`recursion` 参数**：限制 shape update 的递归深度，防爆栈。

`Block.UPDATE_LIMIT = 512`（在 1.1.2 节看过）—— 这是 Mojang 选的"安全上限"。一段代码递归调用 setBlock 时每次 -1，到 0 时不再递归。

**实际场景**：连续摆放 50 个栅栏柱子，每个 setBlock 触发 shape update，shape update 内部如果再 setBlock（罕见），递归深度可能超过 512 → 触发 limit。

## 4.6.7 客户端 / 服务端的差异

`isClientSide` 检查：

```java
// Level.setBlock 内部
if ((flags & UPDATE_CLIENTS) != 0) {
    if ((flags & UPDATE_INVISIBLE) == 0 || !this.isClientSide) {
        this.sendBlockUpdated(pos, oldState, newState, flags);
    }
}
```

**逻辑**：

- 服务端 + UPDATE_CLIENTS + 任意 INVISIBLE → 发 BlockUpdate 包给客户端。
- 客户端 + UPDATE_CLIENTS + UPDATE_INVISIBLE → **不**触发视觉效果（粒子声音）。
- 客户端 + UPDATE_CLIENTS + 没 UPDATE_INVISIBLE → 触发视觉效果。

这就是为什么"玩家挖方块"用 `UPDATE_ALL | UPDATE_INVISIBLE`：

- 服务端：发 BlockUpdate（让其他玩家看到）。
- 客户端（自己）：跳过粒子声音（已经预测过了）。
- 客户端（其他玩家）：触发粒子声音（他们需要看到这次挖掘）。

## 4.6.8 性能特征

| 操作 | UPDATE_ALL (3) | UPDATE_NONE (4) | UPDATE_ALL_IMMEDIATE (11) |
|------|----------------|-----------------|--------------------------|
| chunk 数据写 | ~50 ns | ~50 ns | ~50 ns |
| heightmap 更新 | ~100 ns | ~100 ns | ~100 ns |
| 客户端 BlockUpdate 入队 | ~50 ns | 0 | ~50 ns |
| neighborChanged 链 | 5-50 微秒（视方块） | 0 | 5-50 微秒 |
| shapeUpdate 链 | 1-10 微秒 | 1-10 微秒（除非加 UPDATE_KNOWN_SHAPE） | 1-10 微秒 |
| immediate render dirty | — | — | ~100 ns |
| **总** | ~10-100 微秒 | ~150 ns | ~10-100 微秒 |

**UPDATE_NONE** 是最便宜的——但 99% 场景不能用（玩家会看不到改动）。

## 4.6.9 一个常见 bug：忘记 UPDATE_NEIGHBORS

```java
// ❌ 错误
level.setBlock(pos, redstone_torch, 0);     // flags = 0
```

效果：

- 红石火把放下了。
- 周围**不触发** neighborChanged → 旁边的 redstone wire 不知道有新源 → 信号不传播。

**调试现象**：玩家放红石火把但邻接的红石线不亮。

**修复**：用 `UPDATE_ALL = 3` 至少。

mod 开发者最常见错误就是 setBlock flags 选错。

## 4.6.10 C++ 移植

```cpp
namespace mc::block {

namespace BlockUpdateFlags {
    constexpr int NEIGHBORS                  = 1;
    constexpr int CLIENTS                    = 2;
    constexpr int INVISIBLE                  = 4;
    constexpr int IMMEDIATE                  = 8;
    constexpr int KNOWN_SHAPE                = 16;
    constexpr int SUPPRESS_DROPS             = 32;
    constexpr int MOVE_BY_PISTON             = 64;
    constexpr int SKIP_SHAPE_UPDATE_ON_WIRE  = 128;
    
    constexpr int NONE                        = INVISIBLE;             // = 4
    constexpr int ALL                         = NEIGHBORS | CLIENTS;    // = 3
    constexpr int ALL_IMMEDIATE               = ALL | IMMEDIATE;        // = 11
}

class Level {
public:
    bool setBlock(BlockPos pos, const BlockState* newState, int flags, int recursion = 512) {
        LevelChunk* chunk = getChunkAt(pos);
        const BlockState* oldState = chunk->setBlockState(pos, newState, flags & BlockUpdateFlags::MOVE_BY_PISTON);
        if (oldState == nullptr || oldState == newState) return false;
        
        if (flags & BlockUpdateFlags::CLIENTS) {
            if ((flags & BlockUpdateFlags::INVISIBLE) == 0 || !isClientSide()) {
                sendBlockUpdated(pos, oldState, newState, flags);
            }
        }
        
        if (oldState->getBlock() != newState->getBlock()) {
            oldState->onRemove(*this, pos, newState, flags & BlockUpdateFlags::MOVE_BY_PISTON);
            newState->onPlace(*this, pos, oldState, flags & BlockUpdateFlags::MOVE_BY_PISTON);
        }
        
        if (flags & BlockUpdateFlags::NEIGHBORS) {
            updateNeighborsAt(pos, newState->getBlock());
        }
        
        if (!(flags & BlockUpdateFlags::KNOWN_SHAPE) && recursion > 0) {
            updateNeighbourShapesAt(pos, newState, recursion - 1);
        }
        
        return true;
    }
};

}
```

## 4.6.11 一句话总结

`setBlock(pos, state, flags)` 的 flags 是 8 位掩码：bit 0 NEIGHBORS（触发邻居更新）/ bit 1 CLIENTS（同步客户端）/ bit 2 INVISIBLE（跳过视觉）/ bit 3 IMMEDIATE（立刻重渲染）/ bit 4 KNOWN_SHAPE（跳过 shape update）/ bit 5 SUPPRESS_DROPS / bit 6 MOVE_BY_PISTON / bit 7 SKIP_SHAPE_UPDATE_ON_WIRE；常用 `UPDATE_ALL = 3` (NEIGHBORS+CLIENTS)、`UPDATE_ALL_IMMEDIATE = 11`、`UPDATE_NONE = 4` (实际就是 INVISIBLE)；玩家放/挖方块用 `UPDATE_ALL | UPDATE_INVISIBLE`（客户端已预测）；活塞推动用 `UPDATE_ALL | UPDATE_MOVE_BY_PISTON`；worldgen 期 Feature 用 `19 = NEIGHBORS | CLIENTS | KNOWN_SHAPE`；命令系统 /setblock 用 `UPDATE_ALL_IMMEDIATE = 11`。
