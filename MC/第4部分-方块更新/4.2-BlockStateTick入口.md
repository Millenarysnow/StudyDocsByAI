# 4.2 BlockState tick 入口

## 4.2.0 你将在本节学到什么

读完这一节你应当能闭着眼睛回答：

1. `BlockState.tick` / `BlockState.randomTick` / `BlockState.handleNeighborChanged` 这几个钩子各自做什么？
2. 写一个新方块，要让它"每秒长一点"应该重写哪个方法？要让它"接受红石信号变化"重写哪个？
3. 这些钩子里的 `level` 参数是 `ServerLevel`，意味着什么？
4. `BlockState.isRandomlyTicking()` 是个 hot path 字段——它在哪里维护、谁查询？

## 4.2.1 BlockBehaviour 上的 tick 钩子

打开 `net.minecraft.world.level.block.state.BlockBehaviour`：

```java
public abstract class BlockBehaviour {
    // ... 数十个虚方法 ...
    
    protected void tick(BlockState state, ServerLevel level, BlockPos pos, RandomSource random) {
    }
    
    protected void randomTick(BlockState state, ServerLevel level, BlockPos pos, RandomSource random) {
        this.tick(state, level, pos, random);     // 默认转发给 tick
    }
    
    protected void neighborChanged(BlockState state, Level level, BlockPos pos, Block neighborBlock,
                                   @Nullable Orientation orientation, boolean movedByPiston) {
    }
    
    protected void onPlace(BlockState state, Level level, BlockPos pos, BlockState oldState, boolean movedByPiston) {
    }
    
    protected void onRemove(BlockState state, Level level, BlockPos pos, BlockState newState, boolean movedByPiston) {
    }
    
    protected boolean triggerEvent(BlockState state, Level level, BlockPos pos, int eventId, int eventParam) {
        return false;
    }
    
    protected BlockState updateShape(BlockState state, LevelReader level, ScheduledTickAccess tickAccess,
                                      BlockPos pos, Direction direction, BlockPos neighborPos,
                                      BlockState neighborState, RandomSource random) {
        return state;
    }
    
    // ... 还有 use / attack / entityInside 等交互钩子 ...
}
```

**4 个核心方块更新钩子**：

| 钩子 | 触发 | 频率 | 典型用途 |
|------|------|------|---------|
| `tick(state, level, pos, random)` | scheduled tick 触发 | 按 schedule 时间 | 中继器输出更新、流体扩散 |
| `randomTick(state, level, pos, random)` | random tick 抽中 | 每 section 每 tick 抽 3 次 | 作物长高、树叶腐烂、雪化 |
| `neighborChanged(state, level, pos, neighborBlock, orientation, movedByPiston)` | 邻居 setBlock 触发 | 同步级联 | 红石线信号、栅栏连接 |
| `onPlace(state, level, pos, oldState, movedByPiston)` / `onRemove(...)` | setBlock 自身改变时 | 同步 | 初始化 / 清理（BlockEntity） |
| `triggerEvent(state, level, pos, eventId, param)` | block event 触发 | 第 9 步 | 活塞推动、唱片机 |
| `updateShape(state, ..., neighborState, ...)` | 邻居 setBlock 时（shape 类） | 同步 | 栅栏 / 楼梯连接形状更新 |

## 4.2.2 BlockState 怎么转发到 Block 子类

`BlockState` 不直接持有这些方法——它继承自 `BlockBehaviour.BlockStateBase`：

```java
public class BlockState extends BlockBehaviour.BlockStateBase {
    public BlockState(Block owner, ..., MapCodec<BlockState> propertiesCodec) {
        super(owner, ..., propertiesCodec);
    }
}

// BlockStateBase 内部实现
public abstract static class BlockStateBase extends StateHolder<Block, BlockState> {
    public void tick(ServerLevel level, BlockPos pos, RandomSource random) {
        this.getBlock().tick(this.asState(), level, pos, random);
    }
    public void randomTick(ServerLevel level, BlockPos pos, RandomSource random) {
        this.getBlock().randomTick(this.asState(), level, pos, random);
    }
    public void handleNeighborChanged(Level level, BlockPos pos, Block neighborBlock, ..., boolean movedByPiston) {
        this.getBlock().neighborChanged(this.asState(), level, pos, neighborBlock, ..., movedByPiston);
    }
    // ⋯
}
```

**调用链**：

```
ServerLevel.tickBlock(pos, block) 
    ↓
BlockState.tick(level, pos, random)
    ↓
this.getBlock().tick(state, level, pos, random)
    ↓
具体 Block 子类（如 SugarCaneBlock）的 tick 实现
```

为什么走 BlockState 中转？因为 chunk section 持有的是 BlockState 引用，不是 Block。从 chunk 出发自然先调 BlockState 的方法。

## 4.2.3 一个完整例子：CropBlock.randomTick

```java
public abstract class CropBlock extends BushBlock {
    public static final IntegerProperty AGE = BlockStateProperties.AGE_7;     // 0..7
    
    @Override
    public boolean isRandomlyTicking(BlockState state) {
        return state.getValue(AGE) < this.getMaxAge();
    }
    
    @Override
    public void randomTick(BlockState state, ServerLevel level, BlockPos pos, RandomSource random) {
        if (level.getRawBrightness(pos, 0) >= 9) {
            int age = this.getAge(state);
            if (age < this.getMaxAge()) {
                float growthSpeed = getGrowthSpeed(this, level, pos);
                if (random.nextInt((int)(25.0F / growthSpeed) + 1) == 0) {
                    level.setBlock(pos, this.getStateForAge(age + 1), Block.UPDATE_ALL);
                }
            }
        }
    }
}
```

**逐行解读**：

1. `AGE` 属性：0-7，0 是刚种下、7 是成熟。
2. **`isRandomlyTicking`** 重写：只在 AGE < 7 时才参与 random tick。AGE=7 已经成熟，不再参与，**节省计数器** 和后续 random tick 抽样代价。
3. **`randomTick` 内部**：
   - 检查光照（`getRawBrightness ≥ 9`）。农作物需要光照。
   - 用 `getGrowthSpeed` 计算速度（基础 1.0，被 hydration / 邻接同种作物 / 草方块下方等因素调整）。
   - 用 `random.nextInt(25/speed + 1) == 0` 随机概率——大约 4% 概率成功 tick 一阶。
   - **`level.setBlock(pos, getStateForAge(age+1), UPDATE_ALL)`**——升级 age 同时触发邻居更新。

**整体效果**：作物每被 random tick 抽中一次，~4% 概率长一阶。从 age 0 长到 7 平均需要 7 / 0.04 ≈ 175 次抽中。每个作物每秒被抽中概率约 0.07 × 20 = 1.4 次（randomTickSpeed=3 时）。**长大需要约 125 秒 ≈ 2 分钟**——和玩家直观体验一致。

## 4.2.4 isRandomlyTicking：性能关键

第 1.4.3 节看过 `LevelChunkSection.tickingBlockCount`——只在该计数器 > 0 时 section 才参与 random tick。计数器维护依赖 **`BlockState.isRandomlyTicking()`**。

```java
// BlockBehaviour
public boolean isRandomlyTicking(BlockState state) {
    return state.isRandomlyTicking();
}

// BlockBehaviour.BlockStateBase  
public boolean isRandomlyTicking() {
    return this.isRandomlyTicking;     // 缓存字段
}
```

`isRandomlyTicking` 是 BlockStateBase 的**预计算字段**，在 `populateNeighbours` 时填好（每个 BlockState 只算一次）。

**重写策略**：

- **静态**（每个 BlockState 总是 / 总不参与）：在 BlockBehaviour 子类重写 `isRandomlyTicking(BlockState)` 返回 true / false，BlockStateBase 自动同步缓存字段。
- **动态**（依属性变化）：见 CropBlock 的 `isRandomlyTicking(state) = state.getValue(AGE) < maxAge`——只有 age < 7 的 state 实例才参与。这是**节能优化**——成熟作物从计数器移出。

**效果**：一个 chunk section 含 100 个成熟作物 + 50 个半熟作物 → tickingBlockCount = 50。section 仍然参与 random tick，但每次抽到成熟作物的格子时它的 `state.isRandomlyTicking() == false`，被跳过。比"section 内每格都 randomTick"快得多。

## 4.2.5 SugarCaneBlock.tick：scheduled vs random

甘蔗示例：

```java
public class SugarCaneBlock extends Block {
    public static final IntegerProperty AGE = BlockStateProperties.AGE_15;     // 0..15
    
    @Override
    public boolean isRandomlyTicking(BlockState state) { return state.getValue(AGE) == 0; }     // ⋯
    
    @Override
    public void tick(BlockState state, ServerLevel level, BlockPos pos, RandomSource random) {
        if (!state.canSurvive(level, pos)) {
            level.destroyBlock(pos, true);
        }
    }
    
    @Override
    public void randomTick(BlockState state, ServerLevel level, BlockPos pos, RandomSource random) {
        if (level.getBlockState(pos.above()).isAir()) {
            int height = 1;
            while (level.getBlockState(pos.below(height)).is(this)) height++;
            if (height < 3) {
                int age = state.getValue(AGE);
                if (age == 15) {
                    level.setBlockAndUpdate(pos.above(), this.defaultBlockState());
                    level.setBlock(pos, state.setValue(AGE, 0), 4);
                } else {
                    level.setBlock(pos, state.setValue(AGE, age + 1), 4);
                }
            }
        }
    }
    
    @Override
    public BlockState updateShape(BlockState state, LevelReader level, ScheduledTickAccess access,
                                   BlockPos pos, Direction dir, BlockPos neighborPos, BlockState neighborState, RandomSource random) {
        if (!state.canSurvive(level, pos)) {
            access.scheduleTick(pos, this, 1);     // ★ 邻居变化 → 1 tick 后检查
        }
        return super.updateShape(state, level, access, pos, dir, neighborPos, neighborState, random);
    }
}
```

**SugarCane 用了 3 个钩子**：

- **`tick`** —— scheduled tick 触发，检查"我现在能存活吗"，不能就摧毁自己。
- **`randomTick`** —— random tick 触发，长高一阶。
- **`updateShape`** —— 邻居变化，schedule 一个 tick 在 1 tick 后检查 canSurvive。

**为什么 updateShape 不直接破坏自己**？因为 `updateShape` 不是 `Level.setBlock` 流，而是更细的"形状更新"。如果直接 break 会绕过 setBlock 的正常流程——可能漏掉 BlockEntity 清理 / 客户端同步。**先 schedule 一个 tick，让 setBlock 在 tick 内执行**——这是 Mojang 的标准 idiom。

## 4.2.6 PistonBlock.neighborChanged：触发 BlockEvent

```java
public class PistonBaseBlock extends DirectionalBlock {
    public static final BooleanProperty EXTENDED = BlockStateProperties.EXTENDED;
    
    @Override
    public void neighborChanged(BlockState state, Level level, BlockPos pos, ..., boolean movedByPiston) {
        if (!level.isClientSide && level.hasNeighborSignal(pos) != state.getValue(EXTENDED)) {
            level.setBlock(pos, state.cycle(EXTENDED), Block.UPDATE_NEIGHBORS);
            // ⋯
            level.blockEvent(pos, this, isExtending() ? EVENT_EXTEND : EVENT_RETRACT, ...);     // ★ 发 BlockEvent
        }
    }
    
    @Override
    public boolean triggerEvent(BlockState state, Level level, BlockPos pos, int eventId, int eventParam) {
        if (level instanceof ServerLevel serverLevel) {
            switch (eventId) {
                case EVENT_EXTEND:
                    // 实际推动方块
                    moveBlocks(serverLevel, pos, ...);
                    return true;
                case EVENT_RETRACT:
                    // 缩回
                    return true;
            }
        }
        return false;
    }
}
```

**两阶段**：

1. **`neighborChanged`**（同步）：只更新 EXTENDED 状态 + 发 BlockEvent。**不立刻推动**。
2. **`triggerEvent`**（下一 tick 第 9 步）：真正推动方块。

**为什么分两阶段**：推动会触发大量 setBlock，每个 setBlock 触发更多 neighborChanged。如果在 neighborChanged 内同步执行推动，会无限递归爆栈。延迟到 BlockEvent 让 stack 释放。

## 4.2.7 onPlace / onRemove：跨阶段钩子

```java
public class FurnaceBlock extends BaseEntityBlock {
    @Override
    public void onPlace(BlockState state, Level level, BlockPos pos, BlockState oldState, boolean movedByPiston) {
        if (!oldState.is(state.getBlock())) {
            // 创建 BlockEntity（已由 EntityBlock.newBlockEntity 自动调用）
            // 触发邻居更新（让红石线知道这有新源）
            for (Direction dir : Direction.values()) {
                level.updateNeighborsAt(pos.relative(dir), this);
            }
        }
    }
    
    @Override
    public void onRemove(BlockState state, Level level, BlockPos pos, BlockState newState, boolean movedByPiston) {
        if (!state.is(newState.getBlock())) {
            // 掉落 BlockEntity 内容
            BlockEntity be = level.getBlockEntity(pos);
            if (be instanceof FurnaceBlockEntity furnace) {
                Containers.dropContents(level, pos, furnace);
                level.updateNeighbourForOutputSignal(pos, this);
            }
            super.onRemove(state, level, pos, newState, movedByPiston);
        }
    }
}
```

**`onPlace` / `onRemove`**：在 Block 第一次出现 / 最后一次消失时调用。**用于 BlockEntity 创建 / 销毁 + 容器清理 + 邻居初始通知**。

**注意**：

- 同 Block 但不同 BlockState 之间转换（如 FACING 改变）**不触发** onPlace / onRemove。
- 这两个钩子在 `setBlock` 调用栈内被同步触发——不延迟。

## 4.2.8 完整调度时序

```
某段代码调 level.setBlock(pos, newState, UPDATE_ALL)
  │
  ▼
LevelChunk.setBlockState 改 PalettedContainer
  │
  ├── 旧 oldState.onRemove(level, pos, newState, isMoving)
  │       ↑ Block 第一次消失时调（如果 newState 不同 Block）
  │
  ├── 更新 heightmap / BlockEntity 创建（如果 newState 是 EntityBlock）
  │
  ├── 新 newState.onPlace(level, pos, oldState, isMoving)
  │       ↑ Block 第一次出现时调
  │
  ▼
Level.markAndNotifyBlock 后续：
  │
  │ if (UPDATE_NEIGHBORS in flags):
  ├── this.updateNeighborsAt(pos, sourceBlock)
  │       ↓ 对 6 邻居循环
  │       ├── neighborState.handleNeighborChanged(level, neighborPos, sourceBlock, ...)
  │       │       ↓ 调到具体 block
  │       │       └── Block.neighborChanged(neighborState, level, neighborPos, sourceBlock, ...)
  │       │             - 可能调 level.scheduleTick(...)（→ scheduled tick 队列）
  │       │             - 可能调 level.blockEvent(...)（→ block event 队列）
  │       │             - 可能调 level.setBlock(...)（→ 递归）
  │
  │ if (UPDATE_CLIENTS in flags):
  └── 把 BlockUpdate 加入 chunk 的"出包队列"
        下次 ChunkMap broadcast 时发给客户端
```

## 4.2.9 性能：钩子调用频率

```
单 chunk 单 tick:
- random tick 抽 3 次/section × 24 section × ticking section 比例 ≈ 5-30 次抽样 / chunk / tick
  其中"抽中且 isRandomlyTicking"约 0-5 次 → 0-5 次 randomTick 调用

- scheduled tick 处理（视方块密度）≈ 0-50 次 / chunk / tick
- block event 处理 ≈ 0-5 次 / chunk / tick

- neighbor update 由 setBlock 链触发，受玩家行为驱动。范围从 0（玩家不动）到几千（TNT 大爆炸）。
```

**neighbor update 是真正的不可预测项**——一些 mod 会做"巨型红石机"导致单 tick 几万次 neighbor update。1.21 的 `CollectingNeighborUpdater` 主要为这种场景设计（4.4 节）。

## 4.2.10 C++ 移植

```cpp
namespace mc::block {

class BlockBehaviour {
public:
    virtual ~BlockBehaviour() = default;
    
    virtual void tick(const BlockState& state, ServerLevel& level, BlockPos pos, RandomSource& random) {}
    virtual void randomTick(const BlockState& state, ServerLevel& level, BlockPos pos, RandomSource& random) {
        tick(state, level, pos, random);
    }
    
    virtual void neighborChanged(const BlockState& state, Level& level, BlockPos pos,
                                  Block* neighborBlock, std::optional<Orientation> orientation,
                                  bool movedByPiston) {}
    
    virtual void onPlace(const BlockState& state, Level& level, BlockPos pos,
                          const BlockState& oldState, bool movedByPiston) {}
    virtual void onRemove(const BlockState& state, Level& level, BlockPos pos,
                           const BlockState& newState, bool movedByPiston) {}
    
    virtual bool triggerEvent(const BlockState& state, Level& level, BlockPos pos,
                              int eventId, int eventParam) { return false; }
    
    virtual const BlockState* updateShape(const BlockState& state, LevelReader& level, ScheduledTickAccess& access,
                                            BlockPos pos, Direction dir, BlockPos neighborPos,
                                            const BlockState& neighborState, RandomSource& random) { 
        return &state; 
    }
    
    virtual bool isRandomlyTicking(const BlockState& state) { return false; }
};

}
```

**关键工程选择**：

1. **virtual function 即可**：钩子调用次数有限（每 chunk 每 tick < 100 次），vtable 开销不显著。
2. **`isRandomlyTicking` 必须高效**：被 chunk section 计数器频繁查询。把结果缓存到 BlockState 字段（同 Java）。
3. **`std::optional<Orientation>` 替代 `@Nullable`**：1.21 引入。

## 4.2.11 一句话总结

每个 BlockState 通过 `tick / randomTick / neighborChanged / onPlace / onRemove / triggerEvent / updateShape` 7 个钩子方法响应不同类的更新；`isRandomlyTicking` 缓存字段决定是否参与 random tick；具体 Block 子类（CropBlock / RepeaterBlock / PistonBlock）覆盖这些钩子实现行为；scheduled / random / neighbor / event 4 类机制对应 4 类钩子，可任意组合（如红石火把同时用 3 种）；`updateShape` 在邻居 setBlock 时同步调用，常用 `scheduleTick` 推迟实际处理避免栈级联。
