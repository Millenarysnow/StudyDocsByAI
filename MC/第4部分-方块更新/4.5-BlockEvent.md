# 4.5 BlockEvent

## 4.5.1 直觉：为什么活塞需要"延迟一 tick"

回顾 4.2.6：活塞被 redstone 信号激活时只调 `level.blockEvent(pos, this, EVENT_EXTEND, direction)`——**不立刻推方块**。

为什么？**因为推方块本身要触发大量 setBlock**：

- 活塞前的方块被推到下一格 → setBlock。
- 链式：如果链推 12 格，12 个 setBlock。
- 每个 setBlock 触发邻居更新（6 邻居）→ 72 次 neighborChanged。
- 邻居更新中可能触发更多 setBlock → 更多 neighbor → 递归。

**如果在 neighborChanged 钩子内同步推动方块**：

```
playerActivatesPiston
  → activated piston's neighborChanged
    → "我应该推动" → moveBlocks(...)
      → setBlock(pushedTarget1) → triggers more neighborChanged
        → another piston → moveBlocks
          → setBlock → more neighborChanged
            → another piston → ⋯
```

无限递归 / 爆栈 / 跨 tick 行为不一致。

**Mojang 的解法**：把推动**延迟**到下一 tick——存到队列、统一在 ServerLevel.tick 第 9 步执行：

```
[Tick T] 玩家激活活塞
  → setBlock (EXTENDED 属性 false → true) + level.blockEvent(...)
  → neighborChanged 链结束（方块没动，只是状态变了）
  
[Tick T+1] runBlockEvents 执行
  → triggerEvent(state, level, pos, EVENT_EXTEND, dir)
  → moveBlocks(...) → 真正推动
  → 推动产生的 setBlock 在 tick 第 9 步处理完
```

每 tick 的 BlockEvent 在固定时机集中执行——避免递归、保证确定性。

**视觉效果**：玩家激活活塞时**有 1 tick 延迟**（50 ms 的"卡顿"）。这是 Minecraft 著名的"活塞推动延迟"——历史包袱也是设计选择。

## 4.5.2 BlockEventData 数据结构

`net.minecraft.world.level.BlockEventData`（在 Level 包内）：

```java
public record BlockEventData(BlockPos pos, Block block, int paramA, int paramB) {
    // pos: 哪个方块
    // block: 哪种方块（用于校验）
    // paramA / paramB: 自定义参数（如活塞的方向）
}
```

**4 字段**——就这么简单。

---

## 4.5.3 ServerLevel 端的存储

```java
// ServerLevel
private final ObjectLinkedOpenHashSet<BlockEventData> blockEvents = new ObjectLinkedOpenHashSet<>();
private final List<BlockEventData> blockEventsToReschedule = new ArrayList<>(64);

public void blockEvent(BlockPos pos, Block block, int paramA, int paramB) {
    this.blockEvents.add(new BlockEventData(pos, block, paramA, paramB));
}
```

**`ObjectLinkedOpenHashSet`**：保留插入顺序的 hashset。同 (pos, block, paramA, paramB) 重复 add → 去重。

**为什么用 set 而不是 list**：去重——同一 tick 内对同一活塞多次激活只生成一个 BlockEvent。

## 4.5.4 runBlockEvents 入口

ServerLevel.tick 第 9 步：

```java
// ServerLevel.tick 行 367-369
profilerfiller.popPush("blockEvents");
if (flag) this.runBlockEvents();    // flag = !tickRateManager.isFrozen
```

`runBlockEvents` 实现：

```java
private void runBlockEvents() {
    this.blockEventsToReschedule.clear();
    while (!this.blockEvents.isEmpty()) {
        BlockEventData event = this.blockEvents.removeFirst();
        if (this.shouldTickBlocksAt(event.pos())) {
            if (this.doBlockEvent(event)) {
                // event handled successfully
                this.server.getPlayerList().broadcast(
                    null, event.pos().getX(), event.pos().getY(), event.pos().getZ(), 64.0,
                    this.dimension(),
                    new ClientboundBlockEventPacket(event.pos(), event.block(), event.paramA(), event.paramB())
                );
            }
        } else {
            // chunk 不在 ticking 范围，推到下次
            this.blockEventsToReschedule.add(event);
        }
    }
    this.blockEvents.addAll(this.blockEventsToReschedule);
}

private boolean doBlockEvent(BlockEventData event) {
    BlockState state = this.getBlockState(event.pos());
    return state.is(event.block()) && state.triggerEvent(this, event.pos(), event.paramA(), event.paramB());
}
```

**3 个关键步骤**：

1. **取出 BlockEvent** —— 按插入顺序 FIFO。
2. **检查 chunk 是否在 ticking 范围**（simulation distance 内）—— 不在则推到下次。
3. **`state.triggerEvent`** —— 调到具体 Block 的 `triggerEvent` 钩子（4.2.1 看过）。
4. **广播到客户端** —— 用 `ClientboundBlockEventPacket` 让客户端也跑同样事件（如活塞推动动画在客户端预测显示）。

## 4.5.5 BlockState.triggerEvent

回顾 4.2.6 PistonBaseBlock：

```java
@Override
public boolean triggerEvent(BlockState state, Level level, BlockPos pos, int eventId, int eventParam) {
    if (level instanceof ServerLevel serverLevel) {
        switch (eventId) {
            case EVENT_EXTEND:
                if (this.checkIfExtend(serverLevel, pos, state)) {
                    serverLevel.setBlock(pos, state.setValue(EXTENDED, true), 67);
                    serverLevel.playSound(...);
                    moveBlocks(serverLevel, pos, ...);    // ★ 推动
                }
                return true;
            case EVENT_RETRACT:
                // ⋯ 缩回
                return true;
            case EVENT_CANCELLED_MID_PUSH:
                // ⋯
                return true;
        }
    }
    return false;
}
```

**triggerEvent** 方法**返回 boolean**——告诉 ServerLevel "我处理了这事件"。

**返回 true** → ServerLevel 广播 `ClientboundBlockEventPacket` 给客户端。

**返回 false** → 事件无效（如方块已不存在）→ 不广播。

## 4.5.6 客户端的 BlockEvent

客户端收到 `ClientboundBlockEventPacket`：

```java
// ClientPacketListener.handleBlockEvent
public void handleBlockEvent(ClientboundBlockEventPacket packet) {
    BlockPos pos = packet.getPos();
    Block block = packet.getBlock();
    int paramA = packet.getParamA();
    int paramB = packet.getParamB();
    this.level.blockEvent(pos, block, paramA, paramB);
}

// ClientLevel.blockEvent
@Override
public void blockEvent(BlockPos pos, Block block, int paramA, int paramB) {
    this.getBlockState(pos).triggerEvent(this, pos, paramA, paramB);
}
```

**客户端立刻执行 triggerEvent**——不进队列、不延迟。

**为什么客户端不延迟**？因为客户端的 BlockEvent 是**响应服务端通知**——服务端已经决定了"现在要推动"，客户端只需要播放动画。延迟没意义。

**视觉效果**：服务端 tick T 时玩家激活活塞 → setBlock + blockEvent（队列）。Tick T+1 服务端 runBlockEvents → 真正推动 + 广播包。包到客户端 ~50-100 ms 后 → 客户端 triggerEvent 播放推动动画。**玩家感受到 ~100 ms 总延迟**。

## 4.5.7 持久化

`SerializableChunkData` 包含 BlockEvents 吗？

**答：不直接包含**——但 chunk 卸载时如果 BlockEvents 队列里有事件，会丢失。

实际：vanilla **不持久化** BlockEvents。原因：

- BlockEvents 队列里通常 0-10 个事件，瞬时性。
- 如果 chunk 卸载时有未处理 BlockEvent，玩家感知不到（chunk 卸载意味着玩家已远离）。
- 持久化代价大于价值。

**视觉效果**：玩家激活活塞 + 立刻退出 → 重进游戏发现活塞**没动**。这是已知现象。

## 4.5.8 主要使用者

vanilla 用 BlockEvent 的方块：

| 方块 | 事件 | 用途 |
|------|------|------|
| `PistonBaseBlock` / `MovingPistonBlock` | EXTEND / RETRACT / CANCELLED_MID_PUSH | 推 / 缩 / 中断 |
| `JukeboxBlock` | record_play | 播放唱片 |
| `BeaconBlock` | beacon_setup | beam 颜色变化 |
| `BellBlock` | bell_ring | 钟敲响 |
| `EndPortalBlock` / `EndGatewayBlock` | end_portal_animation | 末地传送门 |
| `ChestBlock` | chest_open / chest_close | 箱子打开 / 关闭动画 |
| `ConduitBlock` | conduit_animation | 海洋之心动画 |

**约 10-15 个 vanilla block 用 BlockEvent**——主要是"需要客户端动画 + 服务端逻辑"协调的方块。

## 4.5.9 完整时序：玩家激活活塞

```
[Tick T - server thread]
玩家放红石线对活塞 → 客户端发 ServerboundUseItemOnPacket
服务端 ServerGamePacketListener 处理 → 玩家放置红石线
  ↓
ServerLevel.setBlock(redstone_wire_pos, redstone_wire, UPDATE_ALL)
  ↓
LevelChunk 改 PalettedContainer
  ↓
neighborUpdater.updateNeighborsAtExceptFromFacing(redstone_wire_pos, ...)
  ↓ for 6 邻居：
neighborState.handleNeighborChanged(level, neighborPos, redstone_wire, ...)
  ↓ 假设其中一个邻居是 redstone_wire
redstone_wire.neighborChanged → 计算新强度 → setBlock
  ↓ 触发更多邻居 → 链式传播 → 信号到达活塞
  ↓
piston.neighborChanged
  ↓ 检查"我现在该推动吗"
level.blockEvent(piston_pos, piston, EVENT_EXTEND, direction)    ★
  ↓ blockEvents.add(BlockEventData(...))
  ↓
neighborChanged 链结束（活塞 EXTENDED 属性已改 + BlockEvent 已入队）
ServerLevel.tick 完成 tick T

[Tick T+1 - server thread]
ServerLevel.tick 第 9 步：runBlockEvents
  ↓
取出 piston BlockEvent
  ↓
piston.triggerEvent(state, level, pos, EVENT_EXTEND, direction)
  ↓
moveBlocks(...) → setBlock 链
  - 推动方块全部移到 +direction
  - 老位置变 air / piston_extension
  - 新位置变 pushed_block
  - 每个 setBlock 触发 neighborChanged 链
  ↓
broadcast ClientboundBlockEventPacket 给客户端

[Tick T+1 - render thread (客户端)]
ClientPacketListener.handleBlockEvent 收到包
  ↓
ClientLevel.blockEvent → triggerEvent
  ↓
客户端触发 piston 推动动画（lerp 0.5 秒）

[Tick T+1 + 100ms - 玩家屏幕]
玩家看到活塞开始推动
```

**总延迟**：玩家放红石线到看到活塞推动 ≈ 50ms (tick 间隔) + ~50ms (网络) ≈ **100 ms**。

这就是为什么 Minecraft 红石电路有"内在延迟"——不只是中继器配置的延迟，活塞推动本身就要 1 tick + 客户端动画时间。

## 4.5.10 限额

ServerLevel 没有显式 budget for runBlockEvents——它一次性处理所有事件。

**为什么不需要 budget**？因为 BlockEvent 数量天然小（< 100 / tick）—— 即使大型红石机器，每 tick 同时激活的活塞也少（活塞数 × 触发频率）。

**潜在风险**：如果某 mod 在 BlockEvent 内 schedule 大量新 BlockEvent，runBlockEvents 可能死循环。Mojang 没看到 vanilla 触发这种场景。

---

## 4.5.11 性能

```
单 BlockEvent 处理：~10 微秒（典型活塞）
单次 runBlockEvents：通常 < 10 events ≈ 100 微秒
极端场景：1000 events × 100 微秒 = 100 ms（可能让那 tick 超时）
```

BlockEvent 不是常见性能瓶颈。

---

## 4.5.12 内存预算

```
ObjectLinkedOpenHashSet<BlockEventData>: 每 entry ~50 字节
平均 < 50 entries → < 3 KB / tick
```

可忽略。

## 4.5.13 C++ 移植

```cpp
namespace mc::level {

struct BlockEventData {
    BlockPos pos;
    Block* block;
    int paramA;
    int paramB;
    
    bool operator==(const BlockEventData& other) const {
        return pos == other.pos && block == other.block && paramA == other.paramA && paramB == other.paramB;
    }
};

struct BlockEventDataHash {
    size_t operator()(const BlockEventData& d) const {
        size_t h1 = std::hash<BlockPos>{}(d.pos);
        size_t h2 = std::hash<Block*>{}(d.block);
        return h1 ^ (h2 << 1) ^ size_t(d.paramA) ^ size_t(d.paramB);
    }
};

class ServerLevel {
public:
    void blockEvent(BlockPos pos, Block* block, int paramA, int paramB) {
        BlockEventData event{pos, block, paramA, paramB};
        if (blockEventsSet_.insert(event).second) {
            blockEventsList_.push_back(event);
        }
    }
    
    void runBlockEvents() {
        std::vector<BlockEventData> rescheduled;
        while (!blockEventsList_.empty()) {
            BlockEventData event = blockEventsList_.front();
            blockEventsList_.pop_front();
            blockEventsSet_.erase(event);
            
            if (shouldTickBlocksAt(event.pos)) {
                if (doBlockEvent(event)) {
                    broadcastBlockEvent(event);
                }
            } else {
                rescheduled.push_back(event);
            }
        }
        for (auto& e : rescheduled) {
            blockEventsList_.push_back(e);
            blockEventsSet_.insert(e);
        }
    }
    
private:
    std::deque<BlockEventData> blockEventsList_;     // 保持插入顺序
    std::unordered_set<BlockEventData, BlockEventDataHash> blockEventsSet_;     // 去重
    
    bool doBlockEvent(const BlockEventData& event) {
        const BlockState* state = getBlockState(event.pos);
        return state->getBlock() == event.block && 
               state->triggerEvent(*this, event.pos, event.paramA, event.paramB);
    }
};

}
```

**关键工程选择**：

1. **`std::deque` + `std::unordered_set`** 双结构 = ObjectLinkedOpenHashSet 等价物。
2. **`BlockEventData` record-like struct** + 自定义 hash。
3. **`broadcastBlockEvent`** 通过网络层发 ClientboundBlockEventPacket。

---

## 4.5.14 一句话总结

`BlockEvent` 是"延迟一 tick 的副作用"机制——`level.blockEvent(pos, block, paramA, paramB)` 把事件存到 ServerLevel 的 ObjectLinkedOpenHashSet（保留插入顺序 + 去重），下一 tick 第 9 步 `runBlockEvents` 统一执行，调每方块的 `triggerEvent` 钩子；主要给活塞推动 / 唱片机播放 / 信标 beam / 钟敲响等"客户端动画 + 服务端逻辑协调"的方块用；处理后通过 `ClientboundBlockEventPacket` 广播给客户端，客户端立刻执行同样事件触发动画；vanilla 不持久化 BlockEvent（chunk 卸载会丢失）；玩家感知的总延迟约 100 ms（tick 50 ms + 网络 50 ms）。
