```

玩家挖方块 → 客户端预测 setBlock(pos, AIR, UPDATE_ALL | UPDATE_INVISIBLE)
            ↓

[Server tick T+0 ~ T+1 - server thread]

  ServerLevel.setBlock(pos, AIR, flags)

    ├── 维护 heightmap
    ├── BlockEntity 处理
    └── 标 unsaved
    ↓

    NeighborUpdater (CollectingNeighborUpdater BFS):
      ↓
    周围 6 邻居 → BlockState.handleNeighborChanged
      ↓ 具体 Block.neighborChanged 钩子
      ↓ 可能调:
      ├── level.scheduleTick(...)        → LevelTicks.schedule

      └── 其他副作用

  Step 6: blockTicks.tick(gameTime, 65536, this::tickBlock)    [scheduled tick]
            ↓ 对每个 ScheduledTick:
            BlockState.tick(level, pos, random) → 执行 Block 子类的 tick 钩子

  Step 8: chunkSource.tick → for each section, randomTick      [random tick]

[Client tick T+1+网络延迟]

  - 收 ClientboundBlockUpdatePacket → ClientLevel.setBlock 显示新方块
  - 收 ClientboundBlockEventPacket → ClientLevel.blockEvent → 立即 triggerEvent 触发动画
```

```cpp
namespace mc::server {

class ServerLevel : public Level {
public:
    void tick(std::function<bool()> haveTime) {
        bool normal = tickRateManager_->runsNormally();
        // 12 步主循环
        if (normal) {
            advanceWeatherCycle();
            handlePlayerSleeping();
            updateSkyBrightness();
            tickTime();        // gameTime++
            
            // Step 6: scheduled tick
            blockTicks_.tick(gameTime_, MAX_BLOCK_TICKS, [this](BlockPos pos, Block* block) {
                tickBlock(pos, block);
            });
            fluidTicks_.tick(gameTime_, MAX_FLUID_TICKS, [this](BlockPos pos, Fluid* fluid) {
                tickFluid(pos, fluid);
            });
        }
        
        raids_.tick();
        
        // Step 8: random tick (chunkSource.tick 内调用 tickChunk)
        chunkSource_->tick(haveTime, true);
        
        // Step 9: block events
        if (normal) runBlockEvents();
        
        // Step 10-12: entity tick
        // ⋯
    }
    
    void scheduleTick(BlockPos pos, Block* block, int delay, TickPriority priority = TickPriority::NORMAL) {
        if (!isClientSide()) {
            blockTicks_.schedule(pos, block, delay, priority);
        }
    }
    
    void blockEvent(BlockPos pos, Block* block, int paramA, int paramB) {
        BlockEventData event{pos, block, paramA, paramB};
        if (blockEventsSet_.insert(event).second) {
            blockEventsList_.push_back(event);
        }
    }
    
private:
    LevelTicks<Block> blockTicks_;
    LevelTicks<Fluid> fluidTicks_;
    std::deque<BlockEventData> blockEventsList_;
    std::unordered_set<BlockEventData, BlockEventDataHash> blockEventsSet_;
    
    void tickBlock(BlockPos pos, Block* block) {
        const BlockState* state = getBlockState(pos);
        if (state->getBlock() == block) {
            state->getBlock()->tick(*state, *this, pos, random_);
        }
    }
    
    void runBlockEvents();     // 详见 4.5
};

// 4.4 Level.setBlock
namespace mc::level {

class Level {
public:
    bool setBlock(BlockPos pos, const BlockState* newState, int flags, int recursion = 512) {
        LevelChunk* chunk = getChunkAt(pos);
        const BlockState* oldState = chunk->setBlockState(pos, newState, flags & BlockUpdateFlags::MOVE_BY_PISTON);
        if (oldState == nullptr || oldState == newState) return false;
        
        if (flags & BlockUpdateFlags::CLIENTS) {
            if ((flags & BlockUpdateFlags::INVISIBLE) == 0 || !isClientSide()) {
                sendBlockUpdated(pos, oldState, newState, flags);
            }
        }
        
        if (oldState->getBlock() != newState->getBlock()) {
            oldState->onRemove(*this, pos, newState, flags & BlockUpdateFlags::MOVE_BY_PISTON);
            newState->onPlace(*this, pos, oldState, flags & BlockUpdateFlags::MOVE_BY_PISTON);
        }
        
        if (flags & BlockUpdateFlags::NEIGHBORS) {
            updateNeighborsAt(pos, newState->getBlock());
        }
        
        if (!(flags & BlockUpdateFlags::KNOWN_SHAPE) && recursion > 0) {
            updateNeighbourShapesAt(pos, newState, recursion - 1);
        }
        
        return true;
    }
    
    void scheduleTick(BlockPos pos, Block* block, int delay, TickPriority priority = TickPriority::NORMAL) {
        if (!isClientSide()) {
            // 转发给具体 ServerLevel
            static_cast<ServerLevel*>(this)->scheduleTick(pos, block, delay, priority);
        }
    }
    
    void blockEvent(BlockPos pos, Block* block, int paramA, int paramB) {
        // ⋯
    }
    
protected:
    std::unique_ptr<NeighborUpdater> neighborUpdater_;
    
    void updateNeighborsAt(BlockPos pos, Block* sourceBlock) {
        neighborUpdater_->updateNeighborsAtExceptFromFacing(pos, sourceBlock, std::nullopt, std::nullopt);
    }
};

}
```

## 4.9.4 关键设计决策

### 决策 1：4 类更新分离

**好处**：每类独立调度、独立持久化、性能特性独立。
**代价**：方块开发者要学 4 个钩子。Mojang 的复杂方块（活塞、红石）确实用多个钩子。

### 决策 2：BFS 替代递归 (CollectingNeighborUpdater)

**好处**：避免 1000+ 格红石电路爆栈。
**代价**：实现复杂度高。但只是一次性投入。

### 决策 3：scheduled tick 的 PriorityQueue + HashSet 双结构

**好处**：去重 + 优先级 + 确定性顺序兼得。
**代价**：内存稍多（每 entry 双倍存储）。

### 决策 4：客户端不跑 scheduled tick

**好处**：客户端简单 + 服务端权威。
**代价**：客户端需要从网络包学习"方块状态变化"——增加带宽。

### 决策 5：65536 budget 不丢弃只延迟

**好处**：水位炸弹只是慢，不数据丢失。
**代价**：服务端可能积压几分钟才清队列——TPS 低期。

## 4.9.5 ECS vs OOP 选择

### 4 类更新机制中的 ECS 友好程度

- **scheduled tick**：每 tick 处理 ~几十到几千个独立任务。**ECS 友好**——可以批处理。
- **random tick**：每 section 抽 3 个独立位置。**ECS 友好**。
- **neighbor update**：高度依赖具体 BlockState 行为。**OOP 更合适**——virtual function 自然分发。
- **block event**：少量、独立。**ECS / OOP 都行**。

### 推荐：混合方案

- BlockBehaviour 子类：**OOP**——~1100 个 Block 子类，每个少量虚方法。
- 计数器 / mob 索引：**ECS-style 列存**——把"哪些 chunk section 含 ticking blocks"写进 bitset，遍历时无 cache miss。
- 实体（玩家、怪物）：**ECS**——对 entity tick / collision 的优化关键。详见 Module 4 entity 部分（本教程未展开）。

## 4.9.6 并发策略

### Server 主线程独占

主线程拥有 ServerLevel 的所有 mutable 状态——chunk / tick queue / blockEvents / entity。**所有改动只能在主线程**。

### 网络线程接收

Netty 线程接收 packet → 提交到主线程 ServerGamePacketListener 处理。**不直接修改世界**——通过队列同步。

### IO 线程后台

IOWorker 负责 chunk save/load——独立线程。**不直接修改 ServerLevel** —— 通过 Future 传递 chunk 数据。

### 没有锁吗？

主线程独占设计**避开了大部分 lock**。但有少数地方：
- ChunkMap.entityTickingChunks 用并发集合（多线程 access）。
- Connection 的 packet queue 用并发队列。

**整体而言 Mojang 的 ServerLevel 是 single-threaded heavy** —— 简单但限制了 multi-core 利用率。Spark / Folia 等性能 mod 探索 multi-threaded ServerLevel，复杂度爆炸式上升。

## 4.9.11 一句话总结
