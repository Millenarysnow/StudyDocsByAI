# 第 1 部分 · 数据结构基石 —— 导读

## 你为什么需要先读这一部分

第 0 部分给了你**世界观**：坐标怎么算、tick 怎么走、客户端 / 服务端怎么分工、resource 怎么命名、JSON 怎么读、反编译怎么读。

第 1 部分给你**实物**：当那些"世界观"具体落地到内存里的时候，到底是一些什么数据结构？一个 chunk 在内存里**长什么样**？一个方块到底**占几个字节**？为什么"橡木原木朝向 Y 轴"和"橡木原木朝向 X 轴"是两个不同的对象但又共享同一个 `Block`？

这一部分还是不讲算法（worldgen / 红石 / 流体那些都是后面的事）。它只回答**「数据 layout 是什么样」**这一个问题。读完它你应当能：

1. 在脑子里画出一个 chunk 的内存图，每个字段的字节占用、用途、生命周期都说得清。
2. 看到 `BlockState` / `Block` / `StateHolder` / `Property` 不再混淆。
3. 看到 `PalettedContainer<BlockState>` 知道它内部三种 palette + 一个 BitStorage 的几何含义。
4. 知道为什么生成期用 `ProtoChunk`、运行期用 `LevelChunk`，以及它们怎么转换。
5. 读 Module 2（NBT 存档）时知道 chunk 序列化要写什么，对照 1.x 给出的内存图能直接画出磁盘 layout。
6. 读 Module 3（worldgen）时不再被 "ChunkAccess" "ProtoChunk.markPosForPostprocessing" 之类的字眼吓到。
7. 读 Module 7（网络）时知道 `ClientboundLevelChunkWithLightPacket` 在序列化哪些字段。

## 它和其它部分的关系

```
第 0 部分（已完成）
        │
        ▼
第 1 部分（你在这里）  ← 数据结构 layout
        │
        ▼
        ├──→ 第 2 部分  NBT / Region 存档（把这些数据写入磁盘）
        ├──→ 第 3 部分  地形生成（往这些数据结构里写入初始内容）
        ├──→ 第 4 部分  方块更新（修改这些数据结构）
        ├──→ 第 5 部分  红石（特化的方块更新）
        ├──→ 第 6 部分  流体（特化的方块更新）
        └──→ 第 7 部分  网络（同步这些数据结构的变更）
```

**这是后面 6 个模块共同依赖的地基**。如果你把它读虚了，后面会反复回来补课。值得多花时间。
