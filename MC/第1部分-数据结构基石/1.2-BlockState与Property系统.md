## 1.2.1 直觉：为什么需要"状态"

上一节我们看到 `Blocks.OAK_LOG` 是一个全局 singleton 描述"橡木原木这个类型"。但世界里同样是橡木原木，可能有不同的具体形态：

- **朝向**：橡木原木可以朝 X、Y、Z 三个轴向放置（`AXIS = X / Y / Z`）。
- **充填**：很多方块可以"充水"（`WATERLOGGED = true / false`）—— 板砖、楼梯、栅栏、树叶都可以充水。
- **状态机阶段**：作物有 0..7 的成熟度（`AGE`），熔炉有"在烧" / "没在烧"（`LIT`），中继器有 1..4 tick 延迟（`DELAY`）。
- **形态**：栅栏会自动连接相邻方块（`NORTH = true, SOUTH = false, EAST = true, WEST = false`），活塞推出还是缩回（`EXTENDED`）。

**这些都不是新方块类型**——它们都是同一个 `Block` 的不同**配置**。Mojang 把这种"类型 + 一组属性值"的组合叫做 **BlockState**（方块状态）。

**核心设计选择**：BlockState 是 **immutable** 的，**全游戏所有可能的 BlockState 在游戏启动时就一次性穷举创建完毕**，运行时只共享指针 / 引用，**永远不 new BlockState**。

为什么这样选？两个理由：

1. **内存**：世界里有 10^8 量级的方块格子，每格存一个 BlockState 引用而不是一个 BlockState 实例，省 99% 内存。
2. **性能**：immutable 共享让 `==` 比较等价于身份比较（一条指令），不需要属性逐一对比。这对 chunk palette / 网络同步是性命攸关的优化。

## 1.2.2 BlockState 类的真身（很简单）

打开 `net.minecraft.world.level.block.state.BlockState`：

```java
public class BlockState extends BlockBehaviour.BlockStateBase {

    public BlockState(
```

## 1.2.3 StateHolder：state 的内存形态

打开 `net.minecraft.world.level.block.state.StateHolder`（行 18-44）：

```java
public abstract class StateHolder<O, S> {
    public static final String NAME_TAG = "Name";
    public static final String PROPERTIES_TAG = "Properties";

    protected final O owner;                                          // 拥有者：Block 实例
    private final Reference2ObjectArrayMap<Property<?>, Comparable<?>> values; // 属性 = 值
    private Map<Property<?>, S[]> neighbours;                         // 邻居跳转表
    protected final MapCodec<S> propertiesCodec;
}
```

四个字段。

### `O owner`：指回 Block

每个 BlockState 都知道自己属于哪个 Block。`block.OAK_LOG` 拥有 3 个 BlockState（AXIS=X/Y/Z），每个 BlockState 的 `owner` 字段都指向 OAK_LOG。

### `Reference2ObjectArrayMap<Property<?>, Comparable<?>> values`

**这是 BlockState 的"配置内容"**：当前 BlockState 的所有属性 → 当前值。

例如朝 Y 轴的橡木原木的 values 内容：

```
{ AXIS -> Direction.Axis.Y }
```

充水的橡木楼梯（`OakStairsBlock`）的 values：

```
{
    FACING       -> Direction.NORTH,
    HALF         -> Half.BOTTOM,
    SHAPE        -> StairsShape.STRAIGHT,
    WATERLOGGED  -> true
}
```

**为什么用 `Reference2ObjectArrayMap`？** 这是 fastutil 提供的一种 map：

1. **基于数组**而不是 hashmap—— 属性数量少（通常 ≤ 5），数组扫描比 hashmap 散列快。
2. **Reference2** = key 比较用 `==` 而不是 `.equals()`—— Property 是 singleton，身份比较即可。
3. **Open** = 开放寻址，更紧凑。

**对一个属性少的方块（如 STONE 没有任何属性）**，`values` 是一个空 ArrayMap，几乎不占空间。

### `Map<Property<?>, S[]> neighbours` —— 这是真正聪明的设计

**问题**：BlockState 是 immutable 的。`state.setValue(AXIS, Direction.Axis.X)` 必须返回**另一个** BlockState 实例。但 immutable 的 BlockState 都在启动时穷举好了，怎么 O(1) 找到那个对应的实例？

**Mojang 的解法**：在启动时，给每个 BlockState 预计算一张"邻居表"。

`neighbours[property]` 是一个数组，长度 = 该 property 的所有可能值数量。`neighbours[AXIS]` 长度 3：

```
neighbours[AXIS][0] -> 状态对应 AXIS=X 的 BlockState 实例
neighbours[AXIS][1] -> 状态对应 AXIS=Y 的 BlockState 实例
neighbours[AXIS][2] -> 状态对应 AXIS=Z 的 BlockState 实例
```

对于"自己当前是 AXIS=Y 的橡木原木"，`neighbours[AXIS][1]` 是它本身（因为 setValue(Y) 不变），`neighbours[AXIS][0]` 和 `[2]` 是另两个橡木原木实例。

**setValue 的实现**（`StateHolder` 行 99-126）：

```java
public <T extends Comparable<T>, V extends T> S setValue(Property<T> p_61125_, V p_61126_) {
    Comparable<?> comparable = this.values.get(p_61125_);
    if (comparable == null) {
        throw new IllegalArgumentException("...");
    } else {
        return this.setValueInternal(p_61125_, p_61126_, comparable);
    }
}

private <T, V> S setValueInternal(Property<T> property, V newValue, Comparable<?> oldValue) {
    if (oldValue.equals(newValue)) {
        return (S)this;                               // 1. 没变化：返回自己
    } else {
        int i = property.getInternalIndex((T)newValue); // 2. 把新值翻译成数组下标
        if (i < 0) {
            throw new IllegalArgumentException("...");
        } else {
            return (S)this.neighbours.get(property)[i];  // 3. 直接查邻居表
        }
    }
}
```

**整个 setValue 是 O(1)**：

1. 查当前值（ArrayMap 线性扫描，但属性 ≤ 5，常数时间）。
2. 把新值翻译成 0-based 下标（属性内部预存的索引）。
3. 直接 `neighbours[property][index]` 数组下标。

**没有 new。没有分配。** 只是返回另一个早已存在的共享实例。

## 1.2.4 启动时怎么穷举所有 state

打开 `StateDefinition` 构造函数（行 33-73）：

```java
protected StateDefinition(
    Function<O, S> stateFactoryHelper,
    O owner,                                        // 该 Block 实例
    StateDefinition.Factory<O, S> stateFactory,
    Map<String, Property<?>> properties             // 注册的所有属性
) {
    this.owner = owner;
    this.propertiesByName = ImmutableSortedMap.copyOf(properties);
    // ... 构造 propertiesCodec ...

    Map<Map<Property<?>, Comparable<?>>, S> map = Maps.newLinkedHashMap();
    List<S> list = Lists.newArrayList();
    Stream<List<Pair<Property<?>, Comparable<?>>>> stream = Stream.of(Collections.emptyList());

    // ★★★ 笛卡尔积穷举 ★★★
    for (Property<?> property : this.propertiesByName.values()) {
        stream = stream.flatMap(prefix -> property.getPossibleValues().stream().map(value -> {
            List<Pair<Property<?>, Comparable<?>>> entry = Lists.newArrayList(prefix);
            entry.add(Pair.of(property, value));
            return entry;
        }));
    }

    stream.forEach(combination -> {
        Reference2ObjectArrayMap<Property<?>, Comparable<?>> attributes = new Reference2ObjectArrayMap<>(combination.size());
        for (Pair<Property<?>, Comparable<?>> pair : combination) {
            attributes.put(pair.getFirst(), pair.getSecond());
        }
        S state = stateFactory.create(owner, attributes, mapcodec1);
        map.put(attributes, state);
        list.add(state);
    });

    // ★★★ 给所有 state 计算 neighbours 表 ★★★
    for (S s : list) {
        s.populateNeighbours(map);
    }

    this.states = ImmutableList.copyOf(list);
}
```

逐段：

### 笛卡尔积穷举

代码用 Java Stream `flatMap` 实现笛卡尔积：

- 起点：`Stream.of(emptyList)` —— 一个空组合。
- 第一个属性 AXIS（3 个值）：流变成 3 个 `[(AXIS, X)]`、`[(AXIS, Y)]`、`[(AXIS, Z)]`。
- 第二个属性 WATERLOGGED（2 个值）：流变成 6 个 `[(AXIS, X), (WL, F)]`、`[(AXIS, X), (WL, T)]`、⋯⋯
- 以此类推。

最后流里的每一项是该 Block 的一种**完整属性组合**。`forEach` 把每个组合 → 一个 BlockState 实例。

**对橡木原木**：1 个属性 AXIS × 3 值 = **3 个 BlockState**。
**对橡木楼梯**：FACING(4) × HALF(2) × SHAPE(5) × WATERLOGGED(2) = **80 个 BlockState**。
**对铁栅栏**：NORTH(2) × SOUTH(2) × EAST(2) × WEST(2) × WATERLOGGED(2) = **32 个 BlockState**。

vanilla 1.21 总共 **约 26000 个 BlockState**。它们全部在启动时一次性创建。

**每个 BlockState 内存开销**约 200-300 字节（包括 values map + neighbours 数组）。26000 × 250 B ≈ 6.5 MB。

### populateNeighbours

`StateHolder.populateNeighbours`（行 128-141）：

```java
public void populateNeighbours(Map<Map<Property<?>, Comparable<?>>, S> allStates) {
    Map<Property<?>, S[]> map = new Reference2ObjectArrayMap<>(this.values.size());

    for (Entry<Property<?>, Comparable<?>> entry : this.values.entrySet()) {
        Property<?> property = entry.getKey();
        S[] array = (S[])property.getPossibleValues().stream()
            .map(value -> allStates.get(this.makeNeighbourValues(property, value)))
            .toArray();
        map.put(property, array);
    }
    this.neighbours = map;
}

private Map<Property<?>, Comparable<?>> makeNeighbourValues(Property<?> changeProp, Comparable<?> newValue) {
    Map<Property<?>, Comparable<?>> map = new Reference2ObjectArrayMap<>(this.values);
    map.put(changeProp, newValue);
    return map;
}
```

对每个属性 P：

1. 枚举该属性的所有可能值 V。
2. 把当前 state 的 values **复制一份**，把 P 改成 V，得到一个新的"目标 values" map。
3. 用这个 map 在 `allStates`（构造时收集到的"values map → state 实例"映射）里查到目标 BlockState。
4. 把所有目标存进数组。

最终每个 BlockState 都有一张完整的 `neighbours` 表，`O(1)` 跳转到任何属性变化后的状态。

**这是一种空间换时间**——每个 state 多存几个数组，换来运行时 setValue 永不分配。**对 BlockState 这种"高频读、零分配"的场景完美**。

## 1.2.5 Property：属性的三种类型

打开 `net.minecraft.world.level.block.state.properties.Property`：

```java
public abstract class Property<T extends Comparable<T>> {
    private final Class<T> clazz;
    private final String name;
    private final Codec<T> codec = Codec.STRING.comapFlatMap(...);
    private final Codec<Property.Value<T>> valueCodec = ...;

    protected Property(String name, Class<T> clazz) { ... }

    public abstract List<T> getPossibleValues();
    public abstract String getName(T value);
    public abstract Optional<T> getValue(String name);
    public abstract int getInternalIndex(T value);
}
```

抽象类。三个具体子类：

### `BooleanProperty`：true / false

```java
public class BooleanProperty extends Property<Boolean> {
    public static BooleanProperty create(String name);
    @Override public List<Boolean> getPossibleValues() { return List.of(true, false); }
}
```

最简单。每个 BooleanProperty 实例覆盖 `{true, false}` 两个值。

**典型用法**：

```java
public static final BooleanProperty WATERLOGGED = BooleanProperty.create("waterlogged");
public static final BooleanProperty LIT = BooleanProperty.create("lit");
public static final BooleanProperty PERSISTENT = BooleanProperty.create("persistent");
public static final BooleanProperty NORTH = BooleanProperty.create("north");
public static final BooleanProperty POWERED = BooleanProperty.create("powered");
```

注意**这些都是 singleton 实例**——同一个 `WATERLOGGED` 实例在所有可充水方块上共享。这让 BlockState 内的 `values` map 里的 key 比较走 `==` 而不是 `.equals()`，更快。

### `IntegerProperty`：连续整数区间

```java
public class IntegerProperty extends Property<Integer> {
    public static IntegerProperty create(String name, int min, int max);
    private final List<Integer> values;  // [min..max] 全部整数
}
```

例：

```java
public static final IntegerProperty AGE_7 = IntegerProperty.create("age", 0, 7);
public static final IntegerProperty AGE_15 = IntegerProperty.create("age", 0, 15);
public static final IntegerProperty STAGE = IntegerProperty.create("stage", 0, 1);
public static final IntegerProperty POWER = IntegerProperty.create("power", 0, 15);
public static final IntegerProperty DELAY = IntegerProperty.create("delay", 1, 4);
public static final IntegerProperty DISTANCE = IntegerProperty.create("distance", 1, 7);
public static final IntegerProperty MOISTURE = IntegerProperty.create("moisture", 0, 7);
```

**注意**多个名为 "age" 的 IntegerProperty——它们看似名字相同但**对应不同范围**，所以是不同 singleton 实例。一个方块只用其中之一（小麦用 AGE_7，胡萝卜用 AGE_7，南瓜茎用 AGE_7，竹子用 AGE_15）。

### `EnumProperty<E>`：自定义枚举

```java
public class EnumProperty<T extends Enum<T> & StringRepresentable> extends Property<T> {
    public static <T extends Enum<T> & StringRepresentable> EnumProperty<T> create(
        String name, Class<T> clazz);
    public static <T extends Enum<T> & StringRepresentable> EnumProperty<T> create(
        String name, Class<T> clazz, T... allowedValues);
}
```

例：

```java
public static final EnumProperty<Direction> FACING = ...;             // 6 values
public static final EnumProperty<Direction> HORIZONTAL_FACING = ...;  // 4 values
public static final EnumProperty<Direction.Axis> AXIS = ...;          // 3 values
public static final EnumProperty<Direction.Axis> HORIZONTAL_AXIS = ...; // 2 values
public static final EnumProperty<Half> HALF = ...;                    // TOP / BOTTOM
public static final EnumProperty<StairsShape> SHAPE = ...;            // 5 values
public static final EnumProperty<DoubleBlockHalf> DOUBLE_BLOCK_HALF = ...;
public static final EnumProperty<RailShape> RAIL_SHAPE = ...;
```

枚举类型必须实现 `StringRepresentable`（提供 `getSerializedName()`）以便序列化为字符串。

`create(name, clazz, T... allowedValues)` 重载允许只用 enum 的部分值。例如 `HORIZONTAL_FACING` 只用 NORTH/SOUTH/EAST/WEST 4 个，不要 UP/DOWN。


**Block 子类引用这些公共属性，而不是自己声明**：

```java
public class CampfireBlock extends BaseEntityBlock {
    public static final BooleanProperty LIT = BlockStateProperties.LIT;
    public static final BooleanProperty SIGNAL_FIRE = BlockStateProperties.SIGNAL_FIRE;
    public static final BooleanProperty WATERLOGGED = BlockStateProperties.WATERLOGGED;
    public static final EnumProperty<Direction> FACING = BlockStateProperties.HORIZONTAL_FACING;
    
    @Override
    protected void createBlockStateDefinition(StateDefinition.Builder<Block, BlockState> builder) {
        builder.add(LIT, SIGNAL_FIRE, WATERLOGGED, FACING);
    }
}
```

`createBlockStateDefinition` 由父类 `Block` 在构造期间调用，让子类把自己关心的属性注册进 `StateDefinition`。

## 1.2.7 完整链：从声明到内存中的 BlockState

把构造期发生的事情按时序串起来。以**营火（CampfireBlock）**为例：

```
启动时 Blocks.<clinit> 执行：

1. 构造 BlockBehaviour.Properties
   props = Properties.of().mapColor(...).strength(...).lightLevel(...).noOcclusion();

2. new CampfireBlock(props):
   2a. super(props) → BlockBehaviour 构造
   2b. 调 createBlockStateDefinition(builder):
       builder.add(LIT, SIGNAL_FIRE, WATERLOGGED, FACING);
   2c. StateDefinition 构造期间：
       笛卡尔积穷举 LIT(2) × SIGNAL_FIRE(2) × WATERLOGGED(2) × FACING(4) = 32 个 BlockState
       每个 BlockState 都被加入 BLOCK_STATE_REGISTRY 全局 ID 表
       每个 BlockState populateNeighbours，建立 O(1) 跳转表
   2d. registerDefaultState(states.any().with(LIT, true)...);
   2e. 把这些状态全部加入全局 BLOCK_STATE_REGISTRY

3. register("campfire", block) 把 block 注册到 BuiltInRegistries.BLOCK
4. Blocks.CAMPFIRE = block;

启动后：
- Blocks.CAMPFIRE 是单一 Block 实例。
- 它的 stateDefinition 持有 32 个 BlockState 实例的 immutable list。
- 32 个 BlockState 全部在全局 BLOCK_STATE_REGISTRY 里有整数 ID。
- 每个 BlockState 自己有 neighbours 表，setValue O(1)。
- 运行时世界里"放营火"= 在 chunk section 写入这 32 个实例之一的引用。
```

整个 vanilla 启动后，全部 26000 个 BlockState 已就位、全部 ID 已分配、全部 neighbours 表已填好。**运行时不会再创建任何 BlockState 实例**。

## 1.2.8 BlockState 的查询 API

最常用的查询：

```java
// 1. 获取某属性的当前值
boolean lit = state.getValue(CampfireBlock.LIT);
Direction facing = state.getValue(CampfireBlock.FACING);
int age = state.getValue(CropBlock.AGE);

// 2. 切换属性（返回另一个 BlockState 实例，O(1)）
BlockState newState = state.setValue(CampfireBlock.LIT, false);

// 3. 循环切换（"下一个值"，对 enum / int 做 mod）
BlockState rotated = state.cycle(CampfireBlock.FACING);  // NORTH → EAST → SOUTH → WEST → NORTH

// 4. 检查是否有某属性
if (state.hasProperty(BlockStateProperties.WATERLOGGED)) {
    boolean wl = state.getValue(BlockStateProperties.WATERLOGGED);
}

// 5. 取所有属性
Collection<Property<?>> properties = state.getProperties();

// 6. 拿到 owner Block
Block block = state.getBlock();

// 7. 等价比较
state == otherState   // 身份比较，因为 immutable + 共享
state.equals(other)   // 等价
```

**`==` 比较是合法的**——这是这套设计的最大红利。chunk section 内部、网络包同步、palette 转换全部利用了这一点。

## 1.2.9 字符串表示与 NBT 序列化

BlockState 的字符串形式：

```
minecraft:campfire[facing=north,lit=true,signal_fire=false,waterlogged=false]
```

`StateHolder.toString()`（行 56-66）就是这个格式的来源：

```java
@Override
public String toString() {
    StringBuilder sb = new StringBuilder();
    sb.append(this.owner);                            // "minecraft:campfire"
    if (!this.getValues().isEmpty()) {
        sb.append('[');
        sb.append(this.getValues().entrySet().stream()
            .map(PROPERTY_ENTRY_TO_STRING_FUNCTION)   // "facing=north"
            .collect(Collectors.joining(",")));
        sb.append(']');
    }
    return sb.toString();
}
```

**NBT 序列化**：在存档里，每个 chunk section 的 palette 把每个 BlockState 写成：

```
{
    Name: "minecraft:campfire",
    Properties: {
        facing: "north",
        lit: "true",
        signal_fire: "false",
        waterlogged: "false"
    }
}
```

**所有属性值都是字符串**——boolean 是 "true"/"false"、enum 是 enum 的 serialized name、integer 是数字字符串。这保证了跨版本兼容性（属性名加减、值改名都能 fix 过去）。

`StateHolder.codec(...)` 提供这个序列化（行 153-164）。后面 Module 2 NBT 章节会展开。

## 1.2.10 反向查询：从 string 到 BlockState

游戏内 `/setblock 10 64 10 minecraft:oak_log[axis=x]` 命令 / datapack 的 block predicate 等地方需要从字符串解析 BlockState。`BlockStateParser` 类负责：

```java
BlockStateParser parser = new BlockStateParser(reader, false);
BlockStateParser.BlockResult result = parser.parse();
BlockState state = result.blockState();
```

它逐字符解析 `namespace:path[key=value,...]`，对每个 `key=value` 调对应 Property 的 `Property.getValue(String)`，最终返回 `Block.defaultBlockState().setValue(prop1, val1).setValue(prop2, val2)...`。

## 1.2.11 字面量"any"：StateDefinition.any()

```java
state = block.getStateDefinition().any();
```

`StateDefinition.any()` 返回**该 Block 穷举出的第一个 BlockState**——并不一定是 default。它常用于在 Block 子类构造里搭一个"基底"，然后链式 `.setValue` 出 default：

```java
this.registerDefaultState(this.stateDefinition.any()
    .setValue(LIT, true)
    .setValue(WATERLOGGED, false));
```

读到 `stateDefinition.any()` 心里念："任意一个 BlockState 实例，作为链式 setValue 的起点"。

## 1.2.12 内存预算

按一个 BlockState 的实际占用估算：

```
BlockState 实例（64-bit JVM, 压缩 oop）:
├── 对象头                                    : 16 字节
├── owner (Block 引用)                        : 4 字节
├── values (Reference2ObjectArrayMap)         : 4 字节 → 单独算
├── neighbours (Map)                          : 4 字节 → 单独算
├── propertiesCodec (MapCodec)                : 4 字节
├── BlockBehaviour.BlockStateBase 字段:
│   ├── @Nullable cache                       : 4 字节
│   ├── int lightBlock                        : 4 字节
│   ├── boolean[] 等 cached                   : ~8 字节
│   └── ⋯⋯
                                                ─────
                                              ≈ 64 字节（对象本身）
                                              + values map (~32 字节, 含 4 entry)
                                              + neighbours map (~80 字节, 含 4 entry × 数组)

每个 BlockState 总占用 ≈ 200-300 字节
```

**全 vanilla**：26000 BlockState × 250 B = **~6.5 MB**。

**chunk 里 BlockState 的引用占用**（这是真正的吃货）：每格只是个 4 字节引用，但 chunk 16×384×16 = 98304 格，2 chunk = 200K 格 × 4 B = 800 KB。**视距 16 chunk² = 256 chunk × 100 KB（紧凑）= 25 MB**。

**这就是为什么 chunk 内不能直接存 BlockState 引用数组**——它必须用 PalettedContainer 进一步压缩。下一节 1.3 讲。

## 1.2.13 C++ 移植设计

C++ 复刻这套机制：

```cpp
// 属性基类
class Property {
public:
    virtual ~Property() = default;
    const std::string& name() const { return name_; }
    virtual int internalIndex(const std::any& value) const = 0;
    virtual std::vector<std::any> possibleValues() const = 0;
    virtual std::string serialize(const std::any& value) const = 0;
    virtual std::any deserialize(const std::string& s) const = 0;
protected:
    std::string name_;
};

class BooleanProperty : public Property {
public:
    static const Property* create(std::string name);
    int internalIndex(const std::any& value) const override {
        return std::any_cast<bool>(value) ? 1 : 0;
    }
    // ...
};

class IntegerProperty : public Property { ... };
class EnumProperty : public Property { ... };

// BlockState：immutable 共享
class BlockState {
public:
    Block* block() const { return block_; }
    
    template<typename T>
    T getValue(const Property* prop) const {
        return std::any_cast<T>(values_.at(prop));
    }
    
    template<typename T>
    const BlockState* setValue(const Property* prop, T newValue) const {
        int idx = prop->internalIndex(newValue);
        return neighbours_.at(prop)[idx];      // O(1)
    }
    
    int32_t globalId() const { return globalId_; }

private:
    friend class StateDefinition;
    Block* block_;
    boost::container::flat_map<const Property*, std::any> values_;
    boost::container::flat_map<const Property*, std::vector<const BlockState*>> neighbours_;
    int32_t globalId_;
};

// StateDefinition：所有 state 的所有者
class StateDefinition {
public:
    StateDefinition(Block* owner, std::vector<const Property*> properties);
    const BlockState& any() const { return *states_.front(); }
    const std::vector<std::unique_ptr<BlockState>>& allStates() const { return states_; }
private:
    Block* owner_;
    std::vector<const Property*> properties_;
    std::vector<std::unique_ptr<BlockState>> states_;
};

// 全局 BlockState ID 表
class BlockStateRegistry {
public:
    int32_t getId(const BlockState* state) const;
    const BlockState* byId(int32_t id) const;
    void registerState(const BlockState* state);
private:
    std::unordered_map<const BlockState*, int32_t> ids_;
    std::vector<const BlockState*> byId_;
};
```

**关键工程选择**：

1. **values 用 `flat_map` 不用 `unordered_map`**：属性数 ≤ 5，flat_map（基于 sorted vector）更快。
2. **`std::any` 还是 `std::variant`？** 属性值类型有限（bool / int / enum），用 `std::variant<bool, int, std::string>` 性能更好。`std::any` 简单但慢。
3. **BlockState 用指针，永远不复制**：所有 chunk / 网络代码都拿 `const BlockState*`。
4. **neighbours 是 vector 数组**：内层用 `std::vector<const BlockState*>`，下标 O(1)。
5. **全局 ID 表用 vector 作 by-id**：byId 是数组直接索引，O(1)。
6. **实例所有权**：StateDefinition 用 `unique_ptr` 拥有，Block 持有 StateDefinition，BlockState 不互相拥有，只有指针引用。

**笛卡尔积穷举的 C++ 版本**：

```cpp
void StateDefinition::buildAllStates() {
    std::vector<std::vector<std::any>> valueLists;
    for (const Property* p : properties_) {
        valueLists.push_back(p->possibleValues());
    }

    // 笛卡尔积递归
    std::vector<std::any> current(properties_.size());
    auto recurse = [&](auto& self, size_t i) -> void {
        if (i == properties_.size()) {
            // 到底了，构造一个 BlockState
            auto state = std::make_unique<BlockState>(owner_);
            for (size_t j = 0; j < properties_.size(); j++) {
                state->values_[properties_[j]] = current[j];
            }
            states_.push_back(std::move(state));
            return;
        }
        for (auto& v : valueLists[i]) {
            current[i] = v;
            self(self, i + 1);
        }
    };
    recurse(recurse, 0);

    // 全部状态创建完后再 populate neighbours
    populateNeighbours();
}

void StateDefinition::populateNeighbours() {
    for (auto& state : states_) {
        for (const Property* p : properties_) {
            auto values = p->possibleValues();
            std::vector<const BlockState*> neighbours;
            for (auto& v : values) {
                auto target = findStateByValues(makeValuesWith(state.get(), p, v));
                neighbours.push_back(target);
            }
            state->neighbours_[p] = std::move(neighbours);
        }
    }
}
```

## 1.2.14 实战：手算一个方块的 state 数量

打开 `Blocks.java`，找一个有趣的方块 —— 比如 `IRON_BARS`（铁栅栏）。它有几个属性？

铁栅栏继承自 `IronBarsBlock`（实际上是 `CrossCollisionBlock`），属性：
- NORTH（boolean） × 2
- SOUTH（boolean） × 2
- EAST（boolean） × 2
- WEST（boolean） × 2
- WATERLOGGED（boolean） × 2

**总计 = 2^5 = 32 个 BlockState**。

但如果你看 `RedstoneWireBlock`（红石线）就更夸张：
- NORTH（enum，3 值：UP/SIDE/NONE） × 3
- SOUTH × 3
- EAST × 3
- WEST × 3
- POWER（int，0..15） × 16

**总计 = 3^4 × 16 = 81 × 16 = 1296 个 BlockState**。仅 RedstoneWire 一个方块就贡献 1296 个 state。

**26000 个 vanilla state 的来源很不平均**——少数几个属性丰富的方块占了大部分（红石线、藤蔓、栅栏 / 玻璃板的连接、可旋转的活塞）。

## 1.2.15 一句话总结

`BlockState = (Block, 属性 → 值 map)`，是 immutable 共享实例；游戏启动时 `StateDefinition` 笛卡尔积穷举所有可能组合（vanilla 总计约 26000 个）一次性创建完毕，运行时永不分配；每个 BlockState 内置 `neighbours` 跳转表使 `setValue` O(1)；`BLOCK_STATE_REGISTRY` 全局给所有 state 分配整数 ID 用于网络 / palette；属性分 Boolean / Integer / Enum 三类，公共属性集中在 `BlockStateProperties` 复用；`==` 比较合法，因为身份即等价。
