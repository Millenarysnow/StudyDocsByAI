# 1.5 ChunkAccess 层次：ProtoChunk vs LevelChunk vs ImposterProtoChunk

## 1.5.0 你将在本节学到什么

读完这一节你应当能闭着眼睛回答：

1. 一个 chunk 在它的"一生"中长什么样？从无到有、从生成到运行、到卸载再到加载，分别由哪些 Java 类承担？
2. `ChunkAccess`（抽象基类）、`ProtoChunk`、`LevelChunk`、`ImposterProtoChunk`、`EmptyLevelChunk` —— 这五个类各自的职责是什么？什么时候用哪一个？
3. 为什么生成阶段不直接用 `LevelChunk`？多了一层 `ProtoChunk` 解决了什么？
4. ProtoChunk → LevelChunk 的"升级"在哪一刻发生？两者如何共享数据、如何隔离？
5. `chunk.setBlock(pos, state, flags)` 这个方法对 ProtoChunk 和 LevelChunk 行为分别是什么？
6. 我在 C++ 里要复现这套层次，最简洁的设计是什么？要不要照搬全部 5 个类？

## 1.5.1 直觉：一个 chunk 的一生

```
玩家走近一片新区域
  → ChunkMap 决定要加载/生成 ChunkPos(x, z)
      │
      ▼
  EMPTY 阶段（占位）
  ProtoChunk 实例创建，所有 24 section 全部 null（懒分配）
      │
      ▼
  Worldgen 流水线（12 个阶段，详见 Module 3）
  STRUCTURE_STARTS / STRUCTURE_REFERENCES / BIOMES / NOISE / SURFACE / CARVERS / FEATURES /
  INITIALIZE_LIGHT / LIGHT / SPAWN
      │
      ▼ 阶段 FULL（最后一阶段）
  ProtoChunk → LevelChunk 升级
  此时该 chunk 的所有数据被原子地"搬"到一个新的 LevelChunk 实例
      │
      ▼ 进入运行期
  LevelChunk 加入 chunkSource，开始接受 ticks / 邻居更新 / 玩家交互
      │
      ▼ 玩家离开 / 服务器关
  LevelChunk 序列化为 NBT 写盘，从内存释放
      │
      ▼ 玩家再来
  从 NBT 读出，立刻构造 LevelChunk（不再回到 ProtoChunk —— 已经是 FULL 状态）
```

**核心设计决策**：worldgen 阶段的 chunk 与运行时的 chunk 用**不同的 Java 类型**承担。

为什么？

1. **生成期与运行期的 API 需求差太多**。Worldgen 需要"我能改任意位置 + 我没有 BlockEntity 概念 + 我只关心物理数据 + 邻居 chunk 可能没生成完"；运行时需要"任何 setBlock 必须触发邻居 + 必须广播给客户端 + 必须维护 BlockEntity"。
2. **生成期允许并行写入但不允许 tick**。运行期允许 tick 但严格禁止跨线程并发写。两个不同的不变量集合，强制类型分离让编译器帮你检查。
3. **未完成的 chunk 不能进 ticking 主循环**。如果一个 chunk 还在 BIOMES 阶段就被 tick，会查询尚未生成的方块、爆栈。类型系统挡住这条路：tick 调度器只接受 `LevelChunk`。

`ChunkAccess` 是它们共同的抽象基类，承担"二者共享的查询接口"。

## 1.5.3 ChunkAccess：共享抽象

打开 `net.minecraft.world.level.chunk.ChunkAccess`（行 60-100）：

```java
public abstract class ChunkAccess implements BiomeManager.NoiseBiomeSource, LightChunk, StructureAccess {
    public static final int NO_FILLED_SECTION = -1;

    protected final ShortList[] postProcessing;
    private volatile boolean unsaved;
    private volatile boolean isLightCorrect;
    protected final ChunkPos chunkPos;
    private long inhabitedTime;
    @Nullable @Deprecated
    private BiomeGenerationSettings carverBiomeSettings;
    @Nullable
    protected NoiseChunk noiseChunk;
    protected final UpgradeData upgradeData;
    @Nullable
    protected BlendingData blendingData;
    protected final Map<Heightmap.Types, Heightmap> heightmaps = Maps.newEnumMap(Heightmap.Types.class);
    protected ChunkSkyLightSources skyLightSources;
    private final Map<Structure, StructureStart> structureStarts = Maps.newHashMap();
    private final Map<Structure, LongSet> structuresRefences = Maps.newHashMap();
    protected final LevelChunkSection[] sections;
    // ... 还有 abstract 方法签名 ...
}
```

**字段含义**（关注高频）：

| 字段 | 用途 | 子类何时关心 |
|------|------|------------|
| `chunkPos` | 自己的 (x, z) chunk 坐标 | 总是 |
| `sections[]` | 24 个 LevelChunkSection（主世界） | 总是 |
| `heightmaps` | 6 种 heightmap（1.6 节） | 总是 |
| `postProcessing` | 待延迟处理的 BlockPos 列表（每 section 一个） | 跨 chunk 写入，详见 Module 3.15 |
| `structureStarts` | 起源于本 chunk 的结构 BoundingBox | worldgen + 运行期 |
| `structuresRefences` | 跨 chunk 结构在本 chunk 的引用 | worldgen + 运行期 |
| `inhabitedTime` | 玩家在本 chunk 累计停留 tick 数 | 难度递增、刷怪 |
| `upgradeData` | 旧版本兼容数据 | 数据迁移用 |
| `blendingData` | 1.18 旧 chunk 与新地形的边界融合数据 | 加载老版本存档 |
| `noiseChunk` | worldgen 用的密度场缓存（Module 3） | 仅生成期 |
| `skyLightSources` | 天光源面 | 光照引擎 |
| `unsaved` | 有未保存修改 | 写盘调度 |
| `isLightCorrect` | 光照已计算 | tick 之前要检查 |

**抽象的关键 API**（节选）：

```java
public abstract BlockState getBlockState(BlockPos pos);
public abstract FluidState getFluidState(BlockPos pos);

@Nullable
public abstract BlockState setBlockState(BlockPos pos, BlockState state, boolean isMoving);

public abstract void setBlockEntity(BlockEntity be);
public abstract void addPackedPostProcess(short packed, int sectionIdx);

public abstract LevelChunkTicks<Block> getBlockTicks();   // 实现因子类不同
public abstract LevelChunkTicks<Fluid> getFluidTicks();
```

子类必须实现这些方法。`getBlockState` 在 ProtoChunk 和 LevelChunk 上都可用——但 `setBlockState` 的语义有微妙差别。下面分别讲。

## 1.5.4 ProtoChunk：生成期的 chunk

打开 `net.minecraft.world.level.chunk.ProtoChunk`（行 40-70）：

```java
public class ProtoChunk extends ChunkAccess {
    @Nullable private volatile LevelLightEngine lightEngine;
    private volatile ChunkStatus status = ChunkStatus.EMPTY;
    private final List<CompoundTag> entities = Lists.newArrayList();
    @Nullable private CarvingMask carvingMask;
    @Nullable private BelowZeroRetrogen belowZeroRetrogen;
    private final ProtoChunkTicks<Block> blockTicks;
    private final ProtoChunkTicks<Fluid> fluidTicks;

    public ProtoChunk(ChunkPos pos, UpgradeData upgradeData, ...) {
        super(pos, upgradeData, ...);
        this.blockTicks = new ProtoChunkTicks<>();
        this.fluidTicks = new ProtoChunkTicks<>();
    }
}
```

**ProtoChunk 独有字段**：

- `status`：当前所处的 ChunkStatus（EMPTY → STRUCTURE_STARTS → ... → FULL）。每跑完一个 worldgen 步骤就推进一次。
- `entities` 是**未反序列化的 NBT 列表** —— ProtoChunk 不持有真正的 Entity 对象，只持有它们将来要变成 Entity 时的 NBT 数据。
- `carvingMask`：carver 阶段记录"哪些格已被雕掉"的 bit mask。
- `belowZeroRetrogen`：1.18 升级数据兼容（Y < 0 的扩展）。
- `blockTicks` / `fluidTicks` 用 `ProtoChunkTicks` —— 一个简单的 list，不带优先队列调度（生成期还不需要按时间触发 tick）。

**ProtoChunk.setBlockState**（行 80+）的核心：

```java
@Override
public BlockState setBlockState(BlockPos pos, BlockState state, boolean isMoving) {
    int x = pos.getX(), y = pos.getY(), z = pos.getZ();
    if (y < this.getMinBuildHeight() || y >= this.getMaxBuildHeight()) {
        return Blocks.VOID_AIR.defaultBlockState();
    }
    int sectionIdx = this.getSectionIndex(y);
    LevelChunkSection section = this.sections[sectionIdx];
    if (section.hasOnlyAir() && state.isAir()) {
        return state;       // 优化：air → air noop
    }

    // 高频: heightmap 维护
    if (state.getLightEmission() > 0) {
        this.skyLightSources.update(x & 15, y, z & 15);
    }

    // 实际写入
    BlockState old = section.setBlockState(x & 15, y & 15, z & 15, state);

    // 6 种 heightmap 同步更新
    this.heightmaps.computeIfAbsent(Heightmap.Types.MOTION_BLOCKING, Heightmap::new)
        .update(x & 15, y, z & 15, state);
    // ... 类似处理 OCEAN_FLOOR / WORLD_SURFACE 等 ...

    // BlockEntity 处理
    if (state.hasBlockEntity()) {
        this.blockEntities.put(pos, ...);
    } else if (old.hasBlockEntity()) {
        this.blockEntities.remove(pos);
    }

    this.unsaved = true;
    return old;
}
```

**关键差别**：

- **没有触发邻居更新**——worldgen 期不能调用 `neighborChanged`，因为周围 chunk 可能还没生成。
- **没有广播给客户端**——chunk 还没"上线"，没有客户端在监听。
- **没有 fluid spread**——worldgen 期的水位由 Aquifer 系统在 NOISE 阶段就一次性铺好，`setBlockState` 不再触发流体模拟。

**ProtoChunk 的写入是"原子写"**——只改本 chunk 数据，不发任何信号。这让生成期可以多线程并行（不同 chunk 互不干扰）。

## 1.5.5 LevelChunk：运行期的 chunk

打开 `net.minecraft.world.level.chunk.LevelChunk`（行 55-90）：

```java
public class LevelChunk extends ChunkAccess {
    static final Logger LOGGER = LogUtils.getLogger();
    private static final TickingBlockEntity NULL_TICKER = ...;
    private final Map<BlockPos, LevelChunk.RebindableTickingBlockEntityWrapper> tickersInLevel = Maps.newHashMap();
    private boolean loaded;
    final Level level;
    @Nullable private Supplier<FullChunkStatus> fullStatus;
    @Nullable private LevelChunk.PostLoadProcessor postLoad;
    private final Int2ObjectMap<GameEventListenerRegistry> gameEventListenerRegistrySections = ...;
    private final LevelChunkTicks<Block> blockTicks;
    private final LevelChunkTicks<Fluid> fluidTicks;
}
```

**LevelChunk 独有字段**：

- `level` —— 反向引用到 owning Level 实例（`ServerLevel` 或 `ClientLevel`）。这是 `setBlock` 触发邻居更新、广播包的入口。
- `loaded` —— 是不是真正在世界里加载（`true` 后才接受玩家交互）。
- `fullStatus` —— 在更精细的 `FullChunkStatus`（INACCESSIBLE / FULL / BLOCK_TICKING / ENTITY_TICKING）阶梯上的位置。决定该 chunk 是否参与 random tick / entity tick。
- `tickersInLevel` —— 实际**正在运行**的 BlockEntity tickers 字典。
- `gameEventListenerRegistrySections` —— Sculk 监听器（1.20+）的注册表。
- `blockTicks` / `fluidTicks` —— **`LevelChunkTicks`**（不是 ProtoChunkTicks），带优先级队列、按 tick 时间排序。

**LevelChunk.setBlockState** 的差别（简化版）：

```java
@Nullable
public BlockState setBlockState(BlockPos pos, BlockState state, boolean isMoving) {
    int sectionIdx = this.getSectionIndex(pos.getY());
    LevelChunkSection section = this.sections[sectionIdx];

    boolean wasEmpty = section.hasOnlyAir();
    if (wasEmpty && state.isAir()) return null;

    BlockState old = section.setBlockState(pos.getX() & 15, pos.getY() & 15, pos.getZ() & 15, state);
    if (old == state) return null;

    // 高频：heightmap 维护
    this.heightmaps.get(Heightmap.Types.MOTION_BLOCKING).update(...);
    // ... 6 种 heightmap 全部更新 ...

    boolean wasLightCorrect = this.isLightCorrect();
    
    // ★ 在运行时 chunk 上有的：
    // 1. 触发 BlockEntity 的 onLoad / onRemove
    if (old.hasBlockEntity()) {
        BlockEntity oldBE = this.getBlockEntity(pos);
        if (oldBE != null) oldBE.setRemoved();
        this.blockEntities.remove(pos);
    }
    if (state.hasBlockEntity()) {
        BlockEntity newBE = ((EntityBlock)state.getBlock()).newBlockEntity(pos, state);
        this.setBlockEntity(newBE);
    }
    
    // 2. 触发光照引擎重算
    if (wasLightCorrect != ...) this.level.getLightEngine().checkBlock(pos);

    // 3. 标记 chunk dirty
    this.unsaved = true;

    return old;
}
```

**LevelChunk 的写入做了 ProtoChunk 不做的所有事**——BlockEntity、光照、unsaved 标记。但**仍然不在 setBlockState 内触发 neighbor update**——neighborChanged 是 `Level.setBlock` 的工作，在外层调用 `chunk.setBlockState` 之后由 Level 层负责。

## 1.5.6 ProtoChunk → LevelChunk 升级

打开 `net.minecraft.world.level.chunk.LevelChunk` 寻找一个特殊构造函数：

```java
public LevelChunk(ServerLevel level, ProtoChunk proto, @Nullable LevelChunk.PostLoadProcessor postLoad) {
    super(
        proto.getPos(),
        proto.getUpgradeData(),
        level,
        level.registryAccess().registryOrThrow(Registries.BIOME),
        proto.getInhabitedTime(),
        proto.getSections(),                    // ★ section 数组直接复用
        proto.getBlendingData()
    );

    // 把 ProtoChunk 的所有数据搬过来
    for (BlockEntity be : proto.getBlockEntities().values()) {
        this.setBlockEntity(be);
    }
    this.pendingBlockEntities.putAll(proto.getBlockEntityNbts());
    
    for (int i = 0; i < proto.getPostProcessing().length; ++i) {
        this.postProcessing[i] = proto.getPostProcessing()[i];
    }
    
    this.setAllStarts(proto.getAllStarts());
    this.setAllReferences(proto.getAllReferences());
    
    for (Entry<Heightmap.Types, Heightmap> entry : proto.getHeightmaps()) {
        if (ChunkStatus.FULL.heightmapsAfter().contains(entry.getKey())) {
            this.setHeightmap(entry.getKey(), entry.getValue().getRawData());
        }
    }
    
    this.skyLightSources = proto.skyLightSources;
    this.setLightCorrect(proto.isLightCorrect());
    this.unsaved = true;     // 升级了就脏，要写盘
}
```

**升级的核心**：**section 数组、heightmap、structure references、postProcessing 全部 by-reference 搬迁**。LevelChunk 接管这些数据所有权，ProtoChunk 实例从此被丢弃。

**这是 by-reference 而不是 deep copy**：

- 24 个 LevelChunkSection 实例**同一引用**地从 proto.sections[] 搬到 levelChunk.sections[]。
- BlockEntity 实例同样 by-reference 移动。
- ⋯⋯

**好处**：升级是 O(1) 的（不复制几 MB 数据）。**代价**：升级一旦发生，proto 实例不能再用——它的 sections[] 现在指向 LevelChunk 拥有的对象，proto 任何写入都会越权写到 LevelChunk 的数据。所以**生成流水线必须保证升级后不再访问 proto**。

升级在 `ChunkStatusTasks.generateFull` 触发（1.21 重构后），Module 3.2 会精确展开时序。

## 1.5.7 ImposterProtoChunk：让 LevelChunk 假装成 ProtoChunk

```java
public class ImposterProtoChunk extends ProtoChunk {
    private final LevelChunk wrapped;
    private final boolean allowWrites;
    
    public ImposterProtoChunk(LevelChunk wrapped, boolean allowWrites) {
        super(wrapped.getPos(), UpgradeData.EMPTY, wrapped.getLevelHeightAccessor(), 
              wrapped.getLevel().registryAccess().registryOrThrow(Registries.BIOME), 
              wrapped.getBlendingData());
        this.wrapped = wrapped;
        this.allowWrites = allowWrites;
    }

    @Override
    public BlockState getBlockState(BlockPos pos) {
        return this.wrapped.getBlockState(pos);    // 转发
    }

    @Override
    @Nullable
    public BlockState setBlockState(BlockPos pos, BlockState state, boolean isMoving) {
        return this.allowWrites ? this.wrapped.setBlockState(pos, state, isMoving) : null;
    }
    // ... 全部 method 转发到 wrapped ...
}
```

**为什么需要 ImposterProtoChunk**？

场景：chunk A 已经生成完毕成为 LevelChunk（运行中）。现在玩家走到 chunk B 这边，触发了 chunk B 的 worldgen 流水线 FEATURES 阶段。FEATURES 阶段会跨 chunk 写入（树叶可能伸到 chunk A）——这是 Module 3.15 讲的跨区块机制。

但 worldgen 代码的 API 接受的是 `WorldGenLevel`，进一步是要操作 `ChunkAccess` 对象（具体而言是 `ProtoChunk`）。如果直接传一个 LevelChunk，类型不对；而且 worldgen 代码可能调到 ProtoChunk 独有方法（`addPackedPostProcess`）。

**解法**：把已存在的 LevelChunk 用 `ImposterProtoChunk` 包装一下，伪装成 ProtoChunk。所有调用透明转发到底层 LevelChunk。这样 worldgen 代码不需要分支判断，统一用 ProtoChunk API。

**`allowWrites`**：决定要不要允许 worldgen 写到这个邻居。通常是 true（因为我们就是要让 feature 写邻居）；某些诊断 / 只读场景可以传 false 拒写。

ImposterProtoChunk 是 1.18+ 引入的。它让"邻居 chunk 可能是 LevelChunk 也可能是 ProtoChunk" 这个二选一从代码消失。

## 1.5.8 EmptyLevelChunk：边界 / 越界占位

```java
public class EmptyLevelChunk extends LevelChunk {
    private static final Holder<Biome> defaultBiome = ...;
    
    public EmptyLevelChunk(Level level, ChunkPos pos, Holder<Biome> biome) {
        super(level, pos);
        this.defaultBiome = biome;
    }

    @Override public BlockState getBlockState(BlockPos pos) { return Blocks.VOID_AIR.defaultBlockState(); }
    @Override public FluidState getFluidState(BlockPos pos) { return Fluids.EMPTY.defaultFluidState(); }
    @Override public int getLightEmission(BlockPos pos) { return 0; }
    @Override public Holder<Biome> getNoiseBiome(int qx, int qy, int qz) { return defaultBiome; }
    @Override public BlockState setBlockState(BlockPos pos, BlockState state, boolean isMoving) { return null; }
    @Override public boolean isEmpty() { return true; }
    // ... 大部分方法返回 "默认值 / null / 0" ...
}
```

**作用**：当代码访问一个**根本没有加载**的 chunk 时，返回这个空 chunk 而不是 NPE。

典型用法：

```java
// 玩家在 chunk (10, 10)，但实体路径搜索碰到了 chunk (1000, 1000)（远未加载）
LevelChunk chunk = level.getChunkSource().getChunk(1000, 1000, false);
if (chunk == null) chunk = EmptyLevelChunk.getInstance();
chunk.getBlockState(somePos);   // 安全地返回 VOID_AIR
```

**`isEmpty() == true`** 是给上层判断"这个 chunk 是占位还是真实"的钩子。

EmptyLevelChunk 实质上是一个 **null object 模式**：避免每个调用点都写 `if (chunk == null)`。

## 1.5.9 完整的访问 / 修改路径

把 5 个类放在一张表里对比：

| 操作 | ChunkAccess 抽象 | ProtoChunk | LevelChunk | ImposterProtoChunk | EmptyLevelChunk |
|------|------------------|-----------|-----------|---------------------|-----------------|
| `getBlockState(pos)` | abstract | 查 sections | 查 sections | 转发到 wrapped | 返回 VOID_AIR |
| `setBlockState` | abstract | 改 sections + heightmap，不触发 neighbor | 改 sections + heightmap + BE + 光照，不触发 neighbor | 转发（如允许） | noop 返 null |
| 触发 neighborChanged | — | 永不 | **永不**（外层 Level.setBlock 负责） | 转发 | 永不 |
| 持有 BlockEntity 字典 | yes | yes（生成期可放一些） | yes（运行期主战场） | 转发 | 空 |
| 持有 entities | NBT 列表 | NBT 列表 | 直接放在 ServerLevel 而非这里 | 转发 | 空 |
| 接受 random tick | 否 | 否 | 是 | 否 | 否 |
| 可被 ChunkSerializer 写盘 | abstract | 是（生成完成后） | 是（运行期变更） | 否（透明） | 否 |
| 类型检查时机 | — | 生成流水线限定 | tick 主循环限定 | worldgen 兼容 | 边界场景 |

## 1.5.10 chunk 写盘 / 读盘的全图

```
玩家放方块
  ▼
ServerLevel.setBlock(pos, state, flags)
  ▼
LevelChunk.setBlockState(pos, state, isMoving)        ← 1.5.5 那段代码
  ▼
LevelChunkSection.setBlockState(...)                   ← 1.4 节
  ▼
PalettedContainer.set(...)                             ← 1.3 节
  ▼
mark unsaved = true
  
      ⋯ 数小时后 ⋯
  
chunk 卸载触发：
  ChunkSerializer.write(LevelChunk, ...)               → SerializableChunkData → CompoundTag
  RegionFile.write(chunkPos, ...)                       → .mca 扇区写入

  ⋯ 玩家再来 ⋯

ChunkMap.read(chunkPos):
  RegionFile.read(chunkPos) → CompoundTag
  ChunkSerializer.read(...) → 直接构造 LevelChunk
       （已经是 FULL 状态，跳过 ProtoChunk 流水线）
```

**关键点**：从 NBT 加载回来的 chunk **直接是 LevelChunk** —— 因为存档里保存的就是"已经 FULL 状态"的 chunk。**不再走 worldgen 流水线**。这是为什么再次进入加载过的区域不会"重新生成"。

ChunkSerializer 的细节在 Module 2 NBT / Region 章节展开。

## 1.5.11 sections 数组的初始化

`ChunkAccess` 构造（节选）：

```java
public ChunkAccess(ChunkPos pos, UpgradeData upgrade, LevelHeightAccessor heightAccess, 
                   Registry<Biome> biomeRegistry, long inhabitedTime,
                   @Nullable LevelChunkSection[] sections, @Nullable BlendingData blending) {
    this.chunkPos = pos;
    this.upgradeData = upgrade;
    this.levelHeightAccessor = heightAccess;
    this.inhabitedTime = inhabitedTime;
    this.sections = new LevelChunkSection[heightAccess.getSectionsCount()];
    if (sections != null) {
        if (sections.length == this.sections.length) {
            System.arraycopy(sections, 0, this.sections, 0, this.sections.length);
        }
    }
    this.replaceMissingSections(biomeRegistry, this.sections);
    // ...
}

private void replaceMissingSections(Registry<Biome> biomes, LevelChunkSection[] arr) {
    for (int i = 0; i < arr.length; i++) {
        if (arr[i] == null) {
            arr[i] = new LevelChunkSection(biomes);    // 默认创建空 section
        }
    }
}
```

**主世界 `sectionsCount = 24`**（`(maxBuildHeight - minBuildHeight) / 16 = (320 - (-64)) / 16 = 24`）。

**`null` 的 section 在运行时不允许出现**——`replaceMissingSections` 强制把所有空槽填上"全 air"section。

**section 数组是 Y-序的**：

```
sections[0]  = Y ∈ [-64, -48)    (即 sectionY = -4)
sections[1]  = Y ∈ [-48, -32)
...
sections[23] = Y ∈ [304, 320)
```

`getSectionIndex(blockY)`:

```java
public int getSectionIndex(int blockY) {
    return (blockY >> 4) - this.getMinSectionY();
}
// 主世界 minSectionY = -4
// blockY=64 → sectionY=4 → index=8
```

## 1.5.12 status 字段：阶段标识

ProtoChunk 的 `status` 字段（行 43）：

```java
private volatile ChunkStatus status = ChunkStatus.EMPTY;
```

它跟踪"当前 chunk 走到 worldgen 流水线哪一步"：

```
EMPTY → STRUCTURE_STARTS → STRUCTURE_REFERENCES → BIOMES → NOISE → SURFACE
   → CARVERS → FEATURES → INITIALIZE_LIGHT → LIGHT → SPAWN → FULL
```

每个 ChunkStep 跑完会把 status 往后推一步。`FULL` 是最后一个状态——下一刻该 chunk 就升级成 LevelChunk 了。

**`volatile`**：因为 worldgen 可能并行多线程跑，status 字段被多线程读写需要内存可见性保证。

LevelChunk 没有 status 字段——它默认是 FULL 之后的状态。

## 1.5.13 内存预算

| 类型 | 主要字段 | 平均内存 |
|------|---------|---------|
| `ChunkAccess` 共享部分 | sections[24]、heightmaps、structureStarts、postProcessing | ~80 KB |
| `+ ProtoChunk` 独有 | status、entities NBT、blockTicks、fluidTicks（list 形式） | +5-20 KB |
| `+ LevelChunk` 独有 | level ref、tickersInLevel、blockTicks（priority queue）、gameEventListeners | +10-30 KB |

一个生成中的 ProtoChunk 大约 100 KB；一个运行中的 LevelChunk 大约 150-200 KB（包含 BlockEntity 对象本体）。

**视距 32×32 = 1024 chunk × 200 KB ≈ 200 MB**——一台 4 GB 的 vanilla 服务端的"视野内 chunk"内存预算。

## 1.5.14 C++ 移植

```cpp
// === 共享基类 ===
class ChunkAccess {
public:
    virtual ~ChunkAccess() = default;
    
    virtual const BlockState* getBlockState(BlockPos pos) const = 0;
    virtual const BlockState* setBlockState(BlockPos pos, const BlockState* state, bool isMoving) = 0;
    virtual const FluidState& getFluidState(BlockPos pos) const = 0;
    virtual void setBlockEntity(std::unique_ptr<BlockEntity> be) = 0;
    
    ChunkPos pos() const { return chunkPos_; }
    int sectionsCount() const { return int(sections_.size()); }
    LevelChunkSection& section(int idx) { return sections_[idx]; }
    Heightmap& heightmap(Heightmap::Type type) { return heightmaps_[size_t(type)]; }
    
protected:
    ChunkAccess(ChunkPos pos, int minSectionY, int maxSectionY, ...);
    
    ChunkPos chunkPos_;
    std::vector<LevelChunkSection> sections_;
    std::array<Heightmap, 6> heightmaps_;
    std::vector<std::vector<int16_t>> postProcessing_;          // per-section
    std::unordered_map<const Structure*, std::unique_ptr<StructureStart>> structureStarts_;
    std::unordered_map<const Structure*, std::vector<int64_t>> structureReferences_;
    int64_t inhabitedTime_ = 0;
    bool unsaved_ = false;
    bool isLightCorrect_ = false;
    int minSectionY_;
    int sectionsCount_;
    
    int sectionIndex(int blockY) const { return (blockY >> 4) - minSectionY_; }
};

// === ProtoChunk ===
class ProtoChunk : public ChunkAccess {
public:
    enum class Status { EMPTY, STRUCTURE_STARTS, STRUCTURE_REFERENCES, BIOMES, NOISE,
                        SURFACE, CARVERS, FEATURES, INITIALIZE_LIGHT, LIGHT, SPAWN, FULL };
    
    Status status() const { return status_.load(); }
    void setStatus(Status s) { status_.store(s); }
    
    const BlockState* setBlockState(BlockPos pos, const BlockState* state, bool isMoving) override;
    
private:
    std::atomic<Status> status_{Status::EMPTY};
    std::vector<NbtCompound> entitiesNbt_;
    std::optional<CarvingMask> carvingMask_;
    ProtoChunkTicks blockTicks_;          // simple list-based queue
    ProtoChunkTicks fluidTicks_;
};

// === LevelChunk ===
class LevelChunk : public ChunkAccess {
public:
    LevelChunk(World* level, ChunkPos pos);
    LevelChunk(ServerLevel* level, ProtoChunk&& proto);    // 升级构造
    
    const BlockState* setBlockState(BlockPos pos, const BlockState* state, bool isMoving) override;
    void onLoad();
    void onUnload();
    
    Level* level() { return level_; }
    bool isLoaded() const { return loaded_; }
    
private:
    Level* level_;
    bool loaded_ = false;
    std::unordered_map<BlockPos, BlockEntity*, BlockPosHash> tickersInLevel_;
    LevelChunkTicks blockTicks_;          // priority queue 按 tick time 排序
    LevelChunkTicks fluidTicks_;
};

// === ImposterProtoChunk ===
class ImposterProtoChunk : public ProtoChunk {
public:
    ImposterProtoChunk(LevelChunk* wrapped, bool allowWrites);
    
    const BlockState* getBlockState(BlockPos pos) const override {
        return wrapped_->getBlockState(pos);
    }
    const BlockState* setBlockState(BlockPos pos, const BlockState* state, bool isMoving) override {
        return allowWrites_ ? wrapped_->setBlockState(pos, state, isMoving) : nullptr;
    }
    // ... 全方法转发 ...

private:
    LevelChunk* wrapped_;
    bool allowWrites_;
};

// === EmptyLevelChunk ===
class EmptyLevelChunk : public LevelChunk {
public:
    EmptyLevelChunk(Level* level, ChunkPos pos);
    static EmptyLevelChunk* getInstance();
    
    const BlockState* getBlockState(BlockPos pos) const override { return &VOID_AIR; }
    const BlockState* setBlockState(BlockPos, const BlockState*, bool) override { return nullptr; }
    bool isEmpty() const override { return true; }
};
```

**关键工程选择**：

1. **`ProtoChunk → LevelChunk` 升级用 move 构造**：
   ```cpp
   LevelChunk::LevelChunk(ServerLevel* level, ProtoChunk&& proto)
       : ChunkAccess(std::move(proto)),     // 数据基类移动
         level_(level), loaded_(false) {
       // 把 BlockEntity 等搬过来
   }
   ```
   ProtoChunk 实例被消耗，调用方手中的引用变 dangling—— 用 `unique_ptr` 包装让编译器帮你强制这点。

2. **`status` 用 `std::atomic<enum>`**：worldgen 多线程读。

3. **`ImposterProtoChunk` 用包装而不是继承 LevelChunk**：保持 ProtoChunk 类型签名，避免把 LevelChunk 的运行时 API 暴露给 worldgen。

4. **`EmptyLevelChunk` 用 Meyer's singleton**：永远只一个实例，return getInstance()。

## 1.5.16 一句话总结

ChunkAccess 是抽象基类承载共享字段（24 sections / 6 heightmaps / structureStarts / postProcessing 等）；ProtoChunk 用于 worldgen 期，写入不触发邻居 / 不广播 / 不 tick；LevelChunk 用于运行期，写入额外维护 BlockEntity / 光照 / unsaved 标记，但 neighbor update 仍由外层 `Level.setBlock` 触发；ProtoChunk → LevelChunk 升级是 by-reference 数据搬迁、O(1)；ImposterProtoChunk 让 LevelChunk 在 worldgen 跨 chunk 写入场景下伪装成 ProtoChunk；EmptyLevelChunk 是 null object 模式给越界访问一个安全占位。
