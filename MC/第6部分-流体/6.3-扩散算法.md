## 6.3.1 直觉：水为什么"找下落点"

观察：

```
桌面：    [水源]                    [洞]
              ▼ 水流方向    ←——→
              开始流向有洞的方向

桌面：    [水源]
              ▼ 4 方向均匀流（无洞）
```

**Mojang 的设计**：水水平扩散时**不是平均向 4 方向**，而是**优先流向最近的"下落点"**——一格"上方有水、下方是空"的位置。

**视觉效果**：

- 玩家在桌面挖个洞 → 周围水会"主动流向洞" 而不是均匀扩散。
- 如果有多个洞 → 流向最近的。
- 如果完全没洞 → 4 方向均匀。

这就是流体的"距离场扩散"——**算每个候选方向到最近下落点的距离**，选最短的。

## 6.3.2 getSpread 主入口

```java
// FlowingFluid
protected Map<Direction, FluidState> getSpread(ServerLevel level, BlockPos pos, BlockState state) {
    int slope = 1000;
    Map<Direction, FluidState> result = Maps.newEnumMap(Direction.class);
    Short2ObjectMap<Pair<BlockState, FluidState>> stateCache = new Short2ObjectOpenHashMap<>();
    Short2BooleanMap holeCache = new Short2BooleanOpenHashMap();
    
    for (Direction dir : Direction.Plane.HORIZONTAL) {
        BlockPos neighborPos = pos.relative(dir);
        short cacheKey = getCacheKey(pos, neighborPos);
        Pair<BlockState, FluidState> neighborStates = stateCache.computeIfAbsent(cacheKey, k -> {
            BlockState bs = level.getBlockState(neighborPos);
            return Pair.of(bs, bs.getFluidState());
        });
        BlockState neighborState = neighborStates.getFirst();
        FluidState neighborFluid = neighborStates.getSecond();
        FluidState newSpread = this.getNewLiquid(level, neighborPos, neighborState);
        
        if (this.canPassThrough(level, newSpread.getType(), pos, state, dir, neighborPos, neighborState, neighborFluid)) {
            BlockPos belowOfNeighbor = neighborPos.below();
            boolean isHole = holeCache.computeIfAbsent(getCacheKey(neighborPos, belowOfNeighbor), 
                k -> {
                    BlockState belowState = level.getBlockState(belowOfNeighbor);
                    return this.isWaterHole(level, this.getFlowing(), neighborPos, neighborState, belowOfNeighbor, belowState);
                });
            
            int distance = isHole ? 0 : this.getSlopeDistance(level, neighborPos, 1, dir.getOpposite(), neighborState, pos, stateCache, holeCache);
            
            if (distance < slope) {
                result.clear();
                slope = distance;
            }
            if (distance == slope) {
                result.put(dir, newSpread);
            }
        }
    }
    
    return result;
}
```

**算法**：

1. 对 4 个水平方向：
   - 计算邻居的 newSpread（如果我流过去那格变什么）。
   - 如果可流过：
     - 邻居下方是不是 hole？是 → distance=0；否 → 调 `getSlopeDistance` 算到最近 hole 的距离。
     - 取**最小 distance** 的方向（多方向同距 → 都算）。
2. 返回 `Map<Direction, FluidState>` —— 应该流向的方向集合。

## 6.3.3 getSlopeDistance：递归 BFS 距离

```java
private int getSlopeDistance(ServerLevel level, BlockPos pos, int currentDistance, Direction skipDirection, BlockState state, BlockPos originalPos, ...) {
    int min = 1000;
    
    for (Direction dir : Direction.Plane.HORIZONTAL) {
        if (dir == skipDirection) continue;     // 不回头
        
        BlockPos neighborPos = pos.relative(dir);
        short cacheKey = getCacheKey(pos, neighborPos);
        Pair<BlockState, FluidState> neighborStates = stateCache.computeIfAbsent(cacheKey, ...);
        BlockState neighborState = neighborStates.getFirst();
        FluidState neighborFluid = neighborStates.getSecond();
        FluidState newSpread = this.getNewLiquid(level, neighborPos, neighborState);
        
        if (this.canPassThrough(level, newSpread.getType(), pos, state, dir, neighborPos, neighborState, neighborFluid)) {
            BlockPos belowOfNeighbor = neighborPos.below();
            boolean isHole = holeCache.computeIfAbsent(getCacheKey(neighborPos, belowOfNeighbor), 
                k -> {
                    BlockState belowState = level.getBlockState(belowOfNeighbor);
                    return this.isWaterHole(level, this.getFlowing(), neighborPos, neighborState, belowOfNeighbor, belowState);
                });
            
            if (isHole) return currentDistance;     // 找到了！返回当前累计距离
            
            // 没找到 + 还在搜索深度内 → 继续递归
            if (currentDistance < this.getSlopeFindDistance(level)) {
                int subDist = this.getSlopeDistance(level, neighborPos, currentDistance + 1, dir.getOpposite(), neighborState, originalPos, stateCache, holeCache);
                if (subDist < min) min = subDist;
            }
        }
    }
    
    return min;
}
```

**算法**（递归 BFS）：

1. 当前位置：扫 4 个方向（除回头）。
2. 每个方向：检查邻居下方是不是 hole。
3. 是 → 返回当前距离。
4. 否：继续递归（深度 + 1）。
5. 超过 `getSlopeFindDistance` (water=4 / lava=2)：放弃。

**返回 1000** 表示找不到 hole（在搜索深度内）。

**`getSlopeFindDistance`**：

- WaterFluid 主世界：**4**（限制水平搜索深度 4 格）。
- WaterFluid 下界：水在下界**会蒸发**（不存在水）。
- LavaFluid 主世界：**2**（更短）。
- LavaFluid 下界：**2** 但 `getDropOff` 不同。

**为什么搜索深度限制**：性能 —— 不限的话每个 wire spread 都要 BFS 整 chunk。

## 6.3.4 isWaterHole：什么算"洞"

```java
private boolean isWaterHole(BlockGetter level, Fluid fluid, BlockPos pos, BlockState state, BlockPos belowPos, BlockState belowState) {
    if (!this.canPassThroughWall(Direction.DOWN, level, pos, state, belowPos, belowState)) {
        return false;
    }
    if (belowState.getFluidState().getType().isSame(fluid)) {
        return true;     // 下方已有同种流体 → 算洞（继续向下流）
    }
    return this.canHoldFluid(level, belowPos, belowState, fluid);     // 下方能容纳水
}

private boolean canHoldFluid(BlockGetter level, BlockPos pos, BlockState state, Fluid fluid) {
    Block block = state.getBlock();
    if (block instanceof LiquidBlockContainer container) {
        return container.canPlaceLiquid(null, level, pos, state, fluid);
    }
    if (block instanceof DoorBlock || state.is(BlockTags.SIGNS) || state.is(Blocks.LADDER) || ...) {
        return false;     // 这些方块"不允许水进入"
    }
    Material material = ...;     // 1.20 之前用 Material 概念，1.20+ 改用 BlockBehaviour
    return state.canBeReplaced();
}
```

**关键**：

- 下方是"可被流体替换"的方块（air、tall_grass、water 自身）→ hole。
- 下方有同种流体 → 算 hole（向下流）。
- 下方是固体 / 特殊方块（梯子、活板门）→ 不算 hole。

## 6.3.5 getCacheKey：缓存优化

`getSpread` / `getSlopeDistance` 内部用 `Short2ObjectMap` / `Short2BooleanMap` 缓存：

```java
private static short getCacheKey(BlockPos from, BlockPos to) {
    int dx = to.getX() - from.getX();
    int dy = to.getY() - from.getY();
    int dz = to.getZ() - from.getZ();
    return (short)((dx + 128 & 255) << 8 | (dy + 128 & 15) << 4 | (dz + 128 & 15));
}
```

**编码 (dx, dy, dz) 偏移到一个 short**——12 bit。

**作用**：递归 BFS 中相同 (pos, neighborPos) 对可能被多次访问——缓存避免重复 getBlockState / getFluidState 调用。

**性能效果**：典型 spread 调用约 15-30 次 getBlockState（不缓存可能 50-100 次）。

## 6.3.6 实战：水流向洞的过程

```
桌面布局：
y=64:   [W][.][.][.][.]          ← W 是水源
y=63:   [.][.][.][.][.]          ← 全是固体（除最右下方有洞）
y=62:   [.][.][.][.][_]          ← _ 是 hole（air）

[Tick 0] 玩家放水源 W (y=64)
  → water.tick → spread
  → 向下检查：y=63 是固体 → 不能下流
  → spreadToSides：调 getSpread(y=64 W)
    
getSpread:
  对 EAST 方向：
    邻居 (1,64,0)：air
    canPassThrough → yes
    检查邻居下方 (1,63,0)：固体，下方再下方 (1,62,0) 也是固体 → not hole
    → getSlopeDistance(pos=(1,64,0), distance=1, skipDir=WEST, ...)
      对 EAST: 检查 (2,63,0) 固体...not hole
      → getSlopeDistance(pos=(2,64,0), distance=2, ...)
        对 EAST: 检查 (3,63,0) 固体, (3,62,0) 固体...not hole
        → getSlopeDistance(pos=(3,64,0), distance=3, ...)
          对 EAST: 检查 (4,63,0) 固体, (4,62,0) air → IS HOLE
          return 3
        return 3
      return 3
    distance EAST = 3
  
  其他方向（NORTH/SOUTH/WEST）：
    NORTH: 没洞 → 1000
    SOUTH: 没洞 → 1000
    WEST: 没洞 → 1000
  
  最小 = 3 (EAST)
  result = { EAST: flowing_water_level=7 }

[Tick 0] 处理 result：
  spreadTo((1,64,0), EAST, water_level=7)
  → setBlock((1,64,0), water_level=7)
  → schedule 下次 tick

[Tick 5] water_level=7 at (1,64,0).tick → spread
  → spreadToSides → getSpread((1,64,0))
  → ... 类似过程，发现 EAST 离 hole 距离 = 2
  → flow EAST

[Tick 25] 水到达 (4,64,0)
  → 检查向下：(4,63,0) 固体 → 不下流
  → 但 (4,63,0) 不是 hole（hole 是再下面）
  → 继续 EAST 但 newLevel = 7-1*5 = 2

最终：水从 W 出发，5 格向 EAST 蔓延，每 5 tick 衰减一格，直到流到 (4,64,0)（4 格邻 hole）→ 流过去 → 下落。
```

**视觉**：玩家放水后看到一条水流"主动找洞"——5-10 秒内完成。

## 6.3.7 affectsFlow：哪些方块影响 flow Vec3

```java
protected boolean affectsFlow(FluidState state) {
    return state.isEmpty() || state.getType().isSame(this.getSource());
}
```

**`getFlow` 计算流向时**：相邻方块如果是空气 / 同种流体 → 影响流向；其他流体（水 vs 熔岩）/ 固体 → 不影响。

## 6.3.8 性能：spread 一次的开销

```
单次 fluid tick → spread:
- 向下检查：1 次 getBlockState + getFluidState
- 4 方向 spreadToSides：
  - 每方向初始检查：1 次 getBlockState
  - getSlopeDistance 递归（深度 ≤ 4）：~10-30 次 getBlockState
- 总：~30-60 次方块查询
- 时间：~10-30 微秒 / spread

每 tick:
- 单大型水域：~100 个 fluidTick
- 总 fluid tick 时间：~1-3 ms / tick
```

可接受。**但水位炸弹（玩家挖大型水底）瞬间产生几千 fluid tick**——会触发 budget=65536 限制 + 多 tick 处理。

## 6.3.10 邻居 spreadToSides 的多方向选择

```java
// 多个方向同距离 (slope) → 都流
result.put(dir, newSpread);
// 注意：不是只选第一个，而是把所有 slope==min 的都放进 result
```

**视觉效果**：

- 水源对称放在两个洞中间 → 同时向两边流。
- 完全没洞 → 4 方向均流（slope=1000 全部相同，全部 fill）。

## 6.3.11 C++ 移植

```cpp
namespace mc::fluid {

class FlowingFluid : public Fluid {
protected:
    using StatePair = std::pair<const BlockState*, FluidState>;
    using StateCache = std::unordered_map<int16_t, StatePair>;
    using HoleCache = std::unordered_map<int16_t, bool>;
    
    static int16_t getCacheKey(BlockPos from, BlockPos to) {
        int dx = to.x - from.x;
        int dy = to.y - from.y;
        int dz = to.z - from.z;
        return int16_t(((dx + 128) & 255) << 8 | ((dy + 128) & 15) << 4 | ((dz + 128) & 15));
    }
    
    std::map<Direction, FluidState> getSpread(ServerLevel& level, BlockPos pos, const BlockState& state) {
        int slope = 1000;
        std::map<Direction, FluidState> result;
        StateCache stateCache;
        HoleCache holeCache;
        
        for (Direction dir : {Direction::NORTH, Direction::EAST, Direction::SOUTH, Direction::WEST}) {
            BlockPos neighborPos = pos.relative(dir);
            int16_t cacheKey = getCacheKey(pos, neighborPos);
            
            auto [it, _] = stateCache.try_emplace(cacheKey, [&]() {
                const BlockState* bs = level.getBlockState(neighborPos);
                return std::make_pair(bs, bs->getFluidState());
            }());
            const BlockState* neighborState = it->second.first;
            FluidState neighborFluid = it->second.second;
            
            FluidState newSpread = getNewLiquid(level, neighborPos, *neighborState);
            
            if (canPassThrough(level, newSpread.getType(), pos, state, dir, neighborPos, *neighborState, neighborFluid)) {
                BlockPos belowOfNeighbor = neighborPos.below();
                int16_t holeKey = getCacheKey(neighborPos, belowOfNeighbor);
                auto [hit, _2] = holeCache.try_emplace(holeKey, [&]() {
                    const BlockState* belowState = level.getBlockState(belowOfNeighbor);
                    return isWaterHole(level, getFlowing(), neighborPos, *neighborState, belowOfNeighbor, *belowState);
                }());
                bool isHole = hit->second;
                
                int distance = isHole ? 0 : getSlopeDistance(level, neighborPos, 1, dir.getOpposite(), *neighborState, pos, stateCache, holeCache);
                
                if (distance < slope) {
                    result.clear();
                    slope = distance;
                }
                if (distance == slope) {
                    result[dir] = newSpread;
                }
            }
        }
        
        return result;
    }
    
    int getSlopeDistance(ServerLevel& level, BlockPos pos, int currentDistance, Direction skipDirection,
                          const BlockState& state, BlockPos originalPos, StateCache& stateCache, HoleCache& holeCache) {
        int min = 1000;
        for (Direction dir : Direction::HORIZONTAL) {
            if (dir == skipDirection) continue;
            // ... 类似 getSpread 的逻辑 ...
            if (isHole) return currentDistance;
            if (currentDistance < getSlopeFindDistance(level)) {
                int sub = getSlopeDistance(level, neighborPos, currentDistance + 1, dir.getOpposite(), *neighborState, originalPos, stateCache, holeCache);
                if (sub < min) min = sub;
            }
        }
        return min;
    }
};

}
```

## 6.3.12 一句话总结

水水平扩散用**距离场算法**——对每个候选方向（4 邻居），调 `getSlopeDistance` 递归 BFS 找最近"hole"（下方可被替换的位置）；选最小距离的方向；多方向同距 → 都流；搜索深度 `getSlopeFindDistance` 主世界水=4 / 熔岩=2 防止性能爆；用 `Short2ObjectMap` 缓存递归中重复的 (pos, neighborPos) 状态查询；视觉效果：水"主动找下落点"而非平均扩散——这是流体"智能"流动的来源；单 spread 约 30-60 次方块查询、~10-30 微秒。
