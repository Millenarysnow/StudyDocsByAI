## 2.2.2 Tag 接口

打开 `net.minecraft.nbt.Tag`：

```java
public interface Tag {
    byte TAG_END = 0; ... TAG_LONG_ARRAY = 12; (12 个常量)
    int MAX_DEPTH = 512;

    void write(DataOutput out) throws IOException;
    @Override String toString();
    byte getId();
    TagType<?> getType();
    Tag copy();
    int sizeInBytes();
    default String getAsString();
    void accept(TagVisitor v);
    StreamTagVisitor.ValueResult accept(StreamTagVisitor v);
    default void acceptAsRoot(StreamTagVisitor v);
}
```

**6 个核心方法**：

1. **`write(DataOutput)`**：把自己写到字节流，按 2.1 节的二进制格式。
2. **`getId()`**：返回 Tag type id（0-12）。
3. **`getType()`**：返回 `TagType<?>` 元描述符（下一小节讲）。
4. **`copy()`**：深拷贝。
5. **`sizeInBytes()`**：估算自己在 JVM 堆上的内存占用（不是磁盘 / wire 大小！）。给 NbtAccounter 算预算用。
6. **`accept(TagVisitor)`**：双分派（visitor pattern）。

**注意 `Tag` 接口里没有 `read` 方法**。读取是 `TagType` 的职责（下一小节）。这是因为读取需要分配新对象，"无状态接口"职责是写入和访问。

## 2.2.3 TagType：Tag 的元类型

打开 `net.minecraft.nbt.TagType`：

```java
public interface TagType<T extends Tag> {
    T load(DataInput in, NbtAccounter acc) throws IOException;
    StreamTagVisitor.ValueResult parse(DataInput in, StreamTagVisitor v, NbtAccounter acc) throws IOException;
    void skip(DataInput in, int count, NbtAccounter acc) throws IOException;
    void skip(DataInput in, NbtAccounter acc) throws IOException;
    String getName();
    String getPrettyName();
    default boolean isValue();

    static TagType<EndTag> createInvalid(int id);
}
```

**为什么 TagType 和 Tag 分开？**

- **Tag 实例**承担"已经反序列化好的对象"——每个 Tag 实例代表一个具体的值。
- **TagType 单例**承担"读取 / 跳过 / parse 的能力"——它是一个静态工厂 + 二进制读取器。

每个 Tag 子类有一个 `public static final TagType<X> TYPE` 静态字段，对应该 type 的 reader：

```java
// CompoundTag.java（行 35-）
public static final TagType<CompoundTag> TYPE = new TagType.VariableSize<CompoundTag>() {
    public CompoundTag load(DataInput in, NbtAccounter acc) throws IOException {
        acc.pushDepth();
        try {
            return loadCompound(in, acc);
        } finally {
            acc.popDepth();
        }
    }
    // ...
};
```

**`TagType.VariableSize` vs `TagType.StaticSize`**：

- StaticSize（基础数值 tag）：每个实例字节数固定（BYTE=1, INT=4, LONG=8, ...），可以快速 skip。
- VariableSize（数组、字符串、列表、复合）：长度动态，必须扫到才知道结束。

## 2.2.4 TagTypes：全局类型注册表

打开 `net.minecraft.nbt.TagTypes`：

```java
public class TagTypes {
    private static final TagType<?>[] TYPES = new TagType<?>[]{
        EndTag.TYPE,
        ByteTag.TYPE, ShortTag.TYPE, IntTag.TYPE, LongTag.TYPE,
        FloatTag.TYPE, DoubleTag.TYPE,
        ByteArrayTag.TYPE, StringTag.TYPE,
        ListTag.TYPE, CompoundTag.TYPE,
        IntArrayTag.TYPE, LongArrayTag.TYPE
    };

    public static TagType<?> getType(int id) {
        return id >= 0 && id < TYPES.length ? TYPES[id] : TagType.createInvalid(id);
    }
}
```

**13 个静态 type 实例的查找表**。给定 type id（0-12），返回对应 TagType。

`getType(invalid id)` 不抛异常，而是返回一个特殊的"createInvalid" TagType——它的所有方法都抛 `IOException`。这种**懒错误**让 parser 主流程不需要处处 try/catch，错误统一在尝试读取时爆出。

## 2.2.5 数值 Tag：6 个不可变 record

`ByteTag` / `ShortTag` / `IntTag` / `LongTag` / `FloatTag` / `DoubleTag` 都是 immutable 的 record-like 类：

```java
// IntTag.java（简化）
public class IntTag extends NumericTag {
    public static final IntTag ZERO = new IntTag(0);
    public static final TagType<IntTag> TYPE = new TagType.StaticSize<IntTag>() {
        public IntTag load(DataInput in, NbtAccounter acc) throws IOException {
            acc.accountBytes(12L);     // 8 字节对象头 + 4 字节 int
            return new IntTag(in.readInt());
        }
        public int size() { return 4; }   // wire 字节
        // ...
    };
    private final int data;

    public IntTag(int v) { this.data = v; }

    public static IntTag valueOf(int v) {
        return v >= -128 && v <= 1024 ? CACHE[v + 128] : new IntTag(v);   // 类似 Integer 缓存
    }

    @Override public byte getId() { return TAG_INT; }
    @Override public void write(DataOutput out) throws IOException { out.writeInt(this.data); }
    @Override public Tag copy() { return this; }   // immutable，自己即拷贝
    @Override public int getAsInt() { return this.data; }
    // ... 各种 getAs* 转换 ...
}
```

**几个细节**：

1. **immutable** —— 字段 `final`、构造后不可改。这让 `copy()` 直接返回 self 即可。
2. **`valueOf` 缓存** —— 类似 `Integer.valueOf`，给小整数预创建实例减少 GC 压力。
3. **`getAs*` 跨类型转换** —— `intTag.getAsLong()` / `intTag.getAsFloat()` 等都允许，做 cast。
4. **共同基类 `NumericTag`** —— 抽取 `getAsByte/Short/Int/Long/Float/Double/Boolean` 等方法。

## 2.2.6 数组 Tag：可变 ByteArrayTag / IntArrayTag / LongArrayTag

```java
// IntArrayTag.java（简化）
public class IntArrayTag extends CollectionTag<IntTag> {
    public static final TagType<IntArrayTag> TYPE = new TagType.VariableSize<IntArrayTag>() { ... };
    private int[] data;

    public IntArrayTag(int[] data) { this.data = data; }
    public IntArrayTag(List<Integer> list) {
        this.data = list.stream().mapToInt(Integer::intValue).toArray();
    }

    @Override public byte getId() { return TAG_INT_ARRAY; }
    @Override public void write(DataOutput out) throws IOException {
        out.writeInt(this.data.length);
        for (int i : this.data) out.writeInt(i);
    }
    @Override public Tag copy() { return new IntArrayTag(this.data.clone()); }
    public int[] getAsIntArray() { return this.data; }
    // ... 实现 List<IntTag> 的接口（包装数组每个元素为 IntTag） ...
}
```

`CollectionTag<E>` 是 ByteArray/IntArray/LongArray/ListTag 的共同基类，让它们能像 `List<E>` 一样迭代。

**`getAsIntArray()`** 直接返回**内部数组引用**——不是 defensive copy。这是性能选择：拷贝 chunk 的 BitStorage 值数组（数千个 int）会很慢。代价：调用方修改返回数组就会修改原 NBT。**约定**：调用方不许改，自己复制需求自己 .clone()。

## 2.2.7 StringTag

```java
public class StringTag implements Tag {
    private static final StringTag EMPTY = new StringTag("");
    public static final TagType<StringTag> TYPE = new TagType.VariableSize<StringTag>() {
        public StringTag load(DataInput in, NbtAccounter acc) throws IOException {
            acc.accountBytes(36L);
            String s = readAccounted(in, acc);
            acc.accountBytes(2L * s.length());     // 估算 String 内存
            return valueOf(s);
        }
    };
    private final String data;

    private StringTag(String s) { this.data = Objects.requireNonNull(s); }
    public static StringTag valueOf(String s) {
        return s.isEmpty() ? EMPTY : new StringTag(s);
    }

    @Override public void write(DataOutput out) throws IOException { out.writeUTF(this.data); }
    @Override public byte getId() { return TAG_STRING; }
    @Override public String toString() { return TagParser.quoteAndEscape(this.data); }
}
```

**注意 `out.writeUTF`** ——这是 Java DataOutput 的 Modified UTF-8 + u16 长度前缀。直接对应 NBT wire 格式。

`NbtAccounter.accountBytes(2L * s.length())` 估算 String 在 JVM 内存里的尺寸——String 内部用 char[]，每个 char 2 字节（UTF-16）。

## 2.2.8 ListTag：异质列表

打开 `net.minecraft.nbt.ListTag`（行 12-45）：

```java
public class ListTag extends CollectionTag<Tag> {
    private static final int SELF_SIZE_IN_BYTES = 37;
    public static final TagType<ListTag> TYPE = new TagType.VariableSize<ListTag>() {
        private static ListTag loadList(DataInput in, NbtAccounter acc) throws IOException {
            acc.accountBytes(37L);
            byte elementType = in.readByte();          // 元素类型
            int length = in.readInt();
            if (elementType == 0 && length > 0) {
                throw new NbtFormatException("Missing type on ListTag");
            }
            acc.accountBytes(4L, (long)length);
            TagType<?> tagType = TagTypes.getType(elementType);
            List<Tag> list = Lists.newArrayListWithCapacity(length);
            for (int j = 0; j < length; j++) {
                list.add(tagType.load(in, acc));         // 递归读子元素
            }
            return new ListTag(list, elementType);
        }
    };

    private final List<Tag> list;
    private byte type;
    
    ListTag(List<Tag> list, byte type) { this.list = list; this.type = type; }
    public ListTag() { this(new ArrayList<>(), TAG_END); }

    public byte getElementType() { return this.type; }
    
    @Override
    public boolean add(Tag tag) {
        if (this.updateType(tag)) {       // 第一次 add 时设 type；后续 add 必须同 type
            this.list.add(tag);
            return true;
        }
        return false;
    }

    @Override
    public void write(DataOutput out) throws IOException {
        if (this.list.isEmpty()) this.type = 0;
        out.writeByte(this.type);
        out.writeInt(this.list.size());
        for (Tag t : this.list) t.write(out);
    }
}
```

**重点**：

1. **第一个 add 决定 type**——`updateType(tag)` 第一次设 this.type，之后插入必须同 type 否则拒绝。
2. **空 ListTag 的 type 是 TAG_END (0)**——序列化时把 0 写进去，反序列化看到 type=0 + length=0 视为合法空列表。
3. **`load` 递归调用 `tagType.load(in, acc)`**——这是 NBT 反序列化的递归入口。每个子元素可能继续是个 ListTag 或 CompoundTag。

## 2.2.9 CompoundTag：键值字典

打开 `net.minecraft.nbt.CompoundTag`（行 35-63）：

```java
public class CompoundTag implements Tag {
    private static final int SELF_SIZE_IN_BYTES = 48;
    public static final TagType<CompoundTag> TYPE = new TagType.VariableSize<CompoundTag>() {
        public CompoundTag load(DataInput in, NbtAccounter acc) throws IOException {
            acc.pushDepth();
            try {
                return loadCompound(in, acc);
            } finally {
                acc.popDepth();
            }
        }
        
        private static CompoundTag loadCompound(DataInput in, NbtAccounter acc) throws IOException {
            acc.accountBytes(48L);
            Map<String, Tag> map = Maps.newHashMap();
            byte childType;
            while ((childType = in.readByte()) != 0) {       // 0 = END marker
                String name = readString(in, acc);
                Tag tag = readNamedTagData(TagTypes.getType(childType), name, in, acc);
                if (map.put(name, tag) == null) {
                    acc.accountBytes(36L);                    // map entry 大小估算
                }
            }
            return new CompoundTag(map);
        }
    };

    private final Map<String, Tag> tags;

    public CompoundTag() { this.tags = Maps.newHashMap(); }
    public CompoundTag(Map<String, Tag> tags) { this.tags = tags; }

    public Set<String> getAllKeys() { return this.tags.keySet(); }
    public int size() { return this.tags.size(); }
    
    public boolean contains(String key) { return this.tags.containsKey(key); }
    public boolean contains(String key, int type) {
        Tag t = this.tags.get(key);
        return t != null && (t.getId() == type ||
                            (type == TAG_ANY_NUMERIC && t instanceof NumericTag));
    }

    public CompoundTag putByte(String key, byte v) { return this.tags.put(key, ByteTag.valueOf(v)) != null ? this : this; }
    public CompoundTag putShort(...);
    public CompoundTag putInt(...);
    public CompoundTag putLong(...);
    // ... 各种类型的 put 方法 ...

    public byte getByte(String key)   { return ((NumericTag)this.tags.get(key)).getAsByte(); }
    public short getShort(...);
    public int getInt(...);
    // ...

    @Override
    public void write(DataOutput out) throws IOException {
        for (String key : this.tags.keySet()) {
            Tag tag = this.tags.get(key);
            writeNamedTag(key, tag, out);
        }
        out.writeByte(0);                  // END marker
    }
}
```

**重点**：

1. **内部是 `HashMap<String, Tag>`**——同名键自动覆盖（put 行为）。这意味着**NBT compound 内同名键不会重复**。
2. **序列化顺序不固定**——HashMap 没有顺序保证。不同 JVM 执行同样代码可能写出字节顺序不同的输出。**这没问题**——反序列化只看 key 名字，顺序不影响语义。
3. **END (0x00) 作为 compound 终结**——`while (readByte != 0)` 循环。
4. **tons of 类型化 getter / putter**：getByte / getInt / getLong / getString / getCompound / getListOfCompound 等。**每种 get 都假设类型对，错了抛 ClassCastException**——所以习惯性先 `contains(key, TAG_INT)` check 一下。
5. **`writeNamedTag(key, tag, out)`** 把"id + name + payload"写出去，对应 2.1 节的 wire layout。

## 2.2.11 Visitor 模式：toString / 序列化 / 转换

`Tag.accept(TagVisitor)`：每个 Tag 子类实现 visitor 双分派，让外部代码无需 instanceof 判断。

```java
public interface TagVisitor {
    void visitString(StringTag t);
    void visitByte(ByteTag t);
    void visitShort(ShortTag t);
    void visitInt(IntTag t);
    void visitLong(LongTag t);
    void visitFloat(FloatTag t);
    void visitDouble(DoubleTag t);
    void visitByteArray(ByteArrayTag t);
    void visitIntArray(IntArrayTag t);
    void visitLongArray(LongArrayTag t);
    void visitList(ListTag t);
    void visitCompound(CompoundTag t);
    void visitEnd(EndTag t);
}
```

每个 Tag 子类的 `accept(visitor)` 调用 `visitor.visit*(this)`。

**典型实现 `StringTagVisitor`**（产生 SNBT）：

```java
public class StringTagVisitor implements TagVisitor {
    private final StringBuilder builder = new StringBuilder();

    public String visit(Tag tag) { tag.accept(this); return this.builder.toString(); }

    @Override public void visitInt(IntTag t)    { this.builder.append(t.getAsInt()); }
    @Override public void visitFloat(FloatTag t){ this.builder.append(t.getAsFloat()).append('f'); }
    @Override public void visitString(StringTag t) { this.builder.append(quoteAndEscape(t.getAsString())); }
    @Override public void visitCompound(CompoundTag t) {
        this.builder.append('{');
        boolean first = true;
        for (String key : t.getAllKeys()) {
            if (!first) this.builder.append(',');
            this.builder.append(escapeKey(key)).append(':');
            t.get(key).accept(this);
            first = false;
        }
        this.builder.append('}');
    }
    // ...
}
```

**其他 visitor 实现**：
- `SnbtPrinterTagVisitor` —— 美化版 SNBT（缩进、换行）。
- `TextComponentTagVisitor` —— 在聊天框可视化展示 NBT，含语法高亮。
- `StreamTagVisitor` —— 边读边访问 NBT，避免完全展开成对象树（用于流式扫描，比如统计某 key）。

**为什么不直接 `Tag.toString()`？** 历史上 toString 输出格式不一致。Mojang 抽出 visitor 让"序列化为何种文本"由调用者决定，多个 visitor 共存。

## 2.2.13 内存预算

JVM 里 NBT 的对象开销（含对象头 + 内部引用）：

| Tag | 平均字节 | 备注 |
|-----|---------|------|
| ByteTag / IntTag / LongTag / FloatTag / DoubleTag | 16-24 | 含对象头 + 单值；valueOf 缓存复用小整数 |
| StringTag (空) | 16 | EMPTY singleton |
| StringTag (短串) | 56 | 28 自身 + ~28 String 内部 |
| ByteArrayTag (N) | 16 + N | 数组头 + 数据 |
| IntArrayTag (N) | 16 + 4N | |
| LongArrayTag (N) | 16 + 8N | |
| ListTag (空) | 56 | ArrayList 内部 |
| ListTag (M elements) | 56 + 8M + Σelt | |
| CompoundTag (空) | 56 | HashMap 内部 |
| CompoundTag (M entries) | 56 + ~36M + Σ(name + value) | |

**典型 chunk NBT 总占用**：~300 KB（vs 磁盘上 ~50 KB 压缩）。

## 2.2.14 实战：构造一个 chunk 头并序列化

```java
CompoundTag root = new CompoundTag();
root.putInt("DataVersion", 4189);
root.putString("Status", "minecraft:full");
root.putInt("xPos", 0);
root.putInt("zPos", 0);
root.putLong("LastUpdate", System.currentTimeMillis() / 50);
root.putByte("isLightOn", (byte)1);

ListTag sections = new ListTag();
for (int sy = -4; sy <= 19; sy++) {
    CompoundTag section = new CompoundTag();
    section.putByte("Y", (byte)sy);
    sections.add(section);
}
root.put("sections", sections);

// 序列化到内存 byte[]
ByteArrayOutputStream baos = new ByteArrayOutputStream();
NbtIo.write(root, new DataOutputStream(baos));
byte[] bytes = baos.toByteArray();
System.out.println("Serialized: " + bytes.length + " bytes");
```

输出大约 ~150 字节（不算 sections 内的实际数据）。

## 2.2.15 C++ 移植

C++ 里 NBT 的最优实现是 `std::variant` + concrete struct（不是 OOP 继承）：

```cpp
namespace mc::nbt {
    struct ByteTag       { int8_t value; };
    struct ShortTag      { int16_t value; };
    struct IntTag        { int32_t value; };
    struct LongTag       { int64_t value; };
    struct FloatTag      { float value; };
    struct DoubleTag     { double value; };
    struct ByteArrayTag  { std::vector<int8_t> value; };
    struct StringTag     { std::string value; };
    struct IntArrayTag   { std::vector<int32_t> value; };
    struct LongArrayTag  { std::vector<int64_t> value; };

    struct ListTag;
    struct CompoundTag;

    using Tag = std::variant<
        std::monostate,         // 0: END
        ByteTag, ShortTag, IntTag, LongTag,
        FloatTag, DoubleTag,
        ByteArrayTag, StringTag,
        ListTag,                // 9
        CompoundTag,            // 10
        IntArrayTag, LongArrayTag
    >;

    struct ListTag {
        std::vector<Tag> elements;
        uint8_t elementType;    // 必须同 type
    };

    struct CompoundTag {
        // 用 flat_map 还是 unordered_map？
        // - flat_map：内存紧凑，小尺寸更快
        // - unordered_map：大尺寸 lookup O(1)
        // 推荐 flat_map（NBT compound 通常 ≤ 30 entry）
        boost::container::flat_map<std::string, Tag> entries;
    };

    // 类型 id（与 variant index 对应）
    enum class TagType : uint8_t {
        END = 0, BYTE, SHORT, INT, LONG, FLOAT, DOUBLE,
        BYTE_ARRAY, STRING, LIST, COMPOUND, INT_ARRAY, LONG_ARRAY
    };

    inline TagType tagType(const Tag& t) {
        return TagType(t.index());      // variant index 与 type id 完美匹配
    }
}
```

**为什么 `std::variant` 比继承好**：

1. **栈上存储**：variant 内联，没有堆分配。NBT 解析时大部分 tag 是基本数值，每个堆分配是性能噩梦。
2. **类型分发更快**：variant index 是 1 字节 enum，switch jump table。继承的 vtable 是 8 字节指针 + 间接调用。
3. **visitor 自然**：`std::visit([](auto& tag){ ... }, tag)` 编译期分派，比虚函数 visitor 更快。
4. **value semantics**：拷贝 / 移动语义统一，无需手写 `clone()`。

**唯一痛点**：variant 必须列出所有 alternatives。NBT 有 12 个固定类型，列起来不痛苦。

## 2.2.16 一句话总结

NBT 在 JVM 内存里是 `Tag` 接口 + 12 个具体子类，每类有对应的 `TagType<T>` 静态 reader 单例；数值 tag 是 immutable 缓存类（`IntTag.valueOf` 类似 `Integer.valueOf`），数组 / 字符串 / 列表 / 复合是 mutable 容器；CompoundTag 内部 HashMap，同名键自动覆盖、序列化顺序无保证；ListTag 强制元素同 type；EndTag 是哨兵（compound 终结符）；TagVisitor 双分派让 toString / SNBT / 渲染分别由不同 visitor 实现；C++ 实现用 `std::variant` + flat_map 比 OOP 继承快 5-10×。
