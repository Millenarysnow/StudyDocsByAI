## 2.6.1 SerializableChunkData 是什么

`net.minecraft.world.level.chunk.storage.SerializableChunkData` 是 1.21 新增的 **Java record**，承担"chunk 内存数据 ↔ NBT" 中间表示。

**它存在的意义**：把 chunk 序列化拆成两步——

1. `LevelChunk → SerializableChunkData`：把内存 chunk 摘抄成"扁平的可序列化结构"。
2. `SerializableChunkData → CompoundTag`：把扁平结构按 NBT 格式打包。

反过来：

1. `CompoundTag → SerializableChunkData`：解析 NBT 字段填到 record。
2. `SerializableChunkData → LevelChunk`：从 record 重建内存 chunk。

**好处**：

- **测试友好**：能直接构造一个 SerializableChunkData，断言它的字段，无需先有一个 chunk 实例。
- **Codec 兼容**：record 自带 codec 配套（虽然这里没全用 codec）。
- **生命周期清晰**：内存对象 / NBT 树 / 序列化中介三层职责严格分。

**对比 1.20 的旧设计**：1.20 的 `ChunkSerializer.read(...)` / `write(...)` 直接接受 NBT，内部一边解析一边构造 LevelChunk，逻辑混在一起、难测试、难修改。1.21 的重构让"解析"和"构造"分两步走。

## 2.6.2 record 字段一览

打开 `SerializableChunkData`（行 76-95）：

```java
public record SerializableChunkData(
    Registry<Biome> biomeRegistry,
    ChunkPos chunkPos,
    int minSectionY,
    long lastUpdateTime,
    long inhabitedTime,
    ChunkStatus chunkStatus,
    @Nullable BlendingData.Packed blendingData,
    @Nullable BelowZeroRetrogen belowZeroRetrogen,
    UpgradeData upgradeData,
    @Nullable long[] carvingMask,
    Map<Heightmap.Types, long[]> heightmaps,
    ChunkAccess.PackedTicks packedTicks,
    ShortList[] postProcessingSections,
    boolean lightCorrect,
    List<SectionData> sectionData,
    List<CompoundTag> entities,
    List<CompoundTag> blockEntities,
    CompoundTag structureData
) {
    // ...
}
```

**18 个字段**。每个对应内存 chunk 的某部分。逐字段拆解：

| 字段 | 类型 | 内存来源 | NBT 字段名 |
|------|------|---------|-----------|
| biomeRegistry | Registry<Biome> | RegistryAccess | （不写盘） |
| chunkPos | ChunkPos | LevelChunk.getPos() | xPos / zPos |
| minSectionY | int | LevelHeightAccessor | yPos |
| lastUpdateTime | long | gameTime when saved | LastUpdate |
| inhabitedTime | long | LevelChunk.inhabitedTime | InhabitedTime |
| chunkStatus | ChunkStatus | ProtoChunk.status / FULL | Status |
| blendingData | BlendingData.Packed? | LevelChunk.blendingData | blending_data |
| belowZeroRetrogen | BelowZeroRetrogen? | ProtoChunk.belowZeroRetrogen | below_zero_retrogen |
| upgradeData | UpgradeData | ChunkAccess.upgradeData | UpgradeData |
| carvingMask | long[]? | ProtoChunk.carvingMask | carving_mask |
| heightmaps | Map<Type, long[]> | ChunkAccess.heightmaps（4 种） | Heightmaps |
| packedTicks | (List<SavedTick<Block>>, List<SavedTick<Fluid>>) | LevelChunkTicks | block_ticks / fluid_ticks |
| postProcessingSections | ShortList[] | ChunkAccess.postProcessing | PostProcessing |
| lightCorrect | boolean | ChunkAccess.isLightCorrect | isLightOn |
| sectionData | List<SectionData> | LevelChunkSection[] | sections |
| entities | List<CompoundTag> | ProtoChunk.entities | entities |
| blockEntities | List<CompoundTag> | LevelChunk.blockEntities serialized | block_entities |
| structureData | CompoundTag | structureStarts + structureRefs | structures |

**`SectionData` 内嵌 record**（同文件）：

```java
public static record SectionData(
    int y,
    @Nullable PalettedContainer<BlockState> states,
    @Nullable PalettedContainerRO<Holder<Biome>> biomes,
    @Nullable DataLayer blockLight,
    @Nullable DataLayer skyLight
) {}
```

每个 section 拆出 5 字段：Y 坐标、BlockState palette、Biome palette、方块光、天空光。

## 2.6.3 写盘时序：LevelChunk → CompoundTag

实际触发写盘的入口是 `ChunkSerializer.write(SerializableChunkData chunk)`（1.21 重构后）：

```java
public static CompoundTag write(SerializableChunkData chunk) {
    CompoundTag root = NbtUtils.addCurrentDataVersion(new CompoundTag());     // DataVersion
    root.putInt(X_POS_TAG, chunk.chunkPos.x);                                  // xPos
    root.putInt(Z_POS_TAG, chunk.chunkPos.z);                                  // zPos
    root.putInt("yPos", chunk.minSectionY);                                    // yPos
    root.putLong("LastUpdate", chunk.lastUpdateTime);
    root.putLong("InhabitedTime", chunk.inhabitedTime);
    root.putString("Status", chunk.chunkStatus.toString());
    root.putBoolean(IS_LIGHT_ON_TAG, chunk.lightCorrect);
    
    if (chunk.blendingData != null) {
        BlendingData.Packed.CODEC.encodeStart(NbtOps.INSTANCE, chunk.blendingData)
            .resultOrPartial(LOGGER::error)
            .ifPresent(t -> root.put("blending_data", t));
    }
    if (chunk.belowZeroRetrogen != null) {
        // ...
    }
    if (chunk.carvingMask != null) {
        root.putLongArray("carving_mask", chunk.carvingMask);
    }

    // Heightmaps
    CompoundTag heightmapsTag = new CompoundTag();
    for (Map.Entry<Heightmap.Types, long[]> e : chunk.heightmaps.entrySet()) {
        heightmapsTag.putLongArray(e.getKey().getSerializationKey(), e.getValue());
    }
    root.put(HEIGHTMAPS_TAG, heightmapsTag);

    // sections
    ListTag sections = new ListTag();
    for (SectionData sd : chunk.sectionData) {
        CompoundTag sec = new CompoundTag();
        sec.putByte("Y", (byte)sd.y);
        if (sd.states != null) {
            sec.put("block_states", BLOCK_STATE_CODEC
                .encodeStart(NbtOps.INSTANCE, sd.states).getOrThrow());
        }
        if (sd.biomes != null) {
            sec.put("biomes", makeBiomeCodec(chunk.biomeRegistry)
                .encodeStart(NbtOps.INSTANCE, sd.biomes).getOrThrow());
        }
        if (sd.blockLight != null) {
            sec.putByteArray(BLOCK_LIGHT_TAG, sd.blockLight.getData());
        }
        if (sd.skyLight != null) {
            sec.putByteArray(SKY_LIGHT_TAG, sd.skyLight.getData());
        }
        sections.add(sec);
    }
    root.put(SECTIONS_TAG, sections);

    // tick lists
    root.put(BLOCK_TICKS_TAG, SavedTick.saveTickList(chunk.packedTicks.blocks(), 
                                                     b -> BuiltInRegistries.BLOCK.getKey(b).toString()));
    root.put(FLUID_TICKS_TAG, SavedTick.saveTickList(chunk.packedTicks.fluids(),
                                                     f -> BuiltInRegistries.FLUID.getKey(f).toString()));

    // post processing
    ListTag pp = new ListTag();
    for (ShortList list : chunk.postProcessingSections) {
        ListTag inner = new ListTag();
        if (list != null) {
            for (short s : list) inner.add(ShortTag.valueOf(s));
        }
        pp.add(inner);
    }
    root.put("PostProcessing", pp);

    // entities & block entities & structures
    root.put("entities", listFromCompounds(chunk.entities));
    root.put("block_entities", listFromCompounds(chunk.blockEntities));
    root.put("structures", chunk.structureData);

    return root;
}
```

**结构**：`root` 是个 CompoundTag，含上面所有顶层字段。每个字段的写入是直接 putXXX 或通过 codec 编码。

## 2.6.4 读盘时序：CompoundTag → SerializableChunkData

打开 `SerializableChunkData.parse`（行 111-）：

```java
@Nullable
public static SerializableChunkData parse(LevelHeightAccessor heightAccess, RegistryAccess registries, CompoundTag root) {
    if (!root.contains("Status", 8)) return null;

    ChunkPos pos = new ChunkPos(root.getInt("xPos"), root.getInt("zPos"));
    long lastUpdate = root.getLong("LastUpdate");
    long inhabited = root.getLong("InhabitedTime");
    ChunkStatus status = ChunkStatus.byName(root.getString("Status"));
    UpgradeData upgrade = root.contains("UpgradeData", 10)
        ? new UpgradeData(root.getCompound("UpgradeData"), heightAccess)
        : UpgradeData.EMPTY;
    boolean lightOn = root.getBoolean("isLightOn");

    BlendingData.Packed blending = root.contains("blending_data", 10)
        ? BlendingData.Packed.CODEC.parse(NbtOps.INSTANCE, root.getCompound("blending_data"))
              .resultOrPartial(LOGGER::error).orElse(null)
        : null;

    BelowZeroRetrogen retrogen = ...;
    long[] carvingMask = root.contains("carving_mask", 12) ? root.getLongArray("carving_mask") : null;

    // heightmaps
    CompoundTag hmTag = root.getCompound("Heightmaps");
    Map<Heightmap.Types, long[]> heightmaps = new EnumMap<>(Heightmap.Types.class);
    for (Heightmap.Types type : status.heightmapsAfter()) {
        String key = type.getSerializationKey();
        if (hmTag.contains(key, 12)) {
            heightmaps.put(type, hmTag.getLongArray(key));
        }
    }

    // tick lists
    List<SavedTick<Block>> blockTicks = SavedTick.loadTickList(
        root.getList("block_ticks", 10),
        s -> BuiltInRegistries.BLOCK.getOptional(ResourceLocation.tryParse(s)),
        pos
    );
    List<SavedTick<Fluid>> fluidTicks = SavedTick.loadTickList(
        root.getList("fluid_ticks", 10),
        s -> BuiltInRegistries.FLUID.getOptional(ResourceLocation.tryParse(s)),
        pos
    );
    ChunkAccess.PackedTicks packedTicks = new ChunkAccess.PackedTicks(blockTicks, fluidTicks);

    // post processing
    ListTag ppTag = root.getList("PostProcessing", 9);
    ShortList[] postProcessing = new ShortList[ppTag.size()];
    for (int k = 0; k < ppTag.size(); k++) {
        ListTag inner = ppTag.getList(k);
        ShortList list = new ShortArrayList(inner.size());
        for (int l = 0; l < inner.size(); l++) list.add(inner.getShort(l));
        postProcessing[k] = list;
    }

    // entities / block_entities
    List<CompoundTag> entities = Lists.transform(root.getList("entities", 10), t -> (CompoundTag)t);
    List<CompoundTag> blockEntities = Lists.transform(root.getList("block_entities", 10), t -> (CompoundTag)t);

    // structures
    CompoundTag structures = root.getCompound("structures");

    // sections
    ListTag sectionsTag = root.getList("sections", 10);
    Registry<Biome> biomeReg = registries.lookupOrThrow(Registries.BIOME);
    Codec<PalettedContainerRO<Holder<Biome>>> biomeCodec = makeBiomeCodec(biomeReg);

    List<SectionData> sectionDataList = new ArrayList<>(sectionsTag.size());
    for (int i = 0; i < sectionsTag.size(); i++) {
        CompoundTag secTag = sectionsTag.getCompound(i);
        int y = secTag.getByte("Y");
        if (y >= heightAccess.getMinSectionY() && y <= heightAccess.getMaxSectionY()) {
            PalettedContainer<BlockState> states = secTag.contains("block_states", 10)
                ? BLOCK_STATE_CODEC.parse(NbtOps.INSTANCE, secTag.getCompound("block_states")).getOrThrow(SerializableChunkData.ChunkReadException::new)
                : new PalettedContainer<>(Block.BLOCK_STATE_REGISTRY, Blocks.AIR.defaultBlockState(), PalettedContainer.Strategy.SECTION_STATES);

            PalettedContainerRO<Holder<Biome>> biomes = secTag.contains("biomes", 10)
                ? biomeCodec.parse(NbtOps.INSTANCE, secTag.getCompound("biomes")).getOrThrow(...)
                : new PalettedContainer<>(biomeReg.asHolderIdMap(), biomeReg.getOrThrow(Biomes.PLAINS), PalettedContainer.Strategy.SECTION_BIOMES);

            DataLayer blockLight = secTag.contains(BLOCK_LIGHT_TAG, 7)
                ? new DataLayer(secTag.getByteArray(BLOCK_LIGHT_TAG)) : null;
            DataLayer skyLight = secTag.contains(SKY_LIGHT_TAG, 7)
                ? new DataLayer(secTag.getByteArray(SKY_LIGHT_TAG)) : null;
            
            sectionDataList.add(new SectionData(y, states, biomes, blockLight, skyLight));
        } else {
            sectionDataList.add(new SectionData(y, null, null, null, null));
        }
    }

    return new SerializableChunkData(
        biomeReg, pos, heightAccess.getMinSectionY(),
        lastUpdate, inhabited, status,
        blending, retrogen, upgrade,
        carvingMask, heightmaps, packedTicks,
        postProcessing, lightOn, sectionDataList,
        entities, blockEntities, structures
    );
}
```

**返回 null 表示**：根 NBT 没有 Status 字段——这通常是数据损坏，调用方应当 fallback。

**`status.heightmapsAfter()`** 控制读哪些 heightmap：例如 BIOMES 阶段的 chunk 只需要 WG 版（已被丢弃），FULL 阶段需要 4 种运行期版。1.6 节看过这个枚举。

## 2.6.5 Section 内的 codec 序列化

注意 BlockState 和 Biome 都通过 `Codec<PalettedContainer<...>>` 序列化：

```java
private static final Codec<PalettedContainer<BlockState>> BLOCK_STATE_CODEC = PalettedContainer.codecRW(
    Block.BLOCK_STATE_REGISTRY, BlockState.CODEC, PalettedContainer.Strategy.SECTION_STATES, Blocks.AIR.defaultBlockState()
);

private static Codec<PalettedContainerRO<Holder<Biome>>> makeBiomeCodec(Registry<Biome> biomeReg) {
    return PalettedContainerRO.codecRO(
        biomeReg.asHolderIdMap(),
        biomeReg.holderByNameCodec(),
        PalettedContainer.Strategy.SECTION_BIOMES,
        biomeReg.getOrThrow(Biomes.PLAINS)
    );
}
```

**`PalettedContainer.codecRW`** 是 1.3 节看过的——把 PalettedContainer 双向编解码。它的 NBT 形态：

```
{
    palette: [
        { Name: "minecraft:air" },
        { Name: "minecraft:stone" },
        { Name: "minecraft:oak_log", Properties: { axis: "y" } }
    ],
    data: [L; <1024 个 long>]    ← 4096 格的 BitStorage
}
```

**特殊优化**：当 palette 只有 1 个 entry 时，`data` 字段可以省略（推断"全 palette[0]"）。这就是为什么空 chunk 的 NBT 只有 palette = [`minecraft:air`]、没有 data。

## 2.6.6 SectionData → LevelChunkSection 的重建

把 SectionData 喂给 `LevelChunkSection` 构造：

```java
new LevelChunkSection(states, biomes);
```

构造函数（1.4 节看过，行 35-39）：

```java
public LevelChunkSection(PalettedContainer<BlockState> states, PalettedContainerRO<Holder<Biome>> biomes) {
    this.states = states;
    this.biomes = biomes;
    this.recalcBlockCounts();      // ★ 关键：从 palette 重算计数器
}
```

`recalcBlockCounts()`（1.4.5 节）从 palette 内容重新计算 nonEmptyBlockCount / tickingBlockCount / tickingFluidCount。**网络包不传计数器、磁盘也不存计数器**，每次都重算——因为这些值很容易计算（一次扫 palette 即可），存盘反而引入"计数器与实际数据不一致"的风险。

## 2.6.7 顶层调用链

完整的"chunk 写盘"流程：

```
ServerChunkCache 决定卸载 chunk(x, z)
  ▼
ChunkSerializer.write(serverLevel, chunk)
  │
  ├── 创建 SerializableChunkData：
  │   - 把 chunk 的 sections / heightmaps / ticks / blockEntities 提取
  │   - 把 entities NBT 列出
  │   - 调 structureStarts / refs 序列化为 CompoundTag
  │
  ├── SerializableChunkData → CompoundTag（按 2.6.3 节的写法）
  │
  ▼
IOWorker.store(chunkPos, compoundTag)
  │
  ├── 异步进队列
  ▼
后台线程：
  RegionFileStorage.write(chunkPos, compoundTag)
    │
    ├── NbtIo.writeUnnamed(compoundTag, dataOutputStream)
    │     ↑ 序列化为 raw bytes
    ├── 用 RegionFileVersion.selected() 包装压缩流
    │     ↑ 压缩
    ├── RegionFile.getChunkDataOutputStream(pos).write(compressedBytes)
    │     ↑ 写到扇区
    └── 更新 offsetTable + timestampTable + fsync
```

---

完整的"chunk 读盘"流程：

```
玩家走进区域，ChunkMap 决定加载 chunk(x, z)
  ▼
IOWorker.loadAsync(chunkPos)
  │
  ▼
后台线程：
  RegionFileStorage.read(chunkPos) → CompoundTag
    │
    ├── 找 region 文件
    ├── 查 offset table
    ├── 读对应扇区
    ├── 按 compression_type 解压
    └── NbtIo.read(decompressedStream)
  ▼
SerializableChunkData.parse(heightAccess, registries, compoundTag)
  │
  ▼
ProtoChunk.read(serverLevel, ..., serializableChunkData)
  │
  ├── 重建 LevelChunkSection[]
  ├── 重建 heightmaps
  ├── 重建 tick queues
  ├── 重建 structureStarts / structureReferences
  ├── 重建 blockEntities（pendingBlockEntities，懒加载）
  ├── 重建 entities NBT 列表（懒加载）
  │
  ▼
判断 chunkStatus：
  ├── status == FULL：构造 LevelChunk（接收 ProtoChunk 升级）
  └── status != FULL：保留 ProtoChunk，重新走 worldgen 流水线后续阶段
```

`ProtoChunk.read` / `LevelChunk` 升级构造在 1.5 节看过。

## 2.6.8 ProtoChunk vs LevelChunk 序列化的差异

写盘时**两类都走同一个 SerializableChunkData**——区别在 `chunkStatus` 字段：

- ProtoChunk：`status = chunkStatus()`（如 NOISE / SURFACE / FEATURES）。
- LevelChunk：`status = ChunkStatus.FULL`。

读盘时根据 status 决定构造哪个类型：

```java
if (chunkStatus == ChunkStatus.FULL) {
    // 直接构造 LevelChunk（跳过 worldgen 流水线）
} else {
    // 构造 ProtoChunk，由 ChunkMap 在后续阶段继续推进 worldgen
}
```

**这就是为什么 worldgen 中途关服再开存档不会重生成已开始的 chunk**——它们的 ProtoChunk 数据持久化了。

## 2.6.9 内存预算

写盘时一个 chunk 在内存中的临时高峰：

```
LevelChunk           ~150 KB
+ SerializableChunkData ~150 KB（拷贝/引用混合）
+ CompoundTag        ~300 KB（NBT 对象图）
+ raw bytes          ~50 KB
+ compressed bytes   ~10 KB

Peak ≈ 660 KB / chunk during save
```

读盘对称（峰值约 600 KB）。

视距 1024 chunk 全 dump 时内存峰值 ~700 MB——所以 IOWorker 串行处理（一个一个写），不并发，避免内存爆。

## 2.6.10 实战：完整 round-trip

```java
// 创建一个空 LevelChunk
ServerLevel level = ...;
LevelChunk chunk = new LevelChunk(level, new ChunkPos(0, 0));
chunk.setBlockState(new BlockPos(8, 64, 8), Blocks.STONE.defaultBlockState(), false);

// 序列化
SerializableChunkData scd = SerializableChunkData.copyOf(level, chunk);
CompoundTag root = ChunkSerializer.write(scd);

// 序列化 NBT 到 byte[]
ByteArrayOutputStream baos = new ByteArrayOutputStream();
DataOutputStream dos = new DataOutputStream(baos);
NbtIo.write(root, dos);
byte[] rawNbt = baos.toByteArray();

// 压缩
byte[] compressed = compress(rawNbt, RegionFileVersion.VERSION_DEFLATE);

// ⋯⋯ 假装写到 .mca 再读出来 ⋯⋯

// 反向：解压 + 解析
byte[] decompressed = decompress(compressed);
CompoundTag parsed = NbtIo.read(new DataInputStream(new ByteArrayInputStream(decompressed)));
SerializableChunkData scd2 = SerializableChunkData.parse(level, registries, parsed);

// 重建 ProtoChunk 或 LevelChunk
ProtoChunk pc = scd2.read(level, registries, ...);
// 或
LevelChunk lc = new LevelChunk(level, pc, ...);   // 升级构造
```

如果你能跑完这整段而 `lc.getBlockState((8, 64, 8))` 仍然是 STONE，本节就过关了。

## 2.6.11 C++ 移植

```cpp
namespace mc::chunk {

// 中间表示
struct SerializableChunkData {
    Registry<Biome>* biomeRegistry;
    ChunkPos chunkPos;
    int minSectionY;
    int64_t lastUpdateTime;
    int64_t inhabitedTime;
    ChunkStatus chunkStatus;
    std::optional<BlendingDataPacked> blendingData;
    std::optional<BelowZeroRetrogen> belowZeroRetrogen;
    UpgradeData upgradeData;
    std::optional<std::vector<uint64_t>> carvingMask;
    std::map<Heightmap::Type, std::vector<uint64_t>> heightmaps;
    PackedTicks packedTicks;
    std::vector<std::vector<int16_t>> postProcessingSections;
    bool lightCorrect;
    std::vector<SectionData> sectionData;
    std::vector<NbtCompound> entities;
    std::vector<NbtCompound> blockEntities;
    NbtCompound structureData;

    struct SectionData {
        int y;
        std::optional<PalettedContainer<const BlockState*>> states;
        std::optional<PalettedContainer<Holder<Biome>>> biomes;
        std::optional<DataLayer> blockLight;
        std::optional<DataLayer> skyLight;
    };

    static SerializableChunkData fromChunk(const LevelChunk& chunk);
    static std::optional<SerializableChunkData> parse(
        const LevelHeightAccessor& height,
        const RegistryAccess& registries,
        const NbtCompound& root);
};

class ChunkSerializer {
public:
    static NbtCompound write(const SerializableChunkData& data);
    static SerializableChunkData read(const NbtCompound& root, ...);
};

}
```

**关键工程选择**：

1. **`SerializableChunkData` 是值类型**：用 `std::move` 进出，避免拷贝。`std::vector<NbtCompound>` 直接持有。
2. **`std::optional<...>`** 替代 `@Nullable`：可读性 + 强制 check。
3. **`SectionData` 是嵌套 struct**：没必要分文件。
4. **NbtCompound 是 2.2 节的 variant**：直接复用。
5. **codec**：第一版可不写，直接 NbtCompound 字段操作。后期为 PalettedContainer 写专门 codec 时再统一。

## 2.6.12 一句话总结

`SerializableChunkData` 是 1.21 引入的 chunk 序列化中间表示，把"内存 LevelChunk ↔ NBT CompoundTag"拆成两步（数据载体类 + NBT 编解码），让序列化逻辑可测试、可独立修改；它持有 18 个字段对应 chunk 内存的全部状态——chunkPos / heightmaps / sections / blockEntities / structureStarts / packedTicks 等；ProtoChunk 与 LevelChunk 用同一份 SerializableChunkData，区别只在 chunkStatus 字段；写盘流程：LevelChunk → SerializableChunkData → CompoundTag → NBT bytes → 压缩 → 扇区；读盘对称，根据 status 决定构造 ProtoChunk 还是 LevelChunk。
