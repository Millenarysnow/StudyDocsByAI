## 7.5.1 包族分类

PLAY 阶段约 200+ 个 packet。Mojang 没有正式分类，但实用上分：

```
玩家行为 (~25 种)：移动、攻击、放置 / 挖方块、聊天、交互
    ServerboundMovePlayerPacket / ServerboundUseItemOnPacket
    ServerboundChatPacket / ServerboundPlayerActionPacket
    
实体同步 (~20 种)：spawn / move / rotate / 状态 / 死亡
    ClientboundAddEntityPacket
    ClientboundMoveEntityPacket
    ClientboundSetEntityDataPacket
    ClientboundRemoveEntitiesPacket
    
方块状态 (~10 种)：单 / 批量 / 事件
    ClientboundBlockUpdatePacket
    ClientboundSectionBlocksUpdatePacket
    ClientboundBlockEventPacket
    ClientboundBlockChangedAckPacket
    
Chunk (~5 种)：发送 / 卸载 / 光照
    ClientboundLevelChunkWithLightPacket
    ClientboundLightUpdatePacket
    ClientboundForgetLevelChunkPacket
    
游戏状态 (~15 种)：天气 / 时间 / 难度 / 重生
    ClientboundGameEventPacket
    ClientboundSetTimePacket
    ClientboundChangeDifficultyPacket
    
玩家管理 (~15 种)：加入 / 离开 / 玩家列表 / 经验
    ClientboundPlayerInfoUpdatePacket
    ClientboundSetExperiencePacket
    ClientboundSetHealthPacket
    
容器 (~15 种)：打开 / 关闭 / 槽位变化 / 操作
    ClientboundOpenScreenPacket
    ClientboundContainerSetSlotPacket
    ServerboundContainerClickPacket
    
聊天 / 系统消息 (~15 种)：聊天 / 命令 / 标题 / boss bar
    ClientboundSystemChatPacket
    ServerboundChatCommandPacket
    
高频低层 (~5 种)：keep-alive / ping / latency
    ClientboundKeepAlivePacket
    ServerboundKeepAlivePacket
    
特殊 (~10 种)：bundle / particle / sound / ⋯
    ClientboundBundlePacket
    ClientboundLevelParticlesPacket
    ClientboundSoundPacket
    
⋯
```

## 7.5.2 玩家移动包族

**5 种 ServerboundMovePlayer 变体**：

```java
public sealed interface ServerboundMovePlayerPacket extends Packet<ServerGamePacketListener> {
    record Pos(double x, double y, double z, boolean onGround, boolean horizontalCollision) implements ServerboundMovePlayerPacket;
    record Rot(float yRot, float xRot, boolean onGround, boolean horizontalCollision) implements ServerboundMovePlayerPacket;
    record PosRot(double x, double y, double z, float yRot, float xRot, boolean onGround, boolean horizontalCollision) implements ServerboundMovePlayerPacket;
    record StatusOnly(boolean onGround, boolean horizontalCollision) implements ServerboundMovePlayerPacket;
}
```

**4 个变种**（实际 5 个 type id，但接口 4 个 record）：

- **`Pos`**：位置变化但无旋转。
- **`Rot`**：旋转变化但无位置。
- **`PosRot`**：位置 + 旋转都变。
- **`StatusOnly`**：仅状态（onGround / collision）变。

**频率**：客户端每 tick (50ms) 发一次，按变化情况选 4 种之一。**理论 20 包/秒/玩家**——实际无变化时不发（`StatusOnly` 也只在状态切换时发）。

**服务端响应**：

- 检查合法性（速度上限 / 边界 / cheat）。
- 更新 ServerPlayer 位置。
- 广播给其他在视距内的玩家 → ClientboundMoveEntityPacket。
- 不发回给本玩家（节省带宽，假设客户端预测正确）。
- 如果不合法 → 发 ClientboundPlayerPositionPacket 强制纠正（橡皮筋）。

## 7.5.3 实体增量同步：VecDeltaCodec

```java
public class VecDeltaCodec {
    private static final double TRUNCATION_STEPS = 4096.0;     // 1/4096 格精度
    
    public static long encode(double x, double y, double z, double oldX, double oldY, double oldZ) {
        long dx = encodeDelta(x, oldX);
        long dy = encodeDelta(y, oldY);
        long dz = encodeDelta(z, oldZ);
        return ...;     // 打包成 long
    }
    
    private static long encodeDelta(double newVal, double oldVal) {
        return Math.round((newVal - oldVal) * TRUNCATION_STEPS);
    }
}
```

**编码**：每实体每 tick 位置 = (x_new - x_old) × 4096，编码为 short。

**精度**：1/4096 格 ≈ 0.244 mm。**人眼不可见的精度**。

**包大小**：

```
ClientboundMoveEntityPacket.Pos:
- entity id: VarInt 1-4 字节
- delta x: short 2 字节
- delta y: short 2 字节
- delta z: short 2 字节
- on ground: byte 1 字节

总：~9 字节 vs 朴素 24 字节 (3 doubles) → 60% 节省
```

**限制**：delta 必须 ∈ short 范围 = ±32768 / 4096 ≈ ±8 格。如果实体一 tick 动 > 8 格 → 用 `ClientboundTeleportEntityPacket` 完整位置。

## 7.5.4 chunk 同步：ClientboundLevelChunkWithLightPacket

```java
public record ClientboundLevelChunkWithLightPacket(
    int x, int z,
    ClientboundLevelChunkPacketData chunkData,
    ClientboundLightUpdatePacketData lightData
) implements Packet<ClientGamePacketListener> {
}

public record ClientboundLevelChunkPacketData(
    CompoundTag heightmaps,            // 仅 WORLD_SURFACE + MOTION_BLOCKING
    byte[] buffer,                      // chunk sections 数据
    List<BlockEntityInfo> blockEntities
) {
}

public record ClientboundLightUpdatePacketData(
    BitSet skyYMask,
    BitSet blockYMask,
    BitSet emptySkyYMask,
    BitSet emptyBlockYMask,
    List<byte[]> skyUpdates,
    List<byte[]> blockUpdates
) {
}
```

**单包结构**：

- chunk 坐标 (x, z)。
- 4 种 heightmap 中的 2 种（WORLD_SURFACE + MOTION_BLOCKING，只发客户端需要的）。
- chunk 24 个 section 的 PalettedContainer 序列化（详见 1.4.9）。
- BlockEntity 列表（每个 chunk 通常 0-5 个）。
- 光照数据（哪些 section 有 sky / block light + 实际数据）。

**典型大小**：

```
chunk sections (BlockState + Biome PalettedContainer): ~30-100 KB raw
heightmaps: ~600 字节
blockEntities: ~1 KB
sky light: ~24 KB（每 section 2 KB）
block light: ~24 KB

总 raw: ~80-150 KB
压缩后 (zlib threshold 256)：~10-30 KB
```

**视距 32 chunk² × 1024 chunk × 30 KB ≈ 30 MB / 玩家**——初始登录 burst。

    public static final StreamCodec<RegistryFriendlyByteBuf, ClientboundBlockUpdatePacket> STREAM_CODEC = ...;

## 7.5.7 批量段更新：ClientboundSectionBlocksUpdatePacket

```java
public record ClientboundSectionBlocksUpdatePacket(
    SectionPos sectionPos,
    short[] positions,              // 每方块在 section 内的 short 编码
    BlockState[] states
) implements Packet<ClientGamePacketListener> {
}
```

**优化**：单 section（16³）内多格变化 → 一个包发所有变化。

**Wire**：

```
[VarInt id]
[SectionPos: long 8 字节]
[VarInt count]
[count × (VarInt encoded_block_state)]    // 每个 14 字节
                                           // bits: state_id (16+) | local_pos (12)
```

每变化方块约 5-8 字节。**比单独 BlockUpdatePacket 节省 ~50% 带宽**。

**触发**：

- 活塞推动多格。
- 爆炸（TNT）。
- 大型 setBlock 操作。

## 7.5.11 Keep-Alive

```java
public record ClientboundKeepAlivePacket(long id) implements Packet<ClientGamePacketListener> {
}

public record ServerboundKeepAlivePacket(long id) implements Packet<ServerGamePacketListener> {
}
```

**协议**：

```
[每 15 秒]
Server → Client: ClientboundKeepAlivePacket(random_id)
Client → Server: ServerboundKeepAlivePacket(same_id)

[Server]
checkKeepAlive: 上次 keep-alive 在 30 秒前 → 断开（"Timed out"）
```

**用途**：

- 检测 dead connection（TCP 不一定立刻报错）。
- 测量 latency（往返时间）。

vanilla 默认 15 秒 keep-alive 间隔 + 30 秒超时。

## 7.5.12 ClientboundBundlePacket：1.20.5+

```java
public class ClientboundBundlePacket extends BundlePacket<ClientGamePacketListener> {
    public ClientboundBundlePacket(Iterable<Packet<? super ClientGamePacketListener>> packets) {
        super(packets);
    }
    
    @Override
    public PacketType<ClientboundBundlePacket> type() {
        return GamePacketTypes.BUNDLE;
    }
    
    @Override
    public void handle(ClientGamePacketListener listener) {
        listener.handleBundlePacket(this);
    }
}
```

**Bundle 机制**：

```
Server send:
  ClientboundBundleDelimiterPacket  [开始 bundle]
  ClientboundAddEntityPacket(creeper)
  ClientboundSetEntityDataPacket(creeper, fuse_active)
  ClientboundSoundPacket(fuse_sound)
  ClientboundBundleDelimiterPacket  [结束 bundle]

Client:
  接收所有 5 个 packet → 组成 ClientboundBundlePacket
  在同一渲染帧应用全部 → 玩家同时看到 creeper spawn + fuse 激活 + 声音
```

**目的**：避免 desync。例：

- 不 bundle：先看到 creeper（无 fuse），下一帧 fuse 激活——视觉不连续。
- bundle：creeper 出现时已 fuse 激活——视觉一致。

**实现**：`PacketBundlePacker` (outbound) + `PacketBundleUnpacker` (inbound) 在 Netty pipeline 里负责 wrap / unwrap。

**用例**：服务端"原子事件"——一次性发多个相关包。

## 7.5.13 完整带宽分析

服务端典型带宽（10 玩家活跃服）：

```
每秒 / 玩家:
- 玩家移动包: ~20 packet × 30 字节 = 600 B/s
- 实体同步: ~50 packet × 15 字节 = 750 B/s
- chunk 加载（边界）: ~5 chunk × 30 KB = 150 KB/s
- 方块更新: ~10 packet × 13 字节 = 130 B/s
- 状态 / 系统: ~5 packet × 50 字节 = 250 B/s

总：~152 KB/s/玩家
10 玩家服务端：~1.5 MB/s 上行
```

**chunk 包是带宽大头**——占 95%。优化重点。

---

## 7.5.14 客户端到服务端的高频包

```
每秒 / 玩家:
- ServerboundMovePlayerPacket: 20 packet × 30 字节 = 600 B/s
- ServerboundClientTickEndPacket (1.20.4+): 20 packet × 5 字节 = 100 B/s
- ServerboundUseItemOnPacket / 挖方块: 0-5 packet × 50 字节 = 250 B/s
- ServerboundChatPacket: 偶尔
- ServerboundKeepAlivePacket: 每 15 秒

总：~1 KB/s/玩家上行
```

**比下行小 100×**——客户端只发自己玩家行为，服务端发整世界状态。

## 7.5.15 C++ 移植：定义 packet 类

```cpp
namespace mc::network::play {

// 用 record-style struct + StreamCodec
struct ClientboundBlockUpdatePacket {
    BlockPos pos;
    const BlockState* blockState;
    
    void write(FriendlyByteBuf& buf) const {
        buf.writeBlockPos(pos);
        buf.writeVarInt(blockState->globalId());
    }
    
    static ClientboundBlockUpdatePacket read(RegistryFriendlyByteBuf& buf) {
        BlockPos pos = buf.readBlockPos();
        const BlockState* state = ALL_STATES[buf.readVarInt()];
        return {pos, state};
    }
    
    void handle(ClientGamePacketListener& listener) const {
        listener.handleBlockUpdate(*this);
    }
};

struct ClientboundLevelChunkWithLightPacket {
    int chunkX;
    int chunkZ;
    LevelChunkPacketData chunkData;
    LightUpdatePacketData lightData;
    
    void write(FriendlyByteBuf& buf) const;
    static ClientboundLevelChunkWithLightPacket read(RegistryFriendlyByteBuf& buf);
    void handle(ClientGamePacketListener& listener) const;
};

// ⋯ 200+ 个 packet 类型 ⋯

}
```

**工程量**：照搬 vanilla packet 列表。每个 packet ~30-100 行。**总 200 packet × 60 行 = 12000 行 C++**。

**优化策略**：用 codec 工具（类似 StreamCodec.composite）减少 boilerplate。

## 7.5.16 一句话总结

PLAY 阶段约 200 种 packet 分若干类——玩家移动（5 变体每 tick 一次）、实体同步（VecDeltaCodec 用 1/4096 精度的 short delta，包小 60%）、chunk 同步（ClientboundLevelChunkWithLightPacket 含 sections + heightmaps + lights，~30 KB 压缩 / chunk）、方块更新（单格 BlockUpdatePacket / 段批量 SectionBlocksUpdatePacket）、BlockEvent（活塞 / 唱片机动画）、Keep-Alive（每 15 秒，30 秒超时）；1.20.5+ Bundle Packet 让多个相关包在同帧应用避免 desync；带宽 95% 是 chunk 包；下行 ~150 KB/s/玩家、上行 ~1 KB/s/玩家；C++ 移植 ~12000 行 boilerplate（每 packet ~60 行）。
