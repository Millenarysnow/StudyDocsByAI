## 7.4.1 压缩：CompressionEncoder / CompressionDecoder

打开 `net.minecraft.network.CompressionEncoder`：

```java
public class CompressionEncoder extends MessageToByteEncoder<ByteBuf> {
    private final byte[] encodeBuf = new byte[8192];
    private final Deflater deflater;
    private int threshold;
    
    public CompressionEncoder(int threshold) {
        this.threshold = threshold;
        this.deflater = new Deflater();
    }
    
    @Override
    protected void encode(ChannelHandlerContext ctx, ByteBuf in, ByteBuf out) {
        int rawLen = in.readableBytes();
        if (rawLen < this.threshold) {
            // 不压缩
            VarInt.write(out, 0);     // 0 表示未压缩
            out.writeBytes(in);
        } else {
            // 压缩
            byte[] rawBytes = new byte[rawLen];
            in.readBytes(rawBytes);
            VarInt.write(out, rawBytes.length);     // 写原始长度
            this.deflater.setInput(rawBytes, 0, rawLen);
            this.deflater.finish();
            while (!this.deflater.finished()) {
                int n = this.deflater.deflate(this.encodeBuf);
                out.writeBytes(this.encodeBuf, 0, n);
            }
            this.deflater.reset();
        }
    }
    
    public void setThreshold(int threshold) { this.threshold = threshold; }
}
```

**算法**：

1. 如果 raw 长度 < threshold：写 `VarInt(0)` + 原始字节。
2. 如果 ≥ threshold：写 `VarInt(rawLen)` + zlib 压缩后字节。

**`VarInt(0)` 表示"未压缩"**——decoder 看到 0 就知道后面是原始数据。

**为什么有阈值**：

- 短包（< 256 字节）压缩效果差（zlib 头开销 5+ 字节）甚至更长。
- 长包（chunk 数据 > 1KB）压缩效果好（80% 压缩率）。
- 阈值切换让"长包压、短包不压"。

**默认阈值 256**：服务端 LOGIN 末尾发 `ClientboundLoginCompressionPacket(threshold=256)` 启用。

## 7.4.2 CompressionDecoder

```java
public class CompressionDecoder extends ByteToMessageDecoder {
    public static final int MAXIMUM_COMPRESSED_LENGTH = 0x7F_FF_FF;     // 8 MB-1
    public static final int MAXIMUM_UNCOMPRESSED_LENGTH = 0x80_0000;     // 8 MB
    private final Inflater inflater;
    private int threshold;
    private boolean validateDecompressed;
    
    @Override
    protected void decode(ChannelHandlerContext ctx, ByteBuf in, List<Object> out) {
        if (!in.isReadable()) return;
        int rawLen = VarInt.read(in);
        
        if (rawLen == 0) {
            // 未压缩
            out.add(in.readBytes(in.readableBytes()));
        } else {
            // 已压缩
            if (this.validateDecompressed) {
                if (rawLen < this.threshold) throw new DecoderException("badly compressed");
                if (rawLen > MAXIMUM_UNCOMPRESSED_LENGTH) throw new DecoderException("too large");
            }
            byte[] compressedBytes = new byte[in.readableBytes()];
            in.readBytes(compressedBytes);
            this.inflater.setInput(compressedBytes);
            byte[] rawBytes = new byte[rawLen];
            this.inflater.inflate(rawBytes);
            this.inflater.reset();
            out.add(Unpooled.wrappedBuffer(rawBytes));
        }
    }
}
```

**反向**：

- `rawLen == 0`：未压缩，直接读剩余。
- `rawLen > 0`：用 zlib 解压，期望解出 rawLen 字节。

**`validateDecompressed`** 校验：

1. rawLen ≥ threshold（说明发送方按规则发——< threshold 应该不压缩）。
2. rawLen ≤ 8 MB（防 zlib bomb）。

防 zlib 炸弹很重要——攻击者可发"100 字节 → 解压 1 GB"的恶意压缩流。

## 7.4.3 加密：AES-CFB8

打开 `net.minecraft.network.CipherEncoder`：

```java
public class CipherEncoder extends MessageToByteEncoder<ByteBuf> {
    private final CipherBase cipher;
    
    public CipherEncoder(Cipher cipher) {
        this.cipher = new CipherBase(cipher);
    }
    
    @Override
    protected void encode(ChannelHandlerContext ctx, ByteBuf in, ByteBuf out) {
        this.cipher.encipher(in, out);
    }
}
```

**`CipherBase`** 包装 javax.crypto.Cipher：

```java
public class CipherBase {
    private final Cipher cipher;
    private byte[] heapIn = new byte[0];
    private byte[] heapOut = new byte[0];
    
    public void encipher(ByteBuf in, ByteBuf out) {
        int len = in.readableBytes();
        byte[] bytes = bufToBytes(in, len);
        int outLen = this.cipher.getOutputSize(len);
        if (this.heapOut.length < outLen) this.heapOut = new byte[outLen];
        out.writeBytes(this.heapOut, 0, this.cipher.update(bytes, 0, len, this.heapOut));
    }
}
```

**算法**：用 AES-CFB8（128-bit 密钥，CFB 模式 8 位反馈）。

**特点**：

- AES-CFB8 是**流密码**变种——不需要 padding，输入字节数 = 输出字节数。
- 每字节加密依赖前 16 字节密文 → **不能并行**。
- IV (initialization vector) = sharedSecret 自身的前 16 字节（Mojang 设计）。

**为什么 CFB8 而不是 GCM / CTR / TLS**：

- 历史选择——Notch 时代的设计。
- 流密码不需要重新协商 IV。
- 简单。

**安全性**：

- AES-CFB8 在 128-bit key 下数学上仍安全。
- **但缺**：没有 authentication（不防中间人篡改密文，只防窃听）。
- 实际：MITM 仍可改 packet 内容——服务端会检测到反序列化错误并断连。

**对比 TLS**：TLS 1.3 用 GCM/Poly1305 + 完整 PKI——更安全。但 TLS 实现复杂（握手、证书、SNI），Mojang 选择简单的 RSA + AES-CFB8 自实现。

## 7.4.4 RSA + AES 握手流程

详细：

```
[客户端] 发 ServerboundHelloPacket(username, profileId)
  
[服务端]
  生成 RSA 1024-bit pub/priv 密钥对
  生成 16 字节随机 verifyToken
  
[服务端] → 客户端：
  ClientboundHelloPacket {
    serverId: "" (空字符串，<1.7 是服务器名)
    publicKey: RSA pub key (DER 编码 ~140 字节)
    verifyToken: 16 字节随机
    shouldAuthenticate: bool（在线模式 = true）
  }
  
[客户端]
  生成 16 字节随机 sharedSecret
  用 publicKey 加密 sharedSecret → encSharedSecret (~128 字节)
  用 publicKey 加密 verifyToken → encVerifyToken
  
[在线模式] 客户端联 Mojang sessionserver:
  POST https://sessionserver.mojang.com/session/minecraft/join
  body: { accessToken, profileId, serverId: SHA1(serverId + sharedSecret + publicKey).hex }
  
[客户端] → 服务端：
  ServerboundKeyPacket {
    encSharedSecret: byte[128]
    encVerifyToken: byte[128]
  }
  
[服务端]
  用 privateKey 解密 → sharedSecret + verifyToken
  校验 verifyToken == 原 verifyToken
  
[服务端启用加密]
  cipher_decrypt = AES-CFB8(sharedSecret, IV=sharedSecret[0..16])
  cipher_encrypt = 同上
  Connection.setEncryptionKey(decrypt, encrypt)
  
[在线模式] 服务端联 Mojang:
  GET https://sessionserver.mojang.com/session/minecraft/hasJoined?username=Steve&serverId=...
  → 返回玩家 profile (UUID + skin url)
  
[服务端] → 客户端 (此后所有包加密):
  ClientboundLoginCompressionPacket(threshold=256)
  Connection.setupCompression(256)
  
[服务端] → 客户端:
  ClientboundGameProfilePacket(uuid, username, properties)
  
[切换到 CONFIGURATION 阶段]
```

## 7.4.5 防中间人：双向校验

**MITM 攻击场景**：

```
Steve → Eve(中间人) → Server

1. Steve 收到 Server 的 publicKey1，但实际是 Eve 篡改后的 publicKey2 (Eve 自己的)
2. Steve 用 publicKey2 加密 sharedSecret_S → 发给 Eve
3. Eve 用自己的 privateKey2 解密 → 得 sharedSecret_S
4. Eve 用真正的 publicKey1 重新加密 sharedSecret_E (自己的) → 发给 Server
5. Server 收到 sharedSecret_E
6. 双方都不知 Eve 在中间
```

**Mojang 的防御**：在线模式下 **Mojang sessionserver** 验证。

```
Steve 联 sessionserver join: serverId = SHA1(serverId + sharedSecret_S + publicKey_received_by_Steve)
Eve 改了 publicKey → SHA1 包含 publicKey2

Server 收到 ServerboundKeyPacket → 解出 sharedSecret_E
Server 联 sessionserver hasJoined: serverId = SHA1(serverId + sharedSecret_E + publicKey1)

Steve 上传的 SHA1 ≠ Server 期望的 SHA1
→ Server 拒绝 Steve（"Failed to verify username"）
```

**Mojang sessionserver 充当 PKI 角色**——双方间接共享密钥认证。

**离线模式** 跳过这步——无认证 → MITM 直接成功。**仅 LAN 用**。

## 7.4.6 在线模式 vs 离线模式

`server.properties`：

```
online-mode=true     # 默认，启用在线模式
```

**在线模式**：

- 服务端联 Mojang 验证玩家身份。
- 玩家用真实 Mojang 账号登录。
- UUID 来自 Mojang，固定。
- 防止盗号 / 假身份。

**离线模式**：

- 不联 Mojang。
- 任何人能用任何用户名登录。
- UUID = MD5(username) 派生（"OfflinePlayer:Steve"）—— 多次重连 UUID 一致但与在线 UUID 不同。
- 用于 LAN / 局域网游戏 / 私服（Bukkit / Forge 等用代理时）。

**为什么有些大型私服用离线**：

- 玩家无 Mojang 账号也能玩（盗版用户）—— 法律灰色地带。
- 服务器自己做用户系统（密码 / 防盗）。
- 节省 Mojang auth 的 ~500 ms 延迟。

## 7.4.7 一段实战：玩家加入服务器全包流量

```
TCP 三次握手：~1 RTT (~50 ms)

[Tick 0]
Client → Server: ClientIntentionPacket(769, "mc.example.com", 25565, LOGIN)
                 ~25 字节

[Tick 1]
Client → Server: ServerboundHelloPacket("Steve", uuid)
                 ~30 字节

[Tick 2]
Server → Client: ClientboundHelloPacket("", pubKey, verifyToken)
                 ~150 字节

[Tick 5] (Client 联 Mojang sessionserver, ~500ms)

[Tick 30]
Client → Server: ServerboundKeyPacket(encSharedSecret, encVerifyToken)
                 ~260 字节

[Tick 31] (Server 联 Mojang hasJoined, ~500ms)

[启用 AES-CFB8 加密]

[Tick 60]
Server → Client: ClientboundLoginCompressionPacket(256)  [加密]
                 ~10 字节
[启用压缩 threshold=256]

Server → Client: ClientboundGameProfilePacket(uuid, "Steve", [])  [加密 + 压缩判断]
                 ~50 字节，未压缩（< 256）

[切到 CONFIGURATION]

Server → Client: 大量 ClientboundRegistryDataPacket / ClientboundUpdateTagsPacket
                 每包 ~10-50 KB，**压缩生效** → 实际 ~2-10 KB

Client → Server: ServerboundFinishConfigurationPacket
[切到 PLAY]

Server → Client: ClientboundLoginPacket + chunk × 200+ + entity × 几十
                 总 ~50 MB → 压缩后 ~10 MB

[玩家可玩]
总耗时：~3-5 秒
```

## 7.4.8 性能开销

```
压缩开销:
- 单包 < 256 字节：~10 ns 检查 + 写 VarInt(0)
- 单包 1 KB（压缩到 ~200B）：~20 微秒压缩
- 单包 50 KB（chunk）：~500 微秒压缩

加密开销:
- AES-CFB8：~5 微秒/KB（不能 SIMD 并行）

总每包平均 < 30 微秒
```

**chunk 包的压缩 + 加密占发送 CPU 的 ~30%**——对单线程 Netty 是显著负担。Mojang 用 IO 线程池分散。

## 7.4.9 Connection.setupCompression / setEncryptionKey

```java
// Connection
public void setupCompression(int threshold, boolean validateDecompressed) {
    if (threshold >= 0) {
        ChannelHandler decompress = this.channel.pipeline().get(HandlerNames.DECOMPRESS);
        if (decompress instanceof CompressionDecoder cd) {
            cd.setThreshold(threshold);
            cd.setValidateDecompressed(validateDecompressed);
        } else {
            this.channel.pipeline().addBefore(HandlerNames.DECODER, HandlerNames.DECOMPRESS, new CompressionDecoder(threshold));
        }
        // 类似处理 COMPRESS
    }
}

public void setEncryptionKey(Cipher decryptCipher, Cipher encryptCipher) {
    this.encrypted = true;
    this.channel.pipeline().addBefore(HandlerNames.SPLITTER, HandlerNames.DECRYPT, new CipherDecoder(decryptCipher));
    this.channel.pipeline().addBefore(HandlerNames.PREPENDER, HandlerNames.ENCRYPT, new CipherEncoder(encryptCipher));
}
```

**动态 pipeline 修改**：握手期间不加密 / 不压缩 → handshake 完成后**插入** decrypt / decompress handler。

**handler 插入位置很关键**：

- DECRYPT 在 SPLITTER 之前（先解密再分帧）。
- DECOMPRESS 在 DECODER 之前（先解压再反序列化）。
- 反之 ENCRYPT 在 PREPENDER 之前（加 VarInt 长度前缀**不**加密）+ COMPRESS 在 ENCRYPT 之前。

**outbound 顺序**：bytes → COMPRESS → ENCRYPT → PREPENDER → socket。

## 7.4.10 客户端选择：在线还是离线

客户端启动时：

```java
// Mojang launcher
if (user.hasMojangAccount && useOnline) {
    profile = mojangAuth();
    accessToken = profile.accessToken;
} else {
    accessToken = "0";    // 离线模式占位
    uuid = generateOfflineUUID(username);
}
```

启动时传 `--accessToken` 参数。`mcp/client/Start.java` 默认 `--accessToken 0` 即离线模式（开发用）。

服务端不直接看 accessToken——而是看玩家**联 Mojang 报告 join** 是否成功。离线模式玩家不联 Mojang，服务端 hasJoined 失败 → 拒绝（如果 online-mode=true）。

## 7.4.11 C++ 移植

```cpp
namespace mc::network {

class CompressionEncoder {
public:
    explicit CompressionEncoder(int threshold) : threshold_(threshold) {}
    
    std::vector<std::byte> encode(std::span<const std::byte> in) {
        std::vector<std::byte> out;
        out.reserve(in.size() + 8);
        
        if (in.size() < threshold_) {
            // 未压缩
            writeVarInt(out, 0);
            out.insert(out.end(), in.begin(), in.end());
        } else {
            // zlib 压缩
            writeVarInt(out, int(in.size()));
            std::vector<std::byte> compressed = zlibCompress(in);
            out.insert(out.end(), compressed.begin(), compressed.end());
        }
        return out;
    }
    
    void setThreshold(int threshold) { threshold_ = threshold; }
    
private:
    int threshold_;
};

class AesCfb8 {
public:
    AesCfb8(std::span<const std::byte> key, std::span<const std::byte> iv);
    
    void encrypt(std::span<const std::byte> in, std::span<std::byte> out);
    void decrypt(std::span<const std::byte> in, std::span<std::byte> out);
    
private:
    // 用 OpenSSL EVP_CIPHER_CTX 或 mbedtls 实现
    ...
};

class Connection {
public:
    void setupCompression(int threshold) {
        compressionThreshold_ = threshold;
        compressionEnabled_ = true;
    }
    
    void setEncryptionKey(std::span<const std::byte> sharedSecret) {
        decryptCipher_ = std::make_unique<AesCfb8>(sharedSecret, sharedSecret);
        encryptCipher_ = std::make_unique<AesCfb8>(sharedSecret, sharedSecret);
        encryptionEnabled_ = true;
    }
    
private:
    bool compressionEnabled_ = false;
    int compressionThreshold_ = -1;
    bool encryptionEnabled_ = false;
    std::unique_ptr<AesCfb8> decryptCipher_;
    std::unique_ptr<AesCfb8> encryptCipher_;
};

}
```

**关键依赖**：

- **zlib**（系统库或 vcpkg）：DEFLATE 压缩。
- **OpenSSL** / **mbedtls** / **botan**：AES 加密 + RSA 密钥对。
- **std::random_device**：sharedSecret / verifyToken 随机生成。

**Mojang sessionserver 接口**（HTTPS POST/GET）—— 用 libcurl 或 cpr (C++ requests)。

## 7.4.12 一句话总结

Mojang 的 packet 压缩在 LOGIN 末尾启用（默认阈值 256 字节）—— 短包 `VarInt(0) + 原始` / 长包 `VarInt(rawLen) + zlib 压缩`，防 zlib 炸弹的 8 MB 解压上限；加密用 AES-CFB8 流密码（128-bit key，IV = sharedSecret 前 16 字节），通过 RSA 1024-bit pub/priv 握手协商共享密钥；在线模式靠 Mojang sessionserver 双向校验防中间人（玩家上传 SHA1(serverId+sharedSecret+pubKey) → 服务端查询匹配）；离线模式跳过 auth → 任何人任何用户名能登录，UUID 由 username 派生；`Connection.setupCompression / setEncryptionKey` 动态修改 Netty pipeline 插入 decompress / decrypt handler；C++ 移植用 zlib + OpenSSL 即可。
