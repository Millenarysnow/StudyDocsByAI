## 7.1.1 Netty 简介

**Netty** 是 Java 的高性能异步网络框架（github.com/netty/netty）。1.7 之后 Mojang 切换到 Netty——之前用 java.nio 自己手写 IO loop。

**为什么 Netty**：

1. **高性能**：基于 epoll / kqueue，单线程能处理数千连接。
2. **抽象一致**：TCP / UDP / 内存通道用同一接口。
3. **handler 链**：把"分帧 / 解压 / 解密 / 反序列化"分层成独立 handler，配置灵活。
4. **零拷贝**：ByteBuf 与 OS native buffer 直接对应。

**Mojang 的应用**：

- 服务端：每个玩家连接 = 一个 Netty Channel + handler pipeline。
- 客户端：玩家与服务器的连接同样走 Netty。
- 单机：用 Netty 的 `LocalChannel` —— 内存通道但走同样 pipeline。

## 7.1.3 完整 inbound pipeline（接收端）

```
[TCP socket bytes 流入]
    ↓
SPLITTER (Varint21FrameDecoder)
    把变长 VarInt 长度前缀的"包"切出来
    ↓
DECOMPRESS (CompressionDecoder)
    如果启用了压缩：检查 packet length，> threshold 则 zlib 解压
    ↓
DECRYPT (CipherDecoder)
    如果启用了加密：AES-CFB8 解密
    ↓
DECODER (PacketDecoder)
    读 packet id (VarInt) + 用 StreamCodec 反序列化包内容 → Packet 对象
    ↓
UNBUNDLER (PacketBundleUnpacker)
    如果是 BundlePacket：拆开成多个独立 Packet 顺序派发
    ↓
PACKET_HANDLER (Connection)
    把 Packet 派发给当前的 PacketListener (ServerGamePacketListener / ClientPacketListener)
```

---

## 7.1.4 完整 outbound pipeline（发送端）

镜像：

```
[Packet 对象]
    ↓
BUNDLER (PacketBundlePacker)
    如果是 BundleDelimiterPacket：把后续包打包成一个 BundlePacket
    ↓
ENCODER (PacketEncoder)
    写 packet id (VarInt) + StreamCodec 序列化包内容 → bytes
    ↓
ENCRYPT (CipherEncoder)
    加密
    ↓
COMPRESS (CompressionEncoder)
    如果总长 > threshold 则压缩
    ↓
PREPENDER (Varint21LengthFieldPrepender)
    在前面加 VarInt 长度前缀
    ↓
[TCP socket bytes 流出]
```

## 7.1.5 SPLITTER：变长长度分帧

打开 `net.minecraft.network.Varint21FrameDecoder`：

```java
public class Varint21FrameDecoder extends ByteToMessageDecoder {
    private static final int MAX_VARINT21_BYTES = 3;
    private final ByteBuf helperBuf = Unpooled.directBuffer(3);
    @Nullable
    private final BandwidthDebugMonitor monitor;
    
    @Override
    protected void decode(ChannelHandlerContext ctx, ByteBuf in, List<Object> out) {
        in.markReaderIndex();
        this.helperBuf.clear();
        if (!copyVarint(in, this.helperBuf)) {
            in.resetReaderIndex();     // 不够 → 等更多字节
            return;
        }
        int packetLen = VarInt.read(this.helperBuf);
        if (in.readableBytes() < packetLen) {
            in.resetReaderIndex();     // 包体不全 → 等
            return;
        }
        if (this.monitor != null) this.monitor.onReceive(packetLen + this.helperBuf.readerIndex());
        out.add(in.readBytes(packetLen));     // 切出一个完整 packet
    }
    
    private static boolean copyVarint(ByteBuf in, ByteBuf out) {
        for (int i = 0; i < 3; i++) {
            if (!in.isReadable()) return false;
            byte b = in.readByte();
            out.writeByte(b);
            if ((b & 0x80) == 0) return true;     // 没设最高位 → VarInt 结束
        }
        throw new CorruptedFrameException("VarInt too big");
    }
}
```

**核心**：

1. 读最多 3 字节 VarInt = 包长度（含包内容，不含长度前缀本身）。
2. 等待 `readableBytes >= packetLen` ——包体到齐再切。
3. 切出 packetLen 字节 → 作为 ByteBuf 传给下游。

**VarInt** 是 protobuf 标准变长编码 —— 7 bit 数据 + 1 bit 续位。1-3 字节表达 0..(2^21-1) ≈ 2M。

`MAX_VARINT21_BYTES = 3` —— Mojang 限制单包最大 ~2M（防止 DoS）。

## 7.1.6 PREPENDER：写长度前缀

```java
public class Varint21LengthFieldPrepender extends MessageToByteEncoder<ByteBuf> {
    @Override
    protected void encode(ChannelHandlerContext ctx, ByteBuf in, ByteBuf out) {
        int len = in.readableBytes();
        if (VarInt.getByteSize(len) > 3) {
            throw new IllegalArgumentException("too long");
        }
        VarInt.write(out, len);
        out.writeBytes(in);
    }
}
```

**简单**：在包内容前加 VarInt 长度。

## 7.1.7 DECODER：包反序列化

打开 `net.minecraft.network.PacketDecoder`：

```java
public class PacketDecoder<T extends PacketListener> extends ByteToMessageDecoder implements ProtocolSwapHandler {
    private final ProtocolInfo<T> protocolInfo;
    
    @Override
    protected void decode(ChannelHandlerContext ctx, ByteBuf in, List<Object> out) {
        if (!in.isReadable()) return;
        try {
            int packetId = VarInt.read(in);
            // 用 ProtocolInfo 找到对应的 StreamCodec
            Packet<? super T> packet = this.protocolInfo.codec().decode(in);
            // ⋯ 校验 packetId 与 packet.type 匹配 ⋯
            out.add(packet);
        } catch (Exception e) {
            throw new SkipPacketException(e);
        }
    }
}
```

**核心步骤**：

1. 读 packet id (VarInt)。
2. 用 `ProtocolInfo.codec()` 找对应 packet 类型的 StreamCodec。
3. StreamCodec.decode(buf) → Packet 对象。
4. 把 Packet 添加到下游。

**`ProtocolInfo`** 是当前协议状态（HANDSHAKE / LOGIN / CONFIGURATION / PLAY 之一）的 PacketType 注册表。详见 7.2 节。

## 7.1.10 send 与 sendPacket 流程

```java
public void send(Packet<?> packet, @Nullable PacketSendListener listener) {
    if (this.isConnected()) {
        this.flushQueue();
        this.sendPacket(packet, listener, true);
    } else {
        this.pendingActions.add(c -> c.sendPacket(packet, listener, true));
    }
}

private void sendPacket(Packet<?> packet, @Nullable PacketSendListener listener, boolean flush) {
    this.sentPackets++;
    if (this.channel.eventLoop().inEventLoop()) {
        this.doSendPacket(packet, listener, flush);
    } else {
        this.channel.eventLoop().execute(() -> this.doSendPacket(packet, listener, flush));
    }
}

private void doSendPacket(Packet<?> packet, @Nullable PacketSendListener listener, boolean flush) {
    ChannelFuture channelFuture = flush ? this.channel.writeAndFlush(packet) : this.channel.write(packet);
    if (listener != null) {
        channelFuture.addListener(future -> {
            if (future.isSuccess()) listener.onSuccess();
            else { Packet<?> retry = listener.onFailure(); if (retry != null) sendPacket(retry, null, true); }
        });
    }
    channelFuture.addListener(ChannelFutureListener.FIRE_EXCEPTION_ON_FAILURE);
}
```

**关键点**：

1. **跨线程调度**：服务端 tick 线程调 send → 实际发送在 Netty event loop 线程。
2. **PacketSendListener** 回调：可监听发送成功 / 失败 + 失败重试。
3. **`writeAndFlush` vs `write`**：flush 立刻写到 socket、write 进 Netty 缓冲。

## 7.1.11 channelRead0：包接收入口

```java
@Override
protected void channelRead0(ChannelHandlerContext ctx, Packet<?> packet) {
    if (this.channel.isOpen()) {
        PacketListener listener = this.packetListener;
        if (listener == null) throw new IllegalStateException("No packet listener");
        if (listener.shouldHandleMessage(packet)) {
            try {
                genericsFtw(packet, listener);
            } catch (RunningOnDifferentThreadException ignored) {
                // 期待的：listener 决定推迟到下一 tick 处理
            } catch (Exception exception) {
                // 处理失败 → 断开连接
            }
            this.receivedPackets++;
        }
    }
}

private static <T extends PacketListener> void genericsFtw(Packet<T> packet, PacketListener listener) {
    packet.handle((T)listener);
}
```

**核心**：

1. 取当前 packetListener。
2. 调 `packet.handle(listener)` —— 让 packet 自己派发到 listener 的对应方法（双分派）。

**`packet.handle(listener)`** 是每个 Packet 类的核心方法：

```java
// 例：ServerboundMovePlayerPacket
@Override
public void handle(ServerGamePacketListener listener) {
    listener.handleMovePlayer(this);
}
```

每个具体 Packet 知道"调 listener 的哪个方法"。

## 7.1.12 RunningOnDifferentThreadException：跨线程协议

```java
public class RunningOnDifferentThreadException extends RuntimeException {
    public static final RunningOnDifferentThreadException RUNNING_ON_DIFFERENT_THREAD = new RunningOnDifferentThreadException();
}
```

**用法**：listener 收到 packet 但**当前在 Netty event loop 线程**，需要推迟到 server tick 线程处理：

```java
// ServerGamePacketListener.handleMovePlayer
@Override
public void handleMovePlayer(ServerboundMovePlayerPacket packet) {
    PacketUtils.ensureRunningOnSameThread(packet, this, this.player.serverLevel());
    // ⋯
}

// PacketUtils.ensureRunningOnSameThread
public static void ensureRunningOnSameThread(Packet<?> packet, PacketListener listener, ServerLevel level) {
    if (!level.getServer().isSameThread()) {
        level.getServer().tell(new TickTask(level.getServer().getTickCount(), () -> {
            // 重新调用 listener.handleX(packet)
            packet.handle((ServerGamePacketListener) listener);
        }));
        throw RunningOnDifferentThreadException.RUNNING_ON_DIFFERENT_THREAD;
    }
}
```

**模式**：

1. Netty 线程收到 packet → 调 listener.handleMovePlayer。
2. ensureRunningOnSameThread 检测到不在 server 主线程。
3. 把"重新调用 handleMovePlayer"的 task 投递到 server 主线程队列。
4. 抛 `RUNNING_ON_DIFFERENT_THREAD` —— Connection 的 `channelRead0` catch 这个异常并 ignore。
5. 下一次 server tick 处理 task → 此时在 server 主线程 → ensureRunningOnSameThread 通过 → 真正处理 packet。

**为什么这么做**：服务端权威世界状态由主线程独占——所有 packet 处理必须在主线程，避免线程竞争。

## 7.1.13 单机 LocalChannel

单机模式不走 socket，用 Netty 的 LocalChannel：

```java
// 服务端 IntegratedServer 启动
EventLoopGroup eventLoopGroup = LOCAL_WORKER_GROUP.get();
ServerBootstrap server = new ServerBootstrap();
server.channel(LocalServerChannel.class)
      .childHandler(new ChannelInitializer<Channel>() {
          protected void initChannel(Channel channel) {
              Connection connection = new Connection(PacketFlow.SERVERBOUND);
              channel.pipeline()
                  .addLast("splitter", new LocalFrameDecoder())     // 内存通道用 LocalFrameDecoder（无需 VarInt）
                  .addLast("decoder", new PacketDecoder<>(...))
                  .addLast("prepender", new LocalFrameEncoder())
                  .addLast("encoder", new PacketEncoder<>(...))
                  .addLast("packet_handler", connection);
          }
      })
      .group(eventLoopGroup)
      .localAddress(LocalAddress.ANY)
      .bind().syncUninterruptibly().channel();

// 客户端 LocalChannel.connect
```

**LocalFrameDecoder / LocalFrameEncoder**：因为内存通道**没有 TCP 流分片**问题——直接传整个 ByteBuf，不需要 VarInt 长度前缀。

**优点**：

- 同进程通信走 Netty 内存通道，零序列化（实际仍序列化 / 反序列化但走的是 ByteBuf in-memory，不走 socket）。
- 协议层完全一致——单机和联机的 packet 处理路径同。

## 7.1.14 EventLoopGroup 选择

Mojang 用 3 种 EventLoopGroup：

```java
public static final Supplier<NioEventLoopGroup> NETWORK_WORKER_GROUP = ...;          // Java NIO（跨平台）
public static final Supplier<EpollEventLoopGroup> NETWORK_EPOLL_WORKER_GROUP = ...;  // Linux epoll（性能更好）
public static final Supplier<DefaultEventLoopGroup> LOCAL_WORKER_GROUP = ...;        // 内存通道
```

**Linux 服务端**优先 `EpollEventLoopGroup`：epoll 比 NIO 快约 30%。**Windows / Mac** 用 NIO。

**默认线程数**：Math.max(1, available cpu cores - 1)。Mojang 服务端默认 1-3 个 IO 线程足以处理 100+ 玩家。

## 7.1.16 一段实战：玩家移动包的完整流程

```
[客户端 Render Thread]
玩家按 W → LocalPlayer.tick → updatePlayerActions
  ServerboundMovePlayerPacket pkt = new ServerboundMovePlayerPacket(x, y, z, ...);
  connection.send(pkt);
    → connection.sendPacket(pkt, null, true)
    → channel.eventLoop().execute(() -> doSendPacket(pkt, ...))

[Client Netty event loop]
channel.writeAndFlush(pkt) → 走 outbound pipeline:
  BUNDLER: noop（非 BundlePacket）
  ENCODER: PacketEncoder.encode → 写 VarInt id + StreamCodec 序列化 → ByteBuf
  ENCRYPT: AES-CFB8 加密（如果握手已加密）
  COMPRESS: > 256 字节才压缩（不压）
  PREPENDER: 加 VarInt 长度前缀
  → TCP socket 写出

[Network 网络传输 ~50 ms]

[Server Netty event loop]
TCP 收到 bytes → 走 inbound pipeline:
  SPLITTER: Varint21FrameDecoder 切出完整 packet
  DECOMPRESS: 检查长度，未压缩 → 跳过
  DECRYPT: AES-CFB8 解密 → 原始 ByteBuf
  DECODER: PacketDecoder → 读 VarInt id → StreamCodec 反序列化 → ServerboundMovePlayerPacket pkt
  UNBUNDLER: noop
  PACKET_HANDLER (Connection): channelRead0(ctx, pkt)
    → packet.handle((ServerGamePacketListener) listener)
    → listener.handleMovePlayer(pkt)
      → PacketUtils.ensureRunningOnSameThread → 投递到 server 主线程 → 抛 RUNNING_ON_DIFFERENT_THREAD
      → channelRead0 catch ignore

[Server 主线程，下一 tick]
TickTask 执行 → packet.handle(listener) 重新调
  → ServerGamePacketListener.handleMovePlayer 实际处理
    → 更新 ServerPlayer 位置
    → 检查合法性（速度 / 穿墙 / cheat 检测）
    → broadcast 给周围玩家 ClientboundMoveEntityPacket
```

**总耗时**：客户端 send 到服务端处理约 50-100 ms（含网络）。

## 7.1.17 性能特征

```
单包处理:
- Outbound pipeline: ~5-20 微秒
- Network: 取决于网络条件
- Inbound pipeline: ~5-20 微秒
- Listener handle: ~100 微秒（含 server logic）

100 玩家服务端，每玩家每秒 ~100 包：
- 总包处理：100 × 100 = 10000 包/秒
- IO 线程占用：~10-30%（单核）

视距 32 的服务端，初始加载 chunk 时短暂 burst：
- 初始 chunk 包：单包 50 KB × ~1000 chunk = 50 MB / 玩家
- 持续 ~10-30 秒
```

**带宽**：vanilla 服务端**chunk 包是带宽大头**（占 ~80%）。优化重点是 chunk 压缩 + diff 同步。

## 7.1.18 C++ 移植：Netty 替代

```cpp
// 选择网络库
namespace mc::network {

// 选项 1：boost::asio（异步 IO，类似 Netty）

    boost::asio::strand<boost::asio::io_context::executor_type> strand_;
    std::deque<Packet> outQueue_;
    
    void doRead() {
        boost::asio::async_read(socket_, ..., 
            boost::asio::bind_executor(strand_, [this](...) { 
                // 解析 packet → 派发 
            }));
    }
};

// 选项 2：enet（UDP-based 可靠层，简单）
class EnetConnection {
    ENetPeer* peer_;
    void send(const Packet& pkt) {
        std::vector<uint8_t> bytes = serialize(pkt);
        ENetPacket* enetPkt = enet_packet_create(bytes.data(), bytes.size(), ENET_PACKET_FLAG_RELIABLE);
        enet_peer_send(peer_, 0, enetPkt);
    }
};

// 选项 3：手写 epoll/IOCP（不推荐）
class HandRolledConnection { ... };
```

**推荐**：

- **小项目** / **单机为主**：用 `boost::asio`，跨平台 + 文档丰富。
- **协议兼容 vanilla**：用 `boost::asio` + 手写 packet 编解码。
- **新协议 + 高性能**：考虑 `quic`（基于 UDP 的现代协议，自带加密 + 多路复用）。

## 7.1.19 一句话总结

Mojang 用 **Netty** 作为网络层——每玩家一个 Connection 实例 + Netty Channel + handler pipeline；inbound 8 层 handler（SPLITTER 分帧 → DECOMPRESS → DECRYPT → DECODER → UNBUNDLER → PACKET_HANDLER），outbound 镜像；`Varint21FrameDecoder` 用 1-3 字节 VarInt 长度前缀分帧；`PacketDecoder` 读 packet id + StreamCodec 反序列化为 Packet 对象 → `Connection.channelRead0` 调 `packet.handle(listener)` 双分派；网络线程收到 packet → 通过 `ensureRunningOnSameThread` 投递到 server 主线程处理；单机用 LocalChannel + LocalFrameDecoder（无 VarInt）走同样 pipeline；Linux 服务端优先 epoll，Windows / Mac 用 NIO；C++ 移植可选 boost::asio / enet / quic。
