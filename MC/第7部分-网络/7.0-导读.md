# 第 7 部分 · 网络协议 —— 导读

## 你为什么需要先读这一部分

前面 6 个部分讲清楚了 Minecraft 服务端怎么管理世界状态。但**所有这些状态最终要送达玩家屏幕**——通过网络。

第 7 部分讲清楚 Minecraft 的网络协议层：

1. Netty pipeline 怎么把 TCP 字节流变成结构化的 Packet。
2. 5 阶段连接状态机（HANDSHAKE → STATUS / LOGIN → CONFIGURATION → PLAY）。
3. StreamCodec / FriendlyByteBuf 系统。
4. 阈值压缩（256 字节以上启用 zlib）+ AES-CFB8 加密。
5. 关键包族——玩家移动 / chunk 同步 / 方块更新 / 实体增量。
6. Bundle Packet（1.20+）：把多个独立包打包让客户端在同一帧应用。
7. 客户端预测 + 服务端权威 + sequence ack 机制。
8. ChunkMap 怎么决定"哪个 chunk 发给哪个玩家"。
9. C++ 移植：用 enet / asio / 自己 hand-roll 的取舍。

## 你的目标

读完这一部分你应当能：

1. 拿一段 wireshark 捕获的 Minecraft 包，能逐字节解析它。
2. 知道任何状态变化（玩家移动、方块更新、实体死亡）通过哪个包传输。
3. 理解客户端为什么能"流畅"显示位置——partialTick 插值 + 客户端预测。
4. 看懂 ChunkMap.update 决定"半径多少 chunk 发给玩家"。
5. 拿到 C++ 移植蓝图，知道用什么库、怎么实现协议兼容。

## 一句话预告

第 7 部分讲清楚 Minecraft 网络协议的全栈——Netty pipeline 把 TCP 流分帧（Varint21LengthFieldPrepender）→ 解压（CompressionDecoder，阈值 256）→ 解密（CipherDecoder, AES-CFB8）→ 反序列化（PacketDecoder + StreamCodec）→ 派发到 PacketListener；连接走 5 阶段状态机（1.20.2+ 新增 CONFIGURATION 阶段同步 registry / tags）；FriendlyByteBuf 提供 VarInt / String / BlockPos / NBT 等基本类型读写；Bundle Packet 让多个独立包在客户端同帧应用避免 desync；ChunkMap 按视距 / 模拟距离决定 chunk 发给谁，每个 ChunkHolder 维护"已发玩家集合"；客户端预测自己玩家行为 + 服务端 ack 包确认 / 回滚；C++ 移植用 enet 简单、asio 灵活、quic 现代——按规模选。
