## 7.2.1 ConnectionProtocol 5 阶段

打开 `net.minecraft.network.ConnectionProtocol`：

```java
public enum ConnectionProtocol {
    HANDSHAKING("handshake"),
    PLAY("play"),
    STATUS("status"),
    LOGIN("login"),
    CONFIGURATION("configuration");
}
```

**5 个状态**：

```
                                 HANDSHAKING
                                       │
                                  (intention)
                                       │
                       ┌───────────────┼─────────────────┐
                       ↓               ↓                 ↓
                   STATUS            LOGIN            TRANSFER
              (服务器列表 ping)    (登录鉴权)       (服务器迁移)
                       │               │                 │
                       └─────────────  │  ─── close ─────┘
                                       ↓
                                 CONFIGURATION
                              (registry / tag 同步)
                                       │
                                  finishConfiguration
                                       │
                                       ↓
                                     PLAY
                              (实际游戏)
```

**5 阶段**：

- **HANDSHAKING**：客户端连进来，发一个 ClientIntentionPacket 表明意图。
- **STATUS**：服务器列表 "ping" 阶段——客户端只是想查服务器在线 / 玩家数 / MOTD。
- **LOGIN**：玩家登录，包括用户名、加密握手、鉴权。1.20.5+ 加 cookie 机制。
- **CONFIGURATION**：1.20.2 引入。同步 datapack 注册表 / tags / 资源包。
- **PLAY**：实际游戏。所有 chunk / 实体 / 玩家行为包都在这里。

## 7.2.2 HANDSHAKING

唯一的 packet：`ClientIntentionPacket`：

```java
public record ClientIntentionPacket(int protocolVersion, String hostName, int port, ClientIntent intention) 
    implements Packet<ServerHandshakePacketListener> {
    
    @Override
    public boolean isTerminal() { return true; }     // ★ 处理后立即切换 protocol
}

public enum ClientIntent {
    STATUS,        // id=1 → 服务器列表 ping
    LOGIN,         // id=2 → 实际登录
    TRANSFER;      // id=3 → 服务器迁移
}
```

**字段**：

- `protocolVersion`：客户端协议版本（1.21.4 = 769 等）。让服务端检查兼容性。
- `hostName / port`：客户端想连的目标（用于 DNS 反向 + 多服 forwarding）。
- `intention`：3 种意图（STATUS / LOGIN / TRANSFER）。

**`isTerminal = true`** 表示 packet 处理后**立即切换协议**——`ServerHandshakePacketListener.handleIntention` 内：

```java
@Override
public void handleIntention(ClientIntentionPacket packet) {
    switch (packet.intention()) {
        case LOGIN, TRANSFER -> this.beginLogin(packet, packet.intention() == ClientIntent.TRANSFER);
        case STATUS -> {
            ServerStatusPacketListenerImpl listener = new ServerStatusPacketListenerImpl(...);
            this.connection.setupInboundProtocol(StatusProtocols.SERVERBOUND, listener);
        }
    }
}
```

**setupInboundProtocol** 切换 PacketDecoder 的 ProtocolInfo——之后用 STATUS / LOGIN 的包定义。

## 7.2.3 STATUS：服务器列表 ping

`ServerListPing` 流程：

```
Client → Server: ServerboundStatusRequestPacket    (空包，"给我状态")
Server → Client: ClientboundStatusResponsePacket   (JSON: motd, players, version)

Client → Server: ServerboundPingRequestPacket(pingTimestamp)
Server → Client: ClientboundPongResponsePacket(echoBack)

→ 客户端关闭连接
```

`ClientboundStatusResponsePacket` 内容（JSON 字符串）：

```json
{
    "version": { "name": "1.21.4", "protocol": 769 },
    "players": { "max": 20, "online": 5, "sample": [{"name":"Steve","id":"..."}] },
    "description": { "text": "A Minecraft Server" },
    "favicon": "data:image/png;base64,..."
}
```

**这是玩家在客户端"添加服务器"看到的列表数据**。

**STATUS 阶段不持久**——查完即关闭连接。下次连接重新走 HANDSHAKING。

## 7.2.4 LOGIN：登录与加密握手

完整流程：

```
Client → Server: ServerboundHelloPacket(username, profileId)
                     "我是 Steve"
Server → Client: ClientboundHelloPacket(serverId, publicKey, verifyToken, shouldAuthenticate)
                     "这是我的 RSA public key + 16 字节随机 verifyToken"
                     
[Client 生成 16 字节 AES 共享密钥 sharedSecret]
[Client 用 RSA public key 加密 sharedSecret 和 verifyToken]
                     
Client → Server: ServerboundKeyPacket(encSharedSecret, encVerifyToken)
Server: 用私钥解出 sharedSecret + verifyToken
        校验 verifyToken 与原值一致
        
[此时双方都有 sharedSecret，启用 AES-CFB8 加密]
        
Server: 联 Mojang auth server 验证玩家身份（在线模式）
                     
Server → Client: ClientboundLoginCompressionPacket(threshold=256)
                     "之后 > 256 字节包要压缩"
Server → Client: ClientboundGameProfilePacket(uuid, username, properties)
                     "登录成功，profile data"
                     
[此后切换到 CONFIGURATION 阶段]
```

**关键**：

1. **加密**：AES-CFB8 共享密钥协商。Mojang 用 RSA 1024-bit 公钥（弱但够用——只为防中间人篡改 sharedSecret）。
2. **在线模式鉴权**：服务端用 sharedSecret + serverId hash 联 Mojang `sessionserver.mojang.com` 验证玩家身份——防止盗号 / 假身份。
3. **离线模式**：服务端跳过 Mojang auth → 任何人能用任何用户名登录。**仅 LAN 局域网用**。

**Compression 阈值**：在 LOGIN 末尾启用——之后 PLAY 阶段所有包遵守 256 字节阈值。

详见 7.4 节。

## 7.2.5 CONFIGURATION：1.20.2 新增

1.20.2 之前所有"客户端启动期"工作（registry 同步、resource pack 加载）混在 LOGIN 末尾或 PLAY 早期。1.20.2 拆出 CONFIGURATION 阶段。

**目的**：

1. 玩家启动游戏时一次性同步 datapack 内容。
2. 玩家切换世界 / 服务器时**不重新登录**——可在 PLAY 中调回 CONFIGURATION 重新同步 registry。

**完整流程**：

```
Server → Client: ClientboundCustomReportDetailsPacket（可选）
Server → Client: ClientboundServerLinksPacket（服务器链接）
Server → Client: ClientboundCustomPayloadPacket(brand, "vanilla")
                     "服务端品牌"
Server → Client: ClientboundUpdateEnabledFeaturesPacket(featureFlags)
                     "启用了哪些 feature flags"
Server → Client: ClientboundSelectKnownPacks(packs)
Client → Server: ServerboundSelectKnownPacks(packs)
                     "客户端确认已知的 datapack（同步 registry 时跳过它们）"
Server → Client: ClientboundRegistryDataPacket(registry, entries)  ×N
                     "biome/dimension/damage_type 等动态注册表内容"
Server → Client: ClientboundUpdateTagsPacket(tags)
                     "全部 tags"
Server → Client: ClientboundFinishConfigurationPacket
                     "我发完了，切到 PLAY"
Client → Server: ServerboundFinishConfigurationPacket
                     "我处理完了，准备 PLAY"
                     
[切换到 PLAY 阶段]
                     
Server → Client: ClientboundLoginPacket(playerId, hardcore, dimensions, ...)
                     "PLAY 阶段第一包：玩家初始化"
```

**关键**：

- registry 同步发送**全部** vanilla + 服务端 datapack 的内容（biome / dimension / damage_type 等）。客户端接收后填到自己的 RegistryAccess。
- tags 同步类似。
- 单机模式仍走完整 CONFIGURATION（虽然客户端 / 服务端在同一进程）—— 协议一致性。

**为什么把 CONFIGURATION 拆出来**？

- 玩家可在 PLAY 中执行 `/transfer` 命令切换服务器——目标服务器需要发新 registry，但**客户端不应重登录**。新设计让 PLAY 能临时切回 CONFIGURATION。
- 可执行的 `ClientboundConfigurationPacket` （把客户端从 PLAY 拉回 CONFIGURATION）。

## 7.2.7 PacketFlow：方向

```java
public enum PacketFlow {
    SERVERBOUND,    // 客户端 → 服务端
    CLIENTBOUND     // 服务端 → 客户端
}
```

**重要**：同一个**名字** + 同一个 ConnectionProtocol 在两个方向上是**不同的 packet 类型**：

```
PLAY 阶段：
- ServerboundChatPacket (客户端 → 服务端：发聊天消息)
- ClientboundSystemChatPacket (服务端 → 客户端：广播系统消息)

LOGIN 阶段：
- ServerboundHelloPacket (客户端 → 服务端：我是谁)
- ClientboundHelloPacket (服务端 → 客户端：这是 RSA key)
```

`Serverbound*` 类有 `handle(ServerXxxPacketListener)`，`Clientbound*` 类有 `handle(ClientXxxPacketListener)`。

## 7.2.8 PacketType + ProtocolInfo

`PacketType<P>` 是一个类型化的 packet 标识：

```java
public record PacketType<T extends Packet<?>>(PacketFlow flow, ResourceLocation id) {
    public static <T extends Packet<?>> PacketType<T> serverbound(ResourceLocation id) {
        return new PacketType<>(PacketFlow.SERVERBOUND, id);
    }
    public static <T extends Packet<?>> PacketType<T> clientbound(ResourceLocation id) {
        return new PacketType<>(PacketFlow.CLIENTBOUND, id);
    }
}

// 例：
public class HandshakePacketTypes {
    public static final PacketType<ClientIntentionPacket> CLIENT_INTENTION = ...;
}

public class GamePacketTypes {
    public static final PacketType<ServerboundMovePlayerPacket.Pos> MOVE_PLAYER_POS = ...;
    public static final PacketType<ClientboundBlockUpdatePacket> BLOCK_UPDATE = ...;
    // ⋯ 200+ 个
}
```

`ProtocolInfo<L>` 是某协议（HANDSHAKE / STATUS / LOGIN / CONFIGURATION / PLAY）+ 某方向（SERVERBOUND / CLIENTBOUND）的全部 PacketType 注册：

```java
public interface ProtocolInfo<T extends PacketListener> {
    ConnectionProtocol id();
    PacketFlow flow();
    StreamCodec<ByteBuf, Packet<? super T>> codec();
    List<PacketType<? extends Packet<? super T>>> listPackets();
    boolean isTerminal();
}
```

**5 个 protocol × 2 个 flow = 10 个 ProtocolInfo 实例**：

- `HandshakeProtocols.SERVERBOUND` (含 ClientIntentionPacket)
- `HandshakeProtocols.CLIENTBOUND` (空——服务端不发包给握手客户端)
- `StatusProtocols.SERVERBOUND` / `StatusProtocols.CLIENTBOUND`
- `LoginProtocols.SERVERBOUND` / `LoginProtocols.CLIENTBOUND`
- `ConfigurationProtocols.SERVERBOUND` / `ConfigurationProtocols.CLIENTBOUND`
- `GameProtocols.SERVERBOUND` / `GameProtocols.CLIENTBOUND`

## 7.2.9 PacketListener 子接口

```java
public interface PacketListener { ... }

public interface ServerboundPacketListener extends PacketListener { ... }
public interface ClientboundPacketListener extends PacketListener { ... }

public interface ServerHandshakePacketListener extends ServerboundPacketListener {
    void handleIntention(ClientIntentionPacket packet);
}

public interface ServerLoginPacketListener extends ServerboundPacketListener {
    void handleHello(ServerboundHelloPacket packet);
    void handleKey(ServerboundKeyPacket packet);
    // ⋯
}

public interface ClientLoginPacketListener extends ClientboundPacketListener {
    void handleHello(ClientboundHelloPacket packet);
    void handleGameProfile(ClientboundGameProfilePacket packet);
    void handleDisconnect(ClientboundDisconnectPacket packet);
    // ⋯
}

public interface ServerGamePacketListener extends ServerboundPacketListener {
    void handleMovePlayer(ServerboundMovePlayerPacket packet);
    void handleBlockEntityTagQuery(ServerboundBlockEntityTagQueryPacket packet);
    // ⋯ 100+ 方法
}

public interface ClientGamePacketListener extends ClientboundPacketListener {
    void handleAddEntity(ClientboundAddEntityPacket packet);
    void handleBlockUpdate(ClientboundBlockUpdatePacket packet);
    void handleLevelChunkWithLight(ClientboundLevelChunkWithLightPacket packet);
    // ⋯ 100+ 方法
}
```

每个协议 + 方向有专属 PacketListener 接口——含该协议所有 packet 的 handle 方法。

具体实现：

- 服务端：`ServerHandshakePacketListenerImpl` / `ServerLoginPacketListenerImpl` / `ServerCommonPacketListenerImpl`（CONFIGURATION + PLAY 共享基础） / `ServerGamePacketListenerImpl`。
- 客户端：`ClientHandshakePacketListenerImpl` / `ClientLoginPacketListenerImpl` / `ClientCommonPacketListenerImpl` / `ClientGamePacketListenerImpl`。

## 7.2.10 协议切换：setupInboundProtocol

```java
// Connection
public void setupInboundProtocol(ProtocolInfo<?> info, PacketListener listener) {
    // 找 PacketDecoder + UNBUNDLER handler
    // 替换它们的 protocolInfo
    this.channel.pipeline().get(PacketDecoder.class).setProtocolInfo(info);
    this.packetListener = listener;
}

public void setupOutboundProtocol(ProtocolInfo<?> info) {
    this.channel.pipeline().get(PacketEncoder.class).setProtocolInfo(info);
}
```

**协议切换发生在以下时机**：

1. HANDSHAKING → STATUS / LOGIN：客户端发完 ClientIntentionPacket，服务端处理后切。
2. LOGIN → CONFIGURATION：登录完成时。
3. CONFIGURATION → PLAY：客户端发 ServerboundFinishConfigurationPacket。
4. PLAY → CONFIGURATION：服务端发 ClientboundStartConfigurationPacket（罕见，用于 /transfer 等）。

## 7.2.11 isTerminal：包处理后强制切协议

```java
public interface Packet<L extends PacketListener> {
    PacketType<? extends Packet<L>> type();
    void handle(L listener);
    default boolean isTerminal() { return false; }
}
```

某些 packet 处理后**强制切换协议**：

- `ClientIntentionPacket`：HANDSHAKING → STATUS / LOGIN。
- `ServerboundFinishConfigurationPacket`：CONFIGURATION → PLAY。
- `ClientboundStartConfigurationPacket`：PLAY → CONFIGURATION。

**`isTerminal = true`** 的 packet 在 `Connection.channelRead0` 内被特殊处理：处理后立刻 `setupInboundProtocol(newInfo, newListener)`。

## 7.2.12 一个完整启动时序

```
[客户端启动游戏，连接服务器 mc.example.com:25565]

[Tick 0]
Client → Server: TCP 连接建立
Client → Server: ClientIntentionPacket(769, "mc.example.com", 25565, LOGIN)
  Server: ServerHandshakePacketListenerImpl.handleIntention
    if intent == LOGIN: 
      this.connection.setupInboundProtocol(LoginProtocols.SERVERBOUND, new ServerLoginPacketListenerImpl(...));

[Tick 1]
Client → Server: ServerboundHelloPacket("Steve", uuid)
  Server: 生成 RSA pub/priv + verifyToken
Server → Client: ClientboundHelloPacket(serverId, pubKey, verifyToken)
  Client: 生成 sharedSecret，用 pubKey 加密
Client → Server: ServerboundKeyPacket(encSecret, encToken)
  Server: 解密验证
  Server: setupInboundProtocol + setupOutboundProtocol (启用加密)
  Server: 联 Mojang auth
  ...
Server → Client: ClientboundLoginCompressionPacket(256)
  Server: setupCompression(256)
Server → Client: ClientboundGameProfilePacket(uuid, "Steve")
  Server: setupInboundProtocol(ConfigurationProtocols.SERVERBOUND, ServerConfigurationPacketListenerImpl)

[Tick 5]
Server → Client: ClientboundUpdateEnabledFeaturesPacket(...)
Server → Client: ClientboundSelectKnownPacks(...)
Client → Server: ServerboundSelectKnownPacks(known_packs)
Server → Client: ClientboundRegistryDataPacket × 30 (各 registry)
Server → Client: ClientboundUpdateTagsPacket(全部 tags)
Server → Client: ClientboundFinishConfigurationPacket
  Server: setupInboundProtocol(GameProtocols.SERVERBOUND, ServerGamePacketListenerImpl)
Client → Server: ServerboundFinishConfigurationPacket
  Client: setupInboundProtocol(GameProtocols.CLIENTBOUND, ClientGamePacketListenerImpl)
  
[Tick 10]
Server → Client: ClientboundLoginPacket(playerId, dimensions, ...)
  → Player spawned at (0, 64, 0)
Server → Client: ClientboundLevelChunkWithLightPacket × N (附近 chunks)
Server → Client: ClientboundSetDefaultSpawnPositionPacket(spawnPos)
...
Server → Client: ClientboundPlayerPositionPacket(0, 64, 0, ...)
  Client: 玩家可见、可控
  
[玩家在游戏内]
Server ↔ Client: PLAY 阶段大量 packet
```

**总耗时**：从连接到玩家可见 ~1-3 秒（含网络 + 服务端 chunk 加载）。

## 7.2.13 性能 / 资源

```
HANDSHAKING：~1-2 packet，瞬时
STATUS：~4 packet，<10ms
LOGIN：~10 packet（含 RSA + Mojang auth），~500ms
CONFIGURATION：~50-100 packet（registry 数据），~500ms-2s
PLAY 启动 burst：~200 packet（chunk 数据），~10s
PLAY 稳态：~50 packet/s/玩家
```

**LOGIN 的 RSA + Mojang auth 是最慢环节**。优化：

- 离线模式跳过 Mojang auth。
- "transfer" 模式从已认证服务器迁移玩家——跳过 auth。

## 7.2.14 C++ 移植

```cpp
namespace mc::network {

enum class ConnectionProtocol { HANDSHAKING, STATUS, LOGIN, CONFIGURATION, PLAY };
enum class PacketFlow { SERVERBOUND, CLIENTBOUND };

struct PacketType {
    PacketFlow flow;
    ResourceLocation id;
};

class PacketListener {
public:
    virtual ~PacketListener() = default;
    virtual ConnectionProtocol protocol() const = 0;
    virtual PacketFlow flow() const = 0;
};

class ServerHandshakePacketListener : public PacketListener {
public:
    virtual void handleIntention(const ClientIntentionPacket& packet) = 0;
    ConnectionProtocol protocol() const override { return ConnectionProtocol::HANDSHAKING; }
    PacketFlow flow() const override { return PacketFlow::SERVERBOUND; }
};

class ServerLoginPacketListener : public PacketListener {
public:
    virtual void handleHello(const ServerboundHelloPacket&) = 0;
    virtual void handleKey(const ServerboundKeyPacket&) = 0;
    // ⋯
};

// ⋯ 各协议 listener 接口

class ProtocolInfo {
public:
    virtual ConnectionProtocol id() const = 0;
    virtual PacketFlow flow() const = 0;
    virtual std::unique_ptr<Packet> decode(int packetId, ByteBuf& buf) = 0;
    virtual int encodePacketId(const Packet& packet) = 0;
};

class Connection {
public:
    void setupInboundProtocol(std::unique_ptr<ProtocolInfo> info, std::unique_ptr<PacketListener> listener);
    void setupOutboundProtocol(std::unique_ptr<ProtocolInfo> info);
    
private:
    std::unique_ptr<ProtocolInfo> inboundProtocol_;
    std::unique_ptr<ProtocolInfo> outboundProtocol_;
    std::unique_ptr<PacketListener> packetListener_;
};

}
```

## 7.2.15 一句话总结

Minecraft 协议有 5 个 ConnectionProtocol：HANDSHAKING（仅 ClientIntentionPacket）→ STATUS（服务器列表 ping）/ LOGIN（鉴权 + 加密握手）/ TRANSFER（服务器迁移）→ CONFIGURATION（1.20.2 引入，registry / tags 同步）→ PLAY（游戏中所有 200+ 种 packet）；同一个名字 + 同一个 protocol 在 SERVERBOUND / CLIENTBOUND 是不同 packet 类型；`PacketType<P> = (PacketFlow, ResourceLocation)`；`ProtocolInfo` 持有该协议 + 该方向的全部 PacketType + StreamCodec；`Packet.isTerminal = true` 让某些 packet 处理后强制切协议（ClientIntentionPacket / ServerboundFinishConfigurationPacket / ⋯）；玩家从启动到入游约 1-3 秒，LOGIN 的 RSA + Mojang auth 是最慢环节。
