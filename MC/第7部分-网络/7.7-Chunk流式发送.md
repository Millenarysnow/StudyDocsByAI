## 7.7.1 ChunkMap：服务端 chunk 管理中枢

`net.minecraft.server.level.ChunkMap` 是 ServerChunkCache 内部的核心：


**关键字段**：

- **`updatingChunkMap`**：当前所有 active chunk holders（按 ChunkPos.long key）。
- **`distanceManager`**：维护"哪些 chunk 在视距 / 模拟距离内"。
- **`viewDistance`**：服务端配置的最大视距。

## 7.7.2 视距 vs 模拟距离

`server.properties`：

```properties
view-distance=10                    # 玩家"能看到"的半径
simulation-distance=10              # chunk "在 ticking" 的半径
```

**两者区别**：

- **view-distance**：客户端能渲染到的 chunk 半径——chunk 数据已发给客户端但**可能不 tick**。
- **simulation-distance**：chunk 在服务端 ticking 主循环中——random tick / scheduled tick / 实体 tick 都跑。

**典型设置**：

- view = 10, simulation = 10：视距等于模拟距离（默认）。
- view = 32, simulation = 8：玩家看远但只近处 chunk 在 tick——优化大型服务器，远处 chunk"冻结"但可见。

**1.18 之前**：两者合一为单一 view-distance。1.18+ 拆开。

## 7.7.3 ChunkHolder 与 4 个 FullChunkStatus

```java
public class ChunkHolder extends GenerationChunkHolder {
    @Nullable private LevelChunk fullChunk;
    private FullChunkStatus oldTicketLevel = FullChunkStatus.INACCESSIBLE;
    private CompletableFuture<ChunkAccess> chunkToSave;
    private final List<ServerPlayer> playerProvider;
    private final BitSet blockChangedLightSectionFilter;
    private final BitSet skyChangedLightSectionFilter;
    private final LevelLightEngine lightEngine;
    
    // 等待发包队列
    private final ShortSet skyLightChangedFromIds = new ShortOpenHashSet();
    private final ShortSet blockLightChangedFromIds = new ShortOpenHashSet();
    private final List<List<ShortSet>> changedBlocksPerSection;
    private boolean hasChangedSections;
    
    // ⋯
}

public enum FullChunkStatus {
    INACCESSIBLE,         // chunk 仅生成但不可访问
    FULL,                 // chunk 加载到 LevelChunk 完成
    BLOCK_TICKING,        // chunk 在 simulation distance 内
    ENTITY_TICKING        // chunk 在更近一圈，实体也 tick
}
```

**4 个 FullChunkStatus 阶梯**：

```
INACCESSIBLE     ← 距玩家最远，chunk 已加载但不可见
   ↓
FULL             ← 客户端已收到，进入运行期
   ↓
BLOCK_TICKING    ← scheduled / random tick 跑
   ↓
ENTITY_TICKING   ← entity 也 tick
```

**对应距离**（玩家半径，单位 chunk）：

```
ENTITY_TICKING < BLOCK_TICKING ≤ simulation-distance < view-distance
```

## 7.7.4 DistanceManager：维护半径

```java
public class DistanceManager {
    private final TickingTracker tickingTracker;
    private final PlayerTicketTracker playerTicketManager;
    private final Map<ChunkPos, ObjectSet<ServerPlayer>> playersPerChunk;
    
    public boolean inEntityTickingRange(long chunkPos);
    public boolean inBlockTickingRange(long chunkPos);

    public boolean addPlayer(SectionPos pos, ServerPlayer player);
    public boolean removePlayer(SectionPos pos, ServerPlayer player);

```

**`PlayerTicketTracker`**：

- 玩家所在 chunk 周围一圈分配 "ticket"（一个标记）。
- ticket level 越低越靠近玩家——决定 chunk 的 FullChunkStatus。

**Ticket 类型**：

```java
public class TicketType<T> {
    public static final TicketType<Unit> START = create("start", ...);                  // 玩家 spawn 起点
    public static final TicketType<ChunkPos> PLAYER = create("player", ...);            // 玩家附近
    public static final TicketType<ChunkPos> FORCED = create("forced", ...);             // 强制加载（命令）
    public static final TicketType<ChunkPos> LIGHT = create("light", ...);               // 光照需要
    public static final TicketType<ChunkPos> PORTAL = create("portal", ...);             // 传送门
    public static final TicketType<Integer> POST_TELEPORT = create("post_teleport", ...);
    public static final TicketType<Long> UNKNOWN = create("unknown", ...);
    public static final TicketType<Unit> DELAYED = create("delayed", ...);
}
```

每个 chunk 维护一个"最高优先级 ticket level"——决定其 FullChunkStatus。

## 7.7.5 玩家移动触发 chunk 加载

```java
// ServerPlayer.tick → ChunkMap.move
public void move(ServerPlayer player) {
    SectionPos oldPos = player.getLastSectionPos();
    SectionPos newPos = SectionPos.of(player);
    
    if (!oldPos.equals(newPos)) {
        // 玩家穿越了 section 边界
        this.distanceManager.removePlayer(oldPos, player);
        this.distanceManager.addPlayer(newPos, player);
        player.setLastSectionPos(newPos);
        
        // 通知 ChunkTrackingView 重新计算
        ChunkTrackingView.difference(oldView, newView, addCallback, removeCallback);
    }
}
```

**ChunkTrackingView.difference**：

- 计算从旧视距集合到新视距集合的差异：
  - **新增 chunk**：发 ClientboundLevelChunkWithLightPacket 给客户端。
  - **移除 chunk**：发 ClientboundForgetLevelChunkPacket。

**触发频率**：玩家穿越 section 边界（每 16 格）。**不是每 tick 触发**。

## 7.7.7 chunk 内方块更新的批处理

`ChunkHolder.changedBlocksPerSection`：

```java
private final List<List<ShortSet>> changedBlocksPerSection;
private boolean hasChangedSections;

public void blockChanged(BlockPos pos) {
    int sectionIdx = SectionPos.blockToSectionCoord(pos.getY()) - this.level.getMinSection();
    List<ShortSet> changed = this.changedBlocksPerSection.computeIfAbsent(sectionIdx, ...);
    changed.add(SectionPos.sectionRelativePos(pos));
    this.hasChangedSections = true;
}
```

**机制**：

- 每次 setBlock(UPDATE_CLIENTS) → ChunkHolder.blockChanged(pos)。
- 不立刻发包——把"哪格改了"加入 set。
- 每 tick 末尾 flush：

```java
// ChunkHolder.broadcastChanges (每 tick 调用)
public void broadcastChanges(LevelChunk chunk) {
    if (this.hasChangedSections) {
        for (each section with changes) {
            ShortSet changes = changedBlocksPerSection[section];
            if (changes.size() == 1) {
                // 单格改 → BlockUpdatePacket
                short pos = changes.iterator().next();
                broadcast(new ClientboundBlockUpdatePacket(...));
            } else {
                // 多格改 → SectionBlocksUpdatePacket
                broadcast(new ClientboundSectionBlocksUpdatePacket(...));
            }
        }
        clear changes.
    }
    
    if (lightChanged) {
        broadcast(new ClientboundLightUpdatePacket(...));
    }
}
```

**优化**：

- 单格改用单包 (~13 字节)。
- 多格改用段包 (~5 字节/格 + header)。
- 单 tick 内对同一格多次 setBlock → 仅发最终状态（去重）。

## 7.7.8 实体追踪：ChunkMap.entityTrackers

```java
public class ChunkMap {
    private final Int2ObjectMap<ChunkMap.TrackedEntity> entityMap = new Int2ObjectOpenHashMap<>();
    
    public class TrackedEntity {
        final ServerEntity serverEntity;
        final Entity entity;
        private final int range;
        SectionPos lastSectionPos;
        private final Set<ServerPlayerConnection> seenBy;
        
        public void updatePlayers(List<ServerPlayer> playersInRange) {
            for (ServerPlayer player : playersInRange) {
                if (this.entity != player) {
                    this.updatePlayer(player);
                }
            }
        }
        
        public void updatePlayer(ServerPlayer player) {
            if (player != this.entity) {
                Vec3 distance = player.position().subtract(this.entity.position());
                int rangeChunks = this.getEffectiveRange();
                double maxDist = Math.min(rangeChunks, ChunkMap.this.viewDistance - 1) * 16;
                double sqrDist = distance.x * distance.x + distance.z * distance.z;
                double sqrMaxDist = maxDist * maxDist;
                boolean shouldSee = sqrDist <= sqrMaxDist && this.entity.broadcastToPlayer(player);
                
                if (shouldSee) {
                    if (this.seenBy.add(player.connection)) {
                        // 第一次见 → 发 spawn packet
                        this.serverEntity.addPairing(player);
                    }
                } else if (this.seenBy.remove(player.connection)) {
                    // 不再见 → 发 remove packet
                    this.serverEntity.removePairing(player);
                }
            }
        }
    }
}
```

**关键**：

- 每个 entity 有 `TrackedEntity` 实例 + `seenBy` set。
- 玩家移动 / 实体移动时调 `updatePlayer` 决定是否 spawn / remove。
- 实体每 tick 推进 `serverEntity.sendChanges()` 发位置 / 数据更新（仅给 seenBy 玩家）。

**追踪范围（不同实体不同）**：

- 玩家：64 格。
- 普通生物：80 格 (5 chunk)。
- 物品 / 经验球：64 格。
- 闪电：512 格（远距离可见）。

## 7.7.9 玩家进维度

进维度时（首次登录或 `/execute in`）：

```java
ServerPlayer.changeDimension(...) {
    Connection.setupInboundProtocol(GameProtocols.SERVERBOUND, gameListener);
    // ⋯
    player.connection.send(new ClientboundRespawnPacket(commonPlayerSpawnInfo, ...));
    // 让客户端清空当前维度的所有 chunk + entity

}
```

**ClientboundRespawnPacket** 让客户端"忘记当前维度状态"——chunk / entity 全部清。然后从头加载新维度。

## 7.7.11 强制加载（forceloaded chunks）

`/forceload add <pos>` 命令——把 chunk 标记为"强制加载"：

```java
// DistanceManager
ticketManager.addTicket(TicketType.FORCED, chunkPos, FORCED_TICKET_LEVEL, chunkPos);
```

**FORCED_TICKET_LEVEL** 让 chunk 即使没玩家附近也保持 BLOCK_TICKING。

**用途**：

- 红石机器（玩家不在但要 tick）。
- 农场（玩家不在但作物要长——但 random tick 仅在 simulation distance，所以仍受限）。
- 命令方块时钟。

**持久化**：写入 `level.dat` 旁的 forceload list。

## 7.7.12 chunk 卸载

```java
// ChunkMap.tick
private void runDistanceManagerUpdates() {
    boolean changed = this.distanceManager.runAllUpdates(this);
    if (changed) {
        // 重新评估每 chunk 的 FullChunkStatus
        // 卸载不再有 ticket 的 chunk → 发 ClientboundForgetLevelChunkPacket
    }
}
```

**卸载流程**：

1. DistanceManager 发现 chunk 不再有 ticket（玩家走远了）。
2. ChunkHolder 标记为可卸载。
3. 等几 tick 缓冲（避免抖动反复卸载）。
4. 调 `IOWorker.store(pos, chunkData)` 持久化。
5. ChunkMap 移除 ChunkHolder。
6. 客户端持有的也通过 ClientboundForgetLevelChunkPacket 通知。

## 7.7.13 性能：chunk 发送 burst

玩家初次登录的 burst：

```
视距 32 chunk² = 32×32 = 1024 chunk
每 chunk 包 ~30 KB（压缩后）
总：30 MB 数据要发

50 Mbps 带宽：30 MB / 6.25 MB/s = 4.8 秒纯传输
加 RTT + ACK：~5-10 秒登录完成
```

**优化**：

- ChunkMap 限制每 tick 发包数量（避免一次性把 socket 打满）。
- 客户端"loading screen"持续到收到足够 chunks。
- 优先发玩家正前方的 chunk。

## 7.7.14 一段实战：玩家走过 chunk 边界

```
玩家在 (15, 64, 0)，正向东走

[Tick 0]
玩家位置 (15.5, 64, 0) → 在 chunk(0, 0) 内
ChunkMap 持有 chunk(-10..10, -10..10) 的 ChunkHolder

[Tick 5]
玩家走到 (16.5, 64, 0) → 进入 chunk(1, 0)
SectionPos.of(player) 改变
ChunkMap.move(player):
  distanceManager.removePlayer(oldSection, player);
  distanceManager.addPlayer(newSection, player);
  → 重新计算 ticket levels
  → 新 chunk(11, 0..10) 进入视距
  → 旧 chunk(-10..-9, 0..10) 退出视距

[Tick 6-10]
对每个新 chunk:
  ChunkPyramid.applyToFull → 加载 / 生成 → 升级到 LevelChunk
  ChunkMap.broadcast → ClientboundLevelChunkWithLightPacket → 客户端

对每个旧 chunk:
  ClientboundForgetLevelChunkPacket → 客户端清

[Tick 30]
所有变化处理完
玩家继续往东，重复
```

**实际上视距 32 时，每秒通常 0-2 chunk 边界穿越**——chunk 加载 / 卸载相对低频。

## 7.7.15 C++ 移植

```cpp
namespace mc::server {

class ChunkHolder {
public:
    enum class FullChunkStatus { INACCESSIBLE, FULL, BLOCK_TICKING, ENTITY_TICKING };
    
    void blockChanged(BlockPos pos) {
        int sectionIdx = sectionToSectionIdx(pos.y);
        if (changedBlocksPerSection_[sectionIdx].size() < 64) {
            changedBlocksPerSection_[sectionIdx].insert(SectionPos::sectionRelativePos(pos));
        } else {
            // 段内变化太多 → 发整 section 重发包
            sectionDirty_[sectionIdx] = true;
        }
        hasChangedSections_ = true;
    }
    
    void broadcastChanges() {
        if (!hasChangedSections_) return;
        
        for (int sIdx = 0; sIdx < 24; sIdx++) {
            auto& changes = changedBlocksPerSection_[sIdx];
            if (changes.size() == 1) {
                BlockPos pos = ...;
                broadcast(ClientboundBlockUpdatePacket{pos, getBlockState(pos)});
            } else if (changes.size() > 1) {
                broadcast(ClientboundSectionBlocksUpdatePacket{...});
            }
            changes.clear();
        }
        hasChangedSections_ = false;
    }

private:
    std::array<std::unordered_set<int16_t>, 24> changedBlocksPerSection_;
    std::array<bool, 24> sectionDirty_;
    bool hasChangedSections_ = false;
    LevelChunk* fullChunk_;
};

class ChunkMap {
public:
    void addPlayer(ServerPlayer* player);
    void removePlayer(ServerPlayer* player);
    
    void tick() {
        runDistanceManagerUpdates();
        for (auto& [pos, holder] : updatingChunks_) {
            holder.broadcastChanges();
        }
    }
    
    void onPlayerMoved(ServerPlayer* player, SectionPos oldPos, SectionPos newPos) {
        distanceManager_.removePlayer(oldPos, player);
        distanceManager_.addPlayer(newPos, player);
        // 计算 ChunkTrackingView 差异，发 chunk packet 或 forget packet
    }

private:
    int viewDistance_ = 10;
    int simulationDistance_ = 10;
    DistanceManager distanceManager_;
    std::unordered_map<int64_t, ChunkHolder> updatingChunks_;
    std::unordered_map<int, TrackedEntity> entityMap_;
};

}
```

## 7.7.16 一句话总结

`ChunkMap` 是服务端 chunk 管理中枢——通过 `DistanceManager` + ticket 系统决定每 chunk 的 `FullChunkStatus`（INACCESSIBLE / FULL / BLOCK_TICKING / ENTITY_TICKING 4 阶梯）；视距（view-distance，玩家可见）vs 模拟距离（simulation-distance，chunk 在 ticking）1.18+ 拆开；玩家移动穿越 section 边界触发 ChunkTrackingView.difference 计算"新增 / 移除 chunk"差异 → 发 ClientboundLevelChunkWithLightPacket / ForgetLevelChunkPacket；ChunkHolder 维护"per-section 变化方块集"批处理（单格用 BlockUpdatePacket / 多格用 SectionBlocksUpdatePacket）；`TrackedEntity` 系统每 entity 维护 seenBy 玩家集，按距离触发 spawn / remove；`/forceload` 命令通过 `TicketType.FORCED` 让 chunk 即使无玩家也保持 BLOCK_TICKING；初次登录 burst ~30 MB 数据需 5-10 秒传输。
