## 7.3.1 ByteBuf 与 FriendlyByteBuf

**Netty 的 ByteBuf** 是 byte buffer 的抽象——支持 zero-copy、引用计数、池化。Mojang 不直接用 ByteBuf，而是包装成 `FriendlyByteBuf`：

```java
public class FriendlyByteBuf extends ByteBuf {
    private final ByteBuf source;
    
    public FriendlyByteBuf(ByteBuf source) {
        this.source = source;
    }
    
    // 基础读写（继承）：byte / short / int / long / float / double / boolean
    
    // Mojang 扩展：
    public FriendlyByteBuf writeVarInt(int value);
    public int readVarInt();
    public FriendlyByteBuf writeVarLong(long value);
    public long readVarLong();
    
    public FriendlyByteBuf writeUtf(String s);
    public String readUtf(int maxLength);
    
    public FriendlyByteBuf writeBlockPos(BlockPos pos);
    public BlockPos readBlockPos();
    
    public FriendlyByteBuf writeUUID(UUID uuid);
    public UUID readUUID();
    
    public FriendlyByteBuf writeNbt(@Nullable Tag tag);
    public CompoundTag readNbt();
    
    public FriendlyByteBuf writeResourceLocation(ResourceLocation rl);
    public ResourceLocation readResourceLocation();
    
    public <T> FriendlyByteBuf writeCollection(Collection<T> col, BiConsumer<FriendlyByteBuf, T> writer);
    public <T> List<T> readList(Function<FriendlyByteBuf, T> reader);
    
    // ⋯ 几十个 helper 方法 ⋯
}
```

**FriendlyByteBuf 是 packet 序列化的核心工具**——封装 Minecraft 特定类型的读写。

**`RegistryFriendlyByteBuf`** 进一步加 `RegistryAccess` 引用：

```java
public class RegistryFriendlyByteBuf extends FriendlyByteBuf {
    private final RegistryAccess registryAccess;
    
    public RegistryAccess registryAccess() { return this.registryAccess; }
}
```

**用途**：序列化时需要 registry 上下文（如把 Holder<Biome> 写成 ResourceLocation）。

## 7.3.2 VarInt：变长整数

打开 `net.minecraft.network.VarInt`：

```java
public class VarInt {
    private static final int MAX_VARINT_SIZE = 5;
    private static final int DATA_BITS_MASK = 127;
    private static final int CONTINUATION_BIT_MASK = 128;
    private static final int DATA_BITS_PER_BYTE = 7;
    
    public static int getByteSize(int value) {
        for (int i = 1; i < 5; i++) {
            if ((value & -1 << i * 7) == 0) return i;
        }
        return 5;
    }
    
    public static int read(ByteBuf buf) {
        int result = 0;
        int shift = 0;
        byte b;
        do {
            b = buf.readByte();
            result |= (b & 127) << shift++ * 7;
            if (shift > 5) throw new RuntimeException("VarInt too big");
        } while ((b & 128) != 0);
        return result;
    }
    
    public static ByteBuf write(ByteBuf buf, int value) {
        while ((value & -128) != 0) {
            buf.writeByte(value & 127 | 128);
            value >>>= 7;
        }
        buf.writeByte(value);
        return buf;
    }
}
```

**编码规则**（与 protobuf VarInt 完全相同）：

- 每字节 7 bit 数据 + 1 bit 续位（最高位）。
- 最高位 = 1 表示后面还有字节、= 0 表示结束。
- 小端序（最低 7 bit 在第一字节）。

**字节数**：

- 0..127：1 字节。
- 128..16383：2 字节。
- 16384..2097151：3 字节。
- 2097152..268435455：4 字节。
- 268435456..2147483647：5 字节。

**`getByteSize`** 反向：给定值，返回需要几字节。

**为什么用 VarInt**：

- 大部分 packet id / 长度都很小（< 256）—— VarInt 1 字节 vs fixed int 4 字节，省 75%。
- 很少出现的大值才用多字节。
- **协议级压缩** —— 比 zlib 更高效（zlib 对小整数效果差）。

## 7.3.3 字符串

```java
public FriendlyByteBuf writeUtf(String s, int maxLength) {
    if (s.length() > maxLength) throw new EncoderException("String too long");
    byte[] bytes = s.getBytes(StandardCharsets.UTF_8);
    if (bytes.length > maxLength * 4) throw new EncoderException("UTF-8 byte length exceeds max");
    this.writeVarInt(bytes.length);
    this.writeBytes(bytes);
    return this;
}

public String readUtf(int maxLength) {
    int byteLen = this.readVarInt();
    if (byteLen > maxLength * 4) throw new DecoderException("String too long");
    byte[] bytes = new byte[byteLen];
    this.readBytes(bytes);
    String s = new String(bytes, StandardCharsets.UTF_8);
    if (s.length() > maxLength) throw new DecoderException("String too long");
    return s;
}
```

**字符串编码**：

```
[length: VarInt]   字节数（不是字符数）
[bytes: UTF-8]
```

**`maxLength` 上限**：防 DoS——别人发 1 GB 字符串。Mojang 默认每种字符串有合理上限（如玩家名 16、聊天 256、资源标识 32767）。

## 7.3.4 BlockPos / UUID / NBT

```java
public FriendlyByteBuf writeBlockPos(BlockPos pos) {
    this.writeLong(pos.asLong());     // 1.0.1 节看过的 long 编码
    return this;
}

public BlockPos readBlockPos() {
    return BlockPos.of(this.readLong());
}

public FriendlyByteBuf writeUUID(UUID uuid) {
    this.writeLong(uuid.getMostSignificantBits());
    this.writeLong(uuid.getLeastSignificantBits());
    return this;
}

public FriendlyByteBuf writeNbt(@Nullable Tag tag) {
    if (tag == null) {
        this.writeByte(0);     // TAG_END = 不存在
    } else {
        try {
            NbtIo.writeAnyTag(tag, new ByteBufOutputStream(this));
        } catch (IOException e) {
            throw new EncoderException(e);
        }
    }
    return this;
}
```

**BlockPos** = 8 字节 long（packed）。

**UUID** = 16 字节（2 long）。

**NBT** = NbtIo.writeAnyTag 输出（详见 2.1 节，含类型 + 数据）。

## 7.3.5 老式 Packet 类（手写 read/write）

1.20.4 之前 Packet 直接持有 read/write 方法：

```java
// 老式（1.20.4-）
public class ServerboundChatPacket implements Packet<ServerGamePacketListener> {
    private final String message;
    private final Instant timeStamp;
    private final long salt;
    
    public ServerboundChatPacket(String message, Instant timeStamp, long salt) { ... }
    
    public ServerboundChatPacket(FriendlyByteBuf buf) {
        this.message = buf.readUtf(256);
        this.timeStamp = Instant.ofEpochMilli(buf.readLong());
        this.salt = buf.readLong();
    }
    
    @Override
    public void write(FriendlyByteBuf buf) {
        buf.writeUtf(this.message, 256);
        buf.writeLong(this.timeStamp.toEpochMilli());
        buf.writeLong(this.salt);
    }
    
    @Override
    public void handle(ServerGamePacketListener listener) {
        listener.handleChat(this);
    }
}
```

**手动维护 read constructor + write 方法**。容易写错—— write 时漏字段、read 时类型错。

## 7.3.6 StreamCodec：1.20.5+ 新方式

1.20.5 引入 `StreamCodec<B, V>`：

```java
public interface StreamCodec<B extends ByteBuf, V> {
    V decode(B buf);
    void encode(B buf, V value);
    
    // 组合
    default <R> StreamCodec<B, R> map(Function<V, R> from, Function<R, V> to);
    
    // 元组组合
    static <B, V1, V2, V> StreamCodec<B, V> composite(
        StreamCodec<B, V1> codec1, Function<V, V1> getter1,
        StreamCodec<B, V2> codec2, Function<V, V2> getter2,
        BiFunction<V1, V2, V> factory
    );
}
```

**新式 Packet**：

```java
public record ServerboundChatPacket(String message, Instant timeStamp, long salt) implements Packet<ServerGamePacketListener> {
    public static final StreamCodec<FriendlyByteBuf, ServerboundChatPacket> STREAM_CODEC = Packet.codec(
        ServerboundChatPacket::write,
        ServerboundChatPacket::new
    );
    
    private ServerboundChatPacket(FriendlyByteBuf buf) {
        this(buf.readUtf(256), Instant.ofEpochMilli(buf.readLong()), buf.readLong());
    }
    
    private void write(FriendlyByteBuf buf) {
        buf.writeUtf(this.message);
        buf.writeLong(this.timeStamp.toEpochMilli());
        buf.writeLong(this.salt);
    }
    
    @Override
    public PacketType<ServerboundChatPacket> type() { return GamePacketTypes.CHAT; }
    
    @Override
    public void handle(ServerGamePacketListener listener) { listener.handleChat(this); }
}
```

**`Packet.codec(writer, reader)`**：

```java
public interface Packet<L extends PacketListener> {
    static <B extends ByteBuf, T extends Packet<?>> StreamCodec<B, T> codec(
        BiConsumer<T, B> writer,
        Function<B, T> reader
    ) {
        return StreamCodec.of((buf, value) -> writer.accept(value, buf), reader);
    }
}
```

**实际仍然手写 read/write**——但用 record + StreamCodec.of 封装。**优势**：

1. record 自动生成 equals/hashCode/toString。
2. StreamCodec 可被 codec 工具重用（如压缩、过滤）。
3. 可与 `Codec<T>`（DataFixerUpper）配套。

## 7.3.7 ByteBufCodecs：基础 codec 库

```java
public class ByteBufCodecs {

    public static final StreamCodec<ByteBuf, Long> VAR_LONG = ...;

    public static final StreamCodec<ByteBuf, Double> DOUBLE = ...;
    public static final StreamCodec<ByteBuf, byte[]> BYTE_ARRAY = ...;
    public static final StreamCodec<ByteBuf, String> STRING_UTF8 = stringUtf8(32767);
    
    public static StreamCodec<ByteBuf, String> stringUtf8(int maxLength) { ... }
    public static <B extends ByteBuf, V> StreamCodec<B, List<V>> collection(IntFunction<List<V>> factory, StreamCodec<B, V> elementCodec) { ... }
    public static <B extends ByteBuf, K, V> StreamCodec<B, Map<K, V>> map(...) { ... }
    public static <B extends ByteBuf, V> StreamCodec<B, Optional<V>> optional(StreamCodec<B, V> codec) { ... }
    
    public static <T extends Enum<T>> StreamCodec<ByteBuf, T> idMapper(IntFunction<T> fromId, ToIntFunction<T> toId) { ... }

```

**用 ByteBufCodecs 组合**：

```java
public static final StreamCodec<RegistryFriendlyByteBuf, ClientboundLoginPacket> STREAM_CODEC = StreamCodec.composite(
    ByteBufCodecs.INT, ClientboundLoginPacket::playerId,
    ByteBufCodecs.BOOL, ClientboundLoginPacket::hardcore,
    ByteBufCodecs.collection(...), ClientboundLoginPacket::levels,
    // ⋯
    ClientboundLoginPacket::new
);
```

**优势**：声明式，无手写读写——更不易写错。

但**实际 Mojang 的代码**：常见的 packet 仍混用——简单的用 `Packet.codec(...)`，复杂的用 `StreamCodec.composite(...)`。

## 7.3.8 Packet.handle 双分派

每个 Packet 必须实现 `handle`：

```java
public interface Packet<L extends PacketListener> {
    PacketType<? extends Packet<L>> type();
    void handle(L listener);
    default boolean isTerminal() { return false; }
}
```

**`handle(listener)`** 调 listener 的对应方法：

```java
// ServerboundMovePlayerPacket
@Override
public void handle(ServerGamePacketListener listener) {
    listener.handleMovePlayer(this);
}
```

**双分派**：

- Connection 知道 Packet 但不知具体类型 → 调 packet.handle(listener)。
- Packet 子类知道自己类型 → 调 listener 的具体 method。
- listener 实现具体逻辑。

## 7.3.9 Wire layout 完整示例

ServerboundChatPacket 在 wire 上：

```
[VarInt: packet id]                 1 byte (e.g. 0x05)
[VarInt: message length]             1-3 bytes (typically 1, e.g. 0x0B = 11)
[bytes: "hello world" UTF-8]         11 bytes
[long: timestamp]                    8 bytes
[long: salt]                         8 bytes

总：~30 bytes（无压缩）
```

如果加密 + 压缩：

```
[Varint length prefix (含本字段后所有内容)]   1-3 bytes
[包内容]
[加密 padding (AES block size)]               几 bytes
```

## 7.3.10 性能 / 内存

```
单 packet 序列化：
- VarInt 写：~1 ns
- 字符串写：~50 ns（含 UTF-8 编码）
- BlockPos / UUID 写：~5 ns
- NBT 写：取决于 NBT 大小

完整 packet 编码：~100 ns - 1 微秒（典型）
```

**ByteBuf 池化**：Netty 的 PooledByteBufAllocator 重用 buffer，减少 GC 压力。

## 7.3.11 C++ 移植

```cpp
namespace mc::network {

class ByteBuf {
public:
    void writeByte(uint8_t b);
    void writeShort(int16_t v);
    void writeInt(int32_t v);
    void writeLong(int64_t v);
    void writeFloat(float v);
    void writeDouble(double v);
    void writeBytes(std::span<const std::byte> data);
    
    uint8_t readByte();
    int16_t readShort();
    int32_t readInt();
    int64_t readLong();
    float readFloat();
    double readDouble();
    void readBytes(std::span<std::byte> out);
    
    // ⋯
};

class FriendlyByteBuf : public ByteBuf {
public:
    void writeVarInt(int32_t value) {
        while ((value & ~0x7F) != 0) {
            writeByte(uint8_t(value & 0x7F) | 0x80);
            value = uint32_t(value) >> 7;
        }
        writeByte(uint8_t(value));
    }
    
    int32_t readVarInt() {
        int32_t result = 0;
        int shift = 0;
        uint8_t b;
        do {
            b = readByte();
            result |= int32_t(b & 0x7F) << (shift++ * 7);
            if (shift > 5) throw std::runtime_error("VarInt too big");
        } while ((b & 0x80) != 0);
        return result;
    }
    
    void writeUtf(std::string_view s, size_t maxLength = 32767) {
        if (s.size() > maxLength * 4) throw std::runtime_error("String too long");
        writeVarInt(int32_t(s.size()));
        writeBytes(std::as_bytes(std::span(s)));
    }
    
    std::string readUtf(size_t maxLength = 32767) {
        int32_t len = readVarInt();
        if (len > int32_t(maxLength * 4)) throw std::runtime_error("String too long");
        std::string s(len, '\0');
        readBytes(std::as_writable_bytes(std::span(s)));
        return s;
    }
    
    void writeBlockPos(BlockPos pos) {
        writeLong(pos.asLong());
    }
    
    BlockPos readBlockPos() {
        return BlockPos::of(readLong());
    }
    
    void writeUUID(uint64_t hi, uint64_t lo) {
        writeLong(int64_t(hi));
        writeLong(int64_t(lo));
    }
    
    void writeNbt(const NbtCompound* tag);
    NbtCompound readNbt();
};

template<typename T>
class StreamCodec {
public:
    using Encoder = std::function<void(FriendlyByteBuf&, const T&)>;
    using Decoder = std::function<T(FriendlyByteBuf&)>;
    
    StreamCodec(Encoder enc, Decoder dec) : encode_(std::move(enc)), decode_(std::move(dec)) {}
    
    void encode(FriendlyByteBuf& buf, const T& value) const { encode_(buf, value); }
    T decode(FriendlyByteBuf& buf) const { return decode_(buf); }
    
private:
    Encoder encode_;
    Decoder decode_;
};

}
```

## 7.3.12 一句话总结

`FriendlyByteBuf` 是 ByteBuf 的 Minecraft 包装——加 VarInt / UTF-8 字符串 / BlockPos / UUID / NBT 等读写方法；VarInt 用每字节 7 bit + 1 bit 续位编码（小值省字节），与 protobuf 兼容；`RegistryFriendlyByteBuf` 加 RegistryAccess 上下文用于序列化 Holder<T>；`StreamCodec<B, V>` 是 1.20.5+ 引入的 packet 序列化抽象，配合 `Packet.codec(write, read)` 让 record-style packet 简洁；ByteBufCodecs 提供基础 codec 库可组合复杂 packet；Packet.handle(listener) 双分派调 listener 具体方法；wire 上 packet = `[VarInt id][payload]`，加压缩 / 加密外层再加 `[VarInt length]`。
