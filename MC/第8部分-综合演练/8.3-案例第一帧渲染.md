# 8.3 案例：客户端从空到第一帧地形渲染

## 8.3.0 场景设定

**初始条件**：

- 客户端已收到 ClientboundLoginPacket（玩家位置已知）。
- 第一批 ClientboundLevelChunkWithLightPacket 正在到达。
- 玩家屏幕仍是 "Loading world" 进度条。

**目标**：从客户端收到第一个 chunk packet 到玩家屏幕看到第一个有内容的画面（地形、天空、太阳）的**完整渲染流程**。

---

## 8.3.1 时序总览

```
[T=0]
客户端收到第一个 ClientboundLevelChunkWithLightPacket
↓
[T=1ms]
ClientLevel.replaceWithPacketData 反序列化 chunk
LevelRenderer.allChanged() 标记初始 dirty
↓
[T=2ms]
ChunkRenderDispatcher 创建 worker pool（8 个）
worker 开始重编译第一个 section mesh
↓
[T=10ms]
第一个 section mesh 完成 → upload 到 GPU
↓
[T=15ms - 渲染帧]
GameRenderer.render 调用 LevelRenderer.renderLevel
绘制天空 + 已 ready 的 chunk
↓
[T=16ms]
SwapBuffers → 玩家看到第一帧画面（部分加载）
↓
[T=2-5s]
所有视距内 chunk mesh 完成
玩家看到完整周围环境
```

## 8.3.3 LevelRenderer：渲染主导

```java
public class LevelRenderer {
    private final Minecraft minecraft;
    private ClientLevel level;
    private ChunkRenderDispatcher chunkRenderDispatcher;

        this.tickRainSplashing();
        
        // 1. 渲染天空 / 太阳 / 月亮
        this.renderSky(...);
        
        // 2. 渲染地形（chunk meshes）
        this.renderLevelStage(LevelRenderer.Stage.SOLID, ...);
        this.renderLevelStage(LevelRenderer.Stage.CUTOUT_MIPPED, ...);
        this.renderLevelStage(LevelRenderer.Stage.CUTOUT, ...);

        this.renderEntities(...);
        
        // 4. 渲染 BlockEntities
        this.renderBlockEntities(...);
        
        // 5. 渲染粒子

        // 7. 调试 / 选中边框等

}
```

**LevelRenderer 不直接 draw call**——它委托给 `ChunkRenderDispatcher` 把 mesh 提交给 GPU。

## 8.3.4 ChunkRenderDispatcher

```java
public class ChunkRenderDispatcher {
    public static final int MIN_RENDER_DISTANCE = 2;
    public static final int MAX_RENDER_DISTANCE = 32;
    
    private final List<ChunkBuilder> threads;     // 8 个 worker thread
    private final ExecutorService executor;
    private final BlockingQueue<ChunkRenderDispatcher.RenderChunk.ChunkCompileTask> taskQueue;
    
    public void rebuildChunkAsync(RenderChunk renderChunk, RenderRegionCache cache) {
        ChunkCompileTask task = renderChunk.createCompileTask(cache);
        this.taskQueue.add(task);
    }
}

class ChunkBuilder implements Runnable {
    @Override
    public void run() {
        while (!shutdown) {
            ChunkCompileTask task = taskQueue.take();
            CompiledChunk compiled = task.doTask();
            
            // upload 到 GPU（在主线程）
            minecraft.executeIfPossible(() -> {
                renderChunk.uploadCompiled(compiled);
            });
        }
    }
}
```

**8 worker thread**（默认）。每个 worker 取 task → 编译 → 主线程 upload。

## 8.3.5 单 section mesh 编译

```java
// ChunkCompileTask.doTask
public CompiledChunk doTask() {
    CompiledChunk compiled = new CompiledChunk();
    
    BlockPos sectionMin = ...;     // section 在世界中的最小角
    
    // 对 16³ = 4096 个方块
    for (int x = 0; x < 16; x++) {
        for (int y = 0; y < 16; y++) {
            for (int z = 0; z < 16; z++) {
                BlockPos pos = sectionMin.offset(x, y, z);
                BlockState state = renderRegion.getBlockState(pos);
                if (state.isAir()) continue;
                
                // 1. 决定方块的 RenderShape
                RenderShape shape = state.getRenderShape();
                if (shape == RenderShape.MODEL) {
                    // 2. 取 BlockModel
                    BakedModel model = blockRenderer.getBlockModel(state);
                    
                    // 3. 对每个 RenderType（SOLID / CUTOUT / TRANSLUCENT）
                    for (RenderType type : RenderType.chunkBufferLayers()) {
                        if (canBeRendered(state, type)) {
                            // 生成 vertex data 写入 compiled 的对应 buffer
                            blockRenderer.renderBlock(state, pos, renderRegion, model, vertexConsumer);
                        }
                    }
                } else if (shape == RenderShape.ENTITYBLOCK_ANIMATED) {
                    // BlockEntity 自己渲染（如箱子、信标）
                } else {
                    // INVISIBLE - 不渲染
                }
                
                // 4. 流体渲染
                FluidState fluid = state.getFluidState();
                if (!fluid.isEmpty()) {
                    fluidRenderer.render(fluid, pos, vertexConsumer, ...);
                }
            }
        }
    }
    
    return compiled;
}
```

**算法**：对 4096 方块每个：

1. 取 BlockState → 决定 RenderShape。
2. 对 MODEL 形状：取 BakedModel → 生成 vertex data。
3. 4 个 RenderType 各自一个 vertex buffer（透明 / 非透明分组渲染）。
4. 流体单独处理（FluidRenderer）。

**typical 一个 section vertex 数**：~10K-100K 顶点（视复杂度）。

## 8.3.6 BakedModel：方块外观

```java
public interface BakedModel {
    List<BakedQuad> getQuads(@Nullable BlockState state, @Nullable Direction face, RandomSource random);
    boolean useAmbientOcclusion();
    boolean isGui3d();
    boolean usesBlockLight();
    boolean isCustomRenderer();
    TextureAtlasSprite getParticleIcon();
}
```

**`BakedQuad`**：4 个顶点 + 法线 + UV 坐标 + 贴图引用 + 阴影偏移。

**vanilla 模型**：

- `oak_log` → 6 个面 × 1 quad/面 = 6 quads。
- `oak_stairs` → 12 quads（楼梯有更多面）。
- `flower` → ~4 quads（cross 形状）。

**BakedModel 来自 datapack**：`assets/minecraft/blockstates/oak_log.json` → 描述每个 BlockState 用哪个 model → `assets/minecraft/models/block/oak_log.json` → 描述模型几何。

启动时 ModelManager 加载所有 datapack model → bake（计算每个 BlockState 应该渲染什么）→ 缓存。

## 8.3.7 RenderType / 渲染层级

```java
public enum RenderType {
    SOLID,            // 不透明（草、木头）
    CUTOUT_MIPPED,    // 镂空有 mipmap（树叶、铁栅栏）
    CUTOUT,           // 镂空无 mipmap（玻璃、花）
    TRANSLUCENT       // 半透明（水、彩色玻璃）
}
```

**4 层渲染顺序**：

1. **SOLID** 先渲染——填充深度缓冲。
2. **CUTOUT_MIPPED** + **CUTOUT** 次——alpha test。
3. **TRANSLUCENT** 最后——alpha blend，必须按 Z 序渲染。

每方块的 mesh 分到对应 RenderType 的 vertex buffer。一个 section 有 4 个 vertex buffer（每 RenderType 一个）。

## 8.3.8 GPU upload

```java
// ChunkBuilder（worker）→ 主线程 callback
minecraft.executeIfPossible(() -> {
    renderChunk.uploadCompiled(compiled);
});

// RenderChunk.uploadCompiled (主线程)
public void uploadCompiled(CompiledChunk compiled) {
    for (RenderType type : RenderType.chunkBufferLayers()) {
        BufferBuilder builder = compiled.getBufferBuilder(type);
        VertexBuffer vb = this.getOrCreateVertexBuffer(type);
        vb.upload(builder.end());     // OpenGL glBufferData
    }
}
```

**OpenGL upload**：

- VertexBuffer 用 GL ARB_buffer_storage / glBufferData。
- 静态缓冲（chunk mesh 不每帧重传）。
- ~10-100 KB / section / RenderType。

**主线程同步**：upload 必须在主线程（OpenGL context 单线程）。worker 准备数据 → 主线程 upload。

## 8.3.9 frustum culling

```java
// LevelRenderer.renderLevel 内部
```

**视锥剔除**：每帧只渲染**摄像机视野内**的 chunk。视距 32 chunk² = 1024 chunk × 24 section = 24576 sections，但视野内通常只 ~500 个。**~50× 优化**。

## 8.3.11 实体渲染

```java
public void renderEntities(...) {
    for (Entity entity : this.level.entitiesForRendering()) {
        if (this.shouldRenderEntity(entity, camera)) {
            EntityRenderer<?, ?> renderer = this.entityRenderDispatcher.getRenderer(entity);
            if (renderer != null) {
                // 1. 计算插值位置（partialTick）
                double renderX = Mth.lerp(partialTick, entity.lastTickX, entity.posX);
                double renderY = Mth.lerp(partialTick, entity.lastTickY, entity.posY);
                double renderZ = Mth.lerp(partialTick, entity.lastTickZ, entity.posZ);
                
                // 2. 渲染（每实体类型有自己的 EntityRenderer）
                renderer.render(entity, ...);
            }
        }
    }
}
```

**partialTick 插值**：详见 4.7.8。每帧根据 (now - lastTickTime) / 50ms 算 0..1，用于实体位置丝滑动画。

## 8.3.12 第一帧总耗时

```
T=0       chunk packet 到达
T=1ms    ClientLevel.setBlock 完成（4096 方块 × 1ns ≈ 4 微秒——很快）
T=2ms    LevelRenderer dirty 标记
T=3ms    第一个 section mesh 编译开始（worker thread）
T=8ms    第一个 section mesh 完成（~5ms 单 section）
T=9ms    主线程 upload 到 GPU
T=10ms   下一帧渲染开始
T=11ms   渲染天空
T=12ms   渲染地形（仅 1 section ready，其他空）
T=13ms   渲染实体（仅自己玩家）
T=14ms   后处理 + SwapBuffers
T=15ms   **玩家看到第一帧画面**
```

**第一帧是不完整的**——只有 1 个 section 显示。后续 ~2-5 秒所有视距 chunk mesh 完成。

**玩家感受**："Loading world" 消失 → 看到天空 + 部分地形 → 1-2 秒后地形完整。

## 8.3.13 性能特征

```
单 chunk packet 处理：~1-3 ms（含反序列化 PalettedContainer）
单 section mesh 编译：~5-50 ms（视复杂度）
GPU upload：~0.1 ms（每 section 几十 KB）
单帧渲染：~5-20 ms（取决于 view distance + 复杂度）

视距 32 chunk² 内全部 mesh 编译：
- 总 24576 sections × 平均 10 ms = 245 秒（单线程）
- 8 worker 并行：~30 秒
- 实际：mesh 仅在 dirty 时编译，多数 chunk 不 dirty → ~3-5 秒首次完成

之后：稳态每帧 ~10-15 ms（60+ FPS）
```

**性能瓶颈**：

- **mesh 编译**：CPU bound（worker 池）。
- **GPU draw call**：~500-2000 个 / 帧（每 RenderChunk 4 个 RenderType）。
- **frustum culling**：CPU 开销（数 ms / 帧）。

## 8.3.15 一句话总结

客户端从空到第一帧地形渲染：(1) 收 ClientboundLevelChunkWithLightPacket → 反序列化 PalettedContainer + light → ClientChunkCache.replaceWithPacketData → ClientLevel.onChunkLoaded → (2) LevelRenderer.onChunkLoaded 标记 dirty → ChunkRenderDispatcher 提交 task 到 8 worker 线程 → (3) ChunkBuilder.doTask 对 16³ 方块取 BakedModel + 生成 vertex data，按 4 个 RenderType（SOLID / CUTOUT_MIPPED / CUTOUT / TRANSLUCENT）分组 → (4) worker 完成 → 主线程 GPU upload (glBufferData) → (5) renderLevel 渲染天空 + 地形 (frustum 内 RenderChunk 的 vertex buffer 直接 draw) + 实体 (partialTick 插值) + 粒子 + 半透明；第一帧 ~15 ms 后玩家看到画面（部分加载），所有视距 chunk mesh ~3-5 秒完成；触及第 0、1、6、7 + 客户端独有渲染层（LevelRenderer / ChunkRenderDispatcher / BakedModel / RenderType / frustum culling）。
