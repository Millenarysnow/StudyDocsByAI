# 第 8 部分 · 综合演练 —— 导读

## 你为什么需要先读这一部分

到这里你已经读完了 0-7 共 8 个部分约 80 篇文档。每一部分都讲清了一个独立的子系统：坐标系、数据结构、存档、地形生成、方块更新、红石、流体、网络。

但**实际玩家行为不会停在某一个子系统里**——它会**贯穿整个引擎**。比如：

- 玩家放一个方块 → 涉及网络（输入包）→ 数据结构（chunk 改）→ 方块更新（neighbor）→ 红石（如果是红石组件）→ 流体（如果 waterlogged）→ 持久化（chunk dirty）→ 网络（同步给其他玩家）。**8 个部分都被触及**。

第 8 部分用 3 个具体案例把整套机制**编织起来**。读完后你应当能：

1. 看到任何玩家行为或服务端事件，**在脑子里画出它经过的全部模块**。
2. 在调试问题时知道**该看哪个部分的代码**。
3. 写 C++ 移植时知道**模块间的接口形状**。
4. 拿到完整的实现里程碑路线图（M0-M9）。

## 阅读建议

8.1 / 8.2 / 8.3 是**端到端时序追踪** —— 每个案例都按时间轴展开，每一步标注涉及的模块。读时**回头查阅对应章节**会有"啊，原来是这样串起来的"的顿悟。

## 一句话预告

第 8 部分把前面 7 个独立模块串成 3 个真实场景——玩家放方块（涉及全部 8 个模块）、单机加载世界（worldgen + chunk + 网络的协同）、客户端第一帧渲染（数据从磁盘 / 网络到 GPU）；最后给出 M0-M9 移植里程碑（从基础数据结构到能联机的最小可玩引擎）；总结跨模块的工程量估算（~50000 行 C++ + 6-12 月工作量）+ 推荐后续学习方向。
