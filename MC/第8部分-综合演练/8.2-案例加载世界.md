# 8.2 案例：单机加载世界 100ms

## 8.2.0 场景设定

**初始条件**：

- 玩家在 Minecraft 主菜单。
- 已存在世界 "MyWorld"（约 5000 个 chunk 已生成）。
- 玩家的角色之前在 (100, 64, 100)。

**目标**：玩家点击"打开 MyWorld"按钮 → 玩家可控（角色显示在屏幕、能移动）的**完整时间轴**。

---

## 8.2.1 时序总览

```
[T=0ms]
玩家点击"Play"按钮
↓
[T=10ms] 启动 IntegratedServer
[T=50ms] 加载 level.dat
[T=100ms] 启动 Server thread
[T=200ms] 创建 ServerLevel + ChunkSource
[T=400ms] 加载 spawn chunks（同步阻塞）
[T=2000ms] 玩家加载完成
[T=2100ms] 客户端 connect 集成服务端
[T=2200ms] 走完整 LOGIN + CONFIGURATION 流程
[T=2500ms] PLAY 阶段，开始接收 chunk
[T=4000ms] 玩家位置 chunk 全部加载，看到画面
[T=4100ms] 玩家可控
```

**总时间**：~4 秒（实际范围 2-15 秒，取决于硬盘速度 + chunk 复杂度）。

## 8.2.2 阶段 1：IntegratedServer 启动

```java
// Minecraft.createWorldOpenFlows
public WorldOpenFlows createWorldOpenFlows() {
    return new WorldOpenFlows(this, this.levelSource);
}

// 玩家点击 Play
public void doLoadLevel(String levelName, ...) {
    // 1. 验证世界存档
    LevelStorageSource.LevelStorageAccess storageAccess = ...;
    
    // 2. 启动 IntegratedServer
    this.minecraft.setScreen(new GenericMessageScreen(Component.translatable("menu.loadingLevel")));
    this.startNewIntegratedServer(...);
}

private void startNewIntegratedServer(LevelStorageSource.LevelStorageAccess storageAccess, ...) {
    // 创建 IntegratedServer
    IntegratedServer server = MinecraftServer.spin(thread -> {
        return new IntegratedServer(thread, this.minecraft, storageAccess, ...);
    });
    this.minecraft.setSingleplayerServer(server);
    
    // 等待服务端启动到能接受连接
    while (!server.isReady()) {
        Thread.sleep(10);
    }
    
    // 客户端连接到集成服务端
    this.connectToServer(...);
}
```

**涉及模块**：第 0.3（客户端 / 集成服务端架构）。

**`MinecraftServer.spin`** 创建一个新线程跑服务端 main loop。

## 8.2.3 阶段 2：服务端初始化

```java
// IntegratedServer.initServer
@Override
public boolean initServer() {
    // 1. 加载 level.dat（含玩家数据、世界数据、worldgen settings）
    this.loadLevel();
    
    // 2. 应用 datapack

}
```

### Step 2.2：createLevels

### Step 2.3：prepareLevels（关键阻塞步骤）

```java
public void prepareLevels(ChunkProgressListener listener) {
    ServerLevel overworld = this.overworld();
    BlockPos spawnPos = overworld.getSharedSpawnPos();
    
    // 1. 加载 spawn 周围 11×11 chunk（"始终加载"区域）
    int spawnRadius = 11;
    int totalChunks = (spawnRadius * 2 + 1) * (spawnRadius * 2 + 1);
    
    listener.updateSpawnPos(new ChunkPos(spawnPos));
    
    // 2. 同步阻塞加载所有 spawn chunk
    for (int dx = -spawnRadius; dx <= spawnRadius; dx++) {
        for (int dz = -spawnRadius; dz <= spawnRadius; dz++) {
            ChunkPos chunkPos = new ChunkPos(spawnPos.getX() / 16 + dx, spawnPos.getZ() / 16 + dz);
            
            // 触发 ChunkPyramid 加载到 FULL
            ServerChunkCache cache = overworld.getChunkSource();
            cache.getChunk(chunkPos.x, chunkPos.z, ChunkStatus.FULL, true);
            // ★ 同步等待，最长 ~50 ms / chunk
        }
    }
    
    // 3. 等所有 chunk 完成
    while (!allLoaded) Thread.sleep(10);
}
```

**~441 chunk × 平均 50ms = ~20 秒**（首次新世界生成）。

**优化**：

- 已存在的 chunk（从磁盘加载）只需 ~5 ms。
- 仅生成期 chunk 用 `LOADING_PYRAMID`（noop 大部分 step）。
- 如果存档已有 spawn chunks → 加载只需 ~2 秒。

**涉及模块**：

- **第 3.2** ChunkPyramid 流水线。
- **第 2.4-2.7** Region 文件 + IOWorker 加载。

## 8.2.4 阶段 3：客户端连接

```java
// Minecraft.connectToServer
private void connectToServer(...) {
    // 创建 LocalChannel 连到 IntegratedServer
    LocalAddress address = this.singleplayerServer.getLocalAddress();
    Connection connection = Connection.connectToLocalServer(address);
    
    // 客户端 ClientPacketListener
    ClientHandshakePacketListenerImpl handshakeListener = new ClientHandshakePacketListenerImpl(connection, ...);
    connection.setListener(handshakeListener);
    
    // 发 ClientIntentionPacket(LOGIN)
    connection.send(new ClientIntentionPacket(SharedConstants.getCurrentVersion().getProtocolVersion(), 
                                                "localhost", 25565, ClientIntent.LOGIN));
    
    // 发 ServerboundHelloPacket
    connection.send(new ServerboundHelloPacket(player.getName(), player.getUUID()));
    
    // 协议切换到 LOGIN（连接器）
}
```

**涉及模块**：第 7.1（LocalChannel）+ 第 7.2（5 阶段状态机）。

**单机模式特殊**：

- LocalChannel：内存通道，无 TCP。
- 跳过加密握手（`ClientboundHelloPacket.shouldAuthenticate = false`）。
- 跳过 Mojang sessionserver auth。
- 直接进入 CONFIGURATION 阶段。

## 8.2.5 阶段 4：CONFIGURATION

```
[Server thread → Client render thread (内存通道)]

Server → Client: ClientboundCustomReportDetailsPacket（可选）
Server → Client: ClientboundUpdateEnabledFeaturesPacket
Server → Client: ClientboundSelectKnownPacks(["minecraft:vanilla"])
Client → Server: ServerboundSelectKnownPacks(["minecraft:vanilla"])
                 // 客户端确认它已知 vanilla 包，跳过这部分 registry 同步

Server → Client: ClientboundRegistryDataPacket × N
                 // 仅同步 mod / datapack 改过的 registry 项
                 // 单机 vanilla：约 5-10 个（多数 vanilla 跳过）

Server → Client: ClientboundUpdateTagsPacket
                 // 全部 tag

Server → Client: ClientboundFinishConfigurationPacket
Client → Server: ServerboundFinishConfigurationPacket

[切换到 PLAY]
```

**总耗时**：~100-300 ms（内存通道极快）。

**涉及模块**：第 7.2（CONFIGURATION 阶段）。

## 8.2.6 阶段 5：PLAY 阶段开始

```
[Server tick]

ClientboundLoginPacket：
  - playerId
  - hardcore: false
  - dimensions: ["minecraft:overworld", "the_nether", "the_end"]
  - viewDistance: 10
  - simulationDistance: 10
  - 等等

ClientboundChangeDifficultyPacket
ClientboundPlayerAbilitiesPacket（飞行 / 创造模式）
ClientboundSetCarriedItemPacket（手持物品）
ClientboundUpdateRecipesPacket（解锁的合成）
ClientboundUpdateAdvancementsPacket（成就）
ClientboundEntityEventPacket
ClientboundContainerSetContentPacket（玩家背包）
ClientboundSetExperiencePacket
ClientboundSetHealthPacket

ClientboundSetDefaultSpawnPositionPacket(spawnPos)

ClientboundLevelChunkWithLightPacket × N
  ↓ chunk 加载到客户端

ClientboundPlayerPositionPacket(玩家位置)
  → 客户端确认 → ServerboundAcceptTeleportationPacket
```

**ClientboundLevelChunkWithLightPacket** 是最大头：

- 视距 10 chunk² = 21×21 = 441 chunk。
- 每 chunk ~30 KB 压缩。
- 总 ~13 MB 数据要发。

**单机内存通道**：~50-200 ms 即可发完。

**联机 50 Mbps**：~3-10 秒。

## 8.2.7 阶段 6：客户端处理 chunk

```java

    PacketUtils.ensureRunningOnSameThread(...);
    
    int chunkX = packet.getX();
    int chunkZ = packet.getZ();
    LevelChunk chunk = this.level.getChunkSource().replaceWithPacketData(
        chunkX, chunkZ, 
        packet.getChunkData(),
        packet.getLightData(),
        consumer -> {
            // 处理 chunk 内 BlockEntity
            for (BlockEntityInfo info : packet.getChunkData().getBlockEntitiesTags()) {
                BlockEntity be = chunk.getBlockEntity(info.packedXZ(), info.y());
                // ⋯
            }
        }
    );
    
    if (chunk != null) {
        this.level.onChunkLoaded(new ChunkPos(chunkX, chunkZ));
    }
}
```

**`replaceWithPacketData`** 内部：

- 反序列化 chunk sections (PalettedContainer)。
- 反序列化 light data。
- 标记 dirty render → ChunkRenderDispatcher 加入 worker queue。

**涉及模块**：第 1（chunk）+ 第 7.5（chunk packet）。

## 8.2.8 阶段 7：客户端 mesh 重编译

```java
// LevelRenderer.allChanged 在 ClientboundLoginPacket 处理后调
public void allChanged() {
    this.minecraft.executeBlocking(() -> {
        if (this.chunkRenderDispatcher == null) {
            this.chunkRenderDispatcher = new ChunkRenderDispatcher(this.level, ...);
        }
        // ⋯
    });
}

// ChunkRenderDispatcher 处理 dirty queue
// 每个 dirty section 提交给 worker thread：
class ChunkBuilder {
    public void rebuild(...) {
        // 1. 从 ClientLevel 读 BlockState[] for 16³
        // 2. 对每方块生成 vertex buffer
        // 3. 把 vertex buffer 上传到 GPU
    }
}
```

**worker 线程数**：默认 8（基于 CPU 核数）。

**单 section mesh 重编译**：~5-50 ms（视复杂度）。

**441 chunks × 24 sections / chunk = ~10000 sections**——并行 8 worker 处理大约 ~2-5 秒。

**实际**：玩家不需要等所有 chunk mesh 完成——客户端**先显示已 ready 的 chunk**，其他逐渐加进来。

**玩家"可控"**条件：

## 8.2.10 完整时间轴

```
T=0      玩家点击 Play
T=10ms   IntegratedServer.spin 创建线程
T=50ms   loadLevel(level.dat) 完成
T=100ms  createLevels（3 维度）完成
T=2000ms prepareLevels（spawn chunks 加载）完成
         （已生成存档：~500 ms；新世界：~10-30 秒）
T=2100ms 客户端 connectToServer（LocalChannel）
T=2150ms HANDSHAKING → LOGIN（瞬时）
T=2200ms LOGIN 完成（单机跳过加密 + auth）
T=2250ms CONFIGURATION 完成（~50 ms）
T=2260ms PLAY 阶段开始：发 ClientboundLoginPacket
T=2270ms ClientboundLevelChunkWithLightPacket × 441 开始
T=2400ms 全部 chunk packet 发完（内存通道）
T=2400ms 客户端 chunkRenderDispatcher 开始重编译 mesh
T=2500ms 玩家附近 9 chunk mesh 完成 → 显示画面
T=2500ms ClientboundPlayerPositionPacket → 客户端确认
T=2500ms **玩家可控**
T=4000ms 视距内全部 chunk mesh 完成（远 chunk 仍在加 mesh）
```

**总时间** ~2.5 秒（已生成存档）/ ~30 秒（首次新世界生成）。

## 8.2.11 性能瓶颈

| 阶段 | 时间 | 瓶颈 |
|------|------|------|
| loadLevel | ~50ms | 磁盘 IO（GZIP 解压） |
| prepareLevels | ~500ms-30s | **Worldgen / chunk IO**（最大头） |
| 客户端 chunk 接收 | ~100-200ms | 内存通道带宽 / packet 处理 |
| 客户端 mesh 重编译 | ~1-3s | CPU（8 worker 并行）|

**优化方向**：

- **prepareLevels 减小 spawnRadius**（默认 11 → 改成 4）— 加载快但玩家可见范围小。
- **chunk 重编译多线程**——已经是 8 worker。
- **mesh 缓存到磁盘**（社区 mod 做过）—— 重启后跳过重编译。

---

## 8.2.12 联机版差异

```
[联机]
TCP 连接握手：~100ms
LOGIN（含 RSA + Mojang auth）：~500-1500ms
CONFIGURATION：~200-500ms
chunk 传输：50 Mbps 下 13 MB → ~3-10 秒
mesh 重编译：同单机

总：~5-15 秒
```

联机版**慢 2-3 倍**——主要因为：

- TCP RTT 延迟（vs 内存通道）。
- 加密 / 压缩 CPU 开销。
- Mojang auth 网络延迟。

## 8.2.14 一句话总结

单机加载世界 ~2-30 秒：(1) IntegratedServer.spin 创建服务端线程 → (2) loadLevel 读 level.dat（GZIP NBT）+ DataFixerUpper 升级 → (3) createLevels 创建 3 个 dimension → (4) prepareLevels 同步加载 spawn 区 ~441 chunks（已存档 ~500ms，新生成 ~30s 是最大瓶颈）→ (5) 客户端 LocalChannel 连接 → (6) 跳过加密的 LOGIN + CONFIGURATION 同步 registry → (7) PLAY 阶段发 ClientboundLoginPacket + 441 个 ClientboundLevelChunkWithLightPacket（内存通道 ~100ms）→ (8) 客户端 8 worker 重编译 mesh（~1-3s）→ (9) 玩家位置周围 chunk ready → ClientboundPlayerPositionPacket 确认 → **玩家可控**；联机版慢 2-3 倍主因 TCP RTT + Mojang auth + 加密；触及第 0-7 几乎所有模块。
