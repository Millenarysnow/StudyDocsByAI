# 8.1 案例：玩家放方块的全栈追踪

## 8.1.0 场景设定

**初始条件**：

- 玩家 Steve 在主世界 (10, 64, 10) 站立，手持泥土物品。
- 玩家面前 (10, 63, 11) 是空气。
- 玩家右键面前的草方块（瞄准面：NORTH，目标位置 = 草方块上面）。

**目标**：追踪从玩家鼠标点击到周围所有玩家屏幕上看到泥土出现的**完整时序**——经过哪些模块、调哪些函数、发哪些包。

---

## 8.1.1 时序总览

```
[T=0, Client Render Thread]
  鼠标事件 → MouseHandler → InteractionManager
  ↓
[T=1ms]
  客户端预测：ClientLevel.setBlock(targetPos, dirt, UPDATE_ALL | UPDATE_INVISIBLE)
  发包 ServerboundUseItemOnPacket
  ↓
[T=50ms - 网络]
  ↓
[T=51ms, Server Netty Thread]
  Connection.channelRead0 → Netty pipeline → packet → ServerGamePacketListener.handleUseItemOn
  → ensureRunningOnSameThread → 投递到 server tick
  ↓
[T=52ms - 等待 tick]
  ↓
[T=70ms, Server Tick Thread]
  ServerLevel.setBlock(targetPos, dirt, UPDATE_ALL)
  → LevelChunk.setBlockState
  → PalettedContainer 改
  → heightmap 更新
  → BlockEntity 处理（不需要）
  ↓
  NeighborUpdater.updateNeighborsAt → 6 邻居 neighborChanged
  ↓
  ChunkHolder.blockChanged → 标记出包队列
  ↓
[T=71ms]
  player.ackSequence(N) → 广播 ClientboundBlockChangedAckPacket(N)
  ChunkMap.broadcast(blockUpdate) → ClientboundBlockUpdatePacket
  ↓
[T=120ms - 网络]
  ↓
[T=121ms, Client Render Thread]
  本玩家收到 BlockUpdate → ClientLevel.setBlock（已是 dirt，noop）
  本玩家收到 ack → 移除待 ack
  其他玩家收到 BlockUpdate → ClientLevel.setBlock + 触发碎块粒子
  → ChunkRenderDispatcher 标记 chunk dirty render
  ↓
[T=130ms]
  下一帧渲染：ChunkRenderDispatcher 重编译 chunk mesh → GPU 上屏
  其他玩家看到泥土
```

**总延迟**：玩家点击到其他玩家看到 ≈ 130 ms。本玩家 1 ms 后就看到（客户端预测）。

## 8.1.2 详细分解：客户端阶段

### Step 1：鼠标输入 → InteractionManager

```java
// Minecraft 主循环
public void runTick() {
    // ⋯
    this.handleKeybinds();     // 处理输入
    
    // 处理鼠标右键
    if (this.options.keyUse.consumeClick()) {
        this.startUseItem();
    }
}

private void startUseItem() {
    if (!this.player.isUsingItem()) {
        ItemStack heldItem = this.player.getItemInHand(InteractionHand.MAIN_HAND);
        BlockHitResult hit = (BlockHitResult) this.hitResult;
        if (hit.getType() == HitResult.Type.BLOCK) {
            // 调用 GameMode.useItemOn
            InteractionResult result = this.gameMode.useItemOn(this.player, InteractionHand.MAIN_HAND, hit);
        }
    }
}
```

**hitResult**：每帧 Minecraft 做 ray cast 计算"玩家鼠标当前指向的方块"。`BlockHitResult` 含目标 BlockPos、命中面、命中精确点。

### Step 2：客户端预测

```java

    BlockPos pos = hit.getBlockPos();

        // 改用 use_item_on 流程
    }
    
    // 客户端预测：立刻放方块
    int sequence = ++this.player.getCurrentSequence();
    
    // 发包
    ServerboundUseItemOnPacket pkt = new ServerboundUseItemOnPacket(hand, hit, sequence);
    this.connection.send(pkt);
    
    // 客户端预测：调用 BlockItem.place 实际放方块（写到 ClientLevel）
    BlockPlaceContext ctx = new BlockPlaceContext(player, hand, heldItem, hit);
    InteractionResult result = heldItem.useOn(ctx);
    
    return result;
}

// BlockItem.useOn 内部：
public InteractionResult useOn(UseOnContext ctx) {
    BlockPos targetPos = ...;     // 命中位置 + 命中面 → 放置位置
    BlockState placedState = this.getPlacementState(...);
    
    // 调用 level.setBlock
    boolean placed = ctx.getLevel().setBlock(
        targetPos, 
        placedState, 
        Block.UPDATE_ALL | Block.UPDATE_INVISIBLE     // ★ flags = 7
    );
    
    if (placed) {

    }

```

**涉及模块**：

- **第 0 部分**：`InteractionHand` enum、BlockHitResult 类型。
- **第 1 部分**：BlockState、placement state 选择。
- **第 4.6**：setBlock flags = `UPDATE_ALL | UPDATE_INVISIBLE`（7）—— 触发邻居更新 + 同步客户端 + 跳过粒子（已预测）。
- **第 7.6**：sequence id 递增。

`ClientLevel.setBlock`：

- **第 4 部分**：邻居更新（InstantNeighborUpdater，客户端简单递归）。

### Step 4：发包


**涉及模块**：

- **第 7.1**：Netty pipeline outbound——BUNDLER → ENCODER → ENCRYPT → COMPRESS → PREPENDER → socket。


### Step 6：handleUseItemOn

```java
// ServerGamePacketListenerImpl.handleUseItemOn
@Override
public void handleUseItemOn(ServerboundUseItemOnPacket packet) {
    PacketUtils.ensureRunningOnSameThread(packet, this, this.player.serverLevel());
    // ★ 不在 server 主线程 → 抛 RUNNING_ON_DIFFERENT_THREAD
    // ServerLevel.tell(task) 投递到 server tick 队列
    
    if (this.player.isImmobile()) return;
    
    InteractionHand hand = packet.getHand();
    ItemStack heldStack = this.player.getItemInHand(hand);
    BlockHitResult hit = packet.getHitResult();
    BlockPos pos = hit.getBlockPos();
    Direction face = hit.getDirection();
    
    // 距离 / 越界检查
    if (this.player.distanceToSqr(pos.getX() + 0.5, pos.getY() + 0.5, pos.getZ() + 0.5) > MAX_INTERACTION_DISTANCE_SQUARED) {
        // 拒绝：玩家太远
        return;
    }
    
    // 实际处理
    InteractionResult result = this.player.gameMode.useItemOn(...);
    
    // ack：无论成功 / 失败都发 sequence ack
    this.player.connection.send(new ClientboundBlockChangedAckPacket(packet.getSequence()));
}
```

**涉及模块**：

- **第 4 部分**：scheduled tick 投递（PacketUtils.ensureRunningOnSameThread 把 task 投递）。
- **第 7.2**：PacketListener 接口。
- **第 7.6**：sequence ack 机制。

### Step 7：投递到 tick 主线程

```java
// PacketUtils.ensureRunningOnSameThread
public static void ensureRunningOnSameThread(Packet<?> packet, PacketListener listener, ServerLevel level) {
    if (!level.getServer().isSameThread()) {
        level.getServer().execute(() -> {
            packet.handle((ServerGamePacketListener) listener);
        });
        throw RunningOnDifferentThreadException.RUNNING_ON_DIFFERENT_THREAD;
    }
}
```

**Mojang 模式**：Netty 线程收到 packet → 投递到主线程 → 抛异常退出 Netty 处理 → 主线程下一 tick 处理。

## 8.1.5 详细分解：服务端主线程处理

### Step 8：服务端 setBlock

主线程下一 tick 调 `packet.handle(...)`：

```java
// ServerPlayerGameMode.useItemOn
public InteractionResult useItemOn(ServerPlayer player, Level level, ItemStack heldStack, InteractionHand hand, BlockHitResult hit) {
    BlockPos pos = hit.getBlockPos();
    BlockState targetState = level.getBlockState(pos);
    
    // 检查目标方块允许交互（如箱子右键打开 GUI 而不是放方块）
    if (!targetState.useWithoutItem(...)) {
        // 走"放置方块"流程
        BlockPlaceContext ctx = new BlockPlaceContext(player, hand, heldStack, hit);
        InteractionResult result = heldStack.useOn(ctx);
        
        if (result.consumesAction() && !player.isCreative()) {
            heldStack.shrink(1);
        }
        return result;
    }
    
    return InteractionResult.PASS;
}

// BlockItem.useOn 服务端版（与客户端代码相同，但改 ServerLevel）
public InteractionResult useOn(UseOnContext ctx) {
    BlockPos targetPos = ...;
    BlockState placedState = this.getPlacementState(ctx);
    
    boolean placed = ctx.getLevel().setBlock(
        targetPos, placedState,
        Block.UPDATE_ALL | Block.UPDATE_INVISIBLE     // 同客户端 flags
    );
    
    return placed ? InteractionResult.SUCCESS : InteractionResult.FAIL;

```

### Step 9：ServerLevel.setBlock

```java
// ServerLevel.setBlock (实际是 Level.setBlock)
public boolean setBlock(BlockPos pos, BlockState newState, int flags, int recursion) {
    LevelChunk chunk = this.getChunkAt(pos);
    BlockState oldState = chunk.setBlockState(pos, newState, ...);
    if (oldState == null || oldState == newState) return false;
    
    // 1. 同步客户端
    if ((flags & UPDATE_CLIENTS) != 0) {
        if ((flags & UPDATE_INVISIBLE) == 0 || !this.isClientSide) {
            this.sendBlockUpdated(pos, oldState, newState, flags);
        }
    }
    
    // 2. onPlace / onRemove
    if (oldState.getBlock() != newState.getBlock()) {
        oldState.onRemove(this, pos, newState, false);
        newState.onPlace(this, pos, oldState, false);
    }
    
    // 3. 邻居更新
    if ((flags & UPDATE_NEIGHBORS) != 0) {
        this.updateNeighborsAt(pos, newState.getBlock());
    }
    
    // 4. shape update
    if ((flags & UPDATE_KNOWN_SHAPE) == 0 && recursion > 0) {
        this.updateNeighbourShapesAt(pos, newState, recursion - 1);
    }
    
    return true;
}
```

**涉及模块**：

- **第 1 部分**：LevelChunk.setBlockState → PalettedContainer + heightmap + 计数器。
- **第 4.6**：8 flag 位逻辑。
- **第 4.4**：CollectingNeighborUpdater 处理邻居链。
- **第 5.1-5.2**：如果是 redstone 组件，邻居更新会传播信号。
- **第 6.5**：如果是 waterloggable 方块，可能影响流体状态。

```java
// 在 ServerChunkCache.tickChunks 调
public void broadcastChanges(LevelChunk chunk) {
    if (this.hasChangedSections) {
        for (int sIdx = 0; sIdx < 24; sIdx++) {
            ShortSet changes = this.changedBlocksPerSection[sIdx];
            if (changes.size() == 1) {
                short relPos = changes.iterator().nextShort();
                BlockPos pos = ...;
                BlockState state = chunk.getBlockState(pos);
                this.broadcast(new ClientboundBlockUpdatePacket(pos, state), false);
            } else if (changes.size() > 1) {
                // 多格变化用 SectionBlocksUpdatePacket
                this.broadcast(new ClientboundSectionBlocksUpdatePacket(...), false);
            }
            changes.clear();
        }
        this.hasChangedSections = false;
    }
}

private void broadcast(Packet<?> packet, boolean includeSelf) {
    List<ServerPlayer> players = this.playerProvider.getPlayers(this.pos, includeSelf);
    for (ServerPlayer p : players) {
        p.connection.send(packet);
    }
}
```

### Step 15：客户端收 BlockUpdate

```java
@Override
public void handleBlockUpdate(ClientboundBlockUpdatePacket packet) {
    PacketUtils.ensureRunningOnSameThread(packet, this, this.minecraft);
    this.level.setServerVerifiedBlockState(packet.getPos(), packet.getBlockState(), Block.UPDATE_ALL);
}

// ClientLevel.setServerVerifiedBlockState
public void setServerVerifiedBlockState(BlockPos pos, BlockState state, int flags) {
    if (!setBlock(pos, state, flags)) return;
    
    // 触发碎块粒子（仅其他玩家——本玩家已预测过）
    BlockState oldState = this.getBlockState(pos);
    if (this.player != null && this.player.isAlive() && !sameBlock) {
        this.levelEvent(2001, pos, Block.getId(oldState));     // 破坏粒子
    }
}
```

### Step 16：本玩家 vs 其他玩家

**本玩家**：

## 8.1.9 详细分解：客户端渲染

### Step 18：chunk dirty render

```java
// ClientLevel.markBlockChanged
public void markBlockChanged(BlockPos pos) {
    LevelChunk chunk = this.getChunkAt(pos);
    chunk.setUnsaved(true);
    // 通知 LevelRenderer
    this.minecraft.levelRenderer.blockChanged(this, pos, oldState, newState, flags);
}

// LevelRenderer.blockChanged
public void blockChanged(BlockGetter level, BlockPos pos, BlockState oldState, BlockState newState, int flags) {
    int sectionX = pos.getX() >> 4;
    int sectionY = pos.getY() >> 4;
    int sectionZ = pos.getZ() >> 4;
    
    this.setSectionDirty(sectionX, sectionY, sectionZ);
    
    // 边界方块也标记邻居 section（光照传播）
    if ((pos.getX() & 15) == 0) this.setSectionDirty(sectionX - 1, sectionY, sectionZ);
    // ⋯ 6 方向 ⋯
}
```

**涉及模块**：

- **客户端独有**（本教程未深入）：LevelRenderer / ChunkRenderDispatcher / mesh 重编译。

### Step 19：下一帧渲染

```java
// Minecraft 渲染循环
public void runFrame() {
    this.gameRenderer.render(partialTick);
}

// LevelRenderer.renderLevel
public void renderLevel(...) {
    // 1. 处理 dirty chunks → 重编译 mesh（在 worker thread）
    this.chunkRenderDispatcher.uploadChunks();
    
    // 2. 渲染所有 chunk mesh（GPU 调用）
    this.renderChunkLayer(RenderType.SOLID, ...);
    this.renderChunkLayer(RenderType.CUTOUT, ...);
    // ⋯
}
```

**chunk mesh 重编译**：

- ChunkRenderDispatcher 把 dirty section 提交给 worker thread。
- Worker 从 ClientLevel 取 BlockState[] → 生成 vertex buffer。
- 主线程 upload 到 GPU。

**典型时间**：单 section mesh 重编译 ~5-50 ms（视复杂度），但分散在多 worker thread。

## 8.1.11 异常路径：服务端拒绝

如果玩家想放方块在受保护区域 / 太远 / 物品不匹配：

```
[T=70ms server]
ServerLevel.setBlock 不被调用（gameMode 拒绝）
↓
仍发 BlockChangedAck(sequence)
但发"复原" BlockUpdate(targetPos, ORIGINAL_AIR) 给本玩家

[T=130ms client（本玩家）]
收到 BlockUpdate(targetPos, AIR) → ClientLevel.setBlock(AIR)
本玩家屏幕：看到刚预测的泥土"消失"——视觉撤销
收到 BlockChangedAck → 移除预测
```

**视觉效果**：玩家放方块"瞬间出现又消失"——常见的反作弊场景。

| **第 7 部分** | Netty pipeline、StreamCodec、客户端预测、ChunkMap broadcast |

**结论**：即使最简单的"放泥土"操作也几乎触及所有模块。

## 8.1.13 一句话总结

玩家放方块的全栈：客户端鼠标输入 → InteractionManager → 客户端预测 setBlock + 发 ServerboundUseItemOnPacket(sequence) → 客户端立刻看到（~1ms）→ 网络 50ms → 服务端 Netty → 主线程 → ServerLevel.setBlock(UPDATE_ALL | UPDATE_INVISIBLE) → LevelChunk + Heightmap + 邻居 BFS + ChunkHolder 出包队列 → tick 末尾 broadcast BlockUpdate / SectionBlocksUpdate + ack → 其他玩家 ~130ms 看到方块 + 碎块粒子；如果服务端拒绝 → 仅本玩家收复原 BlockUpdate（视觉撤销）；触及第 0、1、4、7 共 4 个模块（waterloggable / 红石场景再加 5、6）。
