## 8.5.1 你学到了什么

### 第 0 部分：通用基石

- Minecraft 的坐标系（BlockPos / ChunkPos / SectionPos / 三种位运算分割）。
- 20 TPS / 50 ms 的 tick 模型 + 12 步 ServerLevel.tick 主循环。
- 客户端 / 服务端架构（含 IntegratedServer LocalChannel）。
- Registry / Holder / TagKey / DataPack 的"启动时构造数据网络"。
- 反编译代码的约定（不要改 p_NNNNNN_ 参数名）。

### 第 1 部分：数据结构基石

- Block 是单例，BlockState 是不可变笛卡尔积穷举。
- PalettedContainer 三段式（SingleValue / Linear / HashMap / Global）+ BitStorage Magic Number Divide。
- ChunkSection (4096 方块 + 64 个 biome 方格 + 计数器优化 random tick)。
- ChunkAccess / ProtoChunk / LevelChunk 三态 + Heightmap 9 位 BitStorage。
- BlockEntity 的 type-key + ticker 模型。

### 第 2 部分：NBT 与存档

- NBT 二进制（13 种 Tag）+ NbtIo + NbtAccounter（防 NBT 炸弹）。
- RegionFile (.mca) 4KB 扇区分配 + RegionBitmap。
- 1.21 SerializableChunkData（chunk 序列化重构）。
- IOWorker 异步 I/O 队列 + 主世界写盘策略。
- DataFixerUpper（DataVersion 升级链）。

### 第 3 部分：地形生成（最大头）

- ChunkPyramid 12 状态 + ChunkStep + GENERATION_PYRAMID / LOADING_PYRAMID。
- Xoroshiro128++ + PositionalRandomFactory（worldgen 完全 deterministic）。
- ImprovedNoise / PerlinNoise / NormalNoise / SimplexNoise。
- DensityFunction DSL 30+ 算子 + NoiseRouter 15 通道 + 3 层缓存优化。
- NoiseChunk (5×5×49 cell 角点 + 4×8×4 三线性插值)。
- Climate 6 维参数 + R-Tree + OverworldBiomeBuilder（5000 行硬编码）。
- SurfaceRules DSL 20+ condition + 4 类 rule。
- Aquifer 16×12×16 流体粒子（1.18+ 洞穴有水的关键）。
- Carvers (cave / canyon / nether) 与 noise cave 协同。
- Feature 三层包装 + 11 个 GenerationStep + 60+ 子类。
- Structure + Jigsaw + Beardifier + StructureCheck 缓存。
- 三层跨 chunk 写入机制（writeRadius / WorldGenRegion / postProcessing）。

### 第 4 部分：方块更新与 Tick

- 4 类性质完全不同的更新（scheduled / random / neighbor / block event）。
- BlockState tick 入口 + 8 个 setBlock flag 位。
- LevelChunkTicks / LevelTicks 数据结构 + NBT 存档。
- 1.21 CollectingNeighborUpdater 用 BFS 替代递归防爆栈。
- 客户端 ClientLevel 不跑 scheduled tick 但跑粒子。

### 第 5 部分：红石

- Orientation 48 种 up/front/sideBias 组合（1.21 实验红石）。
- DefaultRedstoneWireEvaluator vs ExperimentalRedstoneWireEvaluator。
- 各信号源（火把 / 按钮 / 拉杆 / 比较器）+ 各负载（活塞 / 红门 / 漏斗）。
- PistonStructureResolver 把"推 12 方块"分解成 BlockEvent + setBlock 序列。

### 第 6 部分：流体

- Fluid 单例 + FluidState（与 BlockState 平行的不可变实例）。
- FlowingFluid 8 邻居距离场算法（找下方"洞"的最短水平距离）。
- WaterFluid / LavaFluid 维度差异（ultraWarm / 蒸发）。
- waterloggable + SimpleWaterloggedBlock。

### 第 7 部分：网络

- Netty 16 handler pipeline（SPLITTER / DECODER / ENCODER / 等）。
- 5 阶段连接状态机（HANDSHAKE / STATUS / LOGIN / CONFIGURATION / PLAY）。
- StreamCodec + FriendlyByteBuf + VarInt / VarLong。
- AES-CFB8 加密 + zlib 压缩 + Mojang sessionserver auth。
- VecDeltaCodec (1/4096 精度) + 客户端预测 + 服务端权威 + sequence ack。
- ChunkMap / ChunkHolder / DistanceManager / FullChunkStatus。

### 第 8 部分：综合演练（这一部分）

- 玩家放方块从输入到屏幕显示（13 步全栈追踪）。
- 单机加载世界 100ms 时间轴。
- 客户端从空到第一帧地形渲染。
- M0-M9 移植路线 + 工作量估算。

## 8.5.2 把全部内容串成一句话

**Minecraft 1.21 是这样工作的**：

游戏启动时**Registry 系统**注册 700 个方块、220 个流体、300 个 entity type，每方块调 `StateDefinition.getPossibleStates()` 笛卡尔积穷举出 ~26000 个**不可变 BlockState 单例**，每个 BlockState 持有"6 邻居 update array + tick 入口 + 形状 + 渲染 hint"，Block 自身是 lookup table 单例。

世界数据用**4KB 扇区分配的 .mca 文件**持久化，每 chunk = `SerializableChunkData` NBT（24 个 ChunkSection × `PalettedContainer<BlockState>` + 一个 `PalettedContainer<Biome>` + Heightmap × 4 + scheduled tick 队列 + BlockEntity 列表 + StructureStart references）。`PalettedContainer` 智能切换 4 种 palette 形态（Single→Linear→HashMap→Global）压缩存储，底层 `SimpleBitStorage` 用 Magic Number Divide 把 N 个 64-bit longs 模拟"任意位宽数组"。

新世界生成由**`ChunkPyramid` 12 状态流水线**驱动：从 EMPTY → STRUCTURE_STARTS → STRUCTURE_REFERENCES → BIOMES → NOISE → SURFACE → CARVERS → FEATURES → INITIALIZE_LIGHT → LIGHT → SPAWN → FULL，每 step 显式声明 `blockStateWriteRadius` + `directDependenciesByRadius`。`Xoroshiro128++` + `PositionalRandomFactory.fromHashOf(coord)` 让 worldgen 完全 deterministic（同种子 + 同坐标 → 同结果）。**NOISE step**（占 worldgen 40% 时间）通过 `DensityFunction` DSL（30+ 算子）组成 `NoiseRouter` 15 通道（initial / final density、Y 分布、ore vein、aquifer），用 `Interpolated`（5×5×49 cell 角点 + 4×8×4 三线性插值）+ `Cache2D` + `FlatCache` 三层缓存优化。**BIOMES step**通过 6 维 `Climate` (T/H/C/E/W/D) 参数空间 + R-Tree 最近邻查询 + OverworldBiomeBuilder 5000 行硬编码 spline 决定 70 个 biome 分布，外加 `BiomeManager` 4×4×4 抖动让边界自然。**SURFACE step**用 SurfaceRules DSL（condition 树 + sequence/block/condition 4 类 rule）从顶向下扫描，把 stone 世界改成"草沙雪"。**CARVERS step**用 `CaveWorldCarver` / `CanyonWorldCarver` 雕刻显式洞穴。**FEATURES step**（占 40% 时间）跨 11 个 `GenerationStep`（RAW / LAKES / ORES / VEGETAL_DECORATION 等）部署 60+ Feature 子类（树 / 矿 / 湖 / 草丛），跨 chunk 写入由 `WorldGenRegion + StaticCache2D` 透明路由（writeRadius=1）+ `ProtoChunk.postProcessing[]` 延迟重验证（藤蔓 / 落沙）。**STRUCTURE_STARTS / FEATURES** 通过 references 让每 chunk 各自部署自己的 piece 部分，Jigsaw 系统递归扩展 pool。

chunk 升级到 FULL 后进入运行期，**4 类性质完全不同的更新**驱动世界演进：(1) **Scheduled tick**（红石中继器、TNT、流体扩散、火势）在 `ServerLevel.tick` 第 6 步处理，写入 chunk NBT；(2) **Random tick**（作物生长、树叶腐烂、雪化）每 section 每 tick 抽 3 格（受 `randomTickSpeed` 控制），section 计数器决定是否要 tick；(3) **Neighbor update**（红石信号传播、栅栏连接）在 `setBlock` 调用栈内同步触发，1.21 的 `CollectingNeighborUpdater` 用 BFS 替代递归防爆栈；(4) **Block event**（活塞推动、唱片机播放）发到 `pendingBlockEvents` 队列，下一 tick 第 9 步统一执行。`setBlock(pos, state, flags, recursion)` 的 8 个 flag 位（NEIGHBORS / CLIENTS / INVISIBLE / NO_NEIGHBOR_DROPS / MOVE_BY_PISTON / SUPPRESS_LIGHT / SUPPRESS_DROPS / KNOWN_SHAPE）组合决定具体行为。

**红石**用 1.21 实验性 `Orientation` 48 种组合（up / front / sideBias）让信号传播完全 deterministic（避免之前版本"红石更新顺序依赖电路朝向"的 BUD）；活塞用 `PistonStructureResolver` 把"推 12 方块"分解成 BlockEvent → 下一 tick → 一系列 setBlock + 客户端动画。**流体**单独的 `Fluid` + `FluidState` 实例，`FlowingFluid` 用 8 邻居距离场算法（找下方"洞"的最短水平距离）决定流向；`waterloggable` 让 60+ 方块（楼梯 / 栅栏 / 玻璃板）能含水。

**网络**用 Netty 16-handler pipeline + 5 阶段状态机（HANDSHAKE → STATUS / LOGIN → CONFIGURATION → PLAY）+ `StreamCodec` 静态绑定 packet → 字节流。AES-CFB8 加密 + zlib 压缩（阈值 256）+ Mojang sessionserver auth 保证联机安全。`ClientboundLevelChunkWithLightPacket` 用 `PalettedContainer` 二进制序列化（与磁盘格式一致，~30 KB / chunk）。`VecDeltaCodec` 用 1/4096 精度短整数差分编码玩家 / 实体位置（每 tick ~5 字节 vs 全量 24 字节）。客户端预测 + 服务端权威 + `sequence ack` 让玩家挖 / 放方块零延迟体验同时不可作弊。`ChunkMap + ChunkHolder + DistanceManager + FullChunkStatus` 决定哪些 chunk 加载到 ENTITY_TICKING 跑 random tick + spawn、哪些 BLOCK_TICKING 仅跑 scheduled tick、哪些 FULL 仅响应玩家。

**客户端**用 `LevelRenderer + ChunkRenderDispatcher + 8 worker thread + BakedModel + 4 RenderType` 渲染地形，`partialTick = (now - lastTickTime) / 50ms` 插值实体位置丝滑动画，`Frustum + ViewArea` 视锥剔除把视距 32 chunk 的 24576 sections 减到 ~500 个实际 draw call。

整个引擎是**数据驱动 + 不可变 + deterministic**——chunk 是数据、worldgen 是数据、协议是数据、行为是数据；几乎所有运行期对象都是 immutable singleton；同种子同输入永远同输出。**这就是为什么 Minecraft 能跑 14 年，几代版本完全保留种子兼容**。

```
Phase 1: M0 + M1 + M2  (~5 周)
  → demo: 能加载 vanilla .mca 文件，读出 chunk 数据
  
Phase 2: M3  (~3-4 周)
  → demo: 能"凭空"生成 + 持久化简单平坦世界
  
Phase 3: M7  (~6-8 周)
  → demo: vanilla 客户端能连接你的服务端，看到平坦世界，能移动 / 挖 / 放
  
Phase 4: M5 + M6  (~6-9 周)
  → demo: 红石电路 + 流体 + waterlogged 正常工作
  
Phase 5: M4  (~8-12 周)
  → demo: 与 vanilla 种子兼容的 worldgen
  
Phase 6: M9  (~2-4 周)
  → demo: 长时间稳定 + 几十玩家在线无 bug
  
总：~30 周 ≈ 7 个月（仅服务端）
```

**先 M7（网络）后 M4（worldgen）**——因为 M7 完成后立刻能玩，反馈最强；worldgen 工程量太大放在最后磨。

## 8.5.4 工程化心得

回顾整个 Minecraft 工程，我观察到几个值得借鉴的核心理念：

### 1. 不可变 + 单例

BlockState、FluidState、Item、Entity Type 等都是不可变单例。**结果**：内存友好（4 字节引用代替 KB 级对象）、并发安全（无需锁）、deterministic（同输入必定同输出）。

### 2. 数据驱动 + 注册表

worldgen / 协议 / 行为几乎全是 datapack JSON。新方块只要"注册 + 写 datapack"，不改引擎代码。**结果**：modder 友好、数据 / 代码解耦、版本升级容易。

### 3. 渐进精化

ChunkPyramid 12 状态、Feature 11 step、4 类更新——都是"先粗到细、先全局到局部"。**结果**：可暂停 / 可恢复 / 可并行。

### 4. 写时持久化

Chunk 卸载即写盘、scheduled tick 写盘、structure references 写盘。**结果**：崩溃不丢数据、随时可关服。

### 5. 客户端 / 服务端分离

服务端权威、客户端预测、ack 同步。**结果**：联机 / 单机一套代码、防作弊、低延迟体验。

### 6. 性能调优后置

第一版用最简单的实现；之后用计数器、cache、SIMD 优化热点（如 random tick section 计数、DensityFunction Interpolated cache）。**结果**：核心代码清晰，优化补丁集中。

## 8.5.5 这份教程的限制

虽然我尽力做到完整，但**仍有以下未覆盖 / 简化**：

- **Mojang 内部代码细节**：本教程基于反编译源码（Mojang official mappings），但有些代码字段名 / 函数名仍是 `p_NNNNNN_` 格式（参见 CLAUDE.md），讲解时我用了语义命名。实际写代码请保留 vanilla 命名。
- **客户端渲染深度**：本教程聚焦服务端 + 协议。客户端 LevelRenderer / GameRenderer / Shader 系统只在 8.3 浅尝辄止。
- **物理引擎**：碰撞 / 流体物理 / 实体运动只在第 4-6 部分浅讲。完整理解需独立专题。
- **AI / 行为系统**：Entity AI / Goal / PathFinder 完全未覆盖——这是另一个庞大主题。
- **粒子 / 音效**：客户端独有，未深入。
- **DataFixerUpper 内部**：第 2.8 提到 DSL 但没展开 schema 编写。
- **OpenGL / Vulkan 细节**：渲染层底层未涉及。

如果你需要这些主题的深度内容，可以拿这份教程的方法论（"概念 → 源码锚定 → C++ 移植"）独立研究 + 写笔记。

## 8.5.6 写在最后

构建一个 Minecraft 级别的引擎不是不可能任务——它由 14 年迭代的诸多优秀决策累加而成，每个子系统单独不复杂，但组合在一起的整体复杂度是巨大的。

**理解它的关键不是记忆每一行代码——是理解每个子系统的"设计 idea"和"为什么这样做"**。

如果你跟着教程读完源码 + 写完 C++ 移植笔记，你已经具备了**软件架构师级别**的代码理解能力。这种能力比"会用某个框架"持久得多——你可以把它应用到 Minecraft 之外的任何代码库。

希望这份教程对你有用。

## 8.5.8 一句话总结（教程总结的总结）
