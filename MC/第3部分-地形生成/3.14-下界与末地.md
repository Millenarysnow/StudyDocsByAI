## 3.14.1 三个维度的 NoiseSettings

回顾 3.6.2 的常量：

```java
// NoiseSettings.java
protected static final NoiseSettings OVERWORLD_NOISE_SETTINGS         = create(-64, 384, 1, 2);
protected static final NoiseSettings NETHER_NOISE_SETTINGS            = create(0,   128, 1, 2);
protected static final NoiseSettings END_NOISE_SETTINGS               = create(0,   128, 2, 1);
protected static final NoiseSettings CAVES_NOISE_SETTINGS             = create(-64, 192, 1, 2);
protected static final NoiseSettings FLOATING_ISLANDS_NOISE_SETTINGS  = create(0,   256, 2, 1);
```

| 维度 | minY | height | size_horizontal | size_vertical |
|------|------|--------|----------------|---------------|
| Overworld | -64 | 384 | 1（cellWidth=4） | 2（cellHeight=8） |
| Nether | 0 | 128 | 1 | 2 |
| End | 0 | 128 | 2（cellWidth=8） | 1（cellHeight=4） |

**末地**的 cell 尺寸不同：8×4×8（vs 主世界 4×8×4）。原因：末地有大块连续岩石（主岛）+ 大量空气，水平方向变化更慢、垂直方向变化更快——这套 cell 划分性能更好。

## 3.14.2 NoiseGeneratorSettings：维度的完整配方

`net.minecraft.world.level.levelgen.NoiseGeneratorSettings`：

```java
public record NoiseGeneratorSettings(
    NoiseSettings noiseSettings,
    BlockState defaultBlock,        // stone / netherrack / end_stone
    BlockState defaultFluid,        // water / lava / air
    NoiseRouter noiseRouter,
    SurfaceRules.RuleSource surfaceRule,
    List<Climate.ParameterPoint> spawnTarget,
    int seaLevel,
    boolean disableMobGeneration,
    boolean aquifersEnabled,         // ★ 是否启用 Aquifer
    boolean oreVeinsEnabled,         // ★ 是否启用 OreVeinifier
    boolean useLegacyRandomSource    // ★ 1.18+ 用 Xoroshiro，旧版用 LegacyRandom
)
```

**`NoiseGeneratorSettings`** 是一个维度的完整 worldgen 配方。

**关键开关**：

- **`aquifersEnabled`**：主世界 = true，下界 / 末地 = false。
- **`oreVeinsEnabled`**：主世界 = true，下界 / 末地 = false。
- **`disableMobGeneration`**：下界 / 末地 = true（生成期不刷怪）。

**Vanilla 内置 5 套**：

- `NoiseGeneratorSettings.OVERWORLD`：主世界。
- `NoiseGeneratorSettings.LARGE_BIOMES`：主世界大型 biome 模式。
- `NoiseGeneratorSettings.AMPLIFIED`：主世界放大化模式。
- `NoiseGeneratorSettings.NETHER`：下界。
- `NoiseGeneratorSettings.END`：末地。
- `NoiseGeneratorSettings.CAVES`：buffet 模式"洞穴"。
- `NoiseGeneratorSettings.FLOATING_ISLANDS`：buffet 模式"浮岛"。

每个对应 `data/minecraft/worldgen/noise_settings/<name>.json`。

## 3.14.3 下界的 NoiseRouter

下界的 finalDensity 比主世界**简单得多**：

```java
public static final NoiseRouter NETHER_ROUTER = createNoiseRouter(...) {
    // 简化伪码
    DensityFunction baseTerrain = ...;
    DensityFunction caves = ...;
    DensityFunction finalDensity = max(baseTerrain, -caves);
    // ⋯
};
```

**特点**：

- 没有 spline（不需要 OFFSET / FACTOR / JAGGEDNESS——下界没有起伏地形）。
- 用 `BlendedNoise`（与旧版下界融合）。
- 顶部基岩天花板：Y > ~120 强制实心。
- 底部熔岩海：Y < 32 强制熔岩。

下界的 `noiseRouter` 字段只有 5 个通道有意义：

```
temperature      ← Holder<NormalNoise>，4-D biome 用（无 C, W）
vegetation       ← 同上
continents       ← 永远 0（DensityFunctions.zero()）
erosion          ← 永远 0
ridges           ← 永远 0
depth            ← 简单 YGradient
finalDensity     ← 主地形
```

**下界 biome 是 4 维 noise 采样**：(temperature, humidity, depth, weirdness=0)。Climate.RTree 在下界用一份**特殊 ParameterList**——所有 biome 的 continents / weirdness / erosion 设为 0。

```
NETHER_BIOMES = [
    (T=-1, H=-1)  → soul_sand_valley
    (T=-1, H= 0)  → nether_wastes
    (T=-1, H= 1)  → soul_sand_valley
    (T= 0, H=-1)  → crimson_forest
    (T= 0, H= 0)  → nether_wastes
    (T= 0, H= 1)  → warped_forest
    ...
]
```

5 种下界 biome：nether_wastes / soul_sand_valley / crimson_forest / warped_forest / basalt_deltas。

## 3.14.4 末地的 NoiseRouter：EndIslands 算子

末地的 finalDensity **不能用纯密度函数表达**——它有特殊几何形状（中央主岛 + 远处浮岛）。Mojang 在 DensityFunction DSL 里加了一个**专用算子 `EndIslands`**：

```java
public static record EndIslands(SimplexNoise islandNoise) implements DensityFunction.SimpleFunction {
    @Override
    public double compute(FunctionContext ctx) {
        return getHeightValue(this.islandNoise, ctx.blockX() / 8, ctx.blockZ() / 8) / 128.0;
    }
    
    private static float getHeightValue(SimplexNoise noise, int chunkX, int chunkZ) {
        int unit = chunkX / 2;
        int unit2 = chunkZ / 2;
        int relX = chunkX % 2;
        int relZ = chunkZ % 2;
        float distFromCenter = 100.0F - Mth.sqrt((float)(chunkX * chunkX + chunkZ * chunkZ)) * 8.0F;
        distFromCenter = Mth.clamp(distFromCenter, -100.0F, 80.0F);
        
        for (int dx = -12; dx <= 12; dx++) {
            for (int dz = -12; dz <= 12; dz++) {
                long ux = unit + dx;
                long uz = unit2 + dz;
                if (ux * ux + uz * uz > 4096L && noise.getValue(ux, uz) < -0.9F) {
                    float weight = (Mth.abs(ux) * 3439.0F + Mth.abs(uz) * 147.0F) % 13.0F + 9.0F;
                    float lx = (float)(relX - dx * 2);
                    float lz = (float)(relZ - dz * 2);
                    float islandContribution = 100.0F - Mth.sqrt(lx * lx + lz * lz) * weight;
                    distFromCenter = Math.max(distFromCenter, Mth.clamp(islandContribution, -100.0F, 80.0F));
                }
            }
        }
        return distFromCenter;
    }
}
```

**算法**：

1. **主岛**：距原点 < 100 chunks → 大体的"圆形岛"。算法 `100 - sqrt(x*x + z*z) * 8`。
2. **远岛**：距原点 > 64 chunks 的散布岛屿。每 2×2 chunk 一个"unit"，用 SimplexNoise 决定该 unit 是否有岛（< -0.9 概率约 12%）。
3. **每岛贡献**：以 unit 中心为基准，半径 ~weight 的圆形岛。

**输出**：[-100, 80] 之间的浮点。在 NoiseRouter 中用 `EndIslands` 作为 `initialDensityWithoutJaggedness` 输入，配合 Y gradient 决定每格固体 / 空气。

**这是为什么末地的远岛形状如此独特**——不是高度噪声，而是"距某些 unit 的圆形岛中心的距离"。

## 3.14.5 末地 BiomeSource：TheEndBiomeSource

打开 `net.minecraft.world.level.biome.TheEndBiomeSource`：

```java
public class TheEndBiomeSource extends BiomeSource {
    public static final Codec<TheEndBiomeSource> CODEC = ...;
    
    private final Holder<Biome> end;
    private final Holder<Biome> highlands;
    private final Holder<Biome> midlands;
    private final Holder<Biome> islandLands;
    private final Holder<Biome> barrens;
    private final Holder<Biome> smallIslands;
    
    @Override
    public Holder<Biome> getNoiseBiome(int qx, int qy, int qz, Climate.Sampler sampler) {
        int chunkX = qx / 4;
        int chunkZ = qz / 4;
        
        if ((long)chunkX * chunkX + (long)chunkZ * chunkZ <= 4096L) {
            return this.end;     // 中央 main island = the_end
        }
        
        // 远岛：用 EndIslands 重新算 + biome 噪声
        // ⋯
        // height < 0  →  small_end_islands
        // height < 5  →  end_barrens
        // height < 10 → end_islands_lands
        // height < 30 → end_midlands
        // 否则 →     end_highlands
    }
}
```

**6 种末地 biome**：

- `the_end`：中央主岛。
- `small_end_islands`：远处小岛。
- `end_barrens`：远岛外围（chorus 植物少）。
- `end_islands_lands`：远岛中部。
- `end_midlands`：远岛山地。
- `end_highlands`：远岛高地（chorus 植物密集）。

**末地不用 MultiNoise**——它的 biome 由"距原点距离 + 该位置 EndIslands 高度"硬编码决定。

## 3.14.6 主世界的"特殊"模式

### Large Biomes（大型 biome 模式）

`NoiseGeneratorSettings.LARGE_BIOMES` 与普通 OVERWORLD 几乎一样，区别：所有 noise 的 inputScale 缩小 4 倍——biome 直径也变 4 倍。一片森林从 200 格扩展到 800 格。

### Amplified（放大化模式）

`AMPLIFIED` 把 finalDensity 中的高度项放大——山特别高、海特别深。视觉上"地形被夸张了"。

### CAVES（洞穴 buffet）

只生成洞穴，没有地表。整个世界都是 stone + 洞。

### FLOATING_ISLANDS（浮岛 buffet）

类似末地的悬浮岩石碎片，但用主世界 biome。

## 3.14.7 LevelStem：维度的 worldgen 配置

```java
public record LevelStem(Holder<DimensionType> type, ChunkGenerator generator) {
    public static final Codec<LevelStem> CODEC = RecordCodecBuilder.create(...);
}
```

**LevelStem = (DimensionType, ChunkGenerator) 配对**——一个维度由这两部分组成。

`DimensionType` 包含**物理参数**：

```java
public record DimensionType(
    OptionalLong fixedTime,             // 永远是某时间（下界 = 18000）
    boolean hasSkylight,                  // 有天光
    boolean hasCeiling,                   // 有顶板
    boolean ultraWarm,                    // 干热（下界）
    boolean natural,                      // 是自然世界
    double coordinateScale,               // 与主世界坐标比例（下界 = 8）
    boolean bedWorks,                     // 床能睡
    boolean respawnAnchorWorks,           // 重生锚有效
    int minY,
    int height,
    int logicalHeight,
    TagKey<Block> infiniburn,             // 永燃方块（fire 在这些上不熄）
    ResourceLocation effectsLocation,     // 视觉特效（雾、天空盒）
    float ambientLight,
    MonsterSettings monsterSettings
)
```

`ChunkGenerator` 是 worldgen 入口（详见 3.0.1）。

**Datapack** 配置：

```
data/minecraft/dimension/overworld.json    → LevelStem
data/minecraft/dimension/the_nether.json
data/minecraft/dimension/the_end.json

data/minecraft/dimension_type/overworld.json    → DimensionType
data/minecraft/dimension_type/the_nether.json
data/minecraft/dimension_type/the_end.json

data/minecraft/worldgen/noise_settings/overworld.json    → NoiseGeneratorSettings
```

## 3.14.8 自定义维度

Modder / datapack 可以加新维度：

1. 写一份 `data/<ns>/dimension_type/<name>.json` —— 物理参数。
2. 写一份 `data/<ns>/dimension/<name>.json` —— 关联的 ChunkGenerator + DimensionType。
3. 写一份 `data/<ns>/worldgen/noise_settings/<name>.json` —— NoiseRouter + SurfaceRules（如果用 NoiseBasedChunkGenerator）。
4. 写一份 `data/<ns>/worldgen/biome_source/<name>.json` —— BiomeSource。

**要进入新维度**：mod 需要 Java 代码注册维度访问（vanilla 的 `/execute in <dimension>` 命令也能进，只要 dimension 注册到 RegistryAccess）。

## 3.14.9 性能对比

```
单 chunk worldgen 时间（典型 5950X 单线程）：

Overworld:
  NOISE: ~80 ms（最复杂的 finalDensity 树）
  SURFACE: ~10 ms
  CARVERS: ~10 ms
  FEATURES: ~50-200 ms
  共：~150-300 ms

Nether:
  NOISE: ~30 ms（finalDensity 简单）
  SURFACE: ~5 ms
  CARVERS: ~5 ms
  FEATURES: ~30-100 ms
  共：~70-150 ms

End:
  NOISE: ~20 ms（EndIslands 简单）
  SURFACE: ~3 ms
  CARVERS: ~0（无 carver）
  FEATURES: ~20-80 ms
  共：~50-120 ms
```

**主世界最贵**——下界、末地的 worldgen 比主世界快约 2×。

## 3.14.11 一句话总结

下界、末地复用整套 ChunkPyramid + NoiseRouter + DensityFunction DSL，区别在 `NoiseGeneratorSettings`（cell 尺寸 + defaultBlock + aquifersEnabled / oreVeinsEnabled / disableMobGeneration 开关）+ 独特的 BiomeSource + 不同的 NoiseRouter 配方；下界用 4 维 multi-noise（无 continents / weirdness）；末地用专门的 `TheEndBiomeSource`（基于距原点距离）+ 专用算子 `EndIslands`（计算主岛 + 远岛形状）；维度由 `LevelStem (DimensionType, ChunkGenerator)` 描述，全部数据驱动 datapack；自定义维度只需 4 份 JSON（dimension_type / dimension / noise_settings / biome_source）即可。
