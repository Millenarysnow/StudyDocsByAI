# 3.1 概念释义

## 3.1.0 你将在本节学到什么

读完这一节你应当**对地形生成有的全部专有名词都建立直观图像**——不是源码细节，而是"这个名字在游戏里是什么、视觉上决定什么、和它隔壁的概念怎么区分"。

这一节没有源码、没有数学、没有 C++ 移植。它只做一件事：**词汇基础**。

如果你完全没玩过 Minecraft，这一节是必读。如果你玩过 100 小时但没研究过 worldgen，这一节也是必读——你会发现"原来那个东西叫这个"。

读完后你应当能闭着眼回答：

1. 「Biome」「方块」「地形」是同一个东西吗？它们各自决定什么？
2. 「温度 / 湿度 / 大陆性 / 侵蚀度 / 怪异度」这五个参数视觉上分别决定什么？
3. 海平面是绝对 Y 坐标吗？为什么主世界 minY 是 -64？
4. 「含水层」「地表层」「基岩层」「雕刻洞」「噪声洞」这五个名词分别什么意思？
5. 「树」是 Block 还是 Feature？「村庄」是 Feature 还是 Structure？区别在哪？
6. 「ProtoChunk」和「LevelChunk」用一句话各自概括是什么。

## 3.1.1 Biome（生物群系）

**视觉**：你打开 Minecraft 进入主世界，环顾四周。会发现地表呈现**一片片有规律的"地区"**——一片绿草地（平原 plains）、一片白雪覆盖的针叶林（雪原 snowy_taiga）、一片黄沙起伏（沙漠 desert）、一片青绿色海面（暖海 warm_ocean）、一片黑松树林（深色森林 dark_forest）、一片漫天樱花（樱花林 cherry_grove，1.20+）⋯⋯ 等等。

每一种**「地区」就是一个 Biome（生物群系）**。Vanilla 1.21 共约 **70 种 biome**。

**关键概念**：Biome **不是地形几何**。地形高低（哪里是山、哪里是平原）由噪声决定；Biome **决定的是表面的"皮肤" + 行为参数**：

- **草色**：plains 是亮绿、savanna 是黄绿、swamp 是暗绿。
- **树叶色**：roofed_forest 暗绿、jungle 鲜绿、birch_forest 偏黄。
- **水色**：cold_ocean 深蓝、warm_ocean 浅青、swamp 浊绿。
- **雾 / 天空色**：基本每个 biome 不同。
- **下雨 / 下雪 / 不下**：温度高就下雨，低就下雪，沙漠不下。
- **环境粒子 / 音效**：sculk 区域有阴森粒子、深色森林有低吼。
- **能刷什么怪**：深色森林刷狼 + 流浪商人，丛林刷豹猫 + 鹦鹉，下界堡垒刷凋灵骷髅。
- **地表方块覆盖**：plains 是草方块 + 泥土，desert 是沙 + 沙石，snowy 是雪 + 草方块。
- **能生成什么 Feature**：plains 长橡树 + 草丛，taiga 长云杉，birch 长桦树，每种 biome 一份 PlacedFeature 列表。

**反过来 Biome 不决定**：

- 山脉走向 / 海拔高低 —— 噪声决定。
- 洞穴位置 —— Density Function + Carver 决定。
- 矿石分布 —— Feature + OreVeinifier 决定。
- 结构（村庄、要塞）位置 —— Structure 决定（虽然结构的可生成 biome 集合受 biome 控制）。

**心智模型**：噪声 + 密度函数决定**"哪里有岩石、哪里是空气"**；Biome 决定**"这片岩石上铺什么、长什么、有什么生物"**。两层正交。

## 3.1.2 五大气候参数（最重要）

**问题**：Mojang 怎么决定一个 (x, z) 坐标是什么 Biome？

**答案**：在每个 (x, z) 上**采样 5 个气候参数**，再加上一个**深度参数**（不是采样的，是从 Y 推导的），共 6 维。每个 Biome 在这 6 维空间里**占据一块超长方体区域**。给一个具体坐标 → 算出 6 维参数 → 找最近 biome。

**这就是 Multi-Noise Biome Source（多噪声生物群系采样器）**。1.18 引入，是当下 Minecraft 主世界长这样的核心设计。

下面五大气候参数视觉上分别决定什么：

### Temperature（温度）

范围 **-1.5 .. 1.5**，但实用区间约 -1.0 到 1.0。**越高越像沙漠 / 丛林、越低越像雪原 / 苔原**。

视觉影响：

- **低温**（< -0.4）：雪原、苔原、冰川、冰刺平原。雪盖 / 冰冻水。
- **中温**（-0.4 到 0.6）：温带——平原、森林、桦木林、白桦原始森林。
- **高温**（> 0.6）：沙漠、稀树草原、丛林、恶地。

**行为影响**：

- 决定**降水类型**：Temperature > 0.15 时 `hasPrecipitation()` 返回雨，否则雪。
- 决定**冰冻**：水方块在低温 biome 表面会自动结冰（运行时 random tick）。
- 决定**饱和度 / 农作物速度**：高温 biome 作物长得快但需要灌溉。

### Humidity（湿度）

范围 **-1.0 .. 1.0**。**越高越湿润 / 植被密集，越低越干燥**。

视觉影响：

- **高湿度**：丛林、沼泽、暗木森林、苔藓丛生洞穴。
- **中湿度**：森林、平原、桦木林。
- **低湿度**：沙漠、稀树草原、恶地、向日葵平原。

**注意湿度和温度独立**——可以高温低湿（沙漠）也可以高温高湿（丛林）也可以低温高湿（雪松林）。

### Continentalness（大陆性）

范围 **-1.2 .. 1.0**。**这是 1.18+ 引入的灵魂参数**——决定「这里是深海还是浅海还是海岸还是内陆山地」。

值的语义（粗略）：

| 区间 | 语义 |
|------|------|
| < -0.45 | **深海** mushroom_fields / deep_ocean |
| -0.45 .. -0.19 | **浅海** ocean / lukewarm_ocean |
| -0.19 .. -0.11 | **海岸** beach / stony_shore |
| -0.11 .. 0.03 | **近内陆** plains / forest 沿海版 |
| 0.03 .. 0.3 | **中内陆** taiga / forest |
| > 0.3 | **远内陆** mountain_meadow / windswept_hills / 高地 |

**视觉**：站在某点，从屏幕看到的"这里看起来是岸边还是远离海"——continentalness 的值从负往正递增对应"深海 → 海岸 → 内陆 → 山地"。

**这是为什么 1.18 的世界有连绵大陆 + 大型海洋的形态**——之前版本的 biome 边界过于碎片化、没有 continentalness 概念，所以"陆地与海洋交错"不明显。

### Erosion（侵蚀度）

范围 **-1.0 .. 1.0**。**决定地表的平滑度 / 起伏程度**。

值的语义：

| 值 | 视觉 |
|----|------|
| 高（> 0.5） | **平原 / 平地 / 高原顶平地**（侵蚀严重 = 起伏小）|
| 中（-0.2 .. 0.5） | **丘陵 / 缓坡** |
| 低（< -0.2） | **山峰 / 陡崖 / 锯齿山脊** |

注意命名反直觉——"侵蚀度高 = 表面平"。这是因为现实地理上侵蚀作用让山被磨平。Mojang 沿用了这个词。

**视觉**：站在山顶看远处。如果地形像揉皱的纸（一堆尖峰），erosion 低；如果地形像桌面（大片平整），erosion 高。

### Weirdness / PV（怪异度 / Peaks-Valleys）

范围 **-1.0 .. 1.0**。**控制"山脊形态"——是山顶（peak）、山坡（slope）、山谷（valley）还是平原**。

但 weirdness 不是直接用，而是**取绝对值再分段**。Mojang 内部把这个变换叫 "PV (Peaks & Valleys)"：

```
weirdness 输入 → PV 计算
weirdness ∈ (-1, -0.85)   → PV = "valleys"（深谷）
weirdness ∈ (-0.85, -0.20) → PV = "low slice"（低缓坡）
weirdness ∈ (-0.20, 0.20)  → PV = "mid slice"（普通）
weirdness ∈ (0.20, 0.85)   → PV = "high slice"（高坡）
weirdness ∈ (0.85, 1.0)    → PV = "peaks"（尖峰）
```

实际就是 |weirdness| 做分段查表。后面 3.5 节展开 spline 时会再展开。

**视觉**：weirdness 的低值给"山谷"形态（在 erosion 低 + continentalness 高地区），高值给"陡峭尖峰"，中值给普通缓坡。

### Depth（深度，导出）

不是噪声采样，而是**从 Y 坐标推导**：

```
depth = (preliminarySurfaceY - currentY) * scaleFactor
```

含义："当前位置距离地表向下多深"。海拔越深越正、地表 0 附近、海拔越高负值越大。

**用途**：让同一组其他 5 维参数下、地表 vs 地下能选不同 biome。这就是为什么 1.18 引入了**地下 biome**：dripstone_caves（钟乳石洞）、lush_caves（茂密洞穴）、deep_dark（深暗之域）。Y 在 -50 附近时 depth 较大，触发地下 biome 区域。

## 3.1.3 海平面 / 世界高度

**主世界**：

- **`min_y = -64`**：世界最底（基岩之下虚空）。
- **`max_y = 320`**（exclusive）：世界最高（虚空到这里）。
- **总高度 = 384 格**。
- **海平面 `seaLevel = 63`**：默认水位高度。海洋 biome 的水面就在这里。
- **基岩层**：Y ∈ [-64, -60) 是不可破基岩 + 一部分随机基岩（避免漏水到虚空）。

**为什么 minY 是 -64 而不是 0**？1.17 之前是 0..256，1.18 改造后扩成 -64..320，主要为了：

- 给地下 biome 更多空间（lush caves / dripstone caves 在原本 0..50 区间）。
- 让深岩层（deepslate，Y < 0）有"真深"的感觉。
- 让铁矿、铜矿、钻石矿的分布在新高度梯度上更合理。

**下界**：

- `min_y = 0`，`max_y = 256`。
- 顶部 Y > 128 实际是基岩天花板（玩家不能到达）。
- 没有海平面（或说"海平面" = 32，岩浆海高度）。

**末地**：

- `min_y = 0`，`max_y = 256`。
- 主岛 + 远岛分布在 Y ~ 60 附近。

**为什么这些参数重要**：worldgen 代码到处假设"Y < seaLevel 是水"、"Y < 0 是 deepslate"、"Y < -54 是基岩"。`LevelHeightAccessor` 接口提供 `getMinY / getMaxY / getHeight`，所有 worldgen 代码都按它工作。**永远不要硬编码 0 或 256**。

## 3.1.4 Aquifer（含水层）

**问题**：1.18 之前，主世界地下默认是 stone。洞穴里默认是 air。地下水只在地表湖泊、河流附近有。

**1.18 之后**：地下随机出现"局部水位"（aquifer，含水层）。洞穴顶到这个水位之间被水填满。

**视觉效果**：你挖矿挖到大型洞穴，里面**经常有湖**。有时湖很大，有时只是浅水洼。1.18 之前几乎没有这种地下湖。

**机制**：在 16×12×16 grid 上每格采样一个**「流体粒子」**：

```
fluidParticle = {
    fluidLevelY: int,      // 这个区域的"水位"在哪个 Y
    fluidType:   water/lava // 是水还是熔岩
}
```

给定一个具体方块位置 (x, y, z)：

- 找最近的 3 个 fluidParticle，加权计算最终水位。
- 如果 y < fluidLevelY 且当前位置是空气 → 填水（或熔岩）。
- 否则保持空气。

**注意 Aquifer 是生成期** 的概念，不是运行时流体。运行时水流（FlowingFluid）见 Module 6。Aquifer 一次性铺好水位，之后水就固定在那。

**Aquifer 也决定地下熔岩**——Y 接近 -54 附近的 aquifer 的 fluidType 是 lava，所以你深挖会遇到熔岩湖。

## 3.1.5 Surface 表面层 vs Stone Bed 基岩层

**视觉**：

- **平原**：地表是 1 格草方块、下面 3 格泥土、再下面是石头。
- **沙漠**：地表是几格沙、下面是沙石、再下面是石头。
- **雪原**：地表是 1 格雪覆盖、1 格雪覆盖的草方块、3 格泥土、石头。
- **海洋**：水底是几格沙 / 砾石、下面是石头。

**机制**：噪声只决定"这里是固体还是空气还是液体"。**"固体的最上面几格用什么方块"**由另一个系统决定——**SurfaceRules（地表规则）**。

**SurfaceRules** 是一组 if-else 规则，对每一格判断"这里要不要替换为别的方块"：

```
if (Y == surfaceY && biome == sand_biome) → set to sand
if (Y == surfaceY - 1..3 && biome == sand_biome) → set to sandstone
if (Y == surfaceY && biome == ice_biome && temperature < 0) → set to snow
...
```

详见 3.8 节。

**为什么需要 SurfaceRules 单独一层**？因为地形噪声是**与 biome 无关**的——同一个噪声场可以放在沙漠也可以放在森林。如果把"地表用什么方块"塞进噪声层，每加一种 biome 都要改噪声代码。SurfaceRules 让"形状" 与 "皮肤" 解耦。

## 3.1.6 Cave Carver vs Noise Cave

**两种洞穴在 Minecraft 里同时存在**，玩家通常不区分，但代码层完全不同。

### Cave Carver（雕刻洞）

经典款。从 1.0 到 1.16 一直是主流洞穴算法。

**形态**：

- **直管隧道**：~2-3 格半径的圆管，蛇形蜿蜒、偶尔分叉。
- **球形房间**：偶尔扩成 5-8 格直径的大房间。
- **峡谷**：很长很高的扁平洞——`CanyonWorldCarver` 生成。

**算法**：在 chunk 生成的 CARVERS 阶段（3.2 节讲流水线），从一个起点出发**递归扩展**——按方向 vector 走一段、扩成椭圆截面、可能分叉一次再继续。直到深度耗尽。

源码：`net.minecraft.world.level.levelgen.carver.WorldCarver` 子类。

### Noise Cave（噪声洞）

1.18 引入。直接用密度函数挖。

**形态**：

- **Cheese cave（奶酪洞）**：大块的不规则空腔，像奶酪上的洞。这是大型房间洞。
- **Spaghetti cave（意大利面洞）**：长条蛇形隧道，但不规则、不像 carver 那么"管子"。
- **Noodle cave（面条洞）**：极细的网状走廊。

**算法**：在 NOISE 阶段（不是 CARVERS！），密度函数计算每格的 finalDensity 时直接减一个"洞穴噪声"。如果 finalDensity 还是负 → 这格是空气。

**视觉差异**：Carver 洞看起来"光滑、有规则"——半径一致、形如管子。Noise 洞看起来"自然、无规则"——形状随噪声场变化，更像现实地理。

**两者协同**：1.18+ 的世界**两种洞同时打**——先 NOISE 阶段挖了 noise cave，然后 CARVERS 阶段又额外打 carver 隧道。所以你在 1.18+ 看到的洞穴是两套算法叠加的结果。

## 3.1.7 Feature / ConfiguredFeature / PlacedFeature

**Feature** 是"长一棵树 / 撒一片矿 / 摆一座湖"这种**地物**的代码模板。Vanilla 约 60 种 Feature 类。

但 Feature 自身不能直接用——它需要参数。所以 Mojang 三层包装：

### `Feature<C>`（算法）

- 抽象基类。子类如 `TreeFeature`、`OreFeature`、`LakeFeature`、`GeodeFeature`（紫水晶簇）。
- 一个 Feature 子类只定义"怎么长"，不管"长什么、长哪里"。
- 例：`TreeFeature` 知道"用树干放置器 + 树叶放置器 + 装饰器组装一棵树"，但不知道"放橡木还是云杉"。

### `ConfiguredFeature<C, F>`（算法 + 配置）

- 把 Feature 与具体 Configuration 配对。
- 例：`oak_tree` ConfiguredFeature = `TreeFeature` + `{trunkPlacer: oak_trunk_2_high, foliagePlacer: blob_radius_2, decorators: [bee_hive_5%]}`。
- 这是 datapack 配方的"模板层"——`data/minecraft/worldgen/configured_feature/oak_tree.json`。

### `PlacedFeature`（配置 + 放置规则）

- ConfiguredFeature + 一组 PlacementModifier（"在哪里放、放多少"的规则）。
- 例：`oak_tree_placed` = `oak_tree` + `[count_random(20%), in_square, heightmap_motion_blocking, biome_filter]`。
- 这是真正"被 worldgen 调用"的对象。`data/minecraft/worldgen/placed_feature/`。

**类比**：

- Feature = "蛋糕的食谱"（怎么做）。
- ConfiguredFeature = "巧克力蛋糕的食谱"（具体什么 flavor）。
- PlacedFeature = "周一晚 7 点在 1 号烤箱做 5 个巧克力蛋糕"（具体什么时候哪里）。

**Biome 引用 PlacedFeature**：每个 biome 的 `BiomeGenerationSettings` 里列出"我要在哪几个 GenerationStep 放哪些 PlacedFeature"（10 个 step，下面 3.11 讲）。

## 3.1.8 Structure / StructureSet / StructureTemplate

Feature 处理"小型地物"（一棵树、一个矿簇、一个紫水晶）。**Structure** 处理"大型多区块建筑"（村庄、要塞、远古城市、海底神殿、堡垒、林地府邸）。

### `Structure`（结构种类）

- 抽象基类。子类如 `JigsawStructure`（村庄、要塞、海底神殿）、`StrongholdStructure`、`OceanMonumentStructure`。
- 决定"这种结构的整体规则"——能在哪些 biome 生成、最大深度、组装算法。

### `StructureSet`（结构组）

- 一组 Structure + 它们的**放置策略**（grid spacing、salt、随机偏移）。
- 例：`villages` StructureSet = `[village_plains, village_desert, village_savanna, village_taiga, village_snowy]`。每 32 chunk 选 1 个起点；起点上根据 biome 选 set 里哪个具体 village 类型。
- 用 `StructurePlacement` 决定 grid（`RandomSpread` / `ConcentricRings`）。要塞用 ConcentricRings（围绕原点同心圆 N 个）；其它通常用 RandomSpread。

### `StructurePiece`（结构片段）

- Structure 实例由多个 piece 组成。
- 一个村庄可能 30 个 piece：村中央广场 + 几条道路 + 5 个房子 + 1 个铁匠铺。
- 每个 piece 有自己的 `BoundingBox`（在世界中的 AABB）。

### `StructureTemplate`（结构模板）

- 以 NBT 形式存储的方块阵列。`.nbt` 文件，加载自 `data/<ns>/structure/`。
- 包含：每格的 BlockState + BlockEntity NBT。
- 是 piece 的"砖块"——一个 piece 通常引用一个 template 加一些参数（旋转、镜像、processor）。

### `Jigsaw 系统`

- "Pool 化"的 piece 组装。
- `StructureTemplatePool` = 一组可互相替换的 piece 模板。
- 随机从 pool 选一个 piece、根据它的 jigsaw 方块连接下一段、递归限深度。
- 村庄、要塞、海底神殿都用这套。

后面 3.12 节展开。

**Structure vs Feature**：

- 大小：Feature 通常 ≤ 1 chunk；Structure 跨 5×5 chunk 起步。
- 决策时机：Feature 在 worldgen 流水线后期（FEATURES step）；Structure 在最早期（STRUCTURE_STARTS step）就预定起点位置，然后影响整个流水线（如 Beardifier 让地形对结构让位）。
- 数据驱动度：两者都 datapack 可配，但 Structure 的"BoundingBox 跨 chunk 写入"机制特别复杂。

## 3.1.9 ProtoChunk vs LevelChunk

这部分在第 1.5 节已经详细讲过。这里在 worldgen 上下文里重申。

### `ProtoChunk`（生成期 chunk）

- worldgen 流水线中的"半成品" chunk。
- 持有 `status` 字段（EMPTY / NOISE / SURFACE / ⋯ / FULL 之一）。
- 写入安全：worldgen 只通过 `setBlockState` 改它，不触发邻居更新、不广播给客户端。
- 多线程并行写：不同 chunk 的 worldgen 任务可在 worker pool 上并行（受 ChunkPyramid 依赖关系约束）。

### `LevelChunk`（运行期 chunk）

- 已 FULL 的 chunk。进入 ticking 主循环，参与 random tick / scheduled tick / 网络同步。
- 写入会触发邻居更新、会广播。
- 单线程（服务端 server thread）。

### worldgen 流水线的 ProtoChunk → LevelChunk 升级

最后一阶段（FULL）触发：

```
所有数据已就位（sections / heightmaps / structureStarts / blockEntities）
    ▼
new LevelChunk(serverLevel, protoChunk)（特殊升级构造，1.5.6 节看过）
    ▼
chunk 进入 ChunkSource，被加入 ticking 表
    ▼
玩家可以挖、可以放、tick 系统启动
```

## 3.1.11 一条具体例子串起来

让我们走一段"玩家走到 (200, 64, 300) 这个新区域"的全流程，验证你能否对号入座所有名词：

```
1. 客户端走过 chunk 边界 → ChunkMap 决定加载 chunk(12, 18)
   （200 >> 4 = 12, 300 >> 4 = 18.75 ≈ 18）
   
2. ChunkPyramid 看依赖：要让 chunk(12, 18) 进 FULL，需要它和周围邻居先到某些 status

3. ProtoChunk(12, 18) 创建，status = EMPTY

4. 推进到 STRUCTURE_STARTS：
   决定 chunk(12, 18) 是否是某个 Structure 的"起点"
   假设 villages StructureSet 的 grid 落到附近 chunk(11, 17)，但不在我们这 chunk
   → 无 structure start

5. 推进到 STRUCTURE_REFERENCES：
   附近 chunk(11, 17) 的 village BoundingBox 可能延伸进我们 chunk
   → 登记一个 reference

6. 推进到 BIOMES：
   对 chunk(12, 18) 内每个 4³ 体素，调 MultiNoiseBiomeSource.getBiome：
   - 算 (T, H, C, E, W, D) 6 维参数
   - 在 6 维空间最近邻找到 → 假设 biome = "minecraft:plains"

7. 推进到 NOISE：
   构造 NoiseChunk
   对每个 cell（4×8×4）的角点：
     - DensityFunction.compute → finalDensity
     - if finalDensity > 0 → 固体（stone）
     - 否则空气（如果在 aquifer 水位下 → 水）
     - 同时 OreVeinifier 决定铜/铁矿脉
   插值到每个 BlockState

8. 推进到 SURFACE：
   对 plains 应用 SurfaceRules：
     - if Y == heightmap.surface → set 草方块
     - if Y - 1..3 → 泥土
     - 否则保持 stone

9. 推进到 CARVERS：
   额外打几个 carver 隧道（与 noise cave 叠加）

10. 推进到 FEATURES：
    chunk(12, 18) 的 plains biome 列出 ~60 个 PlacedFeature
    按 10 个 GenerationStep 顺序处理：
     - LAKES：一个小水坑（30% 几率）
     - UNDERGROUND_ORES：随机散布煤矿、铁矿、铜矿
     - VEGETAL_DECORATION：长几棵橡树（5% / chunk 概率多次抽）
     - TOP_LAYER_MODIFICATION：可能加雪盖（plains 不加）
    Feature 可能跨 chunk 写入（一棵橡树枝叶溢出到 chunk(13, 18)）

11. 推进到 INITIALIZE_LIGHT → LIGHT：
    LightEngine 计算天光 / 方块光

12. 推进到 SPAWN：
    NaturalSpawner 按 plains 的 MobSpawnSettings 刷一些羊、牛、猪

13. 推进到 FULL：
    ProtoChunk → LevelChunk 升级
    chunk 进入 ticking
    
14. 玩家加载到、客户端收 ClientboundLevelChunkWithLightPacket、渲染上屏
```

每一步都涉及 3.1 这一节讲的某些名词。如果你能跟着这段把每个名词对号入座，本节就过关了。

## 3.1.13 一句话总结

地形生成的世界观是两层正交：**噪声 + DensityFunction 决定形状（哪里固体 / 空气 / 液体）**，**Biome 决定皮肤（草色 / 树种 / 刷怪）**；6 维气候参数（T/H/C/E/W/Depth）映射到 70 种 biome；Aquifer 给地下铺水位；SurfaceRules 给地表铺方块；Cave Carver + Noise Cave 协同打洞；Feature 长小地物，Structure 拼大建筑；ProtoChunk 走 12 阶段流水线最终升级为 LevelChunk 进入运行期。
