## 3.13.1 一次性刷怪 vs 周期刷怪

Minecraft 有两种"刷怪"机制：

### 1. **生成期刷怪**（chunk 第一次生成时）

新 chunk 的 SPAWN step 跑一次 `NaturalSpawner.spawnMobsForChunkGeneration` —— 在那个 chunk 里**一次性放下一批生物**（每 chunk ~5-15 只）。这就是为什么玩家走进从未到过的区域立刻能看到牛羊。

### 2. **运行期周期刷怪**（每 tick）

服务端每 tick 在每个 ServerLevel 调度：

- **NaturalSpawner.spawnForChunk**（每 chunk 每 tick 0-N 次刷怪尝试）。
- **PhantomSpawner**（夜里给睡眠不足的玩家刷幻翼）。
- **PatrolSpawner**（每隔 5000-25000 tick 在玩家附近刷劫掠者巡逻队）。
- **CatSpawner**（村庄里刷猫）。
- **VillageSiegeSpawner**（村庄遭僵尸围攻）。
- **WanderingTraderSpawner**（流浪商人）。

**这一节只讲生成期刷怪**——3.16 / Module 4 涉及运行期。

## 3.13.2 SPAWN step 在 ChunkPyramid 的位置

回顾 3.2.6：

```java
.step(SPAWN, s -> s
    .addRequirement(BIOMES, 1)
    .setTask(ChunkStatusTasks::generateSpawn))
```

**为什么 SPAWN 在 LIGHT 之后**：

- 刷怪需要光照值——夜晚怪物只在低光照刷、农场动物只在亮光刷。
- 如果光照还没算完，刷怪行为不一致。

**为什么需要 BIOMES（半径 1）**：

- 一些刷怪行为依赖周围 biome（比如某些 biome 对怪物有 spawn cost）。

**`ChunkStatusTasks.generateSpawn`**：

```java
public static CompletableFuture<ChunkAccess> generateSpawn(WorldGenContext ctx, ChunkStep step,
                                                            StaticCache2D<GenerationChunkHolder> cache, ChunkAccess chunk) {
    return CompletableFuture.supplyAsync(() -> {
        if (!SharedConstants.debugVoidTerrain(chunk.getPos())) {
            ServerLevel level = ctx.serverLevel();
            level.getChunkSource().getGenerator().spawnOriginalMobs(
                new WorldGenRegion(level, cache, step, chunk)
            );
        }
        return chunk;
    }, ctx.unpackTaskExecutor());
}
```

## 3.13.3 ChunkGenerator.spawnOriginalMobs

```java
public abstract void spawnOriginalMobs(WorldGenRegion region);
```

**抽象方法**——由具体 ChunkGenerator 实现。

### NoiseBasedChunkGenerator 主世界实现

```java
@Override
public void spawnOriginalMobs(WorldGenRegion region) {
    if (!this.settings.value().disableMobGeneration()) {
        ChunkPos chunkPos = region.getCenter();
        Holder<Biome> biome = region.getBiome(chunkPos.getWorldPosition().atY(region.getMaxBuildHeight() - 1));
        WorldgenRandom random = new WorldgenRandom(new LegacyRandomSource(RandomSupport.generateUniqueSeed()));
        random.setDecorationSeed(region.getSeed(), chunkPos.getMinBlockX(), chunkPos.getMinBlockZ());
        NaturalSpawner.spawnMobsForChunkGeneration(region, biome, chunkPos, random);
    }
}
```

- 以 chunk 中央 + 顶端 Y 位置的 biome 作为代表。
- 调 `NaturalSpawner.spawnMobsForChunkGeneration`。

### NetherChunkGenerator

下界**不在生成期刷怪**——下界 mob（僵尸猪、Ghast）只在运行期刷。`spawnOriginalMobs` 是空实现。

### EndChunkGenerator

末地也基本不在生成期刷——末地龙和末影人是特殊机制。

## 3.13.4 NaturalSpawner.spawnMobsForChunkGeneration

打开 `net.minecraft.world.level.NaturalSpawner`：

```java
public static void spawnMobsForChunkGeneration(ServerLevelAccessor level, Holder<Biome> biome, ChunkPos chunkPos, RandomSource random) {
    MobSpawnSettings spawnSettings = biome.value().getMobSettings();
    WeightedRandomList<MobSpawnSettings.SpawnerData> creatureSpawns = spawnSettings.getMobs(MobCategory.CREATURE);
    if (!creatureSpawns.isEmpty()) {
        int chunkMinX = chunkPos.getMinBlockX();
        int chunkMinZ = chunkPos.getMinBlockZ();
        
        while (random.nextFloat() < spawnSettings.getCreatureProbability()) {
            // 抽一个生物种类
            Optional<MobSpawnSettings.SpawnerData> spawnData = creatureSpawns.getRandom(random);
            if (spawnData.isEmpty()) continue;
            
            MobSpawnSettings.SpawnerData data = spawnData.get();
            int groupSize = data.minCount + random.nextInt(data.maxCount - data.minCount + 1);
            SpawnGroupData groupData = null;
            
            int gx = chunkMinX + random.nextInt(16);
            int gz = chunkMinZ + random.nextInt(16);
            int rx = gx, rz = gz;
            
            for (int i = 0; i < groupSize; i++) {
                boolean validPosFound = false;
                for (int attempt = 0; attempt < 4 && !validPosFound; attempt++) {
                    BlockPos spawnPos = getTopNonCollidingPos(level, data.type, rx, rz);
                    if (data.type.canSummon() && SpawnPlacements.isSpawnPositionOk(data.type, level, spawnPos)) {
                        float entityX = (float)spawnPos.getX() + 0.5F;
                        float entityZ = (float)spawnPos.getZ() + 0.5F;
                        if (level.noCollision(data.type.getSpawnAABB(entityX, spawnPos.getY(), entityZ))) {
                            // 放置生物
                            Entity entity = data.type.create(level.getLevel(), null, spawnPos, EntitySpawnReason.CHUNK_GENERATION, false, false);
                            if (entity == null) continue;
                            entity.moveTo(entityX, spawnPos.getY(), entityZ, random.nextFloat() * 360.0F, 0.0F);
                            if (entity instanceof Mob mob && mob.checkSpawnRules(level, EntitySpawnReason.CHUNK_GENERATION)) {
                                groupData = mob.finalizeSpawn(level, level.getCurrentDifficultyAt(mob.blockPosition()), EntitySpawnReason.CHUNK_GENERATION, groupData);
                                level.addFreshEntityWithPassengers(mob);
                                validPosFound = true;
                            }
                        }
                    }
                    rx += random.nextInt(5) - random.nextInt(5);
                    rz += random.nextInt(5) - random.nextInt(5);
                    while (rx < chunkMinX || rx >= chunkMinX + 16 || rz < chunkMinZ || rz >= chunkMinZ + 16) {
                        rx = gx + random.nextInt(5) - random.nextInt(5);
                        rz = gz + random.nextInt(5) - random.nextInt(5);
                    }
                }
            }
        }
    }
}
```

**算法**：

1. 取本 chunk biome 的 `MobSpawnSettings`。
2. 取 `MobCategory.CREATURE`（农场动物 + 中性生物）的刷怪表。
3. 用 `getCreatureProbability()` 决定刷几"群"——典型 0.1-0.3，意味着大部分 chunk 0 群、少数 1-2 群。
4. 每群：
   - 从刷怪表抽一种生物（按权重）。
   - 决定群大小（min..max）。
   - 在 chunk 内随机选起点。
   - 群内生物在起点 ±5 格散布。
   - 检查每个位置是否合法（getTopNonCollidingPos + canSummon + noCollision）。
   - 创建 Entity → addFreshEntityWithPassengers。

**只刷 CREATURE category 不刷 MONSTER**——因为 chunk 第一次生成时，玩家可能立刻看到。如果生成期就刷怪物，玩家进新区域会被一群苦力怕扑面。Mojang 选择"只刷一次性的友好动物"。怪物留给运行期周期刷怪——给玩家一定缓冲。

## 3.13.5 MobSpawnSettings：Biome 的刷怪表

```java
public class MobSpawnSettings {
    private final float creatureProbability;
    private final Map<MobCategory, WeightedRandomList<SpawnerData>> spawners;
    private final Map<EntityType<?>, MobSpawnCost> mobSpawnCosts;
    
    public static class SpawnerData {
        public final EntityType<?> type;
        public final int weight;        // 在 category 内的权重
        public final int minCount;
        public final int maxCount;
    }
    
    public static record MobSpawnCost(double energyBudget, double charge) {}
}
```

**主要字段**：

- `creatureProbability`：每群抽出概率（默认 0.1，平原 0.13 等）。
- `spawners`：每个 MobCategory 的刷怪表（MONSTER / CREATURE / AMBIENT / WATER_CREATURE / WATER_AMBIENT / UNDERGROUND_WATER_CREATURE / AXOLOTLS）。
- `mobSpawnCosts`：每种 entity 的刷怪 "cost"（防止过度刷怪）。

## 3.13.6 SpawnPlacements：每种 Entity 的"在哪能刷"

```java
public class SpawnPlacements {
    public static final Map<EntityType<?>, Data> DATA_BY_TYPE = ...;
    
    public static Data getPlacementType(EntityType<?> type) { return DATA_BY_TYPE.get(type); }
    
    public record Data(SpawnPlacementType placementType, Heightmap.Types heightmap, SpawnPredicate<?> predicate) {}
}

public enum SpawnPlacementType {
    NO_RESTRICTIONS,       // 任意位置（蝙蝠）
    IN_WATER,              // 水里（鱼）
    IN_LAVA,               // 熔岩里（岩浆怪）
    ON_GROUND;             // 在地面上（多数生物）
}
```

**`SpawnPredicate`** 是生物特定的可刷条件函数。例：

- 牛：必须在亮光（光照 ≥ 7）+ 草方块上 + 主世界。
- 苦力怕：必须在暗光（光照 ≤ 7）+ 不在玩家 spawn 点 24 格内 + 主世界。
- 末影人：可在任意光照，但 Y > 0 + 不在水里 + 主世界 / 末地。
- 阳光僵尸：需要 Y 较低 + sky light 算入光照判断。

**`getTopNonCollidingPos(level, EntityType, x, z)`**：根据生物 PlacementType 找合适 Y：

- ON_GROUND：从 heightmap 取地表，往下找第一个固体上的格子。
- IN_WATER：找水柱中第一个非空气位置。
- ⋯

## 3.13.7 运行期 spawner（简介）

虽然本节聚焦生成期，给个对比。

### `PhantomSpawner`

```java
public class PhantomSpawner implements CustomSpawner {
    private int nextTick;
    
    @Override
    public int tick(ServerLevel level, boolean spawnHostiles, boolean spawnPassives) {
        if (--this.nextTick > 0) return 0;
        this.nextTick = 60;     // 每 60 tick 检查一次
        if (!level.dimensionType().hasSkyLight() || !spawnHostiles) return 0;
        if (level.getDifficulty() == Difficulty.PEACEFUL) return 0;
        // ⋯
        // 对每个玩家：
        //   - 如果距上次睡眠 ≥ 3 分钟且天黑：1/<lastTimeSinceSleep> 概率刷 1-3 只 phantom
    }
}
```

### `PatrolSpawner`

每 5000-25000 tick 选一个玩家附近的 chunk，刷一只 illager_patrol（劫掠者巡逻队）。

每个 PatrolSpawner / PhantomSpawner 等都实现 `CustomSpawner` 接口，由 `ServerLevel.tickCustomSpawners` 调度。

详见 Module 4 / 第 4 部分。

## 3.13.8 SpawnFinder：玩家初始 spawn 寻找

`Climate.SpawnFinder`（在 `Climate.java`）：

```java
public static class SpawnFinder {
    Climate.SpawnFinder.Result result;
    
    SpawnFinder(List<Climate.ParameterPoint> targets, Climate.Sampler sampler) {
        this.result = getSpawnPositionAndFitness(targets, sampler, 0, 0);
        // 在原点附近螺旋搜索更好的位置
        this.radialSearch(targets, sampler, 2048.0F, 512.0F);
        this.radialSearch(targets, sampler, 512.0F, 32.0F);
    }
}
```

游戏开始 / 玩家死亡后重生时找 spawn 位置：在原点周围螺旋搜索"6 维气候参数最贴近 ParameterList 中目标点"的位置。

`ParameterList.spawnTarget` 列出 vanilla 偏好的 spawn 区域参数（典型：温度中等、湿度中等、近海岸、erosion 中等）。

## 3.13.9 性能

```
单 chunk SPAWN 阶段:
- 每群刷怪：~5-50 次位置检查 + 10-30 次 spawnRules 查询
- 平均 0-3 群：~5-20 ms / chunk

主世界刷怪密度：~1-3 只生物 / chunk（含 0 只）。
```

worldgen 总时间中 SPAWN 阶段占比 ~5-10%。

## 3.13.11 C++ 移植

```cpp
namespace mc::spawning {

struct SpawnerData {
    EntityType* type;
    int weight;
    int minCount;
    int maxCount;
};

struct MobSpawnSettings {
    float creatureProbability;
    std::map<MobCategory, std::vector<SpawnerData>> spawners;
    std::map<EntityType*, MobSpawnCost> mobSpawnCosts;
    
    const std::vector<SpawnerData>& getMobs(MobCategory cat) const;
};

class NaturalSpawner {
public:
    static void spawnMobsForChunkGeneration(
        WorldGenLevel& level,
        Holder<Biome> biome,
        ChunkPos chunkPos,
        RandomSource& random
    );
};

class CustomSpawner {
public:
    virtual ~CustomSpawner() = default;
    virtual int tick(ServerLevel& level, bool spawnHostiles, bool spawnPassives) = 0;
};

class PhantomSpawner : public CustomSpawner { ... };
class PatrolSpawner : public CustomSpawner { ... };
class CatSpawner : public CustomSpawner { ... };
// ⋯

}
```

**关键工程选择**：

1. **MobSpawnSettings 持有 Biome 的 spawn 表** —— 通过 BiomeJSON codec 解析。
2. **WeightedRandomList** —— 按权重抽样的工具。简单实现。
3. **SpawnPlacements 是个全局 hardcoded 表**—— 每种 Entity 注册时填进去。
4. **生成期 vs 运行期** 严格分离：生成期只刷 CREATURE，运行期刷其他。

## 3.13.12 一句话总结

SPAWN step 在 LIGHT 之后执行 `NaturalSpawner.spawnMobsForChunkGeneration` —— 每 chunk 按 biome 的 `creatureProbability` 概率刷 0-N 群"友好生物" + 群大小 4-6；只刷 CREATURE category 不刷 MONSTER（避免玩家进新区域被怪物扑面）；`SpawnPlacements` 决定每种 Entity 在哪能刷（ON_GROUND / IN_WATER / IN_LAVA / NO_RESTRICTIONS）+ 一个 SpawnPredicate 函数（光照 / 高度 / 距离玩家 spawn）；运行期周期 spawner（PhantomSpawner / PatrolSpawner / WanderingTraderSpawner ⋯）通过 `CustomSpawner` 接口接入 `ServerLevel.tickCustomSpawners`；下界、末地的 spawnOriginalMobs 是 noop——它们只在运行期刷。
