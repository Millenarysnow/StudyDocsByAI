## 3.16.2 性能 profile

每 step 在主世界单 chunk 的典型时间（5950X 单线程）：

| Step | 时间 | 占比 | 性质 |
|------|------|------|------|
| EMPTY | 0 | 0% | noop |
| STRUCTURE_STARTS | ~5 ms | 2% | 大部分 chunk 不命中 |
| STRUCTURE_REFERENCES | ~2 ms | 1% | 扫邻居 |
| BIOMES | ~3 ms | 1% | 4³ × 24 R-Tree 查询 |
| **NOISE** | **~80 ms** | **40%** | DensityFunction + Aquifer + OreVeinifier |
| SURFACE | ~10 ms | 5% | 列扫描 + 规则 |
| CARVERS | ~10 ms | 5% | 邻居扫描 + 椭圆 |
| **FEATURES** | **~80 ms** | **40%** | 树 / 矿 / 结构部署 |
| INITIALIZE_LIGHT | 1 ms | <1% | |
| LIGHT | ~5 ms | 2% | 光照传播 |
| SPAWN | ~3 ms | 1% | 一次性刷怪 |
| FULL | <1 ms | <1% | 升级 |
| **总** | **~200 ms** | 100% | |

**两个最贵的 step**：NOISE 和 FEATURES，各占 40%。

**优化机会**：

- NOISE：cache 节点（Interpolated / Cache2D / FlatCache）已经做满。能进一步优化的是**DensityFunction 求值的 SIMD / GPU 加速**。
- FEATURES：树木 / 结构 piece 用模板渲染，I/O bound 部分可以并行。

## 3.16.3 并行策略

ChunkPyramid 的并行结构：

- **同 status 不同 chunk**：可并行（worker pool）。
- **同 chunk 不同 status**：严格串行。
- **同 chunk 同 status 内部**：通常串行（除非该 step 的 task 自己 spawn 子任务）。

`Util.backgroundExecutor()` 通常 4-8 线程。视距 32 chunk 的服务端**同时跑 ~10-20 个 chunk** 的 worldgen 是常态。

## 3.16.7 工程化建议

### 1. 测试驱动

每个子模块都对照 Java 实现 bitwise 测试。**不要先全部实现再测**——一处 bug 会向下游 chain 难以定位。

参考 Cubitect 的 cubiomes 项目（github.com/Cubitect/cubiomes）—— C 语言的 vanilla biome / noise 复刻，**它的 source 是绝佳的参考实现**。

### 2. SIMD 优化（中后期）

NOISE 阶段的 cell 角点求值是热点。AVX2 一次 4 double：

- ImprovedNoise.noise 内部的 grad / lerp 全部能 SIMD。
- 5×49 = 245 角点的 finalDensity 树并行求值。
- 期望 4-8× 加速。

### 3. GPU 计算（更进一步）

Density Function 可以编译成 SPIR-V 或 HLSL compute shader：

- 整个 chunk 的 cell 角点（768 个）一次 dispatch。
- 期望 50-100× 加速。

但工程复杂度上升 5-10×。**建议第一版不考虑**。

### 4. datapack JSON 加载

第一版可以**硬编码**主世界配方（Java 翻译为 C++）。datapack JSON 加载是后续 modder 友好性。

### 5. 跨 chunk 写入测试用例

写一个集成测试：`worldSeed=1` 在 chunk 边界长一棵橡树，验证：

- 树心 chunk 含树干 + 部分叶子。
- 邻居 chunk 含其他叶子。
- 两 chunk 都升级到 FULL 后，整棵树视觉完整。

## 3.16.10 一句话总结

第 3 部分讲清楚了 Mojang 的"凭空造世界"全流程——12 阶段 ChunkPyramid 流水线把 ProtoChunk 从 EMPTY 推到 FULL；ChunkStep + WorldGenRegion + postProcessing 三层保证跨 chunk 写入安全；Xoroshiro128++ + PositionalRandomFactory 保证种子完全决定世界；ImprovedNoise + PerlinNoise + NormalNoise 提供 50+ 噪声实例；DensityFunction DSL 30+ 算子组成 NoiseRouter 15 通道，配合 Interpolated/Cache 优化让 NOISE step 单 chunk 80 ms；Climate 6 维参数 + R-Tree + OverworldBiomeBuilder 5000 行硬编码决定 70 个 biome 分布；SurfaceRules DSL 20+ condition + 4 类 rule 把 stone 世界改成"草沙雪"；Aquifer 16×12×16 流体粒子让 1.18+ 洞穴有水；Carvers 与 noise cave 协同打洞；Feature 三层包装 + 11 个 GenerationStep 长树撒矿；Structure + Jigsaw + Beardifier 部署村庄要塞；末地用专用 EndIslands 算子。所有这些数据驱动 datapack 配置，C++ 移植蓝图明确，工程量可控。
