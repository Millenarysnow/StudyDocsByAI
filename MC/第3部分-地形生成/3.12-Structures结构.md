## 3.12.1 Structure 与 Feature 的核心差异

| 特征 | Feature | Structure |
|------|---------|-----------|
| 大小 | ≤ 1 chunk | 跨 5×5 - 32×32 chunk |
| 决策时机 | FEATURES step（晚） | STRUCTURE_STARTS step（最早） |
| 数据结构 | 直接放 BlockState | 由 Piece 组成树 |
| 跨 chunk 写入 | 通过 blockStateWriteRadius=1 | 通过 StructureReference + BoundingBox 分发 |
| 影响地形 | 无（在地形之上覆盖） | 通过 Beardifier 影响 finalDensity |
| 持久化 | 无（重生成保持一致） | StructureStart 持久化到 chunk NBT |
| 数据驱动度 | 完全 datapack | datapack + 有时 Java 硬编码 |

**最关键差异**：Feature 是"瞬时的"——FEATURES step 跑完就完成。Structure 是"分布式的"——一个结构跨多 chunk，每个 chunk 各自的 FEATURES step 中**只生成它内部的部分**。

## 3.12.3 完整时序：村庄从决定到生成

### Step 1: STRUCTURE_STARTS 阶段

```java
// ChunkStatusTasks.generateStructureStarts:
public static CompletableFuture<ChunkAccess> generateStructureStarts(...) {
    return CompletableFuture.supplyAsync(() -> {
        ChunkPos chunkPos = chunk.getPos();
        StructureManager structureManager = ctx.serverLevel().structureManager();
        ChunkGeneratorStructureState gss = ctx.serverLevel().getChunkSource().getGeneratorState();
        
        for (Structure structure : registry.iterable()) {
            // 看本 chunk 是不是该 structure 的起点
            for (StructureSet set : structureSetsContaining(structure)) {
                if (set.placement().isStructureChunk(gss, chunkPos.x, chunkPos.z)) {
                    // 是！开始组装结构
                    GenerationContext genCtx = new GenerationContext(...);
                    Optional<Structure.GenerationStub> stub = structure.findGenerationPoint(genCtx);
                    if (stub.isPresent()) {
                        StructureStart start = new StructureStart(structure, chunkPos, stub.get().generator().build());
                        chunk.setStartForStructure(structure, start);
                    }
                }
            }
        }
        return chunk;
    });
}
```

**`isStructureChunk`** 用 grid + 噪声 + salt 决定"本 chunk 是不是某个 structure 的起点"。**确定性**：同 worldSeed → 同起点位置。

**`findGenerationPoint`** 是结构的"组装入口"——决定 piece 列表。

### Step 2: STRUCTURE_REFERENCES 阶段

```java
public static CompletableFuture<ChunkAccess> generateStructureReferences(...) {
    int radius = 8;     // ChunkStatus.MAX_STRUCTURE_DISTANCE
    for (int dx = -radius; dx <= radius; dx++) {
        for (int dz = -radius; dz <= radius; dz++) {
            ChunkAccess neighbor = cache.get(chunkPos.x + dx, chunkPos.z + dz);
            if (neighbor == null) continue;
            for (Map.Entry<Structure, StructureStart> entry : neighbor.getAllStarts().entrySet()) {
                StructureStart start = entry.getValue();
                if (start.isValid() && start.getBoundingBox().intersectsChunk(chunkPos)) {
                    // 这个邻居的 structure BoundingBox 触及本 chunk → 注册引用
                    chunk.addReferenceForStructure(entry.getKey(), neighbor.getPos().toLong());
                }
            }
        }
    }
    return chunk;
}
```

**结果**：每个 chunk 知道"我被哪些远处 chunk 的 structure 触及"。这是 chunk 生成自己内容时的查询起点。

### Step 3: FEATURES 阶段（结构 piece 部署）

回顾 3.11.3 的 `applyBiomeDecoration`：

```java
for (int step = 0; step < GenerationStep.Decoration.values().length; step++) {
    // 1. 处理结构（在该 step 注册的）
    for (Structure structure : structuresByStep.get(step)) {
        random.setFeatureSeed(decorationSeed, featureIdx, step);
        // 拿到本 chunk 内的所有该 structure 的 references
        // 对每个 reference：找到 StructureStart，调 placeInChunk
        structureManager.startsForStructure(sectionPos, structure)
            .forEach(start -> start.placeInChunk(level, structureManager, gen, random, chunkBoundingBox, chunkPos));
    }
    // 2. 处理普通 PlacedFeature
    // ...
}
```

**`StructureStart.placeInChunk`**：

```java
public void placeInChunk(WorldGenLevel level, StructureManager structureManager, ChunkGenerator gen,
                         RandomSource random, BoundingBox chunkBox, ChunkPos chunkPos) {
    for (StructurePiece piece : this.pieceContainer.pieces()) {
        if (piece.getBoundingBox().intersects(chunkBox)) {
            piece.postProcess(level, structureManager, gen, random, chunkBox, chunkPos, ...);
        }
    }
}
```

**关键：`piece.getBoundingBox().intersects(chunkBox)`**——只生成 piece 在当前 chunk 内的部分。其他 chunk 的 FEATURES 阶段会各自生成它们的部分。

每个 `piece.postProcess` 内部调 `StructureTemplate.placeInWorld(...)` 把模板方块写到 chunk。

## 3.12.4 Jigsaw 拼接系统

村庄、要塞、海底神殿、堡垒废墟、远古城市——它们都用 **Jigsaw** 系统组装。

### `StructureTemplatePool`

```java
public record StructureTemplatePool(
    Holder<StructureTemplatePool> fallback,
    List<Pair<StructurePoolElement, Integer>> rawTemplates
) {
    public StructurePoolElement getRandomTemplate(RandomSource random) { ... }
}
```

**Pool 是一组等价 piece**。例：`village/plains/houses` pool 含：

- house_small_1.nbt
- house_small_2.nbt
- house_medium_1.nbt
- ⋯ 共约 30 个房屋模板。

每个 entry 有权重——某些模板更常见。

### 拼接算法

```java
public class JigsawPlacement {
    public static Optional<StructurePoolGenerator> addPieces(
        Structure.GenerationContext ctx,
        Holder<StructureTemplatePool> startPool,
        Optional<ResourceLocation> startJigsawName,
        int maxDepth,
        BlockPos startPos,
        boolean useExpansionHack,
        Optional<Heightmap.Types> heightmapTypes,
        int verticalOffset,
        PoolAliasLookup poolAliasLookup,
        DimensionPadding dimensionPadding
    ) {
        // 1. 从 startPool 抽一个 piece
        // 2. 把它放在 startPos
        // 3. 找 piece 的 jigsaw 方块（连接点）
        // 4. 对每个 jigsaw 方块：
        //    - 查它指向哪个 pool（`target` 字段）
        //    - 从那 pool 抽一个新 piece
        //    - 把新 piece 旋转 / 位置对齐到 jigsaw 方块
        //    - 检查新 piece 的 BoundingBox 不冲突
        //    - 递归扩展新 piece 的 jigsaw 方块（直到 maxDepth）
    }
}
```

**Jigsaw 方块**：模板里特殊的方块——`minecraft:jigsaw{name=..., target=..., pool=..., final_state=...}`。

- `name`：本 jigsaw 的标识。
- `target`：哪种类型的 jigsaw 能接到我（`pool` 必须含 `name=target` 的 piece）。
- `pool`：连接哪个 pool。
- `final_state`：拼接完成后这格变成什么方块（通常是空气、cobblestone）。

**视觉**：村庄房屋之间有 path（道路）连起来——道路 piece 的 jigsaw target 是 "house"，所以会去 houses pool 抽个房子接上。

### maxDepth

`maxDepth` 限制递归深度，防止无限扩展。村庄典型 maxDepth = 6（从中央到外缘 6 步）。要塞 maxDepth = 50（深邃地下迷宫）。

### Jigsaw 的优雅之处

完全 datapack 化：**不写一行 Java，能定义一种新结构**。改 pool 的成员可以让村庄的房子都变成沙漠 huts；改 jigsaw 连接关系可以做出"圆形村"、"星形村"⋯⋯

## 3.12.5 Strongholds：同心圆放置

要塞用**特殊放置**——`ConcentricRingsStructurePlacement`：

```java
public class ConcentricRingsStructurePlacement extends StructurePlacement {
    private final int distance;        // 中心距 (1408 chunks ≈ 22528 blocks)
    private final int spread;          // 环宽
    private final int count;            // 要塞总数 (128)
    private final HolderSet<Biome> preferredBiomes;
}
```

**算法**：把世界分成 N 个同心圆环（ring），每环 `count_per_ring` 个要塞。每要塞在环上以等角度间隔分布，再加 RNG 偏移。

**结果**：

- 要塞 1 在距原点 1408-2688 chunks（环 1）。
- 要塞 N+1 在距原点 ~5000 chunks（环 2）。
- 共 128 个要塞。

**这是为什么 Eye of Ender（末影之眼）能"指向最近要塞"**——客户端代码知道这套同心圆规则，能算出 ring 内最近要塞位置。

                    }
                }
            }
        }
        return new Beardifier(rigidPieces, junctions);
    }
    
    @Override
    public double compute(FunctionContext ctx) {
        // 对当前位置 (x, y, z)，计算所有 rigid piece + junction 的 beard 加成
        // ⋯
    }
}
```

**"Beard" 这个名字的来源**：每个 piece 周围有一圈"胡须"——上面是负向（让地形变空气）、下面是正向（让地形变固体）。视觉上像给 piece 周围加了一圈"地形腮"——所以叫 beard。

## 3.12.9 性能

```
单 chunk STRUCTURE_STARTS 阶段:
- 对每种 StructureSet（vanilla ~30 个）
  - placement.isStructureChunk(...): 几次 noise 查询
  - 命中：调用 findGenerationPoint：JigsawPlacement.addPieces 递归扩展
    - 每 piece：找 jigsaw 方块、抽 pool 元素、检查冲突 → ~1-5 ms
    - 总 piece 数：5-300 个
  - 总：~10-100 ms（命中时）
- 大部分 chunk 不命中 → ~1 ms
```

```
单 chunk FEATURES 阶段中的结构部署:
- 本 chunk references 的所有结构
- 每个结构：扫所有 piece → intersect 本 chunk box → postProcess
- 每个 piece：StructureTemplate.placeInWorld(...) 写方块
- 总：~5-50 ms
```

结构生成不是 worldgen 性能瓶颈（只占总时间 5-15%）。

## 3.12.10 内存预算

```
StructureStart per chunk: ~几十字节 + pieces 列表
PiecesContainer: ~每 piece 100-500 字节 × ~10-300 pieces/structure ≈ 1-150 KB

主世界 chunk 含 0-2 个 structure 起点是常态。

StructureTemplate 共享（按 ResourceLocation 加载到内存）：
~几百个模板 × ~1-10 KB / 模板 ≈ 几 MB（共享）

StructureCheck 缓存：~几百 KB
```

```

**关键工程选择**：

1. **Jigsaw 算法 1:1 复刻**：递归 piece 扩展、boundingbox 冲突检测、jigsaw 方块识别。复杂但**可移植**。
2. **StructureTemplate NBT 加载**：用第 2 部分的 NBT 库（已实现）。
3. **PiecesContainer 持久化**：StructureStart 通过 NBT 写盘。`SerializableChunkData.structureData` 字段持有它。
4. **Beardifier kernel** 同 3.6.7：static const 24³ 数组。

---

## 3.12.12 一句话总结

Structure 是大型多 chunk 建筑系统——`Structure` 抽象（~20 子类） + `StructureSet` 组合 + `StructurePlacement` 放置策略（RandomSpread / ConcentricRings）；STRUCTURE_STARTS 阶段决定起点 + 调用 `Structure.findGenerationPoint` 组装 PiecesContainer；STRUCTURE_REFERENCES 阶段把跨 chunk 引用注册；FEATURES 阶段每 chunk 各自部署它内含的 piece 部分；Jigsaw 系统用 StructureTemplatePool + Jigsaw 方块（target / pool）实现"村庄房屋之间用路连接"等递归拼接；Stronghold 用 ConcentricRings 放在距原点 1408+ chunks 的同心圆上；Beardifier 通过 24³ kernel 让地形对 piece 让位（避免房屋悬空 / 地面塞门）；StructureCheck 缓存减少重复 placement 判断；持久化到 chunk NBT（SerializableChunkData.structureData）。
