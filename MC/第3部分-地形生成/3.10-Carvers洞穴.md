## 3.10.1 直觉：管状洞穴的视觉

经典 Minecraft 洞穴（1.0 - 1.17 主流）的视觉特征：

- **半径 2-4 格的圆管**——蜿蜒蛇形。
- **偶尔球形房间**——5-8 格直径。
- **偶尔分叉**——一条隧道分成两条。
- **峡谷（canyon）**——长几百格、宽 2-4 格、高 30-50 格的"裂谷"。

这些都是 **carver**（雕刻器）算法产生的，而不是 noise 直接挖出。

## 3.10.2 WorldCarver 抽象

打开 `net.minecraft.world.level.levelgen.carver.WorldCarver`：

```java
public abstract class WorldCarver<C extends CarverConfiguration> {
    public static final WorldCarver<CaveCarverConfiguration> CAVE = register("cave", new CaveWorldCarver(CaveCarverConfiguration.CODEC));
    public static final WorldCarver<CaveCarverConfiguration> NETHER_CAVE = register("nether_cave", new NetherWorldCarver(CaveCarverConfiguration.CODEC));
    public static final WorldCarver<CanyonCarverConfiguration> CANYON = register("canyon", new CanyonWorldCarver(CanyonCarverConfiguration.CODEC));
    
    public abstract boolean carve(
        CarvingContext ctx,
        C config,
        ChunkAccess chunk,
        Function<BlockPos, Holder<Biome>> biomeAccessor,
        RandomSource random,
        Aquifer aquifer,
        ChunkPos chunkPos,
        CarvingMask mask
    );
    
    public abstract boolean isStartChunk(C config, RandomSource random);
}
```

**3 个内置 carver**：

- **`CaveWorldCarver`**：管状洞穴。主世界用。
- **`NetherWorldCarver`**：下界洞穴。
- **`CanyonWorldCarver`**：峡谷。

**关键 API**：

- `isStartChunk(config, random)`：本 chunk 是不是某个 carver 的"起点"？大部分 chunk 不是。
- `carve(ctx, config, chunk, ...)`：从这个起点出发**雕刻**——可能扩展到周围多个 chunk。

## 3.10.3 CaveWorldCarver 算法（伪码）

```java
@Override
public boolean carve(CarvingContext ctx, CaveCarverConfiguration config, ChunkAccess chunk, ...) {
    int caveCount = random.nextInt(random.nextInt(random.nextInt(15) + 1) + 1);
    
    for (int caveIdx = 0; caveIdx < caveCount; caveIdx++) {
        // 起点：在本 chunk 内随机选一个 (x, y, z)
        double startX = chunk.getMinBlockX() + random.nextInt(16);
        double startY = config.y.sample(random, ctx);     // 从配置中按高度分布采样
        double startZ = chunk.getMinBlockZ() + random.nextInt(16);
        
        int branches = 1;
        if (random.nextInt(4) == 0) {
            // 1/4 概率：球形房间
            float radius = config.horizontalRadiusMultiplier.sample(random) + 1.0F;
            this.carveSphere(ctx, config, chunk, biomeAccessor, aquifer,
                             startX, startY, startZ, radius, 0.5, ...);
            branches += random.nextInt(4);
        }
        
        for (int b = 0; b < branches; b++) {
            float yaw = random.nextFloat() * (float)Math.PI * 2.0F;     // 水平方向
            float pitch = (random.nextFloat() - 0.5F) / 4.0F;            // 垂直方向
            float thickness = config.thicknessFactor.sample(random) + ...;
            int caveLength = 100 + random.nextInt(150);
            
            this.carveTunnel(ctx, config, chunk, biomeAccessor, random.nextLong(),
                             aquifer, startX, startY, startZ,
                             config.horizontalRadiusMultiplier, config.verticalRadiusMultiplier,
                             thickness, yaw, pitch, 0, caveLength, ...);
        }
    }
    return true;
}
```

**关键步骤**：

1. **决定生成几个 cave 起点**：通常 1-15 个，但用 `nextInt(nextInt(...))` 让大部分 chunk 0-3 个，少数 chunk 5+ 个（**reservoir 分布**）。
2. **每个起点**：
   - 在 chunk 内选随机 (x, y, z)。
   - 1/4 概率先挖一个球形房间。
   - 选 1+ 条隧道方向（yaw + pitch）。
   - 对每条隧道调 `carveTunnel`。

### carveTunnel：隧道雕刻

```java
private void carveTunnel(
    CarvingContext ctx, CaveCarverConfiguration config, ChunkAccess chunk,
    Function<BlockPos, Holder<Biome>> biomeAccessor, long seed,
    Aquifer aquifer, double x, double y, double z,
    FloatProvider horizontalRadiusMultiplier, FloatProvider verticalRadiusMultiplier,
    float thickness, float yaw, float pitch,
    int currentLength, int maxLength, double horizontalVerticalRatio
) {
    RandomSource random = new XoroshiroRandomSource(seed);
    int branchPoint = random.nextInt(maxLength / 2) + maxLength / 4;
    boolean shouldBranch = random.nextInt(6) == 0;
    float yawDelta = 0.0F;
    float pitchDelta = 0.0F;
    
    for (int step = currentLength; step < maxLength; step++) {
        double horizRadius = 1.5 + Mth.sin(step * (float)Math.PI / maxLength) * thickness;
        double vertRadius = horizRadius * horizontalVerticalRatio;
        horizRadius *= horizontalRadiusMultiplier.sample(random);
        vertRadius *= verticalRadiusMultiplier.sample(random);
        
        // 沿当前方向走一步
        float xMov = Mth.cos(pitch);
        float yMov = Mth.sin(pitch);
        x += Mth.cos(yaw) * xMov;
        y += yMov;
        z += Mth.sin(yaw) * xMov;
        
        // 平滑变化方向（噪声扰动）
        pitch *= 0.7F;
        pitch += pitchDelta;
        yaw   += yawDelta;
        pitchDelta = pitchDelta * 0.9F + (random.nextFloat() - random.nextFloat()) * random.nextFloat() * 2.0F;
        yawDelta   = yawDelta   * 0.75F + (random.nextFloat() - random.nextFloat()) * random.nextFloat() * 4.0F;
        
        // 分叉
        if (!shouldBranch && step == branchPoint && thickness > 1.0F) {
            // 创建两条新隧道
            this.carveTunnel(ctx, config, chunk, ..., random.nextLong(), aquifer,
                             x, y, z, ..., random.nextFloat() * 0.5F + 0.5F,
                             yaw - (float)Math.PI / 2.0F, pitch / 3.0F,
                             step, maxLength, ...);
            this.carveTunnel(ctx, config, chunk, ..., random.nextLong(), aquifer,
                             x, y, z, ..., random.nextFloat() * 0.5F + 0.5F,
                             yaw + (float)Math.PI / 2.0F, pitch / 3.0F,
                             step, maxLength, ...);
            return;
        }
        
        // 在当前位置雕刻一个椭圆截面
        if (random.nextInt(4) != 0) {
            double distFromOrigin = MathHelper.distanceFromCenter(x, z, ...);
            if (distFromOrigin > maxLength - step + 18.0) return;     // 太远了，停
            if (x < ... || z < ...) return;     // 出了允许范围
            
            this.carveEllipsoid(ctx, config, chunk, biomeAccessor, aquifer,
                                x, y, z, horizRadius, vertRadius, ...);
        }
    }
}
```

**算法精髓**：

1. **方向平滑随机游走**：yaw（水平角）和 pitch（俯仰角）每步轻微扰动，让隧道蜿蜒。
2. **半径变化**：`thickness * sin(step / maxLength)` 让隧道在中段最粗、两端细。
3. **分叉**：`shouldBranch` 决定是否在中点分叉成两条。
4. **椭圆截面雕刻**：每步在当前 (x, y, z) 雕刻一个椭圆形。

### carveEllipsoid：单椭圆雕刻

```java
protected boolean carveEllipsoid(
    CarvingContext ctx, CaveCarverConfiguration config, ChunkAccess chunk,
    Function<BlockPos, Holder<Biome>> biomeAccessor, Aquifer aquifer,
    double x, double y, double z, double horizRadius, double vertRadius, ...
) {
    int xMin = Math.max(Mth.floor(x - horizRadius) - chunk.getPos().getMinBlockX() - 1, 0);
    int xMax = Math.min(Mth.floor(x + horizRadius) - chunk.getPos().getMinBlockX(), 15);
    int yMin = Math.max(Mth.floor(y - vertRadius) - 1, ctx.getMinGenY() + 1);
    int yMax = Math.min(Mth.floor(y + vertRadius) + 1, ctx.getMinGenY() + ctx.getGenDepth() - 8);
    int zMin = Math.max(Mth.floor(z - horizRadius) - chunk.getPos().getMinBlockZ() - 1, 0);
    int zMax = Math.min(Mth.floor(z + horizRadius) - chunk.getPos().getMinBlockZ(), 15);
    
    for (int localX = xMin; localX <= xMax; localX++) {
        int absX = chunk.getPos().getMinBlockX() + localX;
        for (int localZ = zMin; localZ <= zMax; localZ++) {
            int absZ = chunk.getPos().getMinBlockZ() + localZ;
            for (int absY = yMax; absY > yMin; absY--) {
                if (mask.get(localX, absY, localZ)) continue;     // 已雕刻过
                BlockPos pos = new BlockPos(absX, absY, absZ);
                
                if (canReach(x, y, z, absX, absY, absZ, horizRadius, vertRadius)) {
                    // 在椭圆内
                    if (this.shouldCarve(...)) {
                        // 替换为 cave_air 或 water（如果 aquifer 决定填水）
                        carveBlock(ctx, config, chunk, biomeAccessor, mask, pos, aquifer);
                    }
                }
            }
        }
    }
    return true;
}
```

**核心判定**：

```
((px-x)/horizRadius)² + ((py-y)/vertRadius)² + ((pz-z)/horizRadius)² ≤ 1
```

椭圆内的方块被替换为 air（或 water 如果在 aquifer 水位下）。

## 3.10.5 NetherWorldCarver：下界洞穴

下界用 `NetherWorldCarver`：

- 几乎与 CaveWorldCarver 同样算法。
- 区别：替换块是 air（不是 water），不查 aquifer。
- 替换前的判断改为"下界石 / 灵魂土 / 玄武岩可以替换"。

## 3.10.6 CarvingContext / CarvingMask

`CarvingContext`：carver 执行时的上下文。

```java
public class CarvingContext extends WorldGenerationContext {
    private final NoiseChunk noiseChunk;
    private final NoiseRouter router;
    
    public NoiseChunk noiseChunk() { return this.noiseChunk; }
    public DensityFunction barrierNoise() { return this.router.barrierNoise(); }
    public Optional<BlockState> topMaterial(BiomeAccessor biomeAccessor, BlockPos pos, boolean returnAir) { ... }
}
```

**`topMaterial`** 是 carver 知道"这格上面是不是地表"的接口——影响是否在洞口铺草 / 挖泥土等。

`CarvingMask`：

```java
public class CarvingMask {
    private final int minY;
    private final BitSet mask;     // 16×height×16 个 bit
    
    public boolean get(int x, int y, int z) { ... }
    public void set(int x, int y, int z) { ... }
}
```

**16×height×16 个 bit** 标记"哪些格已经被 carver 雕过"——避免重复雕刻、避免一个 chunk 被无限 carve。

## 3.10.7 ChunkPyramid 中的 CARVERS step

回顾 3.2.6：

```java
.step(CARVERS, s -> s
    .addRequirement(STRUCTURE_STARTS, 8)
    .blockStateWriteRadius(0)
    .setTask(ChunkStatusTasks::generateCarvers))
```

**特点**：

- `blockStateWriteRadius = 0`：carver **只写本 chunk**。但 `carveTunnel` 的 RNG seed 由"起点 chunk + 起点 chunk_local 坐标"决定——同一条隧道在它经过的所有 chunk 各自的 CARVERS step 中都会重新跑一遍**部分**算法（每 chunk 各自决定本 chunk 内被 carve 的部分）。
- `addRequirement(STRUCTURE_STARTS, 8)`：邻居 chunk 必须先到 STRUCTURE_STARTS（让 carver 知道附近是否有结构需要避开——比如不要打到要塞里）。

`ChunkStatusTasks.generateCarvers` 的简化：

```java
public static CompletableFuture<ChunkAccess> generateCarvers(WorldGenContext ctx, ChunkStep step,
                                                              StaticCache2D<GenerationChunkHolder> cache, ChunkAccess chunk) {
    return CompletableFuture.supplyAsync(() -> {
        ServerLevel level = ...;
        ChunkPos pos = chunk.getPos();
        BiomeManager biomeManager = level.getBiomeManager();
        ChunkGenerator gen = level.getChunkSource().getGenerator();
        
        // 对邻居 8x8 范围内每个 chunk
        for (int neighborX = pos.x - 8; neighborX <= pos.x + 8; neighborX++) {
            for (int neighborZ = pos.z - 8; neighborZ <= pos.z + 8; neighborZ++) {
                ChunkPos neighborPos = new ChunkPos(neighborX, neighborZ);
                
                // 看这邻居有没有 carver 起点会触及当前 chunk
                gen.applyCarvers(ctx.level(), ctx.options().worldOptions().seed(),
                                 randomState, biomeManager, structureManager,
                                 chunk, neighborPos, ...);
            }
        }
        return chunk;
    }, ctx.unpackTaskExecutor());
}
```

**注意**：carver 影响半径可能跨 8 chunk（因为长隧道可达几百格），所以扫邻居 17×17 范围。每个邻居"作为起点"对当前 chunk 调一次 carve—— carve 内部判断"如果当前椭圆 ≤ chunk 边界 → 雕刻 ; 否则跳过这块（其他 chunk 的 carver step 会负责雕）。

这就是为什么 carver 算法**需要确定性**：同一条隧道在不同 chunk 的 carver step 跑出的部分必须能完美拼接。靠 (起点 chunk 坐标 + worldSeed) 派生的种子保证。

## 3.10.8 与 noise cave 的协同

回顾 3.1.6：1.18+ 同时存在两种洞穴。

**执行顺序**：

1. **NOISE 阶段**（优先）：noise cave 已经被挖了（finalDensity 中包含 cave layer noise + spaghetti + cheese 等）。
2. **CARVERS 阶段**：在 noise cave 之上**额外打** carver tunnel / canyon。

**协同效果**：

- 大部分洞穴是 noise cave（不规则、自然形态）。
- 少数额外 carver 洞穴（规则的管状）。
- 两者在地下交错——玩家挖矿可能挖到一段 noise cave，沿着走遇到 carver tunnel，再穿到 noise cheese cave。**洞穴系统极其丰富**。

**1.17 之前**：只有 carver——洞穴看起来"工程化、规则"。

**1.18+**：两种叠加——洞穴看起来"自然有机"。

`CaveCarverConfiguration` 字段（datapack 可配）：

**Datapack 配置例**（`data/minecraft/worldgen/configured_carver/cave.json`）：

```json
{
    "type": "minecraft:cave",
    "config": {
        "probability": 0.15,
        "y": { "type": "minecraft:trapezoid", "min_inclusive": { "absolute": -58 }, "max_inclusive": { "absolute": 180 } },
        "yScale": 1.0,
        "lava_level": { "absolute": -54 },
        "horizontal_radius_multiplier": { "type": "minecraft:uniform", "value": { "min_inclusive": 0.7, "max_inclusive": 1.4 } },

        "replaceable": "#minecraft:overworld_carver_replaceables"
    }

```

**Modder 可以**：

- 改 `probability` 让洞更密 / 更稀。
- 改 Y 分布让洞主要出现在某高度。
- 改 horizontal/vertical_radius_multiplier 让洞更粗 / 更细。

## 3.10.10 Biome 关联

每个 biome 在 `BiomeGenerationSettings` 中列出"我支持哪些 carver"：

```java
public class BiomeGenerationSettings {
    private final Map<GenerationStep.Carving, HolderSet<ConfiguredWorldCarver<?>>> carvers;
    private final List<HolderSet<PlacedFeature>> features;

```

`GenerationStep.Carving` 是个 enum：

```java
public enum Carving {
    AIR,        // 雕成空气
    LIQUID      // 雕成液体（潜在）
}
```

**主世界几乎所有 biome 在 AIR 阶段都包含**：

- `minecraft:cave`（管洞）
- `minecraft:cave_extra_underground`（更深洞）
- `minecraft:canyon`（峡谷）

**沙漠 biome 还多一个 desert 专属洞**（虽然差异很小）。**The Nether**（下界）只用 `minecraft:nether_cave`。

## 3.10.11 性能

```
单个 chunk 的 CARVERS 阶段:
- 扫邻居 17×17 chunk 看哪些有 carver 起点
- 每个起点：~5-50 步隧道 × ~20 个椭圆方块 / 步 = ~1000 方块查询
- 扫椭圆内每方块 → CarvingMask check + Aquifer query + setBlock

总: ~5-10 ms / chunk（但 chunk 之间高度共享 carver 算法的状态——
  长隧道经过多个 chunk 时，每个 chunk 各自只跑那段相关计算）。
```

CARVERS 阶段是 worldgen 流水线里相对便宜的——比 NOISE / FEATURES 都低。

---

## 3.10.12 内存预算

`CarvingMask` 是 16×384×16 = ~98K bit ≈ 12 KB / chunk。chunk 升级到 FULL 时丢弃（不持久化到 NBT，因为 carver 是 deterministic + 跑一次就够了；但数据载体 SerializableChunkData.carvingMask 字段存它，给中途生成的 chunk 持久化）。

## 3.10.13 C++ 移植

```cpp
namespace mc::carver {

struct FluidPickerLike { /* same as Aquifer.FluidPicker */ };

class CarvingMask {
public:
    CarvingMask(int height, int minY) : height_(height), minY_(minY), bits_(16 * height * 16, false) {}
    bool get(int x, int y, int z) const { return bits_[index(x, y, z)]; }
    void set(int x, int y, int z) { bits_[index(x, y, z)] = true; }
private:
    std::vector<bool> bits_;
    int height_, minY_;
    int index(int x, int y, int z) const { return ((y - minY_) << 8) | (z << 4) | x; }
};

class WorldCarver {
public:
    virtual ~WorldCarver() = default;
    virtual bool carve(CarvingContext& ctx, const CarverConfiguration& config,
                       ChunkAccess& chunk, BiomeAccessor& biomeAccessor,
                       RandomSource& random, Aquifer& aquifer,
                       ChunkPos chunkPos, CarvingMask& mask) = 0;
};

class CaveWorldCarver : public WorldCarver {
public:
    bool carve(CarvingContext&, const CarverConfiguration&, ChunkAccess&, ..., 
               CarvingMask&) override {
        // 1. 决定 cave 起点数量（reservoir 分布）
        // 2. 对每个起点：
        //    - 生成 1+ 条 tunnel
        //    - 对每条 tunnel：调 carveTunnel（递归式平滑游走）
        //      - 每步 carveEllipsoid（椭圆雕刻）
    }
private:
    void carveTunnel(...);
    void carveEllipsoid(...);
};

class CanyonWorldCarver : public WorldCarver { ... };

}
```

**关键工程选择**：

1. **算法照搬**：carver 必须 1:1 与 vanilla 一致才能保证 reproducibility。**任何浮点运算细节差异都会让你的洞穴和 vanilla 的不一样**——种子分享文化破裂。
2. **`CarvingMask` 用 `std::vector<bool>` 还是 `boost::dynamic_bitset`**：后者更紧凑、有 `find_first` 等位操作，给后续优化用。
3. **椭圆判断用整数数学**：避免浮点累积误差。

## 3.10.14 一句话总结

Cave Carver 是经典管状洞穴雕刻——`CaveWorldCarver`（管洞）/ `NetherWorldCarver`（下界）/ `CanyonWorldCarver`（峡谷）三种；算法是"起点 → 平滑随机游走 → 每步在当前位置雕椭圆"，分叉概率约 1/6；雕刻时查 Aquifer 决定洞穴里是否填水；CARVERS 阶段在 ChunkPyramid 里位于 SURFACE 之后、FEATURES 之前，blockStateWriteRadius=0 但通过"邻居 17×17 chunk 各自负责一段"实现长隧道跨 chunk；与 noise cave 协同打出 1.18+ 的丰富洞穴系统；datapack 通过 ConfiguredWorldCarver 配置 probability / Y 分布 / 半径系数；性能 ~5-10 ms / chunk。
