## 3.3.1 直觉：为什么 worldgen 需要"按位置确定的随机"

回顾问题：玩家放置一棵树在 (1000, 64, 1000)，然后离开几个小时回来——那棵树还在原位。这是因为 chunk 已被持久化。

**但**：玩家从未到过的 (10000, 64, 10000) 没被生成过——服务器何时生成它？答案是"玩家走近时才生成"。

**关键问题**：两个不同时间生成的同一坐标 (10000, 64, 10000) **必须长得一样**。否则：

- 服务器跨重启会出现"地形变了"。
- 多人服务器不同节点生成同一区域结果可能不同。
- 玩家创造性同一种子探索两次得到不同地图——破坏种子分享文化。

**解法**：所有 worldgen 算法**完全确定性 + 仅依赖坐标 + worldSeed**。给定相同输入，必产生相同输出。

这是一个看似简单但实操困难的设计。下面看 Mojang 怎么做。

## 3.3.2 RandomSource 接口

`net.minecraft.util.RandomSource` 是 Minecraft 的随机数抽象基类：

```java
public interface RandomSource {
    static RandomSource create() { return create(RandomSupport.generateUniqueSeed()); }
    static RandomSource create(long seed) { return new LegacyRandomSource(seed); }

    RandomSource fork();
    PositionalRandomFactory forkPositional();

    void setSeed(long seed);
    int nextInt();
    int nextInt(int bound);
    long nextLong();
    boolean nextBoolean();
    float nextFloat();           // [0, 1)
    double nextDouble();         // [0, 1)
    double nextGaussian();       // 标准正态
    
    default void consumeCount(int count) {
        for (int i = 0; i < count; i++) this.nextInt();
    }
    default int nextInt(int min, int max) { return min + this.nextInt(max - min + 1); }
    // ⋯
}
```

**两个核心方法**：

- `fork()` —— 创建一个**子流**（child stream）。子流的种子由当前流的下一个 long 决定。用于"我想给某个子模块独立的随机流"。
- `forkPositional()` —— 创建一个 `PositionalRandomFactory`，从中可派生**按坐标确定的随机源**。下面 3.3.5 展开。

## 3.3.3 三种随机源实现

### `LegacyRandomSource`：兼容 java.util.Random

```java
public class LegacyRandomSource implements BitRandomSource {
    private final AtomicLong seed = new AtomicLong();
    private final MarsagliaPolarGaussian gaussianSource = new MarsagliaPolarGaussian(this);

    public LegacyRandomSource(long seed) { this.setSeed(seed); }

    @Override
    public void setSeed(long seed) {
        this.seed.set((seed ^ 25214903917L) & 281474976710655L);    // ★ 与 java.util.Random 完全一致
    }

    @Override
    public int next(int bits) {
        long oldSeed = this.seed.get();
        long newSeed = oldSeed * 25214903917L + 11L & 281474976710655L;
        this.seed.compareAndSet(oldSeed, newSeed);
        return (int)(newSeed >> 48 - bits);
    }
}
```

**LCG（线性同余生成器）** with 标准 java.util.Random 常量。**周期 2^48**。

**用途**：1.18 之前 worldgen 全用它。**1.18+ 仍保留**用于跨版本兼容（旧地图加载时仍要用 LCG 复现旧地形）。

**特性**：
- 速度极快。
- 周期 2^48 ≈ 2.8 × 10^14——大但不够大。
- 状态分布**有偏**：低位质量差。

### `XoroshiroRandomSource`：1.18+ 默认

```java
public class XoroshiroRandomSource implements RandomSource {
    private static final float FLOAT_UNIT = 5.9604645E-8F;    // 1.0f / (1 << 24)
    private static final double DOUBLE_UNIT = 1.110223E-16;    // 1.0d / (1L << 53)
    private final Xoroshiro128PlusPlus randomNumberGenerator;
    private final MarsagliaPolarGaussian gaussianSource;

    public XoroshiroRandomSource(long seed) {
        this(RandomSupport.upgradeSeedTo128bit(seed));
    }

    public XoroshiroRandomSource(RandomSupport.Seed128bit seed128) {
        this.randomNumberGenerator = new Xoroshiro128PlusPlus(seed128);
        this.gaussianSource = new MarsagliaPolarGaussian(this);
    }

    @Override
    public long nextLong() { return this.randomNumberGenerator.nextLong(); }
    // ⋯
}
```

底层是 **Xoroshiro128++**（详见 3.3.4）。**周期 2^128 - 1**。1.18+ 引入。

**特性**：

- 周期 2^128 ≈ 3.4 × 10^38——巨大，实际上无限。
- 状态分布**无偏**（通过 BigCrush 测试）。
- 速度比 LCG 略慢，但 5x 比 java.util.Random.SplittableRandom 快。

### `ThreadSafeLegacyRandomSource`：原子访问的 LCG

```java
public class ThreadSafeLegacyRandomSource implements BitRandomSource {
    // Same algo as LegacyRandomSource, 但 setSeed/next 用 AtomicLong CAS
}
```

**用途**：极少。仅在某些罕见的并发 worldgen 场景。

## 3.3.4 Xoroshiro128++ 算法

打开 `net.minecraft.world.level.levelgen.Xoroshiro128PlusPlus`：

```java
public class Xoroshiro128PlusPlus {
    private long seedLo;
    private long seedHi;

    public Xoroshiro128PlusPlus(long seedLo, long seedHi) {
        this.seedLo = seedLo;
        this.seedHi = seedHi;
        if ((this.seedLo | this.seedHi) == 0L) {
            this.seedLo = -7046029254386353131L;     // GOLDEN_RATIO_64
            this.seedHi = 7640891576956012809L;       // SILVER_RATIO_64
        }
    }

    public long nextLong() {
        long lo = this.seedLo;
        long hi = this.seedHi;
        long result = Long.rotateLeft(lo + hi, 17) + lo;
        hi ^= lo;
        this.seedLo = Long.rotateLeft(lo, 49) ^ hi ^ hi << 21;
        this.seedHi = Long.rotateLeft(hi, 28);
        return result;
    }
}
```

**xoroshiro128++** 是 David Blackman + Sebastiano Vigna 2018 设计的算法（http://prng.di.unimi.it/）：

- **xoroshiro128**：基础变体，周期 2^128。
- **++ scrambler**：在输出端加 rotate + add 提高输出分布质量。

**为什么 Mojang 选 xoroshiro 而不是 PCG / SplitMix64**？

1. **简单**：~8 行算法，无 lookup table。
2. **快**：现代 CPU 上 ~2-3 cycles/output。
3. **质量好**：通过 PractRand / TestU01 BigCrush。
4. **状态紧凑**：仅 128 bit。

**全 0 状态保护**：如果构造时 seedLo/Hi 都是 0，xoroshiro 会停在 0。Mojang 用 GOLDEN_RATIO + SILVER_RATIO 替换以避免。

**`Long.rotateLeft(x, n)`** 在 Java 是 intrinsic（编译为单条 CPU rotate 指令）。C++ 用 `std::rotl`（C++20）。

## 3.3.5 PositionalRandomFactory：按位置确定的随机

**核心需求**：worldgen 需要"给定 (x, y, z) 总能复现同样的随机序列"。比如"在 (100, 64, 100) 这棵橡树长不长 / 几格高 / 树叶长哪里"，只要 worldSeed 不变，结果就要稳定。

**实现**：`PositionalRandomFactory` 接口：

```java
public interface PositionalRandomFactory {
    default RandomSource at(BlockPos pos) {
        return this.at(pos.getX(), pos.getY(), pos.getZ());
    }
    
    RandomSource at(int x, int y, int z);
    RandomSource fromHashOf(String name);
    RandomSource fromHashOf(ResourceLocation rl);
    @VisibleForTesting void parityConfigString(StringBuilder builder);
}
```

**用法**：

```java
PositionalRandomFactory rng = randomState.getOrCreateRandomFactory(NoiseRouterData.OVERWORLD);
RandomSource treeRandom = rng.at(100, 64, 100);
treeRandom.nextInt(...);    // 这棵树的高度
treeRandom.nextInt(...);    // 树叶半径
// ⋯
```

**实现 `XoroshiroPositionalRandomFactory`**：

```java
public class XoroshiroPositionalRandomFactory implements PositionalRandomFactory {
    private final long seedLo;
    private final long seedHi;

    @Override
    public RandomSource at(int x, int y, int z) {
        long mixed = Mth.getSeed(x, y, z);   // 把 (x, y, z) 哈希成 long
        long lo = mixed ^ this.seedLo;
        return new XoroshiroRandomSource(lo, this.seedHi);
    }
}
```

`Mth.getSeed(x, y, z)`（`net.minecraft.util.Mth` 中）：

```java
public static long getSeed(int x, int y, int z) {
    long seed = (long)(x * 3129871) ^ (long)z * 116129781L ^ (long)y;
    seed = seed * seed * 42317861L + seed * 11L;
    return seed >> 16;
}
```

**朴素混合**：把 x、y、z 用大质数线性组合，再做一轮 squared scrambling。**输出统计性能不算最优，但够用**。

**关键性质**：`fromHashOf("string")` 用 MD5 把字符串哈希到 128-bit seed，让"按名字"的随机也能确定性派生：

```java
@Override
public RandomSource fromHashOf(String name) {
    Seed128bit hash = RandomSupport.seedFromHashOf(name);
    return new XoroshiroRandomSource(this.seedLo ^ hash.seedLo(), this.seedHi ^ hash.seedHi());
}
```

例如 `Noises.TEMPERATURE` 这个 noise 用 `forkPositional().fromHashOf("minecraft:temperature")` 得到种子——这就是为什么 datapack 改 noise 名字会改地形。

## 3.3.6 RandomSupport：种子工具集

打开 `net.minecraft.world.level.levelgen.RandomSupport`：

```java
public final class RandomSupport {
    public static final long GOLDEN_RATIO_64 = -7046029254386353131L;     // 0x9E3779B97F4A7C15
    public static final long SILVER_RATIO_64 = 7640891576956012809L;       // 0x6A09E667F3BCC909
    private static final HashFunction MD5_128 = Hashing.md5();

    public static long mixStafford13(long x) {
        x = (x ^ x >>> 30) * -4658895280553007687L;
        x = (x ^ x >>> 27) * -7723592293110705685L;
        return x ^ x >>> 31;
    }

    public static Seed128bit upgradeSeedTo128bit(long seed) {
        return upgradeSeedTo128bitUnmixed(seed).mixed();
    }

    public static Seed128bit upgradeSeedTo128bitUnmixed(long seed) {
        long lo = seed ^ SILVER_RATIO_64;
        long hi = lo + GOLDEN_RATIO_64;
        return new Seed128bit(lo, hi);
    }

    public static Seed128bit seedFromHashOf(String text) {
        byte[] hash = MD5_128.hashString(text, Charsets.UTF_8).asBytes();
        long lo = Longs.fromBytes(hash[0], hash[1], ..., hash[7]);
        long hi = Longs.fromBytes(hash[8], ..., hash[15]);
        return new Seed128bit(lo, hi);
    }

    public static record Seed128bit(long seedLo, long seedHi) {
        public Seed128bit xor(long lo, long hi) { ... }
        public Seed128bit mixed() {
            return new Seed128bit(mixStafford13(this.seedLo), mixStafford13(this.seedHi));
        }
    }
}
```

**`mixStafford13`** 是 Daniel Stafford 2014 年设计的 64-bit avalanche 函数（"Variants of Stafford's Mix13"）。把任意 long 充分混合到一个新的 long，统计性能极佳。

**用途**：把 64-bit seed → 128-bit Xoroshiro state 的展开过程：

```
oldSeed (64 bit)
    │
    │ XOR SILVER_RATIO_64 → seedLo
    │ + GOLDEN_RATIO_64   → seedHi
    ▼
{seedLo, seedHi} (128 bit unmixed)
    │
    │ mixStafford13(seedLo)
    │ mixStafford13(seedHi)
    ▼
{seedLo', seedHi'} (128 bit, avalanche)
    │
    ▼
Xoroshiro128++(seedLo', seedHi')
```

`upgradeSeedTo128bit(worldSeed)` 是 worldgen 起点——把 64-bit worldSeed 扩成 128-bit Xoroshiro 种子。

**MD5 派生 from 字符串**：用 MD5（128-bit 输出）把 "minecraft:temperature" 这种 ResourceLocation 哈希成 128-bit seed。MD5 不安全（已破解）但**用作 PRNG seed 完全够用**——不需要密码学强度。

## 3.3.7 RandomState：所有随机源的容器

`net.minecraft.world.level.levelgen.RandomState` 是一个 chunk generator 持有的"随机源池"：

```java
public final class RandomState {
    private final NoiseRouter router;
    private final Climate.Sampler sampler;
    private final SurfaceSystem surfaceSystem;
    private final PositionalRandomFactory random;
    private final Map<ResourceKey<NormalNoise.NoiseParameters>, NormalNoise> noiseIntances;
    private final Map<ResourceLocation, PositionalRandomFactory> positionalRandoms;
    
    public PositionalRandomFactory getOrCreateRandomFactory(ResourceLocation key) {
        return this.positionalRandoms.computeIfAbsent(key, k -> 
            this.random.fromHashOf(k).forkPositional());
    }
    
    public NormalNoise getOrCreateNoise(ResourceKey<NormalNoise.NoiseParameters> key) {
        return this.noiseIntances.computeIfAbsent(key, k -> {
            // 用 forkPositional + fromHashOf(noise key) 派生这个 noise 的种子
            // 然后构造 NormalNoise
        });
    }
}
```

**派生层级**：

```
worldSeed (64 bit)
    │
    │ upgradeSeedTo128bit
    ▼
worldSeed128 (128 bit)
    │
    │ XoroshiroRandomSource → forkPositional()
    ▼
PositionalRandomFactory rootFactory
    │
    │ rootFactory.fromHashOf("minecraft:overworld")
    ▼
PositionalRandomFactory overworldFactory
    │
    ├── overworldFactory.fromHashOf("minecraft:temperature") → temperature noise
    ├── overworldFactory.fromHashOf("minecraft:humidity") → humidity noise
    ├── overworldFactory.fromHashOf("minecraft:continentalness") → continentalness noise
    ├── overworldFactory.fromHashOf("minecraft:erosion") → erosion noise
    ├── overworldFactory.fromHashOf("minecraft:weirdness") → weirdness noise
    ├── overworldFactory.fromHashOf("minecraft:cave_layer") → cave noise
    ├── ⋯
    │
    ├── overworldFactory.at(x, y, z) → 临时 RandomSource for some position
    │
    └── ⋯
```

**层级保证**：worldSeed 不变 → 任何 chunk / noise / feature 的种子都不变 → 世界完全可复现。

## 3.3.8 WorldgenRandom：兼容封装

`WorldgenRandom`（行 6+）是 1.17 时代的兼容封装——大量旧 worldgen 代码（碎片化的 carver / tree / structure piece）写时假设 `LegacyRandomSource` API（基于 LCG 的 `setSeed` 方法）。1.18 切换到 Xoroshiro 后，Mojang 写了 WorldgenRandom 包装器：

```java
public class WorldgenRandom extends LegacyRandomSource {
    private final RandomSource randomSource;    // 真正的 underlying
    private int count;

    public WorldgenRandom(RandomSource source) {
        super(0L);
        this.randomSource = source;
    }

    @Override
    public RandomSource fork() { return this.randomSource.fork(); }

    @Override
    public PositionalRandomFactory forkPositional() { return this.randomSource.forkPositional(); }

    public long setDecorationSeed(long worldSeed, int chunkX, int chunkZ) {
        this.setSeed(worldSeed);
        long oddA = this.nextLong() | 1L;
        long oddB = this.nextLong() | 1L;
        long seed = (long)chunkX * oddA + (long)chunkZ * oddB ^ worldSeed;
        this.setSeed(seed);
        return seed;
    }

    public void setFeatureSeed(long decorationSeed, int featureIdx, int stepIdx) {
        long seed = decorationSeed + (long)featureIdx + (long)(10000 * stepIdx);
        this.setSeed(seed);
    }
}
```

**`setDecorationSeed`** 是 FEATURES 阶段的入口。给定 (worldSeed, chunkX, chunkZ) 派生该 chunk 的"装饰起点"种子。

**`setFeatureSeed`** 在每一个具体 PlacedFeature 调用前用——给定 (decorationSeed, featureIdx, stepIdx) 派生该 feature 的种子。这就是为什么"同一 chunk 同一 worldSeed 总长同样的树在同样位置"。

## 3.3.10 Slime Chunk：另一个例子

史莱姆在哪些 chunk 自然刷怪（"slime chunk"）？

```java
public static RandomSource seedSlimeChunk(int chunkX, int chunkZ, long worldSeed, long magic) {
    return RandomSource.create(
        worldSeed
        + (long)(chunkX * chunkX * 4987142)
        + (long)(chunkX * 5947611)
        + (long)(chunkZ * chunkZ) * 4392871L
        + (long)(chunkZ * 389711)
        ^ magic
    );
}
```

**这是 1.0 时代的硬编码 LCG seed**——4987142 / 5947611 / 4392871 / 389711 是几个魔术质数。Notch 当年随手写的，留下来不能改（改就破坏存档兼容）。

`magic` 通常是 `0x3AD8025FL`（slime 专用 salt）。

游戏内任意 chunk 是不是 slime chunk：用上面 seed → `nextInt(10) == 0` 即可判定。这就是为什么 mod 工具能精确预测 slime chunks——只要知道 worldSeed。

## 3.3.12 C++ 移植

```cpp
namespace mc::random {

// === Xoroshiro128++ ===
class Xoroshiro128PlusPlus {
public:
    Xoroshiro128PlusPlus(uint64_t lo, uint64_t hi) : seedLo_(lo), seedHi_(hi) {
        if ((seedLo_ | seedHi_) == 0) {
            seedLo_ = 0x9E3779B97F4A7C15ULL;     // GOLDEN_RATIO
            seedHi_ = 0x6A09E667F3BCC909ULL;     // SILVER_RATIO
        }
    }
    
    uint64_t nextLong() {
        uint64_t lo = seedLo_;
        uint64_t hi = seedHi_;
        uint64_t result = std::rotl(lo + hi, 17) + lo;
        hi ^= lo;
        seedLo_ = std::rotl(lo, 49) ^ hi ^ (hi << 21);
        seedHi_ = std::rotl(hi, 28);
        return result;
    }

private:
    uint64_t seedLo_, seedHi_;
};

// === RandomSupport ===
struct Seed128bit {
    uint64_t seedLo, seedHi;
    
    Seed128bit xorWith(uint64_t lo, uint64_t hi) const {
        return {seedLo ^ lo, seedHi ^ hi};
    }
    
    Seed128bit mixed() const {
        return {mixStafford13(seedLo), mixStafford13(seedHi)};
    }
    
    static uint64_t mixStafford13(uint64_t x) {
        x = (x ^ (x >> 30)) * 0xBF58476D1CE4E5B5ULL;
        x = (x ^ (x >> 27)) * 0x94D049BB133111EBULL;
        return x ^ (x >> 31);
    }
};

inline Seed128bit upgradeSeedTo128bit(uint64_t seed) {
    uint64_t lo = seed ^ 0x6A09E667F3BCC909ULL;
    uint64_t hi = lo + 0x9E3779B97F4A7C15ULL;
    return Seed128bit{lo, hi}.mixed();
}

// === RandomSource 接口 ===
class RandomSource {
public:
    virtual ~RandomSource() = default;
    virtual int32_t nextInt() = 0;
    virtual int32_t nextInt(int32_t bound) = 0;
    virtual int64_t nextLong() = 0;
    virtual float nextFloat() = 0;
    virtual double nextDouble() = 0;
    virtual std::unique_ptr<RandomSource> fork() const = 0;
    virtual std::unique_ptr<PositionalRandomFactory> forkPositional() const = 0;
};

class XoroshiroRandomSource : public RandomSource {
public:
    explicit XoroshiroRandomSource(uint64_t seed)
        : XoroshiroRandomSource(upgradeSeedTo128bit(seed)) {}
    
    XoroshiroRandomSource(Seed128bit seed) : rng_(seed.seedLo, seed.seedHi) {}
    
    int64_t nextLong() override { return int64_t(rng_.nextLong()); }
    
    // 其他方法用 nextLong 派生
    
private:
    Xoroshiro128PlusPlus rng_;
};

// === PositionalRandomFactory ===
class PositionalRandomFactory {
public:
    virtual ~PositionalRandomFactory() = default;
    virtual std::unique_ptr<RandomSource> at(int x, int y, int z) const = 0;
    virtual std::unique_ptr<RandomSource> fromHashOf(std::string_view name) const = 0;
};

class XoroshiroPositionalRandomFactory : public PositionalRandomFactory {
public:
    XoroshiroPositionalRandomFactory(uint64_t lo, uint64_t hi)
        : seedLo_(lo), seedHi_(hi) {}
    
    std::unique_ptr<RandomSource> at(int x, int y, int z) const override {
        uint64_t mixed = mixCoords(x, y, z);
        return std::make_unique<XoroshiroRandomSource>(
            Seed128bit{mixed ^ seedLo_, seedHi_}
        );
    }
    
    std::unique_ptr<RandomSource> fromHashOf(std::string_view name) const override {
        auto hash = md5Hash128(name);
        return std::make_unique<XoroshiroRandomSource>(
            Seed128bit{hash.seedLo ^ seedLo_, hash.seedHi ^ seedHi_}
        );
    }
    
private:
    uint64_t seedLo_, seedHi_;
    
    static uint64_t mixCoords(int x, int y, int z) {
        int64_t s = int64_t(x) * 3129871 ^ int64_t(z) * 116129781LL ^ int64_t(y);
        s = s * s * 42317861LL + s * 11LL;
        return uint64_t(s >> 16);
    }
};

}
```

**关键工程选择**：

1. **`std::rotl` (C++20)** ：直接用，编译为 ROL 指令。
2. **`uint64_t` 不用 `int64_t`**：避免 sign extension 错误。
3. **MD5 用 OpenSSL 或 Botan**：随便一个能产生 128-bit hash 的库。
4. **`std::unique_ptr<RandomSource>`** vs 值类型？小 PRNG 状态用值类型更好（XoroshiroRandomSource 仅 16 字节）；如果接口需要多态用 unique_ptr。
5. **`mixStafford13` 常量是 64-bit 魔数**：照抄。

**测试关键**：构造一个 1.21 vanilla 已知坐标 + seed，对比你的实现和 Mojang 的输出。Cubitect 的 cubiomes 项目 (github.com/Cubitect/cubiomes) 有 C 实现可参考校对。

## 3.3.13 实战：检查 worldSeed=1, chunk(0,0) 的生成种子

```java
// 用 Mojang 的代码计算
long worldSeed = 1L;
RandomSupport.Seed128bit world128 = RandomSupport.upgradeSeedTo128bit(worldSeed);
PositionalRandomFactory root = new XoroshiroRandomSource(world128).forkPositional();
PositionalRandomFactory overworld = root.fromHashOf(new ResourceLocation("minecraft:overworld")).forkPositional();
PositionalRandomFactory temperature = overworld.fromHashOf(new ResourceLocation("minecraft:temperature")).forkPositional();
RandomSource at100x100 = temperature.at(100, 64, 100);

System.out.println("First nextLong: " + at100x100.nextLong());
// 应该输出一个固定的 long——run 多少次都一样
```

如果你的 C++ 实现产生同一个 long，**就匹配上 vanilla 了**。

## 3.3.14 一句话总结

Minecraft worldgen 用 **Xoroshiro128++**（1.18+ 默认，64+64 = 128 bit 状态，周期 2^128）替代 java.util.Random LCG（周期 2^48），但保留 `LegacyRandomSource` 兼容旧地图；64-bit worldSeed 通过 `mixStafford13` 升级到 128-bit；**`PositionalRandomFactory.at(x, y, z)`** 是 worldgen 决定性的关键——给定 worldSeed + 坐标必产生同样随机流；**`fromHashOf(name)`** 用 MD5 把 ResourceLocation 哈希到种子；`WorldgenRandom.setDecorationSeed` / `setFeatureSeed` 是 FEATURES 阶段的种子派生入口；同种子任意机器复现完全一致。
