## 3.7.1 直觉：从一维参数到 6 维空间

回顾 3.1.2 节的五大气候参数。给定 (x, z)，5 次 noise 采样得到 5 个 float：

```
T = noise_temperature(x, z)
H = noise_humidity(x, z)
C = noise_continents(x, z)
E = noise_erosion(x, z)
W = noise_weirdness(x, z)
```

加上 depth（从 Y 推导，地下 / 地表 / 高空）共 6 维。

**问题**：每种 biome 应该出现在 (T, H, C, E, W, D) 6 维空间里的哪一块？反过来，给定一个 6 维点，怎么找到"最匹配"的 biome？

**最朴素方案**：把 6 维空间分成 N×N×N×N×N×N 网格，每格存一个 biome 实例。给定一个 6 维点，量化到网格再查表。

**问题**：

- 6^N 网格爆炸（N=10 → 一百万格）。
- 网格边界硬切——biome 边界出现马赛克。
- 不容易让不同 biome 占不同形状的"块"。

**Mojang 的方案**：每个 biome 占据 6 维空间的一个**超长方体**（hyper-rectangular block）。给定一个 6 维点，在所有 biome 的超长方体集合中**找最近的那个**（按欧氏距离）。

这是个**6 维最近邻查询**问题。Mojang 用 **R-Tree**（经典空间索引数据结构）实现——`Climate.RTree`。

## 3.7.2 Climate.Parameter：一维区间

打开 `net.minecraft.world.level.biome.Climate`：

```java
public static record Parameter(long min, long max) {
    public static Parameter point(float v) {
        return span(v, v);
    }
    public static Parameter span(float a, float b) {
        return new Parameter(quantizeCoord(a), quantizeCoord(b));
    }
}

public static long quantizeCoord(float v) {
    return (long)(v * 10000.0F);
}
```

**`Parameter`** 是一维"闭区间"——从 min 到 max。

**量化系数 10000**：所有 float 输入（如 -1.5, 0.3）乘以 10000 转成 long（-15000, 3000）。原因：

- 整数比较比 float 比较快。
- 整数算"距离平方"避免浮点累积误差。
- long 范围 ±2^63 远超需要。

## 3.7.3 Climate.ParameterPoint：6 维超长方体

```java
public static record ParameterPoint(
    Parameter temperature,      // T
    Parameter humidity,          // H
    Parameter continentalness,   // C
    Parameter erosion,           // E
    Parameter depth,             // D
    Parameter weirdness,         // W
    long offset                  // 优先级偏移
)
```

**6 个 Parameter 构成 6 维超长方体**（每维度独立 [min, max]），加一个 offset 给"碰头"时的优先级。

**`offset`** 用法：当一个采样点同时落在多个 ParameterPoint 内时，offset 小的胜出。Mojang 给特殊 biome（如 mushroom_fields）设较低 offset 让它优先。

## 3.7.4 Climate.TargetPoint：单一采样点

```java
public static record TargetPoint(
    long temperature,
    long humidity,
    long continentalness,
    long erosion,
    long depth,
    long weirdness
)
```

**6 个量化 long 构成一个具体点**（不是范围）。

**采样**：在某个世界坐标 (x, y, z) 调 `Climate.Sampler.sample(...)` 得到 TargetPoint。

## 3.7.5 Climate.Sampler：从 NoiseRouter 抽 6 个值

```java
public static record Sampler(
    DensityFunction temperature,
    DensityFunction humidity,
    DensityFunction continentalness,
    DensityFunction erosion,
    DensityFunction depth,
    DensityFunction weirdness,
    List<ParameterPoint> spawnTarget
) {
    public TargetPoint sample(int x, int y, int z) {
        FunctionContext ctx = new SinglePointContext(x, y, z);
        return Climate.target(
            (float)this.temperature.compute(ctx),
            (float)this.humidity.compute(ctx),
            (float)this.continentalness.compute(ctx),
            (float)this.erosion.compute(ctx),
            (float)this.depth.compute(ctx),
            (float)this.weirdness.compute(ctx)
        );
    }
}
```

**Sampler = 6 个 DensityFunction 引用**（来自 NoiseRouter 的 6 个气候通道）。

**`sample(x, y, z)`** 调 6 次 DensityFunction.compute → 6 个 float → 量化为 TargetPoint。

**`spawnTarget` 列表**：玩家世界初始 spawn 时寻找"最适合的位置"的目标 ParameterPoint 列表。详见 3.13 节。

## 3.7.6 Climate.RTree：6 维 R-Tree 最近邻

```java
public static class RTree<T> {
    private static final int CHILDREN_PER_NODE = 10;
    private final Node<T> root;
    private final ThreadLocal<Leaf<T>> lastResult = new ThreadLocal<>();

    public T search(TargetPoint target, DistanceMetric<T> distance) {
        long[] coords = target.toParameterArray();
        Leaf<T> result = this.root.search(coords, this.lastResult.get(), distance);
        this.lastResult.set(result);
        return result.value;
    }

    public static <T> RTree<T> create(List<Pair<ParameterPoint, T>> entries) {
        // 构造 R-Tree
    }
}
```

**R-Tree 是经典空间索引数据结构**：

- **leaf node**：一个 (ParameterPoint, T) 对（biome）。
- **internal node**：一组 child node（最多 10 个）+ 一个**包围盒**（所有 child 的并）。
- **search**：从 root 开始 DFS，对每个 internal node，计算 query 点到包围盒的距离作为"下界"。如果当前最优解 < 下界 → 剪枝。

**为什么 R-Tree 而不是 KD-Tree？**

- KD-Tree 需要每维度分裂——维度多时（6 维）退化成线性扫。
- R-Tree 用包围盒分裂——多维下表现稳定。
- R-Tree 支持"过长方体"的 entry——和 ParameterPoint 完美匹配。

**为什么不用哈希？**

- 哈希适合"完全匹配"，不适合"最近邻"。
- 6 维空间不能简单 hash 量化。

**`CHILDREN_PER_NODE = 10`**：每内部节点最多 10 个 child。这是 R-Tree 的"阶数"，影响树深度 / 单步代价的平衡。Mojang 的 ~600 个 biome ParameterPoint 形成约 3-4 层树（10² = 100，10³ = 1000）。

**`lastResult`** 是优化：连续的 sample 通常空间相邻，结果常是同一个或相近 biome。先尝试上次结果作为初始最优解，能极大加速后续 prune。

**性能**：单次 6 维 R-Tree query 约 50-200 ns。一个 chunk 的 4³ × 24 = 1536 次 biome 查询约 0.3 ms。

**~600 个 ParameterPoint 入口**——每个对应"在某个 (T, H, C, E, W) 区域应该是哪个 biome"。

**为什么不数据驱动**？因为这套配方**实在太复杂**：

- 主世界有约 60 种地表 biome。
- 每个 biome 在 (T, H, C, E, W) 5 维上占多个不连续区域。
- 同一组 (T, H) 在不同 (C, E, W) 下选不同 biome（"中纬度低海拔丘陵 vs 中纬度高海拔山"）。
- 海岸 / 海洋 / 河流 / 地下另有规则。

**5000 行 Java 代码** 在 datapack JSON 里会变成几万行嵌套配置，可读性更差。Mojang 选择保留 Java——它仍然完全暴露给 modder 通过 mixin 修改，只是不通过纯 datapack。

## 3.7.8 关键 5×5 矩阵：温度 × 湿度 → biome

打开 `OverworldBiomeBuilder.middleBiome` 等：

```java
private final ResourceKey<Biome>[][] MIDDLE_BIOMES = new ResourceKey[][]{
    // [temp][humid]
    // humid:  ARID    DRY      NEUTRAL    WET       HUMID
    /*ICY*/  { snowy_plains,  snowy_plains,  snowy_plains, snowy_taiga,    taiga          },
    /*COOL*/ { plains,         plains,        forest,       taiga,          old_growth_spruce_taiga },
    /*NEUTRAL*/{ flower_forest,plains,        forest,       birch_forest,   dark_forest    },
    /*WARM*/ { savanna,        savanna,       forest,       jungle,         jungle         },
    /*HOT*/  { desert,         desert,        desert,       desert,         desert         }
};
```

**这是主世界 biome 的"主表"**——25 个组合。给定 (T, H) 组合就有一个 biome 候选。

实际有更多变体：

- **MIDDLE_BIOMES**：内陆"普通"地形（slope/plain）。
- **MIDDLE_BIOMES_VARIANT**：内陆"特殊"地形（中等山）。
- **PLATEAU_BIOMES**：高原（高 erosion + 高内陆度）。
- **PLATEAU_BIOMES_VARIANT**：高原变体。
- **SHATTERED_BIOMES**：尖峰山（peaks PV，低 erosion）。
- **EXTREME_HILLS**：极端山。

**为什么这么多变体**？因为同 (T, H) 在不同 (E, W) 下视觉应该不同——平原应该是 plains，高原应该是 wooded_badlands_plateau，山顶应该是 frozen_peaks。Mojang 用矩阵硬编码所有组合。

## 3.7.9 海岸 + 海洋 + 河流的特殊处理

`addOffCoastBiomes`（连续值 continents < -0.05）：

```java
// 大致：
//   continents ∈ [-1.2, -0.45]   → deep_ocean / mushroom_fields
//   continents ∈ [-0.45, -0.19]  → ocean
//   continents ∈ [-0.19, -0.11]  → beach / stony_shore
```

按温度分：
- ICY ocean → frozen_ocean
- COOL ocean → cold_ocean
- NEUTRAL ocean → ocean
- WARM ocean → lukewarm_ocean
- HOT ocean → warm_ocean

mushroom_fields 是个特殊点——continentalness 极低（深海 deep）+ weirdness 中性。它的 ParameterPoint offset 较低，让它"夺过"普通 deep_ocean。

**河流**：

```java
// weirdness 在 [-0.1, 0.1] + erosion 高 + continents 中等 → river
```

河流由 weirdness 接近 0 决定——这就是为什么 weirdness 也叫 "ridge"，它定义"山脊 vs 山谷"边界，而 0 附近就是水流的"谷底"。

## 3.7.11 BiomeManager：边界抖动

打开 `net.minecraft.world.level.biome.BiomeManager`：

```java
public class BiomeManager {
    public static final int CHUNK_CENTER_QUART = QuartPos.fromBlock(8);
    private static final int ZOOM_BITS = 2;
    private static final int ZOOM = 4;
    private static final int ZOOM_MASK = 3;
    
    private final BiomeManager.NoiseBiomeSource noiseBiomeSource;
    private final long biomeZoomSeed;

    public BiomeManager(BiomeManager.NoiseBiomeSource source, long seed) {
        this.noiseBiomeSource = source;
        this.biomeZoomSeed = seed;
    }

    public Holder<Biome> getBiome(BlockPos pos) {
        int blockX = pos.getX() - 2;
        int blockY = pos.getY() - 2;
        int blockZ = pos.getZ() - 2;
        int quartX = blockX >> 2;
        int quartY = blockY >> 2;
        int quartZ = blockZ >> 2;
        double dx = (blockX & 3) / 4.0;
        double dy = (blockY & 3) / 4.0;
        double dz = (blockZ & 3) / 4.0;
        // ⋯
        int bestQuartX = 0, bestQuartY = 0, bestQuartZ = 0;
        double bestNoise = Double.POSITIVE_INFINITY;
        for (int corner = 0; corner < 8; corner++) {
            // 8 个相邻 quart 角点采样 noise，用 noise 做加权
            // ⋯
        }
        return this.noiseBiomeSource.getNoiseBiome(qx + bestQuartX, qy + bestQuartY, qz + bestQuartZ, sampler);
    }
}
```

**问题**：朴素查询 4×4×4 quart 体素的 biome → 边界完美直线、视觉马赛克感强。

**BiomeManager 的解法**：对每个 BlockPos，在 quart 体素的 8 个相邻 quart 角点里**用噪声选一个**——加权方式让边界产生 ±2 格的"抖动"。

效果：biome 边界看起来更自然——森林一片片伸入草原、沙漠和草原交界呈不规则曲线。

`biomeZoomSeed` 是 worldSeed 派生的种子。同 worldSeed → 同抖动模式。

## 3.7.12 BiomeSource 的三大实现

`net.minecraft.world.level.biome.BiomeSource` 是"如何决定 biome"的抽象：

```java
public abstract class BiomeSource {
    public static final Codec<BiomeSource> CODEC = Registries.BIOME_SOURCE.byNameCodec()
        .dispatch(BiomeSource::codec, Function.identity());

    public abstract Holder<Biome> getNoiseBiome(int qx, int qy, int qz, Climate.Sampler sampler);
}
```

**3 个实现**：

### `MultiNoiseBiomeSource`

主世界 + 下界都用。本节讨论的就是它。

```java
public class MultiNoiseBiomeSource extends BiomeSource {
    private final Climate.ParameterList<Holder<Biome>> parameters;
    
    @Override
    public Holder<Biome> getNoiseBiome(int qx, int qy, int qz, Climate.Sampler sampler) {
        return this.parameters.findValue(sampler.sample(qx, qy, qz));
    }
}
```

**核心**：调 `parameters.findValue(targetPoint)`——它内部用 RTree 找最近邻 ParameterPoint。

### `FixedBiomeSource`

返回固定 biome。给"buffet" 模式 + 调试用。

```java
public class FixedBiomeSource extends BiomeSource {
    private final Holder<Biome> biome;
    
    @Override
    public Holder<Biome> getNoiseBiome(...) { return this.biome; }
}
```

### `CheckerboardColumnBiomeSource`

棋盘式：相邻区域不同 biome 交替。给调试用。

```java
public class CheckerboardColumnBiomeSource extends BiomeSource {
    private final HolderSet<Biome> biomes;
    private final int size;
    // ⋯
}
```

### `TheEndBiomeSource`

末地用——基于"距离原点的距离 + noise"的特殊算法（不是 multi-noise）。详见 3.14 节。

## 3.7.13 视觉映射：参数 → 玩家眼中的地貌

汇总：

```
Continentalness ≪ 0  (-0.5)：deep_ocean / mushroom_fields
Continentalness ≈ -0.3：ocean
Continentalness ≈ -0.15：beach
Continentalness > 0    ：内陆

  Erosion ≪ 0 (低，山势陡)：windswept / shattered / peaks
  Erosion 适中：plain / forest
  Erosion ≫ 0 (高，平地)：plateau / mesa

    Temperature ≪ 0：ICY (snowy_taiga, frozen_ocean)
    Temperature ≈ -0.2：COOL (taiga)
    Temperature ≈ 0：NEUTRAL (plains, forest)
    Temperature ≈ 0.4：WARM (savanna)
    Temperature > 0.5：HOT (desert, badlands)

      Humidity ≪ 0：ARID (desert, savanna_arid)
      Humidity 适中：DRY/NEUTRAL (plains)
      Humidity ≫ 0：HUMID (jungle, swamp, dark_forest)

        Weirdness：
          |W| 接近 0：river / 谷底
          |W| 中等：普通山坡
          |W| 接近 1：尖峰 / 极端山
          W < -0.85：valleys（深谷）
```

**用 Misode 的 Worldgen Visualizer 可视化**：拖动 5 个滑条看每种组合落到哪个 biome。比读 OverworldBiomeBuilder 直观 10×。

## 3.7.14 实战：手算一个坐标的 biome

给定 worldSeed = 1，BlockPos (100, 64, 100)：

```
1. quartX = 100 >> 2 = 25, quartY = 64 >> 2 = 16, quartZ = 100 >> 2 = 25
2. ClimateSampler.sample(25, 16, 25):
   T = router.temperature.compute(ctx) →  0.32
   H = router.humidity.compute(ctx)    →  0.05
   C = router.continents.compute(ctx)  →  0.45
   E = router.erosion.compute(ctx)     → -0.10
   D = router.depth.compute(ctx)       →  0.0   (地表附近)
   W = router.ridges.compute(ctx)      →  0.18
3. quantize → TargetPoint(3200, 500, 4500, -1000, 0, 1800)
4. RTree.search(target):
   - 找到最近 ParameterPoint 是 plains 的某条目
   - 返回 plains
5. BiomeManager.getBiome((100, 64, 100)):
   - 8 个相邻 quart 角点抖动检查
   - 抖动后可能选 plains、forest 或 birch_forest
   - 假设最终是 plains
```

世界种子 = 1 时 (100, 64, 100) 几乎肯定是 plains。

## 3.7.16 C++ 移植

```cpp
namespace mc::biome {

struct ClimateParameter {
    int64_t min, max;
    
    static ClimateParameter point(float v) { return span(v, v); }
    static ClimateParameter span(float a, float b) {
        return {int64_t(a * 10000), int64_t(b * 10000)};
    }
};

struct ClimateParameterPoint {
    ClimateParameter temperature;
    ClimateParameter humidity;
    ClimateParameter continentalness;
    ClimateParameter erosion;
    ClimateParameter depth;
    ClimateParameter weirdness;
    int64_t offset;
};

struct ClimateTargetPoint {
    int64_t temperature, humidity, continentalness, erosion, depth, weirdness;
};

class ClimateSampler {
public:
    ClimateSampler(DensityFunction* T, DensityFunction* H, DensityFunction* C,
                   DensityFunction* E, DensityFunction* D, DensityFunction* W)
        : T_(T), H_(H), C_(C), E_(E), D_(D), W_(W) {}
    
    ClimateTargetPoint sample(int x, int y, int z) const {
        SinglePointContext ctx{x, y, z};
        return {
            int64_t(T_->compute(ctx) * 10000),
            int64_t(H_->compute(ctx) * 10000),
            int64_t(C_->compute(ctx) * 10000),
            int64_t(E_->compute(ctx) * 10000),
            int64_t(D_->compute(ctx) * 10000),
            int64_t(W_->compute(ctx) * 10000)
        };
    }
private:
    DensityFunction *T_, *H_, *C_, *E_, *D_, *W_;
};

template<typename T>
class ClimateRTree {
public:
    static constexpr int CHILDREN_PER_NODE = 10;
```

## 3.7.17 一句话总结

1.18+ 主世界用 **Multi-Noise Biome Source**——5 个气候 noise（temperature / humidity / continentalness / erosion / weirdness）+ 1 个 depth 维度 = 6 维参数空间；每个 biome 占据 6 维空间的一个超长方体（`ClimateParameterPoint`）；给定一个 6 维点用 **R-Tree 最近邻查询** 找匹配 biome；`OverworldBiomeBuilder` 是 ~5000 行 Java 硬编码 ~600 个 ParameterPoint 入口（5×5 温度湿度矩阵 × erosion × weirdness × continentalness 各 5 段 × 各种例外）；`BiomeManager` 在 4³ quart 体素粒度上做 8 角点抖动让边界自然；`MultiNoiseBiomeSource` / `FixedBiomeSource` / `CheckerboardColumnBiomeSource` 是 BiomeSource 的 3 实现。
