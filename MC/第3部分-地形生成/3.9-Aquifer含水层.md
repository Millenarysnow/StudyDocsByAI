## 3.9.1 直觉：1.18 之前 vs 之后

**1.17 之前**：

- 地下默认是 stone。
- NOISE 算出"空气格"就是空气（除非接触地表水或玩家手放水）。
- 洞穴就是空腔——里面没水。
- 玩家挖矿挖到大洞穴几乎从不见水（除非在地表附近水层渗下来）。

**1.18+**：

- NOISE 算空气格后，**Aquifer 系统再判一次**：这格在不在某个"局部水位"下方？是的话填水。
- 洞穴里**经常**有湖（小到几格、大到上百格的地下水库）。
- Y -54 附近（深岩层底部）的"空气格"经常被 Aquifer 填熔岩。

**视觉**：1.18+ 的洞穴探险是"经常需要游泳" + "经常踩到岩浆湖"，比之前丰富很多。

## 3.9.2 Aquifer 接口

打开 `net.minecraft.world.level.levelgen.Aquifer`：

```java
public interface Aquifer {
    static Aquifer create(NoiseChunk noiseChunk, ChunkPos pos, NoiseRouter router,
                          PositionalRandomFactory random, int minY, int height,
                          Aquifer.FluidPicker fluidPicker) {
        return new Aquifer.NoiseBasedAquifer(noiseChunk, pos, router, random, minY, height, fluidPicker);
    }

    static Aquifer createDisabled(final Aquifer.FluidPicker fluidPicker) {
        return new Aquifer() {
            @Nullable
            public BlockState computeSubstance(FunctionContext ctx, double density) {
                return density > 0.0 ? null : fluidPicker.computeFluid(ctx.blockX(), ctx.blockY(), ctx.blockZ()).at(ctx.blockY());
            }
            public boolean shouldScheduleFluidUpdate() { return false; }
        };
    }

    @Nullable
    BlockState computeSubstance(FunctionContext ctx, double density);

    boolean shouldScheduleFluidUpdate();

    public interface FluidPicker {
        FluidStatus computeFluid(int x, int y, int z);
    }

    public static record FluidStatus(int fluidLevel, BlockState fluidType) {
        public BlockState at(int y) {
            return y < this.fluidLevel ? this.fluidType : Blocks.AIR.defaultBlockState();
        }
    }
}
```

**核心概念**：

- **`computeSubstance(ctx, density)` → BlockState?**：给一个位置 + 该位置的 finalDensity，决定"这格放什么方块"。
  - density > 0 → null（说明是固体，由 NoiseChunk 自己处理放 stone）。
  - density ≤ 0 → 通常是 air，但 Aquifer 可能填水/熔岩。
- **`FluidStatus`**：单一"流体单元"——`(fluidLevelY, fluidType)`。说明"在某区域内，Y < fluidLevelY 的位置应该是 fluidType（水或熔岩）"。
- **`FluidPicker`**：给定 (x, y, z)，返回当前位置的 FluidStatus。

**两种实现**：

1. **`createDisabled`**：简单——只看 FluidPicker。给"无 Aquifer"维度（如末地、超平坦）用。
2. **`NoiseBasedAquifer`**：复杂——主世界用。下面 3.9.3 展开。

### 流体粒子网格

世界被划分成 **16×12×16 grid**：每 16 格 X × 12 格 Y × 16 格 Z 一个"格点"。每个格点对应一个**流体粒子（FluidStatus）**：

```
flu_grid[gridX][gridY][gridZ] = (fluidLevel, fluidType)
```

`fluidLevel` 是该粒子区域的水位 Y。`fluidType` 是 water 或 lava。

**SEPARATION = 6**：实际格点位置不在 `(gridX*16, gridY*12, gridZ*16)`，而是加一个 ±6 范围的 noise 偏移。这让粒子分布**不是规整 grid 而是不规则散点**。

源码常量：

```java
private static final int X_SPACING = 16;
private static final int Y_SPACING = 12;
private static final int Z_SPACING = 16;
private static final int X_SEPARATION = 6;
private static final int Y_SEPARATION = 3;     // Y 方向只 ±3
private static final int Z_SEPARATION = 6;
```

### 单个粒子的水位决策

给定一个 grid 位置，计算它的 FluidStatus：

```java
private FluidStatus computeFluid(int particleX, int particleY, int particleZ) {
    // 1. 调 globalFluidPicker（典型行为：Y < seaLevel 是 water，更深处某 Y 段是 lava）
    FluidStatus baseStatus = this.globalFluidPicker.computeFluid(particleX, particleY, particleZ);
    
    // 2. 看是否要"洪泛"（额外升高水位）
    double floodedness = this.fluidLevelFloodednessNoise.compute(...);
    if (floodedness < -0.3) {
        return baseStatus;     // 不洪泛
    }
    
    // 3. 计算更高的水位
    double spread = this.fluidLevelSpreadNoise.compute(...);
    int additionalLift = ...;
    int newFluidLevel = baseStatus.fluidLevel + additionalLift;
    return new FluidStatus(newFluidLevel, baseStatus.fluidType);
}
```

效果：

- 大部分粒子的水位 = 海平面（63）→ 洞穴 Y < 63 时填水。
- 某些粒子被 floodedness noise 选中 → 水位被抬高（如 Y 80）→ 那块区域的洞穴更高也有水。
- Y 接近 -54 时 globalFluidPicker 返回 lava → 那块的"水位"是熔岩。

### 三粒子混合

任意位置 (x, y, z) 找**最近 3 个粒子**：

```java
private static final int MAX_REASONABLE_DISTANCE_TO_AQUIFER_CENTER = 11;

@Override
public BlockState computeSubstance(FunctionContext ctx, double density) {
    int x = ctx.blockX(), y = ctx.blockY(), z = ctx.blockZ();
    
    // 找邻居 grid 上最近的 3 个粒子
    int gridX = floorDiv(x, X_SPACING);
    int gridY = floorDiv(y, Y_SPACING);
    int gridZ = floorDiv(z, Z_SPACING);
    
    // 在 3x3x3 grid 范围搜索最近 3 个粒子
    long bestDist1 = Long.MAX_VALUE;
    long bestDist2 = Long.MAX_VALUE;
    long bestDist3 = Long.MAX_VALUE;
    int p1Loc = 0, p2Loc = 0, p3Loc = 0;
    
    for (int dx = -1; dx <= 1; dx++)
    for (int dy = -1; dy <= 1; dy++)
    for (int dz = -1; dz <= 1; dz++) {
        long particleLoc = packLocation(gridX + dx, gridY + dy, gridZ + dz);
        long distSq = squaredDistanceFromParticle(particleLoc, x, y, z);
        if (distSq < bestDist1) { bestDist3 = bestDist2; p3Loc = p2Loc;
                                  bestDist2 = bestDist1; p2Loc = p1Loc;
                                  bestDist1 = distSq;    p1Loc = particleLoc; }
        else if (distSq < bestDist2) { ... }
        else if (distSq < bestDist3) { ... }
    }
    
    // 取出 3 个粒子的 FluidStatus
    FluidStatus s1 = getOrCreate(p1Loc);
    FluidStatus s2 = getOrCreate(p2Loc);
    FluidStatus s3 = getOrCreate(p3Loc);
    
    // 计算"相似度"
    double sim12 = similarity(bestDist1, bestDist2);
    double sim13 = similarity(bestDist1, bestDist3);
    double sim23 = similarity(bestDist2, bestDist3);
    
    // 主要：根据 s1 的 FluidStatus 决定（最近的）
    BlockState fluidAtY = s1.at(y);
    
    // 但如果 s2 / s3 与 s1 不同 type 且距离接近 → barrier noise 介入
    if (sim12 > 0 && (s1.fluidType != s2.fluidType || s1.fluidLevel != s2.fluidLevel)) {
        double barrier = this.barrierNoise.compute(...);
        // barrier 决定是不是"墙"
        if (barrier < 某阈值) return Blocks.STONE;     // 墙：把空气替换为石头
    }
    
    return fluidAtY;
}
```

**核心**：`computeSubstance` 不只是"填水"——它也可能"填石头"（aquifer 之间的墙）。这就是为什么 1.18 洞穴里有"地下湖之间被石墙隔开"的视觉。

**`barrierNoise`** 是 NoiseRouter 的 4 个 aquifer 通道之一——专门给"两个 aquifer 之间是不是要造墙"用。

## 3.9.4 与 NoiseChunk 的耦合

回顾 3.6.6：NoiseChunk 的 `getInterpolatedState()` 内部：

```java
public BlockState getInterpolatedState() {
    // ... 计算 finalDensity ...
    return this.blockStateRule.calculate(this, finalDensity);
}

// blockStateRule 的实现是：
class NoiseChunkBlockStateFiller {
    public BlockState calculate(NoiseChunk chunk, double density) {
        BlockState aquiferResult = chunk.aquifer.computeSubstance(chunk, density);
        if (aquiferResult != null) return aquiferResult;
        if (density > 0) return chunk.defaultBlock;
        return Blocks.AIR.defaultBlockState();
    }
}
```

**调用流程**：

1. 拿到 finalDensity。
2. 调 Aquifer.computeSubstance(ctx, density)。
3. Aquifer 决定：固体（返 null）/ 水 / 熔岩 / 石墙 / 空气。
4. 如果 Aquifer 返 null：
   - density > 0 → defaultBlock（stone）。
   - density ≤ 0 → AIR。

**Aquifer 在 NOISE 阶段就执行**——和 finalDensity 同时跑。这是为什么 Aquifer 输出和噪声地形紧密绑定。

## 3.9.5 OreVeinifier：在同一阶段也运行

3.6.6 的 BlockStateFiller 实际比上面的简化版**还多一层**——OreVeinifier。它检查 NoiseRouter 的 vein 通道决定是否把 stone 替换成原矿石：

```java
class CombinedRule {
    public BlockState calculate(NoiseChunk chunk, double density) {
        BlockState veinResult = chunk.oreVeinifier.calculate(chunk);     // 矿脉?
        if (veinResult != null) return veinResult;
        return chunk.aquifer.computeSubstance(chunk, density);
    }
}
```

## 3.9.6 fluidPicker：全局水位选择

`Aquifer.create` 接收 `FluidPicker globalFluidPicker`。它给"未被特殊 aquifer 覆盖的位置"提供默认水位。

主世界的 fluidPicker（伪码）：

```java
FluidPicker overworldFluidPicker = (x, y, z) -> {
    if (y < AQUIFER_LAVA_LEVEL) {        // Y < -54
        return new FluidStatus(AQUIFER_LAVA_LEVEL, Blocks.LAVA.defaultBlockState());
    }
    return new FluidStatus(seaLevel, Blocks.WATER.defaultBlockState());     // 默认海平面
};
```

**这就是为什么 1.18+ 深挖到 Y < -54 经常遇到岩浆**——fluidPicker 在那里默认返 lava。

`AQUIFER_LAVA_LEVEL` = -54（配方常量）。Y < -54 + density ≤ 0 + 没被 barrier 阻挡 → 这格是 lava。

## 3.9.7 视觉对照

```
Y > 80：洞穴里通常空气（高 Y 流体粒子很少）
Y = 30：洞穴里 30% 概率有水（aquifer 选中 + spread noise）
Y = 0：洞穴里 60% 概率有水
Y = -30：洞穴里 80% 概率有水（更接近默认水位粒子）
Y < -54：洞穴里 70% 是熔岩 + 20% 是水 + 10% 空气
```

这就是 1.18+ 玩家深挖时"水越多 → 岩浆 → 全岩浆"的体感。

## 3.9.8 是否触发 fluid update

```java
@Override
public boolean shouldScheduleFluidUpdate() {
    return true;     // NoiseBasedAquifer 永远 true
}
```

`SerializableChunkData.write` 时会读这个 flag——如果 true，Aquifer 填的水/熔岩需要在加载后**触发一次 fluid tick**（让水流"落定"，避免"高悬不下落"的水）。

`createDisabled` 实现返 false——超平坦不需要 fluid update。

## 3.9.9 性能

每个 chunk 的 NOISE 阶段调 ~16K 次 computeSubstance（4 cellCountXZ × 48 cellCountY × 4 cellCountXZ × 4×8×4 块）。每次：

- 找最近 3 个粒子：~27 次距离比较。
- 求 4 个 aquifer noise（barrier / floodedness / spread / lava）。

**总：~1-2 ms / chunk**——加在 80ms NOISE 阶段里不显著。

`aquiferCache` 数组缓存"已计算过的粒子 FluidStatus"，避免同 chunk 内重复算。

## 3.9.10 内存预算

```
NoiseBasedAquifer:
├── aquiferCache (FluidStatus[]):  ~2-3 KB（覆盖 chunk + 邻居一圈）
├── aquiferLocationCache (long[]): ~2 KB
└── 各 noise 引用 + 字段                   ~100 字节

每 chunk Aquifer 状态约 5 KB（worldgen 后丢弃）。
```

## 3.9.11 C++ 移植

```cpp
namespace mc::worldgen {

struct FluidStatus {
    int fluidLevel;
    const BlockState* fluidType;     // water / lava
    
    const BlockState* at(int y) const {
        return y < fluidLevel ? fluidType : &AIR_STATE;
    }
};

class FluidPicker {
public:
    virtual ~FluidPicker() = default;
    virtual FluidStatus computeFluid(int x, int y, int z) const = 0;
};

class Aquifer {
public:
    virtual ~Aquifer() = default;
    virtual const BlockState* computeSubstance(const FunctionContext& ctx, double density) = 0;
    virtual bool shouldScheduleFluidUpdate() const = 0;
    
    static std::unique_ptr<Aquifer> create(NoiseChunk& chunk, ChunkPos pos,
                                            const NoiseRouter& router,
                                            const PositionalRandomFactory& random,
                                            int minY, int height, FluidPicker* picker);
    
    static std::unique_ptr<Aquifer> createDisabled(FluidPicker* picker);
};

class NoiseBasedAquifer : public Aquifer {
public:
    static constexpr int X_SPACING = 16;
    static constexpr int Y_SPACING = 12;
    static constexpr int Z_SPACING = 16;
    
    NoiseBasedAquifer(NoiseChunk& chunk, ChunkPos pos, const NoiseRouter& router,
                      const PositionalRandomFactory& random,
                      int minY, int height, FluidPicker* picker);
    
    const BlockState* computeSubstance(const FunctionContext& ctx, double density) override;
    bool shouldScheduleFluidUpdate() const override { return true; }

private:
    NoiseChunk* noiseChunk_;
    DensityFunction* barrierNoise_;
    DensityFunction* fluidLevelFloodednessNoise_;
    DensityFunction* fluidLevelSpreadNoise_;
    DensityFunction* lavaNoise_;
    const PositionalRandomFactory* random_;
    FluidPicker* globalFluidPicker_;
    
    std::vector<FluidStatus> aquiferCache_;
    std::vector<int64_t> aquiferLocationCache_;
    
    FluidStatus computeAquifer(int particleX, int particleY, int particleZ);
    static int64_t packLocation(int gx, int gy, int gz);
    static double similarity(int64_t d1, int64_t d2);
};

}
```

**关键工程选择**：

1. **缓存数组用 `std::vector` 而非 `std::array`**：覆盖范围是 chunk 大小动态的。
2. **packLocation 用 long 编码 (gridX, gridY, gridZ)**：照搬 Java 实现。
3. **BlockState 共享指针**：FluidStatus 内的 fluidType 是 `const BlockState*`。

## 3.9.12 一句话总结

Aquifer 是 1.18 引入的"地下水位系统"——把世界划分为 16×12×16 grid，每格点放一个 FluidStatus 流体粒子（fluidLevel + fluidType），任意位置查最近 3 粒子加权决定填水 / 熔岩 / 石墙 / 空气；4 个 aquifer noise 通道（barrier / floodedness / spread / lava）控制粒子参数；fluidPicker 给默认水位（主世界 = 海平面 63；Y < -54 → lava）；Aquifer 在 NOISE 阶段执行，与 OreVeinifier 共同决定每格 BlockState；性能 ~1-2 ms / chunk；视觉效果是地下经常出现湖、深处经常出现岩浆，比 1.17 之前的"全石头洞穴"丰富得多。
