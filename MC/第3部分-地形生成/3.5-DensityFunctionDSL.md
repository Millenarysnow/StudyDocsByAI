## 3.5.1 历史背景：为什么 1.18 重写

**1.17 之前**：Minecraft 的地形生成是**硬编码 Java 代码**——`OverworldChunkGenerator` 类直接写出一系列 `if (biome == DESERT) { density *= 0.5 } else if (biome == MOUNTAINS) { density += noise * 2 }`。

**问题**：

1. 加新 biome 必须改 Java、重编译、发版本。
2. modder 想改地形必须用 Forge / Fabric mixin 注入。
3. 内部测试一种新地形要在数百行 Java 间游走。
4. 数据驱动 datapack 完全无法触及地形。

**1.18 重写**：把"决定每格是固体还是空气"完全数据化：

- 整个 worldgen 的核心运算变成"组合一个**密度函数树**，对每格调用 `tree.compute(x, y, z) → double`，> 0 = 固体，< 0 = 空气"。
- 这个树是 datapack JSON 配方，运行时 Codec 解析。
- 树的节点是约 30 种内置算子（数学运算、噪声采样、形状变换、缓存）。
- 主世界的 finalDensity 函数树**约 60 层、几百个节点**——但**完全数据化**。

**Mojang 内部把这套东西叫 Density Function DSL**。这是 Henrik Kniberg 团队 2021 年的工程胜利——它既保持了 Mojang 自己迭代的灵活性，又开放给 modder。

## 3.5.2 DensityFunction 接口

打开 `net.minecraft.world.level.levelgen.DensityFunction`：

```java
public interface DensityFunction {
    Codec<DensityFunction> DIRECT_CODEC = DensityFunctions.DIRECT_CODEC;
    Codec<Holder<DensityFunction>> CODEC = RegistryFileCodec.create(Registries.DENSITY_FUNCTION, DIRECT_CODEC);
    
    double compute(FunctionContext ctx);
    void fillArray(double[] arr, ContextProvider provider);
    DensityFunction mapAll(Visitor visitor);
    double minValue();
    double maxValue();
    KeyDispatchDataCodec<? extends DensityFunction> codec();
    
    // 默认实现的 builder 方法
    default DensityFunction clamp(double min, double max);
    default DensityFunction abs();
    default DensityFunction square();
    default DensityFunction cube();
    default DensityFunction halfNegative();
    default DensityFunction quarterNegative();
    default DensityFunction squeeze();
}
```

**6 个核心方法**：

1. **`compute(ctx) → double`**：单点求值。`ctx` 提供 (x, y, z) + Blender。
2. **`fillArray(arr, provider)`**：批处理求值。一次填充多个点。这是**性能关键**——批处理比单点循环快 5-10×。
3. **`mapAll(visitor)`**：把树中所有节点用 visitor 转换。用于"插入 cache 节点"等优化。
4. **`minValue()` / `maxValue()`**：编译期的输出范围。给优化器（如 RangeChoice 短路判断）用。
5. **`codec()`**：让 datapack JSON 反序列化时找到"这是哪种 DSL 节点"。

**`FunctionContext` 接口**：

```java
public interface FunctionContext {
    int blockX();
    int blockY();
    int blockZ();
    default Blender getBlender() { return Blender.empty(); }
}
```

**`ContextProvider` 接口**（给 fillArray 用）：

```java
public interface ContextProvider {
    FunctionContext forIndex(int index);
    void fillAllDirectly(double[] arr, DensityFunction f);
}
```

## 3.5.3 30 种内置算子总览

打开 `net.minecraft.world.level.levelgen.DensityFunctions`（约 1500 行）。它包含所有内置算子的**实现**与 **codec 注册**。

按用途分组：

### 常量与噪声源

| 算子 | 含义 |
|------|------|
| `Constant(value)` | 常数（如 `0.5`） |
| `Noise(noise, xzScale, yScale)` | 包装一个 NormalNoise 实例 |
| `ShiftedNoise(shiftX, shiftY, shiftZ, xzScale, yScale, noise)` | Noise 但坐标先经过 shift 函数 |
| `ShiftA(noise)` | 取 noise(x, 0, z) ★ 4，用于 biome 抖动 |
| `ShiftB(noise)` | 取 noise(z, x, 0) ★ 4，用于 biome 抖动 |

### 算术

| 算子 | 含义 |
|------|------|
| `Add(a, b)` | a + b |
| `Mul(a, b)` | a × b |
| `Min(a, b)` | min(a, b) |
| `Max(a, b)` | max(a, b) |
| `Mapped(input, type)` | 一元变换：ABS / SQUARE / CUBE / HALF_NEGATIVE / QUARTER_NEGATIVE / SQUEEZE |

### 形状

| 算子 | 含义 |
|------|------|
| `Spline(splineDef, minValue, maxValue)` | spline 插值（折线 / Catmull-Rom） |
| `Clamp(input, min, max)` | clamp 到 [min, max] |
| `RangeChoice(input, minInclusive, maxExclusive, whenInRange, whenOutOfRange)` | 区间分支：input 在 [min,max) 时用 a，否则用 b |
| `YClampedGradient(fromY, toY, fromValue, toValue)` | 沿 Y 线性渐变 |

### 缓存

| 算子 | 含义 |
|------|------|
| `Cache2D(input)` | XZ 缓存（同列的 Y 复用） |
| `FlatCache(input)` | 类似 Cache2D 但跨 cell 共享 |
| `OnceCache(input)` | 单点缓存（避免短期内多次重算同点） |
| `CacheAllInCell(input)` | cell 内全部缓存 |
| `Interpolated(input)` | cell 角点采样、cell 内插值 |

### 引用

| 算子 | 含义 |
|------|------|
| `HolderHolder(holder)` | 延迟绑定一个 Holder<DensityFunction> |
| `MarkerOrMarked` | 标记节点（让 Cache 这种"想被特别处理"的节点参与 visit） |

### 混合

| 算子 | 含义 |
|------|------|
| `BlendDensity(input)` | 与旧 chunk 边界融合 |
| `BlendAlpha` | 融合权重 |
| `BlendOffset` | 融合 Y offset |

### 终端魔法

| 算子 | 含义 |
|------|------|
| `EndIslands(seed)` | 末地大岛硬编码生成（特殊算子） |
| `WeirdScaledSampler(input, noise, mapper)` | 1.18+ 特殊：让 weirdness 缩放某 noise |

## 3.5.4 几个关键算子源码剖析

### Constant

```java
public static record Constant(double value) implements DensityFunction.SimpleFunction {
    public static final Constant ZERO = new Constant(0.0);
    public static final KeyDispatchDataCodec<Constant> CODEC = ...;
    
    @Override public double compute(FunctionContext ctx) { return this.value; }
    @Override public double minValue() { return this.value; }
    @Override public double maxValue() { return this.value; }
}
```

最简单的算子——返回常数。

### Noise

```java
public static record Noise(Holder<NormalNoise.NoiseParameters> noiseData, double xzScale, double yScale) implements DensityFunction {
    @Override
    public double compute(FunctionContext ctx) {
        return this.noise.getValue(
            ctx.blockX() * this.xzScale,
            ctx.blockY() * this.yScale,
            ctx.blockZ() * this.xzScale
        );
    }
    @Override public double minValue() { return -this.maxValue(); }
    @Override public double maxValue() { return this.noise.maxValue(); }
}
```

**一个 noise wrapper**——把世界坐标按 xzScale / yScale 缩放后查 NormalNoise。

`xzScale = 0.25` 意味着"世界坐标 x=4 → noise 输入 1"。即一个完整的 noise 周期跨越 4 倍世界距离。

### Add / Mul / Min / Max

```java
public static record Ap2(Type type, DensityFunction argument1, DensityFunction argument2, double minValue, double maxValue) implements TwoArgumentSimpleFunction {
    @Override
    public double compute(FunctionContext ctx) {
        double a = this.argument1.compute(ctx);
        return switch (this.type) {
            case ADD -> a + this.argument2.compute(ctx);
            case MUL -> a == 0.0 ? 0.0 : a * this.argument2.compute(ctx);
            case MIN -> a < this.argument2.minValue() ? a : Math.min(a, this.argument2.compute(ctx));
            case MAX -> a > this.argument2.maxValue() ? a : Math.max(a, this.argument2.compute(ctx));
        };
    }
}
```

**注意短路优化**：

- `MUL`：如果 `argument1 == 0`，**不计算 argument2**（结果一定是 0）。
- `MIN`：如果 `argument1 < argument2.minValue()`，结果一定是 argument1，**不计算 argument2**。
- `MAX`：类似。

这种短路在密度函数树里**非常常见**——比如计算"地下密度"时，先 cheap 检查 cave layer 噪声，cave layer < 0 直接 0，不用算昂贵的 spaghetti 3D 噪声。**性能提升常见 3-10×**。

### Mapped：一元变换

```java
public static record Mapped(Type type, DensityFunction input, double minValue, double maxValue) implements DensityFunction {
    public enum Type { ABS, SQUARE, CUBE, HALF_NEGATIVE, QUARTER_NEGATIVE, SQUEEZE }
    
    @Override
    public double compute(FunctionContext ctx) {
        double x = this.input.compute(ctx);
        return switch (this.type) {
            case ABS -> Math.abs(x);
            case SQUARE -> x * x;
            case CUBE -> x * x * x;
            case HALF_NEGATIVE -> x > 0.0 ? x : x * 0.5;
            case QUARTER_NEGATIVE -> x > 0.0 ? x : x * 0.25;
            case SQUEEZE -> x = Mth.clamp(x, -1.0, 1.0); x / 2.0 - x * x * x / 24.0;
        };
    }
}
```

**6 种一元变换**：

- `ABS`：绝对值。weirdness → PV 用这个。
- `SQUARE` / `CUBE`：x² / x³。
- `HALF_NEGATIVE`：让负值减半（输入 -1 → 输出 -0.5）。
- `QUARTER_NEGATIVE`：让负值变 1/4。这两个用在"地形低于 0 时不那么强"。
- `SQUEEZE`：(x/2 - x³/24) 的"弱压缩"。让中间值压扁、极值放大。

### Spline

```java
public static record Spline(CubicSpline<SplinePoint, ToFloatFunction<SplinePoint>> spline) implements DensityFunction {
    @Override
    public double compute(FunctionContext ctx) {
        return this.spline.apply(new SplinePoint(ctx));
    }
}
```

**这是地形最复杂的算子**——CubicSpline 是 Mojang 自家实现的多变量样条插值。给定多个 (input, output) 控制点，对任意输入返回光滑插值的输出。

主世界的 OFFSET / FACTOR / JAGGEDNESS 三个 spline 是地形高度的核心。后面 3.5.10 详细展开。

### Cache2D / FlatCache / OnceCache / CacheAllInCell

```java
public static class Cache2D implements DensityFunction {
    private final DensityFunction wrapped;
    private long lastPos = NEG_INF;
    private double lastValue;
    
    @Override
    public double compute(FunctionContext ctx) {
        long pos = ChunkPos.asLong(ctx.blockX(), ctx.blockZ());
        if (pos == this.lastPos) return this.lastValue;
        this.lastPos = pos;
        return this.lastValue = this.wrapped.compute(ctx);
    }
}
```

**只对 (x, z) 缓存最近一次值**——同一 (x, z) 任意 Y 复用。

- 适用：纯 2D 噪声（如 continentalness 不依赖 Y）。在垂直扫描某列时，每个 Y 都查同一 noise，缓存命中 ≈ 100%。
- 性能：~10× 加速。

`FlatCache` 类似但**跨 chunk 共享**。`OnceCache` 是栈上 1-slot 缓存。`CacheAllInCell` 缓存整个 cell 的所有点。

### Interpolated

```java
public static record Interpolated(DensityFunction wrapped) implements DensityFunction {
    @Override
    public double compute(FunctionContext ctx) {
        // 1. 找到当前点所在 cell 的 8 个角点
        // 2. 对 8 角点求 wrapped.compute()
        // 3. 三线性插值
    }
}
```

**关键性能优化**：把昂贵的密度函数（多 noise 叠加 + spline）只在 cell 角点上算，cell 内点用插值。**比朴素逐点算快 64×**（一个 cell = 4×8×4 = 128 点）。

代价：cell 内分辨率降低（4×8×4 → 1×1×1）。Mojang 觉得这点损失不影响视觉效果。

后面 3.6 节 NoiseChunk 详细展开。

### RangeChoice

```java
public static record RangeChoice(DensityFunction input, double minInclusive, double maxExclusive, DensityFunction whenInRange, DensityFunction whenOutOfRange) implements DensityFunction {
    @Override
    public double compute(FunctionContext ctx) {
        double v = this.input.compute(ctx);
        return v >= this.minInclusive && v < this.maxExclusive 
            ? this.whenInRange.compute(ctx) 
            : this.whenOutOfRange.compute(ctx);
    }
}
```

**条件分支**——根据 input 的范围决定走哪个分支。这是 1.18+ 地形"按 Y 区域不同行为"的实现：

```
y_above_sea_level (Y > 64) → 用 spline 高度公式
y_underground     (Y < 0)  → 用 cave noise 公式
y_in_between              → 用 transition spline
```

每种"区域"是一个 RangeChoice 节点，input 是 Y 坐标。

### YClampedGradient

```java
public static record YClampedGradient(int fromY, int toY, double fromValue, double toValue) implements DensityFunction {
    @Override
    public double compute(FunctionContext ctx) {
        return Mth.clampedMap(ctx.blockY(), this.fromY, this.toY, this.fromValue, this.toValue);
    }
}
```

**沿 Y 轴的线性渐变**——`Y < fromY` 返回 fromValue、`Y > toY` 返回 toValue、之间线性。

用途：地表向下的"密度梯度"——Y < -64 时密度大（实心岩石）、Y > 256 时密度小（空气）、之间渐变。

### BlendDensity（旧 / 新地形融合）

```java
public static record BlendDensity(DensityFunction input) implements DensityFunction {
    @Override
    public double compute(FunctionContext ctx) {
        return ctx.getBlender().blendDensity(ctx, this.input.compute(ctx));
    }
}
```

调用 `ctx.getBlender()` 得到 Blender 对象——它知道当前 chunk 是不是邻接老 chunk。如果是，会在边界处用老地形噪声覆盖输入密度，产生平滑过渡。

详细机制超出本节范围（涉及 1.18 升级老地图的特殊处理）。

## 3.5.5 NoiseRouter：八通道路由器

**`NoiseRouter` 不是单一密度函数，而是 15 个命名输出通道的捆绑**：

```java
public record NoiseRouter(
    DensityFunction barrierNoise,                         // Aquifer 用
    DensityFunction fluidLevelFloodednessNoise,           // Aquifer 用
    DensityFunction fluidLevelSpreadNoise,                // Aquifer 用
    DensityFunction lavaNoise,                             // Aquifer 用
    DensityFunction temperature,                           // Biome 采样用
    DensityFunction vegetation,                            // Biome 采样用（即 humidity）
    DensityFunction continents,                            // Biome 采样用
    DensityFunction erosion,                               // Biome 采样用
    DensityFunction depth,                                 // Biome 采样用（导出）
    DensityFunction ridges,                                // Biome 采样用（即 weirdness）
    DensityFunction initialDensityWithoutJaggedness,       // 用于 Aquifer / 简略地表估算
    DensityFunction finalDensity,                          // ★ 主地形：决定每格固体/空气
    DensityFunction veinToggle,                            // OreVeinifier 用
    DensityFunction veinRidged,                            // OreVeinifier 用
    DensityFunction veinGap                                // OreVeinifier 用
) { ... }
```

**15 个通道**，按用途分组：

1. **Aquifer 通道（4）**：barrierNoise / fluidLevelFloodednessNoise / fluidLevelSpreadNoise / lavaNoise。给 Aquifer 系统决定"这格是不是被水填满"。
2. **Biome 采样通道（6）**：temperature / vegetation / continents / erosion / depth / ridges。给 MultiNoiseBiomeSource 决定 biome（3.7 节）。
3. **地形主通道（2）**：initialDensityWithoutJaggedness / finalDensity。**finalDensity 是地形最关键的输出**——决定每格固体或空气。
4. **矿脉通道（3）**：veinToggle / veinRidged / veinGap。给 OreVeinifier 决定矿脉（3.11 节）。

**`mapAll(visitor)`** 把所有 15 个通道用 visitor 转换——用于"插入 Interpolated cache" 等优化。

每个通道都是一棵密度函数树。整个 NoiseRouter 是 datapack 配方 `data/minecraft/worldgen/noise_settings/overworld.json` 的核心。

## 3.5.7 主世界 finalDensity 的组装（鸟瞰）

```
finalDensity
    │
    │ = SLOPED_CHEESE 与 cave 系噪声的复杂组合
    ▼
SLOPED_CHEESE
    │
    │ = OFFSET + FACTOR × (BASE_3D_NOISE - JAGGEDNESS)
    ▼
OFFSET
    │
    │ = -0.5 + spline_offset(continents, erosion, ridges_folded)
    ▼
FACTOR
    │
    │ = spline_factor(continents, erosion, ridges_folded)
    ▼
JAGGEDNESS
    │
    │ = spline_jaggedness(continents, erosion, ridges_folded) × jagged_noise
    ▼
BASE_3D_NOISE_OVERWORLD
    │
    │ = BlendedNoise (一个特殊的 4D 噪声 wrapper，与旧地形融合用)
```

**核心：三个 spline + 一个 base 3D noise**：

- **OFFSET**：世界平均高度的 baseline。值大致 [-0.5, 0.5]（实际 [-1.5, 0.5]）。
- **FACTOR**：高度变化的强度。值大致 [0, 6]。
- **JAGGEDNESS**：山脊的"尖锐度"。值大致 [0, 0.6] × 山脊噪声。
- **BASE_3D_NOISE**：4D 噪声（带 Y），让密度有自然的 3D 变化。

**几何含义**：

```
finalDensity(x, y, z) ≈ OFFSET(x, z) - SLOPE × Y + FACTOR(x, z) × NOISE_3D(x, y, z) - JAGGEDNESS
```

读法：

- 在某个 (x, z) 上，`OFFSET` 给一个"基础高度"。
- 沿 Y 向上，密度逐渐从正变负（负 = 空气）。`-SLOPE × Y` 项决定。
- `FACTOR × NOISE_3D` 在基础高度附近"加扰动"——决定山多还是平。
- `JAGGEDNESS` 让山顶变尖。

**这就是为什么 1.18+ 世界视觉上的"丘陵 / 山脉 / 高原 / 平原"取决于五大气候参数**——它们驱动 OFFSET / FACTOR / JAGGEDNESS 三个 spline 的输出。

## 3.5.8 三大 Spline 详解

主世界最关键的几个 spline 是 OFFSET / FACTOR / JAGGEDNESS 的内核。每个 spline 把 `(continentalness, erosion, ridges_folded)` 的 3 维输入映射到一个 float。

**继续展开 OFFSET spline**：它本身是个嵌套 spline（一个 spline 的"输出"作为另一个 spline 的"控制点"）。Mojang 用 Java 代码硬编码这些（在 `OverworldBiomeBuilder` / `Splines` 类中）。

```java
// 简化伪码
Spline offset = Splines.offsetSpline(...);

double offsetValue = offset.apply(new SplinePoint(continents, erosion, ridges));
```

**为什么用 spline**？因为五大气候参数 → 高度的映射不是简单线性。比如 continents = -0.4 时（深海）高度应该 < seaLevel；continents = 0 时（海岸）高度 = seaLevel；continents = 0.5 时（内陆）高度可以更高（如 100）。这是个**分段非线性**关系。Spline 给你光滑的分段。

**Mojang 在 splines 里直接写死控制点**：

```java
ToFloatFunction.Spline offsetSpline = Splines.spline(
    Splines.point(-0.45, -2.2),       // 深海：最低
    Splines.point(-0.3,  -1.5),
    Splines.point(-0.15, -0.8),       // 浅海
    Splines.point(-0.05, -0.4),       // 海岸
    Splines.point(0.0,    0.0),       // 海平面起点
    Splines.point(0.4,    0.6),       // 内陆
    Splines.point(0.7,    1.2),       // 高地
    Splines.point(1.0,    1.5)
);
```

（实际控制点更多、更复杂，且嵌套了 erosion / ridges 维度。）

**调试工具**：[Misode 的 Worldgen Visualizer](https://misode.github.io/worldgen) 里 spline 可视化非常清晰，强烈推荐边读 source 边对照。

```json
{
    "type": "minecraft:add",
    "argument1": {
        "type": "minecraft:add",
        "argument1": {
            "type": "minecraft:density_function",
            "argument": "minecraft:overworld/offset"
        },
        "argument2": {
            "type": "minecraft:mul",
            "argument1": {
                "type": "minecraft:density_function",
                "argument": "minecraft:overworld/factor"
            },
            "argument2": {
                "type": "minecraft:density_function",
                "argument": "minecraft:overworld/depth"
            }
        }
    },
    "argument2": {
        "type": "minecraft:density_function",
        "argument": "minecraft:overworld/jaggedness"
    }
}
```

**JSON 是函数树的字符串表示**：

- `type` 字段（如 `minecraft:add`）告诉 Codec 这是哪种 DSL 节点。
- 其他字段（`argument1`、`argument2`）是子节点。
- `minecraft:density_function` 类型的节点引用另一个 JSON 文件（用 `argument` 字段是 ResourceLocation）——这是 datapack 文件分组的方式。

**整个主世界 finalDensity 树涉及约 30 个 JSON 文件**，互相引用。Mojang 把它们组织在 `data/minecraft/worldgen/density_function/overworld/` 子目录。

**Modder 可以**：

- 覆盖 `data/minecraft/worldgen/density_function/overworld/sloped_cheese.json` 替换主世界形状。
- 加新 JSON 配置一个全新的密度函数。
- 在 `noise_settings/overworld.json` 里调引用。

**完全数据化**——不写一行 Java，能彻底改地形。这就是 Mojang 1.18 的工程胜利。

## 3.5.10 性能优化：Cache 与 Interpolation

**问题**：朴素的 finalDensity 树有约 60 层 + 几百个节点。对 chunk 内每格调一次 `tree.compute(x, y, z)` = 16×384×16 × 几百次操作 ≈ **千万次乘法**。每个 chunk 几秒，无法接受。

**Mojang 的优化**：

### 1. Interpolated cache

把昂贵的子树（如 SLOPED_CHEESE）包成 Interpolated。只在 4×8×4 = 128 点的 cell 角点求值。cell 内点用三线性插值。**128 倍加速**，视觉差异忽略不计。

### 2. Cache2D for 2D 噪声

continentalness、erosion 等不依赖 Y 的子树包成 Cache2D。同列 Y 复用。**~24 倍加速**（chunk 24 个 section × 16 Y）。

### 3. FlatCache

`(x, z)` 同的相邻 chunk 共享。比 Cache2D 多一层。

### 4. mapAll + visitor

mapAll 在 worldgen 启动时**一次性**把树中所有合适节点替换成 cache 版本：

```java
NoiseRouter optimized = router.mapAll(new InterpolatedNoiseFactory());
```

InterpolatedNoiseFactory 是个 Visitor，识别"可缓存"模式（如 `Mul(2DNoise, *) + Spline(3DNoise)`）并插入 Cache2D / Interpolated 节点。

**优化后**：原本一个 chunk 几秒 → 50-200 ms。流水线时这是 NOISE 阶段最大头。

## 3.5.11 NoiseChunk：DSL 求值的实际容器

## 3.5.12 内存预算

```
NoiseRouter (15 channels):
  每个 channel 是 DensityFunction 树
```

## 3.5.13 C++ 移植

```cpp
namespace mc::density {

class FunctionContext {
public:
    virtual ~FunctionContext() = default;
    virtual int blockX() const = 0;
    virtual int blockY() const = 0;
    virtual int blockZ() const = 0;
    virtual Blender* getBlender() const { return nullptr; }
};

class ContextProvider {
public:
    virtual ~ContextProvider() = default;
    virtual FunctionContext& forIndex(int index) = 0;
};

class DensityFunction {
public:
    virtual ~DensityFunction() = default;
    virtual double compute(const FunctionContext& ctx) const = 0;
    virtual void fillArray(std::span<double> out, ContextProvider& provider) const {
        for (size_t i = 0; i < out.size(); i++) out[i] = compute(provider.forIndex(int(i)));
    }
    virtual double minValue() const = 0;
    virtual double maxValue() const = 0;
};

// 具体算子
class Constant : public DensityFunction {
public:
    explicit Constant(double v) : value_(v) {}
    double compute(const FunctionContext&) const override { return value_; }
    double minValue() const override { return value_; }
    double maxValue() const override { return value_; }
private:
    double value_;
};

class NoiseDF : public DensityFunction {
public:
    NoiseDF(const NormalNoise* noise, double xzScale, double yScale)
        : noise_(noise), xzScale_(xzScale), yScale_(yScale) {}
    double compute(const FunctionContext& ctx) const override {
        return noise_->getValue(ctx.blockX() * xzScale_,
                                 ctx.blockY() * yScale_,
                                 ctx.blockZ() * xzScale_);
    }
    // ⋯
private:
    const NormalNoise* noise_;
    double xzScale_, yScale_;
};

class AddDF : public DensityFunction {
    std::unique_ptr<DensityFunction> a_, b_;
    double minVal_, maxVal_;
public:
    AddDF(std::unique_ptr<DensityFunction> a, std::unique_ptr<DensityFunction> b)
        : a_(std::move(a)), b_(std::move(b)) {
        minVal_ = a_->minValue() + b_->minValue();
        maxVal_ = a_->maxValue() + b_->maxValue();
    }
    double compute(const FunctionContext& ctx) const override {
        return a_->compute(ctx) + b_->compute(ctx);
    }
    double minValue() const override { return minVal_; }
    double maxValue() const override { return maxVal_; }
};

// ⋯ 类似实现 Mul / Min / Max / Mapped / Spline / Clamp / RangeChoice / Cache2D ⋯

struct NoiseRouter {
    std::unique_ptr<DensityFunction> barrierNoise;
    std::unique_ptr<DensityFunction> fluidLevelFloodednessNoise;
    std::unique_ptr<DensityFunction> fluidLevelSpreadNoise;
    std::unique_ptr<DensityFunction> lavaNoise;
    std::unique_ptr<DensityFunction> temperature;
    std::unique_ptr<DensityFunction> vegetation;
    std::unique_ptr<DensityFunction> continents;
    std::unique_ptr<DensityFunction> erosion;
    std::unique_ptr<DensityFunction> depth;
    std::unique_ptr<DensityFunction> ridges;
    std::unique_ptr<DensityFunction> initialDensityWithoutJaggedness;
    std::unique_ptr<DensityFunction> finalDensity;
    std::unique_ptr<DensityFunction> veinToggle;
    std::unique_ptr<DensityFunction> veinRidged;
    std::unique_ptr<DensityFunction> veinGap;
};

// JSON 解析
std::unique_ptr<DensityFunction> parseDensityFunction(const NbtCompound& json, const Registry<NormalNoise>& noises);

}
```

**关键工程选择**：

1. **virtual function 还是 variant？**
   - 30+ 种节点用 variant 需要列出全部，构造代码复杂。
   - virtual function 一个 vtable indirection，但树深 60，3000+ vtable lookup / 节点 = 性能损失约 5-10%。
   - **第一版用 virtual function**，性能瓶颈再优化。
2. **mapAll 用 visitor 模式**：保留 Java 设计。
3. **Cache 状态用 thread_local 或 per-NoiseChunk 实例**：避免并发问题。
4. **Spline 实现**：可参考 Cubitect cubiomes 的 C 实现。
5. **JSON 解析**：用 0.5 节的 Codec 系统或者手写树形 parser。

**性能 target**：实现完整的 NoiseRouter 后，单 chunk NOISE 阶段应当 < 100 ms。如果 >> 这个数，多半是 cache 没正确插入或 Mul 短路没实现。

## 3.5.14 实战：跟踪一个点的密度计算

给定 worldSeed = 1，坐标 (100, 80, 100)：

```
0. ctx = SimpleContext(100, 80, 100)
1. router.finalDensity.compute(ctx) 入口
2. 它是 Add 节点：
   - argument1 (左子树): SLOPED_CHEESE
   - argument2 (右子树): cave_system 加权变换
3. 递归 SLOPED_CHEESE.compute(ctx)：
   - 它是 Add 节点：argument1 = OFFSET + FACTOR × DEPTH，argument2 = -JAGGEDNESS
4. 递归 OFFSET：是 Add(常量 -0.5, Spline(continentalness, erosion, ridges))
5. 递归 Spline.compute：
   - 调 spline.apply(SplinePoint(ctx))
   - SplinePoint 内部调 continentalness.compute(ctx) → say -0.05
   - 再调 erosion.compute(ctx) → say 0.4
   - 再调 ridges_folded.compute(ctx) → say 0.2
   - spline 在三维空间插值得到 say 0.1
6. OFFSET = -0.5 + 0.1 = -0.4
7. ⋯ FACTOR / JAGGEDNESS 类似展开，每个都内嵌 spline + noise
8. SLOPED_CHEESE = OFFSET + FACTOR × DEPTH - JAGGEDNESS
   假设 = -0.4 + 2.0 × 0.3 - 0.05 = 0.15
9. cave 噪声分支：cave noise(100, 80, 100) = -0.05
10. finalDensity = max(0.15, ...) - cave subtraction = 0.10
11. 返回 0.10 → > 0 → 这格是固体

总计 ~20 次 noise sample + ~50 次算术。约 20 微秒。
```

## 3.5.15 一句话总结

1.18 引入的 Density Function DSL 把"决定每格固体 / 空气"完全数据化——~30 种内置算子（Constant / Noise / Add / Mul / Min / Max / Mapped / Spline / Clamp / Cache / Interpolated / RangeChoice / BlendDensity ⋯⋯）组合成一棵密度函数树；`NoiseRouter` 是 15 通道捆绑（4 aquifer + 6 biome 采样 + 2 主地形 + 3 矿脉），其中 `finalDensity` 决定每格固体性；主世界配方在 Java 端是 `NoiseRouterData`，在 datapack 端是约 30 个 `density_function/*.json`；核心结构是 `OFFSET + FACTOR × NOISE_3D - JAGGEDNESS`，三大 spline 把 5 维气候参数映射到地形高度；性能优化通过 Interpolated（cell 角点 + 三线性插值，~128×）、Cache2D（XZ 缓存，~24×）、Mul/Min 短路实现；C++ 移植可用 virtual function，整个 chunk 的 NOISE 阶段目标 < 100 ms。
