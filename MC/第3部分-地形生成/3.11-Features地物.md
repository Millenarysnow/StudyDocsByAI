## 3.11.1 三层包装：Feature / ConfiguredFeature / PlacedFeature

### `Feature<C>`：算法模板

每个 Feature 子类只定义"算法逻辑"——不定义参数。

**PlacementModifier 系列**（约 20 种）：

| Modifier | 含义 |
|----------|------|
| `count_random` | 在 chunk 内尝试 N 次（N 是随机的） |

| `height_range` | Y 范围 |
| `biome` | 检查当前位置 biome 是否允许 |
| `rarity` | rarity in N 几率 |
| `block_predicate` | 当前方块是否符合谓词 |

## 3.11.2 GenerationStep.Decoration：10 个步骤

打开 `net.minecraft.world.level.levelgen.GenerationStep`：

```java
public class GenerationStep {
    public enum Decoration {
        RAW_GENERATION,            // 0
        LAKES,                     // 1
        LOCAL_MODIFICATIONS,       // 2
        UNDERGROUND_STRUCTURES,    // 3
        SURFACE_STRUCTURES,        // 4
        STRONGHOLDS,               // 5
        UNDERGROUND_ORES,          // 6
        UNDERGROUND_DECORATION,    // 7
        FLUID_SPRINGS,             // 8
        VEGETAL_DECORATION,        // 9
        TOP_LAYER_MODIFICATION     // 10
    }
}
```

**11 个枚举值**（其实是 11 个，但常说"10 步"是因为 `RAW_GENERATION` 几乎不用）。每个 biome 在每步贡献一个 `List<Holder<PlacedFeature>>`：

```java
// Biome.java
public class BiomeGenerationSettings {
    private final List<HolderSet<PlacedFeature>> features;     // 11 个 list
    
    public List<HolderSet<PlacedFeature>> features() { return this.features; }
}
```

**FEATURES 阶段**对每个 biome × 每个 step 跑：

```
for step in 0..11:
    for biome in chunk_biomes:
        for placedFeature in biome.features[step]:
            placedFeature.place(...)
```

**11 步的语义**：

| Step | 用途 |
|------|------|
| 0 RAW_GENERATION | 极少用，给最早期生成插入特殊东西 |
| 1 LAKES | 老式湖泊（1.18+ 大部分被 noise cave 取代） |
| 2 LOCAL_MODIFICATIONS | 局部修改（晶洞 / 钟乳石簇） |
| 3 UNDERGROUND_STRUCTURES | 地下小结构（怪物刷怪笼房间 monster_room） |
| 4 SURFACE_STRUCTURES | 地表小结构 |
| 5 STRONGHOLDS | 要塞（特殊：唯一在 features 阶段处理结构的，因为 stronghold 是世界种子级单点结构） |
| 6 UNDERGROUND_ORES | 矿物（煤矿 / 铁矿 / 铜矿 / 金矿 / 钻石 / 红石 / 青金石 / 绿宝石） |
| 7 UNDERGROUND_DECORATION | 地下装饰（藤蔓、瀑布顶板、青苔块） |
| 8 FLUID_SPRINGS | 水/熔岩泉（地下随机出现的水源块） |
| 9 VEGETAL_DECORATION | 植被（草、花、树、竹子） |
| 10 TOP_LAYER_MODIFICATION | 顶层修改（雪盖、冰冻水面） |

**为什么按这个顺序**：

- 矿物（6）必须在树（9）之前——避免树根穿过矿物。
- 雪盖（10）必须在所有 feature 之后——它检查"当前地表"决定要不要覆雪。
- 要塞（5）必须在矿物（6）之前——避免要塞墙被矿物穿。

## 3.11.3 FEATURES 阶段的执行

打开 `ChunkGenerator.applyBiomeDecoration`（简化）：

```java
public void applyBiomeDecoration(WorldGenLevel level, ChunkAccess chunk, StructureManager structureManager) {
    ChunkPos chunkPos = chunk.getPos();
    if (SharedConstants.debugVoidTerrain(chunkPos)) return;
    
    SectionPos sectionPos = SectionPos.of(chunkPos, level.getMinSectionY());
    BlockPos blockPos = sectionPos.origin();
    Registry<Structure> structures = level.registryAccess().registryOrThrow(Registries.STRUCTURE);
    Map<Integer, List<Structure>> structuresByStep = structures.stream()
        .collect(Collectors.groupingBy(s -> s.step().ordinal()));
    
    List<BiomeSource.StepFeatureData> generationSettings = ...;     // biome 排好序的 feature 列表
    
    WorldgenRandom random = new WorldgenRandom(new XoroshiroRandomSource(...));
    long decorationSeed = random.setDecorationSeed(level.getSeed(), blockPos.getX(), blockPos.getZ());
    
    Set<Holder<Biome>> biomesInChunk = ...;
    
    for (int step = 0; step < GenerationStep.Decoration.values().length; step++) {
        // 1. 先处理结构（在该 step 注册的）
        if (structureManager.shouldGenerateStructures()) {
            for (Structure structure : structuresByStep.getOrDefault(step, List.of())) {
                random.setFeatureSeed(decorationSeed, featureIdx, step);
                Supplier<String> contextProvider = () -> structure.toString();
                structureManager.startsForStructure(sectionPos, structure)
                    .forEach(s -> s.placeInChunk(level, structureManager, gen, random, ..., chunkPos));
            }
        }
        
        // 2. 然后处理该 step 注册的 PlacedFeature
        for (BiomeSource.StepFeatureData stepData : generationSettings) {
            if (biomesInChunk.contains(stepData.biome())) {
                List<Holder<PlacedFeature>> features = stepData.featureSet().get(step);
                for (Holder<PlacedFeature> placedFeature : features) {
                    random.setFeatureSeed(decorationSeed, featureIdx, step);
                    try {
                        placedFeature.value().placeWithBiomeCheck(level, gen, random, blockPos);
                    } catch (Exception e) { ... }
                }
            }
        }
    }
}
```

**关键步骤**：

1. **`setDecorationSeed`** 给本 chunk 派生"装饰起点种子"（同 worldSeed + chunkPos = 同种子）。
2. 对每个 step：
   - 处理该 step 的 Structure piece。
   - 处理该 step 的 PlacedFeature。
3. 每个 feature 调用前 **`setFeatureSeed`** 重置种子——保证不同 feature 互不干扰。

**这就是为什么 worldSeed 完全决定 feature 分布**——所有种子派生都是 deterministic。

## 3.11.4 PlacedFeature.placeWithBiomeCheck

```java
public boolean placeWithBiomeCheck(WorldGenLevel level, ChunkGenerator gen, RandomSource random, BlockPos origin) {
    return this.placeInternal(...)
        ? true
        : false;
}

private boolean placeInternal(...) {
    PlacementContext ctx = new PlacementContext(level, gen, Optional.of(this));
    ConfiguredFeature<?, ?> configFeature = this.feature.value();
    Stream<BlockPos> positions = Stream.of(origin);
    for (PlacementModifier modifier : this.placement) {
        positions = positions.flatMap(pos -> modifier.getPositions(ctx, random, pos));
    }
    boolean anyPlaced = false;
    for (BlockPos pos : positions.toList()) {
        if (configFeature.place(level, gen, random, pos)) {
            anyPlaced = true;
        }
    }
    return anyPlaced;
}
```

**核心**：

1. PlacementModifier 链：每个 modifier 的 `getPositions(...)` 接受一个 BlockPos 流、返回新的 BlockPos 流。
2. **每个 modifier 可以扩展 / 过滤**——`count_random(5)` 把 1 个位置变成 5 个；`heightmap(MOTION_BLOCKING)` 把每个位置的 Y 设为地表；`biome()` 过滤掉 biome 不匹配的位置。
3. 最终的位置流喂给 `configFeature.place(..., pos)`。

### TreeFeature.place 的算法（极简化）

```java
@Override
public boolean place(FeaturePlaceContext<TreeConfiguration> ctx) {
    WorldGenLevel level = ctx.level();
    BlockPos origin = ctx.origin();
    TreeConfiguration config = ctx.config();
    RandomSource random = ctx.random();
    
    // 1. 判断 origin 下方是不是合适的"地面"
    BlockState below = level.getBlockState(origin.below());
    if (!validGroundBlock(below)) return false;
    
    // 2. 在 origin 下方设 dirt（如果需要）
    if (config.forceDirt) {
        level.setBlock(origin.below(), config.dirtProvider.getState(random, origin.below()), 19);
    }
    
    // 3. 决定树高
    int height = config.trunkPlacer.getTreeHeight(random);
    
    // 4. 放树干
    Set<BlockPos> trunkPositions = new HashSet<>();
    BiConsumer<BlockPos, BlockState> trunkSetter = (pos, state) -> {
        trunkPositions.add(pos.immutable());
        level.setBlock(pos, state, 19);
    };
    List<FoliageAttachment> attachments = config.trunkPlacer.placeTrunk(level, trunkSetter, random, height, origin, config);
    
    // 5. 放树叶
    Set<BlockPos> foliagePositions = new HashSet<>();
    BiConsumer<BlockPos, BlockState> foliageSetter = (pos, state) -> {
        foliagePositions.add(pos.immutable());
        level.setBlock(pos, state, 19);
    };
    for (FoliageAttachment attachment : attachments) {
        config.foliagePlacer.createFoliage(level, foliageSetter, random, config, height, attachment, ...);
    }
    
    // 6. 应用 decorators
    TreeDecorator.Context decoratorCtx = new TreeDecorator.Context(level, blockSetter, random, trunkPositions, foliagePositions, ...);
    for (TreeDecorator decorator : config.decorators) {
        decorator.place(decoratorCtx);
    }
    
    return true;
}
```

**整个流程**约 20-50 ms / 树（取决于复杂度）。一个 chunk 通常 0-5 棵树，~50-200 ms 总计。

## 3.11.6 OreFeature：矿物撒点

```java
public class OreFeature extends Feature<OreConfiguration> {

        // 对每格：
        //   - 距椭球中心距离 d
        //   - rng 抽 size 次随机决定这格是不是 ore
        //   - 检查目标方块是否可替换（ON STONE / ON DEEPSLATE / ON NETHERRACK）
```

## 3.11.7 OreVeinifier：1.18+ 矿脉系统

`OreVeinifier` 不在 FEATURES 阶段——它在 **NOISE 阶段** 嵌入到 NoiseChunk 里！

```java
public class OreVeinifier {
    private static final BlockState RAW_IRON = Blocks.RAW_IRON_BLOCK.defaultBlockState();
    private static final BlockState RAW_COPPER = Blocks.RAW_COPPER_BLOCK.defaultBlockState();
    private static final BlockState GRANITE = Blocks.GRANITE.defaultBlockState();
    private static final BlockState TUFF = Blocks.TUFF.defaultBlockState();
    
    public static NoiseChunk.BlockStateFiller create(
        DensityFunction veinToggle,
        DensityFunction veinRidged,
        DensityFunction veinGap,
        PositionalRandomFactory random
    ) {
        return ctx -> {
            int y = ctx.blockY();
            double toggle = veinToggle.compute(ctx);
            int absToggle = Mth.floor(toggle);
            
            VeinType type = absToggle > 0 ? VeinType.COPPER : VeinType.IRON;
            int upperLimit = type.maxY;
            int lowerLimit = type.minY;
            int distFromEdge = Math.min(upperLimit - y, y - lowerLimit);
            
            if (distFromEdge < 0) return null;
            
            double f = Mth.clampedMap(distFromEdge, 0.0, 20.0, -0.2, 0.0);
            if (Math.abs(toggle) + f < 0.4) return null;
            
            RandomSource rng = random.at(ctx.blockX(), ctx.blockY(), ctx.blockZ());
            if (rng.nextFloat() > 0.7F) return null;
            if (veinRidged.compute(ctx) >= 0.0) return null;
            
            double rawOre = Mth.clampedMap(Math.abs(toggle), 0.4, 0.6, 0.1, 0.3);
            if (rng.nextFloat() < rawOre && veinGap.compute(ctx) > -0.3) {
                return type == VeinType.IRON ? RAW_IRON : RAW_COPPER;
            }
            return type.fillerBlock;     // GRANITE / TUFF
        };
    }
}
```

**3 个 noise 通道**（来自 NoiseRouter）：

- `veinToggle`：决定"这里该是铁脉还是铜脉还是不是脉"。
- `veinRidged`：脉的"骨架"——只在 ridged > 0 的位置有脉。
- `veinGap`：脉中的"间隙噪声"——决定这格是 raw_ore_block 还是 filler（granite / tuff）。

**两种脉**：

- **IRON**：Y 范围 [-60, 51]。filler = TUFF。
- **COPPER**：Y 范围 [0, 50]。filler = GRANITE。

**视觉**：

- 1.18+ 你深挖到 deepslate 区域时**经常看到一片 tuff（凝灰岩）+ raw_iron_block** 混合的"矿脉"——长几十格、宽几格、形状不规则。
- 类似 copper 在中等深度的 granite + raw_copper 矿脉。

**这是 1.18+ 玩家发现的"矿脉挖矿"——比传统逐格挖矿石高效 5-10×**。

## 3.11.8 RandomPatch：植被散布

```java
public class RandomPatchConfiguration {
    public final int tries;            // 尝试次数（典型 64）
    public final int xzSpread;         // XZ 散布范围
    public final int ySpread;          // Y 散布范围
    public final Holder<PlacedFeature> feature;
}
```

**算法**：在 origin 周围尝试 N 次：

```java
@Override
public boolean place(FeaturePlaceContext<RandomPatchConfiguration> ctx) {
    int placed = 0;
    BlockPos.MutableBlockPos pos = new BlockPos.MutableBlockPos();
    for (int i = 0; i < config.tries; i++) {
        pos.setWithOffset(origin,
            random.nextInt(config.xzSpread + 1) - random.nextInt(config.xzSpread + 1),
            random.nextInt(config.ySpread + 1) - random.nextInt(config.ySpread + 1),
            random.nextInt(config.xzSpread + 1) - random.nextInt(config.xzSpread + 1));
        if (config.feature.value().place(level, gen, random, pos)) placed++;
    }
    return placed > 0;
}
```

**用途**：草丛、花、蕨类——一个 chunk 里散布几十个独立的小 feature。

## 3.11.14 C++ 移植

```cpp
namespace mc::feature {

class FeatureConfiguration { virtual ~FeatureConfiguration() = default; };

class Feature {
public:
    virtual ~Feature() = default;
    virtual bool place(FeaturePlaceContext& ctx) = 0;
};

template<typename C>
class TypedFeature : public Feature {
public:
    bool place(FeaturePlaceContext& ctx) override {
        return placeTyped(ctx, static_cast<const C&>(ctx.config()));
    }
    virtual bool placeTyped(FeaturePlaceContext&, const C& config) = 0;
};

struct ConfiguredFeature {
    Feature* feature;
    std::unique_ptr<FeatureConfiguration> config;
    
    bool place(WorldGenLevel& level, ChunkGenerator& gen, RandomSource& random, BlockPos origin) {
        FeaturePlaceContext ctx{level, gen, random, origin, this, *config};
        return feature->place(ctx);
    }
};

class PlacementModifier {
public:
    virtual ~PlacementModifier() = default;
    virtual std::vector<BlockPos> getPositions(PlacementContext&, RandomSource&, BlockPos input) = 0;
};

struct PlacedFeature {
    Holder<ConfiguredFeature> feature;
    std::vector<std::unique_ptr<PlacementModifier>> placement;
    
    bool placeWithBiomeCheck(WorldGenLevel& level, ChunkGenerator& gen, RandomSource& random, BlockPos origin);
};

// 几十个具体 Feature 子类...
class TreeFeature : public TypedFeature<TreeConfiguration> { ... };
class OreFeature : public TypedFeature<OreConfiguration> { ... };
class RandomPatchFeature : public TypedFeature<RandomPatchConfiguration> { ... };
// ⋯

class GenerationStep {
public:
    enum class Decoration {
        RAW_GENERATION, LAKES, LOCAL_MODIFICATIONS,
        UNDERGROUND_STRUCTURES, SURFACE_STRUCTURES, STRONGHOLDS,
        UNDERGROUND_ORES, UNDERGROUND_DECORATION,
        FLUID_SPRINGS, VEGETAL_DECORATION, TOP_LAYER_MODIFICATION
    };
};

}
```

**关键工程选择**：

1. **Feature 用 OOP 继承**：~60 个子类、行为差异大、virtual 调用一次性 / 树没多深，性能可接受。
2. **TrunkPlacer / FoliagePlacer / TreeDecorator** 也用 OOP——树木相关共 ~30 个类。
3. **PlacementModifier 用 OOP**。
4. **Biome 持有 `std::vector<std::vector<Holder<PlacedFeature>>>`**（11 个 step × 每 step list）。
5. **FeatureSorter 移植**：拓扑排序算法直接搬。

## 3.11.15 一句话总结

Feature 是 Mojang 的"地物装饰"系统——`Feature<C>` 抽象算法（~60 种） + `ConfiguredFeature` 配置（datapack JSON） + `PlacedFeature` 加放置规则；放置由 `PlacementModifier` 链（count_random / in_square / heightmap / biome / rarity / ⋯）控制；Biome 在 11 个 GenerationStep（RAW → LAKES → ORES → ⋯ → VEGETAL → TOP_LAYER）中各列一份 feature 列表；`TreeFeature` 用 TrunkPlacer + FoliagePlacer + TreeDecorator 三件套组装；`OreFeature` 用椭球 + TargetBlockState 让"stone↔iron_ore / deepslate↔deepslate_iron_ore"自动适配；`OreVeinifier` 1.18+ 在 NOISE 阶段嵌入产生大型矿脉；FEATURES 是流水线唯一 blockStateWriteRadius=1 的 step（可跨 chunk 写）；`FeatureSorter` 拓扑排序保证 feature 全局一致顺序。
