# 第 3 部分 · 地形生成 —— 导读

## 你为什么需要先读这一部分

第 0 部分讲了世界观，第 1 部分讲了 chunk 数据结构，第 2 部分讲了存档持久化。但有一个问题它们都没回答：**当玩家走进一个从未被加载过的区域时，那一块的地形是怎么"凭空"产生的？**

这就是地形生成（worldgen / world generation）模块要回答的问题。它是 Minecraft 整个引擎里**最复杂、最庞大、最有研究价值**的子系统：

- ~30 个核心 Java 类（DensityFunction、NoiseRouter、SurfaceRules、Aquifer、OreVeinifier、Climate、OverworldBiomeBuilder ⋯⋯）
- ~5000 行核心代码 + ~200 个 datapack JSON 配方
- 1.18 时整体重写过一次，1.21 又做了 ChunkStep / ChunkPyramid 重构
- 学术上涉及 Perlin/Simplex 噪声、fBm、密度函数组合代数、空间最近邻查询、splines、3D 体素插值等多个方向
- 工程上涉及多线程流水线、跨 chunk 数据依赖、缓存策略

这一部分**就是教程的"主菜"**。你之前买的"地形生成"票证，到这里入场。

## 你的目标

读完这一部分你应当能：

1. 在脑子里画出一张完整的"chunk worldgen pipeline"图——从 EMPTY 到 FULL 经过 12 个 status，每个 status 干什么、依赖哪些邻居、用哪些组件，全部说得出。
2. **看到任何一个 vanilla 主世界坐标 (x, z)，能定性预测那里长什么样、为什么**——基于五大气候参数（温度 / 湿度 / 大陆性 / 侵蚀度 / 怪异度）的取值。
3. 理解 1.18+ 的 Density Function DSL：能读懂 `data/minecraft/worldgen/density_function/overworld/*.json` 任意配方文件，知道它输出什么、怎么参与最终密度场。
4. 理解 SurfaceRules：知道为什么沙漠是沙、雪原是雪、平原是草，每条规则的条件 / 材料分别是什么。
5. 理解 Aquifer：知道为什么 1.18+ 的洞穴里会出现地下湖。
6. 理解 carver vs noise cave 的协同。
7. 理解 Feature 系统：能看出一棵树、一个矿洞、一个紫水晶簇分别由哪个 Feature + 哪些 PlacementModifier 组成。
8. 理解 Structure：知道村庄、要塞、远古城市怎么跨多 chunk 组装。
9. 理解 1.21 的跨 chunk 写入安全网（`ChunkStep.blockStateWriteRadius` + `WorldGenRegion` + `postProcessing`）。
10. **最重要**：拿到一份能用的 C++ 移植蓝图，知道哪些抽象该照搬、哪些可以替换、哪些可以延后。

## 它和其它部分的关系

```
第 0 部分（基石：坐标、tick、registry、codec）
                                    │
第 1 部分（数据结构：Block / BlockState / Chunk / Section）
                                    │
第 2 部分（存档：NBT / Region / IOWorker）
                                    │
                                    ▼
第 3 部分（你在这里：地形生成）  ← 大量调用前面所有部分
   │
   ├── 用第 0.4 的 Registry / Holder 引用 Biome / Feature / DensityFunction
   ├── 用第 0.5 的 Codec 解析所有 datapack JSON
   ├── 用第 0.3 的 random source 派生子系统种子
   ├── 用第 1 部分的 PalettedContainer 写入 BlockState 与 Biome
   ├── 用第 2 部分的 SerializableChunkData 持久化 ProtoChunk
   └── ⋯⋯
                                    │
                                    ▼
第 4 部分（方块更新）           ← 运行期 tick 改变这些已生成的 chunk
第 5/6 部分（红石/流体）         ← 特化的方块更新
第 7 部分（网络）                ← 同步生成结果给客户端
```

**强依赖**：3.x 的所有讲解都假设你读完了第 0、1 部分。第 2 部分大部分内容相对独立，但 SerializableChunkData（2.6 节）会被 worldgen 引用。

## 实战工具准备

强烈推荐边读边跑：

1. **Cubitect 的 cubiomes**（github.com/Cubitect/cubiomes）：C 语言的 vanilla biome / structure 生成器复刻。它的 source 是绝佳的参考实现，**很多算法在这里比 Minecraft 自身代码更易读**。
2. **Misode 的 Worldgen Visualizer**（misode.github.io/worldgen）：在线交互式可视化所有 datapack 配方（Density Function、Biome、Surface Rule）。
3. **Chunkbase**（chunkbase.com）：在线种子查看器。给个种子能看世界生成结果。
4. **Mojang 官方源**：本仓库 `D:\Minecraft\MCP-Reborn-1.21\src\main\java\net\minecraft\world\level\levelgen\` 与 `biome\`。

## 一句话预告

第 3 部分讲清楚 Mojang 怎么用噪声 + 数据驱动配方"凭空造世界"——12 阶段 ChunkStatus 流水线把每个 chunk 从 EMPTY 推进到 FULL；底层是 6 维气候参数 + 30 种密度函数算子组成的 NoiseRouter，决定每格"是固体还是空气";SurfaceRules 给地表铺草沙雪；Aquifer 给地下铺水位；Carvers 雕洞穴；Features 长树木 + 撒矿物；Structures 拼村庄要塞；Beardifier 让结构与地形顺滑融合；最终 ProtoChunk 升级为 LevelChunk 进入运行期 tick。
