4. 红石信号的"语义"是什么——它表示电流？开关？数字信号？

## 5.1.1 红石是什么

**红石**（Redstone）是 Mojang 在 Beta 1.3（2011 年）引入的"游戏内电路系统"。最初设计仅是给玩家造门 + 简单陷阱。后来玩家社区发现可以搭出复杂电路，催生了一整套 metagame——红石电路设计。

**视觉**：

- 红石矿石（在 deepslate / stone 中可挖）→ 红石粉。
- 红石粉撒在地上 → 形成"红石线"网格。
- 红石线像一条电线，红色发光，能传播 0-15 强度的信号。
- 各种"信号源"（拉杆、按钮、压力板）能产生信号。
- 各种"负载"（活塞、灯、门、漏斗）响应信号。
- "传输"组件（中继器、比较器）能放大、延迟、运算信号。

**对开发者**：红石不是物理引擎模拟（不计算电流 / 电压）—— 它是**离散信号传播 + 状态机**：每个 wire / 组件有一个 0-15 的"强度数"。

---

## 5.1.2 信号传播图模型

把红石电路视为一张**有向图**：

```
节点 = 红石组件（每个 BlockPos 上的方块）
边   = "我能给某邻居信号"的关系（有方向 + 强度衰减）
```

**节点类别**：

- **信号源**（source）：能凭空产生信号。如 lever（拉杆）、redstone_torch（红石火把）、button（按钮）、observer（侦测器）。
- **传输**（conductor / transmitter）：把信号传到下一节点，可能放大 / 衰减 / 延迟。如 redstone_wire（红石线）、repeater（中继器）、comparator（比较器）。
- **负载**（load）：被信号驱动产生效果。如 piston（活塞）、redstone_lamp（红石灯）、dispenser（发射器）、door（门）。

**边的属性**：

- **方向**：从源到目标。
- **衰减**：每经过一段距离信号强度衰减（红石线每格 -1）。
- **类型**：强信号 vs 弱信号（5.2 节）。

**关键性质**：

- 图是**动态**的——玩家放置 / 破坏方块时图改变。
- 节点状态不是单纯的 0/1，而是 **0-15 整数强度**。
- 信号变化通过 `neighborChanged`（同步）+ `scheduledTick`（延迟）传播。

## 5.1.3 三类组件详解

### 信号源（约 15 种）

```java
// vanilla 信号源类型
LeverBlock                 // 拉杆 - 持续 15
ButtonBlock                // 按钮 - 短暂 15（按下后 1 秒）
PressurePlateBlock         // 压力板 - 玩家 / 实体踩着时 15
RedstoneTorchBlock         // 红石火把 - 持续 15（除非被信号关掉）
RedstoneBlock              // 红石块 - 持续 15
DaylightDetectorBlock      // 阳光感应器 - 0-15（按光照）
ObserverBlock              // 侦测器 - 检测到方块更新时短暂 15
TargetBlock                // 标靶方块 - 被箭击中时短暂 15
LectorBlock                // 讲台 - 翻页时 0-15
JukeboxBlock               // 唱片机 - 1（持续，给比较器用）
ChestBlock / 其他容器       // 容器 - 0-15（根据填充率，给比较器用）
TrappedChestBlock          // 陷阱箱 - 玩家打开时 0-15
SculkSensorBlock           // 幽匿感测体 - 检测振动时 1-15
CalibratedSculkSensorBlock // 校准过的幽匿感测体
```

**信号源的接口**：

```java
// BlockBehaviour
public boolean isSignalSource(BlockState state) { return false; }
public int getSignal(BlockState state, BlockGetter level, BlockPos pos, Direction direction) { return 0; }
public int getDirectSignal(BlockState state, BlockGetter level, BlockPos pos, Direction direction) { return 0; }
```

子类重写 `isSignalSource` 返 true，并根据自己状态返回 `getSignal` / `getDirectSignal`。

### 传输（5 种）

```java
RedstoneWireBlock         // 红石线 - 距离衰减传播
RepeaterBlock             // 中继器 - 延迟 1-4 tick + 锁存 + 放大到 15
ComparatorBlock           // 比较器 - 测量 / 减法
ObserverBlock             // 侦测器 - 检测前面方块更新（也算半个传输）
PistonHeadBlock / MovingPistonBlock  // 活塞推动期间的传输
```

### 负载（约 30 种）

```java
PistonBaseBlock            // 活塞
RedstoneLampBlock          // 红石灯
NoteBlock                  // 音符盒
DispenserBlock / DropperBlock  // 发射器 / 投掷器
TntBlock                   // TNT
DoorBlock / TrapdoorBlock  // 门 / 活板门
FenceGateBlock             // 栅栏门
HopperBlock                // 漏斗（被信号关闭）
ChestBoatBlock             // 等等
RedstoneRailBlock          // 充能铁轨
SoulCampfireBlock          // 灵魂篝火（被信号控制 lit）
BellBlock                  // 钟
```

负载方块在 `neighborChanged` 钩子内检测周围信号 → 切换自己状态。

## 5.1.4 信号强度的物理意义

**0-15 整数**，不是物理电压。语义：

- **0**：无信号 / 关闭。
- **1-14**：传输中的信号——每经过 1 格 redstone wire 衰减 1。
- **15**：信号源的输出强度——所有信号源都输出 15（除了 daylight detector / target / observer / 容器比较器，它们 0-15 都行）。

**为什么是 15**？因为红石线的最大传输距离是 15 格——超过就衰减为 0。这是 vanilla 历史决定。

**衰减不是"自然规律"**：

- 红石线 → 红石线：-1 / 格。
- 中继器 → 红石线：放大到 15。
- 中继器 / 比较器 → 输出 → 信号：固定（中继器永远输出 15、比较器输出 = 输入或减法）。

## 5.1.5 信号的"传播一次"语义

红石不是**实时连续**——每次传播是离散一次：

```
玩家拉拉杆 → 信号变 15
  → wire(0,0) 收到信号 → 强度变 15 → 触发 wire(1,0) 邻居更新
    → wire(1,0) 强度变 14 → 触发 wire(2,0) 邻居更新
      → wire(2,0) 强度变 13
        → ⋯ 直到 wire(15,0) 强度变 1
          → wire(16,0) 强度变 0（不再变化，不触发邻居）
```

**整个传播过程发生在玩家拉拉杆那一瞬间的同一 tick 内**——通过 neighborChanged 链式同步触发（4.4 节的 CollectingNeighborUpdater 把它 BFS 化）。

**例外**：

- 中继器：信号变化触发 scheduled tick，1-4 tick 后才在输出端反映。
- 比较器：触发 scheduled tick，2 tick 后输出。
- 红石火把：触发 scheduled tick，2 tick 后翻转。

---

## 5.1.6 红石更新分两阶段

每次设备状态变化触发两阶段：

1. **强度变化**：相邻 wire / 组件重新计算强度，链式 setBlock。
2. **机械响应**：强度变化引起负载方块的状态变化（活塞 EXTENDED 翻转、灯 LIT 翻转），可能触发 BlockEvent。

```
玩家关拉杆
   ↓ stage 1
连锁 wire 强度更新（一连串 setBlock + neighborChanged）
   ↓ stage 1 结束（链已经稳定）
   ↓ stage 2
连接的活塞收到 neighborChanged：检查自己强度 → 决定 retract → 发 blockEvent
   ↓
活塞延迟一 tick 缩回（在下一 tick 第 9 步 runBlockEvents）
```

## 5.1.7 红石电路示例

### 与门（AND gate）

```
[lever_A]               
   |                    
   +─── wire ─── repeater ──→ output
                      ↑
                   wire ─── repeater ──→
                      |
                  [lever_B]
```

只有两个拉杆都开时输出才有信号。

### 时钟（pulse generator）

```
redstone_torch (X) ──── wire ────┐
        ↑                          │
        └────────────┬─────────────┘
                redstone_torch
                  在 X 上面
```

红石火把检测下方信号——下方信号变 → 火把翻转 → 强度变 → 触发火把检测 → 反复振荡。

### 计数器（用比较器搭加法器）

略——超过本节范围。详见社区资料。

## 5.1.8 红石的"软实时"特性

红石是**离散事件驱动**——不是物理引擎。这意味着：

- 时序由 server tick 决定（20 Hz / 50 ms）。
- 同 tick 内的多次状态变化按 NeighborUpdater 的 BFS 顺序处理。
- 跨 tick 的延迟由 scheduled tick 调度。

**对时序敏感的电路**（如 0-tick 推塔活塞、bedrock breaker）依赖**精确的更新顺序** —— 这就是为什么 1.21 实验性红石需要慎重——改更新顺序会破坏老电路。

## 5.1.9 redstone 与 1.21 实验红石的差异预告

```
DefaultRedstoneWireEvaluator (vanilla 1.21) ：
  - 整段 wire 网络（所有相连 wire）一次性计算强度
  - 算法 ~10 行
  - 老电路兼容

ExperimentalRedstoneWireEvaluator (1.21 实验)：
  - 每个 wire 单独传播信号
  - 携带 Orientation（信号来源方向）
  - 更接近"真实电路传播"
  - 老电路在某些 BUD 场景下行为不同
```

详见 5.4 节。

## 5.1.10 一句话总结

红石是 Minecraft 的"游戏内电路系统"——把方块视为信号传播图节点，分**信号源**（拉杆 / 按钮 / 红石火把 / 容器 / sculk）/ **传输**（红石线 / 中继器 / 比较器）/ **负载**（活塞 / 灯 / 门 / 漏斗）三类；信号强度 0-15 整数（红石线每格衰减 1，最大 15 格距离）；同 tick 内通过 neighborChanged 链式传播，跨 tick 延迟由 scheduled tick / block event 实现；不是物理引擎，是**离散事件驱动状态机**；玩家可搭从简单门到完整 CPU 的复杂电路。
