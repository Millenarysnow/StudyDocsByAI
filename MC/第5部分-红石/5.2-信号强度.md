# 5.2 信号强度系统

## 5.2.0 你将在本节学到什么

读完这一节你应当能闭着眼睛回答：

1. "强信号"和"弱信号"在游戏机制上是什么差别？玩家能直观看到吗？
2. `getSignal` vs `getDirectSignal` 这两个 BlockBehaviour 钩子各自做什么？
3. 为什么红石线接到 stone 上方块**不会**变成信号源，但中继器接到 stone 上方块**会**？
4. `Level.hasNeighborSignal` / `Level.getBestNeighborSignal` / `Level.getDirectSignal` 三个查询函数各自做什么？
5. "可被供电的方块"是什么概念——哪些方块"导电"？

---

## 5.2.1 直觉：从一个简单场景出发

考虑两个场景：

**场景 A**：

```
[lever] → [wire] → [stone] ← (这块 stone 上面有什么？)
                         |
                         +→ 上面接 [redstone_lamp]
```

玩家拉开拉杆 → wire 信号 15 → stone 接收信号 → 但**stone 上面的灯不亮**！

**场景 B**：

```
[lever] → [repeater] → [stone] ← (这块 stone 上面有什么？)
                            |
                            +→ 上面接 [redstone_lamp]
```

玩家拉开拉杆 → repeater 信号 15 → stone 接收信号 → **stone 上面的灯亮了**！

**差异**：wire 输出"弱信号"，repeater 输出"强信号"。

**这就是 Minecraft 红石的核心机制差别**——"强 / 弱"决定信号能不能"穿过实心方块"。

---

## 5.2.2 强信号 vs 弱信号定义

**弱信号**（weak signal / soft signal）：

- 由 redstone wire 传输的信号。
- **能直接驱动相邻方块**（灯、活塞、门）。
- **不能"加电"实心方块**——stone 接收弱信号时不会成为新信号源，所以 stone 上面的灯不亮。

**强信号**（strong signal / hard signal）：

- 由 repeater / comparator / observer / 信号源直接输出的信号。
- 能直接驱动相邻方块（同弱信号）。
- **能"加电"实心方块**——stone 接收强信号后变成新的信号源，能驱动它的所有邻居。

简单说：**强信号能让 stone "导电"传给后面的方块；弱信号不能**。

## 5.2.3 BlockBehaviour 接口

```java
public abstract class BlockBehaviour {
    public boolean isSignalSource(BlockState state) { return false; }
    
    public int getSignal(BlockState state, BlockGetter level, BlockPos pos, Direction direction) {
        return 0;
    }
    
    public int getDirectSignal(BlockState state, BlockGetter level, BlockPos pos, Direction direction) {
        return 0;
    }
}
```

**3 个钩子**：

- **`isSignalSource`**：本方块**是否**是信号源。开关是、wire 不是、stone 不是。
- **`getSignal`**：弱信号输出。当被相邻方块查询"你给我多少弱信号"时返回。
- **`getDirectSignal`**：强信号输出。被查询"你给我多少强信号"时返回。

**默认实现**返 0 / false——非信号源方块。

### 信号源的典型实现

```java
// LeverBlock
@Override
public boolean isSignalSource(BlockState state) { return true; }

@Override
public int getSignal(BlockState state, BlockGetter level, BlockPos pos, Direction direction) {
    return state.getValue(POWERED) ? 15 : 0;
}

@Override
public int getDirectSignal(BlockState state, BlockGetter level, BlockPos pos, Direction direction) {
    return state.getValue(POWERED) && getConnectedDirection(state) == direction ? 15 : 0;
}
```

**`getSignal` 永远返 15**（如果开关 ON）—— 拉杆给所有 6 个方向弱信号。

**`getDirectSignal` 只对"连接方向"返 15**——拉杆固定贴在某个方块上，只对那个面给强信号。

## 5.2.4 RedstoneWire 的实现

```java
// RedStoneWireBlock
@Override
public int getSignal(BlockState state, BlockGetter level, BlockPos pos, Direction direction) {
    if (!this.shouldSignal) return 0;
    return state.getValue(POWER);     // 红石线 0-15 强度直接传弱信号
}

@Override
public int getDirectSignal(BlockState state, BlockGetter level, BlockPos pos, Direction direction) {
    return !this.shouldSignal ? 0 : state.getSignal(level, pos, direction);
    // ⋯ wire 的 direct signal 仅给特定方向（向下传）
}
```

**关键**：wire 的 `getSignal` 返回当前 POWER 属性值（0-15）—— 即弱信号 = wire 强度。

**wire 的 `getDirectSignal` 仅在特定方向传**——具体规则：wire 只对"它指向的方向"给强信号。这就是为什么 wire 上面那格方块"被供电"——wire 给上方一个 down direction 强信号。

## 5.2.5 RepeaterBlock 的实现

```java
// RepeaterBlock
@Override
public boolean isSignalSource(BlockState state) { return true; }

@Override
public int getSignal(BlockState state, BlockGetter level, BlockPos pos, Direction direction) {
    return this.getDirectSignal(state, level, pos, direction);
}

@Override
public int getDirectSignal(BlockState state, BlockGetter level, BlockPos pos, Direction direction) {
    if (!state.getValue(POWERED)) return 0;
    return state.getValue(FACING) == direction ? 15 : 0;
}
```

**关键**：

1. `isSignalSource = true`——中继器是信号源（不像 wire）。
2. `getSignal` 直接调 `getDirectSignal`——中继器的弱 / 强信号输出**完全相同**。
3. 只对 FACING 方向（输出端）给信号 15。

这就是为什么 repeater 的输出端能让 stone "导电" —— `getDirectSignal` 返 15。

**对比**：

- wire 在不规则方向有 `getSignal` > 0（任何方向都给弱）但 `getDirectSignal` 限制（只下 / 特定方向给强）。
- repeater 只在 FACING 方向给信号，但**强 / 弱都给**。

## 5.2.6 Level 端的查询函数

`Level` 提供高层信号查询 API：

```java
// Level
public int getSignal(BlockPos pos, Direction direction) {
    BlockState state = this.getBlockState(pos);
    int signal = state.getSignal(this, pos, direction);
    return state.isSignalSource() ? Math.max(signal, this.getDirectSignal(pos, direction)) : signal;
}

public int getDirectSignal(BlockPos pos, Direction direction) {
    return this.getBlockState(pos).getDirectSignal(this, pos, direction);
}

public int getDirectSignalTo(BlockPos pos) {
    int max = 0;
    for (Direction dir : Direction.values()) {
        int sig = this.getDirectSignal(pos.relative(dir), dir);
        if (sig >= 15) return 15;
        if (sig > max) max = sig;
    }
    return max;
}

public int getBestNeighborSignal(BlockPos pos) {
    int max = 0;
    for (Direction dir : Direction.values()) {
        int sig = this.getSignal(pos.relative(dir), dir);
        if (sig >= 15) return 15;
        if (sig > max) max = sig;
    }
    return max;
}

public boolean hasNeighborSignal(BlockPos pos) {
    for (Direction dir : Direction.values()) {
        if (this.getSignal(pos.relative(dir), dir) > 0) return true;
    }
    return false;
}

public int getBestNeighborSignalIncludingIndirect(BlockPos pos) {
    int max = 0;
    for (Direction dir : Direction.values()) {
        BlockPos neighborPos = pos.relative(dir);
        BlockState neighbor = this.getBlockState(neighborPos);
        // 检查直接信号
        int directSig = this.getSignal(neighborPos, dir);
        if (directSig >= 15) return 15;
        if (directSig > max) max = directSig;
        
        // 检查"导电方块"的间接信号（强信号穿过实心方块）
        if (neighbor.shouldCheckWeakPower(this, neighborPos, dir)) {
            int indirectSig = this.getDirectSignalTo(neighborPos);
            if (indirectSig >= 15) return 15;
            if (indirectSig > max) max = indirectSig;
        }
    }
    return max;
}
```

**5 个查询函数**：

| 函数 | 含义 |
|------|------|
| `getSignal(pos, dir)` | 单方向：pos 处方块给我多少弱信号 |
| `getDirectSignal(pos, dir)` | 单方向：pos 处方块给我多少强信号 |
| `getDirectSignalTo(pos)` | 6 邻居：周围给我的最强 strong 信号 |
| `getBestNeighborSignal(pos)` | 6 邻居：周围给我的最强 weak 信号 |
| `hasNeighborSignal(pos)` | 6 邻居：是否有任何 weak 信号 |
| `getBestNeighborSignalIncludingIndirect(pos)` | **重要**：6 邻居 weak + 实心方块的 indirect strong |

最后一个是真正的"复合信号查询"——给活塞、redstone_lamp 等使用。

## 5.2.7 实心方块的"导电"规则

回顾场景 B：repeater → stone → lamp 中，stone 怎么"导电"？

**核心**：实心方块自身**不是信号源**（`isSignalSource = false`），**但**当它被 strong signal 供电时，被视为"间接信号源"——它的邻居查询时会得到 indirect signal。

具体由 `Level.getBestNeighborSignalIncludingIndirect` 实现：

```java
// 简化逻辑
for (Direction dir : Direction.values()) {
    BlockPos neighborPos = pos.relative(dir);
    BlockState neighbor = level.getBlockState(neighborPos);
    
    // 弱信号：直接问 neighbor 的 getSignal
    int weakSig = neighbor.getSignal(level, neighborPos, dir);
    
    // 强信号 indirect：如果 neighbor 是"导电"实心方块，扫它的邻居 getDirectSignal
    if (neighbor.shouldCheckWeakPower(level, neighborPos, dir)) {
        int strongSig = level.getDirectSignalTo(neighborPos);
        // 取 max
    }
}
```

**`shouldCheckWeakPower`** 判定方块"导电"——重点：

- **stone / dirt / wood / wool / brick** 等普通固体：**导电**。
- **glass / leaves / slab（半砖）/ stairs / ice**：**不导电**（透明 / 不完整 / 特殊）。
- **redstone_block / 漏斗**：特殊处理。

实现：

```java
public boolean shouldCheckWeakPower(BlockState state, BlockGetter level, BlockPos pos, Direction direction) {
    return state.isRedstoneConductor(level, pos);
}

// BlockState.isRedstoneConductor
public boolean isRedstoneConductor(BlockGetter level, BlockPos pos) {
    return this.cache != null && this.cache.isRedstoneConductor;
}
```

`isRedstoneConductor` 是 BlockState 的预计算字段——构造期就根据 `BlockBehaviour` 的判断填好。

## 5.2.8 视觉对照：信号传播图

```
[lever] (信号源, getSignal=15, getDirectSignal=15 在 ATTACHED 方向)
   │ 给上面的方块强 + 弱 信号
   ↓
[stone] (实心方块, isRedstoneConductor=true)
   │ 接收到 strong signal → 它的邻居查询时返回 strong indirect
   ↓
[wire] (传输, getSignal=POWER, getDirectSignal=只对下方给)
   │ wire 检查 6 邻居：getBestNeighborSignalIncludingIndirect
   │ 邻居 stone 的 strong indirect = 15 → wire POWER = 15

vs.

[redstone_torch] 
   │ 给上面的方块弱信号（不是强）
   ↓
[stone]
   │ 没收到强信号，所以邻居不会返回 strong indirect
   ↓
[wire]
   │ wire 检查 stone 邻居：弱信号源不会让 stone 导电
   │ 但 wire 本身能从下方检测火把弱信号 ← 直接 + 短距
```

红石火把作为信号源比较特殊——它**给上面的方块输出 strong direct signal 15**：

```java
// RedstoneTorchBlock
@Override
public int getDirectSignal(BlockState state, BlockGetter level, BlockPos pos, Direction direction) {
    return direction == Direction.DOWN && state.getValue(LIT) ? 15 : 0;
}
```

仅对 **DOWN** 方向给 strong signal——意思是火把的"上面方块"被强信号供电。所以"火把上面的 stone 能导电"——经典的 redstone tower 电路。

**但 wire 不行**：

```java
// RedStoneWireBlock 简化
@Override
public int getDirectSignal(BlockState state, BlockGetter level, BlockPos pos, Direction direction) {
    return direction == Direction.DOWN ? state.getSignal(level, pos, direction) : 0;
    // wire 仅对 DOWN 给 strong signal（让下方方块能"导电"）
}
```

这就是为什么"wire 上面接灯"灯亮（弱信号直接给灯，灯响应）但"wire 上面接 stone 上面接灯"灯不亮（wire 给上面 stone 的是弱信号，stone 不导电）。

**反过来 redstone_torch 上面接 stone 上面接灯**：火把对 stone 给 DOWN 方向 strong signal → stone 收到 strong → stone 邻居查询时返回 strong indirect → 灯亮。

## 5.2.9 RedstoneWire 输入信号计算

`RedStoneWireBlock` 的核心算法是计算"我应当多强"。简化伪码：

```java
private int calculateTargetStrength(Level level, BlockPos pos) {
    int max = 0;
    
    // 1. 检查 6 邻居的 weak signal + indirect strong
    int neighborSignal = level.getBestNeighborSignalIncludingIndirect(pos);
    if (neighborSignal >= 15) return 15;
    max = neighborSignal;
    
    // 2. 检查相连 wire 的强度 - 1
    BlockPos[] adjacentWires = ...;     // 4 水平方向 + 上下视情况
    for (BlockPos other : adjacentWires) {
        BlockState otherState = level.getBlockState(other);
        if (otherState.is(Blocks.REDSTONE_WIRE)) {
            int otherPower = otherState.getValue(POWER);
            if (otherPower - 1 > max) max = otherPower - 1;
        }
    }
    
    return max;
}
```

**两阶段比较**：

1. 先查 6 邻居的 weak / indirect strong。
2. 再查 4-6 个相连的 wire neighbor，强度 - 1 比较。

取**最大值**——这就是为什么 wire 强度 = "信号源 / 上一格 wire 强度 - 1"中的较大者。

## 5.2.10 一个综合例子

```
[lever] - [wire] - [wire] - [wire]
                              |
                            [stone]
                              |
                            [wire]
                              |
                            [stone]
                              |
                            [wire]
                              |
                            [redstone_lamp]
```

玩家拉杆：

```
1. lever.getSignal = 15
2. wire₀ getBestNeighborSignalIncludingIndirect:
   - 邻居 lever：weak signal = 15 (lever 给所有方向 weak)
   - 取最大 = 15 → wire₀.POWER = 15
3. wire₁ check：
   - 邻居 wire₀：weak signal = 15 → 但 wire-to-wire 用 power-1 比较
   - wire₁.POWER = 15 - 1 = 14
4. wire₂ check：
   - 邻居 wire₁：14 - 1 = 13 → wire₂.POWER = 13
5. stone（首个 stone）：
   - 邻居 wire₂：weak signal = 13
   - stone 不是信号源，但它接收到 wire₂ 的 weak signal
   - 但 wire 不给 stone 强信号 (除非垂直 DOWN 方向)
   - 因此 stone 的"indirect strong" = 0
6. wire₃（stone 下方）：
   - 邻居 stone：getSignal = 0（stone 没被 strong 加电）
   - wire₃.POWER = 0
7. 灯关
```

**结论**：wire → stone → wire → lamp 这种配置**灯不亮**，因为 wire 给 stone 的不是 strong signal。

要让灯亮，第一个 stone 改用 repeater：

```
[lever] - [wire] - [wire] - [wire] - [repeater] - [stone] - [wire] - [stone] - [wire] - [lamp]
                                          ↓ FACING 方向
                                   strong signal = 15
                                   stone 收到 strong → 它的 indirect = 15
                                   wire 检查 stone 邻居 → 收到 indirect 15
                                   wire.POWER = 15
                                   传给下一 stone（同样路径）
                                   最终灯亮
```

## 5.2.11 性能特征

- **`getSignal` / `getDirectSignal`**：O(1) per call。
- **`getBestNeighborSignal`**：6 calls。
- **`getBestNeighborSignalIncludingIndirect`**：最多 6 + 6×6 = 42 calls（每个邻居又问其邻居）。
- **wire `calculateTargetStrength`**：~10-20 calls。

每个 wire 状态变化触发一次。在大规模电路里 wire 强度变化引发链式 setBlock → 链式 calculateTargetStrength → 总 calls 数 = wires × ~30。**1000-wire 电路 ~30000 次邻居信号查询 / tick**。

## 5.2.12 C++ 移植

```cpp
namespace mc::block {

class BlockBehaviour {
public:
    virtual bool isSignalSource(const BlockState& state) const { return false; }
    virtual int getSignal(const BlockState& state, BlockGetter& level, BlockPos pos, Direction dir) const { return 0; }
    virtual int getDirectSignal(const BlockState& state, BlockGetter& level, BlockPos pos, Direction dir) const { return 0; }
    virtual bool shouldCheckWeakPower(const BlockState& state, BlockGetter& level, BlockPos pos, Direction dir) const {
        return state.isRedstoneConductor(level, pos);
    }
};

}

namespace mc::level {

class Level {
public:
    int getSignal(BlockPos pos, Direction dir) const {
        const BlockState* state = getBlockState(pos);
        int signal = state->getBlock()->getSignal(*state, *this, pos, dir);
        if (state->isSignalSource()) {
            return std::max(signal, getDirectSignal(pos, dir));
        }
        return signal;
    }
    
    int getDirectSignal(BlockPos pos, Direction dir) const {
        const BlockState* state = getBlockState(pos);
        return state->getBlock()->getDirectSignal(*state, *this, pos, dir);
    }
    
    int getDirectSignalTo(BlockPos pos) const {
        int max = 0;
        for (Direction dir : Direction::all()) {
            int sig = getDirectSignal(pos.relative(dir), dir);
            if (sig >= 15) return 15;
            if (sig > max) max = sig;
        }
        return max;
    }
    
    int getBestNeighborSignal(BlockPos pos) const { ... }
    bool hasNeighborSignal(BlockPos pos) const { ... }
    int getBestNeighborSignalIncludingIndirect(BlockPos pos) const { ... }
};

}
```

## 5.2.13 一句话总结

红石信号分**强信号**（getDirectSignal）和**弱信号**（getSignal）—— 强信号能让"导电的"实心方块（stone / dirt / wood）成为间接信号源（indirect signal），弱信号不能；wire 给所有 6 方向弱信号但只给 DOWN 方向强信号；repeater / comparator 在 FACING 方向给强 + 弱信号；红石火把对 DOWN 给强信号；`Level.getBestNeighborSignalIncludingIndirect` 是综合查询入口（6 邻居 weak + indirect strong）；`isRedstoneConductor` 是 BlockState 预计算字段决定方块是否"导电"。
