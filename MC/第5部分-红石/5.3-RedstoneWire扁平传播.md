## 5.3.1 RedstoneWireBlock 属性

打开 `net.minecraft.world.level.block.RedStoneWireBlock`：

```java
public class RedStoneWireBlock extends Block {
    public static final EnumProperty<RedstoneSide> NORTH = BlockStateProperties.NORTH_REDSTONE;
    public static final EnumProperty<RedstoneSide> EAST = BlockStateProperties.EAST_REDSTONE;
    public static final EnumProperty<RedstoneSide> SOUTH = BlockStateProperties.SOUTH_REDSTONE;
    public static final EnumProperty<RedstoneSide> WEST = BlockStateProperties.WEST_REDSTONE;
    public static final IntegerProperty POWER = BlockStateProperties.POWER;     // 0..15
    
    private final RedstoneWireEvaluator evaluator;
    private boolean shouldSignal = true;
}

public enum RedstoneSide {
    UP, SIDE, NONE;
}
```

**5 个属性**：

- **`POWER`**：0-15 整数。当前信号强度。
- **`NORTH / EAST / SOUTH / WEST`**：每方向的连接形态。值是 `RedstoneSide`：
  - **`UP`**：连接到上方一格的 wire（爬墙 wire）。
  - **`SIDE`**：连接到同高度旁边的 wire / 信号源。
  - **`NONE`**：没有连接（红色端点）。

**总 BlockState 数**：4 (sides) ^ 3 + 1 = 1296（理论上 81 × 16 = 1296）。回顾 1.2.14。

**视觉**：

- 4 个 side 都是 SIDE → 十字交叉形。
- 仅 NORTH / SOUTH 是 SIDE，EAST / WEST 是 NONE → 一字直线。
- side 是 UP → 红石线在墙上爬升。

## 5.3.2 RedstoneSide 决定逻辑

`RedstoneWireBlock.getConnectingSide` 决定每个方向的连接形态：

```java
private RedstoneSide getConnectingSide(BlockGetter level, BlockPos pos, Direction dir) {
    BlockPos neighborPos = pos.relative(dir);
    BlockState neighborState = level.getBlockState(neighborPos);
    BlockPos abovePos = pos.above();
    BlockState aboveState = level.getBlockState(abovePos);
    
    // 1. 上方有方块阻挡 wire 爬墙？
    if (!aboveState.isRedstoneConductor(level, abovePos)) {
        // 上方不阻挡 + 下方位置有 wire → 爬墙连接
        if (neighborState.isFaceSturdy(level, neighborPos, Direction.UP) && 
            isPowerSourceAt(level, neighborPos.above(), Direction.UP)) {
            return RedstoneSide.UP;
        }
    }
    
    // 2. 同高度连接？
    return shouldConnectTo(neighborState, dir) || (
        !neighborState.isRedstoneConductor(level, neighborPos) && 
        isPowerSourceAt(level, neighborPos.below(), Direction.DOWN)
    ) ? RedstoneSide.SIDE : RedstoneSide.NONE;
}
```

**3 个判断**：

1. 上方非阻挡 + 该方向上方有 wire → UP（爬墙）。
2. 该方向方块是信号源 / 邻接 wire / connector → SIDE（连接）。
3. 该方向方块是非阻挡 + 下方有 wire → SIDE（向下连接）。
4. 否则 → NONE。

**视觉规则**：

- 上方阻挡（如 stone）的 wire 不能爬墙。
- 旁边 wire / 中继器 / 拉杆 → SIDE 连接。

## 5.3.3 updateShape：邻居变化时重连接

```java
@Override
public BlockState updateShape(BlockState state, LevelReader level, ScheduledTickAccess access,
                               BlockPos pos, Direction dir, BlockPos neighborPos, BlockState neighborState, RandomSource random) {
    if (dir == Direction.DOWN) {
        return !this.canSurviveOn(level, neighborPos, neighborState) ? Blocks.AIR.defaultBlockState() : state;
    }
    if (dir == Direction.UP) {
        return this.getConnectionUpdate(level, state, pos);
    }
    return this.getConnectionUpdate(level, state, pos).setValue(PROPERTY_BY_DIRECTION.get(dir), this.getConnectingSide(level, pos, dir));
}
```

**邻居更新时**：

- 下方变化 → 检查 wire 是否还能放（需要下方支撑）。
- 上方变化 → 重新计算所有 4 方向的 RedstoneSide。
- 横向变化 → 仅更新该方向的 RedstoneSide。

## 5.3.4 评估器（Evaluator）抽象

打开 `net.minecraft.world.level.redstone.RedstoneWireEvaluator`：

```java
public abstract class RedstoneWireEvaluator {
    protected final RedStoneWireBlock wireBlock;
    
    public abstract void updatePowerStrength(Level level, BlockPos pos, BlockState state, @Nullable Orientation orientation, boolean updateShape);
    
    protected int getBlockSignal(Level level, BlockPos pos) {
        // 检查 6 邻居的 weak / indirect strong
        return level.getBestNeighborSignalIncludingIndirect(pos);
    }
    
    protected int getIncomingWireSignal(Level level, BlockPos pos) {
        // 检查相连 wire 的 power - 1
        int max = 0;
        for (Direction dir : Direction.Plane.HORIZONTAL) {
            BlockPos neighborPos = pos.relative(dir);
            BlockState state = level.getBlockState(neighborPos);
            if (state.is(this.wireBlock)) {
                max = Math.max(max, state.getValue(RedStoneWireBlock.POWER) - 1);
            }
            
            // 检查斜上 / 斜下方向的 wire（爬墙 + 跌落）
            // ⋯
        }
        return max;
    }
}
```

**抽象方法 `updatePowerStrength`**：每次 wire 收到 neighborChanged 时调用。

**两个具体实现**：

- **`DefaultRedstoneWireEvaluator`**：vanilla 1.21 行为。
- **`ExperimentalRedstoneWireEvaluator`**：1.21 实验性行为（详见 5.4）。

## 5.3.5 DefaultRedstoneWireEvaluator 算法

打开 `DefaultRedstoneWireEvaluator`（行 12-42）：

```java
public class DefaultRedstoneWireEvaluator extends RedstoneWireEvaluator {
    @Override
    public void updatePowerStrength(Level level, BlockPos pos, BlockState state, @Nullable Orientation orientation, boolean updateShape) {
        int newPower = this.calculateTargetStrength(level, pos);
        if (state.getValue(RedStoneWireBlock.POWER) != newPower) {
            if (level.getBlockState(pos) == state) {
                level.setBlock(pos, state.setValue(RedStoneWireBlock.POWER, newPower), 2);     // flags = UPDATE_CLIENTS only
            }
            
            // 触发 7 个邻居更新（自己 + 6 邻居）
            Set<BlockPos> updates = Sets.newHashSet();
            updates.add(pos);
            for (Direction dir : Direction.values()) {
                updates.add(pos.relative(dir));
            }
            for (BlockPos updatePos : updates) {
                level.updateNeighborsAt(updatePos, this.wireBlock);
            }
        }
    }
    
    private int calculateTargetStrength(Level level, BlockPos pos) {
        int blockSignal = this.getBlockSignal(level, pos);     // 周围非 wire 邻居信号
        return blockSignal == 15 ? 15 : Math.max(blockSignal, this.getIncomingWireSignal(level, pos));
    }
}
```

**算法**：

1. 计算目标强度 `newPower`：max(blockSignal, max_neighbor_wire_power - 1)。
2. 如果 `newPower != current POWER`：
   - `setBlock(pos, state.setValue(POWER, newPower), 2)` —— flags = UPDATE_CLIENTS only（不触发邻居）。
   - **手动**触发 7 个 BlockPos 的邻居更新——自己 + 6 邻居。

**为什么 setBlock 用 flags=2 不用 UPDATE_ALL=3**？因为 wire 想**自己控制邻居更新顺序**——`setBlock` 用 UPDATE_NEIGHBORS=1 会触发邻居 6 个的 neighborChanged，但 wire 想**额外**触发"相邻 wire 的邻居"（让信号继续传播）。

具体：

- `setBlock(pos, ..., 2)` 改方块 + 同步给客户端，**不触发** neighborChanged 链。
- 然后手动 `updateNeighborsAt(pos)` + 6×`updateNeighborsAt(neighbor)` —— 7 次。

**这就是"扁平传播"的含义**——单点 wire 强度变化触发 7 邻居更新，链式扩散。

## 5.3.6 一段实战：100 格 wire 的传播

```
玩家拉拉杆
  → wire₀ 收到 lever 邻居变化 → updatePowerStrength
    → calculateTargetStrength = 15
    → setBlock(POWER=15) + 7 邻居更新
    → wire₁ 收到邻居更新（来自 wire₀） → updatePowerStrength
      → calculateTargetStrength = max(0, 15-1) = 14
      → setBlock(POWER=14) + 7 邻居更新
      → wire₂ 收到邻居更新（来自 wire₁） → updatePowerStrength
        → calculateTargetStrength = 14-1 = 13
        → ⋯
```

**问题**：每个 wire 触发 7 邻居更新——其中有 wire₀（已经处理过的）。会不会重复处理？

**答**：会，**这就是 vanilla redstone wire 性能差的原因**——wire₀ 收到 wire₁ 的反向更新，重新算 calculateTargetStrength = 15（已经是 15 了），没变化 → return。但仍消耗 7 次邻居更新。

**性能特征**：100 格 wire 的传播 = 100 wire × 7 update × 6 邻居算 ≈ 4200 次 getSignal 查询 + 100 setBlock。**~3-10 毫秒**。

**可接受**——直到大型 redstone 机器（1000+ wire）变得卡。这是 1.21 实验性红石的优化目标。

## 5.3.7 RedStoneWireBlock.neighborChanged 入口

```java
// RedStoneWireBlock
@Override
public void neighborChanged(BlockState state, Level level, BlockPos pos, Block neighborBlock,
                             @Nullable Orientation orientation, boolean movedByPiston) {
    if (!level.isClientSide) {
        if (state.canSurvive(level, pos)) {
            this.evaluator.updatePowerStrength(level, pos, state, orientation, false);
        } else {
            dropResources(state, level, pos);
            level.removeBlock(pos, false);
        }
    }
}
```

**两个分支**：

- 下方支撑还在 → 调 evaluator.updatePowerStrength。
- 下方支撑没了（玩家挖了下方方块） → wire 掉落物品 + remove。

## 5.3.8 onPlace 和 onRemove

```java
@Override
public void onPlace(BlockState state, Level level, BlockPos pos, BlockState oldState, boolean movedByPiston) {
    if (!oldState.is(state.getBlock()) && !level.isClientSide) {
        this.evaluator.updatePowerStrength(level, pos, state, null, true);
        // 触发垂直方向的 wire 邻居更新
        for (Direction dir : Direction.Plane.VERTICAL) {
            level.updateNeighborsAt(pos.relative(dir), this);
        }
        this.updateNeighborsOfNeighboringWires(level, pos);
    }
}

@Override
public void onRemove(BlockState state, Level level, BlockPos pos, BlockState newState, boolean movedByPiston) {
    if (!movedByPiston && !state.is(newState.getBlock())) {
        super.onRemove(state, level, pos, newState, movedByPiston);
        if (!level.isClientSide) {
            for (Direction dir : Direction.values()) {
                level.updateNeighborsAt(pos.relative(dir), this);
            }
            this.updateNeighborsOfNeighboringWires(level, pos);
        }
    }
}
```

放置 / 移除 wire 时**广播范围内更新**——让所有相关 wire 重新计算强度。

## 5.3.9 设置 setBlock 用 flag 2 的细节

`setBlock(pos, ..., 2)` 含义：

- **bit 0 NEIGHBORS = 0** —— 不触发自动邻居更新链。
- **bit 1 CLIENTS = 1** —— 同步给客户端。
- **bit 2 INVISIBLE = 0** —— 触发视觉。

为什么这么选：

- wire 自己手动控制邻居更新（用 `updateNeighborsAt` 手动）—— 让 7 个 BlockPos 一次性更新而不是 6 个。
- 仍要同步给客户端（让客户端 wire 颜色变化）。
- 触发视觉粒子（红石线变红）。

## 5.3.10 性能：DefaultEvaluator 的瓶颈

```
单 wire neighborChanged：
- updatePowerStrength
- calculateTargetStrength: ~10-20 ns
- setBlock + 7 邻居更新触发 → 触发更多 wire 的 neighborChanged
- 每个邻居 wire 重复同样过程

n 格 wire 链：
- 大致 n × 14 个 neighborChanged 调用（双向传播）
- ~50-200 微秒 / 100 格
```

实际场景：

- 10 格 wire：~5-20 微秒（瞬时）。
- 100 格：~50-200 微秒。
- 1000 格：~500 微秒-2 毫秒。
- 10000 格（巨型电路）：5-50 毫秒（开始接近 tick budget）。

**1.21 实验红石的目标**：把这个数字降低 5-10 倍。详见 5.4 节。

## 5.3.11 Carpet Mod / Lithium 等的优化

社区性能 mod 通常重写 wire 算法：

- **Carpet**：fastBlockUpdate 优化——批量 wire 更新合并、去重邻居更新。
- **Lithium**：完全替换 evaluator——预算每个 wire 的传播路径，一次性更新整个 wire 网。

vanilla 1.21 的 ExperimentalRedstoneWireEvaluator 大致等价于 Lithium 的算法路径。

## 5.3.12 C++ 移植

```cpp
namespace mc::redstone {

class RedstoneWireEvaluator {
public:
    explicit RedstoneWireEvaluator(RedStoneWireBlock* wireBlock) : wireBlock_(wireBlock) {}
    virtual ~RedstoneWireEvaluator() = default;
    
    virtual void updatePowerStrength(Level& level, BlockPos pos, const BlockState& state, std::optional<Orientation> orient, bool updateShape) = 0;
    
protected:
    RedStoneWireBlock* wireBlock_;
    
    int getBlockSignal(Level& level, BlockPos pos) const {
        return level.getBestNeighborSignalIncludingIndirect(pos);
    }
    
    int getIncomingWireSignal(Level& level, BlockPos pos) const {
        int max = 0;
        for (Direction dir : Direction::HORIZONTAL) {
            BlockPos neighborPos = pos.relative(dir);
            const BlockState* state = level.getBlockState(neighborPos);
            if (state->is(*wireBlock_)) {
                int p = state->getValue(RedStoneWireBlock::POWER) - 1;
                if (p > max) max = p;
            }
            // 检查上下斜邻居（爬墙 + 下落）
            // ⋯
        }
        return max;
    }
};

class DefaultRedstoneWireEvaluator : public RedstoneWireEvaluator {
public:
    using RedstoneWireEvaluator::RedstoneWireEvaluator;
    
    void updatePowerStrength(Level& level, BlockPos pos, const BlockState& state, std::optional<Orientation> orient, bool updateShape) override {
        int newPower = calculateTargetStrength(level, pos);
        const BlockState* current = level.getBlockState(pos);
        if (current == &state && current->getValue(RedStoneWireBlock::POWER) != newPower) {
            level.setBlock(pos, state.setValue(RedStoneWireBlock::POWER, newPower), BlockUpdateFlags::CLIENTS);
            
            std::unordered_set<BlockPos> updates;
            updates.insert(pos);
            for (Direction dir : Direction::all()) {
                updates.insert(pos.relative(dir));
            }
            for (BlockPos p : updates) {
                level.updateNeighborsAt(p, wireBlock_);
            }
        }
    }
    
private:
    int calculateTargetStrength(Level& level, BlockPos pos) const {
        int blockSig = getBlockSignal(level, pos);
        return blockSig == 15 ? 15 : std::max(blockSig, getIncomingWireSignal(level, pos));
    }
};

}
```

## 5.3.13 一句话总结

`RedStoneWireBlock` 有 5 属性（POWER 0-15 + 4 个 RedstoneSide UP/SIDE/NONE）共 1296 个 BlockState；`DefaultRedstoneWireEvaluator.updatePowerStrength` 算 max(邻居 weak/indirect strong, 相邻 wire POWER-1) → setBlock(POWER, flags=CLIENTS only) + 7 BlockPos 邻居更新触发链式传播；通过 `setBlock flag=2` 跳过自动邻居更新让 wire 手动控制更新顺序；100 格 wire 传播 ~100 微秒级，但大型电路 (10K wire) 可达 50ms 接近 tick budget；这就是 1.21 实验性红石（5.4 节）的优化目标。
