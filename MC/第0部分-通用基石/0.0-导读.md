# 第 0 部分 · 通用基石 —— 导读

## 你为什么需要先读这一部分

这一部分只回答一个问题：**在我们打开任何源码、讨论任何算法之前，关于这个游戏的世界，最低限度需要先建立起怎样的世界观？**

如果你跳过它，你会在读后面的代码时不停地撞上「这变量是什么坐标？」「这个 chunk 跟那个 section 什么关系？」「服务端的这段代码客户端为什么也跑得到？」之类的问题。所有这些问题在做引擎移植时都是真问题，绕不过去。

所以这一部分故意写得**琐碎**：每一个概念都从「眼睛看到什么」开始讲起，再过渡到代码里的具体类与字段。读完它，你应当能：

1. 看到一个 `BlockPos`、`ChunkPos`、`SectionPos` 不会混淆，能在脑子里立刻还原它指向世界里的哪一个体素 / 哪一段 / 哪一列。
2. 知道客户端代码、服务端代码、集成服务端这三个名词分别意味着「这段逻辑在哪个进程的哪个线程上跑」。
3. 看到一个 `p_122016_` 知道它只是 Mojang 反编译丢失参数名的占位，不是某个秘密含义，并能根据上下文猜出它的语义。
4. 知道 datapack 是什么、Registry 是什么、为什么生成相关的几乎所有「配方」都是 JSON。

## 它和其它部分的关系

```
第 0 部分（你在这里）  ← 概念 + 命名 + 工程约定
        │
        ▼
第 1 部分             ← 数据结构（Block / Chunk / Palette）
        │
        ▼
第 2 / 3 / 4 / 5 / 6 / 7 部分    ← 具体模块
```

**第 0 部分不引用源码细节**，它的目标是让你后面读源码时不被名词卡住。第 1 部分开始才会进入具体的类、具体的方法、具体的位运算。

## 阅读建议

- 你 **不需要**为了通读这一部分启动 Minecraft 客户端。但如果你完全没玩过，强烈建议在 0.1 之前花 10 分钟看一段「Minecraft 全程介绍」视频，建立最基本的视觉印象（生物群系、洞穴、村庄长什么样）。
- 这一部分的代码引用很少。后面每一个深度模块都会回头引用本部分的概念。
- 读完后回去翻一遍 [00-全局大纲.md](../00-全局大纲.md) 的「序言」部分，你应该能看懂依赖图里每一个箭头为什么这么画。
