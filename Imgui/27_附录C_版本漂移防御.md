# 附录 C · 版本漂移防御指南

> **本附录目标**：把 ImGui 跨版本"破坏性变更"的所有典型模式整理成防御 checklist。读完后你应该能：(1) 主动识别"哪些代码在升级时会出问题"；(2) 写"经得起未来 5 个版本演进"的魔改代码；(3) 在升级 ImGui 时按系统化流程而不是"撞错改"。

---

## C.1 ImGui 的版本演进风格

ImGui 团队的"breaking change"哲学：

- **公开 API 极少 break**——`imgui.h` 大多数函数 1.50 时代写的代码到 1.92 仍能编译。
- **Internal API 经常 break**——字段改名 / 改类型 / 改语义。
- **配置宏（imconfig.h）几乎不 break**。
- **Backend API 偶尔 break**——大改往往伴随版本号大跳（如 1.87 / 1.92）。

——即"用户友好 + 维护者自由"的双层契约。

每次新版本发布时，`imgui.h` 顶部的 changelog 会列出所有 breaking change，**必须读**。

## C.2 版本号语义

```cpp
// imgui.h:32~33
#define IMGUI_VERSION       "1.92.8 WIP"
#define IMGUI_VERSION_NUM   19271
```

`IMGUI_VERSION_NUM` 是整数化的版本号——`19271` = `1.92.71`。计算公式：

```
MAJOR.MINOR.PATCH → MAJOR * 10000 + MINOR * 100 + PATCH
1.92.8 → 19208
1.92.7+1 → 19271 (WIP，next is 19272)
```

**用于条件编译**：

```cpp
#if IMGUI_VERSION_NUM >= 19200
    // 1.92.0 及之后的代码
#endif

#if IMGUI_VERSION_NUM < 19200
    // 1.92.0 之前的兼容代码
#endif
```

## C.3 已废弃但仍保留的 API（1.92 时刻）

`imgui.h` 中所有标 `[obsolete]` 或被 `#ifndef IMGUI_DISABLE_OBSOLETE_FUNCTIONS` 包裹的字段。**这些是"软废弃"——能用但官方建议迁移**。

### `ImGuiIO` 中（`imgui.h:2611+`）

```cpp
#ifndef IMGUI_DISABLE_OBSOLETE_FUNCTIONS
    float       FontGlobalScale;            // 1.92 移到 style.FontScaleMain
    
    // 1.91.1 之前的剪贴板 API
    const char* (*GetClipboardTextFn)(void* user_data);
    void        (*SetClipboardTextFn)(void* user_data, const char* text);
    void*       ClipboardUserData;
#endif
```

### `ImDrawList` 中（`imgui.h:3417+`）

```cpp
#ifndef IMGUI_DISABLE_OBSOLETE_FUNCTIONS
    inline void PushTextureID(ImTextureRef tex_ref) { PushTexture(tex_ref); }   // 1.92 改名
    inline void PopTextureID()                      { PopTexture(); }           // 1.92 改名
#endif
```

### `ImFontAtlas` 中

```cpp
#ifndef IMGUI_DISABLE_OBSOLETE_FUNCTIONS
    ImFontAtlasRect TempRect;                       // 1.92 obsoleted
    inline ImFontAtlasRectId AddCustomRectRegular(int w, int h)  // 1.92 重命名
        { return AddCustomRect(w, h); }
    // ...
#endif
```

### 已删除（不再保留）

```cpp
//int       KeyMap[ImGuiKey_COUNT];     // 1.87 删除
//bool      KeysDown[ImGuiKey_COUNT];   // 1.87 删除
//float     NavInputs[];                 // 1.88 删除
```

——这些字段**已经不存在**。`#ifndef IMGUI_DISABLE_OBSOLETE_FUNCTIONS` 包了**注释**而不是真字段，作为"墓碑"提示。

## C.4 历史 breaking change 清单（按时间）

按 ImGui 实际发布历史的关键变更：

### 1.87 (2022-02)：现代输入 API

- ❌ 删除 `io.KeyMap[]`
- ❌ 删除 `io.KeysDown[]`
- ✅ 新增 `io.AddKeyEvent(ImGuiKey, bool)`
- ✅ 新增 `io.AddMousePosEvent / AddMouseButtonEvent / AddMouseWheelEvent`
- ✅ 新增 `io.AddInputCharacter / AddInputCharacterUTF16 / AddInputCharactersUTF8`
- ✅ 新增 `io.AddFocusEvent`
- ✅ `ImGuiKey` 枚举重新设计（>512 是 Named Key）

**迁移**：见第 1.3 章 Hazel 完整迁移代码。

### 1.88 (2022-04)：Gamepad 重构

- ❌ 删除 `io.NavInputs[]`
- ✅ 手柄按钮变成 `ImGuiKey_GamepadXxx`
- ✅ `io.AddKeyAnalogEvent` 支持手柄轴

### 1.89 (2022-11)：Owner-Aware Input + DragDrop

- ✅ 新增 `Shortcut` / `SetShortcutRouting` API
- ✅ 新增 `ImGuiInputFlags_RouteXxx` 标志
- ✅ `SetItemKeyOwner` / `SetKeyOwner` 内部 API

### 1.90 (2023-11)：Tables 改进 + 多选

- ✅ 新增 `BeginMultiSelect / EndMultiSelect`
- ✅ Tables 多个新 flag

### 1.91 (2024-08)：剪贴板移到 PlatformIO

- ❌ 软废弃 `io.GetClipboardTextFn / SetClipboardTextFn / ClipboardUserData`
- ✅ 新位置 `ImGuiPlatformIO::Platform_GetClipboardTextFn / SetClipboardTextFn`
- ✅ 函数签名改：`const char*(*)(ImGuiContext*)` 替代旧的 `(void*)`
- ✅ 新增 `Platform_OpenInShellFn`

### 1.91.6 (2024-11)：CRC32 表更换

- ⚠ ImHashStr 切到 SSE 兼容表（默认）
- ⚠ `IMGUI_USE_LEGACY_CRC32_ADLER` 配置宏保留兼容旧 .ini

### 1.92 (2025-06)：动态纹理 + 字体重构

- ✅ 新增 `ImTextureRef / ImTextureData / ImTextureStatus`
- ✅ 新增 `IMGUI_HAS_TEXTURES`
- ❌ `ImDrawCmd::TextureId` 字段移除（用 `GetTexID()`）
- ❌ 字体 API 改：`AddCustomRectRegular` → `AddCustomRect`
- ❌ `io.FontGlobalScale` 软废弃 → `style.FontScaleMain`
- ✅ 字体动态烘焙（不再需要 atlas->Build）
- ⚠ `font->CalcTextSizeA` 不再线程安全

### 未来已宣告（基于现有 issue）

- 多 Context 并行模式（#5856 / #6293 / #8069）。
- Context 显式参数（#586，长期目标）。
- `InputEventsQueue` 加锁（#5772）。
- 富文本（rich text）支持。

## C.5 防御代码模板

### 模板 1：版本守护写法

```cpp
// 安全访问 internal 字段
#if IMGUI_VERSION_NUM >= 19271 && IMGUI_VERSION_NUM < 20000
    g.LastItemData.ID = my_id;
#else
    #error "Unsupported ImGui version - check internal field compat"
#endif
```

**上下界双重守护**——升级时主动审视 + 防止意外回退。

### 模板 2：obsolete API 检查

```cpp
// 用 IMGUI_DISABLE_OBSOLETE_FUNCTIONS 编译过一遍
// 在 imconfig.h:
#ifdef HAZEL_AUDIT_IMGUI_USAGE
    #define IMGUI_DISABLE_OBSOLETE_FUNCTIONS
#endif
```

定期开 `HAZEL_AUDIT_IMGUI_USAGE` 编译——任何用了 obsolete API 的代码会编译失败 → 立刻清理。

### 模板 3：抽象封装

```cpp
namespace Hazel::ImGuiCompat {

// 用我们的 wrapper 隔离 ImGui 直接调用
inline void SetClipboardCallback(ImGuiPlatformIO& pio, const char*(*get_fn)(ImGuiContext*),
                                                       void(*set_fn)(ImGuiContext*, const char*)) {
#if IMGUI_VERSION_NUM >= 19110
    pio.Platform_GetClipboardTextFn = get_fn;
    pio.Platform_SetClipboardTextFn = set_fn;
#else
    // 旧 API 适配层
    static auto* g_get = get_fn;
    static auto* g_set = set_fn;
    ImGui::GetIO().GetClipboardTextFn = [](void*) { return g_get(ImGui::GetCurrentContext()); };
    ImGui::GetIO().SetClipboardTextFn = [](void*, const char* text) { g_set(ImGui::GetCurrentContext(), text); };
#endif
}

}  // namespace Hazel::ImGuiCompat
```

——你的引擎只调 `Hazel::ImGuiCompat::SetClipboardCallback`。ImGui 升级时只需要改这个 wrapper。

### 模板 4：IMGUI_CHECKVERSION 强制检查

```cpp
void Application::InitImGui() {
    IMGUI_CHECKVERSION();   // ★ 必须的第一行
    
    ImGui::CreateContext();
    // ...
}
```

`IMGUI_CHECKVERSION` 在多 .cpp 编译单元下保护 ABI 一致——任何 .cpp 看到的 sizeof(ImGuiIO) 与 imgui.cpp 看到的不一致就 IM_ASSERT 失败。

### 模板 5：跟踪关键 sizeof

```cpp
// 在你的引擎初始化时打 log：
HZ_CORE_INFO("ImGui version: {} ({})", IMGUI_VERSION, IMGUI_VERSION_NUM);
HZ_CORE_INFO("sizeof(ImGuiIO) = {}", sizeof(ImGuiIO));
HZ_CORE_INFO("sizeof(ImGuiStyle) = {}", sizeof(ImGuiStyle));
HZ_CORE_INFO("sizeof(ImDrawVert) = {}", sizeof(ImDrawVert));
HZ_CORE_INFO("sizeof(ImDrawIdx) = {}", sizeof(ImDrawIdx));
```

升级 ImGui 后对比这些 sizeof——异常变化提示 ABI 改了。

## C.6 真实迁移清单（1.84 → 1.92）

如果你有一份 Cherno Hazel 老代码（1.84 时代），按这个清单逐项处理：

### Phase 1：编译失败必修（红色）

- [ ] 删除所有 `io.KeyMap[X] = Y;`
- [ ] 把所有 `io.KeysDown[code] = true/false` 替换为 `io.AddKeyEvent(...)`
- [ ] 把所有手柄 `io.NavInputs[X] = Y` 替换为 `io.AddKeyEvent(ImGuiKey_GamepadX, ...)`
- [ ] 写 `HazelKeyToImGuiKey` 转换函数

### Phase 2：行为正确性必修（橙色）

- [ ] 把 `io.MouseDown[i] = ...` 替换为 `io.AddMouseButtonEvent(i, ...)`
- [ ] 把 `io.MousePos = ...` 替换为 `io.AddMousePosEvent(x, y)`（多视口下传虚拟桌面坐标）
- [ ] 把 `io.MouseWheel += ...` 替换为 `io.AddMouseWheelEvent(0, dy)`
- [ ] 删除手动 `io.KeyCtrl/Shift/Alt/Super = ...`（自动派生）
- [ ] 添加 `OnWindowFocus / OnWindowLostFocus` → `io.AddFocusEvent(...)`
- [ ] 字符输入 `(unsigned short)` 改 `(unsigned int)`（避免截断）

### Phase 3：1.91 / 1.92 跟进（黄色）

- [ ] 剪贴板从 `io.SetClipboardTextFn` 移到 `pio.Platform_SetClipboardTextFn`
- [ ] `io.FontGlobalScale = X` 改 `style.FontScaleMain = X`
- [ ] `cmd->TextureId` 改 `cmd->GetTexID()`
- [ ] `ImGui::Image((ImTextureID)x, ...)` → `ImGui::Image(ImTextureRef(x), ...)`（隐式构造仍能编）

### Phase 4：建议增强

- [ ] 实现 IME 桥接（CJK 用户必需）
- [ ] 启用 `ImGuiBackendFlags_RendererHasTextures`（动态字体）
- [ ] 启用 `ConfigFlags_DpiEnableScaleFonts`（HiDPI）
- [ ] 启用 `ConfigDebugHighlightIdConflicts`（默认就开）

## C.7 升级流程标准操作

每次 ImGui 升级时按这个流程：

### Step 1：备份 + 阅读 changelog

```bash
git tag pre-imgui-upgrade
git submodule update --remote imgui   # 或下载新版
```

打开 imgui.h 顶部，找到 `// CHANGELOG` 段——读所有 1.XX → 1.YY 的 BREAKING CHANGES。

### Step 2：编译看错误

```bash
cmake --build . --config Debug
```

收集所有编译错误。每个错误对应一个迁移点。

### Step 3：开启 obsolete 检测

```cpp
// imconfig.h（临时）
#define IMGUI_DISABLE_OBSOLETE_FUNCTIONS
```

再次编译——这次会暴露所有"还在用的 obsolete API"。逐个改成新 API。

### Step 4：运行 Demo + Metrics

```cpp
ImGui::ShowDemoWindow();
ImGui::ShowMetricsWindow();
```

跑一帧——确认所有功能可视化都正常（窗口、按钮、滑块、表格、Demo 各章节）。

### Step 5：跑你的引擎测试

如果你有自动化测试（imgui_test_engine）：

```bash
./HazelTests --gtest_filter=ImGui*
```

如果没有，手动测试每个面板。

### Step 6：性能回归测试

```cpp
// 测量一帧 ImGui 的耗时
auto t0 = high_resolution_clock::now();
ImGui::NewFrame();
RenderUI();
ImGui::Render();
auto dt = duration_cast<microseconds>(high_resolution_clock::now() - t0).count();

HZ_CORE_INFO("ImGui frame: {} us", dt);
```

对比升级前 / 升级后——如果新版变慢，去看 release notes 找原因。

### Step 7：升级 .ini

如果是 1.91.6 之前升级到 1.91.6+：CRC32 表换了 → **所有窗口位置丢失**。要么：

- 用 `IMGUI_USE_LEGACY_CRC32_ADLER` 兼容旧 .ini（不推荐，长期看会废）。
- 让用户重新调整窗口（可接受）。
- 写迁移工具：解析旧 .ini → 用新 hash 算法重新写 ID。

## C.8 监控 ImGui 升级风险

### 1. 跟踪 GitHub release

订阅 https://github.com/ocornut/imgui/releases —— 每次 release 收邮件。

### 2. 跟踪 dev branch

ImGui 有 `master` / `docking` 分支。Docking 分支多了 multi-viewport 等。两者都活跃维护。

### 3. 关键 issue / discussion

- **#586**：让 Context 显式参数。如果实现了，所有 ImGui::XXX 函数签名会变 → 大迁移。
- **#5772**：InputEventsQueue 加锁。改了之后多线程模型可能演进。
- **#8069 / #6293 / #5856**：多 Context 并行。

定期看这些 issue 的 update。

### 4. 关键宏的监控

```cpp
// 这些宏的存在 / 取消存在 = 大变更信号
IMGUI_HAS_TABLE       // 1.80+
IMGUI_HAS_TEXTURES    // 1.92+
IMGUI_HAS_DOCK        // Docking 分支
IMGUI_HAS_VIEWPORT    // Docking 分支
```

定义新宏 = 新功能上线。

## C.9 长期防御策略

### 策略 1：包装层（Adapter Layer）

不直接调 ImGui，而是在 `Hazel::UI::` 命名空间封装：

```cpp
namespace Hazel::UI {

void Begin(const char* name);
bool Button(const char* label);
bool SliderFloat(const char* label, float& value, float min, float max);
// ...

}  // namespace
```

应用代码只调 `Hazel::UI::*`。ImGui 升级时只改 wrapper。

**代价**：API 重复 + 性能略有损失（一次 inline call）。
**收益**：升级时改一个文件就行。

99% 应用不需要这层抽象——直接用 ImGui API 性价比更高。除非你有"严苛 LTS 要求"或"想换 GUI 库"。

### 策略 2：钉死版本

```bash
# .gitmodules
[submodule "vendor/imgui"]
  path = vendor/imgui
  url = https://github.com/ocornut/imgui
  branch = v1.92.x
```

把 ImGui 钉到某个 LTS 版本（例如 1.92.x）。**只升级 patch 版本**——稳定性高，但拿不到新功能。

### 策略 3：保持锐意（推荐）

每 3-6 个月升级一次到最新稳定版。代价是定期迁移（每次 1 天工作量），收益是持续拿到新特性 + bug 修复。

## C.10 本附录小结

ImGui 版本漂移防御的 4 条铁律：

1. **公开 API 稳定，Internal API 漂移**——尽量只用公开 API，必须用 internal 时**总是**包裹 `IMGUI_VERSION_NUM` 守护。
2. **每次升级读 changelog**——`imgui.h` 顶部的 CHANGELOG 段是 ground truth。
3. **定期开 `IMGUI_DISABLE_OBSOLETE_FUNCTIONS` 编译**——主动暴露老代码。
4. **`IMGUI_CHECKVERSION()` 是必须的**——保护 ABI 一致性。
