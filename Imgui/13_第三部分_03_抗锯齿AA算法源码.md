## 3.3.0 为什么需要软件 AA

GPU 硬件提供两种"开箱即用"的 AA：

1. **MSAA**（Multi-Sample Anti-Aliasing）：每个像素采样多个子像素，覆盖率求平均。优点：通用且效果好；缺点：内存翻倍 + 带宽翻倍 + 不能被自定义 shader 利用。
2. **`glLineWidth + GL_LINE_SMOOTH`**：OpenGL 的内置抗锯齿线。优点：一行代码；缺点：质量极差（只在某些驱动上做 AA、宽度受限、不一致）。

**ImGui 对这两种都不满意**：

- MSAA 不开默认就难看；开了浪费带宽（UI 全屏 4×AA = 4× 带宽）。
- `GL_LINE_SMOOTH` 在不同 GPU 上行为不同，无法保证视觉一致性。

**ImGui 的方案**：在 CPU 端**软件 AA**——为每条线/每个填充区域生成额外的"渐变 alpha 顶点"。配合标准 alpha blend，得到漂亮、一致、跨平台的抗锯齿效果。

代价：**顶点数翻倍/三倍**。但 ImGui 的 UI 顶点本来就少（万级），翻倍后也比 MSAA 4× 全屏便宜得多。

## 3.3.1 AA 的视觉原理：从内不透明到外透明的渐变

```
不带 AA 的 1px 线：
  ┌──┐
  │██│      硬边 → 锯齿
  └──┘

带 AA 的 1px 线：
  ┌──┐
  │░░│      
  │██│      内部不透明
  │░░│      
  └──┘      外部 alpha 渐变到 0 → 平滑

更准确的视觉模型（每个像素的 alpha）：
  alpha = 0.0 → 0.5 → 1.0 → 0.5 → 0.0
  位置：    外      过渡      内       过渡    外
```

把"内部完全不透明 + 外部 alpha=0"的两组顶点连接成三角形带，GPU 在光栅化时**线性插值** alpha，自动产生过渡。

最终经过 alpha blend：
```
DstColor = SrcColor * SrcAlpha + DstColor * (1 - SrcAlpha)
```

—— alpha = 1.0 处完全覆盖、alpha = 0 处保持原色、中间渐变。

## 3.3.2 两个核心宏：法线计算与修正

打开 `imgui_draw.cpp:803~805`：

```cpp
#define IM_NORMALIZE2F_OVER_ZERO(VX,VY)     { float d2 = VX*VX + VY*VY; if (d2 > 0.0f) { float inv_len = ImRsqrt(d2); VX *= inv_len; VY *= inv_len; } } (void)0
#define IM_FIXNORMAL2F_MAX_INVLEN2          100.0f
#define IM_FIXNORMAL2F(VX,VY)               { float d2 = VX*VX + VY*VY; if (d2 > 0.000001f) { float inv_len2 = 1.0f / d2; if (inv_len2 > IM_FIXNORMAL2F_MAX_INVLEN2) inv_len2 = IM_FIXNORMAL2F_MAX_INVLEN2; VX *= inv_len2; VY *= inv_len2; } } (void)0
```

### `IM_NORMALIZE2F_OVER_ZERO`：单位化向量

```cpp
{
    float d2 = VX*VX + VY*VY;       // 长度的平方
    if (d2 > 0.0f) {
        float inv_len = ImRsqrt(d2); // 1.0 / sqrt(d2)
        VX *= inv_len;
        VY *= inv_len;
    }
}
```

把 `(VX, VY)` 单位化（使长度为 1）。`d2 > 0.0f` 防止除零（退化情况两点重合）。

**`ImRsqrt` 是 1/sqrt** ——某些平台上 `1/sqrt(x)` 比 `sqrt(x)` + `1/x` 更快（特别是用了 SSE rsqrtps 指令）。

### `IM_FIXNORMAL2F`：处理"急转弯"的法线放大

```cpp
{
    float d2 = VX*VX + VY*VY;
    if (d2 > 0.000001f) {
        float inv_len2 = 1.0f / d2;            // 注意：是 1/d²，不是 1/sqrt(d²)
        if (inv_len2 > IM_FIXNORMAL2F_MAX_INVLEN2)   // 100.0
            inv_len2 = IM_FIXNORMAL2F_MAX_INVLEN2;
        VX *= inv_len2;
        VY *= inv_len2;
    }
}
```

这个宏更微妙——**它做的不是"单位化"，而是"补偿"**。

### 为什么需要补偿

考虑一条折线在转角处：

```
       n1
       ↑
       │
   ──→─┼─→──   (segment 1)
       │
       │       (segment 2)
       │
       ▼
       n2
```

`temp_normals[i]` 存的是每段的**单位法线**（垂直于线段方向）。在转角处，两段法线的"平均"`(n1 + n2) * 0.5` 不再是单位长度——它**短于 1**：

```
急转弯（90°）：
  n1 = (1, 0)
  n2 = (0, 1)
  avg = (0.5, 0.5)
  |avg| = 0.707 ≈ 1/√2
```

如果直接用这个平均向量乘 `half_draw_size`，转角处的"伸长量"小于其他地方——**视觉上转角更细**。

### 补偿公式

我们想让顶点投射出去后**沿外侧轮廓的垂直距离仍为 `half_draw_size`**。设两条相邻段的法线 `n1, n2`，夹角 `θ`（线段转角的一半）：

```
|avg| = cos(θ)              （单位向量平均的长度）
我们想要 vertex 离原线段的距离 = half_draw_size
所以伸长量 = half_draw_size / cos(θ)
       = half_draw_size / |avg|

把 avg 缩放：avg * (1 / |avg|) → 单位长度
再乘 half_draw_size → 实际伸长量

但 ImGui 简化成：
avg * (1 / |avg|²) * half_draw_size

这是因为 |avg|² = (avg.x)² + (avg.y)²
1 / |avg|² 比 1 / |avg| 计算便宜（不开方）
```

**等价性**：

```
avg / |avg|² = (avg / |avg|) * (1/|avg|)
            = unit_avg * (1 / |avg|)
            = 单位向量 * 补偿因子
```

——刚好补偿了转角处法线缩短的效果。

### 为什么有 `MAX_INVLEN2 = 100`

如果两段法线**完全相反**（180° 转角），`avg = (0, 0)`，`d2 = 0`——除零。或者接近时 `1/d2` 变得极大，顶点被推到无穷远。

ImGui clamp 到 100：表示最大伸长 = 10× 单位长度。这对应"两段夹角为 ~5°"的极端情况。

注释里有个"案例号"`(see #4053, #3366)`——这是历史上某些"细线段产生奇怪几何"的 bug 修复后的 magic number。

## 3.3.4 准备阶段：每段法线

```cpp
// imgui_draw.cpp:840~860
const int idx_count = use_texture ? (count * 6) : (thick_line ? count * 18 : count * 12);
const int vtx_count = use_texture ? (points_count * 2) : (thick_line ? points_count * 4 : points_count * 3);
PrimReserve(idx_count, vtx_count);

// 临时缓冲：法线 + 临时顶点
_Data->TempBuffer.reserve_discard(points_count * ((use_texture || !thick_line) ? 3 : 5));
ImVec2* temp_normals = _Data->TempBuffer.Data;
ImVec2* temp_points = temp_normals + points_count;

// 计算每段法线
for (int i1 = 0; i1 < count; i1++)
{
    const int i2 = (i1 + 1) == points_count ? 0 : i1 + 1;
    float dx = points[i2].x - points[i1].x;
    float dy = points[i2].y - points[i1].y;
    IM_NORMALIZE2F_OVER_ZERO(dx, dy);
    temp_normals[i1].x = dy;          // 法线 = 切线旋转 90°
    temp_normals[i1].y = -dx;
}
if (!closed)
    temp_normals[points_count - 1] = temp_normals[points_count - 2];
```

**法线的几何**：

```
切线 = (dx, dy)（线段方向）
法线 = (dy, -dx)（顺时针旋转 90°）
```

对一条**水平向右**的线段 `(1, 0)`：
- 切线 = (1, 0)
- 法线 = (0, -1)（指向上方）

ImGui 用"上方"作为"线段的左侧"——这和它的"扇形 fill 必须顺时针"约定保持一致（CW 朝上）。

**`closed` vs 开放线**：

- 闭合线（环）：每段都有"下一段"——法线计算正常。
- 开放线：最后一段没有"下一段"——直接复制倒数第二段的法线（避免越界）。

### `temp_points` 的容量

```
非 thick_line / use_texture：每点 2 个临时点 → 总 vtx_count = points_count * 2 或 *3
thick_line：每点 4 个临时点 → 总 vtx_count = points_count * 4

reserve_discard(points_count * ((use_texture || !thick_line) ? 3 : 5))
                                                              ↑   ↑
                                                              法线1+点2  法线1+点4
```

`reserve_discard` 是 `ImVector` 的"扩容但不保留旧数据"版本——比 `reserve` 快（不需要 memcpy 旧数据）。

## 3.3.5 PATH 2：1 像素 AA 细线（最常见）

```cpp
// imgui_draw.cpp:862~959 (路径 2 部分，非 use_texture 且非 thick_line)
const float half_draw_size = AA_SIZE;   // 1.0 像素

// 每个 pivot 点 → 3 个顶点：center + outer1 + outer2
// 每个段 → 12 个索引（4 个三角形）
```

### 几何模型

```
            outer1   ← alpha = 0
          /
        center       ← alpha = 1
          \
            outer2   ← alpha = 0

线段方向 →
```

每个 pivot 点（line 上的转折点）生成 3 个顶点：
- **center**：在原始位置 + 0 偏移，alpha 全色。
- **outer1**：偏移 `+normal * half_draw_size`，alpha = 0。
- **outer2**：偏移 `-normal * half_draw_size`，alpha = 0。

### 顶点计算

```cpp
// imgui_draw.cpp:949~957
for (int i = 0; i < points_count; i++)
{
    _VtxWritePtr[0].pos = points[i];              _VtxWritePtr[0].uv = opaque_uv; _VtxWritePtr[0].col = col;       // Center
    _VtxWritePtr[1].pos = temp_points[i * 2 + 0]; _VtxWritePtr[1].uv = opaque_uv; _VtxWritePtr[1].col = col_trans; // Left edge
    _VtxWritePtr[2].pos = temp_points[i * 2 + 1]; _VtxWritePtr[2].uv = opaque_uv; _VtxWritePtr[2].col = col_trans; // Right edge
    _VtxWritePtr += 3;
}
```

**`col_trans = col & ~IM_COL32_A_MASK`**——保留 RGB，alpha 设 0。

`temp_points` 在前面已经填充：

```cpp
// imgui_draw.cpp:899~904
ImVec2* out_vtx = &temp_points[i2 * 2];
out_vtx[0].x = points[i2].x + dm_x;
out_vtx[0].y = points[i2].y + dm_y;
out_vtx[1].x = points[i2].x - dm_x;
out_vtx[1].y = points[i2].y - dm_y;
```

`(dm_x, dm_y)` 是 `IM_FIXNORMAL2F` 修正后的 "平均法线 × half_draw_size"。

### 索引：4 个三角形 / 段

每段连接两个 pivot 点（idx1 = 当前段起点的中心，idx2 = 终点的中心）。每个 pivot 周围 3 顶点，所以：
- `idx1 + 0` = 起点 center
- `idx1 + 1` = 起点 left
- `idx1 + 2` = 起点 right
- `idx2 + 0` = 终点 center
- `idx2 + 1` = 终点 left
- `idx2 + 2` = 终点 right

```cpp
// imgui_draw.cpp:914~921
_IdxWritePtr[0] = (idx2 + 0); _IdxWritePtr[1] = (idx1 + 0); _IdxWritePtr[2] = (idx1 + 2); // Right tri 1
_IdxWritePtr[3] = (idx1 + 2); _IdxWritePtr[4] = (idx2 + 2); _IdxWritePtr[5] = (idx2 + 0); // Right tri 2
_IdxWritePtr[6] = (idx2 + 1); _IdxWritePtr[7] = (idx1 + 1); _IdxWritePtr[8] = (idx1 + 0); // Left tri 1
_IdxWritePtr[9] = (idx1 + 0); _IdxWritePtr[10] = (idx2 + 0); _IdxWritePtr[11] = (idx2 + 1); // Left tri 2
_IdxWritePtr += 12;
```

**4 个三角形构成一个"双面渐变带"**：

```
左侧 fringe (alpha 0 → 1)：
  idx1+1 (left, α=0)  ───  idx2+1 (left, α=0)
       \               /  \
        \    Tri 4    /    \    Tri 3
         \           /      \
  idx1+0 (center, α=1) ─── idx2+0 (center, α=1)
         /           \      /
        /    Tri 1    \    /    Tri 2
       /               \  /
  idx1+2 (right, α=0)  ───  idx2+2 (right, α=0)
右侧 fringe (alpha 1 → 0)：
```

GPU 光栅化时，从 left（α=0）到 center（α=1）到 right（α=0）线性插值——形成两侧的过渡。

### 这就是 1 像素 AA 线的全部秘密

每段 4 个三角形 = 12 个索引 = 3 个顶点 / pivot。看起来浪费，但**GPU 端零额外计算**——alpha blend 全自动。

最终视觉效果：1 像素粗线，带 1 像素的左右过渡（共 3 像素宽，但视觉上仍是 1 像素的"细线"）。

## 3.3.6 PATH 3：粗 AA 线（thickness > 1）

```cpp
// imgui_draw.cpp:962~1029 (路径 3)
const float half_inner_thickness = (thickness - AA_SIZE) * 0.5f;
```

### 几何模型

粗线需要"内部不透明区"+ "两侧 AA fringe"：

```
                outer1   ← alpha = 0  （fringe 外缘）
              /
            inner1       ← alpha = 1  （内部边缘）
            │
            │            ← 不透明核心区
            │
            inner2       ← alpha = 1
              \
                outer2   ← alpha = 0
```

每个 pivot 4 个顶点：

```cpp
// 计算 4 个偏移量
float dm_out_x = dm_x * (half_inner_thickness + AA_SIZE);
float dm_out_y = dm_y * (half_inner_thickness + AA_SIZE);
float dm_in_x  = dm_x * half_inner_thickness;
float dm_in_y  = dm_y * half_inner_thickness;

// 写入 4 个临时点
out_vtx[0].x = points[i2].x + dm_out_x;   // Outer +
out_vtx[1].x = points[i2].x + dm_in_x;    // Inner +
out_vtx[2].x = points[i2].x - dm_in_x;    // Inner -
out_vtx[3].x = points[i2].x - dm_out_x;   // Outer -
// ... y 类似
```

### 索引：6 个三角形 / 段

```cpp
// 18 索引 = 6 三角形 / 段

//   [outer+, inner+] x 2 段 = 2 三角形 (fringe +)
//   [inner+, inner-] x 2 段 = 2 三角形 (核心)
//   [inner-, outer-] x 2 段 = 2 三角形 (fringe -)
```

```cpp

_IdxWritePtr[9]  = idx1+0; _IdxWritePtr[10] = idx2+0; _IdxWritePtr[11] = idx2+1;  // fringe + 2
_IdxWritePtr[12] = idx2+2; _IdxWritePtr[13] = idx1+2; _IdxWritePtr[14] = idx1+3;  // fringe - 1
_IdxWritePtr[15] = idx1+3; _IdxWritePtr[16] = idx2+3; _IdxWritePtr[17] = idx2+2;  // fringe - 2
```

### 顶点颜色

```cpp

_VtxWritePtr[0].pos = temp_points[i*4 + 0]; _VtxWritePtr[0].col = col_trans;  // Outer +, α = 0
_VtxWritePtr[1].pos = temp_points[i*4 + 1]; _VtxWritePtr[1].col = col;        // Inner +, α = 1
```

## 3.3.7 PATH 1：纹理 AA（线宽 ≤ 32）

`AntiAliasedLinesUseTex` 是个有趣的优化——**用一张预生成的纹理替代多三角形**。

### 想法

观察：宽度为 N 像素的 AA 线，沿垂直方向的 alpha 分布是固定的：

```
N=1:  [0.5]
N=2:  [1.0, 1.0] + 两端 fringe
N=3:  [0.5, 1.0, 0.5]
N=4:  [1.0, 1.0, 1.0, 1.0] + 两端 fringe
...
```

——**预先把所有宽度的 alpha 分布烘焙成一张纹理！**

```
TexUvLines[1]   →  纹理中"宽度 1 的 alpha 渐变"区段的 UV
TexUvLines[2]   →  宽度 2 ...
...
TexUvLines[63]  →  宽度 63
```

### 几何模型

每个 pivot **只 2 个顶点**（左右两侧）：

```cpp
// imgui_draw.cpp:872
const float half_draw_size = (thickness * 0.5f) + 1;
// outer 顶点偏移到 thickness/2 + 1 像素（额外 1 像素是 fringe）

// imgui_draw.cpp:941~946
ImVec4 tex_uvs = _Data->TexUvLines[integer_thickness];
ImVec2 tex_uv0(tex_uvs.x, tex_uvs.y);
ImVec2 tex_uv1(tex_uvs.z, tex_uvs.w);
for (int i = 0; i < points_count; i++)
{
    _VtxWritePtr[0].pos = temp_points[i * 2 + 0]; _VtxWritePtr[0].uv = tex_uv0; _VtxWritePtr[0].col = col;
    _VtxWritePtr[1].pos = temp_points[i * 2 + 1]; _VtxWritePtr[1].uv = tex_uv1; _VtxWritePtr[1].col = col;
    _VtxWritePtr += 2;
}
```

**关键差异**：

- 顶点的 `uv` 不再是白像素 UV，而是**线宽对应的纹理 UV 区段**。
- 顶点的 `col` 是 `col`（不是 col_trans）——alpha 由纹理采样决定，不是顶点颜色。

### 渲染时

GPU pixel shader：

```glsl
out_color = texture(font_atlas, uv) * frag_color;
```

`texture(...)` 采样图集——返回烘焙好的 alpha。乘以 `frag_color`（其 alpha = 1）。

**为什么需要双线性采样**：纹理空间内的 fringe 是不连续的（每像素一个值），双线性插值才能产生平滑过渡。如果 backend 用 NEAREST 采样，会看到锯齿。

### 性能

每段：
- 索引 6 个（2 三角形）。
- 顶点 2 个 / pivot。

**比 PATH 2 省 50% 顶点 + 50% 索引**——相同视觉质量。

### 限制

```cpp
// imgui_draw.cpp:833
const bool use_texture = (Flags & ImDrawListFlags_AntiAliasedLinesUseTex) 
                      && (integer_thickness < IM_DRAWLIST_TEX_LINES_WIDTH_MAX) 
                      && (fractional_thickness <= 0.00001f) 
                      && (AA_SIZE == 1.0f);
```

**4 个限制**：

1. backend 必须开启 `ImDrawListFlags_AntiAliasedLinesUseTex`。
2. 线宽必须 < `IM_DRAWLIST_TEX_LINES_WIDTH_MAX`（默认 32 像素）。
3. 线宽必须是整数（小数像素不在烘焙范围）。
4. `AA_SIZE == 1.0f`（不能与 `_FringeScale` 配合）。

**实战建议**：为了最佳性能，开 `AntiAliasedLinesUseTex` + 线宽用整数 + 不缩放画布。

## 3.3.8 PATH 4：非 AA 线（最快但难看）

```cpp
// imgui_draw.cpp:1034~1062
const int idx_count = count * 6;
const int vtx_count = count * 4;
PrimReserve(idx_count, vtx_count);

for (int i1 = 0; i1 < count; i1++)
{
    const int i2 = (i1 + 1) == points_count ? 0 : i1 + 1;
    const ImVec2& p1 = points[i1];
    const ImVec2& p2 = points[i2];

    float dx = p2.x - p1.x;
    float dy = p2.y - p1.y;
    IM_NORMALIZE2F_OVER_ZERO(dx, dy);
    dx *= (thickness * 0.5f);
    dy *= (thickness * 0.5f);

    _VtxWritePtr[0].pos.x = p1.x + dy; _VtxWritePtr[0].pos.y = p1.y - dx; ...
    _VtxWritePtr[1].pos.x = p2.x + dy; _VtxWritePtr[1].pos.y = p2.y - dx; ...
    _VtxWritePtr[2].pos.x = p2.x - dy; _VtxWritePtr[2].pos.y = p2.y + dx; ...
    _VtxWritePtr[3].pos.x = p1.x - dy; _VtxWritePtr[3].pos.y = p1.y + dx; ...
    _VtxWritePtr += 4;

    _IdxWritePtr[0] = ...; ... // 6 索引
    _IdxWritePtr += 6;
    _VtxCurrentIdx += 4;
}
```

**没有"段间共享顶点"**——每段独立 4 个顶点。这是为什么注释里说 `// FIXME-OPT: Not sharing edges`。

每段的 4 顶点构成一个矩形：

```
[0]──────[1]
 │        │       矩形宽度 = thickness
[3]──────[2]       4 顶点全是不透明 col
```

**性能**：每段 4 顶点 + 6 索引 = 24 字节顶点 + 12 字节索引 = 96 字节 / 段。最少。

**视觉**：硬边——线段边缘锯齿明显。仅适合性能极度受限的场景（嵌入式/手机）。

## 3.3.9 `AddConvexPolyFilled` 的 AA 模式

打开 `imgui_draw.cpp:1067~1147`。

### 几何模型

凸多边形 AA 填充 = 内部填充 + 外圈渐变 fringe：

```
        outer (alpha = 0)
       /│\
      / │ \
     /  │  \
    /   │   \
   /    │    \
  /  inner   \
 /   (alpha = 1)
/             \
```

每个原始顶点 → 2 个顶点（inner + outer），共 `points_count * 2` 顶点。

### 顶点计算

```cpp
// imgui_draw.cpp:1106~1126
for (int i0 = points_count - 1, i1 = 0; i1 < points_count; i0 = i1++)
{
    // Average normals
    const ImVec2& n0 = temp_normals[i0];
    const ImVec2& n1 = temp_normals[i1];
    float dm_x = (n0.x + n1.x) * 0.5f;
    float dm_y = (n0.y + n1.y) * 0.5f;
    IM_FIXNORMAL2F(dm_x, dm_y);
    dm_x *= AA_SIZE * 0.5f;
    dm_y *= AA_SIZE * 0.5f;

    // Add vertices
    _VtxWritePtr[0].pos.x = (points[i1].x - dm_x); _VtxWritePtr[0].pos.y = (points[i1].y - dm_y); _VtxWritePtr[0].uv = uv; _VtxWritePtr[0].col = col;        // Inner
    _VtxWritePtr[1].pos.x = (points[i1].x + dm_x); _VtxWritePtr[1].pos.y = (points[i1].y + dm_y); _VtxWritePtr[1].uv = uv; _VtxWritePtr[1].col = col_trans;  // Outer
    _VtxWritePtr += 2;
    
    // ... fringe 索引
}
```

**关键**：inner = `points[i] - dm * 0.5`，outer = `points[i] + dm * 0.5`。注意是 `±dm * 0.5`——`dm` 已经是 `AA_SIZE * 0.5` 了，所以总偏移是 `AA_SIZE`，但**对称分布**于原始顶点两侧。

这意味着**原始多边形轮廓的 alpha = 0.5**（处于过渡中点），而不是 alpha = 1。如果你的原始多边形精确覆盖某个像素，最终该像素会得到 50% alpha——这是 ImGui AA 的标准设计。

### 索引：内部填充 + fringe

#### 内部填充（扇形）

```cpp
// imgui_draw.cpp:1086~1090
for (int i = 2; i < points_count; i++)
{
    _IdxWritePtr[0] = vtx_inner_idx;
    _IdxWritePtr[1] = vtx_inner_idx + ((i - 1) << 1);
    _IdxWritePtr[2] = vtx_inner_idx + (i << 1);
    _IdxWritePtr += 3;
}
```

注意 `(i - 1) << 1` 和 `(i << 1)`——左移 1 = 乘 2。因为每个 pivot 有 2 顶点（inner + outer），所以索引步长是 2。

`vtx_inner_idx = _VtxCurrentIdx` —— 第一个 inner 顶点。`vtx_inner_idx + (i << 1)` —— 第 i 个 inner 顶点。

形成：`(inner_0, inner_{i-1}, inner_i)` 的扇形三角化（与第 3.2 章的扇形相同）。

#### Fringe 索引

```cpp
// imgui_draw.cpp:1122~1125
_IdxWritePtr[0] = vtx_inner_idx + (i1 << 1);
_IdxWritePtr[1] = vtx_inner_idx + (i0 << 1);
_IdxWritePtr[2] = vtx_outer_idx + (i0 << 1);
_IdxWritePtr[3] = vtx_outer_idx + (i0 << 1);
_IdxWritePtr[4] = vtx_outer_idx + (i1 << 1);
_IdxWritePtr[5] = vtx_inner_idx + (i1 << 1);
_IdxWritePtr += 6;
```

每条边（i0 → i1）：
- 三角形 1: (inner_i1, inner_i0, outer_i0)
- 三角形 2: (outer_i0, outer_i1, inner_i1)

形成"内 → 外 alpha 渐变"的两个三角形。

### 总顶点 / 索引

- 顶点：`points_count * 2`
- 索引：
  - 内部填充：`(points_count - 2) * 3`
  - Fringe：`points_count * 6`
  - 总计：`(points_count - 2) * 3 + points_count * 6`

例：6 边形（hexagon）：
- 12 顶点
- 12 + 36 = 48 索引（16 三角形）

非 AA 6 边形：
- 6 顶点
- 12 索引（4 三角形）

**AA 比非 AA 多 4× 几何**——但视觉质量提升明显。

## 3.3.10 非 AA 路径（凸填充）

```cpp
// imgui_draw.cpp:1129~1146
const int idx_count = (points_count - 2) * 3;
const int vtx_count = points_count;
PrimReserve(idx_count, vtx_count);

for (int i = 0; i < vtx_count; i++)
{
    _VtxWritePtr[0].pos = points[i]; _VtxWritePtr[0].uv = uv; _VtxWritePtr[0].col = col;
    _VtxWritePtr++;
}
for (int i = 2; i < points_count; i++)
{
    _IdxWritePtr[0] = _VtxCurrentIdx;
    _IdxWritePtr[1] = _VtxCurrentIdx + i - 1;
    _IdxWritePtr[2] = _VtxCurrentIdx + i;
    _IdxWritePtr += 3;
}
_VtxCurrentIdx += vtx_count;
```

朴素扇形——`points_count` 个顶点 + `(N-2) * 3` 个索引。

## 3.3.11 AA flag 的运行时控制

`ImDrawList::Flags` 是 per-DrawList 字段：

```cpp
ImDrawListFlags Flags;   // 当前 list 的 AA 设置
```

由 `ImDrawListSharedData::InitialFlags` 在 `_ResetForNewFrame` 中初始化（参见第 3.1 章）。

**用户可以临时改**：

```cpp
ImDrawList* dl = ImGui::GetWindowDrawList();
ImDrawListFlags backup = dl->Flags;
dl->Flags &= ~ImDrawListFlags_AntiAliasedLines;   // 关闭 AA 线
dl->AddLine(...);   // 这条线没有 AA
dl->Flags = backup;
```

**用途**：

- 性能关键路径：大量小图标 / 调试线。
- 像素艺术：需要硬边。
- 自定义渲染：你已经在 shader 里做了 AA，不需要 ImGui 帮忙。

### 全局开关

```cpp
ImGuiStyle& style = ImGui::GetStyle();
style.AntiAliasedLines = true;
style.AntiAliasedLinesUseTex = true;
style.AntiAliasedFill = true;
```

`SetupDrawListSharedData` 每帧把这些 flag 复制到 `g.DrawListSharedData.InitialFlags`，下帧新建的 DrawList 用新设置。

## 3.3.12 性能基准与优化建议

### 顶点数量对比

考虑画一条 100 段的折线（thickness = 1）：

| 模式 | 顶点数 | 索引数 |
|---|---|---|
| 非 AA | 400 | 600 |
| AA 细线 (PATH 2) | 300 | 1200 |
| 纹理 AA (PATH 1) | 200 | 600 |

**纹理 AA 总数据量最少 + 视觉最好**。

### 一帧 ImGui 的 AA 开销估算

中等编辑器一帧可能 ~5000~30000 顶点。其中：
- 字体（无 AA）：~50%
- 矩形填充（无 AA / AA Fill）：~30%
- 线段（AA Lines）：~10%
- 圆/圆角（AA Lines + AA Fill）：~10%

如果全部开 AA：顶点数大约多 50%。GPU 这 5000~10000 多余顶点完全不构成瓶颈。

### 建议

| 应用类型 | 建议 |
|---|---|
| **桌面编辑器** | 全开 AA + AntiAliasedLinesUseTex |
| **桌面游戏 UI** | AA Lines + AA Fill 开，UseTex 看 backend 是否支持 |
| **手机/嵌入式** | 关 AA，靠 MSAA 兜底 |
| **VR/AR** | 可能要关 AA（高分辨率 + 90 FPS 太敏感） |
| **像素艺术** | 全关 AA |

## 3.3.15 本章小结

`ImGui` AA 算法的 5 个核心要点：

1. **每个 pivot 多生成几个顶点**——内部 alpha=1 + 外部 alpha=0，让 GPU 光栅化时自动插值。
2. **`IM_NORMALIZE2F_OVER_ZERO` / `IM_FIXNORMAL2F`**——单位化和补偿转角处法线缩短。
3. **4 条路径**：纹理 AA / AA 细线 / AA 粗线 / 非 AA——按线宽和后端能力选择。
4. **凸多边形 AA**：内部扇形填充 + 外圈 fringe 渐变，每点 2 顶点。
5. **`_FringeScale`**：缩放 AA 区段宽度，配合"画布缩放"使用。

记住的两个数字：

- **AA 细线**：12 索引 / 段，3 顶点 / pivot。
- **纹理 AA**：6 索引 / 段，2 顶点 / pivot（最快 + 最好）。

读完本章你应该能看着 ImGui 任意 widget 的几何，说出"这是哪条 AA 路径生成的"。
