# 附录 A · ImGui 调试与性能分析工具速查

> **本附录目标**：把 ImGui 自带的调试工具**全部列出**——每个工具一段速查，配上"什么场景用它"。读完后你应该能在遇到任何 UI bug 时秒选工具，不用翻 Demo 找半天。

---

## A.1 三件套总览

```cpp
ImGui::ShowDemoWindow(&show_demo);              // ① Demo 窗（活文档 + 工具入口）
ImGui::ShowMetricsWindow(&show_metrics);        // ② Metrics 窗（内部状态全景）
ImGui::ShowDebugLogWindow(&show_debug_log);     // ③ Debug Log 窗（事件流）
```

**Debug 构建中默认开启全部三个**：

```cpp
#ifdef HZ_DEBUG
    if (m_ShowDemo)      ImGui::ShowDemoWindow(&m_ShowDemo);
    if (m_ShowMetrics)   ImGui::ShowMetricsWindow(&m_ShowMetrics);
    if (m_ShowDebugLog)  ImGui::ShowDebugLogWindow(&m_ShowDebugLog);
#endif
```

## A.2 Demo 窗：`ShowDemoWindow`

### 用途

- **活文档**：每个 ImGui 功能都有一段最小可运行的示例代码——`imgui_demo.cpp` 里。
- **工具入口**：Demo → Tools 子菜单里有所有调试工具的开关。
- **样式编辑器**：Demo → Tools → Style Editor，实时改主题颜色 + 间距，能保存到 ini。

### 速查：在 Demo 里找某功能的代码

1. Demo 窗里翻到对应章节（例如 `Widgets / Sliders`）。
2. 注释里能看到示例代码的源行。
3. 直接 grep `imgui_demo.cpp` 的对应章节名（例如搜 `// "Widgets/Sliders"`）。

### Demo 里值得记住的几个章节

| 章节 | 内容 |
|---|---|
| `Configuration` | 所有 io.ConfigFlags / Style 全选项的实时编辑 |
| `Window options` | ImGuiWindowFlags 全开关 |
| `Widgets` | 所有控件的用法示例 |
| `Layout & Scrolling` | Layout 各种特殊用法 |
| `Tables & Columns` | 表格全功能展示 |
| `Inputs, Navigation & Focus` | 焦点 / 导航的细节 |
| `Examples` | 完整的"小工具"实例（Console / SimpleLayout / Console / 等） |

## A.3 Metrics 窗：`ShowMetricsWindow`

### 顶部统计

```
Dear ImGui 1.92.8 WIP (19271)
Application avg 16.667 ms/frame (60.0 FPS)
27 vertices, 48 indices (16 triangles), 5 windows, 23 active windows
```

——一眼看 fps + 顶点/三角形数 + 窗口数。

### 子标签

#### Tools

| 工具 | 快捷查 |
|---|---|
| **Item Picker** | 按"开始"按钮，下次点击的 item 被高亮 + 显示 ID |
| **ID Stack Tool** | 反查任何 ID 的"哈希路径"（参见第 4.1 章） |
| **Show windows rectangles** | 可视化 OuterRect / InnerRect / WorkRect 等 |
| **Show windows begin order** | 标注 g.Windows 中每个窗口的 BeginOrder |
| **Stack tool** | 看当前 IDStack 的内容 |

#### Windows

每个窗口的状态：

```
"Editor" (Active=1, Skipped=0, Hidden=0, Collapsed=0)
   Pos=(100, 100), Size=(800, 600)
   Vtx=2456, Idx=4536
   Flags=ImGuiWindowFlags_None
```

——能看哪个窗口顶点最多（性能定位）、哪个窗口在 hidden 列表（找不到的窗口）。

#### Tables

每个 ImGuiTable 的内部状态——列宽、排序、隐藏列等。

#### DrawLists

按 viewport / window / BgFg 分组显示所有 ImDrawList——展开看每个 cmd 的：

- ClipRect (x1, y1, x2, y2)
- TexRef
- VtxOffset / IdxOffset / ElemCount

**点击 cmd**会在屏幕上**高亮**该 cmd 影响的区域——视觉确认"这个 cmd 画了什么"。

#### Viewports

Multi-Viewport 模式下每个 viewport 的状态——位置、大小、Platform / Renderer UserData。

#### IO

`ImGuiIO` 的所有字段——MouseDown / KeyMods / WantCaptureMouse / 等。

#### Inputs

当前帧 `g.InputEventsQueue` / `InputEventsTrail` 的全部事件——能看到 trickle 算法把哪些事件推迟到下一帧。

#### Memory

```
Active allocations: 47
Allocation count: 1234
Free count: 1187
```

——`g.DebugMemAllocCount / FreeCount` 的可视化。监控内存泄漏。

## A.4 Debug Log 窗：`ShowDebugLogWindow`

### 用途

ImGui 内部关键事件的**实时事件流**。比 Metrics 的"快照"更动态——你能看到"为什么这一帧 ActiveId 突然变化"。

### 事件类别

```cpp
enum ImGuiDebugLogFlags_ {
    ImGuiDebugLogFlags_EventActiveId      = 1 << 0,   // ActiveId 变更
    ImGuiDebugLogFlags_EventFocus         = 1 << 1,   // 焦点变更
    ImGuiDebugLogFlags_EventPopup         = 1 << 2,   // Popup 开/关
    ImGuiDebugLogFlags_EventNav           = 1 << 3,   // 导航
    ImGuiDebugLogFlags_EventClipper       = 1 << 4,   // ListClipper
    ImGuiDebugLogFlags_EventSelection     = 1 << 5,   // Multi-Select
    ImGuiDebugLogFlags_EventIO            = 1 << 6,   // 输入事件
    ImGuiDebugLogFlags_EventInputRouting  = 1 << 7,   // 快捷键路由
    ImGuiDebugLogFlags_EventDocking       = 1 << 8,
    ImGuiDebugLogFlags_EventViewport      = 1 << 9,
    ImGuiDebugLogFlags_OutputToTTY        = 1 << 20,  // 输出到控制台
    // ...
};
```

——**勾选感兴趣的类别**，对应事件就显示。

### 典型用法

#### 排查"焦点跳转"问题

```
开启 EventFocus 类别 → 看哪个 widget 偷了焦点
```

#### 排查"快捷键不响应"

```
开启 EventInputRouting 类别 → 看 Shortcut 调用是否被路由到正确的 owner
```

#### 排查"ActiveId 异常"

```
开启 EventActiveId 类别 → 看 ActiveId 在哪一帧被谁夺走
```

### 写入 Debug Log（自家代码）

```cpp
// imgui_internal.h
IMGUI_API void DebugLog(const char* fmt, ...);

// 用法：
ImGui::DebugLog("[MyApp] Loaded %d items in %.2f ms\n", count, time_ms);
```

——你的代码能往 Debug Log 写——给"自定义控件 + ImGui 默认事件"统一在一处。

## A.5 Item Picker 详解

### 用法

1. Demo → Tools → Item Picker。
2. 按 "Start"——鼠标变成十字十字光标。
3. 点击想调查的 widget。
4. ID Stack Tool 显示该 widget 的 ID 路径。

### 实现原理

`imgui.cpp:4988~4995`：

```cpp
if (g.DebugItemPickerActive && g.HoveredIdPreviousFrame == id)
    GetForegroundDrawList()->AddRect(bb.Min, bb.Max, IM_COL32(255, 255, 0, 255));
if (g.DebugItemPickerBreakId == id)
    IM_DEBUG_BREAK();
```

——当激活 Item Picker 时，每个 hovered 的 item 被画黄色框 + 调用 `IM_DEBUG_BREAK()`（如果你设了 break ID）。

### Break on Item

进阶用法——Item Picker 的"break"模式：

1. 点击 widget 后，记录其 ID。
2. 设 `g.DebugItemPickerBreakId = recorded_id`。
3. 下次该 ID 被 hover → debugger 自动 break。

——能让你在调试器里检查"那个 widget 被提交时的调用栈"。

## A.6 ID Stack Tool 详解

### 用法

```
Demo → Tools → ID Stack Tool
```

界面：

```
[Picker] [Pick]   ← 点这里激活 picker
ID 0xABCD1234:
   "Editor"          (window) 0xA1B2C3D4
   ↳ "Tools"         (PushID)  0xC3D4E5F6
     ↳ #5            (PushID int) 0x12345678
       ↳ "Save"      (Item) 0xABCD1234
```

——清楚显示这个 ID 的每一层贡献来源。

### 实现原理

回看第 4.1 章的 `DebugHookIdInfo`：

```cpp
ImGuiID ImGuiWindow::GetID(const char* str, const char* str_end) {
    ImGuiID seed = IDStack.back();
    ImGuiID id = ImHashStr(str, str_end ? (str_end - str) : 0, seed);
#ifndef IMGUI_DISABLE_DEBUG_TOOLS
    if (g.DebugHookIdInfoId == id)
        ImGui::DebugHookIdInfo(id, ImGuiDataType_String, str, str_end);
#endif
    return id;
}
```

——每次 `GetID` 计算出的 ID 等于用户选中的 `DebugHookIdInfoId` 时，记录"贡献"。最终 ID Stack Tool 显示整个贡献链。

## A.7 Show windows rectangles

```
Metrics → Tools → Show windows rectangles
```

每个窗口的 6 种 rect 用不同颜色：

| 颜色 | Rect | 含义 |
|---|---|---|
| 红色 | OuterRectClipped | 整个窗口外边界（被父裁剪后） |
| 绿色 | InnerRect | 内部（去除标题栏 / 菜单栏） |
| 蓝色 | InnerClipRect | InnerRect 缩进 WindowPadding/2 |
| 黄色 | WorkRect | 内容区（控件画在这） |
| 紫色 | ContentRegionRect | Content size 计算 |
| 橙色 | NavRect | Nav 用的 rect |

——直观理解第 4.2 章的"6 个嵌套 rect"。

## A.8 Style Editor

```
Demo → Tools → Style Editor
```

实时编辑：

- **Sizes** 标签：所有 padding / spacing / rounding 等数值。
- **Colors** 标签：所有 ImGuiCol_ 颜色。
- **Fonts** 标签：当前加载的字体列表 + 大小调整。
- **Rendering** 标签：AntiAliasedLines / Tessellation 等渲染参数。

### 保存样式

```
Style Editor → "Export" 按钮
   → 把当前 style 导出为 C++ 代码
```

复制粘贴到你的 `SetDarkThemeColors` 即可——这是设计师"调主题"的标准工作流。

## A.9 自定义调试输出

### `DebugLog` 写日志

```cpp
ImGui::DebugLog("[MyEditor] Selected entity: %d\n", entity_id);
```

——出现在 Debug Log 窗里。

### `DebugLocateItem` 高亮某个 ID

```cpp
ImGui::DebugLocateItem(my_id);
```

——下一帧把对应 widget 高亮黄色。用于"对程序员展示"——例如出错弹框时点一下"定位"。

### `DebugLocateItemOnHover`

```cpp
ImGui::DebugLocateItemOnHover(my_id);
```

——鼠标在某 widget 上 hover 时高亮"另一个" widget（用于"显示从这里到那里的关系"）。

### `DebugStartItemPicker`

```cpp
ImGui::DebugStartItemPicker();
```

——以编程方式触发 Item Picker（不需要用户去 Demo 菜单点）。

## A.10 性能分析

### 嵌入 Tracy / Optick

```cpp
#define HZ_PROFILE_FUNCTION() TracyCFunction()

void ImGuiLayer::Begin() {
    HZ_PROFILE_FUNCTION();   // ← Tracy 钩子
    // ...
}
```

Tracy 会显示每个 ImGui 函数的耗时——比 ImGui 自己的 Framerate 更精细。

### `IMGUI_DEBUG_LOG_TIMER_*` 内部分析

ImGui 内部有些代码包了简单 timer：

```cpp
// imgui.cpp 中（伪代码）
double t0 = ImGui::GetTime();
// ... 耗时操作 ...
double dt = ImGui::GetTime() - t0;
IMGUI_DEBUG_LOG("Operation took %.2f ms\n", dt * 1000);
```

打开 Debug Log 的 OutputToTTY 能看到这些。

### CPU 端 vs GPU 端

```cpp
// 一帧 ImGui 总耗时分布：
// CPU 端：
//   - NewFrame:      0.5 ms
//   - Build UI:      3-10 ms（应用代码）
//   - Render:        0.5 ms
//   - RenderDrawData CPU 部分:  1-2 ms
// GPU 端：
//   - Draw call 提交 + 光栅化:   0.2-1 ms
```

如果 RenderDrawData 慢——可能是 cmd 数量太多 / driver overhead 大。
如果 Build UI 慢——可能是用户代码低效（每帧重复算字符串等）。

## A.11 一份调试流程模板

遇到 UI bug 时的标准排查顺序：

```
1. 是不是显示问题？
    → Metrics → Windows → 找到问题窗口 → 看 Active / Hidden / Skipped
    → 看 Vtx 数（异常多 = 几何爆炸）
    
2. 是不是输入响应问题？
    → Item Picker 选目标 widget → 确认 ID
    → Debug Log 开 ActiveId → 看是否被偷
    → Metrics → IO → 看 WantCaptureMouse / Keyboard

3. 是不是布局问题？
    → Metrics → Tools → Show windows rectangles
    → 看 6 个 rect 是否符合预期
    → DebugShowGroupRects 看 BeginGroup 边界

4. 是不是焦点 / 导航问题？
    → Debug Log 开 Focus + Nav
    → 看 NavId 流转

5. 是不是 ID 冲突？
    → ConfigDebugHighlightIdConflicts (默认开)
    → hover 重复 widget 看是否有红框警告
    → 极端：IMGUI_DEBUG_HIGHLIGHT_ALL_ID_CONFLICTS

6. 性能问题？
    → Metrics → DrawLists → 看 cmd 数 / vtx 数
    → 检查是否用 ListClipper 跳过不可见行
    → 检查 ChannelsSplit 用得是否合理

7. 内存问题？
    → Metrics → Memory → 看 Active 是否持续上涨
    → 自己加 g.DebugMemAllocCount / FreeCount 监控
```

按这个顺序排查，95% 的 bug 能在 5 分钟内定位。

## A.13 本附录小结

ImGui 的"自带调试工具"是它**最被低估的特性**——它的内省能力比 99% 的 GUI 库都好。

记住的"3 件套 + 4 工具"：

- **3 件套**：Demo / Metrics / Debug Log。
- **4 工具**：Item Picker / ID Stack Tool / Show Rectangles / Style Editor。

任何 UI bug 优先用这些，再考虑加 print。
