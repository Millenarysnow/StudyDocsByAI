## 3.4.0 一帧 ImGui 的"draw call 数量"是怎么决定的

回顾第 3.1 章末尾的"性能预算"：一帧 ImGui ~50~500 个 draw call。这个数字不是命运注定——而是 **ImGui 内部"合并算法"**的结果。

**关键事实**：每个 `ImDrawCmd` ≈ 一次 GPU draw call。如果 ImGui 不做合并，每画一个矩形都新建一个 cmd，那么一帧可能有上万个 draw call——CPU 端 driver overhead 就能把帧率拖到 10 fps。

ImGui 的合并策略：**只要 `ClipRect / TexRef / VtxOffset` 不变，就把图元累加到当前 cmd**。本章前半段就是讲"什么时候这 3 个会变 + 怎么处理"。

## 3.4.1 三个不变量：ClipRect / TexRef / VtxOffset

```cpp
// imgui.h:3216
struct ImDrawCmdHeader {
    ImVec4          ClipRect;
    ImTextureRef    TexRef;
    unsigned int    VtxOffset;
};
```

这 3 个字段是 cmd 的"身份证"——决定一次 GPU draw call 的状态。

### 为什么是这 3 个

**ClipRect**：影响 `glScissor`。改变时必须重新提交 scissor 命令——必须新建 cmd。

**TexRef**：影响 `glBindTexture`。改变时必须重新绑定纹理——必须新建 cmd。

**VtxOffset**：影响 `glDrawElementsBaseVertex` 的 base vertex 参数。改变时索引基址变了——必须新建 cmd（即使其他状态相同）。

其他字段不影响合并：
- `IdxOffset` / `ElemCount`：每个 cmd 自己算。
- `UserCallback`：见后面（callback 强制屏障）。

### 内存连续布局的妙用

`imgui.h:3179` 的注释：

> `// - The ClipRect/TexRef/VtxOffset fields must be contiguous as we memcmp() them together (this is asserted for).`

`ImDrawCmdHeader` 的 3 个字段在 `ImDrawCmd` 中**前 3 个位置且连续**——可以用一次 `memcmp` 比较。

```cpp
// imgui_draw.cpp:564~568
#define ImDrawCmd_HeaderSize                            (offsetof(ImDrawCmd, VtxOffset) + sizeof(unsigned int))
#define ImDrawCmd_HeaderCompare(CMD_LHS, CMD_RHS)       (memcmp(CMD_LHS, CMD_RHS, ImDrawCmd_HeaderSize))
#define ImDrawCmd_HeaderCopy(CMD_DST, CMD_SRC)          (memcpy(CMD_DST, CMD_SRC, ImDrawCmd_HeaderSize))
#define ImDrawCmd_AreSequentialIdxOffset(CMD_0, CMD_1)  (CMD_0->IdxOffset + CMD_0->ElemCount == CMD_1->IdxOffset)
```

`HeaderSize` 编译期算出 = `offsetof(VtxOffset) + 4 = ClipRect(16) + TexRef(16) + VtxOffset(4) = 36` 字节。

`memcmp` 36 字节是一次连续比较，编译器可向量化（SSE 一条 PCMPEQQ 指令比 4 个 float + 16 字节 + 4 字节）。比"逐字段比较"快。

`AreSequentialIdxOffset`：检查 cmd0 的"末尾索引"恰好是 cmd1 的"起始索引"——即两个 cmd 在 IdxBuffer 中**物理相邻**。这是合并的必要条件。

## 3.4.2 `_OnChangedClipRect`：Clip Rect 变化时的合并算法

```cpp
// imgui_draw.cpp:585~605
void ImDrawList::_OnChangedClipRect()
{
    IM_ASSERT_PARANOID(CmdBuffer.Size > 0);
    ImDrawCmd* curr_cmd = &CmdBuffer.Data[CmdBuffer.Size - 1];

    // 情况 A：当前 cmd 已经有几何 + ClipRect 不同 → 必须新建
    if (curr_cmd->ElemCount != 0 && memcmp(&curr_cmd->ClipRect, &_CmdHeader.ClipRect, sizeof(ImVec4)) != 0)
    {
        AddDrawCmd();
        return;
    }
    IM_ASSERT(curr_cmd->UserCallback == NULL);

    // 情况 B：当前 cmd 是空的 + 与前一 cmd 的 header 完全相同 + 物理相邻 → 删除当前空 cmd（合并到前一）
    ImDrawCmd* prev_cmd = curr_cmd - 1;
    if (curr_cmd->ElemCount == 0 && CmdBuffer.Size > 1 && ImDrawCmd_HeaderCompare(&_CmdHeader, prev_cmd) == 0 && ImDrawCmd_AreSequentialIdxOffset(prev_cmd, curr_cmd) && prev_cmd->UserCallback == NULL)
    {
        CmdBuffer.pop_back();
        return;
    }

    // 情况 C：当前 cmd 是空的 + 不能合并 → 直接更新当前 cmd 的 ClipRect
    curr_cmd->ClipRect = _CmdHeader.ClipRect;
}
```

### 三种情况

#### 情况 A：当前 cmd 已经有几何 → 新建 cmd

最常见场景。例如：

```
绘制 → curr_cmd = { ClipRect=A, ElemCount=12 }
PushClipRect(B)
   ↓ _CmdHeader.ClipRect = B
   ↓ _OnChangedClipRect()
   ↓ 当前 cmd 有 12 个索引 + ClipRect 不同
   ↓ AddDrawCmd() → 新 cmd { ClipRect=B, ElemCount=0 }
```

#### 情况 B：当前 cmd 空 + 可与前 cmd 合并 → 弹出当前 cmd

例如：

```
绘制 → curr_cmd = { ClipRect=A, ElemCount=12 }
PushClipRect(B)
   ↓ AddDrawCmd → 新 cmd { ClipRect=B, ElemCount=0 }
   ↓ 用户没画任何东西
PopClipRect (回到 A)
   ↓ _CmdHeader.ClipRect = A
   ↓ _OnChangedClipRect()
   ↓ 当前 cmd { ClipRect=B, ElemCount=0 }
   ↓ 前 cmd { ClipRect=A, ElemCount=12 }
   ↓ 当前 cmd 空 + _CmdHeader 与前 cmd header 相同 → 弹出当前 cmd
```

**合并后状态**：只剩一个 cmd `{ ClipRect=A, ElemCount=12 }`。**Push/Pop 一次空操作什么都没产生**——零开销。

#### 情况 C：当前 cmd 空 + 不能合并 → 修改当前 cmd

```
开始 → curr_cmd = { ClipRect=fullscreen, ElemCount=0 }
PushClipRect(B)
   ↓ _CmdHeader.ClipRect = B
   ↓ _OnChangedClipRect()
   ↓ 当前 cmd 空，但前面没有 cmd 可合并（只有这一个）
   ↓ 直接修改 curr_cmd->ClipRect = B
```

### 这个算法解决了什么

**问题**：用户代码可能"嵌套 PushClipRect 然后什么都不画再 PopClipRect"——例如某个分支提前 return。如果每次 Push/Pop 都新建一个 cmd，会产生大量空 cmd。

**解决**：上面 3 种情况的组合——空 cmd 自动被合并/删除，最终输出的 `CmdBuffer` 紧凑。

## 3.4.3 `_OnChangedTexture` 与 `_OnChangedVtxOffset`

逻辑和 `_OnChangedClipRect` 几乎一样：

```cpp
// imgui_draw.cpp:607~630
void ImDrawList::_OnChangedTexture()
{
    IM_ASSERT_PARANOID(CmdBuffer.Size > 0);
    ImDrawCmd* curr_cmd = &CmdBuffer.Data[CmdBuffer.Size - 1];
    if (curr_cmd->ElemCount != 0 && curr_cmd->TexRef != _CmdHeader.TexRef)
    {
        AddDrawCmd();
        return;
    }
    if (curr_cmd->UserCallback != NULL)
        return;

    ImDrawCmd* prev_cmd = curr_cmd - 1;
    if (curr_cmd->ElemCount == 0 && CmdBuffer.Size > 1 && ImDrawCmd_HeaderCompare(&_CmdHeader, prev_cmd) == 0 && ImDrawCmd_AreSequentialIdxOffset(prev_cmd, curr_cmd) && prev_cmd->UserCallback == NULL)
    {
        CmdBuffer.pop_back();
        return;
    }
    curr_cmd->TexRef = _CmdHeader.TexRef;
}
```

——三段同构。`PushTexture` / `PopTexture` 也获得相同的"空 push/pop 零开销"特性。

```cpp
// imgui_draw.cpp:632~646
void ImDrawList::_OnChangedVtxOffset()
{
    _VtxCurrentIdx = 0;     // ← 注意：重置 _VtxCurrentIdx 为 0
    IM_ASSERT_PARANOID(CmdBuffer.Size > 0);
    ImDrawCmd* curr_cmd = &CmdBuffer.Data[CmdBuffer.Size - 1];
    if (curr_cmd->ElemCount != 0)
    {
        AddDrawCmd();
        return;
    }
    IM_ASSERT(curr_cmd->UserCallback == NULL);
    curr_cmd->VtxOffset = _CmdHeader.VtxOffset;
}
```

`_OnChangedVtxOffset` 略有不同——它会重置 `_VtxCurrentIdx = 0`。这是"16-bit 索引超过 64K 顶点"时的逃生路径：

```
正在写顶点：VtxBuffer.Size = 65000, _VtxCurrentIdx = 65000
PrimReserve(6, 4)：检测到 65000 + 4 ≥ 65536
   ↓ _CmdHeader.VtxOffset = VtxBuffer.Size = 65000
   ↓ _OnChangedVtxOffset()
   ↓ _VtxCurrentIdx = 0       ← 索引值从 0 开始
   ↓ AddDrawCmd → 新 cmd { VtxOffset=65000 }
继续写：索引值 0,1,2,...
渲染时：实际访问的顶点 = VtxBuffer[0+65000], VtxBuffer[1+65000], ...
```

GPU 用 `glDrawElementsBaseVertex(..., base_vertex=65000)` 完成偏移加法。

## 3.4.4 `_TryMergeDrawCmds`：相邻 cmd 的回看合并

```cpp
// imgui_draw.cpp:571~581
void ImDrawList::_TryMergeDrawCmds()
{
    IM_ASSERT_PARANOID(CmdBuffer.Size > 0);
    ImDrawCmd* curr_cmd = &CmdBuffer.Data[CmdBuffer.Size - 1];
    ImDrawCmd* prev_cmd = curr_cmd - 1;
    if (ImDrawCmd_HeaderCompare(curr_cmd, prev_cmd) == 0
        && ImDrawCmd_AreSequentialIdxOffset(prev_cmd, curr_cmd)
        && curr_cmd->UserCallback == NULL && prev_cmd->UserCallback == NULL)
    {
        prev_cmd->ElemCount += curr_cmd->ElemCount;
        CmdBuffer.pop_back();
    }
}
```

**做的事**：检查最后两个 cmd 是否能合并（header 相同 + 物理相邻 + 不是 callback）。如果能：把 curr 的 ElemCount 加到 prev、弹出 curr。

**何时调用**：通常用户不会直接调。`Channels API` 的 `Merge` 内部会用。

## 3.4.5 `AddCallback` 作为渲染屏障

```cpp
// imgui_draw.cpp:529~562
void ImDrawList::AddCallback(ImDrawCallback callback, void* userdata, size_t userdata_size)
{
    IM_ASSERT_PARANOID(CmdBuffer.Size > 0);
    ImDrawCmd* curr_cmd = &CmdBuffer.Data[CmdBuffer.Size - 1];
    IM_ASSERT(callback != NULL);
    IM_ASSERT(curr_cmd->UserCallback == NULL);
    if (curr_cmd->ElemCount != 0)
    {
        AddDrawCmd();
        curr_cmd = &CmdBuffer.Data[CmdBuffer.Size - 1];
    }

    curr_cmd->UserCallback = callback;
    if (userdata_size == 0)
    {
        curr_cmd->UserCallbackData = userdata;
        curr_cmd->UserCallbackDataSize = 0;
        curr_cmd->UserCallbackDataOffset = -1;
    }
    else
    {
        IM_ASSERT(userdata != NULL);
        IM_ASSERT(userdata_size < (1u << 31));
        curr_cmd->UserCallbackData = NULL;
        curr_cmd->UserCallbackDataSize = (int)userdata_size;
        curr_cmd->UserCallbackDataOffset = _CallbacksDataBuf.Size;
        _CallbacksDataBuf.resize(_CallbacksDataBuf.Size + (int)userdata_size);
        memcpy(_CallbacksDataBuf.Data + (size_t)curr_cmd->UserCallbackDataOffset, userdata, userdata_size);
    }

    AddDrawCmd();   // ← 强制新建一个空 cmd 在 callback 之后
}
```

### Callback 是什么

它是用户提供的函数指针，在 backend 渲染到对应 cmd 时被调用：

```cpp
typedef void (*ImDrawCallback)(const ImDrawList* parent_list, const ImDrawCmd* cmd);
```

用途：

- 切换渲染状态（例如换 shader 画 3D 场景）。
- 上传 push constant / uniform。
- 设置自定义 sampler。

详见第 5.3 章实战。

### 为什么 callback 强制新建 cmd

**callback 必须独占一个 cmd**——它的"位置"决定渲染顺序。如果某个 cmd 既包含几何**又**包含 callback，backend 不知道是先画几何还是先调 callback。

ImGui 的解决：

- callback **必须**在一个**全空** cmd（无几何）上。
- 然后立刻 `AddDrawCmd` 创建另一个空 cmd 接收后续几何。

```
普通 cmd { TexRef=A, ElemCount=20 }
callback cmd { UserCallback=MyFn, UserCallbackData=ptr, ElemCount=0 }
普通 cmd { TexRef=A, ElemCount=15 }   ← 后续几何
```

backend 渲染：

```cpp
for (cmd : pcmd) {
    if (cmd.UserCallback) {
        cmd.UserCallback(draw_list, &cmd);   // 调 callback，可能改 GL 状态
    } else {
        glDrawElements(GL_TRIANGLES, cmd.ElemCount, ...);
    }
}
```

### 特殊值 `ImDrawCallback_ResetRenderState`

```cpp
#define ImDrawCallback_ResetRenderState     (ImDrawCallback)(-8)
```

backend 看到这个特殊值时，**重新调用 SetupRenderState**（恢复 ImGui 的标准状态）。

用法：

```cpp
// 用户代码
ImDrawList* dl = ImGui::GetWindowDrawList();
dl->AddCallback(MyCustomCallback, NULL);   // 切换到我的 shader 渲染
// ... 我的渲染产生顶点 ...
dl->AddCallback(ImDrawCallback_ResetRenderState, NULL);   // 重置回 ImGui 标准
// ... 后续 ImGui 控件正常工作 ...
```

backend 端：

```cpp
// imgui_impl_opengl3.cpp 内（伪代码）
if (pcmd->UserCallback != NULL) {
    if (pcmd->UserCallback == ImDrawCallback_ResetRenderState)
        ImGui_ImplOpenGL3_SetupRenderState(...);   // ← 重置
    else
        pcmd->UserCallback(draw_list, pcmd);
}
```

### `_CallbacksDataBuf`：用户数据缓冲

回顾 1.91.4 引入的 `userdata_size > 0` 模式：

```cpp
struct MyData { int a, b, c; } d = {1, 2, 3};
draw_list->AddCallback(MyCallback, &d, sizeof(d));   // 复制
```

ImGui 把 `sizeof(d)` 字节复制到 `_CallbacksDataBuf`，记录 `UserCallbackDataOffset`。Render 时把 offset 加到 buf base 还原指针。

**为什么需要复制**：用户的 `d` 在 `AddCallback` 调用结束后就**离开作用域**——直接存指针会悬挂。

## 3.4.6 `ImDrawListSplitter`：Channels API

### 问题：图层的 Z-order 与 batching 的矛盾

考虑一个节点编辑器：

```
背景网格（用纹理 A）
节点框（无纹理）
节点内的图标（用纹理 B）
节点之间的连线（无纹理）
选中框（无纹理）
```

如果按用户代码顺序提交：

```
绘制顺序：背景 → 节点 1 → 节点 2 → ... → 连线 → 选中框
```

**问题**：每个节点之间都用了"无纹理 → 纹理 B → 无纹理"的纹理切换——一个节点 3 个 cmd × 100 个节点 = 300 cmd。

### 想要的合并

```
分桶：
  Channel 0：背景 (1 cmd, 纹理 A)
  Channel 1：节点框 (合并成 1 cmd, 无纹理)
  Channel 2：节点图标 (合并成 1 cmd, 纹理 B)
  Channel 3：连线 (合并成 1 cmd, 无纹理)
  Channel 4：选中框 (合并成 1 cmd, 无纹理)

最终 cmd 数 = 5 而不是 ~300
```

但是——按节点顺序处理更自然（用户代码是 `for (node) { draw_node(); }`）。怎么解决？

### 解法：Channel 拆分 + 合并

`ImDrawListSplitter` 让用户**虚拟地"切换通道"**——不影响绘制顺序，但内部把命令分桶。最后 `Merge` 时按 Channel 顺序拼起来。

```cpp
ImDrawListSplitter splitter;
splitter.Split(draw_list, 5);   // 5 个通道

splitter.SetCurrentChannel(draw_list, 0);
DrawBackground();   // 进入 channel 0

for (Node node : nodes) {
    splitter.SetCurrentChannel(draw_list, 1);
    DrawNodeFrame(node);   // 进入 channel 1
    
    splitter.SetCurrentChannel(draw_list, 2);
    DrawNodeIcon(node);   // 进入 channel 2
}

for (Edge edge : edges) {
    splitter.SetCurrentChannel(draw_list, 3);
    DrawEdge(edge);   // 进入 channel 3
}

splitter.SetCurrentChannel(draw_list, 4);
DrawSelection();   // 进入 channel 4

splitter.Merge(draw_list);
// 此时 draw_list 包含 channel 0,1,2,3,4 顺序拼接的命令
```

### 内部数据结构

```cpp
// imgui.h:3223
struct ImDrawChannel
{
    ImVector<ImDrawCmd>  _CmdBuffer;
    ImVector<ImDrawIdx>  _IdxBuffer;
};

// imgui.h:3232
struct ImDrawListSplitter
{
    int                       _Current;    // 当前 channel 编号
    int                       _Count;      // 活跃 channel 数
    ImVector<ImDrawChannel>   _Channels;
};
```

注意 channel **不**包含 `VtxBuffer`——所有 channel 共享一个 VtxBuffer。这样：

- 切换 channel 时只交换 CmdBuffer 和 IdxBuffer。
- 顶点写入持续推进同一个 VtxBuffer——索引值仍然有效（`_VtxCurrentIdx` 不重置）。

### `SetCurrentChannel` 的实现

```cpp
// imgui_draw.cpp:2232
void ImDrawListSplitter::SetCurrentChannel(ImDrawList* draw_list, int idx)
{
    IM_ASSERT(idx >= 0 && idx < _Count);
    if (_Current == idx) return;

    // 把当前 draw_list 的 CmdBuffer/IdxBuffer 拷贝（实际是 swap 字段）到当前 channel
    memcpy(&_Channels.Data[_Current]._CmdBuffer, &draw_list->CmdBuffer, sizeof(draw_list->CmdBuffer));
    memcpy(&_Channels.Data[_Current]._IdxBuffer, &draw_list->IdxBuffer, sizeof(draw_list->IdxBuffer));
    _Current = idx;
    // 把目标 channel 的内容拷到 draw_list
    memcpy(&draw_list->CmdBuffer, &_Channels.Data[idx]._CmdBuffer, sizeof(draw_list->CmdBuffer));
    memcpy(&draw_list->IdxBuffer, &_Channels.Data[idx]._IdxBuffer, sizeof(draw_list->IdxBuffer));
    draw_list->_IdxWritePtr = draw_list->IdxBuffer.Data + draw_list->IdxBuffer.Size;

    // 处理新通道的"当前 cmd 状态"
    ImDrawCmd* curr_cmd = (draw_list->CmdBuffer.Size == 0) ? NULL : &draw_list->CmdBuffer.Data[draw_list->CmdBuffer.Size - 1];
    if (curr_cmd == NULL)
        draw_list->AddDrawCmd();
    else if (curr_cmd->ElemCount == 0)
        ImDrawCmd_HeaderCopy(curr_cmd, &draw_list->_CmdHeader);
    else if (ImDrawCmd_HeaderCompare(curr_cmd, &draw_list->_CmdHeader) != 0)
        draw_list->AddDrawCmd();
}
```

**精彩之处**：用 `memcpy` 交换 `ImVector` 字段（3 个 int + ptr）。这其实就是 swap——但用 memcpy 写出来是为了避免 `ImVector::swap` 的间接调用（可能不会被内联）。

### `Merge`：把所有 channel 按顺序拼接

```cpp
// imgui_draw.cpp:2161（节选）
void ImDrawListSplitter::Merge(ImDrawList* draw_list)
{
    if (_Count <= 1) return;

    SetCurrentChannel(draw_list, 0);   // 切回 channel 0
    draw_list->_PopUnusedDrawCmd();

    // 计算合并后的总大小 + 修正 IdxOffset
    int new_cmd_buffer_count = 0;
    int new_idx_buffer_count = 0;
    ImDrawCmd* last_cmd = (_Count > 0 && draw_list->CmdBuffer.Size > 0) ? &draw_list->CmdBuffer.back() : NULL;
    int idx_offset = last_cmd ? last_cmd->IdxOffset + last_cmd->ElemCount : 0;
    for (int i = 1; i < _Count; i++)
    {
        ImDrawChannel& ch = _Channels[i];
        if (ch._CmdBuffer.Size > 0 && ch._CmdBuffer.back().ElemCount == 0 && ch._CmdBuffer.back().UserCallback == NULL)
            ch._CmdBuffer.pop_back();   // 弹出空 cmd

        if (ch._CmdBuffer.Size > 0 && last_cmd != NULL)
        {
            ImDrawCmd* next_cmd = &ch._CmdBuffer[0];
            if (ImDrawCmd_HeaderCompare(last_cmd, next_cmd) == 0 && last_cmd->UserCallback == NULL && next_cmd->UserCallback == NULL)
            {
                // 合并相邻 channel 的最后/最先 cmd
                last_cmd->ElemCount += next_cmd->ElemCount;
                idx_offset += next_cmd->ElemCount;
                ch._CmdBuffer.erase(ch._CmdBuffer.Data);
            }
        }
        // ...
        for (int cmd_n = 0; cmd_n < ch._CmdBuffer.Size; cmd_n++)
        {
            ch._CmdBuffer.Data[cmd_n].IdxOffset = idx_offset;
            idx_offset += ch._CmdBuffer.Data[cmd_n].ElemCount;
        }
    }

    draw_list->CmdBuffer.resize(draw_list->CmdBuffer.Size + new_cmd_buffer_count);
    draw_list->IdxBuffer.resize(draw_list->IdxBuffer.Size + new_idx_buffer_count);

    // 写入合并后的 cmd 和 idx 数据
    ImDrawCmd* cmd_write = ...;
    ImDrawIdx* idx_write = ...;
    for (int i = 1; i < _Count; i++) {
        ImDrawChannel& ch = _Channels[i];
        memcpy(cmd_write, ch._CmdBuffer.Data, ch._CmdBuffer.Size * sizeof(ImDrawCmd));
        memcpy(idx_write, ch._IdxBuffer.Data, ch._IdxBuffer.Size * sizeof(ImDrawIdx));
        // ...
    }
    // ...
    _Count = 1;
}
```

**核心逻辑**：

1. 弹出每个 channel 末尾的空 cmd（`_PopUnusedDrawCmd` 等价）。
2. **跨 channel 合并**：channel i-1 的最后 cmd 和 channel i 的第一 cmd 如果 header 相同，合并。
3. 修正每个 cmd 的 IdxOffset（因为 channel 之间的 IdxBuffer 拼接后偏移变了）。
4. 用 `memcpy` 把所有 channel 的 cmd / idx 拼接到 draw_list 的 buffer。

**结果**：原来分散在 N 个 channel 的命令，按 channel 顺序合并到 draw_list 的 CmdBuffer。如果跨 channel 的 cmd 状态相同，自动合并。

### `ImDrawList::ChannelsXxx` vs 自己用 `ImDrawListSplitter`

```cpp
// imgui.h:3400~3402
inline void ChannelsSplit(int count)    { _Splitter.Split(this, count); }
inline void ChannelsMerge()             { _Splitter.Merge(this); }
inline void ChannelsSetCurrent(int n)   { _Splitter.SetCurrentChannel(this, n); }
```

`ImDrawList` 自带一个 `_Splitter` 字段——可以直接用 `dl->ChannelsSplit(N)`。

但 `imgui.h:3397~3399` 注释明确说：

> `// - This API shouldn't have been in ImDrawList in the first place!`
> `//   Prefer using your own persistent instance of ImDrawListSplitter as you can stack them.`
> `//   Using the ImDrawList::ChannelsXXXX you cannot stack a split over another.`

——`ChannelsXXX` 不能嵌套！如果你的代码 `Split` 后又调用了某个函数，里面也 `Split`——内层会破坏外层的状态。

**正确做法**：在自己的类里持有 `ImDrawListSplitter`，不用 `ImDrawList::Channels*`。

### Tables / Columns 的内部使用

`imgui_tables.cpp` 内部用 `ImDrawListSplitter` 实现"每列独立 batch"——所以 1000 行 × 5 列的表格，相同列的所有单元格被合并成 1 cmd（如果都用同一纹理）。一个表格 ~5 cmd 而不是 5000。

## 3.4.7 1.92 动态纹理：`ImTextureRef` / `ImTextureData` / `ImTextureStatus`

第 0.4 章已经讲过基础，这里深入。

### 旧模型（1.91 之前）

```cpp
// 旧
typedef void* ImTextureID;   // backend 自定义

ImDrawCmd::TextureId = my_gl_handle;   // 直接存 backend 句柄
```

**问题**：

1. ImGui 只能引用"已创建"的纹理。动态字体（用户输入新字符）需要"先 cancel 当前帧渲染、build 字体、上传纹理、重新渲染"——复杂。
2. backend 必须维护"哪些纹理还在引用"——容易泄漏。

### 1.92 新模型


### Backend 必须实现的 4 件事

```cpp
// 在每帧 RenderDrawData 开头：
if (draw_data->Textures != nullptr)
    for (ImTextureData* tex : *draw_data->Textures)
```

`MyBackend_UpdateTexture` 根据 status：

```cpp
void MyBackend_UpdateTexture(ImTextureData* tex)
{
    if (tex->Status == ImTextureStatus_WantCreate) {
        // 1. 创建 GPU 纹理
        GLuint gl_handle;
        glGenTextures(1, &gl_handle);
        glBindTexture(GL_TEXTURE_2D, gl_handle);
        glTexImage2D(GL_TEXTURE_2D, 0, GL_RGBA, tex->TexWidth, tex->TexHeight, 0, GL_RGBA, GL_UNSIGNED_BYTE, tex->Pixels);
        // 2. 通知 ImGui
        tex->TexID = (ImTextureID)(uintptr_t)gl_handle;
        tex->Status = ImTextureStatus_OK;
    }
    else if (tex->Status == ImTextureStatus_WantUpdates) {
        // 1. 部分更新
        GLuint gl_handle = (GLuint)(uintptr_t)tex->TexID;
        glBindTexture(GL_TEXTURE_2D, gl_handle);
        for (const ImTextureRect& r : tex->Updates) {
            glTexSubImage2D(GL_TEXTURE_2D, 0, r.x, r.y, r.w, r.h, GL_RGBA, GL_UNSIGNED_BYTE, /* 像素子区 */);
        }
        tex->Status = ImTextureStatus_OK;
    }
    else if (tex->Status == ImTextureStatus_WantDestroy) {
        GLuint gl_handle = (GLuint)(uintptr_t)tex->TexID;
        glDeleteTextures(1, &gl_handle);
        tex->Status = ImTextureStatus_Destroyed;
    }
}
```

这 4 个分支处理纹理的完整生命周期——backend 完全反应式（只在 ImGui 请求时操作）。

### Backend 注册支持的 flag

```cpp

```

——告诉 ImGui "我支持动态纹理"。如果没设这个 flag，ImGui 会回退到"每帧重建整个图集"的旧模式。

## 3.4.8 渲染后端的完整契约

### Backend 必须做的事

1. **配置 RenderState**（OpenGL / DX11 状态机模式）：
   - `glBlendFunc(SRC_ALPHA, ONE_MINUS_SRC_ALPHA)`
   - `glDisable(GL_DEPTH_TEST)`
   - `glDisable(GL_CULL_FACE)`
   - `glEnable(GL_SCISSOR_TEST)`
   - 绑定 ImGui 专用 shader / 投影矩阵

2. **每个 ImDrawList**:
   - 上传 VtxBuffer / IdxBuffer 到 GPU。
   - 绑定 vertex layout（pos / uv / col）。

3. **每个 ImDrawCmd**:
   - 检查 `pcmd->UserCallback`：
     - `ResetRenderState` → 重新调 SetupRenderState。
     - 其他 → 调用 callback。
     - NULL → 走渲染分支。
   - 渲染分支：
     - 设置 scissor（基于 `pcmd->ClipRect`，注意坐标系转换 + Y 翻转）。
     - 绑定纹理（基于 `pcmd->GetTexID()`）。
     - 提交 draw call（`pcmd->ElemCount` / `pcmd->IdxOffset` / `pcmd->VtxOffset`）。

4. **动态纹理**（如果开了 `ImGuiBackendFlags_RendererHasTextures`）：
   - 在 `RenderDrawData` 开头处理 `draw_data->Textures` 中状态非 OK 的纹理。

### Backend 可以假设什么

- 顶点格式是 `ImDrawVert`（除非用了 `IMGUI_OVERRIDE_DRAWVERT_STRUCT_LAYOUT`）。
- 索引格式是 `ImDrawIdx`（默认 16-bit）。
- 三角形列表（`GL_TRIANGLES`），不是 strip / fan。
- 顺时针顶点顺序（不重要，因为 backend 关闭剔除）。
- ClipRect 在 `[DisplayPos, DisplayPos + DisplaySize]` 范围内（如果不开 multi-viewport，DisplayPos = 0）。

### Backend 不能做什么

- **不能修改 `ImDrawList` 的内容**——这是 ImGui 内部状态。
- **不能跨帧持有 `ImDrawList*`**——它在下一帧 `_ResetForNewFrame` 时会被清。
- **不能假设 cmd 顺序**：用户可能用 Channels API 重排了顺序。

```cpp
bool HazelImGui_RendererInit(Hazel::RendererAPI* api)
{
    auto* bd = new HazelImGuiRendererData();
    
    ImGuiIO& io = ImGui::GetIO();
    io.BackendRendererName = "Hazel";
    io.BackendFlags |= ImGuiBackendFlags_RendererHasVtxOffset;
    io.BackendFlags |= ImGuiBackendFlags_RendererHasTextures;
    io.BackendRendererUserData = bd;
    
    // 1. 创建 shader
    static const char* vert_src = R"(
        #version 410 core
        layout(location = 0) in vec2 Pos;
        layout(location = 1) in vec2 UV;
        layout(location = 2) in vec4 Color;
        uniform mat4 ProjMtx;
        out vec2 vUV;
        out vec4 vColor;
        void main() {
            vUV = UV;
            vColor = Color;
            gl_Position = ProjMtx * vec4(Pos.xy, 0.0, 1.0);
        }
    )";
    static const char* frag_src = R"(
        #version 410 core
        in vec2 vUV;
        in vec4 vColor;
        uniform sampler2D Tex;
        out vec4 OutColor;
        void main() {
            OutColor = vColor * texture(Tex, vUV);
        }
    )";
    bd->Shader = Hazel::Shader::Create(vert_src, frag_src);

    bd->IBO = Hazel::IndexBuffer::Create(/*dynamic*/);
    bd->VAO = Hazel::VertexArray::Create();
    bd->VAO->AddVertexBuffer(bd->VBO, /* 顶点布局 = ImDrawVert */);
    bd->VAO->SetIndexBuffer(bd->IBO);

    ImGui::GetPlatformIO().Renderer_TextureMaxWidth  = 8192;
    ImGui::GetPlatformIO().Renderer_TextureMaxHeight = 8192;
```

### RenderDrawData 函数（核心）

```cpp
void HazelImGui_RendererRenderDrawData(ImDrawData* draw_data)
{
    auto* bd = (HazelImGuiRendererData*)ImGui::GetIO().BackendRendererUserData;
    if (draw_data->DisplaySize.x <= 0 || draw_data->DisplaySize.y <= 0) return;
    
    int fb_width  = (int)(draw_data->DisplaySize.x * draw_data->FramebufferScale.x);
    int fb_height = (int)(draw_data->DisplaySize.y * draw_data->FramebufferScale.y);
    
    // 1. 处理纹理状态变化（1.92+）
    if (draw_data->Textures != nullptr) {
        for (ImTextureData* tex : *draw_data->Textures) {
            if (tex->Status != ImTextureStatus_OK)
                HazelImGui_UpdateTexture(tex);
        }
    }
    
    // 2. 设置渲染状态
    Hazel::RenderCommand::EnableBlending(BlendFunc::SrcAlpha, BlendFunc::OneMinusSrcAlpha);
    Hazel::RenderCommand::DisableDepthTest();
    Hazel::RenderCommand::DisableCullFace();
    Hazel::RenderCommand::EnableScissorTest();
    Hazel::RenderCommand::SetViewport(0, 0, fb_width, fb_height);
    
    // 3. 设置投影矩阵
    float L = draw_data->DisplayPos.x;
    float R = draw_data->DisplayPos.x + draw_data->DisplaySize.x;
    float T = draw_data->DisplayPos.y;
    float B = draw_data->DisplayPos.y + draw_data->DisplaySize.y;
    glm::mat4 proj = glm::ortho(L, R, B, T);   // 注意 B/T 顺序——Y 翻转
    
    bd->Shader->Bind();
    bd->Shader->SetMat4("ProjMtx", proj);
    bd->Shader->SetInt("Tex", 0);
    bd->VAO->Bind();
    
    // 4. 遍历每个 DrawList
    ImVec2 clip_off = draw_data->DisplayPos;
    ImVec2 clip_scale = draw_data->FramebufferScale;
    for (const ImDrawList* dl : draw_data->CmdLists)
    {
        // 上传 VBO / IBO
        bd->VBO->SetData(dl->VtxBuffer.Data, dl->VtxBuffer.Size * sizeof(ImDrawVert));
        bd->IBO->SetData(dl->IdxBuffer.Data, dl->IdxBuffer.Size * sizeof(ImDrawIdx));
        
        // 遍历 cmd
        for (int cmd_i = 0; cmd_i < dl->CmdBuffer.Size; cmd_i++)
        {
            const ImDrawCmd* pcmd = &dl->CmdBuffer[cmd_i];
            
            // 4a. UserCallback
            if (pcmd->UserCallback != nullptr) {
                if (pcmd->UserCallback == ImDrawCallback_ResetRenderState) {
                    HazelImGui_SetupRenderState();   // 重置
                } else {
                    pcmd->UserCallback(dl, pcmd);
                }
                continue;
            }
            
            // 4b. 设置 scissor（注意 Y 翻转，OpenGL 原点在左下）
            ImVec2 clip_min((pcmd->ClipRect.x - clip_off.x) * clip_scale.x,
                            (pcmd->ClipRect.y - clip_off.y) * clip_scale.y);
            ImVec2 clip_max((pcmd->ClipRect.z - clip_off.x) * clip_scale.x,
                            (pcmd->ClipRect.w - clip_off.y) * clip_scale.y);
            if (clip_max.x <= clip_min.x || clip_max.y <= clip_min.y) continue;
            Hazel::RenderCommand::SetScissor(
                (int)clip_min.x, fb_height - (int)clip_max.y,
                (int)(clip_max.x - clip_min.x), (int)(clip_max.y - clip_min.y));
            
            // 4c. 绑定纹理
            ImTextureID tex_id = pcmd->GetTexID();
            Hazel::Texture2D::BindByGLHandle((uint32_t)(uintptr_t)tex_id, /*slot=*/0);
            
            // 4d. 提交 draw call
            Hazel::RenderCommand::DrawIndexedBaseVertex(
                pcmd->ElemCount,
                sizeof(ImDrawIdx) == 2 ? IndexType::UInt16 : IndexType::UInt32,
                pcmd->IdxOffset * sizeof(ImDrawIdx),
                pcmd->VtxOffset);
        }
    }
}
```

### UpdateTexture 函数

```cpp
void HazelImGui_UpdateTexture(ImTextureData* tex)
{
    if (tex->Status == ImTextureStatus_WantCreate) {
        // 创建 GPU 纹理（用 Hazel 的 Texture2D 抽象）
        Hazel::Texture2DSpecification spec;
        spec.Width = tex->TexWidth;
        spec.Height = tex->TexHeight;
        spec.Format = Hazel::ImageFormat::RGBA8;
        spec.GenerateMips = false;
        
        auto texture = Hazel::Texture2D::Create(spec);
        texture->SetData(tex->Pixels, tex->TexWidth * tex->TexHeight * 4);
        // 必须设 LINEAR 采样（AntiAliasedLinesUseTex 需要）
        texture->SetFilter(Hazel::TextureFilter::Linear);
        
        // 把 Hazel handle 转成 ImTextureID
        tex->SetTexID((ImTextureID)(uintptr_t)texture->GetRendererID());
        tex->SetStatus(ImTextureStatus_OK);
        // 记得保存 texture 引用，避免被 GC
        tex->BackendUserData = texture.get();
    }
    else if (tex->Status == ImTextureStatus_WantUpdates) {
        auto* texture = (Hazel::Texture2D*)tex->BackendUserData;
        for (const ImTextureRect& r : tex->Updates) {
            // 复制像素子区到纹理
            uint8_t* sub_pixels = /* 从 tex->Pixels 提取 (r.x, r.y, r.w, r.h) 子区 */;
            texture->SetSubData(r.x, r.y, r.w, r.h, sub_pixels);
        }
        tex->SetStatus(ImTextureStatus_OK);
    }
    else if (tex->Status == ImTextureStatus_WantDestroy) {
        if (auto* texture = (Hazel::Texture2D*)tex->BackendUserData)
            delete texture;
        tex->BackendUserData = nullptr;
        tex->SetStatus(ImTextureStatus_Destroyed);
    }
}
```

至此第三部分（渲染管线深度剖析）4 章全部完成：

| 章 | 主题 | 核心收获 |
|---|---|---|
| 3.1 | 一帧旅程全链路 | NewFrame 20 步 / DrawDataBuilder 扁平化 / BgFgDrawLists 惰性创建 |
| 3.2 | ImDrawList 与 Path 系统 | 3 个游标的指针推进 / `_CmdHeader` 模板 / ArcFastVtx[48] 预计算表 / Path → AddPolyline / AddConvexPolyFilled |
| 3.3 | 抗锯齿 AA 算法源码 | 4 条路径 / 法线计算 + 修正 / 内不透明外透明渐变 / 纹理 AA 的 50% 顶点节省 |
| 3.4 | 顶点合并 / Splitter / Backend 契约 | 3 个不变量 (ClipRect/TexRef/VtxOffset) / 3 种 OnChanged 情况 / Channels API / 1.92 动态纹理 / 完整 Backend 骨架 |

**第三部分回答的根本问题**：ImGui 是怎么把"用户的 ImGui::Button 调用"变成"GPU 上画的三角形"的？

10 条机制全在这 4 章里：

1. `NewFrame` 重置逐帧状态（HoveredId、DrawList...）。
2. 用户调 `Button`/`Slider` 等 → 最终调用 `ImDrawList::AddRect` 等。
3. `AddRect` 走 Path API 或 PrimReserve+PrimWriteVtx。
4. 顶点写入用裸指针推进（无函数调用开销）。
5. AA 模式额外生成"alpha 渐变 fringe"顶点。
6. 状态变化（PushClipRect 等）通过 `_OnChangedXxx` 决定新建/合并 cmd。
7. `Render` 把多个 ImDrawList 收集到 `ImDrawData`。
8. `ImDrawDataBuilder` 按 layer 排序。
9. Backend 上传 VB/IB + 设状态 + 提交 draw call。
10. 1.92 动态纹理：backend 反应式处理 `WantCreate/WantUpdates/WantDestroy`。

读完第三部分你应该能：
- 写自家 Renderer Backend（不依赖 imgui_impl_*）。
- 用低级 API（`PrimReserve` + `_VtxWritePtr`）写自定义图元。
- 用 `ImDrawListSplitter` 优化大量同纹理图元。
- 用 `AddCallback` 嵌入自定义 GPU 渲染。
- 在 RenderDoc 里调试 ImGui 的渲染。
