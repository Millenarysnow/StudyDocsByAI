## 3.1.1 `NewFrame` 的 20 个步骤

打开 `imgui.cpp:5485`。`NewFrame` 大约 250 行——但我们不需要逐行讲，按"职能"分组。

### 第一组：开场仪式（5485~5520）

```cpp
void ImGui::NewFrame()
{
    IM_ASSERT(GImGui != NULL && "No current context. Did you call ImGui::CreateContext() and ImGui::SetCurrentContext() ?");
    ImGuiContext& g = *GImGui;

    // ① 删除"待移除"的钩子
    for (int n = g.Hooks.Size - 1; n >= 0; n--)
        if (g.Hooks[n].Type == ImGuiContextHookType_PendingRemoval_)
            g.Hooks.erase(&g.Hooks[n]);

    // ② NewFramePre 钩子
    CallContextHooks(&g, ImGuiContextHookType_NewFramePre);

    // ③ 用户错误检查
    ErrorCheckNewFrameSanityChecks();

    // ④ 加载/保存 .ini
    UpdateSettings();

    // ⑤ 帧计数
    g.Time += g.IO.DeltaTime;
    g.FrameCount += 1;
    g.TooltipOverrideCount = 0;
    g.WindowsActiveCount = 0;
    g.MenusIdSubmittedThisFrame.resize(0);

    // ⑥ Framerate 滑动平均
    g.FramerateSecPerFrameAccum += g.IO.DeltaTime - g.FramerateSecPerFrame[g.FramerateSecPerFrameIdx];
    g.FramerateSecPerFrame[g.FramerateSecPerFrameIdx] = g.IO.DeltaTime;
    g.FramerateSecPerFrameIdx = (g.FramerateSecPerFrameIdx + 1) % IM_COUNTOF(g.FramerateSecPerFrame);
    g.FramerateSecPerFrameCount = ImMin(g.FramerateSecPerFrameCount + 1, IM_COUNTOF(g.FramerateSecPerFrame));
    g.IO.Framerate = (g.FramerateSecPerFrameAccum > 0.0f) ? (1.0f / (g.FramerateSecPerFrameAccum / (float)g.FramerateSecPerFrameCount)) : FLT_MAX;
    // ...
```

#### Hook 系统（① ②）

`g.Hooks` 是 `ImVector<ImGuiContextHook>`——存放用户注册的钩子函数。8 种钩子类型（`imgui_internal.h:2173`）：

```cpp
enum ImGuiContextHookType {
    ImGuiContextHookType_NewFramePre,
    ImGuiContextHookType_NewFramePost,
    ImGuiContextHookType_EndFramePre,
    ImGuiContextHookType_EndFramePost,
    ImGuiContextHookType_RenderPre,
    ImGuiContextHookType_RenderPost,
    ImGuiContextHookType_Shutdown,
    ImGuiContextHookType_PendingRemoval_,
};
```

**用法**：你在 ImGui 内部某些时刻插自己的代码——例如 imgui_test_engine 用钩子收集 item 信息。

`PendingRemoval_` 是延迟删除：你在钩子函数内部不能 erase 自己（会破坏迭代），所以先标记，下帧 NewFrame 开始时清。这是 ImGui 处理"自删除"的经典做法。

#### `ErrorCheckNewFrameSanityChecks`（③）

检查常见用户错误：
- `io.DeltaTime <= 0` → 警告（应该有合理时间增量）。
- `io.DisplaySize.x <= 0 || y <= 0` → 警告（屏幕大小未设）。
- IniFilename 不应该是相对路径（容易误导用户）等。

这是 ImGui 给开发者的"早期警告系统"——错误时让你立刻看到，而不是几小时后某个奇怪 bug。

#### `UpdateSettings`（④）

```cpp
// 简化伪代码
void UpdateSettings() {
    if (!SettingsLoaded && IniFilename != NULL) {
        LoadIniSettingsFromDisk(IniFilename);   // 首次 NewFrame 加载
        SettingsLoaded = true;
    }
    if (SettingsDirtyTimer > 0.0f) {
        SettingsDirtyTimer -= DeltaTime;
        if (SettingsDirtyTimer <= 0.0f && IniFilename != NULL)
            SaveIniSettingsToDisk(IniFilename);   // 延迟保存
    }
}
```

**首次 NewFrame** 加载 ini，之后每帧检查"脏定时器"——用户改了某些状态后，5 秒（`io.IniSavingRate` 默认）后保存。这避免每个微小变化都 IO。

#### Framerate 滑动平均（⑥）

`g.FramerateSecPerFrame[60]` 是一个环形缓冲——保留最近 60 帧的 DeltaTime。`io.Framerate` 是这 60 帧的算术平均的倒数。

**为什么用 60 帧滑动平均**：让显示"FPS"稳定不抖动——单帧抖动在用户看不见，但累计 60 帧能反映真实状态。

`UpdateViewportsNewFrame` 处理 multi-viewport 模式下：

打开 `imgui.cpp:5460~5483`：

```cpp
static void SetupDrawListSharedData()
{
    ImGuiContext& g = *GImGui;

    ImRect virtual_space(FLT_MAX, FLT_MAX, -FLT_MAX, -FLT_MAX);
    for (ImGuiViewportP* viewport : g.Viewports)
        virtual_space.Add(viewport->GetMainRect());
    g.DrawListSharedData.ClipRectFullscreen = virtual_space.ToVec4();
    g.DrawListSharedData.CurveTessellationTol = g.Style.CurveTessellationTol;
    g.DrawListSharedData.SetCircleTessellationMaxError(g.Style.CircleTessellationMaxError);
    g.DrawListSharedData.InitialFlags = ImDrawListFlags_None;
    if (g.Style.AntiAliasedLines)
        g.DrawListSharedData.InitialFlags |= ImDrawListFlags_AntiAliasedLines;
    if (g.Style.AntiAliasedLinesUseTex && !(g.IO.Fonts->Flags & ImFontAtlasFlags_NoBakedLines))
        g.DrawListSharedData.InitialFlags |= ImDrawListFlags_AntiAliasedLinesUseTex;
    if (g.Style.AntiAliasedFill)
        g.DrawListSharedData.InitialFlags |= ImDrawListFlags_AntiAliasedFill;
    if (g.IO.BackendFlags & ImGuiBackendFlags_RendererHasVtxOffset)
        g.DrawListSharedData.InitialFlags |= ImDrawListFlags_AllowVtxOffset;
    g.DrawListSharedData.InitialFringeScale = 1.0f;
}
```

**`ImDrawListSharedData` 是什么**：所有 ImDrawList 共享的"全局参数"——包括：

- `ClipRectFullscreen`：所有 viewport 拼起来的最大裁剪矩形。
- `CurveTessellationTol`：Bezier 曲线细分容差。
- `CircleSegmentCounts[64]`：预计算的圆形细分段数表（按半径查表）。
- `ArcFastVtx[48]`：预计算的圆周采样点（48 个角度的 sin/cos）。
- `TexUvWhitePixel`：字体图集中"纯白像素"的 UV 坐标。
- `Font / FontSize`：当前字体。
- `InitialFlags`：新建 DrawList 时的默认 flags。

每个 `ImDrawList` 通过 `_Data` 字段持有一个 `ImDrawListSharedData*`——这样它能查表、共享预计算数据，不需要每个 DrawList 自己存。

`SetupDrawListSharedData` 每帧更新这些数据——例如用户修改 `Style.AntiAliasedLines` 会反映到 `InitialFlags`，下一帧新建的 DrawList 就用新设置。

### 第六组：Item / Widget 状态老化（5547~5570）


## 3.1.2 用户构建 UI 阶段

**这一阶段没有"统一的代码路径"**——它由用户的 ImGui 调用驱动。但每次 `ImGui::Button` 等控件调用都会：

1. **`ItemAdd`**：注册 ID + 几何到布局系统。
2. **`ItemHoverable`**：检测鼠标是否在它上面。
3. **`ButtonBehavior` / `SliderBehavior`**：检测交互。
4. **`RenderXxx`**：往 `window->DrawList` 写顶点。

第 4 章会逐个剖析这条流水线。这里只看**对 DrawList 的影响**：

```
用户：ImGui::Button("Save")
     │
     ▼
ItemAdd → 布局算出 bb (bounding box)
     │
     ▼
ButtonBehavior → 返回 hovered/held/pressed
     │
     ▼
RenderNavCursor + RenderFrame + RenderText
     ↓                ↓                ↓
window->DrawList    window->DrawList    window->DrawList
   ->AddRect          ->AddRectFilled    ->AddText
```

**所有控件最终都把数据写到 `window->DrawList`**——一个 ImDrawList 对应一个 Window。

### 例外：Background / Foreground DrawList

```cpp
// imgui.cpp:5183~5226
ImDrawList* ImGui::GetBackgroundDrawList() { return GetBackgroundDrawList(g.Viewports[0]); }
ImDrawList* ImGui::GetForegroundDrawList() { return GetForegroundDrawList(g.Viewports[0]); }
```

每个 viewport 有 2 个特殊 DrawList：

- **Background**：在所有窗口**之下**绘制（例如背景图、网格）。
- **Foreground**：在所有窗口**之上**绘制（例如鼠标光标、tooltip）。

```cpp
// imgui.cpp:5183 (简化)
static ImDrawList* GetViewportBgFgDrawList(ImGuiViewportP* viewport, size_t drawlist_no, const char* drawlist_name)
{
    ImDrawList* draw_list = viewport->BgFgDrawLists[drawlist_no];
    if (draw_list == NULL) {
        draw_list = IM_NEW(ImDrawList)(&g.DrawListSharedData);
        draw_list->_OwnerName = drawlist_name;
        viewport->BgFgDrawLists[drawlist_no] = draw_list;
    }
    if (viewport->BgFgDrawListsLastTimeActive[drawlist_no] != (float)g.Time) {
        draw_list->_ResetForNewFrame();
        draw_list->PushTexture(g.IO.Fonts->TexRef);
        draw_list->PushClipRect(viewport->Pos, viewport->Pos + viewport->Size, false);
        viewport->BgFgDrawListsLastTimeActive[drawlist_no] = (float)g.Time;
    }
    return draw_list;
}
```

**惰性创建**：第一次调 `GetBackgroundDrawList` 才 `IM_NEW`，缓存在 viewport 中。

**惰性重置**：检测 `LastTimeActive != g.Time`——本帧第一次访问时调 `_ResetForNewFrame` + 设默认状态。这样如果用户**不**调用，DrawList 不会浪费时间清空。

### 用户场景

## 3.1.3 `EndFrame`：收尾仪式

`Render()` 内部会先调 `EndFrame()`（如果用户没显式调）。

`EndFrame` 干的事：

1. **关闭隐式 Debug 窗口**：与 `NewFrame` 末尾的隐式 `Begin("Debug##Default")` 配对。
2. **错误检查**：栈是否平衡（`PushID/PopID` 配对、`PushStyleVar/PopStyleVar` 配对、`Begin/End` 配对）。**不平衡时 `ErrorRecoveryTryToRecoverState` 自动恢复**。
3. **关闭未提交的 Drag/Drop**：用户启动了 drag 但本帧没"释放"——保持 active。
4. **`UpdateMouseMovingWindowEndFrame`**：处理"用户拖标题栏移动窗口"。
5. **`NavEndFrame`**：导航的尾段处理（Tab 切焦点时机）。
6. **窗口排序**：`g.Windows` 按 Z-Order 排序，让父窗口在子窗口之前（绘制顺序）。
7. **NavFocus 状态更新**。
8. **DragDrop payload 续命**：上一帧的 payload 还要再活一帧（让用户有机会接收）。
9. **`io.MetricsActiveAllocations`** 等统计字段更新。
10. **清理 `_NextWindowData` / `_NextItemData`**——上一帧调 `SetNextWindowSize` 等的临时状态如果未消费就清掉。
11. **`CallContextHooks(EndFramePost)`**。

### `g.Windows` 排序

`EndFrame` 中有一段：

```cpp
// 简化
g.WindowsTempSortBuffer.resize(0);
g.WindowsTempSortBuffer.reserve(g.Windows.Size);
for (ImGuiWindow* window : g.Windows)
    if (!window->Active || window->RootWindow != window)
        continue;   // 跳过非激活和子窗口（子窗口跟随父窗口排序）
    AddWindowToSortBuffer(&g.WindowsTempSortBuffer, window);
g.Windows.swap(g.WindowsTempSortBuffer);
```

**为什么排序**：`g.Windows` 是绘制顺序——后画在前画之上。父窗口必须在子窗口之前，否则子窗口先画但被父窗口背景盖住。

### `g.WindowsActiveCount`

```cpp
io.MetricsActiveWindows = g.WindowsActiveCount;
```

——这就是 Metrics 窗里看到的"Active windows"数。

## 3.1.4 `Render`：DrawData 构建

`Render()` 是最终的"出口"。简化后流程：

```cpp
void ImGui::Render() {
    if (!g.WithinFrameScope) return;
    if (g.FrameCountEnded != g.FrameCount)
        EndFrame();   // ← 用户没显式调，自动调
    g.FrameCountRendered = g.FrameCount;
    g.IO.MetricsRenderWindows = 0;

    CallContextHooks(&g, ImGuiContextHookType_RenderPre);

    // 遍历每个 viewport，构建它的 DrawData
    for (ImGuiViewportP* viewport : g.Viewports) {
        ImDrawDataBuilder& builder = viewport->DrawDataBuilder;
        for (int n = 0; n < ARRAYSIZE(builder.Layers); n++)
            builder.Layers[n]->resize(0);   // 清空 4 层 layer

        // 把 BgFgDrawList 加到 Background / Foreground 层
        if (viewport->BgFgDrawLists[0])
            AddRootWindowToDrawData(viewport->BgFgDrawLists[0], 0);
        // ... Foreground 类似

        // 遍历 g.Windows，把每个 window 的 DrawList 加到对应层
        for (ImGuiWindow* window : g.Windows) {
            if (IsWindowActiveAndVisible(window) && (window->Flags & ImGuiWindowFlags_ChildWindow) == 0)
                AddRootWindowToDrawData(window, viewport);
        }

        // FlattenIntoSingleLayer：把 4 层合并到一个数组
        builder.FlattenIntoSingleLayer();

        // 设置 DrawData 字段
        SetupViewportDrawData(viewport, &builder.Layers[0]);
        // 这里把 builder.Layers[0] 转成 viewport->DrawDataP 的 CmdLists
        // 设置 DisplayPos / DisplaySize / FramebufferScale 等
    }

    // 累计统计
    for (ImGuiViewportP* viewport : g.Viewports) {
        g.IO.MetricsRenderVertices += viewport->DrawDataP.TotalVtxCount;
        g.IO.MetricsRenderIndices += viewport->DrawDataP.TotalIdxCount;
    }

    CallContextHooks(&g, ImGuiContextHookType_RenderPost);
    g.WithinFrameScope = false;
}
```

### `ImDrawDataBuilder` 的 4 层 layer

```cpp
// imgui_internal.h（简化）
struct ImDrawDataBuilder {
    ImVector<ImDrawList*>* Layers[ImGuiLayer_COUNT];   // 4 个指针
    ImVector<ImDrawList*>  LayerData0;
    ImVector<ImDrawList*>  LayerData1;
    // ... 等价于 N 个 ImVector
};
```

**4 层（按绘制顺序，从底到顶）**：

```cpp
enum ImGuiLayer {
    ImGuiLayer_Background = 0,    // BgFgDrawLists[0] + 工具/网格
    ImGuiLayer_Default = 1,        // 普通窗口
    ImGuiLayer_Foreground = 2,     // BgFgDrawLists[1] + 鼠标光标
    ImGuiLayer_Tooltip = 3,        // Tooltip 窗口
    ImGuiLayer_COUNT = 4,
};
```

**为什么分层**：tooltip 必须画在所有窗口之上。`g.Windows` 排序虽然能控制 Z-Order，但 tooltip 是"动态"窗口（鼠标 hover 时弹出），与普通窗口的层级关系是"全局之上"——分层比"插入到 g.Windows 末尾"更稳定。

### `FlattenIntoSingleLayer`：扁平化

```cpp
// 简化
void FlattenIntoSingleLayer() {
    int total = 0;
    for (int n = 1; n < ImGuiLayer_COUNT; n++)
        total += Layers[n]->Size;
    Layers[0]->reserve(Layers[0]->Size + total);
    for (int n = 1; n < ImGuiLayer_COUNT; n++) {
        for (ImDrawList* dl : *Layers[n])
            Layers[0]->push_back(dl);
        Layers[n]->resize(0);
    }
}
```

**做的事**：把 Layer 1 / 2 / 3 全部追加到 Layer 0，按"Background → Default → Foreground → Tooltip"顺序拼接。结果就是 `Layers[0]` 是按绘制顺序排好的 ImDrawList* 数组。

### 最终的 `ImDrawData`

```cpp
struct ImDrawData {
    bool                Valid;
    int                 CmdListsCount;
    int                 TotalIdxCount;
    int                 TotalVtxCount;
    ImVector<ImDrawList*> CmdLists;        // = Layers[0] 的内容
    ImVec2              DisplayPos;
    ImVec2              DisplaySize;
    ImVec2              FramebufferScale;
    ImGuiViewport*      OwnerViewport;
    ImVector<ImTextureData*>* Textures;
};
```

**关键**：`CmdLists` 不是拷贝 ImDrawList——它存的是**指针**。指针指向 `g.Windows[i]->DrawList` 等已存在的 DrawList。所以 `Render` 是 O(N) 的"打包"操作，没有顶点级别的拷贝。

## 3.1.5 `GetDrawData`：拿出最终结果

```cpp
// imgui.cpp:5166
ImDrawData* ImGui::GetDrawData()
{
    ImGuiContext& g = *GImGui;
    ImGuiViewportP* viewport = g.Viewports[0];
    return viewport->DrawDataP.Valid ? &viewport->DrawDataP : NULL;
}
```

**就这 4 行**：返回主 viewport 的 DrawData，如果 Valid。

**注意**：`GetDrawData` 只返回主 viewport。Multi-Viewport 模式下副 viewport 的 DrawData 在 `ImGui::GetPlatformIO().Viewports[i]->DrawData` 里——通过 `RenderPlatformWindowsDefault` 自动遍历。

### 常见误区

```cpp
ImDrawData* dd = ImGui::GetDrawData();
ImGui::NewFrame();
// ... 此时 dd 仍指向 viewport->DrawDataP，但 Valid 已是 false
SomeRenderCall(dd);   // ← UB！
```

**正确做法**：`GetDrawData` 应该在 `Render` 之后**立即**调，立即传给 backend。

## 3.1.7 Multi-Viewport 渲染

```cpp
if (io.ConfigFlags & ImGuiConfigFlags_ViewportsEnable) {
    ImGui::UpdatePlatformWindows();
    ImGui::RenderPlatformWindowsDefault();
}
```

### `UpdatePlatformWindows`

遍历 `g.Viewports`：

- 标记为"待销毁"的 viewport → 调 `Renderer_DestroyWindow` + `Platform_DestroyWindow`。
- 标记为"待创建"的 viewport → 调 `Platform_CreateWindow` + `Renderer_CreateWindow`。
- 已存在的 viewport → 检查位置/大小变化，调对应 setter。

这一步**只更新 OS 窗口**，不渲染。

### `RenderPlatformWindowsDefault`

```cpp
// 简化
for (ImGuiViewportP* viewport : g.Viewports) {
    if (viewport->Flags & ImGuiViewportFlags_IsMinimized) continue;
    if (viewport == g.Viewports[0]) continue;   // 主 viewport 用户已经渲染过
    
    if (g.PlatformIO.Platform_RenderWindow)
        g.PlatformIO.Platform_RenderWindow(viewport, NULL);
    if (g.PlatformIO.Renderer_RenderWindow)
        g.PlatformIO.Renderer_RenderWindow(viewport, NULL);
    if (g.PlatformIO.Platform_SwapBuffers)
        g.PlatformIO.Platform_SwapBuffers(viewport, NULL);
    if (g.PlatformIO.Renderer_SwapBuffers)
        g.PlatformIO.Renderer_SwapBuffers(viewport, NULL);
}
```

**4 个回调每个 viewport 调一遍**：
- `Platform_RenderWindow`：切换 GL Context / 设当前 D3D RTV / 等。
- `Renderer_RenderWindow`：调 `RenderDrawData(viewport->DrawData)`。
- `Platform_SwapBuffers`：swap 该 viewport 的 swap chain。
- `Renderer_SwapBuffers`：通常空（renderer 通常已经通过 `Platform_SwapBuffers` 完成）。

### Backend 的责任

为支持 Multi-Viewport，你的 Renderer Backend 必须实现：

```cpp
// Init 时注册
io.BackendFlags |= ImGuiBackendFlags_RendererHasViewports;
ImGuiPlatformIO& pio = ImGui::GetPlatformIO();
pio.Renderer_CreateWindow  = MyRenderer_CreateWindow;
pio.Renderer_DestroyWindow = MyRenderer_DestroyWindow;
pio.Renderer_SetWindowSize = MyRenderer_SetWindowSize;
pio.Renderer_RenderWindow  = MyRenderer_RenderWindow;
pio.Renderer_SwapBuffers   = MyRenderer_SwapBuffers;
```

`MyRenderer_RenderWindow` 是核心——给定一个 viewport，调 `RenderDrawData(viewport->DrawData)`，输出到这个 viewport 的 framebuffer。

第 5.4 章会有完整的 Hazel 实现样例。

## 3.1.8 一个具体的 timing：30fps 编辑器一帧的耗时分布

理论上的耗时（桌面 GPU 中等编辑器场景）：

```
T0: poll OS events                       0.1 ms
T1: Backend NewFrame                     0.3 ms（含纹理状态检查）
T2: ImGui::NewFrame                      0.2 ms（含 trickle / 状态老化）
T3: 用户构建 UI                            ~10 ms（应用代码主体！）
   └ ItemAdd / Hover / Behavior          ~3 ms
   └ DrawList 写入                        ~5 ms
   └ 字符串格式化（ImFormatString）        ~2 ms
T4: ImGui::Render                        0.5 ms（DrawDataBuilder 扁平化）
T5: Backend RenderDrawData               1.0 ms（VB/IB 上传 + draw call）
T6: Multi-Viewport 处理                   ~ N × 0.5 ms (每个副 viewport)
T7: SwapBuffers                          ~ vsync 阻塞
─────────────────────────────────────────────────
总计                                      ~13 ms / frame  ≈ 75 fps
```

**最耗时的是 T3——用户代码的 UI 构建**。优化方向：

- 用 `ImGuiListClipper` 跳过不可见行（千行 list 提速 10×）。
- 把字符串 cache 起来（`ImFormatString` 反复调代价不小）。
- 减少不必要的 `Push/Pop` 栈操作（每次入栈都是 ImVector::push_back）。

T1 / T2 / T4 / T5 在用户层面**几乎不可优化**——是 ImGui 内部的固定开销。如果你的 ImGui 在这里慢，要么是 Backend 实现差（例如每 cmd 一次 glBufferSubData），要么是 ImGui 版本太老。

## 3.1.9 实战：在 Hazel 里编排一帧

```cpp
void Application::Run()
{
    while (m_Running)
    {
        float time = (float)glfwGetTime();
        Timestep ts = time - m_LastFrameTime;
        m_LastFrameTime = time;

        // ① OS 事件泵（包括 ImGui Backend Callback）
        m_Window->OnUpdate();   // glfwPollEvents → io.AddXxxEvent

        if (m_Minimized) continue;

        // ② 游戏逻辑（与 ImGui 解耦）
        for (Layer* layer : m_LayerStack)
            layer->OnUpdate(ts);

        // ③ ImGui 帧
        m_ImGuiLayer->Begin();   // Backend NewFrame × 2 → ImGui::NewFrame
        for (Layer* layer : m_LayerStack)
            layer->OnImGuiRender();
        m_ImGuiLayer->End();      // ImGui::Render → RenderDrawData → 多视口

        // ④ swap chain present（如果 ImGui 没接管）
        m_Window->OnRender();   // 这里 swap 主窗口
    }
}
```

**`m_ImGuiLayer->Begin / End`** 包了第 1.3 章给出的全部逻辑。

**OnEvent vs OnUpdate vs OnImGuiRender 的协作**：

```
OnEvent:        Hazel::Event 派发到所有 Layer，包括 ImGuiLayer
OnUpdate:       游戏逻辑（移动相机、更新动画）
OnImGuiRender:  在 ImGui::Begin/End 之间调，构建 UI
```

如果你的某个 Layer 想在游戏逻辑里读 ImGui 状态：

```cpp
void EditorLayer::OnUpdate(Timestep ts) {
    if (m_ViewportFocused && m_ViewportHovered)   // ← 这两个由 OnImGuiRender 设置
        m_CameraController.OnUpdate(ts);
}

void EditorLayer::OnImGuiRender() {
    ImGui::Begin("Viewport");
    m_ViewportFocused = ImGui::IsWindowFocused();
    m_ViewportHovered = ImGui::IsWindowHovered();
    // ...
    ImGui::End();
}
```

**注意时序**：`OnImGuiRender` 在 `OnUpdate` **之后**调。所以 `m_ViewportFocused` 在 `OnUpdate` 用的是**上一帧**的值——对于交互来说**够用**（一帧延迟 = 16ms，用户感知不到）。

## 3.1.11 本章小结

让我们回顾"一帧"的全过程：

```
NewFrame              输入消费 / 状态老化 / 字体准备 / 视口更新（约 200 行代码）
   ↓
用户 UI 构建            数千次 ImGui 调用，每次都最终写入 window->DrawList
   ↓
EndFrame              栈检查 / 错误恢复 / 窗口排序
   ↓
Render                遍历窗口 → DrawDataBuilder 4 层扁平化 → DrawData
   ↓
Backend RenderDrawData  顶点上传 → draw call
   ↓
Multi-Viewport         遍历副 viewport 重复上一步
   ↓
SwapBuffers            present 到屏幕
```

**关键概念回顾**：

1. `ImDrawListSharedData`：所有 DrawList 共享的"全局参数"（圆形采样表、Tess 容差、字体白像素 UV 等）。
2. `BgFgDrawLists`：每个 viewport 的 2 个特殊 DrawList，画在所有窗口下/上。
3. `ImDrawDataBuilder`：4 层 layer（Background/Default/Foreground/Tooltip）→ FlattenIntoSingleLayer → CmdLists。
4. `ImDrawData::Valid`：保护用户不在错误时机访问 DrawData。
5. **CmdLists 是指针数组**——`Render` 不拷贝顶点。

读完本章你应该能在白板上画出"一帧 ImGui"的全部时序——这是后续 3 章（ImDrawList 内部细节、AA 算法、顶点合并）的"上下文"。
