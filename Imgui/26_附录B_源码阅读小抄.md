## B.1 11 个核心 SECTION 的"从外到内"阅读顺序

读 ImGui 源码时按这个顺序读，从"用户视角"逐步深入到"实现细节"：

### 第一层：契约接口

1. **`imgui.h:30~110`** — 版本宏 + IM_ASSERT + IMGUI_API。**5 分钟**了解整个对外契约。
2. **`imgui.cpp:[SECTION] CONTEXT AND MEMORY ALLOCATORS]`**（约 1414 行）— 全局上下文 / 分配器。**10 分钟**了解 GImGui 机制。
3. **`imgui.cpp:[SECTION] USER FACING STRUCTURES]`**（约 1456 行）— ImGuiStyle / ImGuiIO / ImGuiPlatformIO 的构造函数。**20 分钟**了解默认值。

### 第二层：核心数据结构

4. **`imgui.h` 中 `struct ImVector`**（约 2207 行）— 60 行实现 + 注释。**15 分钟**完全理解。
5. **`imgui.h` 中 `struct ImDrawCmd / ImDrawVert / ImDrawData`**（3180 / 3201 / 3445 行）— 3 个核心结构体。**10 分钟**。
6. **`imgui_internal.h:[SECTION] ImGuiContext]`**（约 2192 行）— 4500 字节 / 100+ 字段的 Context。**30 分钟**扫一遍。
7. **`imgui_internal.h:[SECTION] ImGuiWindowTempData, ImGuiWindow]`**（约 2589 行）— 100+ 字段的 Window。**30 分钟**。

### 第三层：主流程

8. **`backends/imgui_impl_opengl3.cpp::ImGui_ImplOpenGL3_RenderDrawData`**（约 536 行）— 200 行 backend。**45 分钟**逐行读完。
9. **`imgui.cpp:[SECTION] MAIN CODE]` 中的 `NewFrame / EndFrame / Render`** — 核心 3 函数。**90 分钟**。
10. **`imgui.cpp:[SECTION] ITEM SUBMISSION]`**（约 11195 行）— `ItemAdd / ItemSize / KeepAliveID`。**30 分钟**。
11. **`imgui.cpp:[SECTION] LAYOUT]`**（约 11321 行）— `SameLine / Indent / BeginGroup`。**30 分钟**。

### 第四层：高级机制

读完上面再深入：

- `imgui.cpp:[SECTION] INPUTS]`（9301 行）— 输入处理 + 路由。
- `imgui.cpp:[SECTION] ID STACK]`（9138 行）— 哈希算法。
- `imgui.cpp:[SECTION] WINDOW FOCUS]` — 焦点 / Z-Order。
- `imgui_widgets.cpp` 中的 `ButtonBehavior` — 万能交互函数。
- `imgui_draw.cpp` 中的 `AddPolyline / AddConvexPolyFilled` — AA 算法。

**总耗时**：5 小时左右把"骨架"读完。本系列前 4 部分（17 章）覆盖了这 5 小时的内容并扩展。

## B.3 命名缩写字典

ImGui 源码里的缩写：

| 缩写 | 全称 | 含义 |
|---|---|---|
| `g` | global | `ImGuiContext& g = *GImGui;`——通常在函数开头 |
| `IO` | input/output | `g.IO`——`ImGuiIO` 实例 |
| `DC` | DrawContext | `window->DC`——`ImGuiWindowTempData` 实例 |
| `bb` | bounding box | widget 的矩形 |
| `cmd` | command | `ImDrawCmd` 简称 |
| `vtx` / `idx` | vertex / index | 顶点 / 索引 |
| `ofs` / `off` | offset | 偏移 |
| `pcmd` / `pwin` | pointer to cmd / window | C 风格命名 |
| `fb` | framebuffer | 帧缓冲 |
| `cr` | clip rect | 裁剪矩形 |
| `ID` | identifier | `ImGuiID` |
| `Mod` | modifier | Key modifier |

| 前缀 | 表示 |
|---|---|

| `ImGuiCond_` | 条件（Always / Once / FirstUseEver / 等） |

## B.4 调试器条件断点 10 例

实际排查时的"魔术配方"：

### 1. 监视 ActiveId 变化

```
位置：imgui.cpp:SetActiveID 函数开头
条件：true
作用：每次 ActiveId 变化都停 → 看调用栈
```

### 2. 监视特定 widget 被 hover

```
位置：imgui.cpp:ItemHoverable 函数开头
条件：id == 0xABCD1234
（用 ID Stack Tool 拿到目标 widget 的 ID）
```

### 3. 监视特定 ID 被分配

```
位置：imgui.cpp:ImHashStr 末尾（return ~crc 之前）
条件：(~crc) == 0xABCD1234
作用：ID 被算出时停下，看是谁在算
```

### 4. 监视窗口创建

```
位置：imgui.cpp 中 CreateNewWindow 函数开头
条件：strcmp(name, "MyWindow") == 0
```

### 5. 监视 Cmd 创建

```
位置：imgui_draw.cpp:AddDrawCmd 内部
条件：CmdBuffer.Size > 100
作用：cmd 数量异常时停下
```

### 6. 监视内存分配峰值

```
位置：imgui.cpp:MemAlloc 内部
条件：size > 65536
作用：大块分配时停（找出哪个容器扩到极大）
```

### 7. 监视特定窗口的 SkipItems

```
位置：imgui.cpp 中 Begin() 设置 SkipItems 的位置
条件：window->ID == 0xA1B2C3D4 && window->SkipItems
作用：找出"为什么这个窗口本帧不画"
```

### 8. 监视 ID 冲突

```
位置：imgui.cpp:11286 (IM_ASSERT id != window->ID)
条件：id == window->ID
作用：捕获"空 ID at root"错误的瞬间
```

### 9. 监视 RenderDrawData 中具体 Cmd

```
位置：backends/imgui_impl_opengl3.cpp:RenderDrawData 的 cmd 循环
条件：pcmd->ElemCount > 1000
作用：找出哪个 cmd 几何特别大
```

### 10. 监视 InputEventsQueue 异常

```
位置：imgui.cpp:UpdateInputEvents 开头
条件：g.InputEventsQueue.Size > 100
作用：事件堆积时停（trickle 阻塞或多线程错误）
```

## B.5 阅读源码的 10 个高效搜索

### 搜 SECTION 标记

```
[SECTION]
```

——找所有章节锚点。

### 搜 FIXME

```
FIXME-OPT
FIXME-MULTITHREADING
FIXME-DPI
FIXME-NAV
```

——找官方自己标的"待优化 / 待修复"位置。

### 搜版本号

```
1.92.0
1.91.6
```

——找特定版本引入的功能。

### 搜 IMGUI_HAS

```
IMGUI_HAS_TEXTURES
IMGUI_HAS_DOCK
```

——条件编译的特性宏。

### 搜废弃 API

```
IMGUI_DISABLE_OBSOLETE_FUNCTIONS
```

——找已废弃但仍保留的字段 / 函数。

### 搜历史 issue 编号

```
#586
#5772
#8069
```

——某些复杂修复都标了 issue 号——能去 GitHub 看完整背景。

### 搜 IM_ASSERT_USER_ERROR

```
IM_ASSERT_USER_ERROR
```

——所有"用户可能犯的错"——既是文档也是检查点。

### 搜 IMGUI_DEBUG_LOG_

```
IMGUI_DEBUG_LOG_ACTIVEID
IMGUI_DEBUG_LOG_FOCUS
```

——所有写到 Debug Log 窗的事件触发点。

## B.6 IDE 配置建议

### Visual Studio

```xml
<!-- .vsconfig -->
<EnableIntelliSense>true</EnableIntelliSense>
<UnusedCodeRules>...</UnusedCodeRules>
```

把 ImGui 加到工程，Intellisense 自动索引。`Ctrl+,` 模糊查找函数 / 类。

### VS Code + clangd

```json
// settings.json
{
  "C_Cpp.default.includePath": [
    "${workspaceFolder}/imgui/**"
  ]
}
```

clangd 是当前最准的 C++ 索引器。

### CLion

直接打开 imgui 仓库当 CMake 工程——CLion 索引完整。

## B.7 推荐阅读顺序（再读一遍）

如果你已经读完本系列，回头读 ImGui 源码用这个顺序：

1. **`imgui.h` 全文** — 1 小时（含所有公开 API）。
2. **`imgui.cpp` 顶部 1500 行** — 1 小时（INCLUDES 到 CONTEXT）。
3. **`imgui_internal.h` 全文 SECTION** — 1 小时（每个 SECTION 头部段）。
4. **`imgui.cpp` 的 NewFrame / EndFrame / Render** — 2 小时。
5. **任意 widget**（例如 `Slider` 在 `imgui_widgets.cpp`）— 1 小时（从 API 到 ItemAdd 到 ButtonBehavior）。
6. **`imgui_draw.cpp` 的 AddPolyline + AddConvexPolyFilled** — 2 小时（AA 算法）。
7. **`backends/imgui_impl_*.cpp`** — 1 小时（与你引擎匹配的那个）。

**总计 ~9 小时**——按这个顺序你能完整内化 ImGui 的内部模型。
