## 1.1.1 三层架构：从 OS 到 ImGui Core

ImGui 系统的"完整骨架"长这样：

```
┌────────────────────────────────────────────────────────────────────┐
│                  ① 应用层 (Application Layer)                       │
│                                                                    │
│   你的引擎 / 编辑器代码：                                             │
│     - main 循环                                                     │
│     - 业务逻辑                                                       │
│     - 调用 ImGui::Begin / ImGui::Button / ...                       │
│     - 调用 ImGui::Render / 提交 draw data                           │
└────────────────────────────────────────────────────────────────────┘
                              │
        ┌─────────────────────┴─────────────────────┐
        │                                           │
        ▼                                           ▼
┌────────────────────────┐              ┌────────────────────────┐
│  ② Backend Layer       │              │  ② Backend Layer       │
│      (Platform)        │              │      (Renderer)        │
│                        │              │                        │
│  - 接 OS 消息泵         │              │  - 接 GPU API          │
│  - 把 OS 输入转为        │              │  - 把 ImDrawData       │
│    io.AddXxxEvent       │              │    上传 + 提交 draw    │
│  - Multi-Viewport 模式： │              │  - 字体纹理上传 / 更新   │
│    创建 / 销毁 OS 窗口    │              │  - Multi-Viewport 模式：│
│                        │              │    每个 viewport 一个   │
│  - 鼠标光标 / 剪贴板 /   │              │    swap chain          │
│    IME / DPI            │              │                        │
│                        │              │                        │
│  典型实现：              │              │  典型实现：              │
│   imgui_impl_glfw.cpp   │              │   imgui_impl_opengl3   │
│   imgui_impl_sdl3.cpp   │              │   imgui_impl_vulkan    │
│   imgui_impl_win32.cpp  │              │   imgui_impl_dx11      │
└────────────────────────┘              └────────────────────────┘
        │                                           │
        └─────────────────────┬─────────────────────┘
                              │
                              ▼
┌────────────────────────────────────────────────────────────────────┐
│                  ③ ImGui Core (库本体)                              │
│                                                                    │
│   - imgui.cpp (主流程：Begin / End / NewFrame / Render)             │
│   - imgui_widgets.cpp (Button / Slider / Combo / TreeNode...)      │
│   - imgui_draw.cpp (ImDrawList / Path / 字体光栅化)                  │
│   - imgui_tables.cpp (Tables 控件)                                  │
│   - imgui_demo.cpp (Demo 窗 - 可剥离)                                │
│                                                                    │

└────────────────────────────────────────────────────────────────────┘

                  │   操作系统 / GPU      │
                  └─────────────────────┘
```

**关键观察**：

1. **应用层只与 ImGui Core 直接对话**——通过 `ImGui::XXX` 公开 API。不与 Backend 直接对话（除了 init 时的 `ImGui_ImplXXX_Init`）。
2. **Backend 层是"双头蛇"**——Platform Backend 和 Renderer Backend 是独立的，应用层各 init 一次。
3. **Backend 与 Core 通过 `ImGuiIO` / `ImGuiPlatformIO` 两个总线对话**——Backend 不直接调内部函数。

## 1.1.2 `ImGuiIO`：Backend 与 Core 之间的"用户态总线"

`ImGuiIO` 是 ImGui 中**最庞大的公开结构体**之一（`imgui.h:2398~2624`，约 230 行）。它扮演**"配置 + I/O" 双重角色**。

### `ImGuiIO` 的字段分类

读 `imgui.h:2398` 的 `ImGuiIO` 定义，可以把它的字段分成 5 大类：

#### Class A：配置（用户在初始化时填）

```cpp
ImGuiConfigFlags    ConfigFlags;         // ImGuiConfigFlags_NavEnableKeyboard 等
ImGuiBackendFlags   BackendFlags;        // ImGuiBackendFlags_HasMouseCursors 等
ImVec2              DisplaySize;         // 屏幕分辨率（每帧更新）
ImVec2              DisplayFramebufferScale;  // HiDPI 比例
float               DeltaTime;           // 这一帧时长（每帧更新）
const char*         IniFilename;         // .ini 路径，NULL = 禁用
ImFontAtlas*        Fonts;               // 字体图集
```

**典型用法**：

```cpp
ImGuiIO& io = ImGui::GetIO();
io.ConfigFlags |= ImGuiConfigFlags_NavEnableKeyboard;
io.ConfigFlags |= ImGuiConfigFlags_DockingEnable;       // Docking 分支独有
io.ConfigFlags |= ImGuiConfigFlags_ViewportsEnable;     // Multi-Viewport
io.IniFilename = "imgui.ini";
io.Fonts->AddFontDefault();
```

#### Class B：行为开关（Config*）

```cpp
bool        ConfigInputTrickleEventQueue;     // = true
bool        ConfigInputTextCursorBlink;        // = true
bool        ConfigDragClickToInputText;        // = false
bool        ConfigWindowsResizeFromEdges;      // = true
bool        ConfigWindowsMoveFromTitleBarOnly; // = false
bool        ConfigMacOSXBehaviors;             // = (defined(__APPLE__))
bool        ConfigErrorRecovery;               // = true
// ... 约 30 个 ConfigXXX
```

每个 ConfigXXX 都是 **bool 开关**，控制 ImGui 的某项行为。**默认值是经过实战调优的**——多数情况下你不需要改。

`imgui.h:2432` 的 `ConfigInputTrickleEventQueue` 在第 1.3 章会重点讲。

#### Class C：输入事件入队 API（动词函数）

```cpp
// imgui.h:2519~2528
IMGUI_API void  AddKeyEvent(ImGuiKey key, bool down);
IMGUI_API void  AddKeyAnalogEvent(ImGuiKey key, bool down, float v);
IMGUI_API void  AddMousePosEvent(float x, float y);
IMGUI_API void  AddMouseButtonEvent(int button, bool down);
IMGUI_API void  AddMouseWheelEvent(float wheel_x, float wheel_y);
IMGUI_API void  AddMouseSourceEvent(ImGuiMouseSource source);
IMGUI_API void  AddFocusEvent(bool focused);
IMGUI_API void  AddInputCharacter(unsigned int c);
IMGUI_API void  AddInputCharacterUTF16(ImWchar16 c);
IMGUI_API void  AddInputCharactersUTF8(const char* str);
```

**这是 1.87+ 的"现代 Input API"**——所有 Backend 必须调它们把 OS 输入"灌进" ImGui。第 1.2 / 1.3 章会专题展开。

#### Class D：输出 / 反馈（用户在 NewFrame 后读）

```cpp
// imgui.h:2542~2554
bool        WantCaptureMouse;          // ImGui 想吞这个鼠标事件
bool        WantCaptureKeyboard;        // ImGui 想吞这个键盘事件
bool        WantTextInput;              // 移动设备应弹软键盘
bool        WantSetMousePos;            // ImGui 想把鼠标传送到 io.MousePos
bool        WantSaveIniSettings;        // 该保存 .ini 了
bool        NavActive;                  // 键盘/手柄导航是否激活
bool        NavVisible;                 // Nav 高亮是否可见
float       Framerate;                  // 60 帧滑动平均 FPS
int         MetricsRenderVertices;      // 上一帧产生的顶点数
int         MetricsRenderIndices;       // 上一帧产生的索引数
int         MetricsRenderWindows;       // 可见窗口数
ImVec2      MouseDelta;                 // 这一帧鼠标移动量
```

**最重要的两个**：

- `WantCaptureMouse` / `WantCaptureKeyboard`：你的引擎应用层应**先读**这两个 flag，再决定要不要把同一个输入事件传给游戏逻辑。**注意**：你应该读"上一帧 EndFrame 后"的值，因为 NewFrame 会把它们置 false 并重新计算。FAQ 的官方推荐是**在 NewFrame 之前**读。

```cpp
// 引擎主循环典型用法
while (running) {
    PollOSEvents();           // 把 OS 事件喂给 ImGui Backend
    if (!io.WantCaptureMouse) {
        // ImGui 不要鼠标，把鼠标事件交给游戏
        DispatchMouseToGame();
    }
    if (!io.WantCaptureKeyboard) {
        DispatchKeyboardToGame();
    }
    ImGui::NewFrame();
    BuildUI();                // 各种 ImGui::XXX 调用
    ImGui::Render();
    BackendRenderDrawData(ImGui::GetDrawData());
    SwapBuffers();
}
```

#### Class E：内部状态 / 兼容遗产

```cpp
// imgui.h:2560+
ImGuiContext*     Ctx;
ImVec2            MousePos;            // ← 由 AddMousePosEvent 间接更新
bool              MouseDown[5];         // ← 由 AddMouseButtonEvent 间接更新
float             MouseWheel;
bool              KeyCtrl, KeyShift, KeyAlt, KeySuper;   // 派生自 Mod 键
ImGuiKeyData      KeysData[ImGuiKey_NamedKey_COUNT];     // 所有命名键的状态
// ...
```

注意 `imgui.h:2563` 的注释：

> `(this block used to be written by backend, since 1.87 it is best to NOT write to those directly, call the AddXXX functions above instead)`

**翻译**：1.87 之前，Backend 直接写 `io.MousePos / io.MouseDown[]`。1.87 之后，应通过 `AddXxxEvent` 入队，由 ImGui 内部更新这些字段。**直接写仍然可用**（兼容遗留代码），但**不推荐**。

#### Class F：完全废弃（Legacy）

```cpp
// imgui.h:2606~2609 (注释掉的字段)
//int       KeyMap[ImGuiKey_COUNT];     // 1.87 前的 native → ImGuiKey 映射表
//bool      KeysDown[ImGuiKey_COUNT];    // 1.87 前的"按键状态数组"
//float     NavInputs[ImGuiNavInput_COUNT];  // 1.88 前的手柄输入
//void*     ImeWindowHandle;             // 1.87 前的 IME HWND
```

这些字段**已被删除**。以前的代码（包括 Cherno Hazel 老教程的 `ImGuiBuild.cpp`）大量使用它们。如果你有老代码引用这些，编译会失败——这是第 1.2 章的重点。

### `ImGuiIO` 的设计哲学

**一个对象承担"配置 + 输入 + 输出"三重职责**——这违反单一职责原则，但在 ImGui 的语境下是合理的：

- 整个进程只有一个 Context、只有一个 IO，没必要拆。
- Backend 代码每帧大量读写 IO，把字段集中减少 cache miss。
- Backend 代码改了 IO，立刻能在 ImGui 内部生效，不需要额外 sync 步骤。

**但代价**：`sizeof(ImGuiIO)` 大约 **3000+ 字节**——是 ImGui 中第二大的结构（仅次于 `ImGuiContext` 本身）。整个程序里只有这一个，所以问题不大。

## 1.1.3 `ImGuiPlatformIO`：Backend 与 Core 之间的"平台态总线"

`ImGuiPlatformIO`（`imgui.h:3984` 附近）是 1.91 之后新引入的总线，专门处理**"平台相关但不每帧变化"**的接口：

```cpp
struct ImGuiPlatformIO {
    // ───── 剪贴板 ─────
    const char* (*Platform_GetClipboardTextFn)(ImGuiContext* ctx);
    void        (*Platform_SetClipboardTextFn)(ImGuiContext* ctx, const char* text);
    void*       Platform_ClipboardUserData;

    // ───── IME (输入法) ─────
    void        (*Platform_SetImeDataFn)(ImGuiContext* ctx, ImGuiViewport* viewport, ImGuiPlatformImeData* data);
    void*       Platform_ImeUserData;

    // ───── Open in Shell ─────
    bool        (*Platform_OpenInShellFn)(ImGuiContext* ctx, const char* path);
    void*       Platform_OpenInShellUserData;

    // ───── Locale ─────
    ImWchar     Platform_LocaleDecimalPoint;   // = '.'

    // ───── Renderer 后端纹理（1.92 新增）─────
    ImGuiBackendFlags   Renderer_TextureMaxWidth, Renderer_TextureMaxHeight;
    ImVector<ImTextureData*>  Textures;        // 所有 backend 管理的纹理列表

    // ───── Multi-Viewport（Docking 分支独有）─────
    void        (*Platform_CreateWindow)(ImGuiViewport* vp);
    void        (*Platform_DestroyWindow)(ImGuiViewport* vp);
    void        (*Platform_ShowWindow)(ImGuiViewport* vp);
    void        (*Platform_SetWindowPos)(ImGuiViewport* vp, ImVec2 pos);
    ImVec2      (*Platform_GetWindowPos)(ImGuiViewport* vp);
    void        (*Platform_SetWindowSize)(ImGuiViewport* vp, ImVec2 size);
    ImVec2      (*Platform_GetWindowSize)(ImGuiViewport* vp);
    void        (*Platform_SetWindowFocus)(ImGuiViewport* vp);
    bool        (*Platform_GetWindowFocus)(ImGuiViewport* vp);
    bool        (*Platform_GetWindowMinimized)(ImGuiViewport* vp);
    void        (*Platform_SetWindowTitle)(ImGuiViewport* vp, const char* str);
    void        (*Platform_SetWindowAlpha)(ImGuiViewport* vp, float alpha);
    void        (*Platform_UpdateWindow)(ImGuiViewport* vp);
    void        (*Platform_RenderWindow)(ImGuiViewport* vp, void* render_arg);
    void        (*Platform_SwapBuffers)(ImGuiViewport* vp, void* render_arg);
    float       (*Platform_GetWindowDpiScale)(ImGuiViewport* vp);
    void        (*Platform_OnChangedViewport)(ImGuiViewport* vp);
    ImVec4      (*Platform_GetWindowWorkAreaInsets)(ImGuiViewport* vp);
    int         (*Platform_CreateVkSurface)(ImGuiViewport* vp, ImU64 vk_inst, const void* vk_allocators, ImU64* out_vk_surface);

    // ───── Renderer Multi-Viewport ─────
    void        (*Renderer_CreateWindow)(ImGuiViewport* vp);
    void        (*Renderer_DestroyWindow)(ImGuiViewport* vp);

```

### `ImGuiIO` vs `ImGuiPlatformIO` 的责任划分

| | `ImGuiIO` | `ImGuiPlatformIO` |
|---|---|---|
| **频率** | 每帧调（输入事件 / DisplaySize / DeltaTime） | 偶尔调（剪贴板 / IME / 创建窗口） |
| **数据 vs 函数** | 主要是数据字段 | 主要是函数指针（回调） |
| **数量** | 1 个（per Context） | 1 个（per Context） |
| **谁填** | Backend 调 AddXxxEvent / 用户填 ConfigFlags | Backend 在 Init 时挂回调 |
| **谁读** | ImGui Core 每帧读 | ImGui Core 在需要时调 |

**心智模型**：

- `ImGuiIO` 像"数据交换库"——你往里塞输入事件，从里读 WantCapture。
- `ImGuiPlatformIO` 像"接口适配层"——你提供"如何创建一个 OS 窗口"等回调，ImGui 自己去调。

### 历史漂移（1.91 的拆分）

1.91.1 之前，剪贴板函数是放在 `ImGuiIO` 里的：

```cpp
// imgui.h:2614~2618 (注释段，已废弃)
// Legacy: before 1.91.1, clipboard functions were stored in ImGuiIO instead of ImGuiPlatformIO.
const char* (*GetClipboardTextFn)(void* user_data);
void        (*SetClipboardTextFn)(void* user_data, const char* text);
void*       ClipboardUserData;
```

1.91.1 之后这些移到 `ImGuiPlatformIO`，老字段保留作兼容。如果你的代码读 `io.GetClipboardTextFn`，**仍然能编译**，但官方建议迁移到 `ImGui::GetPlatformIO().Platform_GetClipboardTextFn`。

**几个值得反复强调的点**：

1. **输入事件入队是异步的**——`io.AddKeyEvent` 可以在 OS 回调里立刻调（甚至从另一线程，但要小心；见第 6 章），事件先存进 `g.InputEventsQueue`，等 `NewFrame` 时才被处理。
2. **`NewFrame` 是状态重置时刻**——所有"逐帧状态"在这里清零，所有"事件队列"在这里被消费。
3. **Render 是数据冻结时刻**——`Render` 后再调 ImGui 函数会改 Context，但**不会**反映到这一帧的 DrawData。

## 1.1.5 `ImGuiViewport`：Multi-Viewport 引入的"显示单元"抽象

Docking 分支的杀手锏功能是 **Multi-Viewport**——让 ImGui 窗口可以拖出主窗口之外，成为独立的 OS 窗口。

不开 Multi-Viewport：

```
        ┌─────────────────────┐
        │  Main OS Window     │
        │  ┌───┐ ┌──────┐   │
        │  │GUI│ │ GUI  │   │
        │  └───┘ └──────┘   │
        │                     │
        │       3D Scene      │
        │                     │
        └─────────────────────┘
```

——所有 ImGui 窗口都被裁剪在主 OS 窗口边界内。

开 Multi-Viewport：

```
        ┌─────────────────────┐         ┌──────────┐
        │  Main OS Window     │         │ Detached │
        │  ┌───┐                │         │ ImGui    │
        │  │GUI│                │         │ Window   │
        │  └───┘                │         │   ↑      │
        │                     │         │   被拖出  │
        │       3D Scene      │         │   主窗口  │
        │                     │         │          │
        └─────────────────────┘         └──────────┘
```

——某个 ImGui 窗口被拖出了主 OS 窗口，成为一个**新的 OS 窗口**。

### `ImGuiViewport` 表示什么

```cpp
struct ImGuiViewport {
    ImGuiID         ID;
    ImGuiViewportFlags Flags;
    ImVec2          Pos;          // 在虚拟桌面坐标系中的位置（多显示器跨越）
    ImVec2          Size;         // 这个 viewport 的尺寸
    ImVec2          WorkPos;      // 减去 OS 装饰（标题栏 / 任务栏）的工作区
    ImVec2          WorkSize;
    float           DpiScale;
    ImDrawData*     DrawData;     // 这个 viewport 的渲染数据
    ImGuiID         ParentViewportId;

    // Platform / Renderer 用户数据（backend 存自己的句柄）
    void*           PlatformUserData;
    void*           PlatformHandle;       // 通常是 OS 窗口句柄（HWND / NSWindow*）
    void*           PlatformHandleRaw;
    bool            PlatformWindowCreated;
    bool            PlatformRequestMove;
    bool            PlatformRequestResize;
    bool            PlatformRequestClose;

    void*           RendererUserData;     // 通常是 swap chain / framebuffer
};
```

**两类 viewport**：

1. **主 viewport (Main Viewport)**：
   - `ImGuiViewportFlags_OwnedByApp`（应用程序创建的主窗口）
   - `Pos = (0, 0)`、`Size = io.DisplaySize`
   - `PlatformHandle` 通常是引擎主窗口的句柄

2. **副 viewport (Secondary Viewport)**：
   - 由 ImGui 内部根据"被拖出主窗口的 ImGui 窗口"动态创建
   - `Pos` 是该窗口在虚拟桌面坐标系中的位置
   - `PlatformHandle` 是 ImGui 调用 `Platform_CreateWindow` 让 Backend 创建的新 OS 窗口

### Multi-Viewport 的工作流程

```
用户拖动 ImGui 窗口 → 拖出主窗口边界
        │
        ▼
ImGui::Render() / ImGui::EndFrame() 内部检测到这一情况
        │
        ▼
- 创建一个新的 ImGuiViewport
- 设置 PlatformRequestMove / PlatformRequestResize
        │
        ▼
ImGui::UpdatePlatformWindows()  ← 用户主循环显式调用
        │
        ▼
对于每个新创建 / 待销毁的 viewport，调用：
    Platform_CreateWindow(vp);     ← Backend 创建一个 OS 窗口
    Renderer_CreateWindow(vp);     ← Backend 创建对应的 swap chain
        │
        ▼
ImGui::RenderPlatformWindowsDefault()  ← 用户主循环显式调用
        │
        ▼
对于每个非主 viewport：
    Platform_RenderWindow(vp);     ← Backend 设置当前 GL Context / D3D RTV
    Renderer_RenderWindow(vp);     ← Backend 调 RenderDrawData(vp->DrawData)
    Platform_SwapBuffers(vp);
    Renderer_SwapBuffers(vp);
```

### 启用 Multi-Viewport 的代价

**代价 1：Backend 必须实现完整的 PlatformIO 回调集**

不开 Multi-Viewport 时，Backend 只需要更新 `io.MousePos / io.AddKeyEvent` 等基础 IO。开 Multi-Viewport 后，**Backend 必须实现 18+ 个 Platform_XXX 回调 + 5 个 Renderer_XXX 回调**——这是 `imgui_impl_glfw.cpp` / `imgui_impl_sdl3.cpp` 中相当大一部分代码量的来源。

**代价 2：每个副 viewport 一次 swap chain present**

5 个副窗口 = 5 次 swap chain present = 5 次潜在的 vsync。可能影响整体帧率。

**代价 3：渲染状态切换频繁**

Vulkan / DX12 模式下，每个 viewport 都有自己的 framebuffer，需要切换 RenderPass / 命令缓冲。

**代价 4：调试更复杂**

GPU 性能分析工具（RenderDoc 等）会显示 N 倍的渲染过程。

### 启用 Multi-Viewport 的收益

**收益**：用户可以**像专业 IDE 一样**自由布局工作区——把 Inspector 拖到第二显示器，把场景视图全屏放在主显示器，把 Console 浮在角落。

对**编辑器型**应用（Hazel 显然是），这个收益巨大。**对游戏运行时 UI**则通常不需要。

## 1.1.6 配置宏门面：`imgui.h` 顶部 80 行的"接口契约"

打开 `imgui.h:30~110`，这是整个 ImGui 的**接口契约层**：

```cpp
// imgui.h:32~35
#define IMGUI_VERSION       "1.92.8 WIP"
#define IMGUI_VERSION_NUM   19271
#define IMGUI_HAS_TABLE             // ...
#define IMGUI_HAS_TEXTURES          // 1.92 引入的动态纹理系统
```

**这 4 行的作用**：用户代码可以这样写：

```cpp
#if IMGUI_VERSION_NUM >= 19200
    ImGui::Image(my_tex_ref, ...);   // 1.92+ 用 ImTextureRef
#else
    ImGui::Image((ImTextureID)my_tex, ...);   // 1.92 之前用 ImTextureID
#endif

#ifdef IMGUI_HAS_DOCK
    io.ConfigFlags |= ImGuiConfigFlags_DockingEnable;
#endif
```

**`IMGUI_HAS_*` 是"特性宏"**——告诉用户某个特性是否在编译时存在。

```cpp
// imgui.h:104
#define IMGUI_CHECKVERSION()        ImGui::DebugCheckVersionAndDataLayout(IMGUI_VERSION, sizeof(ImGuiIO), sizeof(ImGuiStyle), sizeof(ImVec2), sizeof(ImVec4), sizeof(ImDrawVert), sizeof(ImDrawIdx))
```

**调用时机**：你的应用第一次调 `CreateContext` 之前。它会比对"应用编译时看到的 sizeof" 和 "imgui.cpp 编译时看到的 sizeof"。不一致就 IM_ASSERT 失败——这是检测 ABI 不一致的最后防线。

```cpp
// imgui.h:76~92 (节选)
#ifndef IMGUI_API
#define IMGUI_API
#endif

#ifndef IMGUI_IMPL_API
#define IMGUI_IMPL_API              IMGUI_API
#endif

#ifndef IM_ASSERT
#include <assert.h>
#define IM_ASSERT(_EXPR)            assert(_EXPR)
#endif
```

**这一段的核心思想**：所有"可能需要外部覆盖"的宏都用 `#ifndef ... #define ... #endif` 包起来。用户在 `imconfig.h` 中可以覆盖任何一个，不需要改 ImGui 源码。

## 1.1.7 一个最小可工作的"应用 + Backend + Core"骨架

为了把上面所有概念落地，给一份**最简集成**伪代码（基于 GLFW + OpenGL3）：

```cpp
// main.cpp
#include "imgui.h"
#include "backends/imgui_impl_glfw.h"
#include "backends/imgui_impl_opengl3.h"
#include <GLFW/glfw3.h>

int main() {
    // ───── ① OS 窗口 + GL Context ─────
    glfwInit();
    GLFWwindow* window = glfwCreateWindow(1280, 720, "ImGui Demo", nullptr, nullptr);
    glfwMakeContextCurrent(window);

    // ───── ② ImGui Core 初始化 ─────
    IMGUI_CHECKVERSION();                     // 检查 ABI 一致
    ImGui::CreateContext();                    // 创建 GImGui

    ImGuiIO& io = ImGui::GetIO();
    io.ConfigFlags |= ImGuiConfigFlags_NavEnableKeyboard;
    io.ConfigFlags |= ImGuiConfigFlags_DockingEnable;     // Docking
    io.ConfigFlags |= ImGuiConfigFlags_ViewportsEnable;   // Multi-Viewport

    ImGui::StyleColorsDark();

    // ───── ③ Backend 初始化（顺序：Platform 然后 Renderer）─────
    ImGui_ImplGlfw_InitForOpenGL(window, true);
    ImGui_ImplOpenGL3_Init("#version 130");

    // ───── ④ 主循环 ─────
    while (!glfwWindowShouldClose(window))
    {
        // OS 输入消息泵（GLFW 内部会调 io.AddXxxEvent）
        glfwPollEvents();

        // Backend NewFrame
        ImGui_ImplOpenGL3_NewFrame();
        ImGui_ImplGlfw_NewFrame();

        // Core NewFrame
        ImGui::NewFrame();

        // 用户代码构建 UI
        ImGui::ShowDemoWindow();

        // Render
        ImGui::Render();

        int display_w, display_h;
        glfwGetFramebufferSize(window, &display_w, &display_h);
        glViewport(0, 0, display_w, display_h);
        glClearColor(0.1f, 0.1f, 0.1f, 1.0f);
        glClear(GL_COLOR_BUFFER_BIT);

        // Renderer 提交 ImDrawData
        ImGui_ImplOpenGL3_RenderDrawData(ImGui::GetDrawData());

        // Multi-Viewport 处理
        if (io.ConfigFlags & ImGuiConfigFlags_ViewportsEnable) {
            GLFWwindow* backup_current_context = glfwGetCurrentContext();
            ImGui::UpdatePlatformWindows();
            ImGui::RenderPlatformWindowsDefault();
            glfwMakeContextCurrent(backup_current_context);
        }

        glfwSwapBuffers(window);
    }

    // ───── ⑤ 清理 ─────
    ImGui_ImplOpenGL3_Shutdown();
    ImGui_ImplGlfw_Shutdown();
    ImGui::DestroyContext();
    glfwDestroyWindow(window);
    glfwTerminate();
}
```

**这个骨架包含了"集成 ImGui 所需的全部要素"**：

| 步骤 | 责任方 | 说明 |
|---|---|---|
| ① 创建 OS 窗口 | 应用 | 与 ImGui 无关，但要给 ImGui 一个 GL Context |
| ② Core 初始化 | 应用 | `IMGUI_CHECKVERSION` + `CreateContext` + 配置 IO |
| ③ Backend 初始化 | 应用 | **顺序**：先 Platform 后 Renderer |
| ④ 每帧 4 步 | Backend + Core + 应用 | NewFrame × 3 + UI 构建 + Render + RenderDrawData |
| ⑤ 清理 | 应用 | **顺序**：先 Renderer Shutdown 后 Platform Shutdown 后 DestroyContext |

**注意 NewFrame 的顺序**：Renderer 然后 Platform 然后 Core。**反过来不行**——Platform 在自己的 NewFrame 里依赖 Renderer 已经处理过纹理（动态字体场景下）。

## 1.1.8 Hazel 引擎集成 ImGui 的"理想接缝"

Cherno Hazel 教程里 ImGui 集成在 `Hazel::ImGuiLayer` 类中：

```cpp
class ImGuiLayer : public Layer {
public:
    void OnAttach() override;       // ← Core + Backend init
    void OnDetach() override;       // ← Core + Backend shutdown
    void Begin();                    // ← Backend NewFrame + Core NewFrame
    void End();                      // ← Render + RenderDrawData + Multi-Viewport
    void OnEvent(Event& e) override; // ← 把 Hazel Event 桥接到 io.AddXxxEvent
};
```

**Application 主循环里**：

```cpp
void Application::Run() {
    while (m_Running) {
        // 1. OS 事件泵
        m_Window->OnUpdate();    // GLFW pollEvents → 触发 Layer 的 OnEvent

        // 2. 游戏 Layer 更新
        for (Layer* layer : m_LayerStack) layer->OnUpdate();

        // 3. ImGui 帧
        m_ImGuiLayer->Begin();
        for (Layer* layer : m_LayerStack) layer->OnImGuiRender();
        m_ImGuiLayer->End();

        // 4. swap chain present
        m_Window->SwapBuffers();
    }
}
```

**几个关键设计决策**：

1. **`ImGuiLayer` 是 LayerStack 的最后一个**——确保它的 `OnEvent` 在所有游戏 Layer 之后执行（因此能根据 `WantCaptureMouse` 决定要不要阻断事件）。
2. **`Begin / End` 包住 ImGui 帧**——所有其他 Layer 的 `OnImGuiRender` 都在这之间调，所以它们可以放心调 `ImGui::Begin / Button` 等 API。
3. **`OnEvent` 桥接**——把 Hazel 自有的 `Event` 体系（`KeyPressedEvent` / `MouseMovedEvent` 等）转换成 `io.AddXxxEvent` 调用。

**这个架构的关键漏洞是 `OnEvent` 桥接**——Cherno 老教程的实现使用了 1.87 之前的 API（直接写 `io.KeysDown[]`），这在现代 ImGui 上**会编译失败**。第 1.2 章会详细对比，第 1.3 章给出迁移代码。

## 1.1.10 BackendFlags：Backend 的"能力声明"

与 `ConfigFlags`（用户填的偏好）不同，`BackendFlags` 是 **Backend 填给 Core 的"我能做什么"声明**：

```cpp
// imgui.h:2405
ImGuiBackendFlags  BackendFlags;            // = 0  // See ImGuiBackendFlags_ enum
```

| Flag | 含义 | 谁填 |
|---|---|---|
| `ImGuiBackendFlags_HasGamepad` | Platform Backend 能感应手柄 | Platform Backend |
| `ImGuiBackendFlags_HasMouseCursors` | Platform Backend 能改鼠标光标形状 | Platform Backend |
| `ImGuiBackendFlags_HasSetMousePos` | Platform Backend 能传送鼠标位置 | Platform Backend |
| `ImGuiBackendFlags_RendererHasVtxOffset` | Renderer 支持 base vertex draw call | Renderer Backend |
| `ImGuiBackendFlags_RendererHasTextures` | Renderer 支持动态纹理（1.92+） | Renderer Backend |
| `ImGuiBackendFlags_PlatformHasViewports` | Platform Backend 实现了 Multi-Viewport 回调 | Platform Backend |
| `ImGuiBackendFlags_RendererHasViewports` | Renderer Backend 实现了 Multi-Viewport 回调 | Renderer Backend |

**作用**：Core 根据这些 flag 决定**走哪条代码路径**。例如：

- 如果 `RendererHasVtxOffset == false`，Core 会保证每个 ImDrawCmd 的索引值 < 64K（牺牲 draw call 数量）。
- 如果 `PlatformHasViewports + RendererHasViewports == true` 且用户开了 `ConfigFlags_ViewportsEnable`，才真正启用 Multi-Viewport。

**Backend 在 Init 函数里设置这些 flag**：

```cpp
// 例如 imgui_impl_glfw.cpp 中：
io.BackendFlags |= ImGuiBackendFlags_HasMouseCursors;
io.BackendFlags |= ImGuiBackendFlags_HasSetMousePos;
io.BackendFlags |= ImGuiBackendFlags_PlatformHasViewports;
```

```cpp
// imgui_impl_opengl3.cpp 中：
io.BackendFlags |= ImGuiBackendFlags_RendererHasVtxOffset;
io.BackendFlags |= ImGuiBackendFlags_RendererHasTextures;   // 1.92+
```

## 1.1.11 Backend Userdata：跨函数共享数据的标准模式

打开 `imgui_impl_glfw.cpp` 的 `Init` 函数，你会看到这样一段：

```cpp
// 简化伪代码
ImGui_ImplGlfw_Data* bd = IM_NEW(ImGui_ImplGlfw_Data)();
bd->Window = window;
bd->Time = 0.0;
bd->MouseWindow = NULL;
// ...

ImGuiIO& io = ImGui::GetIO();
io.BackendPlatformUserData = (void*)bd;
io.BackendPlatformName = "imgui_impl_glfw";
```

**`BackendPlatformUserData` 是 Backend 存放自己内部状态的地方**——所有 Platform Backend 函数（`NewFrame` / `Shutdown` / 各种回调）通过：

```cpp
ImGui_ImplGlfw_Data* bd = (ImGui_ImplGlfw_Data*)ImGui::GetIO().BackendPlatformUserData;
```

拿回这个状态结构。

**类似地**，`BackendRendererUserData` 是 Renderer Backend 用的。

**为什么这样设计**：Backend 不能用全局变量（多个 Context 时会冲突），但又需要跨函数共享状态。`BackendXxxUserData` 是 ImGui 给 Backend 的"per-Context 自由空间"。

**自研 Backend 时的标准模式**：

```cpp
struct MyEngineImGuiBackend {
    Hazel::Window* Window;
    Hazel::Renderer* Renderer;
    Hazel::Texture2D* FontTexture;
    // ... 其他你需要的状态
};

void MyImGuiBackend_Init(Hazel::Window* w, Hazel::Renderer* r) {
    auto* bd = IM_NEW(MyEngineImGuiBackend)();
    bd->Window = w;
    bd->Renderer = r;
    ImGui::GetIO().BackendPlatformUserData = bd;
    ImGui::GetIO().BackendRendererUserData = bd;   // 可以共用
}
```

## 1.1.12 本章小结

让我们把整章的核心收获浓缩到一张图：

```
┌────────────────────────────────────────────────────────────────┐
│                    应用层（你的代码）                              │
│  · 调 ImGui::XXX 公开 API                                       │
│  · 设置 io.ConfigFlags                                          │
│  · 主循环驱动 NewFrame / Render                                  │
└────────────────────────────────────────────────────────────────┘
                              ↕  ImGuiIO（数据总线）
                              ↕  ImGuiPlatformIO（接口总线）
┌────────────────────────────────────────────────────────────────┐
│                    Backend 层                                    │
│  Platform Backend (输入/窗口/IME/剪贴板)                           │
│  Renderer Backend (顶点上传/Draw call/纹理)                        │
│  · 设置 io.BackendFlags                                         │
│  · 调 io.AddXxxEvent 入队输入                                    │
│  · 实现 PlatformIO.Platform_/Renderer_ 系列回调                  │
│  · 用 BackendPlatformUserData / BackendRendererUserData 存状态   │
└────────────────────────────────────────────────────────────────┘
                              ↕
┌────────────────────────────────────────────────────────────────┐
│                    ImGui Core (GImGui)                          │
│  · 单例 Context（线程不安全）                                     │
│  · 每帧重置：HoveredId / LastItemData / DrawList                 │
│  · 跨帧持久：Windows / Tables / Settings / FontAtlas             │
│  · Multi-Viewport：Viewports / DockNodes                        │
└────────────────────────────────────────────────────────────────┘
```

**记住的 6 件事**：

1. **三层架构**：Application / Backend / Core，Backend 又分 Platform 和 Renderer。
2. **两个总线**：`ImGuiIO`（数据 / 输入 / 输出）+ `ImGuiPlatformIO`（接口回调 / Multi-Viewport）。
3. **一帧的标准节奏**：`Backend NewFrame × 2 → Core NewFrame → 用户构建 UI → Core Render → Renderer RenderDrawData → 多视口处理`。
4. **Multi-Viewport 是 Docking 分支独有**——开了之后 Backend 必须实现 18+ 平台回调 + 5 渲染回调。
5. **`ConfigFlags`（用户偏好）vs `BackendFlags`（Backend 能力）**——两者结合决定实际启用的功能。
6. **集成的"理想接缝"是 ImGuiLayer 模式**——Begin/End 包住 ImGui 帧，OnEvent 桥接输入，但**桥接代码是迁移痛点**（下一章主题）。
