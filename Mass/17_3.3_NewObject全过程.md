# §3.3 NewObject<T> 全过程 — 一个 UObject 实例的诞生

> **本节地图**:模块一第 3 章第 3 节。§3.1 看 UObject 三层继承,§3.2 看 GUObjectArray 的内存布局。这一节走完 **`NewObject<T>(...)` 这个最常用 API 的完整执行路径** —— 从一行用户代码到对象就绪。
>
> 这条路径上有 6-8 个关键阶段。每阶段都是一个 hook 点,你的子类可以在不同阶段重写不同 virtual 函数。理解这张时序图后:
> - 看到 `PostInitProperties` 知道它什么时候被调
> - 知道 `Outer` 参数为什么不能是 nullptr
> - 给自己的 UClass 写 ctor + PostInitProperties 不再迷糊
> - Mass 视角下能立刻对照看出"NewObject 一次的成本"为什么数十万 entity 不该走这条路径
>
> **预备知识**:§3.1 / §3.2、§1.2(FMemory)、§2.2(UClass / CDO)。
>
> **读完之后你能做到**:
> - 画出 `NewObject` 的完整时序图
> - 理解 `StaticAllocateObject` / `StaticConstructObject_Internal` / `FObjectInitializer` 三个核心组件的职责
> - 知道 CDO 如何参与字段初始化(template object pattern)
> - 看到自定义 `UObject` 子类构造函数的"该写什么不该写什么"
> - 估算一次 NewObject 的 CPU / 内存开销(数微秒,几十次小 alloc 起步)
> - 在 Mass 项目中**避免** NewObject 进 hot path

## 3.3.1 浅入:你写 `NewObject` 时实际发生了什么

```cpp
UMyComponent* C = NewObject<UMyComponent>(this);
```

这一行做了什么?简化版"心理模型":

1. 算清楚我要为 `UMyComponent` 分配多少字节(从反射拿 `PropertiesSize`)
2. 从 GMalloc 拿一块那么大的内存
3. 在那块内存上 placement new,调 `UMyComponent` 的 C++ 构造函数
4. 用 CDO(Class Default Object)初始化字段(那些没在 ctor 里手动赋值的)
5. 把对象登记到 GUObjectArray
6. 调用 `PostInitProperties`(子类钩子)
7. 返回指针

实际过程更复杂(需要处理 Outer 关系、subobject 实例化、Editor 标志),但骨架是这条线。

接下来我们逐步展开。

---

## 3.3.2 入口 1:`NewObject<T>` 模板函数

`Engine/Source/Runtime/CoreUObject/Public/UObject/UObjectGlobals.h:1889`(主重载):

```cpp
template <class T>
T* NewObject(
    UObject* Outer, 
    const UClass* Class, 
    FName Name = NAME_None, 
    EObjectFlags Flags = RF_NoFlags, 
    UObject* Template = nullptr, 
    bool bCopyTransientsFromClassDefaults = false, 
    FObjectInstancingGraph* InInstanceGraph = nullptr, 
    UPackage* InExternalPackage = nullptr)
{
    if (Name == NAME_None)
    {
        FObjectInitializer::AssertIfInConstructor(Outer, TEXT("..."));
    }

#if DO_CHECK
    CheckIsClassChildOf_Internal(T::StaticClass(), Class);
#endif

    FStaticConstructObjectParameters Params(Class);
    Params.Outer = Outer;
    Params.Name = Name;
    Params.SetFlags = Flags;
    Params.Template = Template;
    Params.bCopyTransientsFromClassDefaults = bCopyTransientsFromClassDefaults;
    Params.InstanceGraph = InInstanceGraph;
    Params.ExternalPackage = InExternalPackage;

    T* Result = static_cast<T*>(StaticConstructObject_Internal(Params));
    return Result;
}
```

模板的主要事:
1. **Validation**:`AssertIfInConstructor` 检测你不能在 ctor 里调 `NewObject`(那应该用 `CreateDefaultSubobject`)
2. **类型一致性检查**:`CheckIsClassChildOf_Internal` 确认 `Class` 真是 `T` 的子类
3. **打包参数**:把所有参数塞进 `FStaticConstructObjectParameters` 结构体
4. **转发到** `StaticConstructObject_Internal`

### 3.3.2.1 参数详解

| 参数 | 含义 | 默认 | 实战 |
|---|---|---|---|
| `Outer` | 父对象(对象树位置)| 必填 | 通常 `this`(组件挂在 actor)、`GetTransientPackage()`(临时对象) |
| `Class` | 实际类型 | 必填(显式重载) | 反射动态构造时用 |
| `Name` | 对象名(`/Game/.../Foo:Comp0`) | NAME_None(自动生成) | 资产/可识别对象给名字 |
| `Flags` | EObjectFlags | RF_NoFlags | 通常默认 |
| `Template` | 模板对象(替代 CDO) | nullptr → 用 CDO | 复制现有对象时填 |
| `bCopyTransientsFromClassDefaults` | 是否从 CDO 拷 transient 字段 | false | 通常默认 |

99% 你只用最简单形式 `NewObject<T>(this)` 或 `NewObject<T>()`(默认 Outer = TransientPackage)。

### 3.3.2.2 三个重载

UObjectGlobals.h:1889 / 1919 / 1934 三个重载:
- `NewObject<T>(Outer, Class, Name, ...)` — 最完整
- `NewObject<T>(Outer = TransientPackage)` — 最简
- `NewObject<T>(Outer, Name, Flags, ...)` — 不用显式指定 Class(从 T 推导)

它们都最终走 `StaticConstructObject_Internal`。

## 3.3.3 入口 2:`StaticConstructObject_Internal` —— 真正的"工厂"

`UObjectGlobals.h:604`:

```cpp
COREUOBJECT_API UObject* StaticConstructObject_Internal(const FStaticConstructObjectParameters& Params);
```

这是一个**非模板**函数(在 .cpp 实现)。所有 `NewObject` / `DuplicateObject` / 编辑器创建对象 / 资产加载等路径**最终都汇集到这里**。

### 3.3.3.1 工作流(简化)

```cpp
UObject* StaticConstructObject_Internal(const FStaticConstructObjectParameters& Params)
{
    // 1. 决定 Template(默认值来源)
    UObject* Template = Params.Template;
    if (!Template)
    {
        Template = Params.Class->GetDefaultObject();    // ★ 用 CDO 作 template
    }

    // 2. 分配内存 + 调构造函数
    UObject* Result = StaticAllocateObject(
        Params.Class, Params.Outer, Params.Name, Params.SetFlags, ...);
    
    // 3. 用 FObjectInitializer 完成"对象初始化协议"
    {
        FObjectInitializer ObjectInitializer(Result, Template, ...);
        // ObjectInitializer 析构时:
        //   - InitProperties 从 Template 拷字段
        //   - 实例化 subobjects
        //   - 调 Result->PostInitProperties()
        //   - 调 Result->PostCDOContruct() (若 Result 是 CDO)
    }
    
    // 4. 后续流程(如果是 PostLoad 路径,会调 PostLoad 等)
    
    return Result;
}
```

### 3.3.3.2 三个核心组件

`StaticConstructObject_Internal` 协调三个组件:

1. **`StaticAllocateObject`** — 内存分配 + 构造函数调用(§3.3.4)
2. **`FObjectInitializer`** — 字段初始化、subobject 实例化、PostInitProperties hook(§3.3.5)
3. **CDO** — 字段默认值的来源(§3.4 详讲,这里只 use)

## 3.3.4 阶段 1:`StaticAllocateObject` —— 内存 + ctor

`UObjectGlobals.h:1275`:

```cpp
COREUOBJECT_API UObject* StaticAllocateObject(
    const UClass* Class, 
    UObject* InOuter, 
    FName Name, 
    EObjectFlags SetFlags, 
    EInternalObjectFlags InternalSetFlags = EInternalObjectFlags::None, 
    bool bCanReuseSubobjects = false, 
    bool* bOutReusedSubobject = nullptr, 
    UPackage* ExternalPackage = nullptr, 
    int32 SerialNumber = 0, 
    FRemoteObjectId RemoteId = FRemoteObjectId(), 
    class FGCReconstructionGuard* GCGuard = nullptr);
```

工作流(简化):

### 3.3.4.1 Step A — 计算大小

```cpp
SIZE_T Size = Class->GetPropertiesSize();        // 反射数据里读
uint32 Alignment = Class->GetMinAlignment();
```

`PropertiesSize` 是 §2.2.4 讲的 `UStruct` 字段。它是**类的所有字段加 vtable 加内嵌 subobject 后的总字节数**。

### 3.3.4.2 Step B — 检查重复

```cpp
// 如果 Outer 下已经有同名对象,可能重用或报错
UObject* Existing = StaticFindObjectFastInternal(Class, InOuter, Name);
if (Existing)
{
    // 复用或报错(看 SetFlags / Reload 模式)
}
```

这一步在编辑器 reload 资产 / 命令行重启 PIE 时关键。

### 3.3.4.3 Step C — 分配内存

```cpp
UObject* Memory = (UObject*)FMemory::Malloc(Size, Alignment);
```

走的就是 §1.2 讲的 GMalloc。**一次小 alloc**,通常进 SmallPool。

### 3.3.4.4 Step D — 注册到 GUObjectArray

```cpp
GUObjectArray.AllocateUObjectIndex(Memory, /* InternalFlags */);
// 内部:
//   - 找一个空 InternalIndex(优先重用 freelist)
//   - 把 Memory 指针塞进 GUObjectArray 那个 FUObjectItem
//   - 设置 EInternalObjectFlags
```

§3.2 讲过 GUObjectArray 是 chunked 数组。`AllocateUObjectIndex` 是其 `Add` 接口。

### 3.3.4.5 Step E — 调 C++ 构造函数

```cpp
Class->ClassConstructor(FObjectInitializer(Memory, Template, ...));
```

`ClassConstructor` 是 `UClass` 的字段(§2.2.4.3),由 UHT 在 .gen.cpp 里生成,长这样:

```cpp
// .gen.cpp(UHT 生成,简化)
UClass* Z_Construct_UClass_UMyComponent_Statics::ClassParams = {
    &UMyComponent::StaticClass,
    "Engine",
    /* ClassConstructor */ [](const FObjectInitializer& OI) {
        new ((EInternalConstructor*)OI.GetObj()) UMyComponent(OI);
    },
    // ...
};
```

`new ((EInternalConstructor*)OI.GetObj()) UMyComponent(OI)` 是 **placement new** —— 在已分配的内存上构造对象。

### 3.3.4.6 你写的 ctor 在这里被调

```cpp
// UMyComponent.cpp(你写的)
UMyComponent::UMyComponent(const FObjectInitializer& ObjectInitializer)
    : Super(ObjectInitializer)
{
    // 这里你做 default 字段赋值、CreateDefaultSubobject 等
}
```

注意:
- ctor 接收一个 `FObjectInitializer&` 参数(由 ClassConstructor lambda 传入)
- 必须调 `Super(ObjectInitializer)` 才能让父类正确初始化
- ctor 里**不能** `NewObject` —— 用 `ObjectInitializer.CreateDefaultSubobject<>` 代替

### 3.3.4.7 此时对象状态

构造函数返回后,对象的:
- 字段是**ctor 显式赋值的初值**(没赋的字段是垃圾内存!)
- vtable 已就绪
- ObjectFlags 已包含传入的 SetFlags
- InternalIndex 已分配
- Outer / Class / Name 已设置

但**字段还没从 CDO 拷贝默认值**!这是下一阶段的事。

## 3.3.5 阶段 2:`FObjectInitializer` —— 字段初始化协议

`UObjectGlobals.h:1291` 定义:

```cpp
class FObjectInitializer
{
    UObject* Obj;                       // 正在初始化的对象
    UObject* ObjectArchetype;           // 模板(通常是 CDO)
    EObjectInitializerOptions Options;
    FObjectInstancingGraph* InstanceGraph;
    
    // 子对象列表(CreateDefaultSubobject 注册的)
    TArray<UObject*> ComponentInstantiations;
    // ...

public:
    FObjectInitializer(UObject* InObj, UObject* InObjectArchetype, EObjectInitializerOptions InOptions, FObjectInstancingGraph* InInstanceGraph = nullptr);
    ~FObjectInitializer();              // ★ 析构时跑完所有初始化
    
    template<class TReturnType>
    TReturnType* CreateDefaultSubobject(FName SubobjectFName, ...) { /* ... */ }
};
```

**精妙之处**:`FObjectInitializer` 是 RAII 对象。它在 ctor 期被构造,**析构时**完成所有"协议剩余步骤"。所以你的 UObject ctor 里只要正常做事,RAII 自动收尾。

### 3.3.5.1 析构函数的工作

伪代码:

```cpp
FObjectInitializer::~FObjectInitializer()
{
    // 1. InitProperties:从 Archetype/CDO 拷贝字段
    InitPropertiesFromArchetype(Obj, ObjectArchetype);
    
    // 2. 实例化 subobjects(CreateDefaultSubobject 在 ctor 里登记的子对象,
    //    现在统一构造 + 链入 Outer/Owner 关系)
    InstanceSubobjectTemplates(Obj);
    
    // 3. 清除 RF_NeedInitialization flag
    Obj->ClearFlags(RF_NeedInitialization);
    
    // 4. 调 hook
    Obj->PostInitProperties();          // ★ 你重写的虚函数被调
    
    // 5. 如果是 CDO,调 PostCDOContruct
    if (Obj->HasAnyFlags(RF_ClassDefaultObject))
    {
        Obj->PostCDOContruct();
    }
}
```

### 3.3.5.2 `InitProperties` —— 从 CDO 拷字段

`InitProperties` 是个反射驱动的过程:

```cpp
// 简化伪代码
void UClass::InitPropertiesFromCustomList(uint8* DataPtr, const uint8* DefaultsPtr)
{
    for (FProperty* P = PropertyLink; P; P = P->PropertyLinkNext)
    {
        // 跳过 native ctor 已经设过的(P 不在"还需 init"列表)
        if (!P->ShouldDuplicateValue()) continue;
        
        // 复制 default 值
        P->CopyCompleteValue(
            DataPtr + P->GetOffset_ForInternal(),         // 目标:对象的字段地址
            DefaultsPtr + P->GetOffset_ForInternal()      // 源:CDO 的字段地址
        );
    }
}
```

**核心**:每个 UPROPERTY 字段从 CDO 同名字段**拷过来**。所以:

```cpp
UCLASS()
class UMyComp : public UActorComponent
{
public:
    UPROPERTY()
    int32 Health = 100;             // ★ default 100,这是 ctor 里赋的
};
```

CDO 创建时(反射注册期),CDO 的 `Health = 100`。每次 `NewObject<UMyComp>`:
1. ctor 跑,你的代码可能再次 `Health = 100`(ctor body)
2. `InitProperties` 把 CDO 的 Health(100)拷过来 —— **覆盖** ctor 写的值

**含义**:
- 字段默认值优先用 `int32 Health = 100;`(ctor 初始化列表 / 默认成员初始值),会**反映到 CDO**,所以 NewObject 的实例自然继承
- 在 ctor body 里 `Health = SomeRuntime();`(动态值)**会被 InitProperties 覆盖回 CDO 值**!这是新人常见困惑

### 3.3.5.3 ctor body 与 default 的关系示例

```cpp
UCLASS()
class UMyComp : public UActorComponent
{
public:
    UPROPERTY()
    int32 Health = 100;        // 字段默认 100
    
    UPROPERTY()
    int32 Mana = 50;
};

UMyComp::UMyComp(const FObjectInitializer& ObjectInitializer)
    : Super(ObjectInitializer)
{
    Mana = 999;          // ← ctor body 里改 Mana
}

// NewObject 后,实例的 Mana 是?
//   ctor 跑完:    Health = 100, Mana = 999
//   InitProperties: 从 CDO 拷
//     CDO 的 Mana 是多少?CDO 也跑过 ctor!
//     所以 CDO.Mana = 999(ctor body 在 CDO 创建时也跑了)
//   InitProperties 拷过来:实例的 Mana = 999
//
// 看似没差,实际:**任何时候你在 ctor body 写"动态值"(如 FMath::Rand()),
//   CDO 创建时跑一次得到一个值,之后所有实例从 CDO 拷这个固定值,失去随机性**

// 实战教训:ctor 里别用动态值。要随机初始化,放 PostInitProperties。
```

### 3.3.5.4 `PostInitProperties()` —— 你的"对象就绪"钩子

```cpp
void UMyComp::PostInitProperties()
{
    Super::PostInitProperties();
    
    // 此时:
    // - 所有 UPROPERTY 字段已从 CDO 拷贝
    // - subobjects 已实例化
    // - GC 已知道这个对象
    
    // 适合做的事:
    // - 动态初始化(随机种子、外部资源加载)
    // - 注册到 Subsystem
    // - 设置依赖外部状态的字段
}
```

**纪律**:`PostInitProperties` 是子类初始化逻辑的**正确位置**。ctor body 里只放"静态默认值",动态逻辑放 PostInitProperties。

## 3.3.6 阶段 3:Subobject 实例化(`CreateDefaultSubobject`)

如果你的类有内嵌 components,典型写法:

```cpp
UCLASS()
class AMyActor : public AActor
{
public:
    UPROPERTY()
    TObjectPtr<UStaticMeshComponent> MeshComp;
};

AMyActor::AMyActor(const FObjectInitializer& OI)
    : Super(OI)
{
    MeshComp = CreateDefaultSubobject<UStaticMeshComponent>(TEXT("MeshComp"));
    MeshComp->SetStaticMesh(...);
}
```

`CreateDefaultSubobject` 是 `FObjectInitializer` 的方法。它做:

1. 在当前对象的 InitProperties 阶段,递归对子对象 NewObject
2. 子对象的 Outer 是当前对象
3. 子对象自己也有 CDO,也走完整 NewObject 流程
4. Sub 子对象 Field 也通过 CDO 初始化

这就是为什么 **Actor / Component 嵌套深时,NewObject 一次能触发数十次内部分配**(每个 component 都是一次 NewObject)。

### 3.3.6.1 `CreateDefaultSubobject` 必须在 ctor 里

```cpp
// ✅
AMyActor::AMyActor(const FObjectInitializer& OI) {
    MeshComp = CreateDefaultSubobject<UStaticMeshComponent>(TEXT("MeshComp"));
}

// ❌
void AMyActor::SomeFunc() {
    auto* C = NewObject<UStaticMeshComponent>(this, TEXT("MeshComp"));   // 不会触发 CDO 子对象关系
}
```

`CreateDefaultSubobject` 内部更新 CDO 的子对象 archetype 链。运行时 NewObject **不能**做这个,因为 CDO 已经定型。

## 3.3.7 完整时序图

```
NewObject<T>(Outer)                          ← 用户调用
   │
   ↓
NewObject<T>(...) 模板
   │  - Validation
   │  - 打包 FStaticConstructObjectParameters
   │
   ↓
StaticConstructObject_Internal               ← 工厂入口
   │
   ├──→ Template = Params.Template ?: Class->GetDefaultObject()  (CDO)
   │
   ├──→ StaticAllocateObject
   │     ├─ Size = Class->PropertiesSize
   │     ├─ FMemory::Malloc(Size, Align)        ← §1.2 走 GMalloc
   │     ├─ GUObjectArray.AllocateUObjectIndex  ← §3.2 注册到全局表
   │     └─ Class->ClassConstructor(FObjectInitializer(...))  ← placement new + 你的 ctor
   │           │
   │           └─ 你的 UMyClass::UMyClass(OI) : Super(OI) { ... }
   │                 - 字段初始化(默认值)
   │                 - CreateDefaultSubobject<>(...)(登记到 OI)
   │
   ├──→ FObjectInitializer 析构(自动)
   │     ├─ InitProperties:从 Template 拷字段(覆盖 ctor body 写的值!)
   │     ├─ 实例化 subobjects(把 CreateDefaultSubobject 的对象真正构造)
   │     ├─ ClearFlag(RF_NeedInitialization)
   │     ├─ Obj->PostInitProperties()           ← 你的钩子
   │     └─ if (CDO) Obj->PostCDOContruct()
   │
   └──→ 返回对象
```

## 3.3.8 时序里的额外阶段(资产加载路径)

`NewObject` 是"代码路径"。资产加载("`/Game/Foo.Bar`" 这种序列化)走稍长的路径:

```
LoadObject<T>(Path)                          ← 加载入口
   │
   ↓
LinkerLoad → 反序列化字段
   │
   ↓
StaticConstructObject_Internal(...)          ← 同样的工厂!
   │
   ↓
... NewObject 全套 ...
   │
   ↓
PostLoad()                                    ← ★ 加载特有钩子
   │  - 给加载的对象一次"调整数据"机会
   │  - 比如旧版本数据迁移、计算缓存字段
   │
   ↓
PostLoadSubobjects()                          ← 子对象 PostLoad
```

`PostLoad` 仅在**资产加载**时被调,直接 NewObject 时**不被调**。

实战:你子类需要"无论代码 NewObject 还是资产加载都要做某事",写在 `PostInitProperties`。仅"资产加载完成后做版本迁移",写在 `PostLoad`。

| Validation + 打包参数 | ~50 ns | 模板代码 |
| StaticAllocateObject | | |
| - Size 计算 | ~5 ns | 读 UClass 字段 |
| - FMemory::Malloc | ~50-200 ns | 取决于 alloc size,SmallPool TLS 命中 |
| - GUObjectArray.AllocateUObjectIndex | ~100-500 ns | atomic + listener 通知 |
| - placement new + ctor body | 看你的 ctor | 普通 ~500 ns - 几 μs |
| FObjectInitializer 析构 | | |
| - InitProperties(字段拷贝) | ~500 ns - 几 μs | 取决于字段数 |
| - 实例化 subobjects | 每个 subobject 全部递归 | 复杂 |

### 3.3.9.1 数量级对比

```
NewObject 一次:           几微秒

```

**NewObject 是慢的**。50K 单位每个走 NewObject,**几十秒**起步。这就是 Mass 必须绕开 NewObject 的物理原因。

## 3.3.10 Mass / RTS 视角下的纪律

### (1)Mass entity 创建**绝不**走 NewObject

Mass 创建 entity 走 `FMassEntityManager::CreateEntity` / `BatchCreateEntities`。内部:
- chunk 已预分配(一次性 FMemory::Malloc)
- 在 chunk 里就地 placement new Fragment(POD,几乎零开销)
- 不走 GUObjectArray
- 不调 PostInitProperties / PostLoad

50K entity 创建 ≈ 几十毫秒 vs NewObject 几十秒。差**1000 倍**。

### (2)Mass Subsystem / Processor / Trait 走 NewObject 没问题

这些是**框架结构**,启动时一次创建,不在 hot path。NewObject 的几微秒开销分摊到启动期,完全可以接受。

### (3)Actor 池化(对偶 NewObject 的开销)

如果你 RTS 有"少量但重要的 Actor"(英雄、Boss),它们生死频繁时,**池化**:

```cpp
class UMyActorPool : public UWorldSubsystem
{
    TArray<TObjectPtr<AHero>> Pool;
    
    AHero* Acquire()
    {
        if (Pool.Num() > 0)
        {
            AHero* H = Pool.Pop();
            H->Reset();           // 你的 reset 函数
            return H;
        }
        return GetWorld()->SpawnActor<AHero>();   // 新建
    }
    
    void Release(AHero* H)
    {
        H->Deactivate();
        Pool.Push(H);
    }
};
```

避免重复 NewObject + GC + NewObject 的循环。

### (4)`PostInitProperties` vs `BeginPlay`

```cpp
void UMyComp::PostInitProperties()
{
    // - 对象数据就绪
    // - World 可能还不存在(CDO 创建期)
    // - 不能调外部 Subsystem
}

void UMyComp::BeginPlay()
{
    // - 对象在 World 里活了
    // - 能调任何 Subsystem
    // - 适合启动外部资源
}
```

新人常把"获取 Subsystem"放 `PostInitProperties`,这在 CDO 创建时会崩(此时 World 不存在)。**纪律**:外部交互放 `BeginPlay`(Actor / ActorComponent)或 `Initialize`(Subsystem)。

## 3.3.11 改 Engine:Hook NewObject(罕见)

如果你想 hook 所有 NewObject(典型场景:RTS 项目想统计"哪些类型的对象创建最多"):

**最优雅**:用 `FUObjectArray::FUObjectCreateListener`(§3.2.6.1)。**不改 Engine**。

```cpp
class FRTSObjectStatsListener : public FUObjectArray::FUObjectCreateListener
{
    TMap<UClass*, int32> CreationCounts;
public:
    virtual void NotifyUObjectCreated(const UObjectBase* Object, int32 Index) override
    {
        UObject* Obj = (UObject*)Object;
        CreationCounts.FindOrAdd(Obj->GetClass())++;
    }
    virtual void OnUObjectArrayShutdown() override {}
};

// 启动时
GUObjectArray.AddUObjectCreateListener(&Listener);
```

实战:99% 你不需要 hook NewObject 本身。Listener 已足够。

## 3.3.12 实操:测一次 NewObject 的耗时

```cpp
static FAutoConsoleCommand CmdBenchNewObject(TEXT("rts.BenchNewObject"),
    TEXT("Benchmark NewObject"),
    FConsoleCommandDelegate::CreateLambda([]()
    {
        const int32 N = 10000;
        UObject* Outer = GetTransientPackage();
        
        // 简单 UObject
        double Start = FPlatformTime::Seconds();
        for (int32 i = 0; i < N; ++i)
        {
            UObject* O = NewObject<UObject>(Outer);
            (void)O;
        }
        UE_LOG(LogTemp, Display, TEXT("NewObject<UObject>: %.2fμs/op"),
            (FPlatformTime::Seconds() - Start) * 1e6 / N);
        
        // ActorComponent(更复杂)
        Start = FPlatformTime::Seconds();
        for (int32 i = 0; i < N / 10; ++i)
        {
            UActorComponent* C = NewObject<UActorComponent>(Outer);
            (void)C;
        }
        UE_LOG(LogTemp, Display, TEXT("NewObject<UActorComponent>: %.2fμs/op"),
            (FPlatformTime::Seconds() - Start) * 1e6 * 10 / N);
        
        // 强制 GC 清掉这些对象
        CollectGarbage(GARBAGE_COLLECTION_KEEPFLAGS);
    }));
```

跑 `rts.BenchNewObject`。期望:
- `NewObject<UObject>`: ~1-3 μs
- `NewObject<UActorComponent>`: ~5-30 μs

记下数字,对比 Mass `CreateEntity` 的 ~500 ns,你会立刻明白量级差。
