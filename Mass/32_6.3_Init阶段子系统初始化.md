# §6.3 Init 阶段的子系统初始化顺序

> **本节地图**:模块二第 6 章第 3 节。§6.2 走完了 PreInit。这一节走 `FEngineLoop::Init` —— **GEngine 创建、Subsystem 初始化、第一个 World 加载**的阶段。
>
> 这一节有两个新角色出场:
> - **GEngine**(终于在这一阶段被 `NewObject` 出来)
> - **UEngineSubsystem / UGameInstanceSubsystem**(进程级 / 游戏级 Subsystem)
>
> Init 完成后,引擎可以开始 Tick 第一帧。
>
> **预备知识**:§6.1 / §6.2,§3.3 NewObject。
>
> **读完之后你能做到**:
> - 看懂 `FEngineLoop::Init` 内部 GEngine 创建逻辑
> - 区分 UEngineSubsystem / UGameInstanceSubsystem / UWorldSubsystem 的初始化时机
> - 在自定义 RTS Subsystem 里**正确**响应 `Initialize` / `Deinitialize`
> - 知道 `OnPostEngineInit` 委托是什么时候被广播的
> - 看到 `LoadDefaultMap` 知道这是第一个 World 出生时刻

## 6.3.1 浅入:Init 做什么

`PreInit` 完成后,所有"基础设施"就位但还没有"游戏世界"。Init 把"游戏世界"创建出来:

```
PreInit 完成 → 模块加载、UClass 反射注册、GMalloc / Stat / Trace / Config 就绪
   ↓
FEngineLoop::Init
   ├─ NewObject<UGameEngine>(或 UUnrealEdEngine)        ← GEngine 诞生
   ├─ GEngine->ParseCommandline()
   ├─ InitTime()                                          ← 帧时基线
   ├─ GEngine->Init(this)                                 ← UEngine 内部初始化
   │     ├─ 创建 RHI(渲染硬件接口)
   │     ├─ 创建 Renderer
   │     ├─ Slate 初始化
   │     ├─ 创建 GameViewportClient
   │     ├─ NewObject<UEngineSubsystem*>(每种 EngineSubsystem 一个)
   │     ├─ 调每个 EngineSubsystem::Initialize
   │     └─ ...
   ├─ FCoreDelegates::OnPostEngineInit.Broadcast()         ← ★ 你的代码常 hook 这里
   ├─ LoadModulesForProject(PostEngineInit)                ← LoadingPhase=PostEngineInit 模块
   ├─ GEngine->Start()                                     ← 启动 Editor 或 LoadDefaultMap
   │     └─ Game build:LoadDefaultMap → 创建 UWorld → 创建 GameInstance
   │     └─ Editor build:打开 Editor 主窗口
   └─ 第一个 World 就绪
```

## 6.3.2 GEngine 的诞生

`LaunchEngineLoop.cpp:4702-4731`:

```cpp
UClass* EngineClass = nullptr;
if (!GIsEditor)
{
    // Game build
    FString GameEngineClassName;
    GConfig->GetString(TEXT("/Script/Engine.Engine"), TEXT("GameEngine"), 
                        GameEngineClassName, GEngineIni);
    EngineClass = StaticLoadClass(UGameEngine::StaticClass(), nullptr, *GameEngineClassName);
    GEngine = NewObject<UEngine>(GetTransientPackage(), EngineClass);
}
else
{
#if WITH_EDITOR
    // Editor build
    FString UnrealEdEngineClassName;
    GConfig->GetString(TEXT("/Script/Engine.Engine"), TEXT("UnrealEdEngine"), 
                        UnrealEdEngineClassName, GEngineIni);
    EngineClass = StaticLoadClass(UUnrealEdEngine::StaticClass(), nullptr, *UnrealEdEngineClassName);
    GEngine = GEditor = GUnrealEd = NewObject<UUnrealEdEngine>(GetTransientPackage(), EngineClass);
#endif
}
```

### 6.3.2.1 几个关键观察

**(1)从 INI 读类名**

`/Script/Engine.Engine` 段下 `GameEngine` / `UnrealEdEngine` 字段:

```ini
; DefaultEngine.ini
[/Script/Engine.Engine]
GameEngine=/Script/Engine.GameEngine
UnrealEdEngine=/Script/UnrealEd.UnrealEdEngine
```

**这意味着你能换 GEngine 的实际类型**:

```cpp
// MyRTSEngine.h
UCLASS()
class MYRTS_API UMyRTSGameEngine : public UGameEngine
{
    GENERATED_BODY()
    
    virtual void Init(IEngineLoop* InEngineLoop) override
    {
        Super::Init(InEngineLoop);
        // 你的 RTS 全局初始化
    }
};
```

```ini
; MyRTS/Config/DefaultEngine.ini
[/Script/Engine.Engine]
GameEngine=/Script/MyRTS.MyRTSGameEngine
```

**之后 Game build 启动时,GEngine 是 UMyRTSGameEngine 实例**。这是**自定义引擎行为最优雅的姿势** — 不改 UE Engine,不改 LaunchEngineLoop,只改 INI + 写子类。

### 6.3.2.2 `GIsEditor` 决定走哪条

`-game` 命令行 / `IsRunningCommandlet()` 等检测让 `GIsEditor = false`,即使在 Editor exe 里也走 GameEngine 路径。这就是"Editor 启动 Standalone Game"的内部机制。

### 6.3.2.3 GEngine 是 UObject(走 NewObject)

`NewObject<UEngine>(GetTransientPackage(), EngineClass)` 走 §3.3 完整路径。Outer 是 `TransientPackage`(进程级临时包,GC root)。

之后 `check(GEngine)` 确认成功。

## 6.3.3 `GEngine->Init(this)` —— 引擎内部初始化

`LaunchEngineLoop.cpp:4763`:

```cpp
GEngine->Init(this);
```

`this` 是 `FEngineLoop*`,UEngine 拿来 ref 主循环。

`UEngine::Init` 是个虚函数,**Editor 和 Game build 行为不同**。简化共同部分:

```cpp
void UEngine::Init(IEngineLoop* InEngineLoop)
{
    // 1. RHI / Renderer 初始化
    GetRendererModule().PostInit();
    
    // 2. Slate 初始化(UI 框架)
    InitializeRenderingCVarsCaching();
    InitializeRunningAverageDeltaTime();
    
    // 3. 创建 EngineSubsystem
    EngineSubsystemCollection.Initialize();
    
    // 4. Editor 特有 / Game 特有(各自重写后做)
    
    // 5. 触发"Engine 初始化中"委托
    FCoreDelegates::OnEngineInitialized.Broadcast();
    
    // ...
}
```

### 6.3.3.1 `EngineSubsystemCollection.Initialize`

这一行是关键。`UEngine` 内部持有 `FSubsystemCollection<UEngineSubsystem>`。`Initialize` 内部:

```cpp
// 简化伪代码
void FSubsystemCollection::Initialize()
{
    // 找出所有 UEngineSubsystem 子类
    TArray<UClass*> SubsystemClasses = GetAllDerivedClasses(UEngineSubsystem::StaticClass());
    
    for (UClass* C : SubsystemClasses)
    {
        // 检查 ShouldCreateSubsystem(C 的 CDO 调,允许子类否决)
        UEngineSubsystem* CDO = GetDefault<UEngineSubsystem>(C);
        if (!CDO->ShouldCreateSubsystem(/* outer */ this->Outer))
            continue;
        
        // 实例化
        UEngineSubsystem* Sub = NewObject<UEngineSubsystem>(this->Outer, C);
        
        // 调 Initialize
        Sub->Initialize(*this);
        
        // 存到 collection
        Subsystems.Add(C, Sub);
    }
}
```

**含义**:你**只需要**写一个 `UEngineSubsystem` 子类,UE 自动:
1. 启动期实例化
2. 调你的 `Initialize`
3. 通过 `GEngine->GetEngineSubsystem<T>()` 给你访问

**完全不需要**手动注册或在某个地方 `new`。

### 6.3.3.2 `UEngineSubsystem` 的 RTS 用例

进程级单例(跨 World 持久):

```cpp
UCLASS()
class MYRTS_API URTSAssetCacheSubsystem : public UEngineSubsystem
{
    GENERATED_BODY()
public:
    virtual void Initialize(FSubsystemCollectionBase& Collection) override
    {
        // 进程启动期(GEngine 创建后)调用
        // 加载常用资产到内存
    }
    
    virtual void Deinitialize() override
    {
        // 进程退出时
    }
};

// 使用
URTSAssetCacheSubsystem* Cache = GEngine->GetEngineSubsystem<URTSAssetCacheSubsystem>();
```

EngineSubsystem 跨 World / 跨关卡持久,适合"进程级缓存"。

## 6.3.4 `OnPostEngineInit` 委托

`LaunchEngineLoop.cpp:4769`:

```cpp
FCoreDelegates::OnPostEngineInit.Broadcast();
```

这是**所有 OnPostEngineInit 监听者**的触发时机。在 GEngine->Init 完成之后立刻广播。

### 6.3.4.1 这时候有什么可用

✅ GEngine 完整可用
✅ EngineSubsystem 已就绪
✅ Slate / Renderer 就绪
✅ 反射 / GC / 模块系统全部就绪
❌ 还没有 World(LoadDefaultMap 在更后面)
❌ 还没有 GameInstance(Game build)
❌ 还没有 PlayerController / Pawn

适合"我需要 GEngine 但不需要 World" 的初始化:Editor 工具菜单注册、自定义 RHI hook、加载全局资产。

### 6.3.4.2 Editor 工具典型用法

```cpp
class FMyRTSEditorModule : public IModuleInterface
{
    virtual void StartupModule() override
    {
        FCoreDelegates::OnPostEngineInit.AddRaw(this, &ThisClass::OnPostEngineInit);
    }
    
    void OnPostEngineInit()
    {
        // Editor 主菜单已就绪,注册自定义菜单项
        FMenuBuilder MenuBuilder(...);
        UToolMenus::Get()->ExtendMenu(...);
    }
};
```

LoadingPhase=PostEngineInit 与 OnPostEngineInit 委托**几乎等价**(LoadingPhase=PostEngineInit 模块的 StartupModule 在委托广播前后被调,具体看时序细节)。99% 的项目两者通用。

## 6.3.6 `GEngine->Start()` —— 真正"运行游戏"

`LaunchEngineLoop.cpp:4811`:

```cpp
GEngine->Start();
```

这一步是**Editor 和 Game 行为分歧最大的地方**。

### 6.3.6.1 Game build:`UGameEngine::Start`

简化:

```cpp
void UGameEngine::Start()
{
    // 创建 GameInstance
    GameInstance = NewObject<UGameInstance>(this, GameInstanceClass);
    GameInstance->Init();
    
    // GameInstance 内部:
    //   - 实例化 UGameInstanceSubsystem
    //   - 调每个 GameInstanceSubsystem::Initialize
    
    // 加载默认关卡
    FString DefaultMap = GetDefault<UGameMapsSettings>()->GetGameDefaultMap();
    UWorld* World = LoadWorld(DefaultMap);
    
    // 创建 PlayerController + Pawn
    GameInstance->CreateLocalPlayer(0);
    World->BeginPlay();
}
```

### 6.3.6.2 Editor build:`UUnrealEdEngine::Start`

打开 Editor 主窗口,**不**自动加载关卡(用户手动开关卡)。

### 6.3.6.3 GameInstance / GameInstanceSubsystem

`UGameInstance` 是"一局游戏"的容器(跨关卡)。它持有 `UGameInstanceSubsystem`。

```cpp
UCLASS()
class URTSPlayerProfileSubsystem : public UGameInstanceSubsystem
{
    GENERATED_BODY()
public:
    virtual void Initialize(FSubsystemCollectionBase& Collection) override
    {
        // GameInstance 创建后调
        // 加载玩家档案、登录服务器
    }
};

// 使用
URTSPlayerProfileSubsystem* P = GameInstance->GetSubsystem<URTSPlayerProfileSubsystem>();
// 或
P = GetWorld()->GetGameInstance()->GetSubsystem<URTSPlayerProfileSubsystem>();
```

GameInstanceSubsystem 在**关卡切换之间持久**(切关卡换 World,GameInstance 不变)。

### 6.3.6.4 Subsystem 四象限对照

```
┌─────────────────────┬────────────────────────────────┐
│  Subsystem 类型     │  生命周期 / 用途                │
├─────────────────────┼────────────────────────────────┤
│  UEngineSubsystem    │  进程级,跨 GameInstance 持久   │
│                      │  GEngine->GetEngineSubsystem<T>│
│                      │  适合:全局缓存、跨进程资源    │
├─────────────────────┼────────────────────────────────┤
│  UGameInstanceSubs  │  一局游戏,跨 World 持久        │
│                      │  GameInstance->GetSubsystem<T> │
│                      │  适合:玩家档案、登录会话       │
├─────────────────────┼────────────────────────────────┤
│  UWorldSubsystem     │  随 World 创建/销毁            │
│                      │  World->GetSubsystem<T>        │
│                      │  适合:场景内逻辑、Mass Subsys │
├─────────────────────┼────────────────────────────────┤
│  ULocalPlayerSubs   │  随本地玩家创建/销毁            │
│                      │  LocalPlayer->GetSubsystem<T>  │
│                      │  适合:Enhanced Input、UI 状态 │
└─────────────────────┴────────────────────────────────┘
```

§11 详讲。这一节先建立"四种 Subsystem 各对应一个时期"的认知。

## 6.3.7 第一个 World 加载

`Start()` 内部 `LoadWorld(DefaultMap)`:

```
LoadDefaultMap
   ↓
读 .umap 资产
   ↓
反序列化 UWorld 对象
   ↓
World->InitWorld()
   ├─ 创建 PersistentLevel
   ├─ 加载所有 Actor / ActorComponent
   └─ 实例化 UWorldSubsystem(★ 包括 UMassEntitySubsystem)
   ↓
World->BeginPlay()
   ├─ Actor::BeginPlay 链(GameMode → GameState → Pawn → ...)
   └─ Subsystem::OnWorldBeginPlay
   ↓
第一帧 Tick 之前的状态完成
```

§7.1 / §7.2 详细拆 `UWorld::InitWorld`。这一节你只需要知道:**Init 末尾,World + GameInstance + Subsystem 全部就绪,Mass Subsystem 在这一刻也存在了**。

## 6.3.8 服务器 / Editor / Standalone 在 Init 的差异

### 6.3.8.1 Dedicated Server

```
GEngine = UGameEngine(或 UServerCommandletEngine)
   ↓
跳过 Slate / Renderer(NullRHI)
   ↓
LoadDefaultMap = ServerDefaultMap
   ↓
开 Listen Port,等待 Client 连接
```

### 6.3.8.2 Editor + PIE

```
GEngine = UUnrealEdEngine
   ↓
打开 Editor 主窗口
   ↓
等用户打开关卡(LoadEditorWorld)
   ↓
玩家点 "Play" → UEditorEngine::PlayInEditor → 创建 PIE World
```

PIE World 是**Editor World 的副本**,与 Editor World 共存。`GEngine` 仍是 UEditorEngine。

### 6.3.8.3 Standalone Game(玩家 build)

```
GEngine = UGameEngine
   ↓
LoadDefaultMap
   ↓
直接玩
```

## 6.3.9 RTS / Mass 视角下的 Init 接入

### 6.3.9.1 全局 RTS Subsystem 的层次划分

```cpp
// 进程级缓存(常用资产、配置)
UCLASS()
class URTSAssetCacheSubsystem : public UEngineSubsystem { /* ... */ };

// 玩家档案 / 登录会话(跨关卡)
UCLASS()
class URTSPlayerSessionSubsystem : public UGameInstanceSubsystem { /* ... */ };

// Mass entity / 战斗状态(随 World 出生)
UCLASS()
class URTSBattleSubsystem : public UWorldSubsystem { /* ... */ };

// 玩家本人选择 / UI 状态
UCLASS()
class URTSSelectionSubsystem : public ULocalPlayerSubsystem { /* ... */ };
```

每个 Subsystem 的 `Initialize` 在对应时机被调,**完全不需要**你写注册代码。

### 6.3.9.2 自定义 GEngine 子类(高级)

如果你想 hook `UGameEngine::Init` / `Tick` / 帧节奏:

```cpp
UCLASS()
class UMyRTSGameEngine : public UGameEngine
{
    GENERATED_BODY()
    
    virtual void Init(IEngineLoop* InEngineLoop) override
    {
        // RTS 特有的进程级初始化
        Super::Init(InEngineLoop);
    }
    
    virtual void Tick(float DeltaSeconds, bool bIdleMode) override
    {
        // 加 RTS 特定的 hook(全局 cooldown 等)
        Super::Tick(DeltaSeconds, bIdleMode);
    }
};

// DefaultEngine.ini
[/Script/Engine.Engine]
GameEngine=/Script/MyRTS.MyRTSGameEngine
```

99% 你**不需要**自定义 GEngine。EngineSubsystem 已经覆盖大部分场景。

### 6.3.9.3 Mass Subsystem 何时就绪

`UMassEntitySubsystem` 是 `UWorldSubsystem`。**只在 LoadDefaultMap 后**才存在。

如果你 RTS 主菜单(还没进入战斗关卡)就想跑 Mass(典型场景:主菜单背景演示动画),**主菜单关卡也是一个 World**,创建时它的 Mass Subsystem 也就绪。"Mass Subsystem 必须有 World"是硬约束,但 World 不必"是战斗关卡"。

## 6.3.10 `GEngine->Start()` 的完整时序图(综合)

```
GEngine->Init(this)                          ← UEngine 初始化
   ├─ UEngineSubsystem::Initialize(每种)
   ├─ Slate / Renderer / RHI 初始化
   └─ 完成

OnPostEngineInit 委托广播

LoadModulesForProject(PostEngineInit)        ← 加载这阶段模块

GEngine->Start()                              ← 启动游戏循环
   ├─ Game build:
   │     ├─ NewObject<UGameInstance>
   │     ├─ GameInstance->Init()
   │     │     └─ UGameInstanceSubsystem::Initialize(每种)
   │     ├─ LoadDefaultMap → UWorld 创建
   │     │     ├─ UWorldSubsystem::Initialize(每种,含 UMassEntitySubsystem)
   │     │     ├─ Actor 加载 / BeginPlay
   │     │     └─ ULocalPlayer 创建 → ULocalPlayerSubsystem::Initialize
   │     └─ 第一帧 Tick 前
   │
   └─ Editor build:
         打开 Editor 主窗口 / 等用户操作

返回 FEngineLoop::Init
   ↓
进 Tick 循环
```

## 6.3.11 调试 Init 阶段问题

### 6.3.11.1 EngineSubsystem 没初始化

可能原因:
- 模块没在 PostEngineInit 之前加载(LoadingPhase 太晚)
- `ShouldCreateSubsystem` 返回 false(检查 CDO 实现)
- UCLASS 标记错(漏 GENERATED_BODY)

诊断:`obj list class=YourEngineSubsystem` 看是否实例存在。

### 6.3.11.2 Subsystem `Initialize` 没被调

可能:
- 该 Subsystem 类型与 Outer 不匹配(EngineSubsystem 装到 GameInstance 上)
- Subsystem 类有循环依赖(`Collection.InitializeDependency<T>()` 死循环)

### 6.3.11.3 World 加载失败

LoadDefaultMap 失败的常见原因:
- DefaultMap INI 配错路径
- .umap 资产引用了不存在的 UClass(模块没加载或被删)
- 玩家级别 cook 时 .umap 没进 PAK

诊断:启动加 `-log -LogCmds="Log LogStreaming Verbose"` 看加载详情。
