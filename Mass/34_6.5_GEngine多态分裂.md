# §6.5 GEngine 多态分裂 — UEngine / UGameEngine / UEditorEngine

> **本节地图**:模块二第 6 章压轴。前面几节反复提到 `GEngine` 是 `UEngine*` 全局指针,实际指向 `UGameEngine` / `UUnrealEdEngine` / 自定义子类。这一节把这条多态链完整拆开。
>
> 这是"看似简单但容易混乱"的一章 —— 因为 Editor / Game / PIE / Server 各自走不同分支,而文档常常只讲一种。
>
> **预备知识**:§6.1-§6.4。
>
> **读完之后你能做到**:
> - 看到 `GEngine->XxxFunction()` 知道实际跑的是哪个类的实现
> - 区分 `GEngine` / `GEditor` / `GUnrealEd` 三个全局变量
> - 用 INI 配置自定义 GEngine 子类(不改 Engine)
> - 知道 RTS 项目是否需要自定义 GEngine(99% 不需要)

## 6.5.1 浅入:三个全局变量

`Engine.h` / `Editor.h` 头部定义:

```cpp
// Engine/Source/Runtime/Engine/Public/Engine/Engine.h
extern ENGINE_API UEngine* GEngine;

// Engine/Source/Editor/UnrealEd/Public/Editor.h
extern UNREALED_API class UEditorEngine* GEditor;

// Engine/Source/Editor/UnrealEd/Public/Editor/UnrealEdEngine.h
extern UNREALED_API class UUnrealEdEngine* GUnrealEd;
```

实际指向**同一个对象**(在 Editor build 中),只是不同静态类型:

```
[Editor build]
   GEngine    : UEngine*           ← 指向 UUnrealEdEngine 实例
   GEditor    : UEditorEngine*     ← 同一对象的 UEditorEngine 视图
   GUnrealEd  : UUnrealEdEngine*   ← 同一对象的最具体类型视图

[Game build]
   GEngine    : UEngine*           ← 指向 UGameEngine 实例
   GEditor    : nullptr            (Game build 没有 Editor 类)
   GUnrealEd  : nullptr
```

§6.3.2 看到的 `LaunchEngineLoop.cpp:4727`:

```cpp
GEngine = GEditor = GUnrealEd = NewObject<UUnrealEdEngine>(GetTransientPackage(), EngineClass);
```

一行赋三个全局变量。**它们都是同一个对象的不同接口面**。

## 6.5.2 类继承图

```
                    UObject
                       │
                       ↓
                    UEngine                    (Engine.h)
                       │
              ┌────────┴────────┐
              ↓                 ↓
       UGameEngine          UEditorEngine     (UnrealEd 模块)
       (GameEngine.h)            │
                                 ↓
                          UUnrealEdEngine
                          (UnrealEdEngine.h)
```

**Game build 不知道 UEditorEngine 存在**(它是 UnrealEd 模块的,Game 不依赖 UnrealEd)。所以 Game build 头文件**根本不能 #include "EditorEngine.h"**。

### 6.5.2.1 这造成的代码模式

```cpp
// 对象 RTS 代码(可能跑 Editor 也可能跑 Game)
void DoSomething()
{
#if WITH_EDITOR
    if (GEditor)        // 只在 Editor build 编译
    {
        GEditor->BeginPlayMap(...);
    }
#endif
    
    GEngine->Tick(...);   // 永远可用
}
```

`#if WITH_EDITOR` 包裹 Editor-only 代码。Game build 这一段编译期消失。

## 6.5.3 `UEngine`(基类)的核心字段与方法

`Engine/Source/Runtime/Engine/Classes/Engine/Engine.h` 是核心头文件,几千行。挑关键:

```cpp
class UEngine : public UObject, public FExec
{
public:
    // 子系统集合
    FSubsystemCollection<UEngineSubsystem> EngineSubsystemCollection;
    
    // World 列表(可能多个 PIE / 网络 World)
    TIndirectArray<FWorldContext> WorldList;
    
    // 默认配置
    TSubclassOf<class APawn>            DefaultPawnClass;
    TSubclassOf<class APlayerController> PlayerControllerClass;
    TSubclassOf<class AGameMode>          GameModeClass;
    TSubclassOf<class UGameInstance>      GameInstanceClass;
    
    // ViewportClient 类
    TSubclassOf<class UGameViewportClient> GameViewportClientClass;
    
    // 关键虚函数
    virtual void Init(IEngineLoop* InEngineLoop);
    virtual void Tick(float DeltaSeconds, bool bIdleMode);
    virtual void PreExit();
    virtual void Start();
    virtual UWorld* GetWorldFromContextObject(const UObject* Object, EGetWorldErrorMode ErrorMode) const;
    virtual UGameInstance* GetGameInstance() const;
    
    // 错误 / 退出
    virtual void OnLostFocusPause(bool EnablePause);
    virtual void RequestExit(bool Force);
    
    // 配置 / Console
    virtual void ParseCommandline();
    virtual bool Exec(UWorld* InWorld, const TCHAR* Cmd, FOutputDevice& Out = *GLog);
    
    // ...
};
```

虚函数都很基础,Game / Editor 各自重写。

### 6.5.3.1 `WorldList` —— 多 World 共存

`UEngine::WorldList` 是 `FWorldContext` 数组。一个 FWorldContext 包含一个 UWorld + 它的网络配置。**为什么需要数组**?

- **Editor + PIE**:Editor World + PIE World 共存
- **PIE 多 client**:每个 client 独立 World(Listen Server + Client1 + Client2)
- **网络 demo / replay**:demo World 与正常 World 共存

`UEngine::GetWorldFromContextObject` / `GetGameInstance` 等方法走 WorldList 查找。

实战:`GEngine->GetWorld()` 返回**第一个 game World**(可能不是你想要的 PIE World)。**正确姿势**:总是从某个 UObject 的 `GetWorld()` 调用,而不是直接 `GEngine->GetWorld()`。

```cpp
// ❌ 不一定对
UWorld* W = GEngine->GetWorld();

// ✅ 上下文相关
UWorld* W = SomeActor->GetWorld();
UWorld* W = SomeWorldContextObj->GetWorld();
UWorld* W = GetWorld();   // 在 UObject / Actor 类内部
```

## 6.5.4 `UGameEngine`

`Engine/Source/Runtime/Engine/Classes/Engine/GameEngine.h`。关键重写:

```cpp
class UGameEngine : public UEngine
{
public:
    UPROPERTY()
    TObjectPtr<UGameInstance> GameInstance;
    
    UPROPERTY()
    TObjectPtr<UGameUserSettings> GameUserSettings;     // 玩家画质设置
    
    // 主窗口
    TSharedPtr<class SWindow> GameViewportWindow;
    
    virtual void Init(IEngineLoop* InEngineLoop) override;
    virtual void Start() override;
    virtual void Tick(float DeltaSeconds, bool bIdleMode) override;
    virtual void PreExit() override;
    
    virtual UGameInstance* GetGameInstance() const override { return GameInstance; }

{
    // 进一步 Editor 体验(Outliner、Selection 工具等)
    // ...

```

`UUnrealEdEngine` 是 `UEditorEngine` 的标准子类,实际 Editor 实例用的就是它。

### 6.5.5.1 PIE 流程在哪里

`UEditorEngine::PlayInEditor`:

```cpp
void UEditorEngine::PlayInEditor(UWorld* InWorld, const FRequestPlaySessionParams& InRequestParams)
{
    // 1. 复制 Editor World 到一个 PIE World
    UWorld* PIEWorld = DuplicateWorldForPIE(InWorld);
    
    // 2. 创建 PIE GameInstance
    UGameInstance* GameInstance = NewObject<UGameInstance>(...);
    GameInstance->InitForPlayInEditor(...);
    
    // 3. PIE World 加进 WorldList
    FWorldContext& Context = WorldList[Add(...)];
    Context.SetCurrentWorld(PIEWorld);
    
    // 4. World->BeginPlay
    PIEWorld->BeginPlay();
    
    // 5. 注册 PIE 状态
    bIsPIEActive = true;
}
```

PIE 之所以"看起来像独立运行",是因为 `WorldList` 里**Editor World + PIE World 共存**,`UEngine::Tick` 都 tick。但 GEngine 仍是 UUnrealEdEngine,Editor UI 仍可用(暂停 PIE / Resume)。

## 6.5.6 自定义 GEngine 子类

§6.3.2.1 简单提过。完整最佳实践:

### 6.5.6.1 Game Engine 子类

```cpp
// MyRTSGameEngine.h
UCLASS(transient)
class MYRTS_API UMyRTSGameEngine : public UGameEngine
{
    GENERATED_BODY()
public:
    virtual void Init(IEngineLoop* InEngineLoop) override
    {
        Super::Init(InEngineLoop);
        UE_LOG(LogTemp, Display, TEXT("UMyRTSGameEngine Init"));
        // 你的 RTS 全局初始化(罕见,大多用 EngineSubsystem)
    }
    
    virtual void Tick(float DeltaSeconds, bool bIdleMode) override
    {
        Super::Tick(DeltaSeconds, bIdleMode);
        // 你的全局 tick(几乎没必要,FTickableGameObject 替代)
    }
};

// MyRTSGameEngine.cpp - 不需要太多
```

### 6.5.6.2 配置 INI

```ini
; MyRTS/Config/DefaultEngine.ini
[/Script/Engine.Engine]
GameEngine=/Script/MyRTS.MyRTSGameEngine
```

启动 Game build 时 `LaunchEngineLoop.cpp:4709` 读 INI,`StaticLoadClass(UGameEngine::StaticClass(), nullptr, "/Script/MyRTS.MyRTSGameEngine")` 找你的类,实例化。

### 6.5.6.3 Editor Engine 子类(罕见)

```ini
; DefaultEngine.ini
[/Script/Engine.Engine]
UnrealEdEngine=/Script/MyRTSEditor.MyRTSUnrealEdEngine
```

继承 UUnrealEdEngine + 重写 `Tick` / `PlayInEditor`。Editor 工具开发偶尔需要,大部分用 EditorSubsystem。

### 6.5.6.4 何时不要自定义 GEngine

**99% 的 RTS 项目不需要**。你想要的功能几乎都能用:
- `UEngineSubsystem`(进程级)
- `UGameInstanceSubsystem`(一局级)
- `UWorldSubsystem`(关卡级)
- `FCoreDelegates::OnPostEngineInit`(启动期 hook)

只有以下场景才考虑自定义 GEngine:
- 替换 `LoadMap` 行为(典型场景:RTS 自己的关卡序列化格式)
- 替换 `OnLostFocusPause`(自定义失焦行为)
- 全局 RHI / Renderer hook(渲染剥离时偶尔用)

## 6.5.7 实战:日志区分跑在哪个 Engine

```cpp
static FAutoConsoleCommand CmdInspectEngine(TEXT("rts.InspectEngine"),
    TEXT("Print current engine info"),
    FConsoleCommandDelegate::CreateLambda([]()
    {
        if (!GEngine) { UE_LOG(LogTemp, Warning, TEXT("GEngine null!")); return; }
        
        UE_LOG(LogTemp, Display, TEXT("GEngine class: %s"), *GEngine->GetClass()->GetName());
        UE_LOG(LogTemp, Display, TEXT("GIsEditor: %d"), GIsEditor);
        UE_LOG(LogTemp, Display, TEXT("IsRunningGame: %d"), IsRunningGame());
        UE_LOG(LogTemp, Display, TEXT("IsRunningDedicatedServer: %d"), IsRunningDedicatedServer());
        UE_LOG(LogTemp, Display, TEXT("IsRunningCommandlet: %d"), IsRunningCommandlet());
        UE_LOG(LogTemp, Display, TEXT("WorldList count: %d"), GEngine->GetWorldContexts().Num());
        for (const FWorldContext& Ctx : GEngine->GetWorldContexts())
        {
            UE_LOG(LogTemp, Display, TEXT("  World: %s (Type=%d)"), 
                Ctx.World() ? *Ctx.World()->GetName() : TEXT("null"),
                (int32)Ctx.WorldType);
        }
    }));
```

跑 `rts.InspectEngine`:
- Editor:`GEngine class: UnrealEdEngine` + WorldList 1-2 个(Editor World + 可能 PIE)
- Game build:`GEngine class: GameEngine` + WorldList 1 个

## 6.5.8 其它"全局指针"速查

UE 有不少全局指针,容易混:

| 全局指针 | 类型 | 何时有效 |
|---|---|---|
| `GEngine` | UEngine* | Init 之后 |
| `GEditor` | UEditorEngine* | Editor build,Init 之后 |
| `GUnrealEd` | UUnrealEdEngine* | Editor build,Init 之后 |
| `GWorld` | UWorld* | 当前**主**World(被弃用,改用 GetWorld())|
| `GLog` | FOutputDevice* | 总是有效 |
| `GConfig` | FConfigCacheIni* | PreInit 之后 |
| `GMalloc` | FMalloc* | Lazy(§1.3) |
| `GFrameCounter` | uint64 | 总是有效(0 起) |
| `GGameThreadId` | uint32 | GuardedMain 后 |

**`GWorld` 已 deprecated**(在 5.x):它是个全局指针,在多 World 场景(PIE / 网络)下不准确。新代码用 `GetWorld()`(从 UObject)或 `WorldContext->World()`。

## 6.5.9 RTS 项目何时碰 GEngine

### 6.5.9.1 OK 用 GEngine 的场景

```cpp
// 屏幕调试日志(任意线程都行)
GEngine->AddOnScreenDebugMessage(-1, 5.f, FColor::Yellow, TEXT("Hi"));

// 强制 GC
GEngine->ForceGarbageCollection(false);

// 退出
GEngine->RequestExit(false);

// 取 GameInstance(Game build)
UGameInstance* GI = GEngine->GetGameInstance();
```

### 6.5.9.2 不该用 GEngine 的场景

```cpp
// ❌ 取当前 World(不准确,PIE 多 World)
UWorld* W = GEngine->GetWorld();

// ❌ 调 EditorOnly 方法在 Game build
GEngine->Editor->...   // Game build 没有 Editor 字段

// ❌ 在 ctor 里访问 GEngine
class AMyActor {
    AMyActor() {
        GEngine->...   // GEngine 可能 null(Actor CDO 创建时)
    }
};
```

### 6.5.9.3 取 World 的标准姿势

```cpp
class AMyActor : public AActor
{
    void Foo()
    {
        UWorld* W = GetWorld();        // ★ 标准
    }
};

class UMyWorldSubsystem : public UWorldSubsystem
{
    void Foo()
    {
        UWorld* W = GetWorld();
    }
};

// 全局 lambda / FCoreDelegates 监听器(没有 UObject 上下文)
auto Lambda = []() {
    if (!GEngine || GEngine->GetWorldContexts().Num() == 0) return;
    UWorld* W = GEngine->GetWorldContexts()[0].World();   // ★ 第一个 World(谨慎)
};
```

### 6.5.10.1 RTS 项目接入引擎的"决策表"

```
你想做的事                                推荐姿势
─────────────────────────────────────────────────────────────────
进程级单例(资产缓存、统计)              UEngineSubsystem
跨关卡持久(玩家档案、登录)              UGameInstanceSubsystem
关卡内逻辑(战斗、雾战、Mass)            UWorldSubsystem
玩家本人(Selection、UI 状态)            ULocalPlayerSubsystem
启动期一次性(GEngine 已就绪)           OnPostEngineInit 委托
每帧逻辑但不是 Actor                     FTickableGameObject
全局热点钩子(替换 LoadMap 等)          自定义 GEngine 子类(罕见)
全局命令行 / 配置                        UDeveloperSettings
```
