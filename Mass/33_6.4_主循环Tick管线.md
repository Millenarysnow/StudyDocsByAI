# §6.4 主循环 FEngineLoop::Tick 的整体管线

> **本节地图**:模块二第 6 章第 4 节。Init 完成后,引擎进入 `while (!IsEngineExitRequested()) { EngineTick(); }` 循环。每帧 `FEngineLoop::Tick` 是这个循环的实体。
>
> 这一节我们把 Tick **完整拆开**,看它每帧做哪些事、三线程怎么同步、`GEngine->Tick` / `World->Tick` 在哪段 触发。
>
> **预备知识**:§6.1 / §6.3,§5(并发)。
>
> **读完之后你能做到**:
> - 画出 GameThread / RenderThread / RHIThread 的三线程时间线
> - 在 Insights 时间线上认出每个 frame 的关键 phase
> - 知道 Mass Tick 在什么位置被调用
> - 估算各 phase 的预算分配(Mass Tick / 渲染 / Slate / Network)

## 6.4.1 浅入:每帧的 12 个动作

`FEngineLoop::Tick`(LaunchEngineLoop.cpp:5536)简化:

```cpp
void FEngineLoop::Tick()
{
    SCOPED_NAMED_EVENT_TEXT("FEngineLoop::Tick", FrameColor);
    
    // 1. 退出请求处理
    BeginExitIfRequested();
    
    // 2. Heartbeat(死锁检测)
    FThreadHeartBeat::Get().HeartBeat();
    FGameThreadHitchHeartBeat::Get().FrameStart();
    
    // 3. 渲染线程 / RHI 配置同步
    LatchRenderThreadConfiguration();
    
    // 4. Movie player 阻塞(Loading screen)
    FMoviePlayerProxy::BlockingForceFinished();
    
    // 5. 计算 DeltaTime + 帧率限制
    UpdateTimeAndHandleMaxTickRate();
    
    // 6. 各种 stat / log flush
    GLog->FlushThreadedLogs();
    GFrameCounter++;
    
    // 7. Slate 输入采集
    FCoreDelegates::OnSamplingInput.Broadcast();
    if (FSlateApplication::IsInitialized() && !bIdleMode)
    {
        FSlateApplication::Get().PollGameDeviceState();
        FSlateApplication::Get().FinishedInputThisFrame();
    }
    
    // 8. ★★ 核心:GEngine 主 Tick(World tick / Actor tick / Mass Processor 走这里)
    GEngine->Tick(FApp::GetDeltaTime(), bIdleMode);
    
    // 9. Slate platform / input tick
    FSlateApplication::Get().Tick(ESlateTickType::PlatformAndInput);
    
    // 10. Concurrent slate tasks(渲染线程提交准备)
    
    // 11. RHI / RenderThread 命令推送
    GEngine->TickDeferredCommands();
    
    // 12. EndOfFrame / RHIBeginFrame 下一帧准备
    EndOfFrameUpdates();
    RHIBeginFrame();
}
```

每帧 16.6 ms 内,这些操作完成得不能再多。

## 6.4.2 三线程时间线

UE 的并行渲染有三个 named threads(§5.2.2.3):

```
GameThread  : ── A:Tick ──── B:Tick ──── C:Tick ──── D:Tick ──
                  │             │             │             │
                  ↓ enqueue     ↓             ↓             ↓
RenderThread:  ── ──── A:Render ──── B:Render ──── C:Render ──
                            │             │             │
                            ↓ enqueue     ↓             ↓
RHIThread   :  ── ──── ──── A:Submit ──── B:Submit ──── ──
                                  │             │
                                  ↓ submit      ↓
GPU         :  ── ──── ──── ──── A:Draw ──── B:Draw ────
```

**典型延迟**:GameThread 的输入到 GPU 出图,**2-3 帧延迟**(每帧 16.6ms,合 33-50ms)。

### 6.4.2.1 同步点

每帧 GameThread 在 `RHIBeginFrame()` 处与 RHIThread 同步 — 如果 GPU 跟不上(Render queue 满),GameThread **阻塞等**。这是为什么"GPU 慢导致 GameThread 帧率掉" — RHIThread 反压回来了。

### 6.4.2.2 RenderingTickables

Tick 中 `LatchRenderThreadConfiguration` 做"GameThread 给 RenderThread 配置打补丁"。`-onethread` 模式(单线程渲染)直接 GameThread 跑 `TickRenderingTickables`,正常多线程模式 enqueue 给 RenderThread。

## 6.4.3 `GEngine->Tick` —— 真正的"游戏 tick"

`LaunchEngineLoop.cpp:5828`:

```cpp
GEngine->Tick(FApp::GetDeltaTime(), bIdleMode);
```

`UEngine::Tick` 是虚函数,UGameEngine / UEditorEngine 各重写。简化共同部分:

```cpp
void UGameEngine::Tick(float DeltaSeconds, bool bIdleMode)
{
    Super::Tick(DeltaSeconds, bIdleMode);
    
    // 各 World 的 tick(可能多个 World)
    for (FWorldContext& Context : WorldList)
    {
        UWorld* World = Context.World();
        if (World && !World->IsPendingKill())
        {
            World->Tick(LEVELTICK_All, DeltaSeconds);    // ★★★ World tick
        }
    }
    
    // Render world(对每个 World 准备渲染)
    RedrawViewports();
    
    // Subsystem tick / GameInstance tick
    
    // GC 检查触发(§4.2)
    ConditionalCollectGarbage();
}
```

### 6.4.3.1 `UWorld::Tick` 是 game logic 的"心脏"

`UWorld::Tick` 内部:
- 处理 World Tick Function(每个 Actor / Component 的 Tick)
- TickGroup 调度(PrePhysics / DuringPhysics / PostPhysics / PostUpdateWork)
- **Mass Processor 在某个 TickGroup 里跑**(§8.4 详讲)
- 物理 / 网络复制 / Animation
- 玩家输入路由

§7 / §8 详细拆。这一节你只需要知道:**`GEngine->Tick → World->Tick → Mass Tick`** 是一条链。

## 6.4.4 帧时长控制

`UpdateTimeAndHandleMaxTickRate`:

```cpp
// 简化
void FEngineLoop::UpdateTimeAndHandleMaxTickRate()
{
    double CurrentTime = FPlatformTime::Seconds();
    double LastTickTime = ...;
    float DeltaTime = (float)(CurrentTime - LastTickTime);
    
    // 帧率限制
    float MaxTickRate = GEngine->GetMaxTickRate(DeltaTime);    // 看 t.MaxFPS cvar
    if (MaxTickRate > 0.0f)
    {
        float WaitTime = FMath::Max(1.0f / MaxTickRate - DeltaTime, 0.0f);
        FPlatformProcess::Sleep(WaitTime);
        // 重算 DeltaTime
    }
    
    FApp::SetDeltaTime(DeltaTime);
}
```

cvar:
- `t.MaxFPS 60` — 锁 60fps
- `t.MaxFPS 0` — 不限
- `r.VSync 1` — VSync(锁屏幕刷新率)

**RTS 实战**:玩家可调 `t.MaxFPS`。游戏自身**不**应该写死帧率,让玩家选。

## 6.4.5 Slate Tick(UI 框架)

`Slate` 是 UE 的 immediate-mode UI 框架,`UMG` 是它的 retained-mode 包装。每帧两次 tick:

### 6.4.5.1 第一次:输入采集(Tick 早期)

```cpp
FSlateApplication::Get().PollGameDeviceState();
FSlateApplication::Get().FinishedInputThisFrame();
```

收集鼠标 / 键盘 / 手柄输入,产生 input event。后续 `World->Tick` 内部传给 PlayerController。

### 6.4.5.2 第二次:平台 + 输入分发

```cpp
FSlateApplication::Get().Tick(ESlateTickType::PlatformAndInput);
```

把累积的输入派发给 Slate widgets(UMG 也走这条)。

### 6.4.5.3 第三次:绘制(在 EndFrame 阶段)

`ESlateTickType::Time` 模式,准备 Slate widget 的 paint 数据,enqueue 给 RenderThread。

**所以一帧内 Slate 实际被 tick 多次**(每次 `ESlateTickType` 不同)。这是 Slate 的"分阶段 tick"模型。

---

## 6.4.6 Movie / Loading Screen 的 Tick 处理

`FMoviePlayerProxy::BlockingForceFinished()` 出现两次。它检测"是不是有 loading movie 在播":
- 有 movie 播 → 阻塞 GameThread,直到 movie 结束
- 没 movie → 立即返回

为什么阻塞?加载关卡时,GameThread 跑 `LoadWorld` 几百 ms,玩家不应该看到画面卡住,而是看到 Loading 动画。Movie player 用 RenderThread 独立播 movie,GameThread 阻塞期间不影响渲染。

---

## 6.4.7 EndOfFrame / RHIBeginFrame

```cpp
EndOfFrameUpdates();   // 把这一帧的所有 GameThread 命令打包给 RenderThread
RHIBeginFrame();       // 通知 RHI "开始下一帧"
```

`EndOfFrameUpdates` 是个相对重量级操作(几百 us 到 ms),它**等 RenderThread 完成上一帧的关键 phase** 才返回。是 GameThread - RenderThread 同步点。

---

## 6.4.8 完整的"一帧" Insights 视图

启动加 `-trace=cpu,frame,gpu`,Insights 时间线一帧大概长这样:

```
GameThread:      [HeartBeat][Slate Input][World Tick(Pre)][Physics][World Tick(Post)][Slate Tick][EndOfFrame]
                      ▲ 0.1ms      0.3ms        ~6ms          1ms        ~3ms          1ms          0.5ms
                                                  │
                                                  ↓ enqueue 渲染命令
RenderThread:    [────────────────][Render上一帧][Render 这一帧 Pre]                               [开始下一帧]
                                       ▲ ~5ms        ~6ms
                                       │
                                       ↓ enqueue RHI 命令
RHIThread:       [───────────────][Submit 上一帧][Submit 这一帧]
                                      ▲ ~3ms

GPU:             [────────────────────────][Draw 上一帧][Draw 这一帧]
                                                ▲ ~5ms
```

每个 thread 都"满负荷":Game/Render/RHI 流水线(pipeline)各自跑各自的帧。

## 6.4.9 Idle Mode

```cpp
GEngine->Tick(DeltaTime, bIdleMode);
```

`bIdleMode = true` 时:
- 渲染最小化(可能黑屏 / 仅 logo)
- 物理 / 网络仍跑(否则游戏停)
- CPU / GPU 占用降低

**触发**:Editor 失焦(玩家 alt-tab 走)、移动设备进后台。`FApp::IsForegrounded()` 返回 false。

实战:RTS 多人游戏**绝不**因为玩家 alt-tab 暂停模拟(其他玩家在线!),所以 idle mode 默认 game logic 仍跑。

## 6.4.10 RTS / Mass 视角下的 Tick 接入

### 6.4.10.1 Mass Tick 在 World Tick 内

```
FEngineLoop::Tick
   ↓
GEngine->Tick(DeltaTime)
   ↓
World->Tick(LEVELTICK_All, DeltaTime)
   ├─ TickGroup_PrePhysics (★ Mass Processor 通常这里)
   ├─ TickGroup_DuringPhysics
   ├─ TickGroup_PostPhysics
   └─ TickGroup_PostUpdateWork
```

§8.4 详细拆 TickGroup。这一节你只需知道:**Mass Processor 跑在 World Tick 的某个 TickGroup**,被 GameThread 调度。Mass Processor 的并行(`ParallelForEachEntityChunk`)用 worker pool,但**调度入口**仍在 GameThread。

### 6.4.10.2 RTS 项目的帧预算分配建议

```
GameThread 帧预算 16.6 ms 拆分:
  HeartBeat / Slate Input        :  0.5 ms
  Mass Pre-Physics Processor     :  3 ms      (50K entity 移动 / AI)
  Physics                         :  1 ms      (RTS 物理少)
  Mass Post-Physics Processor    :  2 ms      (Steering 修正、命中检测)
  PlayerController / 输入 / UI    :  1 ms
  Networking 复制               :  1.5 ms
  GC 增量 / Stat / Log           :  0.5 ms
  Slate Tick / EndOfFrame         :  1 ms
  --------------------------------------
  Total                           : 10.5 ms
  剩余                           :  6.1 ms 余量

RenderThread / RHIThread / GPU 在另外两条线,独立预算
```

健康的 RTS 项目应该控制 GameThread < 12 ms,留余量给峰值。

### 6.4.10.3 自定义 GEngine Tick(罕见)

如果你 RTS 想加"全局每帧逻辑,所有 World 之外":

```cpp
UCLASS()
class UMyRTSGameEngine : public UGameEngine
{
    virtual void Tick(float DeltaSeconds, bool bIdleMode) override
    {
        Super::Tick(DeltaSeconds, bIdleMode);
        
        // 你的全局 tick(全局 cooldown / 跨 World 状态等)
    }
};
```

**99% 不需要**。EngineSubsystem + `FTickableGameObject` 接口够用。

### 6.4.10.4 `FTickableGameObject` —— 不需要 Actor 也能 Tick

```cpp
class FMyTicker : public FTickableGameObject
{
public:
    virtual void Tick(float DeltaTime) override
    {
        // 每帧调
    }
    
    virtual ETickableTickType GetTickableTickType() const override
    {
        return ETickableTickType::Always;
    }
    
    virtual TStatId GetStatId() const override
    {
        RETURN_QUICK_DECLARE_CYCLE_STAT(FMyTicker, STATGROUP_Tickables);
    }
    
    virtual UWorld* GetTickableGameObjectWorld() const override
    {
        return GWorld;
    }
};
```

`FTickableGameObject` 在 `World->Tick` 末尾被调度。**适合"想每帧 tick 但不是 Actor / Component"**:工具类、debug 可视化、独立计时器。

EngineSubsystem / WorldSubsystem 的 `Tick` 接口也基于这个。

```
GameThread: 12.5 ms

```

### 6.4.11.2 `stat fps`

### 6.4.11.3 Insights 帧时间线

`-trace=cpu,frame,gpu`,Insights 加载,顶部"Frames"面板显示每帧颜色:

- 绿:< 16.6 ms(60fps)
- 黄:< 33.3 ms(30fps)
- 红:更慢

点红帧 zoom 进去,看是什么 scope 拖慢。

### 6.4.11.4 GameThread 长 task 定位

GameThread tick 内某段超过 5 ms 通常是问题。典型嫌疑:
- 某 Actor BeginPlay 里加载大资产
- 某 ActorComponent::Tick 跑了密集逻辑
- Mass Processor 没走并行路径

Insights 一目了然 — 长块 scope 名字直接告诉你。

## 6.4.13 实操提示与下一节预告

### 实操提示

- **`stat unit` 永远开着**:开发期屏幕角落显示,异常立刻发现
- **DeltaTime 上限**:`UpdateTimeAndHandleMaxTickRate` 会把 DeltaTime 限制在最大 0.4 秒(防止物理 explode),所以暂停后恢复你不会拿到一个 10 秒的 DeltaTime
- **帧率不稳**:看 `t.UnsteadyFrameTimeFudgeFactor` cvar 等,但通常是某段代码每隔几秒做一次重计算导致的
- **Mass Tick 在哪**:`DumpTicks` 命令列出所有 TickFunction,搜 `Mass`
