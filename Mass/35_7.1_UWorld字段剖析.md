# §7.1 UWorld 字段剖析 — 游戏世界容器

> **本节地图**:模块二第 7 章第 1 节。`UWorld` 是 UE 的"游戏世界容器"。一个 World 包含:关卡、Actor、网络驱动、游戏状态、Tick 调度器。
>
> 这是后面所有章节(Tick / GameMode / Subsystem / Mass)的"容器"。理解 UWorld 字段后,你看到任何 `World->Xxx` 调用都立刻知道在做什么。
>
> **预备知识**:§3(UObject)、§6(GEngine 启动)。
>
> **读完之后你能做到**:
> - 看到 `UWorld` 任意字段知道它管什么
> - 区分 EWorldType 各种(Game / Editor / PIE / EditorPreview)
> - 用 `GetWorld()` / `GetGameInstance()` / `GetAuthGameMode()` / `GetGameState<>()` 正确取上下文
> - 在自定义 Subsystem 里精确处理 World 生命周期

---

## 7.1.1 浅入:World 是什么

```cpp
// 简化心智模型
class UWorld
{
    ULevel*  PersistentLevel;          // 主关卡(永远存在)
    TArray<ULevel*>  Levels;           // 所有当前加载的子关卡(streaming)
    UNetDriver*  NetDriver;            // 网络层
    AGameModeBase*  AuthorityGameMode; // 服务器规则(仅 server)
    AGameStateBase*  GameState;        // 公共状态(server + client 都有)
    
    // Subsystem 集合
    FSubsystemCollection<UWorldSubsystem> SubsystemCollection;
    
    // Tick 调度器
    FTickTaskManager* TickTaskManager;
    
    // ... 几十个其它字段 ...
};
```

整个 RTS 战斗"在一个 UWorld 里跑"。每个 World 有完整自己的:Actor 列表、Subsystem 实例、网络连接、Tick 调度。**多 World 共存**(PIE / 网络 demo)是合法的。

---

## 7.1.2 UWorld 类继承

`Engine/Source/Runtime/Engine/Classes/Engine/World.h:917`:

```cpp
class UWorld final : public UObject, public FNetworkNotify
```

注意 `final`:**UWorld 不能被继承**。这是 Epic 决定的硬约束 —— UWorld 太核心,子类化会导致引擎不稳定。**所有"自定义 World 行为"通过 WorldSubsystem 完成**。

`FNetworkNotify` 是网络回调接口,UWorld 实现它接收网络事件(连接 / 断开 / 包到达)。

## 7.1.3 关键字段:核心三剑客

### 7.1.3.1 `PersistentLevel`(World.h:939)

```cpp
UPROPERTY(Transient)
TObjectPtr<class ULevel> PersistentLevel;
```

**主关卡**,始终存在(只要 World 存在)。所有 streaming 子关卡都被它"包含"。Actor 默认 spawn 到 PersistentLevel。

`Transient` 意味着:**不参与序列化**(World 序列化时 PersistentLevel 单独走)。

### 7.1.3.2 `NetDriver`(World.h:943)

```cpp
UPROPERTY(Transient)
TObjectPtr<class UNetDriver> NetDriver;
```

服务器或客户端的"网络驱动"。它管:
- 玩家连接(`UNetConnection`)
- Actor 复制(`ServerReplicateActors`)
- RPC 收发

PIE / Standalone 可能没有 NetDriver(单机)。多人时一定有。

§13 详讲。

### 7.1.3.3 `AuthorityGameMode` + `GameState`(World.h:1406-1410)

```cpp
UPROPERTY(Transient, ReplicatedUsing=OnRep_AuthorityGameMode)
TObjectPtr<class AGameModeBase> AuthorityGameMode;

UPROPERTY(Transient, ReplicatedUsing=OnRep_GameState)
TObjectPtr<class AGameStateBase> GameState;
```

**`AuthorityGameMode`**:仅服务器存在。Client 这字段是 nullptr。GameMode 持有"游戏规则"(谁赢谁输 / 何时开始)。

**`GameState`**:服务器创建,Replicated 到所有客户端。Client 也能读 GameState(查看分数、当前阶段)。

§9 详讲 GameMode/GameState。

## 7.1.4 关键字段:`Levels` 与 streaming

```cpp
// World.h:986-991
UPROPERTY(Transient)
TArray<TObjectPtr<ULevelStreaming>> StreamingLevels;

UPROPERTY(Transient, DuplicateTransient)
FStreamingLevelsToConsider StreamingLevelsToConsider;
```

**`StreamingLevels`**:配置层 — "我**可以**加载这些子关卡"。每个 `ULevelStreaming` 描述一个子关卡 + 其加载条件。

实际**已加载的关卡**通过 `GetLevels()` 拿到(包括 PersistentLevel + 已 stream-in 的子关卡)。

§7.3 World Partition 在 5.x 替代了大部分传统 streaming。

## 7.1.5 关键字段:`PerModuleDataObjects` 与 `ExtraReferencedObjects`

```cpp
UPROPERTY(Transient)
TArray<TObjectPtr<UObject>> ExtraReferencedObjects;

UPROPERTY(Transient)
TArray<TObjectPtr<UObject>> PerModuleDataObjects;
```

**`ExtraReferencedObjects`**:外部模块挂的"防 GC 引用"。某模块需要某 UObject 在该 World 生命周期内不被 GC,挂到这里。

**`PerModuleDataObjects`**:每模块自己存的 World-scoped 数据。例如 Mass 在某 World 有自己的状态,可以挂这里。

实战:**绝大多数情况用 WorldSubsystem 替代**,这两个字段是"老式接口"。

## 7.1.6 EWorldType —— World 的"身份"

`EngineTypes.h:1261`:

```cpp
namespace EWorldType
{
    enum Type
    {
        None,            // 子关卡的"附属 World"等
        Game,            // 玩家正在玩的 World
        Editor,          // Editor 中编辑的 World
        PIE,             // Play In Editor World
        EditorPreview,   // 编辑器小窗预览(Material 编辑器、Mesh 编辑器)
        GamePreview,     // 游戏内预览
        GameRPC,         // 仅 RPC 用的极简 World(无场景)
        Inactive,        // 加载了但暂未编辑的 Editor World
    };
}
```

`UWorld::WorldType` 字段决定行为:

```cpp
if (World->WorldType == EWorldType::Editor)
{
    // 编辑模式特定逻辑
}

if (World->WorldType == EWorldType::PIE)
{
    // PIE 特定
}

if (World->IsGameWorld())
{
    // Game / PIE 都算 game world(玩家在玩)
}
```

### 7.1.6.1 `IsGameWorld()`

```cpp
bool UWorld::IsGameWorld() const
{
    return WorldType == EWorldType::Game 
        || WorldType == EWorldType::PIE 
        || WorldType == EWorldType::GamePreview 
        || WorldType == EWorldType::GameRPC;
}
```

实战常用:**判断"玩家在玩"**(包括 PIE)。

```cpp
// 例:Mass Subsystem 仅在 game world 创建
bool URTSMassSubsystem::ShouldCreateSubsystem(UObject* Outer) const
{
    UWorld* World = Cast<UWorld>(Outer);
    return World && World->IsGameWorld();
}
```

## 7.1.7 World 的"全局指针"`GWorld`

```cpp
// 全局变量(老式)
ENGINE_API extern UWorld* GWorld;
```

**5.x 已 deprecated**(§6.5.8)。它指向"主 World",但多 World 场景下不准确。

**正确姿势**:从 `UObject` 的 `GetWorld()` 取上下文 World:

```cpp
class AMyActor : public AActor
{
    void Foo()
    {
        UWorld* W = GetWorld();   // ★ 取所属 World
    }
};

// 全局 lambda(无 UObject 上下文)— 罕见
auto Lambda = []() {
    if (GEngine && GEngine->GetWorldContexts().Num() > 0)
    {
        UWorld* W = GEngine->GetWorldContexts()[0].World();
    }
};
```

## 7.1.8 `GetWorld()` 的多种重写

`UObject::GetWorld()`(`Object.h`)默认返回 nullptr。子类重写:

```cpp
// AActor::GetWorld
UWorld* AActor::GetWorld() const
{
    return GetLevel()->GetWorld();
}

// UActorComponent::GetWorld
UWorld* UActorComponent::GetWorld() const
{
    return GetOwner() ? GetOwner()->GetWorld() : nullptr;
}

// UWorldSubsystem::GetWorld
UWorld* UWorldSubsystem::GetWorld() const
{
    return Cast<UWorld>(GetOuter());
}
```

每个有 World 上下文的 UObject 子类都重写 GetWorld。**返回 nullptr 的情况是合法的**(对象还没附到 World)。

### 7.1.8.1 `GetWorldChecked` —— 强制非 null

```cpp
UWorld* W = SomeObj->GetWorldChecked();   // 内部 check(W != nullptr)
```

你确定 World 应该存在的场景用这个。

## 7.1.9 `GetGameInstance` / `GetAuthGameMode` / `GetGameState`

UWorld 提供取上下文的便利方法:

```cpp
class UWorld
{
public:
    UGameInstance* GetGameInstance() const;          // 拿 GameInstance(可能 null,Editor World 没有)
    
    template<typename T> T* GetGameInstance() const  // 类型化版本
    { return Cast<T>(GetGameInstance()); }
    
    AGameModeBase* GetAuthGameMode() const;          // 仅 server,client 永 null
    template<typename T> T* GetAuthGameMode() const;
    
    AGameStateBase* GetGameState() const;            // server + client 都有
    template<typename T> T* GetGameState() const;
    
    APlayerController* GetFirstPlayerController() const;   // 第一个本地玩家
    
    // ...
};
```

### 7.1.9.1 实战:取游戏状态

```cpp
// 在你某 Actor / Subsystem 内
ARTSGameState* GS = GetWorld()->GetGameState<ARTSGameState>();
if (GS)
{
    GS->TotalUnitsAlive++;   // 修改全局状态
}

// 服务器才有的 GameMode
ARTSGameMode* GM = GetWorld()->GetAuthGameMode<ARTSGameMode>();
if (GM)   // client 这里 null
{
    GM->RegisterPlayerKill(...);
}
```

## 7.1.10 World 的生命周期事件

UWorld 在**几个关键时刻**触发委托:

```cpp
// FWorldDelegates(WorldDelegates.h)
struct FWorldDelegates
{
    // World 创建后,InitWorld 之前
    static FWorldEvent OnPreWorldInitialization;
    static FWorldEvent OnPostWorldInitialization;
    
    // BeginPlay 前
    static FWorldEvent OnWorldBeginTearDown;
    
    // World 析构前
    static FWorldEvent OnPreWorldFinishDestroy;
};
```

监听:

```cpp
class FMyModule : public IModuleInterface
{
    void StartupModule() override
    {
        FWorldDelegates::OnPostWorldInitialization.AddRaw(this, &FMyModule::OnWorldInit);
    }
    
    void OnWorldInit(UWorld* World, const UWorld::InitializationValues IVS)
    {
        if (World->IsGameWorld())
        {
            // 游戏 World 创建后做事
        }
    }
};
```

## 7.1.13 `UWorld::InitWorld` —— 初始化全套

```cpp
// 简化伪代码
void UWorld::InitWorld(const InitializationValues IVS)
{
    // 1. 设置基础字段
    WorldType = IVS.WorldType;
    
    // 2. 创建 PersistentLevel(如果还没)
    if (!PersistentLevel)
    {
        PersistentLevel = NewObject<ULevel>(this);
    }
    
    // 3. 创建 Subsystem(★★★ Mass Subsystem 在这里实例化)
    SubsystemCollection.Initialize(this);
    
    // 4. 创建 NetDriver(如果是网络 World)
    if (IVS.bCreateNetworkManager)
    {
        InitializeNetwork();
    }
    
    // 5. 触发 OnPreWorldInitialization → OnPostWorldInitialization 委托
    FWorldDelegates::OnPostWorldInitialization.Broadcast(this, IVS);
}
```

### 7.1.13.1 `BeginPlay` 在 InitWorld 之后

```cpp
// 简化
void UWorld::BeginPlay()
{
    // 1. 创建 GameMode(仅 server)
    if (HasAuthority())
    {
        AuthorityGameMode = SpawnActor<AGameModeBase>(...);
    }
    
    // 2. 触发所有 Actor::BeginPlay
    for (AActor* A : PersistentLevel->Actors)
    {
        A->DispatchBeginPlay();
    }
    
    // 3. 通知 Subsystem
    SubsystemCollection.NotifyBeginPlay();
}
```

## 7.1.14 一个常见的"生命周期"图

```
LoadMap / CreateWorld / DuplicateForPIE
   ↓
NewObject<UWorld> + 设置字段
   ↓
World->InitWorld(IVS)
   ├─ 创建 PersistentLevel
   ├─ 创建 NetDriver
   ├─ ★ 实例化 UWorldSubsystem(包括 UMassEntitySubsystem)
   ├─ 触发 OnPostWorldInitialization 委托
   ↓
World->BeginPlay()
   ├─ Spawn AuthorityGameMode(仅 server)
   ├─ Spawn AGameStateBase
   ├─ Actor::BeginPlay 链
   ├─ Subsystem::OnWorldBeginPlay
   ↓
[World 处于 "in game" 状态]
   ↓
World->Tick (每帧)
   ↓
   ...
   ↓
EndOfWorld(关卡切换 / 玩家退出)
   ↓
World->BeginTearingDown
   ├─ 触发 OnWorldBeginTearDown 委托
   ↓
World->CleanupWorld
   ├─ 销毁所有 Actor
   ├─ 销毁 Subsystem
   ↓
World 被 GC 回收
```

## 7.1.15 RTS / Mass 视角下的 World 关注点

### 7.1.15.1 Mass Subsystem 在 InitWorld 创建

`UMassEntitySubsystem` 是 `UWorldSubsystem`,在 `World->InitWorld` 里被实例化。**这一刻起 Mass 可用**。

```
InitWorld → SubsystemCollection.Initialize → UMassEntitySubsystem::Initialize
                                                ├─ 注册 Fragment 类型 BitSet
                                                ├─ 创建 Archetype 容器
                                                └─ 准备命令缓冲
```

后续 `BeginPlay` 时各 Mass Processor / Spawner 才开始工作。

### 7.1.15.2 自定义 RTS Subsystem 的 ShouldCreateSubsystem

```cpp
UCLASS()
class URTSCombatSubsystem : public UWorldSubsystem
{
    GENERATED_BODY()
public:
    virtual bool ShouldCreateSubsystem(UObject* Outer) const override
    {
        UWorld* World = Cast<UWorld>(Outer);
        if (!World) return false;
        
        // 仅在 game world(Game / PIE)创建,Editor World 不要
        return World->IsGameWorld();
    }
};
```

否则 Editor 打开关卡(EWorldType::Editor)也会创建 — 通常你不需要。

### 7.1.15.3 World 切换时 Mass 重置

切关卡 → 旧 World 销毁 → 旧 UMassEntitySubsystem 销毁 → 所有 Mass entity 自动销毁。新 World 创建 → 新 Subsystem → 全新 Mass 状态。

**Mass 状态不跨 World 持久**。如果你需要"保留某些信息切关卡"(玩家库存、技能解锁),用 GameInstanceSubsystem 持有,不要放 Mass。

## 7.1.16 调试 World 字段

```cpp
static FAutoConsoleCommand CmdInspectWorld(TEXT("rts.InspectWorld"),
    TEXT("Print current World info"),
    FConsoleCommandDelegate::CreateLambda([]()
    {
        if (!GEngine) return;
        
        for (const FWorldContext& Ctx : GEngine->GetWorldContexts())
        {
            UWorld* W = Ctx.World();
            if (!W) continue;
            
            UE_LOG(LogTemp, Display, TEXT("=== World %s ==="), *W->GetName());
            UE_LOG(LogTemp, Display, TEXT("  Type: %s"), LexToString(W->WorldType));
            UE_LOG(LogTemp, Display, TEXT("  IsGameWorld: %d"), W->IsGameWorld());
            UE_LOG(LogTemp, Display, TEXT("  HasBegunPlay: %d"), W->HasBegunPlay());
            UE_LOG(LogTemp, Display, TEXT("  PersistentLevel: %s"), W->PersistentLevel ? *W->PersistentLevel->GetName() : TEXT("null"));
            UE_LOG(LogTemp, Display, TEXT("  NetDriver: %s"), W->NetDriver ? TEXT("yes") : TEXT("no"));
            UE_LOG(LogTemp, Display, TEXT("  AuthorityGameMode: %s"), W->GetAuthGameMode() ? *W->GetAuthGameMode()->GetClass()->GetName() : TEXT("null (client)"));
            UE_LOG(LogTemp, Display, TEXT("  GameState: %s"), W->GetGameState() ? *W->GetGameState()->GetClass()->GetName() : TEXT("null"));
            UE_LOG(LogTemp, Display, TEXT("  Actors count: %d"), W->PersistentLevel ? W->PersistentLevel->Actors.Num() : 0);
        }
    }));
```

跑 `rts.InspectWorld` 看当前 World 状态。Editor + PIE 时能看到两个 World。
