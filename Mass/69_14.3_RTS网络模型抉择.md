## 14.3.1 两种模型对比

### Authoritative + Snapshot(权威服务器 + 状态快照)

```
Server 模拟所有单位
   ↓
每 tick 计算 delta
   ↓
发送状态快照给所有 client
   ↓
Client 仅显示(不模拟)
```

**特点**:
- ✅ 简单,不需要 determinism
- ✅ 反作弊容易(server 权威)
- ✅ 重连容易(收快照即可恢复)
- ❌ 带宽:状态量 × 50K 单位 × N client(大)
- ❌ Server CPU:模拟 50K 单位

### Lockstep(同步输入)

```
所有 client 都模拟所有单位
   ↓
client 之间只同步玩家"输入命令"(几 KB / s)
   ↓
所有 client 在相同输入下产生相同状态(deterministic)
```

**特点**:
- ✅ 带宽极低(只发命令)
- ✅ 服务器轻(可能纯转发,不模拟)
- ❌ 严格要求 determinism(浮点精度、SIMD、编译器差异都要确保一致)
- ❌ 反作弊难(每个 client 都模拟)
- ❌ 重连难(从 0 重放所有命令)
- ❌ 一个 client 卡 → 全员等(同步 lockstep)

## 14.3.2 历史选型

```
StarCraft 1 / Warcraft 3 / Age of Empires(经典 RTS):
   ✓ Lockstep + Determinism
   理由:90 年代带宽极低,Lockstep 是唯一选择

现代游戏(2010+):
   FPS / TPS:Authoritative Snapshot
   MOBA(Dota 2、League):Authoritative Snapshot
   现代 RTS(They Are Billions / Anno 系):多用 Authoritative Snapshot
```

## 14.3.3 Determinism 的硬约束(Lockstep)

Lockstep 要求**每个 client 在相同输入下产生 byte-byte 相同的状态**。任何不一致 → "desync"(玩家看到不同的世界,直接崩溃)。

困难来源:
- **浮点不确定性**:`a*b+c` vs `fma(a,b,c)` 不同(IEEE 754 但实现差异)
- **SIMD 路径**:SSE / AVX / NEON 在不同 CPU 不同
- **编译器**:相同代码不同编译器 / 优化级别可能不一致
- **库**:`std::sin` 不保证跨平台一致
- **OS / 时钟**:用 wall clock 直接 desync

**RTS 想用 Lockstep**,代码必须:
- 用 fixed-point 数学(`int32_t` 模拟 float)
- 不用 SIMD(或写自己的 deterministic SIMD)
- 不用 wall clock(用 lockstep tick 计数器)
- 不用线程(单线程,`ParallelFor` 也禁)
- 不用 `std::sort`(用确定性排序)
- 测试矩阵:Win + Linux + Mac 跨平台模拟

**这是巨大的工程成本**,5 年项目 → 整本"determinism 手册"。

## 14.3.4 Mass 与 Determinism 的冲突

Mass 默认走 SIMD-friendly + 多线程并行(§5.5)。这意味着 **Mass 不是 deterministic 的**:
- ParallelForEachEntityChunk 多 worker 跑,顺序不固定
- SIMD 操作浮点
- 内存分配顺序不固定

**Mass + Lockstep 几乎不兼容**(除非你重写 Mass 的并行调度,代价巨大)。

→ Mass-based RTS **必须**选 Authoritative Snapshot。

## 14.3.5 Authoritative Snapshot 的优化

```
[基础方案]
Server 模拟 → 每帧广播 50K 单位状态

[实战优化]
Server 模拟 → 每帧:
   1. 兴趣管理(每 client 只看 ~5K 可见 entity)
   2. 量化(位置 5 字节,朝向 1 字节)
   3. Delta encoding(仅变化字段)
   4. Dormancy(静止单位低频)
   5. Iris 推送模型
   
→ 每帧 ~75 KB / connection,可行
```

详细计算见 §14.1.8。

## 14.3.6 RTS 选型决策表

```
项目特征                       推荐模型
────────────────────────────────────────
单位数量 < 1000               传统 Replication(简单)
单位数量 1K - 10K             Replication Graph(中等)
单位数量 > 10K(50K 级)       Iris + Mass(大规模)

并行 / 多线程优化             Authoritative Snapshot(必须)
极低带宽(< 50 KB/s)         Lockstep(若能 determinism)
快速迭代 / 5.x 现代化         Authoritative Snapshot
经典 RTS 复刻(SC2 / WC3)    Lockstep(传统选择,但难)
```

---

## 14.3.7 混合方案(罕见)

```
Authoritative Snapshot + Client Prediction:
   - 主要走 Snapshot
   - 玩家自己单位的关键操作(移动 / 选择)本地预测
   - Server reconcile

但 RTS 本身延迟容忍度高(命令发出 → 几百 ms 后单位响应,玩家可接受),
通常不需要预测。
```
