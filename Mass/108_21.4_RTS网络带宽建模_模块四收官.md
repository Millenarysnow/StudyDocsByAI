## 21.4.1 完整建模

```
50K Mass entity + 10 client + Mass + Iris:

Server CPU:
   - Mass tick:               7-8 ms
   - Replication 处理:        1-2 ms(push to Iris)
   - Iris filter / serialize: 2-3 ms
   - 网络发包:                1 ms
   总:~ 12-15 ms / 帧 ✓
   
每 client 带宽:
   - Bubble 内 entity:       ~5K
   - 每帧 dirty:               ~5% = 250 entity
   - 每 dirty 量化:            5-10 字节
   - 总:~ 1.5-2.5 KB / 帧 = 90-150 KB/s ✓
   
内存:
   - 50K Mass entity × ~256 字节 = 12.8 MB(Mass 数据)
   - + 10 client × bubble metadata = 几 MB
   - 总:几十 MB(对比传统 Replicated Actor 几百 MB,优秀)
```

**完全可行**。

---

## 21.4.2 调谐手柄

```
带宽紧张?
   ↓
   - 减小 Bubble 半径 → 看到 entity 数减少
   - 增加量化(位置 5字节 → 3字节)
   - 降低 NetUpdateFrequency(10 Hz 改 5 Hz)
   - Tag entity dormancy(静止单位不复制)

CPU 紧张?
   ↓
   - 减少 ReplicationProcessor query 范围
   - 用 Tag 排除"远距 entity"(LOD-aware replication)
   - 调小 ReplicationGrid cell size
```
