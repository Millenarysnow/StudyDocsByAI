## 17.3.1 Archetype 是什么

> **同 fragment 组合的 entity 群组**。

```
Archetype A: [FPositionFragment, FVelocityFragment, FActiveTag]
   ├─ Entity 0
   ├─ Entity 1
   ├─ Entity 2
   ...

Archetype B: [FPositionFragment, FVelocityFragment, FHealthFragment, FActiveTag]
   ├─ Entity 5
   ├─ Entity 6
   ...

Archetype C: [FPositionFragment, FActiveTag, FFrozenTag]   ← 冻结状态的 entity
   ...
```

**每独特组合 → 一个 archetype**。同组合 entity 共享内存布局,SoA 排布。

---

## 17.3.2 为什么 Archetype 化

```
传统 ECS(Sparse Set):
   Position 数组 + Velocity 数组 + ...
   Entity 5 在 Position 数组的某 index,Velocity 数组的另一 index
   join 多 component:每 entity 散落访问

Archetype ECS:
   同组合 entity 数据**紧密在一起**(SoA in chunk)
   Processor 扫一个 archetype = 顺序访问 cache friendly
```

→ Archetype 模型 cache 友好,SIMD 友好。

---

## 17.3.3 Archetype 创建时机

```cpp
// 第一次出现新 fragment 组合时,EM 自动创建新 archetype
FMassEntityHandle E1 = EM.CreateEntity({ FPosition, FVelocity });
   // → Archetype A 创建(如果未存在),E1 加入

FMassEntityHandle E2 = EM.CreateEntity({ FPosition, FVelocity });
   // → 复用 Archetype A,E2 加入

FMassEntityHandle E3 = EM.CreateEntity({ FPosition, FVelocity, FHealth });
   // → 新 Archetype B 创建,E3 加入
```

Archetype 由 fragment / tag 类型组合**唯一标识**(`uint32 ArchetypeHash`)。

---

## 17.3.4 Archetype 迁移(Add/Remove Fragment)

```cpp
EM.AddFragment<FHealth>(E1);
   // E1 原本在 Archetype A,新组合 = A + FHealth = Archetype B
   // E1 数据从 Archetype A 的 chunk 拷到 Archetype B 的 chunk
   // E1 在 Archetype A 移除
```

**迁移成本**:几微秒(拷贝所有 fragment + chunk 整理)。

**纪律**:hot path 内**避免** add/remove fragment。批量做 / 在 Tag 切换状态(Tag 添加移除虽然也算迁移,但因 Tag 是 0 字节,迁移略快)。

## 17.3.5 FMassArchetypeData 字段(简化)

```cpp
struct FMassArchetypeData
{
    // 这个 archetype 的"组合描述"
    FMassFragmentBitSet FragmentBitSet;
    FMassTagBitSet TagBitSet;
    FMassChunkFragmentBitSet ChunkFragmentBitSet;
    FMassSharedFragmentBitSet SharedFragmentBitSet;
    
    // 每 fragment 类型在 chunk 内的偏移(SoA 布局)
    TArray<FMassArchetypeFragmentConfig> FragmentConfigs;
    
    // 此 archetype 的 chunk 链
    TArray<FMassArchetypeChunk> Chunks;
    
    // 当前 entity 数
    int32 NumEntities;
    
    // chunk 容量(看 fragment 总大小)
    int32 EntityCountPerChunk;
    
    // ...
};
```

## 17.3.6 计算 EntityCountPerChunk

```cpp
// 简化伪代码
int32 ComputeEntityCountPerChunk(...)
{
    int32 SumOfFragmentSizes = 0;
    for (FragmentType : Fragments)
        SumOfFragmentSizes += FragmentType->GetStructureSize();
    
    // chunk 默认 128KB
    return ChunkAllocSize / SumOfFragmentSizes;
}
```

例:

```
Fragment 总和 = 32 + 16 + 4 + 8 = 60 字节 / entity
Chunk 容量 = 128KB / 60 = 2184 entity / chunk
```

50K entity / 2184 = ~23 chunks.

## 17.3.7 RTS 的 Archetype 估算

```
RTS 单位类型:
   Soldier:Position + Velocity + Health + AttackPower + Active   = 1 archetype
   Worker:Position + Velocity + Health + Carry                    = 1 archetype  
   Projectile:Position + Velocity + Damage + Lifetime              = 1 archetype
   ResourceNode:Position + ResourceAmount                          = 1 archetype
   ...

每 entity 状态变化(死了 / 中毒)→ 加 Tag → 新 archetype
   Soldier + FDeadTag                  → 新 archetype
   Soldier + FBurningTag               → 新 archetype
   Soldier + FBurningTag + FFrozenTag  → 新 archetype
```

理论 archetype 数 = 2^状态数 × 单位类型数。**RTS 通常 30-100 个 archetype**(实际命中的组合数远少于全排列)。
