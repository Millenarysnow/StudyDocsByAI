## 8.4.1 浅入:World Tick 的工作清单

`World->Tick(LEVELTICK_All, DeltaTime)` 内部:

```
1. OnWorldTickStart 委托广播
2. 网络:接收包 → BroadcastTickDispatch
3. 时间更新 RealTimeSeconds
4. AsyncPhysicsBegin
5. 各 TickGroup 依次执行:
   ├─ TG_PrePhysics
   ├─ TG_StartPhysics
   ├─ TG_DuringPhysics(物理并行执行)
   ├─ TG_EndPhysics
   ├─ TG_PostPhysics
   └─ TG_PostUpdateWork
6. NewlySpawned 重跑(处理新 spawn 的 actor 在本帧内 tick)
7. 网络复制:ServerReplicateActors
8. UpdateLevelStreaming(Streaming 状态机)
9. World Subsystem 遍历(一些 subsystem hook)
10. OnWorldTickEnd 委托
```

## 8.4.2 主入口

`Engine/Source/Runtime/Engine/Private/LevelTick.cpp:1477`:

```cpp
void UWorld::Tick(ELevelTick TickType, float DeltaSeconds)
{
    SCOPE_TIME_GUARD(TEXT("UWorld::Tick"));
    
    if (GIntraFrameDebuggingGameThread) return;
    
    FWorldDelegates::OnWorldTickStart.Broadcast(this, TickType, DeltaSeconds);
    
    // 网络接收
    BroadcastTickDispatch(DeltaSeconds);
    
    // 物理 + tick groups
    SetupPhysicsTickFunctions(DeltaSeconds);
    
    for (int32 Group = 0; Group < TG_NewlySpawned; ++Group)
    {
        ETickingGroup CurrentGroup = (ETickingGroup)Group;
        TickTaskManagerInterface.RunTickGroup(CurrentGroup);
    }
    
    // 重跑 NewlySpawned
    while (HasNewlySpawnedActors())
    {
        TickTaskManagerInterface.RunTickGroup(TG_NewlySpawned);
    }
    
    // 网络复制
    ServerReplicateActors(DeltaSeconds);
    
    // Streaming
    UpdateLevelStreaming();
    
    // ...
    FWorldDelegates::OnWorldTickEnd.Broadcast(this, TickType, DeltaSeconds);
}
```

实际代码 1500+ 行,涵盖大量 edge case。这里的简化保留主干。

## 8.4.4 TickGroup 顺序执行(详)

`TickTaskManager.cpp:1165`:

```cpp
void DispatchTickGroup(ENamedThreads::Type CurrentThread, ETickingGroup WorldTickGroup)
{
    // 1. 找出该 group 所有 TickFunction
    TArray<FTickFunction*> Functions = GetTickFunctionsForGroup(WorldTickGroup);
    
    // 2. 按 prerequisite DAG 排序
    TopologicalSort(Functions);
    
    // 3. 派发 task(可并行)
    for (FTickFunction* TF : Functions)
    {
        if (TF->bRunOnAnyThread)
        {
            // 派给 worker 池
            UE::Tasks::Launch(UE_SOURCE_LOCATION, [TF] { TF->ExecuteTick(...); });
        }
        else
        {
            // GameThread 上 inline 执行
            TF->ExecuteTick(...);
        }
    }
    
    // 4. 等本 group 所有 task 完成,再进下一 group
    WaitForGroup(WorldTickGroup);
}
```

**关键**:同 group 内的 TickFunction **可能并行**(取决于 `bRunOnAnyThread`)。**不同 group 串行**(group N 完成才启 group N+1)。

### 8.4.4.1 物理并行

`TG_StartPhysics` 提交物理任务给物理引擎线程。物理任务在 `TG_DuringPhysics` 期间**并行执行**。`TG_EndPhysics` 等物理完成。

```
GameThread:  TG_StartPhysics → TG_DuringPhysics → TG_EndPhysics → TG_PostPhysics
                                       │
                                       ↓ 同时
PhysicsThread:                  [物理模拟 4-6ms]
```

利用空闲 GameThread 跑 game logic 与物理并行。**但**物理结果到 `TG_EndPhysics` 才可用,之后才能用 `Actor::Velocity` 等物理状态。

## 8.4.5 `TG_NewlySpawned` —— 重跑机制

`tick group 6` 是 `TG_NewlySpawned`(`EngineBaseTypes.h:107`)。它是**特殊**的 group,不固定顺序,而是**反复执行**。

```cpp
do {
    int32 NumProcessedThisIteration = ProcessNewlySpawnedActors();
} while (NumProcessedThisIteration > 0);
```

逻辑:
1. 当前帧某个 Actor::Tick 内 SpawnActor 创建新 actor
2. 新 actor 也想这一帧 BeginPlay + Tick
3. NewlySpawned group 收集这些新 actor,**在本帧内**让它们 tick
4. 如果 NewlySpawned 内又 spawn 了新 actor,继续重跑

**潜在死循环**:Actor::Tick 内 SpawnActor 一个会 SpawnActor 的 actor → 无限。引擎有 max iteration 限制(几千)。

**实战影响**:RTS 战斗中"投射物 tick 时新生成爆炸 actor"是合法的,本帧内爆炸就 tick。

## 8.4.7 Streaming 更新

```cpp
UpdateLevelStreaming();
```

每帧检查 `StreamingLevels`:
- 哪些应该被加载 / 卸载
- 异步加载完成的 → 转 LoadedNotVisible

Streaming 是**异步**的,这一帧只触发,实际加载/卸载跨多帧。

## 8.4.8 World Tick 与 Mass 的接口

Mass Processor 通过 `UMassSimulationSubsystem` tick:

```cpp
class UMassSimulationSubsystem : public UTickableWorldSubsystem
{
    virtual void Tick(float DeltaTime) override
    {
        // 跑所有 Processor,按 ExecutionPhase 划分
        for (EMassProcessingPhase Phase : EnumerateAll())
        {
            FMassExecutionContext Ctx(EntityManager, DeltaTime);
            ExecutePhase(Phase, Ctx);
        }
    }
};
```

但 `UTickableWorldSubsystem::Tick` 默认在 `World->Tick` 末尾被调,**不**精确属于某 TickGroup。

实际 Mass 用更精细的方式:**注册 Mass 自己的 TickFunction 到具体 TickGroup**(`UMassProcessor::ExecutionPhase` 配置):

```cpp
EMassProcessingPhase::PrePhysics    → 注册 TickFunction 到 TG_PrePhysics
EMassProcessingPhase::DuringPhysics → TG_DuringPhysics
EMassProcessingPhase::PostPhysics   → TG_PostPhysics
EMassProcessingPhase::FrameEnd      → TG_PostUpdateWork
```

这样 Mass Processor 与 actor tick **同 TickGroup 协调执行**。详 §18.4。

## 8.4.9 World Tick 性能预算分布

典型 RTS Game,50K Mass entity + ~50 actor + 1 player:

```
World->Tick 总耗时 ~10 ms / 帧:
   - OnWorldTickStart 委托                          ~10 μs
   - 网络接收 + 分发                                 ~500 μs - 2 ms
   - TG_PrePhysics:                                  ~3-5 ms
     ├─ ~50 个 actor tick                           ~100 μs
     ├─ Mass PrePhysics Processors                  ~3-4 ms (并行)
     ├─ PlayerController tick                        ~100 μs
   - TG_StartPhysics → TG_DuringPhysics             ~1 ms (并行物理)
     │ Mass DuringPhysics Processors                 同时跑
   - TG_EndPhysics → TG_PostPhysics                 ~500 μs
   - TG_PostUpdateWork:                              ~1-2 ms
     ├─ Mass FrameEnd Processors                    ~1 ms (LOD / Repr)
     └─ 网络复制准备                                  ~500 μs
   - NewlySpawned 重跑                              ~100 μs
   - ServerReplicateActors                           ~1-2 ms
   - UpdateLevelStreaming                           ~50-200 μs
```

健康 RTS 应该 World Tick < 12 ms,留余量给渲染、UI、其它系统。

## 8.4.11 RTS / Mass 视角的关键纪律

### (1)Mass Subsystem TickFunction 占据"中心位置"

```
TG_PrePhysics:
   ├─ ~10 个 Player / Hero actor 的 Tick                ~50 μs
   ├─ Mass PrePhysics Processors(50K entity 并行)      ~3 ms
   └─ ...
```

少量 Actor + Mass 并行是常态。50K actor + Mass 是灾难。

### (2)Networking 阶段 Mass 自有处理

`ServerReplicateActors` 只复制 actor。Mass entity 用自己的复制机制(`UMassReplicationProcessor` + Iris,§14 / §21)。所以 50K Mass entity 不增加 ServerReplicateActors 耗时。

### (3)注意 NewlySpawned 重跑

Actor::Tick 内 SpawnActor 触发 NewlySpawned。如果你 RTS Hero::Tick 每帧 spawn 一个特效 actor(应该用 Niagara),NewlySpawned 会反复跑。**改用 Niagara emitter 或 Mass entity**。

### (4)World Tick 委托用法

```cpp
class URTSDebugSubsystem : public UWorldSubsystem
{
    virtual void OnWorldBeginPlay(UWorld& InWorld) override
    {
        FWorldDelegates::OnWorldTickStart.AddUObject(this, &ThisClass::OnTickStart);
    }
    
    void OnTickStart(UWorld* W, ELevelTick Type, float DT)
    {
        // 每帧 World Tick 开始时调
        // 适合 debug 监控
    }
};
```

`OnWorldTickStart` / `OnWorldTickEnd` 委托允许"在 World Tick 边界做事",不需要自己 actor。

## 8.4.12 实操与下一节预告

### 实操

```cpp
static FAutoConsoleCommand CmdTickProfile(TEXT("rts.TickProfile"),
    TEXT("Print tick statistics"),
    FConsoleCommandDelegate::CreateLambda([]()
    {
        UWorld* W = GWorld;
        TMap<ETickingGroup, int32> GroupCounts;
        
        for (TActorIterator<AActor> It(W); It; ++It)
        {
            if (It->PrimaryActorTick.IsTickFunctionRegistered())
            {
                GroupCounts.FindOrAdd(It->PrimaryActorTick.TickGroup)++;
            }
        }
        
        for (const auto& Pair : GroupCounts)
        {
            UE_LOG(LogTemp, Display, TEXT("TG %d: %d ticks"), 
                (int32)Pair.Key, Pair.Value);
        }
    }));
```

跑一次,看你 RTS 项目当前各 TickGroup 多少 tick。健康项目 PrePhysics 50-200 个,数千就要警惕。
