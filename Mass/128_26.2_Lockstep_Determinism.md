# §26.2 Lockstep + Determinism — 严格条件

> **本节地图**:模块五第 26 章第 2 节。Lockstep 是**少数项目**才选的方案 — 但若你坚持,本节给出落地纪律。
>
> **预备知识**:§14.3。

---

## 26.2.1 Mass + Lockstep 不兼容(再强调)

```
Lockstep 要求 byte-byte determinism

Mass 默认:
   - SIMD-friendly 浮点(不 deterministic across CPUs)
   - ParallelForEachEntityChunk(执行顺序不固定)
   - 多 worker 内存分配顺序不固定
   - std::sort 等(可能不稳定排序)
```

→ **Mass + Lockstep 几乎不可行**。除非完全重写 Mass 调度成 deterministic 单线程模式。

---

## 26.2.2 若坚持 Lockstep

```
1. 改 Mass 调度:
   - 全部单线程
   - 固定 chunk 顺序
   - 取消 ParallelForEach
   
2. 数学库:
   - 用 fixed-point(int32)替代 float
   - 重写所有数学函数
   
3. 编译器约束:
   - 锁定编译器版本 + 优化级别
   - 跨平台测试 byte-byte 一致

工程成本:1-2 年专项
```

---

## 26.2.3 Lockstep 的优势

```
✓ 极低带宽(只发命令,几 KB/s)
✓ 服务器轻
✓ 适合 P2P 模式
```

如果你 RTS 是经典风格(SC1 复刻)+ 带宽极敏感 → 考虑。
