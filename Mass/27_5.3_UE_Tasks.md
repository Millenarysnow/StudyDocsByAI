# §5.3 UE::Tasks — 5.0+ 的现代 Task API

> **本节地图**:模块一第 5 章第 3 节。§5.2 介绍 TaskGraph 并指出 5.x 的它已经是 `UE::Tasks` 的兼容层。这一节直接看 `UE::Tasks` —— 5.0+ 推荐的新 API。
>
> 设计哲学:**比 TaskGraph 简洁 + 更灵活**。
> - 用 lambda 直接 launch,不写 `TGraphTask<TTask>` 模板 boilerplate
> - 用 `FPipe` 替代 Named Threads(更细粒度的"串行域")
> - 返回值优雅(`TTask<T>::GetResult`)
> - 内置 `BusyWait`,等待时不浪费 worker
>
> **预备知识**:§5.2 TaskGraph 心智模型(任务依赖图)。
>
> **读完之后你能做到**:
> - 用 `UE::Tasks::Launch(...)` 启动任意异步工作
> - 用 `FPipe` 实现"轻量串行域"(替代 Named Thread)
> - 用 `FTaskEvent` 实现手动 trigger 同步
> - 看到 5.x 新代码里 `UE::Tasks::*` 调用知道在干啥

## 5.3.1 浅入:`UE::Tasks::Launch` 一行启动 task

```cpp
#include "Tasks/Task.h"

using namespace UE::Tasks;

// 启动一个异步 task,返回一个 handle
TTask<int32> Task = Launch(UE_SOURCE_LOCATION, []() -> int32 {
    return ComputeSomething();
});

// 后续:阻塞获取结果
int32 Result = Task.GetResult();
```

**对比 TaskGraph**:

```cpp
// TaskGraph 老式
class FMyTask
{
    int32 Result;
public:
    void DoTask(...) { Result = ComputeSomething(); }
    static ENamedThreads::Type GetDesiredThread() { return ENamedThreads::AnyThread; }
    static ESubsequentsMode::Type GetSubsequentsMode() { return ESubsequentsMode::TrackSubsequents; }
    FORCEINLINE TStatId GetStatId() const { RETURN_QUICK_DECLARE_CYCLE_STAT(...); }
};

FGraphEventRef E = TGraphTask<FMyTask>::CreateTask().ConstructAndDispatchWhenReady();
E->Wait();
int32 Result = ...;     // 还要从 task 对象拿
```

**几行 vs 一行**。Lambda + 模板返回值推导让 UE::Tasks 写起来像 std::async。

## 5.3.2 完整 API:`Launch`

`Engine/Source/Runtime/Core/Public/Tasks/Task.h:266`:

```cpp
template<typename TaskBodyType>
TTask<TInvokeResult_T<TaskBodyType>> Launch(
    const TCHAR* DebugName,
    TaskBodyType&& TaskBody,
    ETaskPriority Priority = ETaskPriority::Normal,
    EExtendedTaskPriority ExtendedPriority = EExtendedTaskPriority::None,
    ETaskFlags Flags = ETaskFlags::None);
```

参数:
- `DebugName` —— Insights / debugger 里看到的名字。`UE_SOURCE_LOCATION` 是个宏,展开为 "file:line"
- `TaskBody` —— lambda / functor / 函数指针,**任何 callable**
- `Priority` —— 见下
- `ExtendedPriority` —— 进阶,通常默认
- `Flags` —— 进阶

返回 `TTask<R>`,`R` 自动从 `TaskBody` 返回类型推导。

### 5.3.2.1 `ETaskPriority`

```cpp
enum class ETaskPriority : int8
{
    High,
    Normal,
    Default = Normal,
    BackgroundHigh,
    BackgroundNormal,
    BackgroundLow,
    Count,
};
```

`Background*` 是后台优先级(类似 `ENamedThreads::BackgroundThreadPriority`),低优先 worker 跑。

### 5.3.2.2 `ETaskFlags`

```cpp
enum class ETaskFlags : int8
{
    None = 0,
    DoNotRunInsideBusyWait = 1 << 0,    // BusyWait 期间不跑这个 task
};
```

99% 不需要。`DoNotRunInsideBusyWait` 给"我的 task 必须在指定线程跑,即使别人 BusyWait"用。

## 5.3.3 等待:`Wait` / `BusyWait` / `GetResult`

### 5.3.3.1 `Wait` —— 阻塞等待

```cpp
TTask<void> T = Launch(UE_SOURCE_LOCATION, []{ DoStuff(); });
T.Wait();           // 阻塞,直到 task 完成
```

`Wait` 内部调度器**不浪费 worker**:如果当前线程是 worker,它会去帮其它任务,直到本任务完成。这比 `FRunnable + WaitForCompletion` 高效得多。

### 5.3.3.2 `BusyWait` —— 等待时跑别的 task

```cpp
T.BusyWait();           // 等期间,继续从 worker 池拿别的 task 跑
```

`BusyWait` 比 `Wait` 更激进:即使本线程不是 worker(比如 GameThread),也帮忙跑 task。**风险**:可能跑你不期望的 task,改 GameThread-only 状态。

实战:GameThread 上等"不是必须 GameThread 跑的 task"用 `BusyWait` 比 `Wait` 好(GameThread 不浪费)。

### 5.3.3.3 `GetResult` —— 等 + 取结果(`TTask<T>` 专用)

```cpp
TTask<int32> T = Launch(UE_SOURCE_LOCATION, []() -> int32 { return 42; });
int32 R = T.GetResult();    // 内部调 Wait,然后返回 42
```

`Task.h:196`:

```cpp
ResultType& GetResult()
{
    check(IsValid());
    FTaskHandle::Wait();
    return static_cast<Private::TTaskWithResult<ResultType>*>(Pimpl.GetReference())->GetResult();
}
```

返回**引用**,所以你可以连续读、修改:

```cpp
TTask<TArray<int32>> T = Launch(UE_SOURCE_LOCATION, []() {
    return MakeBigArray();
});
TArray<int32>& Arr = T.GetResult();    // 取引用
Arr.Sort();                              // 在原地修改
```

## 5.3.4 依赖图:Prerequisites

`Launch` 还有重载支持依赖:

```cpp
// Task.h:289 第二个重载
template<typename TaskBodyType, typename PrerequisitesCollectionType>
TTask<TInvokeResult_T<TaskBodyType>> Launch(
    const TCHAR* DebugName,
    TaskBodyType&& TaskBody,
    PrerequisitesCollectionType&& Prerequisites,
    ETaskPriority Priority = ETaskPriority::Normal,
    /* ... */);
```

用法:

```cpp
TTask<int32> A = Launch(UE_SOURCE_LOCATION, []{ return ComputeA(); });
TTask<int32> B = Launch(UE_SOURCE_LOCATION, []{ return ComputeB(); });

// C 等 A 和 B
TTask<int32> C = Launch(UE_SOURCE_LOCATION,
    [&]() {
        return A.GetResult() + B.GetResult();
    },
    Prerequisites(A, B)
);
```

或显式 `TArray<TTask<...>>`:

```cpp
TArray<TTask<int32>> Tasks;
Tasks.Add(A);
Tasks.Add(B);

TTask<int32> C = Launch(UE_SOURCE_LOCATION, []{ return 0; }, Tasks);
```

`Prerequisites(...)` 是个 helper(`Tasks/TaskPrivate.h`),把可变数量的 task 打包成 collection。

### 5.3.4.1 `Wait(Prerequisites)` 等多个

```cpp
Wait(MakeArrayView({ A, B, C }));      // 等 A、B、C 都完成
```

或 `BusyWait`。

## 5.3.5 `FPipe` —— 替代 Named Threads 的"串行域"

`Engine/Source/Runtime/Core/Public/Tasks/Pipe.h:28`:

```cpp
class FPipe
{
public:
    explicit FPipe(const TCHAR* InDebugName);
    ~FPipe();
    
    bool HasWork() const;
    bool WaitUntilEmpty(FTimespan Timeout = FTimespan::MaxValue());
    
    template<typename TaskBodyType>
    TTask<TInvokeResult_T<TaskBodyType>> Launch(
        const TCHAR* InDebugName,
        TaskBodyType&& TaskBody,
        ETaskPriority Priority = ETaskPriority::Default,
        /* ... */);
    
    // 还有带 Prerequisites 重载
};
```

注释(line 20-23):

> "A chain of tasks that are executed one after another. Can be used to synchronise access to a shared resource as FPipe guarantees non-concurrent tasks execution. FPipe is a replacement for named threads because it's lightweight and flexible — there can be a large dynamic number of pipes each controlling its own shared resource."

**核心**:一个 `FPipe` 内的 task **保证不并发**(顺序执行),但不绑定到特定 OS 线程(任何 worker 都能跑 pipe 里的 task,只要保证一次只跑一个)。

### 5.3.5.1 经典用例:替代 Named Threads

如果你有一个"需要保护的共享资源"(典型:日志文件、网络发送队列、单一渲染上下文),老式做法:
- 起一个 `FRunnableThread` 专门跑它
- 或用 `ENamedThreads::SomeNamedThread`

新式做法:

```cpp
class URTSLogger : public UWorldSubsystem
{
    UE::Tasks::FPipe LogPipe{ UE_SOURCE_LOCATION };
    FString CurrentLog;

public:
    void LogAsync(FString Msg)
    {
        // 这个 task 进 LogPipe,保证与其它 LogAsync task 串行
        LogPipe.Launch(UE_SOURCE_LOCATION, [this, M = MoveTemp(Msg)]() {
            CurrentLog += M;
            CurrentLog += TEXT("\n");
            // 写文件等
        });
    }
};
```

**优势**:
- 不占用 OS 线程(idle 时 worker 跑别的)
- 多个 Pipe 可共存(每个保护各自的资源)
- 自动调度优先级

### 5.3.5.2 与 Named Threads 对比

| 维度 | Named Thread | FPipe |
|---|---|---|
| 绑定 OS 线程 | ✓ 一对一 | ✗(任何 worker 都能跑) |
| 任务串行 | ✓(单线程自然) | ✓(Pipe 保证) |
| 资源占用 | 一个完整线程(MB 级 stack) | 仅 pipe 元数据 |
| 数量 | 引擎内只有几个 named thread | 可有数千 pipe |
| 动态创建 | ✗ | ✓ |
| 适合 | GameThread / RenderThread / RHIThread | 局部串行域、对象级保护 |

**新代码的纪律**:**"一个共享资源" → 给它一个 `FPipe`**。不要起新 named thread。

### 5.3.5.3 `WaitUntilEmpty` —— 析构前清理

```cpp
~URTSLogger()
{
    LogPipe.WaitUntilEmpty();   // 必须等所有 task 完成,才能销毁 pipe
}
```

否则 `~FPipe()` 内部 `check(!HasWork())` 会触发(line 42)。

## 5.3.6 `FTaskEvent` —— 手动 trigger 的同步

`Task.h:235`:

```cpp
class FTaskEvent : public Private::FTaskHandle
{
public:
    explicit FTaskEvent(const TCHAR* DebugName);
    
    template<typename PrerequisitesType>
    void AddPrerequisites(const PrerequisitesType& Prerequisites);
    
    void Trigger();
};
```

类似 §5.2.5 的 TaskGraph `FGraphEvent`。**事件可作 prerequisite 给其它 task,然后手动 Trigger 才解除**。

```cpp
FTaskEvent Event{ TEXT("MyEvent") };

// 一个等事件的 task
TTask<void> Later = Launch(UE_SOURCE_LOCATION,
    []{ DoLater(); },
    Prerequisites(Event));

// Later 不会跑,直到:
Event.Trigger();    // 这一刻 Later 进就绪队列
```

实战:多个 worker 等同一外部信号(异步 IO 完成、网络包到达)。

## 5.3.7 嵌套任务

```cpp
TTask<void> Outer = Launch(UE_SOURCE_LOCATION, [&]() {
    // 在 task body 内启动子 task
    TTask<int32> Inner = Launch(UE_SOURCE_LOCATION, []() -> int32 {
        return ComputeInner();
    });
    
    // Outer 不会算"完成",直到 Inner 也完成
    AddNested(Inner);    // 等价于 TaskGraph 的 DontCompleteUntil
});
```

5.x UE::Tasks 提供 `AddNested` API(在 task body 内可调)。这样依赖图可动态扩展。

## 5.3.8 完整示例:RTS 雾战异步更新

```cpp
class URTSFogOfWarSubsystem : public UWorldSubsystem
{
    UE::Tasks::TTask<void> CurrentFogTask;
    TArray<uint8> VisibilityMatrix;
    
public:
    void Tick(float DeltaTime)
    {
        // 上一帧的雾战还没完?跳过这帧(简单策略)
        if (CurrentFogTask.IsValid() && !CurrentFogTask.IsCompleted())
        {
            return;
        }
        
        // 启动新雾战 task
        CurrentFogTask = UE::Tasks::Launch(UE_SOURCE_LOCATION, [this]() {
            FMemory::SetupTLSCachesOnCurrentThread();   // worker 可能新启动,确保 TLS
            
            UpdateVisibilityMatrix(VisibilityMatrix);   // 重计算,可能几毫秒
        }, UE::Tasks::ETaskPriority::BackgroundNormal);
    }
    
    virtual void Deinitialize() override
    {
        if (CurrentFogTask.IsValid())
        {
            CurrentFogTask.Wait();
        }
    }
};
```

注意:
- Subsystem `Deinitialize` 时**等** task 完成,否则 task 会访问已销毁的 `this`
- `BackgroundNormal` 优先级让它不抢 GameThread / Mass tick

## 5.3.9 与 TaskGraph 的互通

**TaskGraph `FGraphEventRef` 可作 UE::Tasks 的 prerequisite**(因为底层 TaskGraph 已经是 UE::Tasks 子集)。反之亦然。

```cpp
// TaskGraph 启动
FGraphEventRef GraphTask = FFunctionGraphTask::CreateAndDispatchWhenReady([] { /* ... */ });

// UE::Tasks 等它
TTask<void> NewTask = Launch(UE_SOURCE_LOCATION, []{}, Prerequisites(GraphTask));
```

5.x 让两套接口能**自由组合**,迁移期不破坏旧代码。

## 5.3.10 RTS / Mass 视角下的纪律

### (1)新代码默认 UE::Tasks

任何 RTS 项目新写的并发代码,优先 `UE::Tasks::Launch` / `FPipe`。**只**在改引擎现有 TaskGraph 代码时用 `TGraphTask`。

### (2)对象级串行用 FPipe

每个需要"我自己内部串行"的 Subsystem / Manager,给一个 FPipe 成员变量:

```cpp
class URTSCommandSubsystem : public UWorldSubsystem
{
    UE::Tasks::FPipe CommandPipe{ UE_SOURCE_LOCATION };
    TArray<FRTSCommand> CommandQueue;

public:
    void EnqueueCommand(FRTSCommand Cmd)
    {
        CommandPipe.Launch(UE_SOURCE_LOCATION, [this, C = MoveTemp(Cmd)]() {
            // 安全:所有 EnqueueCommand 的 task 串行执行
            CommandQueue.Add(C);
        });
    }
};
```

替代过去用 `FCriticalSection` + Lock 的写法。

### (3)`BusyWait` 在 GameThread 优于 `Wait`

```cpp
// GameThread 上
TTask<void> T = Launch(UE_SOURCE_LOCATION, [] { DoLongStuff(); });
T.BusyWait();    // 等期间帮 worker 跑别的 task,GameThread 不空转
```

### (4)Mass Processor 用 ParallelFor,但底层是 UE::Tasks

```cpp
ParallelForEachEntityChunk(EntityManager, Context, [](auto& Frag) { /* ... */ });
// 底层启动多个 UE::Tasks::Launch,worker 跑 chunk
```

你**不**直接调 `UE::Tasks::Launch`,但理解它能让你**调试 Mass 性能**时知道在看什么。

## 5.3.12 实操提示与下一节预告

### 实操提示

- **DebugName 写有意义**:Insights 的 task 时间线显示这个名字,起得有信息量(`"FogUpdate"` 而不是 `"Task1"`)
- **Lambda 闭包注意生命周期**:`[this]` 要确保 `this` 在 task 完成前不被销毁。**Subsystem Deinitialize 必须等 task 完成**
- **不要在 task 内 `co_await`**:UE::Tasks 不是 coroutine,task body 必须同步完成
