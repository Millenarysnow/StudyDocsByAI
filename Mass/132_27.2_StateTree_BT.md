# §27.2 StateTree 替代 Behavior Tree

> **本节地图**:模块五第 27 章第 2 节。Mass 单位的 AI 决策器选 StateTree。
>
> **预备知识**:§20.5 StateTree 集成。

---

## 27.2.1 BehaviorTree vs StateTree

```
BehaviorTree(经典):
   - 树形,每帧从根遍历
   - Service / Decorator / Task 类层级
   - 适合复杂 NPC AI,不适合 50K
   - 每个 Pawn 一个 BTComponent,UObject 开销
   
StateTree(5.x 新):
   - 状态 + Transition 表达
   - 数据驱动(可不依附 UObject)
   - Mass 友好(每 entity 一个状态 token)
   - 适合大规模
```

---

## 27.2.2 StateTree + Mass

```
class UMassStateTreeProcessor : public UMassProcessor
{
    Query.RequireFragment<FMassStateTreeInstanceFragment>();
    Query.RequireFragment<FMassStateTreeContextFragment>();
    
    Execute(...)
    {
        for entity in chunk:
            StateTree.Tick(Context);   // 推进状态机
    }
};
```

每 entity 持 `FMassStateTreeInstanceFragment` 16-32 字节。50K × 32 = 1.6 MB,可接受。

---

## 27.2.3 RTS 单位 StateTree 示例

```
[Idle]
   ├─ 收到 Move 命令 → [Move]
   ├─ 检测到敌人 → [Combat]
   └─ Bored → [Wander]

[Move]
   ├─ 到达终点 → [Idle]
   └─ 检测到敌人 → [Combat]

[Combat]
   ├─ 敌人死 → [Idle]
   ├─ 自己 Health < 30% → [Flee]
   └─ Cooldown 完成 → 攻击

[Flee]
   └─ 到达安全区 → [Idle]
```

每状态对应一组 Mass Tag(`FUnitIdleTag` / `FUnitMovingTag` 等),Processor 只处理对应 Tag 的 entity。

---

## 27.2.4 性能

```
StateTree tick:
   - 每 entity 几百 ns(简单状态)
   - 50K × 几百 ns = ~30 ms / 帧 ❌ 还是太慢

优化:
   - 不每帧 tick,改"事件驱动"(收到命令 / 触发条件 才推进)
   - LOD-aware:远距 entity 降频
   - 50K × 0.5(只 50% 每帧 tick) × 几百 ns = ~10 ms ✓
```
