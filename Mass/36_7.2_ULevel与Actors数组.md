## 7.2.1 浅入:Level 是 Actor 的容器

```
UWorld
   ├─ PersistentLevel: ULevel*       (主关卡)
   │     ├─ Actors: TArray<AActor*>  (该关卡所有 Actor)
   │     └─ Brush / Static Geometry / Lighting
   │
   ├─ Levels: TArray<ULevel*>        (PersistentLevel + 已 stream-in 的子关卡)
   │
   └─ StreamingLevels: TArray<ULevelStreaming*> (配置:可加载的子关卡)
```

实战:小关卡 World = 1 个 PersistentLevel,大关卡 World = 1 PersistentLevel + N 个 streaming sub-level。

---

## 7.2.2 `ULevel::Actors` —— 核心数组

`Engine/Source/Runtime/Engine/Classes/Engine/Level.h:432`:

```cpp
class ULevel : public UObject, public IInterface_AssetUserData, ...
{
public:
    TArray<TObjectPtr<AActor>> Actors;       // 主 Actor 数组
    TArray<TObjectPtr<AActor>> ActorsForGC;  // GC 用的 Actor 引用
    // ...
};
```

### 7.2.2.1 `Actors` 数组的用途

- 关卡序列化时遍历这个数组保存所有 Actor
- 关卡加载时反序列化填充这个数组
- World->BeginPlay 遍历这个数组调 BeginPlay
- Streaming Level 卸载时遍历这个数组销毁 Actor

### 7.2.2.2 `ActorsForGC`

GC 引用收集**专用**数组,通常与 Actors 内容一致。某些情况下(Actor 已 destroy 但还在 actors 里)它们会有差异,GC 用 ActorsForGC 防止漏标记。

### 7.2.2.3 `SpawnActor` 时的添加

```cpp
// 简化伪代码:UWorld::SpawnActor
AActor* SpawnedActor = NewObject<AActor>(...);
SpawnedActor->PostSpawnInitialize(...);

// 加到 Level 的 Actors 数组
Level->Actors.Add(SpawnedActor);
Level->ActorsForGC.Add(SpawnedActor);
```

新 spawn 的 Actor 默认进 `PersistentLevel`。可以指定 `SpawnParams.OverrideLevel` 把 Actor 放到子关卡。

### 7.2.2.4 `Destroy` 时的移除

```cpp
// 简化:AActor::Destroy
Level->Actors.Remove(this);   // O(N) — Actors 数组是无序的
// MarkAsGarbage,GC 之后真销毁
```

注意 `Remove` 是 O(N)。**大量 spawn/despawn**(数万 Actor)会让这一行卡。**Mass entity 不进 Actors 数组**,这就是它快的根因之一。

### 7.2.2.5 遍历 Actors

```cpp
// 标准
for (AActor* Actor : World->PersistentLevel->Actors)
{
    if (Actor && IsValid(Actor))    // 过滤 nullptr 和 garbage
    {
        // ...
    }
}

// 用 TActorIterator(更安全,跨所有 Levels)
for (TActorIterator<AHero> It(World); It; ++It)
{
    AHero* H = *It;
    // ...
}
```

`TActorIterator<T>` 是模板,自动过滤类型 + 跨 streaming level + 排除 garbage,**强烈推荐**。

## 7.2.3 关卡加载状态机

`ELevelStreamingState`(LevelStreaming.h:110):

```cpp
enum class ELevelStreamingState : uint8
{
    Removed,           // 完全移除(从 World->StreamingLevels 中除去)
    Unloaded,          // 注册了但未加载到内存
    FailedToLoad,      // 加载失败
    Loading,           // 异步加载中
    LoadedNotVisible,  // 已加载,但 actors 不可见(不参与 tick / 渲染)
    MakingVisible,     // 正从加载中过渡到可见
    LoadedVisible,     // ★ 完全活跃(可见 + tick + 渲染)
    MakingInvisible    // 正从可见过渡到不可见
};
```

### 7.2.3.1 状态转换图

```
   ┌──────────┐
   │ Unloaded │ ◀─────┐
   └────┬─────┘       │
        │ Load        │
        ↓             │
   ┌──────────┐       │
   │ Loading  │       │
   └────┬─────┘       │
        ↓             │
   ┌──────────────────┴──┐
   │ LoadedNotVisible    │ ◀────┐
   └──┬──────────────────┘      │
      │ MakeVisible              │ MakeInvisible
      ↓                          │
   ┌──────────────────┐          │
   │ MakingVisible    │          │
   └────┬─────────────┘          │
        ↓                         │
   ┌──────────────────┐           │
   │ LoadedVisible    │ ─────────┘
   └──────────────────┘
```

**异步过渡**(`Loading` / `MakingVisible`)可能跨多帧。这就是"开关卡时部分 actor 还没出现" 的状态。

### 7.2.3.2 `ULevelStreaming` 配置

```cpp
class ULevelStreaming : public UObject
{
    bool bShouldBeLoaded;        // 应该加载吗?
    bool bShouldBeVisible;       // 应该可见吗?
    
    FName WorldAssetPackageFName;   // 子关卡资产路径
    
    ELevelStreamingState GetCurrentState() const;
    
    // 委托
    FLevelStreamingVisibilityStatus OnLevelShown;
    FLevelStreamingVisibilityStatus OnLevelHidden;
};
```

### 7.2.3.3 触发加载

```cpp
// 蓝图 / C++ 都可
UGameplayStatics::LoadStreamLevel(this, TEXT("MySublevel"), 
    /*MakeVisible*/ true, /*ShouldBlock*/ false, FLatentActionInfo{});

// 或直接操作 LevelStreaming
ULevelStreaming* LS = ...;
LS->SetShouldBeLoaded(true);
LS->SetShouldBeVisible(true);
```

`bShouldBlock = true` 阻塞 GameThread 直到加载完(卡帧,慎用)。`false` 异步加载(几帧到几秒)。

### 7.2.3.4 Streaming 的 actors 处理

**Loading**:Actor 反序列化到内存,但 ULevel 还没加进 World。
**LoadedNotVisible**:Actor 在 ULevel.Actors 里,但**不 tick,不渲染**。物理也禁用。
**MakingVisible** → **LoadedVisible**:逐 actor 调 BeginPlay,加进 tick 系统。

## 7.2.4 `World->Levels` —— 当前活跃关卡

```cpp
// World.h
TArray<TObjectPtr<ULevel>> Levels;
```

**`Levels` = PersistentLevel + 所有 LoadedVisible 的 streaming levels**。tick / 渲染遍历这个数组。

**`StreamingLevels` 是配置**(可能加载哪些),**`Levels` 是实际活跃**(已加载且可见)。两者数量通常不同。

## 7.2.5 `TActorIterator<T>` 跨 Level 遍历

```cpp
for (TActorIterator<AStaticMeshActor> It(World); It; ++It)
{
    AStaticMeshActor* SMA = *It;
    // 这里会遍历 PersistentLevel + 所有 LoadedVisible streaming level 里的 AStaticMeshActor
}
```

`TActorIterator` 内部:
1. 取 `World->Levels`(只活跃的)
2. 对每个 Level 的 Actors 数组遍历
3. 过滤 `IsA<T>` 类型
4. 过滤 `IsValid`(已 garbage 的跳过)

**99% 的"找特定类型 Actor"用 TActorIterator**,不要自己写双重 for 循环。

### 7.2.5.1 实战 RTS:找所有英雄

```cpp
TArray<AHero*> AllHeroes;
for (TActorIterator<AHero> It(GetWorld()); It; ++It)
{
    AllHeroes.Add(*It);
}
```

**性能**:O(总 Actor 数 × 类型检查)。10K Actor 大约几百微秒。**绝不**在 Mass Processor 内 hot path 调,启动期 / UI 操作时调 OK。

## 7.2.6 关卡保存与序列化

ULevel 是 `.umap` 资产的真正内容。资产保存时:

```cpp
// 简化
void ULevel::Serialize(FArchive& Ar)
{
    Super::Serialize(Ar);
    
    // 序列化 Actors 数组(及每个 Actor 的字段)
    Ar << Actors;
    
    // 序列化 ActorsForGC、其它元数据
    // ...
}
```

每个 Actor 的字段也是 delta-序列化(§3.4.6 与 archetype 不同的部分)。

**.umap 文件大小**主要看 Actor 数量 + 每个 Actor 字段量。RTS 项目把杂兵走 Mass(不 spawn 进 Level),关卡文件就小得多。

## 7.2.7 Editor 视图 vs Game 视图

### 7.2.7.1 Editor 模式

Editor World 加载关卡:
- 所有 Actor 在 Editor World 里
- 但**不 tick**(EWorldType::Editor)
- 你可以编辑、移动、添加 Actor

### 7.2.7.2 PIE / Game 模式

`PlayInEditor` 复制 Editor World → PIE World。PIE World 走完整 BeginPlay → tick。

切回 Editor 时 PIE World 销毁,Editor World 完整保留(用户的修改)。

## 7.2.8 RTS / Mass 视角下的 Level 关注

### (1)Mass entity 不进 ULevel.Actors

Mass entity 是 8 字节句柄,**不**是 AActor。ULevel.Actors 数组完全不知道 Mass entity 的存在。50K Mass entity = 0 个 Actor 增量。

这是为什么 Mass 关卡不"膨胀":Actor 多 → .umap 大 + Levels 加载慢 + tick 系统压力大。Mass 完全绕过这条路径。

### (2)RTS 主关卡 = 静态部分,动态单位走 Mass

```
RTS 关卡 .umap 包含:
   - 地形 (Landscape)
   - 静态建筑(StaticMeshActor)
   - 资源点 / 出生点(自定义 PointActor)
   - GameMode / GameState 类配置
   - Mass Spawner 配置(数据资产)
   
不包含:
   - 50K 杂兵(运行时 Mass spawn)
   - 投射物
   - 临时效果
```

### (3)Streaming 用于 RTS "战雾外的世界"

如果 RTS 是大型(海岛、大陆),用 streaming 把"远处区块"卸载:

```cpp
// 玩家位置变化时检测可见区块
ULevelStreaming* LS = UGameplayStatics::GetStreamingLevel(this, TEXT("Region_NE"));
LS->SetShouldBeLoaded(IsRegionVisible(NE));
LS->SetShouldBeVisible(IsRegionVisible(NE));
```

**5.x 推荐用 World Partition 替代手动 Streaming**(§7.3 详讲)。

### (4)Mass entity 跨 streaming level

Mass entity 默认**不与 streaming level 关联**。它们存在于 Mass Subsystem(World 级),streaming 关卡加载/卸载不影响 Mass entity。

如果你需要"卸载某区域时该区域的 Mass 单位也消失",自己写逻辑(查 entity 位置 / streaming volume)+ DestroyEntity。
