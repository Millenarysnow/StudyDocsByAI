## 24.4.1 16.6 ms 帧预算分配

```
RTS 60fps (16.6ms):

GameThread:
   - Heartbeat / Slate Input          0.5 ms
   - World->Tick 框架                  0.3 ms
   - Mass PrePhysics Processor         3 ms (50K entity 并行)
   - 物理 / Overlap                    1 ms
   - Mass DuringPhysics                1 ms (与物理并行)
   - Mass PostPhysics                  0.5 ms
   - PlayerController / Input          0.5 ms
   - UI / Slate Tick                   1 ms
   - Network 复制                      1.5 ms
   - GC / Stats / Log                  0.5 ms
   - Mass FrameEnd (LOD/Repr)          1 ms
   - Mass Replication push to Iris     1 ms
   - EndOfFrame                         0.5 ms
   ──────────────────────────────────
   Total                              ~12 ms ← 留 4 ms 余量

RenderThread(独立线程):
   - 渲染上一帧                        ~6 ms

RHIThread / GPU:
   - Submit + GPU draw                 ~6 ms

总帧时间(GameThread bottleneck):~12 ms ✓ 保持 60fps
```

## 24.4.2 关键性能预算

| 子系统 | 预算 | 实测 |
|---|---|---|
| Mass tick(50K entity) | < 7 ms | 6-8 ms ✓ |
| 物理 | < 2 ms | 1 ms(RTS 物理少)✓ |
| 网络复制 | < 2 ms | 1.5 ms(Mass + Iris)✓ |
| 渲染(GameThread 端) | < 3 ms | ~2 ms(ISMC 上传)✓ |
| GC 增量 | < 1 ms / 帧 | < 0.5 ms ✓ |

## 24.4.4 当 Mass tick 超预算时

```
诊断:
   1. Insights 看哪个 Processor 最慢
   2. ParallelForEachEntityChunk 是否 worker 平衡?
   3. Query 是否选对 entity(没有处理多余的 archetype)?
   
优化:
   - 加 LOD,远 entity 跳过
   - 增加 Processor 并行度
   - 减少 fragment 大小
   - 用 Tag 状态切换避免 hot path 分支
```
