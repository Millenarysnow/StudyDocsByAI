## 29.3.1 灰度发布

```
新版本上线 → 不能一次推全量:
   1. 内部测试(QA)
   2. 5% 灰度(指定地区)
   3. 25% 灰度
   4. 50% 灰度
   5. 100%

匹配服务做 version routing:
   client v1.0.0 → 旧 DS pool
   client v1.1.0 → 新 DS pool
   双版本共存 1-2 周,旧版本沉淀玩家迁移
```

---

## 29.3.2 配置热更

```
不重打包能改的内容:
   - GameplayAbility 数值(.json 下发,代码读 json)
   - 单位数值(JSON / DataTable)
   - UI 文案
   - 商店配置

热更架构:
   1. 配置存中心服务器(CDN)
   2. Client 启动时拉最新配置
   3. 配置版本号检查,过期重拉
   
URTSConfigSubsystem 拉配置 → 全局只读访问
```

---

## 29.3.3 Pak 热更(代码热更不行)

```
.pak 可以热更:
   - 启动时检查 server 上 manifest
   - 下载新 pak 到本地
   - mount 进虚拟文件系统
   - 旧 pak 替换

代码不能热更(无 Lua):
   - C++ 代码改了必须重打整个 client 包
   - 但资产 / 配置可以热更 → 减少强制更新频率

Lua / TypeScript 嵌入:
   - 一些公司加 Lua 层,只用 Lua 写"业务"
   - 代价:性能 + 调试复杂度增加
```

---

## 29.3.4 反作弊

```
RTS 客户端预测 → 玩家可能"自我加速":
   Server 必须保留 authoritative state
   Server 验证每个命令(单位 ID 是否归玩家、是否在合法范围)
   Server 驳回非法命令

防内存修改:
   - EAC / VAC / 自研反作弊
   - 加密关键数值(玩家本地货币、天赋)
   - 客户端只展示 server 数据,不存"权威值"
```
