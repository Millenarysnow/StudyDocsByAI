## 12.3.1 浅入:网络上"指针"怎么传

```cpp
USTRUCT()
struct FAttackEvent
{
    UPROPERTY()
    TObjectPtr<AActor> Attacker;     // 这个怎么传到 client?
    
    UPROPERTY()
    TObjectPtr<UMaterial> Effect;
};
```

Server 端 `Attacker = SomeActor`(64 位指针)。直接发指针给 client 没用 —— client 端这个地址完全是别的对象。

**解法**:NetGUID(`FNetworkGUID`,32 位整数)= 全局唯一对象 ID。

```
Server:
   Attacker = ptr_to_SomeActor
   序列化时:Attacker.NetGUID = 12345
   发出去
   
Client:
   接收 NetGUID = 12345
   在本地 PackageMap 查 12345 → ptr_to_本地的SomeActor
   赋给 Attacker
```

## 12.3.2 `UPackageMap` 的角色

```cpp
class UPackageMap : public UObject
{
public:
    // Server 写入 / Client 读取
    virtual bool SerializeObject(FArchive& Ar, UClass* InClass, UObject*& Obj, FNetworkGUID* OutNetGUID = nullptr);
    
    // 静态 GUID 注册
    virtual bool SerializeName(FArchive& Ar, FName& InName);
    
    // ...
};
```

`SerializeObject` 是核心:**把 UObject* 序列化为 NetGUID**(发送时)或**反序列化(NetGUID → UObject*)**(接收时)。

每个 NetConnection 持有一个 PackageMap,管理"这个 connection 已经知道哪些对象"。

## 12.3.3 Static GUID(资产)

资产(Mesh / Material / Class / DataAsset)的 GUID **由 path hash 计算**:

```
"/Game/Meshes/SwordMesh.SwordMesh" → hash 计算 → NetGUID 0x12345678
```

**Server 和 Client 都能算出相同 GUID**。第一次复制时 server 不需要发"完整 path",只发 GUID。client 用 GUID 反向找对应资产(或加载之)。

---

## 12.3.4 Dynamic GUID(运行时 spawn)

运行时 SpawnActor 的 actor:
- Server 给它分配新的 NetGUID(从计数器)
- 第一次复制时,server 通过 ControlChannel 发"GUID X 对应 ClassY,name Z"给 client
- Client 在本地 SpawnActor 创建对应 actor + 关联 GUID
- 之后引用该 actor 直接发 GUID

---

## 12.3.5 GUID 的 Ack 机制

Server 不知道 client "还没收到" GUID 映射,直到 client ack。所以 server 端会:
- Buffer 等待 ack 的 actor 字段
- 只在 ack 后才发引用 GUID
- 如果 ack 一直没来,可能 retransmit

实战:可能看到"actor spawn 后几帧才 visible 在 client"——就是 GUID ack 延迟。

## 12.3.6 RTS 视角:GUID 爆炸

50K replicated actor + 10K 资产 = 60K NetGUID。
GUID 表(server / client 各一份)+ ack 状态 = 几十 MB。
ack 处理 = ServerReplicateActors 中显著开销。

→ **Mass entity 不分配 NetGUID**,Mass 自己定义"entity index → 网络 ID" 映射(更紧凑)。详 §14。
