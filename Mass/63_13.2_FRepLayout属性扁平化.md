## 13.2.1 浅入:RepLayout 是 UClass 反射的"网络加速版"

```
UClass 反射数据(给所有用):
   PropertyLink: 所有 UPROPERTY 字段(链表)
   RefLink:     仅含 UObject 引用的字段(GC 用)

UClass 反射的"网络专用版":
   FRepLayout:   仅 Replicated 字段,扁平化成数组 + 类型化
```

每个 replicated UClass 在反射注册末尾生成一个 `FRepLayout`。Server `ServerReplicateActors` 用它快速:
- 比较 actor 当前状态 vs 上次发送状态
- 找出 dirty 字段
- 序列化到包

---

## 13.2.2 `FRepLayout` 结构

```cpp
class FRepLayout
{
public:
    // 每个 replicated 字段一个 entry
    TArray<FRepParentCmd> Parents;
    TArray<FRepLayoutCmd> Cmds;
    
    // 字段哈希(用于版本检测)
    uint32 RepLayoutLCG;
    
    // 接口
    void CompareProperties(...);   // server diff
    void SerializeProperties(...); // 序列化
    void ReceiveProperties(...);   // client 接收
};
```

### 13.2.2.1 FRepLayoutCmd

```cpp
struct FRepLayoutCmd
{
    int16 EndCmd;                  // 嵌套 struct 用
    uint16 Offset;                 // 字段在 actor 内字节偏移
    uint16 ElementSize;            // 字段大小
    uint16 RelativeHandle;
    ERepLayoutCmdType Type;        // Int / Bool / Object / Array / DynamicArray ...
    FProperty* Property;           // 反射指针
};
```

每个字段一个 Cmd。基础类型(int / float / bool)直接序列化。复合类型(struct / array)递归。

## 13.2.3 CmpAndCopy 算法

```cpp
// 简化伪代码
bool FRepLayout::CompareProperties(
    const void* ActorState,    // 当前 actor 内存
    const void* ShadowState)   // 上次发送的"影子状态"
{
    bool bChanged = false;
    
    for (FRepLayoutCmd& Cmd : Cmds)
    {
        const void* Cur = (uint8*)ActorState + Cmd.Offset;
        const void* Old = (uint8*)ShadowState + Cmd.Offset;
        
        if (Cmd.Property->Identical(Cur, Old))
        {
            // 没变,跳过
        }
        else
        {
            // 变了,记 dirty,拷新值到 ShadowState
            FMemory::Memcpy((void*)Old, Cur, Cmd.ElementSize);
            bChanged = true;
            // 加进 DirtyFields 列表
        }
    }
    
    return bChanged;
}
```

每个 actor 一份 ShadowState(per-connection,因为不同 client 看到的 dirty 集不同)。

### 13.2.3.1 性能

50 字段 × `Identical()` 比较 ≈ ~1 μs / actor。
50K actor × 10 connection = 500K × 1 μs = **500 ms / 帧**。

完全不可行。**RepLayout 在大规模 actor 下是性能杀手**。

→ Mass 不走这条路。Iris 的 push model 改成"actor 主动通知 dirty,不全扫"。

---

## 13.2.4 ShadowState 内存

```
每 connection × 每 actor × actor 字段大小 = 巨大
50K actor × 10 client × 平均 1KB 字段 = 500MB / server
```

ShadowState 内存爆炸。
