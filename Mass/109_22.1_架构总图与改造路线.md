## 22.1.1 五种 Mass 化深度

```
深度 1:全 Actor + 个别 Mass(轻度)
   - 90% 仍然 Actor / Component 体系
   - Mass 仅做"多发投射物"等高频小对象
   - 风险低,改动小
   - 上限:~1K 单位

深度 2:GameMode/Controller 保留,Pawn → Mass(中度)
   - Pawn 走 Mass entity
   - Player 仍然 PlayerController + 一个 CameraPawn
   - GameMode / GameState 不变
   - 上限:~5-10K 单位

深度 3:GameState 保留,PC 极简,单位全 Mass(标准)
   ✓ 推荐
   - 50K 单位走 Mass
   - PC 仅管输入与镜头
   - GameMode / GameState 不变(全局逻辑)
   - 上限:50K+ 单位

深度 4:自定义 GameInstanceSubsystem 接管 World(深度)
   - 自定义 World tick / Subsystem 主导
   - GameMode / GameState 几乎空壳
   - 上限:超大规模(几十万 entity)
   - 风险:需要重写很多框架代码

深度 5:自研 World 类型 + 自研 Tick 主循环(极端)
   - 几乎完全脱离 UE Gameplay 框架
   - 仅用 UE 渲染 + 网络底层
   - 风险:5 年项目级别
   - 收益:边际(深度 3-4 已够用)
```

---

## 22.1.2 选哪个?

**99% 的 RTS 项目选深度 3**。理由:

```
深度 3 的优势:
   ✓ Mass 处理大量同类 entity(性能可达 50K+)
   ✓ 保留 GameMode / GameState(玩家熟悉的胜负 / 复制机制)
   ✓ PC 仍存在(输入路由 / RPC / 本地玩家状态)
   ✓ 与 UE 网络体系完全兼容(GameMode 触发 Mass 网络)
   ✓ 与 UE Editor / BP 协作良好
   
代价:
   - 学习曲线(Mass 与 OOP 的范式切换)
   - 调试期工具偏弱(对比 GameplayDebugger)
   - Mass 内部 API 仍在迭代(5.x 5.4-5.7 有改动)
```

深度 1-2 → 不适合大规模 RTS,Mass 用得太浅,得不到性能收益
深度 4-5 → 收益边际,工程成本极高

## 22.1.3 改造路线建议(从 0 项目)

```
新项目 Phase 1(2 周):
   1. 项目骨架(§0.2):Module / Plugin 拆分
   2. 启用 Mass(§16.1)
   3. 一个最简 Soldier entity + Movement Processor
   4. 50 个 entity 跑起来,Insights 看性能

Phase 2(1 月):
   5. 完整 Trait 配置(§19)— Combat / AI / LOD / Representation
   6. 1000 entity + ISMC 渲染验证
   7. PC + CommandSubsystem 完整链路

Phase 3(2 月):
   8. Mass + Iris 网络复制(§21)
   9. PIE 多 client 测试

Phase 4(2 月):
   10. 50K entity 压力测试
   11. 渲染剥离(VAT)
   12. 调谐 LOD / Bubble

Phase 5(持续):
   13. AI 完善(StateTree / 寻路 / 编队)
   14. 关卡内容
   15. UI / 主菜单 / 上线工程化
```

## 22.1.4 改造路线建议(从已有 Actor 项目)

```
Phase 1(诊断):
   - stat unit / Insights 找瓶颈
   - 哪种 Actor 数量最多 / 最慢?

Phase 2(单类型 Mass 化):
   - 把数量最多的兵种(假设 Soldier)Mass 化
   - 保留其它 Actor 不动
   - 测试性能改善

Phase 3(扩张):
   - 逐类 Mass 化
   - 网络层切换 Iris

Phase 4(渲染剥离):
   - 旧 SkeletalMesh 改 VAT

Phase 5(收尾):
   - 删除遗留代码
   - 整理工程
```

每 Phase 之间**保持游戏可玩**。

## 22.1.5 团队协作建议

```
程序员任务:
   - Fragment / Tag / Trait C++ 实现
   - Processor 性能优化
   - 网络层集成
   - 渲染剥离

策划任务:
   - DA_*.uasset 配置(EntityConfig 资产)
   - Trait 参数调谐
   - StateTree 行为编辑

美术任务:
   - 单位模型 + VAT 烘焙
   - ISMC 优化
   - Niagara 特效

测试:
   - 单元测试(Mass 单 Processor)
   - 集成测试(50K spawn 不崩)
   - 网络测试(2-10 client)
   - 性能回归(每 build 跑基准)
```

策划改 Trait 资产 → 不需要程序员介入(策划友好性)。
