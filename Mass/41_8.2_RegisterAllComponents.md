# §8.2 RegisterAllComponents — Component 的"激活仪式"

> **本节地图**:模块二第 8 章第 2 节。§8.1 看到 SpawnActor 末尾调 `RegisterAllComponents`。这一步本身**比 NewObject 更重** — Component 要挂到渲染场景、物理引擎、Tick 系统。理解这条链让你**看清 RTS 中 actor 数量级的代价**。

## 8.2.1 浅入:Component 不"自动"工作

```cpp
UStaticMeshComponent* C = NewObject<UStaticMeshComponent>(this);
C->SetStaticMesh(SomeMesh);
// ❌ 此时 C 不渲染、不参与物理、不接受 Tick!
```

`NewObject<UActorComponent>` 只创建对象。要让它**实际工作**,必须:
1. **AttachToActor**(挂到 Actor 的 component 树)
2. **RegisterComponentWithWorld**(挂到 World 的渲染 / 物理 / Tick 系统)

`SpawnActor` 内部调用 `RegisterAllComponents` 完成全套激活。

---

## 8.2.2 Component 注册的三个时机

### 8.2.2.1 `OnComponentCreated`(Actor 内嵌或动态加挂)

`Engine/Source/Runtime/Engine/Classes/Components/ActorComponent.h:1314`:

```cpp
virtual void OnComponentCreated();
```

时机:
- Actor ctor 里 `CreateDefaultSubobject` 创建的 component → spawn 时 OnComponentCreated 被调
- 运行时 `NewObject<UMyComponent>` + `AttachToComponent` 添加的 → 调用 RegisterComponent 时

实战:**初始化 component 内部状态**(分配 buffer、计算 cache 字段)。**不**应该访问 World(可能还没 attach 到 World)。

### 8.2.2.2 `OnRegister`(Component 挂到 World 后)

`ActorComponent.h:816`:

```cpp
virtual void OnRegister();
```

时机:`RegisterComponentWithWorld` 内部调。**此时 GetWorld() 可用**。

实战:
- 渲染组件:创建 SceneProxy(`UPrimitiveComponent::OnRegister` 触发)
- 物理组件:创建 BodyInstance,加进 PhysX/Chaos
- Tick component:把 PrimaryComponentTick 加到 World 的 TickTaskManager

### 8.2.2.3 `BeginPlay`(World 已 BeginPlay 时)

```cpp
virtual void BeginPlay();
```

只在 World `HasBegunPlay` 时调。Editor 模式不调。

## 8.2.3 `RegisterAllComponents` 主流程

```cpp
// 简化伪代码
void AActor::RegisterAllComponents()
{
    PreRegisterAllComponents();
    
    // 遍历所有 component(深度优先,根 component 先)
    TInlineComponentArray<UActorComponent*> Components;
    GetComponents(Components);
    
    for (UActorComponent* C : Components)
    {
        if (!C->IsRegistered())
        {
            C->RegisterComponentWithWorld(GetWorld());
        }
    }
    
    PostRegisterAllComponents();
    
    bHasRegisteredAllComponents = true;
}
```

`RegisterComponentWithWorld` 是 component 真正"上场"的地方。

---

## 8.2.4 `RegisterComponentWithWorld` 内部

`ActorComponent.h:1036`:

```cpp
void RegisterComponentWithWorld(UWorld* InWorld, FRegisterComponentContext* Context = nullptr);
```

简化逻辑:

```cpp
void UActorComponent::RegisterComponentWithWorld(UWorld* World)
{
    // 1. 设置 World 引用
    WorldPrivate = World;
    
    // 2. 调 OnRegister(虚函数,子类重写)
    OnRegister();
    
    // 3. 创建渲染状态(若是 PrimitiveComponent)
    CreateRenderState_Concurrent();
    
    // 4. 创建物理状态(若有物理)
    OnCreatePhysicsState();
    
    // 5. 注册 Tick(若 PrimaryComponentTick.bCanEverTick == true)
    RegisterAllComponentTickFunctions(true);
    
    // 6. 标记已注册
    bRegistered = true;
    
    // 7. 通知 World(component list)
    World->AddNetworkActor(GetOwner());     // 网络对象列表
}
```

每一步都做实质工作。

## 8.2.5 `CreateRenderState_Concurrent` —— 渲染场景

`UPrimitiveComponent`(可见 component 基类)有一个 `FPrimitiveSceneProxy` 镜像在 RenderThread。注册时:

```cpp
void UPrimitiveComponent::CreateRenderState_Concurrent()
{
    // 1. 创建 SceneProxy(GameThread)
    SceneProxy = CreateSceneProxy();
    
    // 2. ENQUEUE_RENDER_COMMAND 把它注册到 RenderThread 的 Scene
    ENQUEUE_RENDER_COMMAND(AddPrimitive)(
        [Scene = GetWorld()->Scene, Proxy = SceneProxy](FRHICommandListImmediate&)
        {
            Scene->AddPrimitive(Proxy);
        });
}
```

**含义**:每个新的可见 component → GameThread 创建 SceneProxy + RenderThread 加进 Scene。

**RTS 数量级**:50K StaticMeshComponent → 50K SceneProxy → RenderThread 处理 50K primitive。**直接卡死**。

**Mass 不走这条路** — `URepresentationProcessor` 直接管理 ISMC 实例,GPU 端用 `GPUScene` 紧凑存储,不需要每单位一个 SceneProxy。详 §20.2 / §25。

---

## 8.2.6 `OnCreatePhysicsState` —— 物理引擎

```cpp
void UPrimitiveComponent::OnCreatePhysicsState()
{
    // 创建 BodyInstance
    BodyInstance.InitBody(BodySetup, ComponentToWorld, this, GetWorld()->GetPhysicsScene());
}
```

加入 Chaos 物理引擎,参与碰撞 / 物理模拟。每个 component 一个 BodyInstance。

50K 物理 body → Chaos 卡。RTS 单位**很少需要物理碰撞**,Mass 单位用自己的 `MovementProcessor` + 简单距离 query 替代。

---

## 8.2.7 `RegisterAllComponentTickFunctions` —— Tick 注册

```cpp
void UActorComponent::RegisterAllComponentTickFunctions(bool bRegister)
{
    if (PrimaryComponentTick.bCanEverTick && bRegister)
    {
        PrimaryComponentTick.RegisterTickFunction(GetWorld()->PersistentLevel);
    }
}
```

**`PrimaryComponentTick`** 是 component 上的 `FTickFunction`(§8.3 详讲)。注册后该 tick 进 World 的 TickTaskManager 调度。

**纪律**:Component 不需要 tick 时,**ctor 里设** `PrimaryComponentTick.bCanEverTick = false`。这能省一次 tick 注册 + 每帧调度开销。

## 8.2.8 Component 数量级的"代价"

```
1 个 AActor + 5 个 UActorComponent:
   - NewObject × 6                    ~30-50 μs
   - RegisterAllComponents
     ├─ CreateRenderState × ~3 primitive ~30-100 μs
     ├─ OnCreatePhysicsState × ~2 body  ~20-50 μs
     ├─ RegisterTickFunction × ~5       ~5-15 μs
   - PostInitializeComponents           ~5-10 μs
   - DispatchBeginPlay                  ~5-50 μs(看 BP)
   ─────────────────────────────────────
   总计                                 ~100-300 μs
```

50K 这种 actor → **5-15 秒**。游戏开局直接卡死。

**RTS 实战**:每个 actor 的 Component 数量**严格控制**:
- 英雄 / Boss:可以 10-20 component(Mesh、Animation、Movement、Capsule、SkillSet、AI、Audio、HUD、...)
- 普通杂兵:**走 Mass**,根本没 Component 概念

## 8.2.9 `UnregisterAllComponents`(销毁阶段)

Actor `Destroy` 时反向走:

```cpp
void AActor::UnregisterAllComponents()
{
    for (UActorComponent* C : Components)
    {
        if (C->IsRegistered())
        {
            C->UnregisterComponent();
        }
    }
}

void UActorComponent::UnregisterComponent()
{
    // 1. 移出 Tick 系统
    PrimaryComponentTick.UnRegisterTickFunction();
    
    // 2. 移出物理
    OnDestroyPhysicsState();
    
    // 3. 移出渲染场景
    DestroyRenderState_Concurrent();
    
    // 4. 调 OnUnregister
    OnUnregister();
    
    bRegistered = false;
}
```

Destroy 50K actor 也是几秒级别。

## 8.2.10 Component 与 Mass 的对比

| 维度 | Actor + Component | Mass entity + Fragment |
|---|---|---|
| 创建 | NewObject × N + RegisterAll(几百 μs) | placement new(几百 ns) |
| 渲染 | 每 component 一个 SceneProxy | ISMC 共享 + GPU instance |
| 物理 | 每 component 一个 BodyInstance | Mass 自定义,不走 Chaos |
| Tick | 每 component 一个 TickFunction | 批量并行 Processor |
| 内存 | KB 级 / actor | 几百字节 / entity |

数量级差**几个**。

## 8.2.11 实操与下一节预告

### 实操

```cpp
// 量自己 Actor 的 component 数量
static FAutoConsoleCommand CmdInspectComponents(TEXT("rts.InspectComponents"),
    TEXT("rts.InspectComponents <ActorName>"),
    FConsoleCommandWithArgsDelegate::CreateLambda([](const TArray<FString>& Args)
    {
        if (Args.Num() == 0) return;
        AActor* A = FindFirstObject<AActor>(*Args[0]);
        if (!A) return;
        
        TInlineComponentArray<UActorComponent*> Cs;
        A->GetComponents(Cs);
        
        UE_LOG(LogTemp, Display, TEXT("=== %s has %d components ==="), *A->GetName(), Cs.Num());
        for (UActorComponent* C : Cs)
        {
            UE_LOG(LogTemp, Display, TEXT("  %s : %s"), 
                *C->GetName(), *C->GetClass()->GetName());
        }
    }));
```
