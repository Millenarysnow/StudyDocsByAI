## 10.1.1 浅入:输入是个有顺序的"事件流"

```
1. OS / 硬件:键盘按 W
   ↓
2. Windows 消息泵:WM_KEYDOWN
   ↓
3. UE 应用层:FWindowsApplication::ProcessMessage
   ↓
4. Slate 应用:FSlateApplication::ProcessKeyDownEvent
   ↓
5. Game Viewport:UGameViewportClient::InputKey
   ↓
6. PlayerController:APlayerController::InputKey
   ↓
7. PlayerInput:UPlayerInput::InputKey
   ↓
8. InputComponent stack:遍历 PC + 当前 Pawn 的 InputComponent
   ↓
9. 你的 lambda / 函数被调
```

每一步都是 hook 点。

---

## 10.1.2 第 1-3 步:OS / Windows / Slate

OS 把键盘事件 → Windows MessageQueue → UE 应用消息泵 → Slate。这一段对 RTS 项目几乎透明 — UE 已经包好。

你几乎不需要碰这层。除非:
- 你写自定义 input 插件(VR 控制器等)
- 你要拦截 IME 输入(中日韩输入法)
- 调试"为什么键盘事件根本没到 game"

---

## 10.1.3 第 4 步:Slate 与 Game 的"双轨"

`FSlateApplication` 收到键盘事件后,**优先**派发给 Slate widgets(UMG / Editor 工具)。如果某 widget"消费"了事件(`FReply::Handled()`),不再传递。

```
键盘事件
   ↓
FSlateApplication::ProcessKeyDownEvent
   ├─ 1. 找 focused widget
   ├─ 2. widget 处理(返回 FReply)
   │     │
   │     ├─ Handled → 停止
   │     └─ Unhandled → 传给 viewport
   │
   └─ 3. 转给 GameViewportClient(进入 game input 链)
```

### 10.1.3.1 Focus 机制

只有"获得焦点"的 widget 收到键盘事件。鼠标事件类似(基于位置 hit-test)。

```cpp
// 想让游戏接收输入
SlateApp->SetUserFocusToGameViewport(0);   // ControllerId 0
```

实战:RTS 打开聊天框时,焦点在 chat input → 不应该响应"WASD 移动相机"。chat 关闭后焦点回 Game viewport。

## 10.1.4 第 5 步:`UGameViewportClient::InputKey`

```cpp
// 简化伪代码
bool UGameViewportClient::InputKey(const FInputKeyEventArgs& EventArgs)
{
    // 1. 派发到对应 LocalPlayer(分屏时第 N 个手柄给第 N 个玩家)
    ULocalPlayer* TargetLP = GetLocalPlayerForController(EventArgs.ControllerId);
    
    // 2. 调玩家 PC 的 InputKey
    if (TargetLP && TargetLP->PlayerController)
    {
        return TargetLP->PlayerController->InputKey(EventArgs);
    }
    
    return false;
}
```

ViewportClient 是**输入分发器**,根据 ControllerId 路由到对应 LocalPlayer 的 PC。

### 10.1.4.1 多手柄 / 分屏

```
Controller 0: 第一个手柄 → LocalPlayer 0 → PC 0
Controller 1: 第二个手柄 → LocalPlayer 1 → PC 1
...
```

`UGameInstance::CreatePlayer(ControllerId)` 关联手柄到玩家。

## 10.1.5 第 6 步:`APlayerController::InputKey`

```cpp
bool APlayerController::InputKey(const FInputKeyEventArgs& EventArgs)
{
    // 调用 UPlayerInput
    if (PlayerInput)
    {
        return PlayerInput->InputKey(EventArgs);
    }
    return false;
}
```

PC 把事件转给 `UPlayerInput` 处理(下一节)。

---

## 10.1.6 第 7-8 步:`UPlayerInput` 与 InputComponent stack

`UPlayerInput` 是 PC 的输入处理器,它维护一个 **InputComponent stack**:

```
Stack:
   Top:    PC.InputComponent          (顶层,先处理)
           Pawn.InputComponent         (Pawn 自己 SetupPlayerInputComponent 注册的)
   Bottom: Engine 默认 InputComponent
```

事件按栈顶 → 栈底 顺序派发。某 InputComponent 的绑定**消费**事件后,后面的不再处理。

### 10.1.6.1 InputComponent 是什么

```cpp
class UInputComponent : public UActorComponent
{
public:
    // Action 绑定(按键事件)
    TArray<FInputActionBinding> ActionBindings;
    
    // Axis 绑定(连续值,如鼠标移动)
    TArray<FInputAxisBinding> AxisBindings;
    
    // Touch / Gesture 绑定
    // ...
    
    void BindAction(FName ActionName, EInputEvent EventType, ...);
    void BindAxis(FName AxisName, ...);
};
```

每个 InputComponent 有一组绑定。当事件到达时,匹配绑定的 lambda / 函数被调。

### 10.1.6.2 旧式 Input 绑定

```cpp
void ARTSCameraPawn::SetupPlayerInputComponent(UInputComponent* IC) override
{
    IC->BindAxis("CamForward", this, &ThisClass::MoveForward);
    IC->BindAction("Select", IE_Pressed, this, &ThisClass::OnSelectPressed);
}
```

这是 UE4 时代的写法。`Project Settings → Input → Action Mappings / Axis Mappings` 配置 KeyName → ActionName 映射。

**5.0+ 推荐 Enhanced Input**(§10.3),不再用旧的 Action/Axis 系统。但旧系统**仍能用**,UE 兼容。

## 10.1.7 完整时序图

```
[Hardware] Win/Linux/Mac 键鼠手柄
   ↓
[OS Event Queue]
   ↓
[FWindowsApplication / FLinuxApplication]
   ↓
[FSlateApplication::ProcessKeyDownEvent / ProcessMouseButtonDownEvent]
   │
   │ 1. focus widget 处理(UMG / Editor)
   │    ├─ Handled → 停
   │    └─ Unhandled
   ↓
[UGameViewportClient::InputKey]
   │ 2. 找 LocalPlayer (按 ControllerId)
   ↓
[ULocalPlayer::PlayerController->InputKey]
   ↓
[APlayerController::InputKey]
   ↓
[UPlayerInput::InputKey]
   │ 3. 入队 / Tick 处理
   ↓
[UPlayerInput::ProcessInputStack]
   │ 4. 遍历 InputComponent stack
   │
   ↓
[InputComponent::ExecuteBindings]
   │ 5. 调你的 lambda / 函数
   ↓
[你的代码]
```

## 10.1.8 输入不响应的常见原因

诊断顺序:

1. **焦点**:Slate widget 是不是消费了事件?切焦点到 game viewport
2. **InputComponent 没注册**:Pawn 的 `SetupPlayerInputComponent` 是否被调?需要 `bReceiveInput` 等
3. **InputAction / Mapping 没配**:Project Settings → Input 里有没有
4. **PC 的 PlayerInput 是 null**:启动顺序问题

调试:

```cpp
// 拦截 InputKey 看
bool ARTSPlayerController::InputKey(const FInputKeyEventArgs& EventArgs)
{
    UE_LOG(LogTemp, Display, TEXT("InputKey: %s,Event=%d"),
        *EventArgs.Key.ToString(), (int32)EventArgs.Event);
    return Super::InputKey(EventArgs);
}
```

如果这里都没日志 → 事件没到 PC,问题在 Slate / focus 层。

## 10.1.9 RTS 视角:输入接收点

```
ARTSPlayerController::SetupInputComponent
   ├─ BindAction "Select" → ::OnSelectPressed(本地)
   ├─ BindAction "Command" → ::OnCommandPressed(本地)
   └─ BindAction "OpenMenu" → ::OnMenuToggle(本地)

ARTSCameraPawn::SetupPlayerInputComponent
   ├─ BindAxis "MoveForward" → ::MoveForward (相机)
   ├─ BindAxis "MoveRight" → ::MoveRight
   ├─ BindAxis "Zoom" → ::ZoomCamera
   └─ BindAxis "RotateMouse" → ::RotateCamera
```

PC 接收"游戏命令"输入,Pawn 接收"相机控制"输入。各自职责。
