# §18.6 ParallelForEachEntityChunk — 并行执行

> **本节地图**:模块四第 18 章第 6 节。Processor 单线程跑 50K entity 已经够快,**但**8 worker 并行能 ~8 倍加速。这一节看并行 API。
>
> **预备知识**:§5.3 UE::Tasks,§17 / §18.1-§18.5。

---

## 18.6.1 用法

```cpp
void URTSMovementProcessor::Execute(...)
{
    Query.ParallelForEachEntityChunk(EM, Ctx, [&](FMassExecutionContext& InCtx)
    {
        // 这个 lambda 会**在多个 worker 上并行**跑(每 worker 一个 chunk)
        auto Pos = InCtx.GetMutableFragmentView<FMassPositionFragment>();
        // ...
    });
}
```

仅一个 API 差异:`ParallelForEachEntityChunk` 替代 `ForEachEntityChunk`。

---

## 18.6.2 性能差距

```
50K entity / 64 entity per chunk = 780 chunks

单线程:780 chunks × 几 μs / chunk = 3 ms
8 worker 并行:780 / 8 = 100 chunks per worker × 几 μs = 0.5 ms

加速 ~6 倍(work stealing 不完美,但接近理论)
```

---

## 18.6.3 安全性约束

并行时,worker 之间**不能** RW 冲突。Mass 内部用 BitSet 检测:

```
Query Required = ReadWrite FPosition
```

→ 多 worker **不**会同时读写同 chunk 的 FPosition(每 worker 拿不同 chunk)。

但:**修改 Subsystem / 全局状态** → 必须自己用 atomic / mutex / Defer:

```cpp
Query.ParallelForEachEntityChunk(EM, Ctx, [&](FMassExecutionContext& InCtx)
{
    // ❌ 不安全:多 worker 写同一 Subsystem 字段
    GetCombatSubsystem()->TotalDamage += LocalDamage;
    
    // ✅ 安全:atomic
    static_cast<std::atomic<int32>*>(...)->fetch_add(LocalDamage);
    
    // ✅ 安全:Defer(GameThread flush)
    InCtx.Defer().PushCommand<...>(...);
});
```

---

## 18.6.4 何时用 Parallel vs Single

```
✓ Parallel:fragment 操作,无外部依赖,大量 entity
   - Movement / AI / LOD / Representation
   
✗ Single:轻量 + 外部依赖
   - CommandProcessor(改 Subsystem)
   - 调试可视化(每帧少量)
```
