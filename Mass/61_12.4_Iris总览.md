## 12.4.1 传统 Replication 的"痛点"

```
传统 Replication:
   - 每帧 ServerReplicateActors 遍历所有 actor
   - 每 actor 计算 relevancy + diff
   - 用 ActorChannel 维护状态
   - "Polled" 模型(轮询每个 actor)
```

痛点:
- 50K actor → 50K channel,内存爆炸
- 每帧扫描 50K(O(N))→ ServerReplicateActors 几十毫秒
- Diff 计算 + RepLayout 比较开销大
- 难以并行(GameThread 阻塞)

---

## 12.4.2 Iris 的核心思路

Iris 改"polled"为 **"pushed"** 模型:
- Actor 状态变 → 主动**通知** Iris(push dirty)
- Iris 维护 dirty 集合,只复制真改的
- DataStore-centric:数据集中,actor 不必有 channel
- 支持并行:Iris 有自己的多线程调度

```
传统:每帧扫所有 actor → 找 dirty → 发包
Iris:actor 变化时 → push dirty → Iris 后台聚合 → 发包
```

---

## 12.4.3 启用 Iris

在 GameMode INI 配:

```ini
[/Script/Engine.GameModeBase]
GameNetDriverReplicationSystem = 1   ; 1 = Iris,0 = 传统
```

或代码:

```cpp
ARTSGameMode::ARTSGameMode()
{
    GameNetDriverReplicationSystem = EReplicationSystem::ReplicationGraph;  // 或 Iris
}
```

启用后,UE 内部用 `UReplicationSystem`(Iris 的接口)替代 `ServerReplicateActors`。

## 12.4.4 Iris 关键概念

### 12.4.4.1 Replicated Object

Iris 不区分 Actor / Component / 自定义对象 — 都是"replicated object"。每个 object 有:
- 唯一 ID
- 状态字段(类似 UPROPERTY)
- 配置(filtering / 优先级 / dormancy)

### 12.4.4.2 Filtering(替代 IsNetRelevantFor)

Iris 用 **filtering 函数**:

```cpp
class FRTSFogFilter : public UNetObjectFilter
{
    virtual bool IsObjectVisible(...) override
    {
        // 自定义可见性逻辑
    }
};
```

支持空间索引、视野检测、组件过滤。比 IsNetRelevantFor 灵活。

### 12.4.4.3 Push Model

```cpp
// 传统 Replicated 字段
UPROPERTY(Replicated)
int32 Health;

// Iris Push Model
UPROPERTY(Replicated, ReplicatedUsing = OnRep_Health)
int32 Health;

void SetHealth(int32 NewHealth)
{
    Health = NewHealth;
    MARK_PROPERTY_DIRTY_FROM_NAME(ThisClass, Health, this);   // ★ 主动 push
}
```

`MARK_PROPERTY_DIRTY` 通知 Iris 这个字段变了。Iris 不必轮询比较。

## 12.4.5 Iris 与 Mass 集成

`UMassNetworkingTrait` + Iris ReplicationBridge 让 Mass entity 直接用 Iris:

```cpp
USTRUCT()
struct FMassReplicatedFragment : public FMassFragment
{
    GENERATED_BODY()
    
    // Mass replicate-aware fragment
    UPROPERTY()
    int32 NetID;
};
```

Mass 自己的 Replication Processor(`UMassReplicationProcessor`):
- 每帧扫所有 entity
- 检测哪些"replicated"(`FMassReplicatedFragment` 等)
- 通过 Iris API push dirty

→ Iris 把 50K entity 当 50K replicated object,但 push 模型 + 紧凑 ID 让性能可接受。

§14 / §21 详细讲 Mass + Iris。

## 12.4.6 Iris 启用建议

| 项目类型 | 推荐 |
|---|---|
| 单机 / 小型多人(< 8 player) | 传统(简单) |
| 中型多人(< 50 player) | 传统 + 优化 |
| 大型多人 / RTS 数万 entity | **Iris + Mass** |

5.7 Iris **已生产可用**(Fortnite Battle Royale 用)。RTS 大规模项目应该用。
