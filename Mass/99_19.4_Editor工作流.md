## 19.4.1 完整工作流

```
1. 程序员:
   - 写 FRTSCombatFragment(USTRUCT)
   - 写 URTSCombatTrait(UMassEntityTraitBase 子类,UPROPERTY 暴露给策划)
   - 写 URTSCombatProcessor(消费 FRTSCombatFragment)

2. 策划在 Editor:
   - 创建 DA_Soldier(UMassEntityConfigAsset)
   - 加 URTSCombatTrait → 配 BaseHealth = 100,BaseDamage = 10
   - 加 UMassMovementTrait → 配 MaxSpeed = 5
   - 加 UMassRepresentationTrait → 选 SoldierMesh
   - 保存

3. 关卡:
   - 拖 UMassSpawner 进关卡
   - SpawnEntityType = DA_Soldier(70%) + DA_Worker(30%)
   - 加 UMassEnvironmentSpawnDataGenerator(在 Volume 内随机)

4. 运行:
   - BeginPlay 触发 SpawnerActor.DoSpawning
   - Mass 编译 EntityTemplate(若未缓存)
   - SpawnEntities × N
   - 你的 Processor 开始处理
```

---

## 19.4.2 Hot Reload 友好性

策划改 Trait 参数(BaseHealth 100 → 150):

- 资产保存 → DA_Soldier 重编 Template
- **已 spawn 的 entity 不变**(它们用旧 Template 创建)
- **下次 spawn 用新值**

如果你想"已 spawn 的也变" → Processor 主动读 Trait 参数(每帧或事件触发)。

## 19.4.3 Editor 工具:Mass Debugger

`Window → Developer Tools → Mass Debugger`:
- 列出当前 World 所有 entity
- 显示 archetype + Fragment / Tag
- 查看 Processor 列表 + ExecutionOrder
- 运行时改 Tag(测试用)

实战:策划改完资产 → PIE 测试 → Mass Debugger 看 entity 数据是否正确。

---

## 19.4.4 资产的版本控制

`UMassEntityConfigAsset` 是 .uasset 文件,git LFS 推荐。

策划改 Trait 参数 → asset 变 → git diff 显示 binary diff(用 UE Asset Diff 工具看)。

**纪律**:Trait 名字 / Fragment 类型一旦定型,**不要改名**(老 .uasset 引用会找不到)。
