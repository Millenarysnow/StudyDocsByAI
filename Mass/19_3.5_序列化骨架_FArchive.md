# §3.5 序列化骨架 — FArchive 双向接口与版本号

> **本节地图**:模块一第 3 章压轴。前面四节我们看完了 UObject 的结构、内存、生命周期、模板对象。这一节看 UObject **如何把自己写到磁盘 / 网络,又如何从磁盘 / 网络读回**。
>
> UE 的序列化机制核心是一个抽象基类 `FArchive`,它**用同一组代码同时承担读和写**。这一刻你看不出方向,等真正走到字段时,内部 IsLoading()/IsSaving() 决定行为。这是一种独特的设计,看一次就忘不了。
>
> 本节聚焦"骨架"—— 结构。具体到某个 FArchive 子类(如 `FArchiveLoadCompressedProxy`、`FNetBitWriter`、`FObjectAndNameAsStringProxyArchive`)的细节属于深度阅读题,不在 RTS 项目的常规视野里。
>
> **预备知识**:§2.3(反射查询)、§3.4(archetype delta 序列化思路)。
>
> **读完之后你能做到**:
> - 看到 `<<` 操作符链的"流式"代码,**立刻**知道这一行同时是读和写
> - 区分 `FArchive::IsLoading()` / `IsSaving()` / `IsCooking()` 的语义
> - 自定义 USTRUCT / UObject 的 Serialize 函数
> - 用 `FCustomVersion` 给资产加版本号,平滑升级旧资产
> - 知道 5.x 的 `FStructuredArchive` 是什么,与传统 FArchive 的关系
> - 在 RTS 项目里**避免**把 Mass Fragment 走传统 UObject 序列化路径

## 3.5.1 浅入:`<<` 操作符为什么能同时承担读写

最基础的写法:

```cpp
void MyFunc(FArchive& Ar)
{
    int32 Health;
    FString Name;
    
    Ar << Health;       // 这一行做什么?
    Ar << Name;
}
```

**这两行同时是"读"和"写"**:
- 如果 `Ar.IsSaving()` → 把 `Health` / `Name` 写到 Archive
- 如果 `Ar.IsLoading()` → 从 Archive 读出值填入 `Health` / `Name`

**同一段代码完成正反两个方向**。这种设计的好处:**永远只写一份序列化代码**,读和写自动一致。如果你写一段读代码忘了对应字段,写代码也跟着失效,bug 立刻可见。

C# / Python 等语言往往要写两个函数(Serialize / Deserialize)。UE 的双向 `<<` 是非常优雅的"自反"设计。

## 3.5.2 `FArchive` 的核心结构

`Engine/Source/Runtime/Core/Public/Serialization/Archive.h:1207`:

```cpp
class FArchive : private FArchiveState
{
public:
    FArchive() = default;
    virtual ~FArchive();
    
    // 各类型的 operator<<(虚函数,子类重写)
    virtual FArchive& operator<<(FName& Value)         { return *this; }
    CORE_API virtual FArchive& operator<<(FText& Value);
    virtual FArchive& operator<<(UObject*& Value)      { return *this; }
    virtual FArchive& operator<<(FField*& Value)       { return *this; }
    
    // ... 各种 *Ptr / Soft / Weak ...
    CORE_API virtual FArchive& operator<<(struct FLazyObjectPtr& Value);
    CORE_API virtual FArchive& operator<<(struct FObjectPtr& Value);
    CORE_API virtual FArchive& operator<<(struct FSoftObjectPtr& Value);
    CORE_API virtual FArchive& operator<<(struct FSoftObjectPath& Value);
    CORE_API virtual FArchive& operator<<(struct FWeakObjectPtr& Value);
    
    // 基础类型(friend 函数,通过 Serialize() 转发)
    inline friend FArchive& operator<<(FArchive& Ar, ANSICHAR& Value);
    inline friend FArchive& operator<<(FArchive& Ar, WIDECHAR& Value);
    inline friend FArchive& operator<<(FArchive& Ar, uint8& Value);
    inline friend FArchive& operator<<(FArchive& Ar, int32& Value);
    inline friend FArchive& operator<<(FArchive& Ar, float& Value);
    // ... 等等 ...
    
    // 真正的字节读写接口(子类实现)
    virtual void Serialize(void* V, int64 Length) {}
    virtual int64 Tell() {}
    virtual int64 TotalSize() {}
    virtual void Seek(int64 InPos) {}
    
    // 状态查询
    using FArchiveState::IsLoading;
    using FArchiveState::IsSaving;
    using FArchiveState::IsTextFormat;
    using FArchiveState::IsCooking;
    using FArchiveState::IsTransacting;
    // ...
};
```

### 3.5.2.1 双层结构:`FArchiveState` + `FArchive`

`FArchive` 私有继承 `FArchiveState`。`FArchiveState`(Archive.h 上半部分)持有所有"状态字段"(各种 bool flag、版本号、错误标志),`FArchive` 持有"行为接口"(虚函数)。

为什么拆?让你的子类**只需要重写虚函数**,不要操心一堆 `bool` 字段的初始化。

### 3.5.2.2 关键状态接口

```cpp
// Archive.h:236+
UE_FORCEINLINE_HINT bool IsLoading() const           { return ArIsLoading; }
UE_FORCEINLINE_HINT bool IsSaving() const            { return ArIsSaving; }
UE_FORCEINLINE_HINT bool IsLoadingFromCookedPackage() const { return ArIsLoadingFromCookedPackage; }
UE_FORCEINLINE_HINT bool IsTextFormat() const        { return (ArIsTextFormat && WITH_TEXT_ARCHIVE_SUPPORT); }

// 还有
bool IsCooking() const;
bool IsTransacting() const;     // Editor undo/redo
bool IsCountingMemory() const;   // GC / 引用统计 archive
bool IsObjectReferenceCollector() const;
```

**注意**:`IsLoading() == !IsSaving()` **不一定成立**。某些 archive(`FArchiveCountMem`、引用收集器)既不读也不写,只是"扫"对象。`Serialize` 函数里要主动判断,**不要假设** "不是 saving 就是 loading"。

### 3.5.2.3 真正读写字节的入口

```cpp
// Archive.h(子类必须重写)
virtual void Serialize(void* V, int64 Length) {}
```

这是**抽象的"读 / 写 N 字节到这个内存地址"接口**。每个 archive 子类重写它:
- 文件 archive:`fread` / `fwrite`
- 内存 archive:`memcpy`
- 网络 archive:写到 bit stream
- 计数 archive:仅累加 size

所有 `operator<<` 最终都调到这个 `Serialize(ptr, size)`。

## 3.5.3 `<<` 操作符的双向魔法

让我们看一个最简单的 `int32` 序列化(`Archive.h:1438` 附近):

```cpp
inline friend FArchive& operator<<(FArchive& Ar, uint8& Value)
{
    Ar.Serialize(&Value, sizeof(uint8));
    return Ar;
}

// int32 类似(可能调 ByteSwap 处理 endian)
```

**就这么简单**:`Serialize(&Value, sizeof(...))`。

具体方向:
- 如果 archive 是写,`Serialize` 内部把 `*Value` 字节写出去
- 如果 archive 是读,`Serialize` 内部把字节读出来填入 `*Value`
- 调用方不知道也不关心方向

### 3.5.3.1 复合类型靠递归

```cpp
struct FMyData
{
    int32 Health;
    FString Name;
    TArray<float> Buffer;
};

FArchive& operator<<(FArchive& Ar, FMyData& V)
{
    Ar << V.Health;        // 调 int32 的 <<
    Ar << V.Name;          // 调 FString 的 <<
    Ar << V.Buffer;        // 调 TArray<float> 的 <<
    return Ar;
}
```

每个 `<<` 进入对应类型的 `<<`,递归到底走 `Serialize(ptr, size)`。

### 3.5.3.2 容器序列化

`TArray<T>::operator<<` 大致:

```cpp
template<typename T, typename A>
FArchive& operator<<(FArchive& Ar, TArray<T, A>& A)
{
    int32 SerializeNum = Ar.IsLoading() ? 0 : A.Num();
    Ar << SerializeNum;
    
    if (Ar.IsLoading())
    {
        A.Empty(SerializeNum);
        A.AddDefaulted(SerializeNum);
    }
    
    for (int32 i = 0; i < SerializeNum; ++i)
    {
        Ar << A[i];      // 递归调元素的 <<
    }
    return Ar;
}
```

**关键观察**:`Ar << SerializeNum` 这一句既写又读 —— 写时输出"我有几个元素",读时收到"我应该读几个元素"。然后循环序列化每个元素。

### 3.5.3.3 字符串序列化

`FString::operator<<` 类似,先序列化长度,再序列化字符。处理 UTF-8 / UTF-16 编码差异。

### 3.5.3.4 UObject* 序列化(关键)

```cpp
virtual FArchive& operator<<(UObject*& Value) { return *this; }
```

基类**默认空操作**!子类重写:
- **资产 archive**:序列化对象的 PathName(`/Game/Foo.Bar`),加载时 LoadObject
- **网络 archive**:序列化 NetGUID(对象的网络 ID),收端用 PackageMap 解析
- **复制对象 archive**(DuplicateObject):序列化对象,递归复制
- **GC 引用收集 archive**:读取 `Value` 指针,挂到引用列表

**同一行 `Ar << SomeObjectPtr`,在不同 archive 子类里语义完全不同**。

## 3.5.4 `UObject::Serialize` —— 反射驱动的字段序列化

UObject 的默认 `Serialize` 实现(`Engine/Source/Runtime/CoreUObject/Private/UObject/Obj.cpp` 等):

```cpp
void UObject::Serialize(FArchive& Ar)
{
    UClass* Class = GetClass();
    
    // 1. 序列化 ObjectFlags 等头部信息(在某些 archive 里跳过)
    
    // 2. 调 UClass::SerializeBin 或 SerializeTaggedProperties
    Class->SerializeBin(Ar, this);
    // 内部:遍历 PropertyLink,对每个字段调 FProperty::SerializeItem
    
    // 3. 序列化 sparse data(SparseClassData,5.x 引入,稀疏字段)
    
    // 4. 子类钩子(虚函数,子类重写)
}
```

`UClass::SerializeTaggedProperties`(在 Class.cpp 里)是**复杂的标签序列化**:每个字段写一个 tag(name + type),反序列化时按 tag 匹配字段。这样新增 / 删除字段后老资产仍能加载(找不到的字段就跳过)。

### 3.5.4.1 自定义 UObject Serialize

```cpp
class UMyObject : public UObject
{
public:
    UPROPERTY()
    int32 Health;
    
    int32 NonReflectedField;     // 没 UPROPERTY,反射不知道
    
    virtual void Serialize(FArchive& Ar) override
    {
        Super::Serialize(Ar);    // 让基类处理 UPROPERTY 字段
        
        // 自己处理非反射字段
        Ar << NonReflectedField;
    }
};
```

何时需要这样?
- 字段类型不是反射支持的(如 `std::map`、自定义结构体)
- 需要复杂的版本兼容逻辑
- 序列化派生数据(从其它字段算出的缓存,可重算的不需要存)

### 3.5.4.2 USTRUCT 的 Serialize

USTRUCT 默认序列化通过反射。也可以自定义:

```cpp
USTRUCT()
struct FMyStruct
{
    GENERATED_BODY()
    
    int32 X, Y;
    
    bool Serialize(FArchive& Ar)
    {
        Ar << X;
        Ar << Y;
        return true;
    }
};

template<>
struct TStructOpsTypeTraits<FMyStruct> : TStructOpsTypeTraitsBase2<FMyStruct>
{
    enum { WithSerializer = true };       // 通知反射:这个 struct 有自定义序列化
};
```

`TStructOpsTypeTraits` 是 USTRUCT 的"自定义行为"机制 —— 通过模板特化告诉反射"我的 struct 有自定义 Serialize / NetSerialize / `==` 比较 /Copy"等。

## 3.5.5 `FCustomVersion` —— 版本号管理

资产文件需要跨版本兼容。如果你 1.0 版本的字段是 `int32 Health`,2.0 改成 `float Health`,旧 .uasset 文件加载时怎么处理?

UE 的解法:`FCustomVersion`。

### 3.5.5.1 注册自定义版本

```cpp
// MyRTSCustomVersion.h
struct FRTSCustomVersion
{
    enum Type
    {
        BeforeCustomVersionWasAdded = 0,
        InitialVersion,
        ChangedHealthToFloat,         // 我们的迁移点
        AddedManaField,
        // ... 每次资产格式变化加一个 ...
        VersionPlusOne,
        LatestVersion = VersionPlusOne - 1
    };

    static const FGuid GUID;          // 这个版本表的 GUID
    
private:
    FRTSCustomVersion() {}
};

// MyRTSCustomVersion.cpp
const FGuid FRTSCustomVersion::GUID(0x1234ABCD, 0x..., 0x..., 0x...);

FCustomVersionRegistration GRegisterRTSCustomVersion(
    FRTSCustomVersion::GUID, 
    FRTSCustomVersion::LatestVersion, 
    TEXT("RTSVersion"));
```

`FCustomVersionRegistration` 是个全局静态对象,启动期把这个 GUID/Latest 配对**注册到 archive 的版本元数据**里。每次资产保存时,资产头部记录"我的资产用到的所有 CustomVersion + 当时的 Latest Version 数字"。

### 3.5.5.2 序列化时检查版本

```cpp
void UMyData::Serialize(FArchive& Ar)
{
    Super::Serialize(Ar);
    
    // 让 archive 跟踪本资产用了 RTSVersion
    Ar.UsingCustomVersion(FRTSCustomVersion::GUID);
    
    int32 RTSVer = Ar.CustomVer(FRTSCustomVersion::GUID);
    
    if (RTSVer < FRTSCustomVersion::ChangedHealthToFloat)
    {
        // 旧版本:Health 是 int32
        int32 OldHealth = 0;
        Ar << OldHealth;
        Health = (float)OldHealth;        // 迁移到 float
    }
    else
    {
        Ar << Health;                      // 新版本:直接 float
    }
    
    if (RTSVer >= FRTSCustomVersion::AddedManaField)
    {
        Ar << Mana;
    }
    // 旧版本没有 Mana → 用默认值(在 ctor 里赋的)
}
```

**实战意义**:玩家用 5.0 存了存档,你后来出 5.1 改了存档格式 → 用 CustomVersion 自动识别旧存档,做迁移。**永远不要**在不加版本检查的情况下改资产格式,否则旧资产无法加载。

### 3.5.5.3 引擎自带的版本

`FFrameworkObjectVersion` / `FCoreObjectVersion` / `FRenderingObjectVersion` 等,Epic 自己用来标记引擎版本变化。资产保存时同时记录引擎版本和你的版本。

## 3.5.6 `FStructuredArchive` —— 5.x 新一代结构化序列化

传统 `FArchive` 是**字节流**(flat binary),无标签。问题:
- JSON / XML 这种结构化格式难支持
- 调试时看不清"这一段是哪个字段"

5.x 引入 `FStructuredArchive`(`Engine/Source/Runtime/Core/Public/Serialization/StructuredArchive.h`):

```cpp
void UMyObject::Serialize(FStructuredArchive::FRecord Record)
{
    Super::Serialize(Record);
    
    Record << SA_VALUE(TEXT("Health"), Health);
    Record << SA_VALUE(TEXT("Name"), Name);
    
    // 嵌套结构
    auto Inner = Record.EnterField(TEXT("Stats"));
    Inner << SA_VALUE(TEXT("Strength"), Strength);
    Inner << SA_VALUE(TEXT("Dexterity"), Dexterity);
}
```

每个字段带名字。底层 archive 可以是:
- 二进制(忽略名字,行为同传统 FArchive)
- JSON(把名字写进 JSON key)
- XML / 其它格式

UE 5 的资产保存 / Editor undo / cook pipeline 已经在向 `FStructuredArchive` 迁移。但传统 `FArchive` 仍然是**绝大多数代码的接口** —— 你大多数情况看到的还是 `Serialize(FArchive& Ar)` 重载。

UObject 同时提供两个版本:

```cpp
virtual void Serialize(FArchive& Ar);
virtual void Serialize(FStructuredArchive::FRecord Record);    // 5.x 新增
```

默认实现互相转发(后者用 `FStructuredArchiveFromArchive` adapter 包装前者)。

## 3.5.7 网络序列化与 `NetSerialize`

资产保存用 FArchive,**网络复制也是**。网络 archive 子类:`FNetBitWriter` / `FNetBitReader`,用 bit-level 流压缩。

### 3.5.7.1 自定义 NetSerialize(USTRUCT)

```cpp
USTRUCT()
struct FMyVector
{
    GENERATED_BODY()
    
    float X, Y, Z;
    
    bool NetSerialize(FArchive& Ar, UPackageMap* Map, bool& bOutSuccess)
    {
        // 自定义压缩:用 16-bit fixed point 而非 32-bit float
        if (Ar.IsSaving())
        {
            int16 PackedX = (int16)(X * 100.0f);
            int16 PackedY = (int16)(Y * 100.0f);
            int16 PackedZ = (int16)(Z * 100.0f);
            Ar << PackedX << PackedY << PackedZ;
        }
        else
        {
            int16 PackedX, PackedY, PackedZ;
            Ar << PackedX << PackedY << PackedZ;
            X = PackedX * 0.01f;
            Y = PackedY * 0.01f;
            Z = PackedZ * 0.01f;
        }
        bOutSuccess = true;
        return true;
    }
};

template<>
struct TStructOpsTypeTraits<FMyVector> : TStructOpsTypeTraitsBase2<FMyVector>
{
    enum { WithNetSerializer = true };
};
```

每个 FMyVector 在网络上 6 字节(3 × int16),而非默认 12 字节(3 × float)。**RTS 50K 单位每帧位置同步**这种压缩极重要。

### 3.5.7.2 RPC 参数序列化

UFUNCTION RPC 调用时,参数自动通过 archive 序列化。每个参数类型必须支持 `<<`(基础类型 / UObject*/USTRUCT 都支持)。

## 3.5.9 RTS / Mass 视角下的纪律

### (1)Mass Fragment **不要**走 UObject 序列化

Fragment 是 USTRUCT,理论上能 `Ar << Fragment`。但:
- 50K entity × 序列化每个 Fragment 字段开销高
- 反射查询每字段(慢)
- archive 的 padding / 对齐损失内存

**正确姿势**:Mass 自定义序列化(批量 binary blob 拷贝),避开通用 archive 路径。`Engine/Source/Runtime/MassEntity/...` 里 Mass 自己有序列化代码。

### (2)RTS 网络层用 NetSerialize 压缩

每种 RTS 用到的关键复制类型(单位位置、朝向、状态)都自定义 `NetSerialize` 做量化压缩。原生 RepLayout 复制原始 32-bit float 太浪费。

### (3)SaveGame 用 CustomVersion 必备

RTS 项目存档复杂(战役进度、技能解锁、单位经验)。**第一天就**注册 `FRTSCustomVersion`,任何字段变化都加新版本号。否则一旦上线,旧存档就彻底失效。

### (4)资产格式稳定性优先

Trait / EntityConfig / DataAsset 等配置资产的字段一旦定型,**避免**改 UPROPERTY 名字 / 类型。改名字会让所有引用此字段的资产丢失数据(老资产里的 tag 找不到对应字段就丢弃)。

如果非要改:
- 优先用 `UPROPERTY(meta=(DeprecatedProperty, DeprecationMessage="..."))` 标记旧字段
- 在 PostLoad 里做迁移

```cpp
void URTSUnitConfig::PostLoad()
{
    Super::PostLoad();
    
    if (OldHealthInt > 0 && Health == 0.0f)
    {
        Health = (float)OldHealthInt;          // 迁移
        OldHealthInt = 0;
    }
}
```
