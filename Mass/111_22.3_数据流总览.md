## 22.3.1 玩家命令完整链

```
玩家鼠标点击屏幕(Client A)
   ↓
APlayerController::InputKey
   ↓
EnhancedInput 触发 IA_Command
   ↓
ARTSPlayerController::OnCommand
   ↓
[Client A 本地处理]
URTSSelectionSubsystem(LP)更新选择
   ↓
ARTSPlayerController::ServerIssueCommand RPC
   ↓ 网络
[Server]
ARTSPlayerController::ServerIssueCommand_Implementation
   ├─ 验证(玩家是否拥有 entity?)
   └─ 入队
URTSCommandSubsystem(World)
   ↓ 命令缓冲
[Mass tick - PrePhysics]
URTSCommandProcessor
   ├─ 读 CommandQueue
   ├─ 修改 entity FCommandQueueFragment
   ↓
URTSAIProcessor
   ├─ 读 FCommandQueueFragment
   ├─ 决策 → 设 FMovementGoalFragment
   ↓
URTSMovementProcessor
   ├─ 读 FMovementGoalFragment
   ├─ 计算 FVelocityFragment + 路径
   ↓
[Mass tick - PostPhysics]
URTSSteeringProcessor:避障调整
   ↓
[Mass tick - FrameEnd]
UMassLODProcessor:计算 LOD
UMassRepresentationProcessor:更新 ISMC instance
UMassReplicationProcessor:push dirty 到 Iris
   ↓
[Iris]
filter / serialize / 发包
   ↓ 网络
[Client A,B 各自接收]
Iris 反序列化 → 更新本地 EntityView
   ↓
RepresentationProcessor 在 client 也跑 → ISMC 渲染
```

---

## 22.3.2 数据流要点

每步:
- **职责单一**(只改一种 fragment)
- **DAG 排序**(后面的 Processor 看到前面的输出)
- **批量并行**(每 Processor 内部 ParallelForEachEntityChunk)
- **命令缓冲**(修改不立即生效,phase 末统一 flush)

---

## 22.3.3 跨进程通信(命令链)

```
Client A 命令 → 通过 RPC 进 server
Server CommandSubsystem 处理 → Mass entity 状态变
Mass 复制 → Client A,B 看到 entity 移动
```

3 跳:Client → Server → Mass 处理 → 复制回客户端。延迟 ~100-200ms 可接受(RTS 命令容忍度高)。
