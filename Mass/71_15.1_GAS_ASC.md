# §15.1 ASC(UAbilitySystemComponent)架构

> **本节地图**:模块三第 15 章第 1 节。GAS(Gameplay Ability System)是 UE 自带的"技能 / 属性 / 效果"框架。这一节看 GAS 的核心:`UAbilitySystemComponent`(ASC)。
>
> RTS 项目**通常不用 GAS**(详 §15.6),但理解 GAS 让你能对比"自研 Mass 技能层"的取舍。
>
> **预备知识**:§9 / §13 / §14。
>
> **读完之后你能做到**:
> - 看 ASC 的 Owner / Avatar 双引用
> - 知道 GAS 的 5 个核心概念(ASC / Attribute / Effect / Ability / Cue)
> - 评估 GAS 是否适合你 RTS 项目

---

## 15.1.1 GAS 五大核心

```
1. ASC (UAbilitySystemComponent):actor 的"技能管理器"组件
2. Attribute (FGameplayAttribute):数值字段(Health / Mana)
3. AttributeSet (UAttributeSet):一组 Attribute 的容器
4. GameplayEffect (UGameplayEffect):对 Attribute 的修改(伤害、buff)
5. GameplayAbility (UGameplayAbility):技能行为(可激活)
6. GameplayCue:轻量视觉/音频效果
7. GameplayTag:层级标签(状态标记 / 技能 ID)
```

---

## 15.1.2 ASC 的 Owner / Avatar 双引用

```cpp
class UAbilitySystemComponent : public UGameplayTasksComponent
{
public:
    // Owner Actor:管理逻辑、网络复制、一般是 PlayerState 或 Hero
    UPROPERTY(Replicated)
    TObjectPtr<AActor> OwnerActor;
    
    // Avatar Actor:实际在世界中的"身体",一般是 Pawn / Character
    UPROPERTY(Replicated)
    TObjectPtr<AActor> AvatarActor;
    
    void InitAbilityActorInfo(AActor* InOwnerActor, AActor* InAvatarActor);
    
    // 接口
    void GiveAbility(...);
    void TryActivateAbility(...);
    void ApplyGameplayEffect(...);
    
    UPROPERTY(Replicated)
    FGameplayAbilitySpecContainer ActivatableAbilities;
    // ...
};
```

### 15.1.2.1 为什么 Owner / Avatar 分开

```
场景 1:简单(Owner == Avatar)
   AHero 持有 ASC
   Owner = Hero,Avatar = Hero
   
场景 2:Pawn 死亡但角色不死(MOBA / RPG)
   Owner = APlayerState(永生)
   Avatar = APawn(死了重生新 Avatar)
   死亡时 Avatar 切换到新 Pawn,buff / cooldown 不丢
```

RTS 中:玩家英雄死亡重生 → Avatar 切换。其它 Mass 单位死了直接销毁,无 ASC,不涉及。

### 15.1.2.2 Init

```cpp
// 通常在 Pawn::PossessedBy 或 Hero::BeginPlay 调
ASC->InitAbilityActorInfo(OwnerActor, AvatarActor);
```

## 15.1.3 ASC 的网络复制

ASC 完全 replicated:
- ActivatableAbilities(已学的技能)→ replicated
- AttributeSet → replicated
- ActiveEffects(当前生效的 effect) → replicated

每个 ASC 自带网络通信(可走 Iris 或传统)。

### 15.1.3.1 ASC 实例数

```
ASC 数量 = 拥有 ASC 的 Actor 数

英雄(每队 1-3) × 玩家(2-8) = ~10 ASC
+ 重要 NPC(boss): 几个
+ 50K 杂兵 ASC?
   ❌ 不要 — 50K UObject 灾难(§4.5)
```

→ Mass 杂兵**不要**用 ASC。下一节详讲。

## 15.1.4 RTS 视角:ASC 装哪

```cpp
// 英雄(数量少,值得 ASC)
UCLASS()
class AHero : public ACharacter
{
    UPROPERTY()
    TObjectPtr<UAbilitySystemComponent> ASC;
};

// 玩家本人(全局技能,跨英雄)
UCLASS()
class ARTSPlayerState : public APlayerState
{
    UPROPERTY()
    TObjectPtr<UAbilitySystemComponent> ASC;       // 玩家级技能(科技、英雄通用)
};

// Mass 杂兵
USTRUCT()
struct FUnitFragment : public FMassFragment
{
    int32 Health;
    int32 Damage;
    // 不用 GAS,自定义简化版"技能"
};
```
