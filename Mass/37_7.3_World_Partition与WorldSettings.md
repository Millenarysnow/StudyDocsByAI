## 7.3.1 浅入:为什么需要 World Partition

4.x 时代大型关卡(例如开放世界 RPG)的做法:
- 主关卡 + N 个手动配置的 Sub-Level
- Streaming Volume(玩家走进某区域,加载对应 Sub-Level)
- Sub-Level 内 Actor 共享主关卡的灯光 / lightmap

**痛点**:
- 美术手动切分关卡,几十个 Sub-Level 文件,管理痛苦
- Lightmap 跨 Sub-Level 编译复杂
- 大量 Actor 在 Editor 里同时编辑,卡 Editor

5.x **World Partition** 解决:
- **一个**主关卡文件(`.umap`)
- Editor 把 Actor 按空间网格自动切片(每 actor 存独立 .uasset)
- 运行时按"流送源"(玩家位置)动态加载需要的网格单元

**类似 Unity Addressables 或 Bevy ECS 的空间索引**,但深度集成 UE Actor 系统。

## 7.3.2 World Partition 的关键概念

### 7.3.2.1 Cell(网格单元)

Editor 把 World 按 N×N 米网格(典型 256m × 256m)切分。每 cell 包含**位于该空间范围内的 actor**。

```
World(2048m × 2048m):
   Cell (0,0): 256m × 256m,含 Actor A、B、C
   Cell (1,0): 256m × 256m,含 Actor D、E
   Cell (0,1): ...
   ...
   总 8 × 8 = 64 cells
```

每 cell 是独立的 .uasset,运行时按需加载。

### 7.3.2.2 Streaming Source(流送源)

通常是玩家或相机。运行时:
- 玩家在 (X, Y) 位置
- 加载半径 R 内的 cells
- 加载半径 2R 内的 cells 用 HLOD(低质量代表)
- 其它 cells 不加载

```
                ┌─────────┐
                │ HLOD    │
       ┌────────┼─────────┼────────┐
       │ HLOD   │ Loaded  │ HLOD   │
       │        │ 玩家在这│        │
       └────────┼─────────┼────────┘
                │ HLOD    │
                └─────────┘
```

### 7.3.2.3 HLOD(Hierarchical Level of Detail)

远处 cell 不需要"完整 actor 模拟",用一个**合成的 HLOD actor**(merged mesh)代表。Editor 自动生成 HLOD assets。

玩家走近时:HLOD 卸载,真正 cell 加载。走远时反向。

## 7.3.3 启用 World Partition

新建 World 时:
- Editor → File → New Level → "Open World"(自动启用 WP)
- 或 "Empty Level" 然后在 World Settings 加 `AWorldSettings::SupportsWorldPartition = true`

启用后:
- World 不再有"主 Level + Sub-Level"区分
- Editor 顶部 World Partition 工具条显示 cell 网格
- Actor 拖进 World 自动归属对应 cell

### 7.3.3.1 关键 World Settings

`AWorldSettings`(`Engine/Source/Runtime/Engine/Classes/GameFramework/WorldSettings.h`)字段:

```cpp
// 默认 GameMode 类(可被 GameMode 覆盖)
TSubclassOf<AGameModeBase> DefaultGameMode;

// 重力
float WorldGravityZ;
float DefaultGravityZ;

// 物理设置
float TimeSpeed;          // 时间流速倍率
float DefaultMaxDistanceFieldOcclusionDistance;

// World Partition 配置(嵌入 AWorldPartitionSubsystem)
UPROPERTY(EditAnywhere)
TObjectPtr<UWorldPartition> WorldPartition;

// 资源限制
int32 MaxActorsInLevel;   // Editor 警告阈值
```

`AWorldSettings` 是个**特殊 Actor**,每 World 有且仅有一个,自动 spawn 到 PersistentLevel。

### 7.3.3.2 取 WorldSettings

```cpp
AWorldSettings* WS = World->GetWorldSettings();
WS->TimeSpeed = 0.5f;     // 慢动作(影响所有 Tick)
```

## 7.3.4 Data Layers —— 横切关注点

**Data Layers** 让你把 Actor 按"功能层"分组,不是按空间。例:

```
Layer "Trees"        - 所有树木 actors
Layer "Buildings"    - 所有建筑
Layer "Combat"       - 战斗相关 actors
Layer "Cinematic"    - 过场动画 actors(平时不加载)
```

每个 Actor 可属于多个 Layer。运行时:

```cpp
// 加载某 Layer
UWorldPartitionSubsystem* WP = World->GetSubsystem<UWorldPartitionSubsystem>();
WP->SetDataLayerRuntimeState(TEXT("Cinematic"), EDataLayerRuntimeState::Activated);
```

Data Layer 与空间 cell **正交**:cell 决定"加载哪些区域",Layer 决定"加载哪些功能"。最终加载 = cell 集 ∩ Layer 集。

### 7.3.4.1 RTS 用例

```
Layer "MainBattle"     - 主战场关卡内容
Layer "Tutorial"       - 教学关卡内容(剧情模式才加载)
Layer "DebugDraw"      - 调试可视化(开发期才加载)
```

不同模式加载不同 Layer,关卡资产复用。

## 7.3.5 World Partition 在运行时

### 7.3.5.1 `UWorldPartitionSubsystem`

```cpp
class UWorldPartitionSubsystem : public UWorldSubsystem
{
public:
    // 设置流送源(玩家位置)
    UFUNCTION(BlueprintCallable)
    void RegisterStreamingSourceProvider(...);
    
    // 强制加载某区域
    void ForceLoadCells(...);
    
    // 查 Data Layer 状态
    void SetDataLayerRuntimeState(...);
};
```

实战:玩家位置变化时,WP 自动管理 cell 加载/卸载,**你不需要手动调任何 API**。

### 7.3.5.2 流送源默认行为

每个 PlayerController 自动注册为流送源。多人游戏(2 player 分屏 / 网络)所有玩家位置都贡献流送范围。

### 7.3.5.3 何时阻塞

某些情况(初始加载、teleport)WP 会阻塞 GameThread 等关键 cell 加载完。`r.WorldPartition.MaxFramesToWaitForCell` 等 cvar 控制阈值。

## 7.3.6 World Partition vs 传统 Streaming

| 维度 | 传统 Streaming | World Partition |
|---|---|---|
| 文件结构 | 主 Level + N 个 Sub-Level .umap | 主 Level + 自动切分的 cell .uasset |
| Editor 工作流 | 美术手动切分 | 自动按网格 |
| Sub-Level 数量 | 几十(管得动) | 几百到几千(自动) |
| Lightmap | 跨 Level 复杂 | 自动跨 cell 处理 |
| HLOD | 手动配置 | 自动生成 |
| Data Layers | 不支持 | ✓ |
| 运行时 API | LoadStreamLevel() | RegisterStreamingSource() |
| 适用 | 中小关卡 / 已有项目 | 大型 / 开放世界 |
| 5.x 推荐 | 仍可用 | ✓ |

**RTS 项目选型**:
- **小型 RTS(单战场)**:不需 WP,普通 World 即可
- **大型 RTS(战役、大地图)**:启用 WP,管理大量地形 / 资源点

## 7.3.7 World Partition 与 Mass 的关系

### 7.3.7.1 Mass entity **不**参与 WP cell

Mass entity 不是 Actor,不被 WP 管理。50K 单位无论分布在哪个 cell 都"在 Mass Subsystem 里",不被 cell 加载/卸载影响。

### 7.3.7.2 RTS 实战:Static 部分走 WP,Dynamic 走 Mass

```
WP 管理:
   - 地形 (Landscape)
   - 建筑 (StaticMeshActor)
   - 资源点 (RTS 自定义 Actor)
   
Mass 管理:
   - 50K 单位
   - 投射物
   - 临时效果
```

WP 加载/卸载远处建筑,但 Mass 单位**永远在内存**(数量级小,~200 字节/entity × 50K = 10MB)。

### 7.3.7.3 单位"出 WP 加载范围"怎么办

实战需要:玩家镜头远离某区域,该区域的 Mass 单位**也应该 LOD 降级**(不渲染,但仍模拟)。

Mass `URepresentationProcessor`(§20.2)实现:
- 每帧计算 entity 到玩家的距离
- 远的 entity 切换"LOD Off"(不创建渲染 instance,但 Mass 数据仍在)
- 极远的 entity 可以"sleep"(暂停 AI tick)

WP cell 范围与 Mass LOD 范围**独立调谐**,不互相干扰。

## 7.3.8 调试 World Partition

### 7.3.8.1 Editor 里看 cell

Editor → World Partition window,看 cell 网格、Loaded / Unloaded 状态。点 cell 显示其内 Actor。

### 7.3.8.2 运行时 cvar

```
wp.Runtime.HLOD 0/1                    # 关 HLOD(强制加载真 cell)
wp.Runtime.DebugDrawCells 1            # 屏幕上画 cell 边界
wp.Runtime.DebugDrawHLODs 1            # 显示 HLOD 替代
```

### 7.3.8.3 看 streaming 状态

`stat WorldPartition` 显示 cell 数量、当前加载状态。

## 7.3.9 实操与下一节预告

### 实操

新建一个 RTS 项目时:
- 关卡<2km × 2km → 不开 WP
- 关卡 ≥ 2km × 2km → 启用 WP
- 大型战役多关卡 → 每个关卡独立选择

不要"为了 WP 而 WP" — 小关卡传统 Level 完全够用,WP 反而增加复杂度。
