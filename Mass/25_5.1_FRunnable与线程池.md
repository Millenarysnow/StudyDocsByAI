## 5.1.1 浅入:UE 的并发抽象有几层

UE 提供的并发设施按"**抽象层次**"分:

```
高层(易用,功能丰富)
   │
   │  Mass Processor 调度(自带依赖图,§18)
   │  Async / Future / TFuture
   │  UE::Tasks(5.0+ 推荐,§5.3)
   │  TaskGraph(传统主流,§5.2)
   │  FQueuedThreadPool(简单后台任务)
   │  FRunnableThread / FRunnable(原始线程)
   │  FPlatformProcess::CreateThread(平台层)
   │  std::thread / pthread(C++ 标准 / OS)
   │
低层(贴近 OS,功能少)
```

**纪律**:**优先用高层 API**。低层 API 是"逃生通道",当高层不能满足特殊需求时才用。

这一节聚焦最底两个抽象 —— `FRunnable` / `FRunnableThread` / `FQueuedThreadPool`。它们是 TaskGraph(§5.2)的底层。

## 5.1.2 `FRunnable` —— "我要在线程上跑什么"

`Engine/Source/Runtime/Core/Public/HAL/Runnable.h:19`:

```cpp
class FRunnable
{
public:
    virtual bool Init() { return true; }              // 线程启动时调,返回 false 终止
    virtual uint32 Run() = 0;                          // 主循环
    virtual void Stop() {}                             // 请求终止(从其它线程调)
    virtual void Exit() {}                             // 退出清理
    
    virtual class FSingleThreadRunnable* GetSingleThreadInterface() { return nullptr; }
    
    virtual ~FRunnable() {}
};
```

`FRunnable` 是**接口**(纯虚)。你继承它,实现自己的"线程逻辑"。

### 5.1.2.1 生命周期 4 个虚函数

```
线程创建
   ↓
Init()       ← 在新线程上下文里调!不是创建者线程
   ↓ 返回 true
Run()        ← 真正干活的循环
   ↓ 返回(从 Run 自然退出 或 Stop 触发)
Exit()       ← 在新线程上下文里调
   ↓
线程退出
```

### 5.1.2.2 一个最小例子

```cpp
class FMyWorker : public FRunnable
{
    bool bShouldStop = false;
    FEvent* WorkAvailable;        // 唤醒事件
    
public:
    FMyWorker()
    {
        WorkAvailable = FPlatformProcess::GetSynchEventFromPool();
    }
    
    virtual bool Init() override
    {
        // 在新线程的上下文里:setup TLS、加 log category 等
        FMemory::SetupTLSCachesOnCurrentThread();   // §1.5
        return true;
    }
    
    virtual uint32 Run() override
    {
        while (!bShouldStop)
        {
            WorkAvailable->Wait();      // 阻塞等待工作
            
            if (bShouldStop) break;
            
            DoActualWork();
        }
        return 0;
    }
    
    virtual void Stop() override
    {
        bShouldStop = true;
        WorkAvailable->Trigger();       // 唤醒
    }
    
    virtual void Exit() override
    {
        FMemory::ClearAndDisableTLSCachesOnCurrentThread();
    }
};
```

注意 `Stop()` 在**创建者线程**调,`Run()` 在**新线程**跑。`bShouldStop` 是跨线程通信(应该 `std::atomic<bool>` 更安全)。

### 5.1.2.3 `Stop` 的语义不是"立即终止"

`Stop()` 只是**请求**线程退出。它不强行 kill。你必须在 `Run()` 循环里**主动检查** `bShouldStop` 并退出。

OS 级 kill thread 是**不安全**的(对象可能在持锁、释放未完成),UE 完全避免。

## 5.1.3 `FRunnableThread` —— OS 线程的抽象

`Engine/Source/Runtime/Core/Public/HAL/RunnableThread.h:19`:

```cpp
class FRunnableThread
{
public:
    static CORE_API FRunnableThread* Create(
        FRunnable* InRunnable,
        const TCHAR* ThreadName,
        uint32 InStackSize = 0,
        EThreadPriority InThreadPri = TPri_Normal,
        uint64 InThreadAffinityMask = FPlatformAffinity::GetNoAffinityMask(),
        EThreadCreateFlags InCreateFlags = EThreadCreateFlags::None);

    virtual void SetThreadPriority(EThreadPriority NewPriority) = 0;
    virtual void Suspend(bool bShouldPause = true) = 0;
    virtual bool Kill(bool bShouldWait = true) = 0;
    virtual void WaitForCompletion() = 0;
    
    enum class ThreadType { Real, Fake, Forkable };
    virtual ThreadType GetThreadType() const;
    // ...
};
```

### 5.1.3.1 创建一个真线程

```cpp
FMyWorker* Worker = new FMyWorker();
FRunnableThread* Thread = FRunnableThread::Create(
    Worker,                                  // FRunnable
    TEXT("MyRTS_AsyncWorker"),               // 名字(在 debugger / Insights 里显示)
    0,                                        // StackSize 0 = 默认(通常 1MB)
    TPri_Normal,                              // 优先级
    FPlatformAffinity::GetNoAffinityMask(),   // 亲和性(no = OS 自由调度)
    EThreadCreateFlags::None);

// 之后 Worker 在新线程上跑 Init -> Run -> Exit
// 关闭:
Thread->Kill(/*bShouldWait*/ true);          // 调 FRunnable::Stop + 等线程退出
delete Thread;
delete Worker;
```

### 5.1.3.2 `EThreadPriority`

```cpp
enum EThreadPriority
{
    TPri_Normal,
    TPri_AboveNormal,
    TPri_BelowNormal,
    TPri_Highest,
    TPri_Lowest,
    TPri_SlightlyBelowNormal,
    TPri_TimeCritical,
    TPri_Num
};
```

99% 用 `TPri_Normal`。`TPri_TimeCritical` 是音频线程级别的"绝不能被抢占"(实际能,但 OS 优先调度)。

### 5.1.3.3 `EThreadCreateFlags`

```cpp
enum class EThreadCreateFlags : int8
{
    None = 0,
    AllowAudioWorkerThread = 1 << 0,    // 允许音频系统调用
    // ... 其它平台特定 ...
};
```

通常 `None`。

### 5.1.3.4 `ThreadType::Real / Fake / Forkable`

- **Real**:真 OS 线程
- **Fake**:`FPlatformProcess::SupportsMultithreading() == false` 时(主机 / 嵌入式),`FRunnableThread::Create` 返回**Fake** thread,在主线程 tick 时跑 `FRunnable`。这让代码**不需要 #if 单线程平台**也能跨平台。
- **Forkable**:服务器 fork 后才变 Real,父进程是 Fake。给 prefork 优化用。

### 5.1.3.5 实战:启动期 setup / 退出 cleanup

```cpp
class FMyWorker : public FRunnable
{
    virtual bool Init() override
    {
        // 关键:这些在新线程上下文里跑
        FMemory::SetupTLSCachesOnCurrentThread();         // §1.5 TLS
        FPlatformMisc::BeginNamedEvent(FColor::Cyan, "MyWorker startup");   // profiling 锚点
        return true;
    }
    
    virtual void Exit() override
    {
        FMemory::ClearAndDisableTLSCachesOnCurrentThread();
    }
};
```

漏掉 `SetupTLSCachesOnCurrentThread` 后,你这个线程上的 `FMemory::Malloc` 全部走慢路径(锁全局池,§1.5)。

## 5.1.4 OS 同步原语:`FEvent`、`FCriticalSection`

线程间通信常用:

### 5.1.4.1 `FEvent`(信号量)

```cpp
FEvent* E = FPlatformProcess::GetSynchEventFromPool();   // 从池里拿一个

// 线程 A
E->Wait();              // 阻塞等待
// 或带超时
E->Wait(100);           // 等 100ms,超时返回

// 线程 B
E->Trigger();           // 唤醒一个等待者

FPlatformProcess::ReturnSynchEventToPool(E);   // 用完归还
```

`FEvent` 默认是 manual reset(触发后保持触发态,直到 Reset)。auto reset 用 `GetSynchEventFromPool(/*bIsManualReset*/ false)`。

### 5.1.4.2 `FCriticalSection`(mutex)

```cpp
FCriticalSection Lock;

// RAII 写法
{
    FScopeLock S(&Lock);     // 获得锁
    // 临界区
}   // 析构时释放
```

**性能**:Windows 上 `FCriticalSection` 是 `CRITICAL_SECTION`(用户态 spin + 内核态 wait),非竞争情况下纳秒级。

### 5.1.4.3 5.x 推荐用 `std::mutex` / `std::condition_variable`

5.x 倾向 std 同步原语。新代码:

```cpp
#include <mutex>
#include <condition_variable>

std::mutex M;
std::condition_variable CV;
bool bReady = false;

// 线程 A
{
    std::unique_lock<std::mutex> Lock(M);
    CV.wait(Lock, [&] { return bReady; });
}

// 线程 B
{
    std::lock_guard<std::mutex> Lock(M);
    bReady = true;
}
CV.notify_one();
```

UE 自家 `FEvent` / `FCriticalSection` 仍可用,**但官方倾向 std**。这条纪律和 §1.1.7 的 `FPlatformAtomics` deprecated 同源。

## 5.1.5 `FQueuedThreadPool` —— 简单后台任务池

`Engine/Source/Runtime/Core/Public/Misc/QueuedThreadPool.h:104`:

```cpp
class FQueuedThreadPool
{
public:
    static CORE_API FQueuedThreadPool* Allocate();
    
    virtual bool Create(uint32 InNumQueuedThreads, uint32 StackSize = (32 * 1024), 
                         EThreadPriority ThreadPriority = TPri_Normal, 
                         const TCHAR* Name = TEXT("UnknownThreadPool")) = 0;
    
    virtual void AddQueuedWork(class IQueuedWork* InQueuedWork, EQueuedWorkPriority InPriority = EQueuedWorkPriority::Normal) = 0;
    virtual bool RetractQueuedWork(class IQueuedWork* InQueuedWork) = 0;
    
    virtual int32 GetNumThreads() const = 0;
    virtual void Destroy() = 0;
};
```

设计:**N 个 worker 线程 + 一个工作队列**。提交 `IQueuedWork` 到队列,空闲 worker 拿走执行。

### 5.1.5.1 `IQueuedWork` 接口

```cpp
class IQueuedWork
{
public:
    virtual void DoThreadedWork() = 0;     // worker 线程调
    virtual void Abandon() = 0;             // 工作被取消时调
    virtual ~IQueuedWork() {}
};
```

### 5.1.5.2 `GThreadPool` —— 全局共享池

```cpp
extern CORE_API FQueuedThreadPool* GThreadPool;        // 通用任务池
extern CORE_API FQueuedThreadPool* GLargeThreadPool;   // 长任务池(资产加载用)
extern CORE_API FQueuedThreadPool* GIOThreadPool;      // IO 任务池
```

启动期被 UE 创建,worker 数 = `FPlatformMisc::NumberOfWorkerThreadsToSpawn()`。**绝大多数后台任务用 GThreadPool 即可**,不要自己再 Allocate。

### 5.1.5.3 何时用 FQueuedThreadPool

✅ **批量独立任务**:几百个互相独立的小任务(资产解压、贴图压缩、shader 编译)
✅ **不需要任务依赖图**:每个 task 自包含

❌ **任务间有依赖**:用 TaskGraph(§5.2)
❌ **需要 GameThread / RenderThread 调度**:用 TaskGraph

### 5.1.5.4 实战:并行处理一批资产

```cpp
class FAssetLoadWork : public IQueuedWork
{
    FString Path;
public:
    FAssetLoadWork(const FString& InPath) : Path(InPath) {}
    
    virtual void DoThreadedWork() override
    {
        FMemory::SetupTLSCachesOnCurrentThread();
        // 实际加载
        // ...
        delete this;        // 自删除(常见模式)
    }
    
    virtual void Abandon() override { delete this; }
};

// 提交一批
for (FString& P : AssetPaths)
{
    GThreadPool->AddQueuedWork(new FAssetLoadWork(P));
}
```

## 5.1.6 `FAsyncTask<T>` / `FAutoDeleteAsyncTask<T>` —— 模板辅助

直接写 `IQueuedWork` 重复代码多。UE 提供模板:

```cpp
class FMyWork : public FNonAbandonableTask
{
    int32 Data;
public:
    FMyWork(int32 InData) : Data(InData) {}
    
    void DoWork()
    {
        // 真正的工作
    }
    
    FORCEINLINE TStatId GetStatId() const
    {
        RETURN_QUICK_DECLARE_CYCLE_STAT(FMyWork, STATGROUP_ThreadPoolAsyncTasks);
    }
};

// 提交 + 自删除
(new FAutoDeleteAsyncTask<FMyWork>(42))->StartBackgroundTask();
```

或保留句柄查询完成:

```cpp
FAsyncTask<FMyWork>* Task = new FAsyncTask<FMyWork>(42);
Task->StartBackgroundTask();
// 后续
if (Task->IsDone())
{
    // 拿结果
    int32 Result = Task->GetTask().GetResult();
    delete Task;
}
```

## 5.1.7 各种"并发"的对比

| API | 抽象层次 | 任务依赖 | 自带线程池 | 适合场景 |
|---|---|---|---|---|
| `std::thread` | OS 直接 | 无 | 无 | 第三方库,绕开 UE |
| `FRunnableThread::Create` | OS + UE TLS | 无 | 无 | 长期运行的"专用"线程(网络、AI 主循环) |
| `FQueuedThreadPool` | 中等 | 无 | ✓ GThreadPool | 批量独立后台任务 |
| `TaskGraph`(§5.2) | 高 | ✓ | ✓ Named threads + Worker | 大多数游戏并发 |
| `UE::Tasks`(§5.3) | 高 | ✓ pipe | ✓ | 5.x 推荐,Task graph 后继 |
| `Async<T>(...)` | 包装 | ✓ Future | ✓ | "我要异步算个值" |

**纪律**:**默认用 TaskGraph 或 UE::Tasks**。`FRunnableThread` 仅在你需要"独占一个 OS 线程长期跑"(网络主循环、AI tick driver)时用。

## 5.1.8 Mass / RTS 视角下的并发选型

### (1)Mass Processor 永远走 TaskGraph

```cpp
// ❌ 不要这样
class UMyMassProcessor : public UMassProcessor
{
    virtual void Execute(FMassEntityManager& EntityManager, FMassExecutionContext& Context) override
    {
        FRunnableThread::Create(...);    // 错!Mass 调度系统自己有线程
    }
};

// ✅ Mass 自带 ParallelForEachEntityChunk,走 TaskGraph
ParallelForEachEntityChunk(EntityManager, Context, [](...) { /* 处理 */ });
```

Mass 的并行调度内部用 TaskGraph,worker 线程已经 setup TLS / stat / trace。你自起线程会绕开这套基础设施。

### (2)长期网络后台线程可以用 FRunnableThread

如果你 RTS 的网络层需要"独立线程跑 socket 阻塞 IO":

```cpp
class FRTSNetThread : public FRunnable
{
    virtual uint32 Run() override
    {
        while (!bStop)
        {
            int32 N = recv(Socket, Buf, sizeof(Buf), 0);    // 阻塞调用
            if (N > 0) ProcessIncoming(Buf, N);
        }
        return 0;
    }
};
```

这种"专用阻塞线程"是 `FRunnableThread` 的合法场景。**用 TaskGraph 反而别扭**(TaskGraph 是任务调度,不擅长长期 hold 一个线程做阻塞 IO)。

### (3)RTS 异步资产加载用 FQueuedThreadPool 或 5.x AsyncLoading

5.x 的 `UAssetManager` / `FStreamableManager` 已经封装好异步加载,**不要自己写**:

```cpp
TSharedPtr<FStreamableHandle> Handle = UAssetManager::GetStreamableManager().RequestAsyncLoad(
    SoftPath, 
    FStreamableDelegate::CreateLambda([](){ /* 加载完成 */ }));
```

底层走 GIOThreadPool。你不需要碰 IQueuedWork。

### (4)Mass 之外的"每帧重 task"也走 TaskGraph

例如你 RTS 的雾战(FogOfWar)更新:

```cpp
// ✅ TaskGraph
auto FogTask = TGraphTask<FFogUpdateTask>::CreateTask().ConstructAndDispatchWhenReady();
// 后续依赖
auto RenderTask = TGraphTask<FFogRenderTask>::CreateTask({ FogTask }).ConstructAndDispatchWhenReady();
```

不要自起 FRunnableThread 跑雾战(线程整帧只工作几毫秒,大部分时间空转浪费)。

## 5.1.9 实操:启动一个自定义线程

```cpp
class URTSGameSubsystem : public UWorldSubsystem
{
    FRunnableThread* MyThread = nullptr;
    FRTSNetThread*   MyRunnable = nullptr;

public:
    virtual void Initialize(FSubsystemCollectionBase& Collection) override
    {
        MyRunnable = new FRTSNetThread();
        MyThread = FRunnableThread::Create(MyRunnable, TEXT("RTS_NetThread"));
    }

    virtual void Deinitialize() override
    {
        if (MyThread)
        {
            MyThread->Kill(/*bShouldWait*/ true);
            delete MyThread;
            MyThread = nullptr;
        }
        delete MyRunnable;
        MyRunnable = nullptr;
    }
};
```

**关键纪律**:
- Subsystem `Deinitialize` 时**必须** kill + 等待 + 释放
- 漏掉一个,进程退出可能 leak / hang
