# §0.3 调试与剖析工具

> **本节地图**:模块零的最后一节。把 UE5 自带的"诊断工具箱"一次摆开 — 日志、stat、trace、cvar、Insights、Visual Logger。后面**每一节**讲源码时都会用这些工具来验证"代码到底跑了没、跑得多快、跑了几次"。
>
> **预备知识**:§0.1 / §0.2(必读)。
>
> **读完之后你能做到**:
> - 在自己的代码里熟练插入 log / stat / trace / cvar
> - 用 Unreal Insights 抓帧 + 读懂主要面板
> - 写自定义的 Trace Channel(后面 RTS 给 Mass / 战斗系统用)
> - 知道哪种工具适合哪种问题 — 不会"看 stat 找内存泄漏"这种错配
> - 调试期能在十秒内回答"这个函数被调了几次、各调了多久"

## 0.3.1 一张工具适配表(先看这里)

| 你想知道 | 用什么 |

| "这段代码到底跑没跑" | `UE_LOG` |

## 0.3.2 日志系统:UE_LOG 的完整面貌

### 0.3.2.1 三件套:Category + Verbosity + Format

```cpp
// 头文件:声明一个日志分类(放在你的 .h 或 Module.h)
DECLARE_LOG_CATEGORY_EXTERN(LogMyRTS, Log, All);

// 源文件:定义这个分类(放在 Module 的某个 .cpp,通常是 Module.cpp)
DEFINE_LOG_CATEGORY(LogMyRTS);

// 使用
UE_LOG(LogMyRTS, Log, TEXT("Spawned %d entities at %s"), Count, *Location.ToString());
```

`DECLARE_LOG_CATEGORY_EXTERN` 在 `Engine/Source/Runtime/Core/Public/Logging/LogMacros.h:361` 展开后:

```cpp
// LogMacros.h:361
#define DECLARE_LOG_CATEGORY_EXTERN(CategoryName, DefaultVerbosity, CompileTimeVerbosity) \
    extern struct FLogCategory##CategoryName : public FLogCategory<ELogVerbosity::DefaultVerbosity, ELogVerbosity::CompileTimeVerbosity> \
    { \
        UE_FORCEINLINE_HINT FLogCategory##CategoryName() : FLogCategory(TEXT(#CategoryName)) {} \
    } CategoryName;
```

**含义**:每个 LogCategory 是一个**全局静态对象**,自带名字 + 默认 verbosity + 编译期 verbosity。`DEFINE_LOG_CATEGORY(LogMyRTS)` 就是给这个对象一个实体定义。

### 0.3.2.2 Verbosity 等级

```cpp
enum ELogVerbosity::Type
{
    NoLogging   = 0,  // 关闭
    Fatal       = 1,  // 立即崩溃 + 写日志
    Error       = 2,  // 红色,但不崩
    Warning     = 3,  // 黄色
    Display     = 4,  // 永远显示(即使 verbosity 关到 Log)
    Log         = 5,  // 默认,正常日志
    Verbose     = 6,  // 详细
    VeryVerbose = 7,  // 极详细
};
```

`DECLARE_LOG_CATEGORY_EXTERN(LogMyRTS, Log, All)`:
- 第二参 `Log` = 运行时默认 verbosity(可被 INI 或控制台覆盖)
- 第三参 `All` = 编译期最大 verbosity(决定哪些 UE_LOG **能进**二进制)

**纪律**:
- Shipping 包,通常希望 `Verbose` / `VeryVerbose` 在编译期就被裁掉。可写 `DECLARE_LOG_CATEGORY_EXTERN(LogMyRTS, Log, Log)` — 编译期最高 Log,Verbose 直接消失。
- Display 等级特殊:即使运行时 verbosity 调到 `NoLogging`,Display 还是会输出。**用来标识"启动 banner"或"上线检查日志"**。

### 0.3.2.3 运行时调整 verbosity

控制台输入:
```
Log LogMyRTS Verbose                  // 把这个分类提到 Verbose
Log LogMyRTS NoLogging                // 关掉
Log LogMyRTS reset                    // 恢复默认
LogCmds                               // 列出所有分类当前 verbosity
```

INI 配置(`DefaultEngine.ini`):
```ini
[Core.Log]
LogMyRTS=Verbose
LogTemp=Warning      ; 把不重要的 LogTemp 压到 Warning
```

### 0.3.2.4 屏幕日志:GEngine->AddOnScreenDebugMessage

仅用于运行时**调试可视化**,会打到游戏画面上:

```cpp
if (GEngine)
{
    GEngine->AddOnScreenDebugMessage(
        -1,                               // Key (-1 = 唯一新条目, 整数=覆盖同 key)
        5.f,                              // 显示时间(秒)
        FColor::Yellow,
        FString::Printf(TEXT("Entity count: %d"), Count));
}
```

**坑**:屏幕日志不进 .log 文件,只在屏幕上瞬时显示。**不要**用它做"事后分析",请用 UE_LOG。

### 0.3.2.5 RTS 项目的日志分类规划

```cpp
// MyRTSCore/Public/MyRTSLog.h
DECLARE_LOG_CATEGORY_EXTERN(LogRTSCore, Log, All);
DECLARE_LOG_CATEGORY_EXTERN(LogRTSMass, Log, All);
DECLARE_LOG_CATEGORY_EXTERN(LogRTSNetwork, Log, All);
DECLARE_LOG_CATEGORY_EXTERN(LogRTSCommand, Log, All);
DECLARE_LOG_CATEGORY_EXTERN(LogRTSRender, Log, All);
DECLARE_LOG_CATEGORY_EXTERN(LogRTSAI, Log, All);
```

每个子系统一个 LogCategory。这样上线后看玩家发回来的 .log,你能精准筛选。

## 0.3.3 Stat 系统:每帧累计计数器

Stat 系统比 Log 更重: log 是"事件流",stat 是"每帧聚合的数字",由 GameThread 累加,可视化展示。

### 0.3.3.1 三大类 Stat

```cpp
// 1. Cycle Stat — 测时间
DECLARE_CYCLE_STAT(TEXT("MyRTS Tick"), STAT_MyRTSTick, STATGROUP_MyRTS);

// 2. Counter Stat — 计数
DECLARE_DWORD_COUNTER_STAT(TEXT("Active Entities"), STAT_RTSActiveEntities, STATGROUP_MyRTS);

// 3. Memory Stat — 测内存
DECLARE_MEMORY_STAT(TEXT("Mass Fragment Memory"), STAT_RTSFragmentMem, STATGROUP_MyRTS);
```

每个 stat 必须属于一个 **STATGROUP**,先声明:

```cpp
// 头文件里
DECLARE_STATS_GROUP(TEXT("MyRTS"), STATGROUP_MyRTS, STATCAT_Advanced);
```

### 0.3.3.2 Cycle Stat 的使用(最常用)

```cpp
void UMyMassProcessor::Execute(...)
{
    SCOPE_CYCLE_COUNTER(STAT_MyRTSTick);       // 自动测出这个 scope 的时间
    
    // ... 你的逻辑 ...
}
```

`SCOPE_CYCLE_COUNTER` 在 `Stats/Stats.h:245` 定义,展开成一个 RAII 对象,析构时把"开始-结束"差的 cycle 数累加到 stat。

游戏运行时 console 输入 `stat MyRTS`,就能看到:
```
STAT_MyRTSTick:        2.45 ms
STAT_RTSActiveEntities: 4823
```

### 0.3.3.3 Counter Stat / Memory Stat

```cpp
// 设置 / 增量
SET_DWORD_STAT(STAT_RTSActiveEntities, EntityCount);
INC_DWORD_STAT(STAT_RTSActiveEntities);
DEC_DWORD_STAT(STAT_RTSActiveEntities);
INC_DWORD_STAT_BY(STAT_RTSActiveEntities, BatchSize);

// 内存
SET_MEMORY_STAT(STAT_RTSFragmentMem, BytesUsed);
INC_MEMORY_STAT_BY(STAT_RTSFragmentMem, AllocatedSize);
DEC_MEMORY_STAT_BY(STAT_RTSFragmentMem, FreedSize);
```

### 0.3.3.4 控制台命令

```
stat MyRTS              ; 在屏幕显示 MyRTS group
stat MyRTS -hide        ; 隐藏
stat unit               ; 帧时间总览(必备)
stat fps                ; FPS
stat scenerendering     ; 渲染统计
stat memory             ; 内存分类
stat slow 0.5           ; 仅显示耗时 > 0.5ms 的 cycle stat
stat dumpave            ; dump 平均值
stat dumpframe          ; dump 当前帧
stat startfile / stopfile  ; 录制 .ue4stats 文件供事后分析
```

### 0.3.3.5 Stat 的局限

stat 是"每帧聚合"。它告诉你"这一帧 MyRTSTick 总共 2.45ms",**但不告诉你**:
- 这 2.45ms 内部分布到哪些子函数
- 不同帧之间的具体波动
- 是哪个 worker 线程跑的

要回答这些,你需要 **Trace + Insights**(下一节)。

## 0.3.4 Trace 系统:你会用一辈子的工具

Stat 给"每帧汇总数字"。Trace 给"每事件的精确时间线"。Trace 是 5.x 推力推的新系统,Insights 是它的可视化前端。

### 0.3.4.1 第一个 Trace 宏

```cpp
void UMyMassProcessor::Execute(...)
{
    TRACE_CPUPROFILER_EVENT_SCOPE(MyRTS_MassProcessor_Execute);
    
    // 你的逻辑
}
```

宏定义在 `Engine/Source/Runtime/Core/Public/ProfilingDebugging/CpuProfilerTrace.h:449`:

```cpp
#define TRACE_CPUPROFILER_EVENT_SCOPE(Name) \
    TRACE_CPUPROFILER_EVENT_SCOPE_CONDITIONAL(Name, true)
```

这个宏在 `CPUPROFILERTRACE_ENABLED` 为 0 时直接展开为空,所以 Shipping 不带任何开销。

`Name` 是一个**符号字面量**(不是字符串),`TRACE_CPUPROFILER_EVENT_SCOPE_TEXT(...)` 才接受字符串。两者用途:
- 静态名:`TRACE_CPUPROFILER_EVENT_SCOPE(MyName)` — 编译期就知道,最快
- 动态名:`TRACE_CPUPROFILER_EVENT_SCOPE_TEXT(*FString::Printf(TEXT("Foo_%d"), Idx))` — 运行时拼接,更灵活但更慢

### 0.3.4.2 启动 Trace

启动 Editor / Game 时加命令行:
```
UnrealEditor.exe MyRTS.uproject -trace=cpu,frame,bookmark,counter
```

或者 Editor 启动后,通过 **Trace Status** 工具栏(右下角小图标)随时开启。

收到的 trace 文件落到:
```
%LOCALAPPDATA%/UnrealEngine/Common/UnrealTrace/Store/<时间戳>.utrace
```

或在游戏控制台里:
```
Trace.Start cpu,frame,bookmark
Trace.Stop
Trace.SnapshotFile mytrace.utrace      ; 立即落盘当前内存里的 trace
```

### 0.3.4.3 Trace Channel 速查

启动时 `-trace=` 后面跟 channel 列表,常用值:

| Channel | 内容 |
|---|---|
| `cpu` | 所有 `TRACE_CPUPROFILER_EVENT_SCOPE` |
| `frame` | 每帧时间线锚点 |
| `gpu` | GPU draw 时间 |
| `task` | TaskGraph 任务调度 |
| `mass` | Mass 模块自带的 trace |
| `bookmark` | 关键事件锚点(BeginPlay / Replicate / 自定义) |
| `counter` | 计数器(自定义指标的时序图) |
| `loadtime` | 加载时间 |
| `gc` | 垃圾回收 |
| `render` | 渲染管线 |
| `slate` | Slate / UMG |
| `audio` | 音频 |
| `net` | 网络 |
| `physics` | 物理 |

**RTS 项目调试套餐**:`cpu,frame,bookmark,counter,task,mass,gc,net`

### 0.3.4.4 自定义 Trace Channel(进阶)

为 RTS 项目注册自己的 channel:

```cpp
// MyRTSTrace.h
#include "Trace/Trace.h"
#include "Trace/Trace.inl"

UE_TRACE_CHANNEL_EXTERN(RTSChannel, MYRTSCORE_API);

// MyRTSTrace.cpp
UE_TRACE_CHANNEL_DEFINE(RTSChannel)
```

使用:
```cpp
TRACE_CPUPROFILER_EVENT_SCOPE_ON_CHANNEL(MyRTS_FogOfWar_Update, RTSChannel);
```

启动:
```
-trace=cpu,frame,RTSChannel
```

**好处**:你可以**只**抓取 RTS 自己的 scope,不被 Engine 自己的 cpu trace 淹没。

### 0.3.4.5 Counter Trace(时序计数器)

```cpp
// 声明
TRACE_DECLARE_INT_COUNTER_EXTERN(RTSEntityCount);
// MyRTSTrace.cpp 里
TRACE_DECLARE_INT_COUNTER(RTSEntityCount, TEXT("RTS/EntityCount"));

// 每帧更新
TRACE_COUNTER_SET(RTSEntityCount, EntityCount);
TRACE_COUNTER_INCREMENT(RTSEntityCount);
TRACE_COUNTER_DECREMENT(RTSEntityCount);
TRACE_COUNTER_ADD(RTSEntityCount, Delta);
```

Insights 里这些 counter 会变成时序图,你能看到"RTS Entity Count 在 60 秒内的曲线"。**RTS 必装**:每个关键指标(在场单位、命令队列长度、网络包率)都注册一个 counter。

### 0.3.4.6 Bookmark(打锚点)

```cpp
TRACE_BOOKMARK(TEXT("Battle Start"));
TRACE_BOOKMARK(TEXT("Wave %d started"), WaveIndex);
```

Insights 时间轴上会显示**竖线 + 标签**。事后看 trace 时,你能在分钟级时间线上一眼定位到关键事件。

**RTS 实战**:游戏关键事件全部 bookmark — 单位选择、命令下达、技能释放、单位死亡批次、网络断连。

## 0.3.5 Unreal Insights 实战工作流

### 0.3.5.1 启动与加载

```
Engine/Binaries/Win64/UnrealInsights.exe
```

打开后,左边是 Trace Store(刚抓的文件列表),双击加载。

### 0.3.5.2 主要面板

**1. Timing Insights(主战场)**

- 顶部时间轴:可拖拽缩放
- 中间多条**轨道**:每个 Worker 线程一条
- 鼠标悬停事件:显示该 scope 的耗时、命中次数、调用栈
- **过滤**:输入框过滤 scope 名(`MyRTS_*` 只看 RTS 相关)
- **聚合**:"Aggregation" 视图把同名 scope 聚合成一行,看"这个 scope 全帧累计 / 平均 / 最大"

**2. Frame Bar**

每帧一条柱,颜色表示帧时间 — 绿色 < 16.6ms,黄色 < 33.3ms,红色更长。点一帧切到该帧时间线。

**3. Tasks(任务图)**

如果你 trace 了 `task` channel,这里显示 TaskGraph 的依赖关系图。后面 §5 / §18 看 Mass 并行调度时极有用。

**4. Counters Panel**

时序图,展示所有 `TRACE_COUNTER_*` 注册的指标。

**5. Memory Insights(独立 tab)**

需要在启动时加 `-trace=memory`,代价高,只在排查内存问题时开。能给到:
- 每个 scope 的分配量
- 内存类别(LLM tag)分布
- 分配栈(Calltree)

**6. Bookmarks Panel**

所有 `TRACE_BOOKMARK` 列表,点一项跳到对应时间。

### 0.3.5.3 一个真实的诊断流程示例

**场景**:你的 RTS 5K 单位时帧时间从 8ms 涨到 22ms,不知道哪里慢。

1. 启动 `-trace=cpu,frame,bookmark,counter,mass,task`,玩到 5K 单位场景
2. 拷出 .utrace,Insights 打开
3. 在 Frame Bar 里找一个 22ms 的帧,点进去
4. 在 Timing Insights 里看主线程,找最大的红色 scope
5. 假设看到 `MyRTS_PathfindProcessor_Execute = 14ms`,**抓住它**
6. 双击展开,看子 scope。可能内部有 `MyRTS_AStar_Search = 13.5ms`
7. 看 Tasks 面板,这个 Processor 是单线程跑的还是并行的?
8. 决策:加并行(Mass 自带 ParallelForEachEntityChunk),或换流场寻路

**关键纪律**:**永远先 trace 后改代码**。靠想象优化往往优化错地方。

### 0.3.5.4 Insights 高级:对比两个 trace

Insights 可以同时打开两个 trace,左右对比"优化前 vs 优化后"。回归测试时极重要。

## 0.3.6 Console Variable / Console Command

UE 自带一套强大的 cvar/cmd 系统,让你**无需改代码、无需重启**就能调整运行时行为。

### 0.3.6.1 注册 Console Variable

```cpp
// MyMassProcessor.cpp
static TAutoConsoleVariable<int32> CVarRTSMaxParallel(
    TEXT("rts.MaxParallelProcessors"),       // 名字
    8,                                        // 默认值
    TEXT("Max parallel Mass processors. Set to 0 to force single-threaded."),
    ECVF_Default                              // 标志
);

void UMyMassProcessor::Execute(...)
{
    const int32 MaxParallel = CVarRTSMaxParallel.GetValueOnGameThread();
    // ...
}
```

控制台:
```
rts.MaxParallelProcessors 4
rts.MaxParallelProcessors            ; 查看当前值
```

### 0.3.6.2 ECVF_* 标志

```cpp
ECVF_Default              // 默认,可读可写
ECVF_ReadOnly             // 只读,启动后不能改(用于性能开关)
ECVF_Cheat                // 作弊类,Shipping 默认隐藏
ECVF_Scalability          // 性能档位类,Editor 显示在 Scalability 设置
ECVF_RenderThreadSafe     // 渲染线程读取安全
```

**线程安全坑**:`GetValueOnGameThread()` 只能在 GameThread 调,`GetValueOnRenderThread()` / `GetValueOnAnyThread()` 在对应线程调。Mass Processor 跑在 worker 线程时用 `GetValueOnAnyThread()`(标志要带 `ECVF_RenderThreadSafe` 或类似)。

### 0.3.6.3 cvar 的回调

变量被改时触发函数:

```cpp
static TAutoConsoleVariable<int32> CVarRTSDebug(
    TEXT("rts.Debug"),
    0,
    TEXT("Toggle RTS debug visualization. 0=off, 1=basic, 2=verbose"),
    FConsoleVariableDelegate::CreateLambda([](IConsoleVariable* Var)
    {
        UE_LOG(LogRTSCore, Log, TEXT("Debug level changed to %d"), Var->GetInt());
        // 重新初始化某些资源
    }),
    ECVF_Default
);
```

### 0.3.6.4 注册 Console Command

cvar 是"读取一个值",command 是"执行一个动作":

```cpp
// 简单形式
static FAutoConsoleCommand CmdRTSDumpEntities(
    TEXT("rts.DumpEntities"),
    TEXT("Dump all RTS entities to log."),
    FConsoleCommandDelegate::CreateStatic(&UMyDebugger::DumpAllEntities)
);

// 带参数
static FAutoConsoleCommand CmdRTSSpawnUnits(
    TEXT("rts.SpawnUnits"),
    TEXT("Spawn N test units. Usage: rts.SpawnUnits <count>"),
    FConsoleCommandWithArgsDelegate::CreateStatic(
        [](const TArray<FString>& Args)
        {
            int32 Count = (Args.Num() > 0) ? FCString::Atoi(*Args[0]) : 100;
            // ... spawn logic ...
        })
);
```

### 0.3.6.5 头文件位置

`Engine/Source/Runtime/Core/Public/HAL/IConsoleManager.h` 是 cvar/cmd 的核心头。注释丰富,可以通读一次。

### 0.3.6.6 RTS 实战:一组必备 cvar

```cpp
// 调试可视化
rts.Debug.DrawEntityHandles    // 在每个 entity 上画 ID
rts.Debug.DrawSelectionLine    // 画选择射线
rts.Debug.DrawCommandPath      // 画命令路径
rts.Debug.DrawFog              // 显示战争迷雾掩码

// 性能开关
rts.MaxParallelProcessors      // 并行 processor 数量上限
rts.ForceLOD                   // 强制所有单位用某 LOD(0=High,3=Off)
rts.DisableMassReplication     // 关掉 Mass 网络复制(本地测试)
rts.SpawnRate                  // 单位生成速率倍数

// Profiling 辅助
rts.SimulateLag <ms>           // 模拟网络延迟
rts.SimulateUnitCount <N>      // 强制创建 N 个测试单位
```

**纪律**:每一个调试可视化、每一个性能开关都留 cvar。**永远不要**写"为了 debug 临时加个 if (true)"再忘删 — 用 cvar,提交进 git,以后随手开关。

## 0.3.7 Visual Logger:可视化的 AI 调试器

Visual Logger 是 UE 自带的"重放调试工具"。它录制游戏运行时的位置、绘图、文本,事后逐帧回放。**RTS 调 AI / 寻路必备**。

### 0.3.7.1 启动

控制台:
```
visualloggerstarttrace      ; 开始录制
visualloggerstoptrace       ; 停止
visualloggerload <file>     ; 加载历史 .vlog 文件
```

或 Editor 菜单:Window → Developer Tools → Visual Logger。

### 0.3.7.2 在代码里录入数据

```cpp
#include "VisualLogger/VisualLogger.h"

void AMyAIController::TickAI()
{
    // 文本日志
    UE_VLOG(this, LogRTSAI, Log, TEXT("Picking new target..."));

    // 画线
    UE_VLOG_SEGMENT(this, LogRTSAI, Log, GetActorLocation(), TargetLoc, FColor::Yellow,
        TEXT("Target candidate"));

    // 画框
    UE_VLOG_BOX(this, LogRTSAI, Log, FBox(StartLoc, EndLoc), FColor::Red,
        TEXT("Threat zone"));

    // 画路径
    UE_VLOG_LOCATION(this, LogRTSAI, Log, NewWaypoint, 16.f, FColor::Green,
        TEXT("Waypoint %d"), Idx);
}
```

### 0.3.7.3 RTS 实战姿势

VisualLogger 默认接受 Actor / Controller 作为日志主体。Mass Entity 不是 UObject,要自己实现 logger entity:

```cpp
// 让 Subsystem 当代理 logger
void UMyMassDebugSubsystem::Tick(float DeltaTime)
{
    if (!FVisualLogger::IsRecording()) return;
    
    Manager->ForEachEntity([&](const FMassEntityHandle& Handle)
    {
        const FVector Pos = GetEntityPos(Handle);
        UE_VLOG_LOCATION(this, LogRTSAI, Log, Pos, 16.f, FColor::Blue,
            TEXT("E%d"), Handle.Index);
    });
}
```

播放时你能逐帧拖动时间轴,看每个 entity 的位置变化。

## 0.3.9 内存调试(Memory Insights / LLM)

### 0.3.9.1 LLM(Low Level Memory Tracker)

启动加 `-llm`,运行时:

```
stat llm                ; 显示按 LLM tag 分类的内存
stat llmfull            ; 完整列表
```

Tag 包括:`UObject`、`Meshes`、`Textures`、`Audio`、`Animation`、`Engine`、`UI`、`RHI`...

代码里给某段代码标 LLM tag:
```cpp
LLM_SCOPE(ELLMTag::EngineMisc);
LLM_SCOPE_BYNAME("MyRTS/Mass");          // 自定义命名
```

### 0.3.9.2 Memory Insights

启动 `-trace=memory`(代价高,5x 帧时间膨胀)。Insights 加载后能看到:
- 分配热点(Calltree)
- LLM 时序
- 泄漏候选(分配但未释放的 calltree)

**不要**在性能 profiling 同时开 memory trace,两者互相干扰。

### 0.3.9.3 内存调试黄金法则

调内存问题用专用工具(LLM / Memory Insights),**不要**靠 `stat memory` 估算。`stat memory` 只显示分配器层面的总数,不告诉你哪段代码分配的。

## 0.3.11 Insights / Trace 的开发周期"工作流"

**一个迭代周期内你应该这样用工具**:

### Phase 1 — 写代码
- 关键 scope 用 `TRACE_CPUPROFILER_EVENT_SCOPE` 包起来(免费,不影响性能)
- 关键计数器用 `TRACE_COUNTER_*` 注册
- 关键事件用 `TRACE_BOOKMARK`
- 调试可视化用 cvar 控制开关
- 日志用对应 LogCategory

### Phase 2 — 本地跑
- Editor 跑 PIE,先看 `stat unit` 三个数字(GameThread / RenderThread / GPU)
- 数字超预算 → 启动 Insights trace,抓一段
- 在 Insights 找 hotspot,改代码,重测

### Phase 3 — 自动化回归
- 写一个 `-ExecCmds="rts.SpawnUnits 10000;rts.StartTrace 30s;Quit"` 的命令行启动
- 在 CI 上每天跑一次,产生 .utrace + 关键指标 csv
- 对比昨天,有 > 5% 退化就报警

这套流程是**专业级 RTS 项目**的标配,前期建立比后期补做容易十倍。

## 0.3.12 与 Mass 重构的对照思考

### (1)Mass 自带 Trace Channel

`Engine/Source/Runtime/MassEntity/Public/MassEntityTypes.h` 等里有大量 `TRACE_CPUPROFILER_EVENT_SCOPE_ON_CHANNEL(..., MassChannel)`。运行 RTS 时**永远开 mass channel**。

### (2)Mass Processor 写 Trace Scope 的纪律

每个自定义 Processor 必须:
```cpp
void UMyMassProcessor::Execute(FMassEntityManager& EntityManager, FMassExecutionContext& Context)
{
    TRACE_CPUPROFILER_EVENT_SCOPE_ON_CHANNEL(MyMassProcessor_Execute, RTSChannel);
    // ...
}
```

如果是并行执行 + 多 chunk,可以按 chunk 再嵌一层。

### (3)Counter Trace 是 RTS 的命脉

至少这几个 counter 必装:
- `RTS/EntityCount` — 当前 entity 数量
- `RTS/ActiveCommandCount` — 命令队列长度
- `RTS/SelectionCount` — 已选中单位
- `RTS/NetSendBytes/s` — 发送字节
- `RTS/NetRecvBytes/s` — 接收字节
- `RTS/RenderInstanceCount` — ISMC 实例数
- `RTS/PathRequestQueue` — 寻路请求队列长度

每个 counter 都是**生产事故的预警雷达**。某天某个 counter 异常飙升,你能立刻定位到子系统。

### (4)Visual Logger 在 Mass 上的姿势

Mass Entity 不是 UObject,Visual Logger 默认不支持。**RTS 项目应该自己写一层**适配:用一个 Subsystem 当 logger 主体,每帧把所有"调试关心"的 entity 信息 vlog 进去。后面 §28(调试稳定性)细讲。

## 0.3.13 实操提示与下一节预告

### 实操提示

- **第一周必做**:在你的 Module 启动代码里加一个 LogCategory,加一个 cvar(哪怕只是 `rts.Hello`),加一个 SCOPE_CYCLE_COUNTER。**手感建立比理论重要**。

- **不要**在 PIE 里习惯性 `stat unit` 一闪就关。把它**长开**,进入肌肉记忆,有一天屏幕角落数字突然变大你就能立刻发现。
