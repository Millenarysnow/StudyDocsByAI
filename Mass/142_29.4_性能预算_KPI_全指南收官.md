## 29.4.1 RTS 性能 KPI(立项基线)

### 客户端

```
帧率:
   ✓ 60 FPS(高端 PC)
   ✓ 30 FPS(中端 PC)
   ✓ 不 freeze > 100 ms

帧时间分布:
   - Game thread: < 10 ms
     - Mass:        < 5 ms
     - Render submit: < 3 ms
     - 其它:        < 2 ms
   - Render thread: < 8 ms
   - GPU:           < 12 ms
   
内存:
   - 工作集: < 4 GB
   - VRAM:   < 4 GB(中端 GPU)

加载时间:
   - 启动到主菜单: < 30 s
   - 进入战斗:    < 30 s
```

### 服务器

```
帧率:
   ✓ 30 Hz simulation(每帧 33 ms 预算)
   - Mass tick: < 8 ms
   - Replication: < 5 ms
   - 缓冲: 20 ms

容量:
   - 单 DS 进程 200-500 MB
   - 单服务器 32 核:跑 16-32 个 DS 进程
   - 1 台机器:128-256 玩家同时在线

带宽:
   - 每 client < 200 KB/s 上行(玩家命令)
   - 每 client < 200 KB/s 下行(snapshot)
   - 8 玩家 1 局 = 1.6 MB/s × 1000 局 = 1.6 GB/s 总带宽
```

## 29.4.2 KPI 监控

```
游戏内自动埋点:
   - Frame time histogram(P50 / P95 / P99)
   - GC pause time
   - Mass processor 各自耗时
   - Server tick rate
   - 网络 RTT / packet loss
   - 玩家 FPS / 内存 / GPU

上传到运营后台:
   - 每 5 分钟一次聚合上传
   - 异常告警:P99 > 50 ms 报警
```

## 29.4.3 退场建议

```
上线第一周:
   - 人盯监控,异常立即灰度回滚
   - QA / 客服每日报告异常
   - 玩家反馈速通道(Discord / 微博)

第二周-第一月:
   - 平稳期,继续灰度新版本
   - 周会复盘 KPI 指标趋势

第三月起:
   - 进入维护期
   - 配置 / 数值热更 / 新内容版本

性能退化风险:
   - 新单位 / 技能加入 → Mass tick 时长增长
   - 持续 profiling,守住 8 ms 红线
```
