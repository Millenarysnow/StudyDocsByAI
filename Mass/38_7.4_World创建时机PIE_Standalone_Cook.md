# §7.4 World 创建时机:PIE / Standalone / Cook 阶段差异

> **本节地图**:模块二第 7 章第 4 节。前面三节看 World / Level 静态结构。这一节看**动态**:不同启动方式(Editor / PIE / Game / Server / Cook)下 World 怎么被创建,差异在哪。
>
> 这一节看似偏 Editor 内部细节,但理解它能让你**精确诊断**"PIE 没问题但打包后崩"或"Editor 跑得通 Standalone Game 跑不通"这类常见问题。
>
> **预备知识**:§7.1 / §7.2,§6.5 GEngine 多态。
>
> **读完之后你能做到**:
> - 区分 PIE / Standalone / DedicatedServer / Cook 各自 World 创建路径

> - 知道 `IsRunningGame()` / `IsRunningCommandlet()` / `WITH_EDITOR` 各种判断

## 7.4.1 浅入:为什么"PIE 通过不代表打包通过"

很多 Editor 跑得好的代码,打包后崩或不工作。原因往往是 **PIE 与 Standalone 的 World 创建路径差异**:
- PIE 用 Editor World 的副本(`DuplicateWorldForPIE`)
- Standalone 用 `LoadObject<UWorld>` 从 .pak 加载
- 反序列化路径不同
- 某些资源 Editor 自动加载 / Cooked 包必须显式

理解这些差异 → 知道在 Editor 里能用的某些 API(找 Editor World、修改资产)在打包**完全不存在**。

## 7.4.2 五种启动方式对照

```
┌────────────────────────┬──────────────────────────────┐
│ 启动方式                │ World 创建路径                │
├────────────────────────┼──────────────────────────────┤
│ Editor 启动             │ 不创建 World(用户手动开关卡)│
│ Editor → PIE            │ Editor World 复制 → PIE World │
│ Standalone Game(Editor)│ 类似 PIE,但独立进程          │
│ Cooked Game(玩家版本)  │ LoadDefaultMap from .pak     │
│ Dedicated Server         │ LoadDefaultMap,绕开图形       │
│ Cook commandlet         │ 加载 + 序列化为 .pak           │
└────────────────────────┴──────────────────────────────┘
```

下面逐一拆。

## 7.4.3 Editor 模式:不自动创建游戏 World

启动 `UnrealEditor.exe`(无 .uproject 或带 .uproject):
1. `GEngine = UUnrealEdEngine`
2. **不**调 `LoadDefaultMap`
3. 用户操作:File → Open Level → 加载某 .umap

加载关卡后:
- 创建 `UWorld`,WorldType = `EWorldType::Editor`
- 走 `InitWorld`,但**不**走 `BeginPlay`
- Actor 在 World 里,但**不 Tick**

### 7.4.3.1 Editor World 的特殊性

```cpp
World->WorldType == EWorldType::Editor
World->IsGameWorld() == false
World->HasBegunPlay() == false
```

**Subsystem 仍然初始化**(`UWorldSubsystem::Initialize` 被调),所以你的 Mass Subsystem 在 Editor World 里**也会创建** —— 除非你重写 `ShouldCreateSubsystem` 拒绝。

### 7.4.3.2 实战:Mass Subsystem 不在 Editor World 创建

```cpp
class URTSMassWrapperSubsystem : public UWorldSubsystem
{
public:
    virtual bool ShouldCreateSubsystem(UObject* Outer) const override
    {
        UWorld* W = Cast<UWorld>(Outer);
        if (!W) return false;
        
        // 仅 Game / PIE,Editor 不要(Editor 编辑关卡时不需要 RTS 战斗逻辑)
        return W->IsGameWorld();
    }
};
```

否则 Editor 打开关卡时也会跑 RTS 战斗 Subsystem,浪费 + 可能触发 BeginPlay 流程混乱。

## 7.4.4 PIE(Play In Editor)模式

§6.5.5.1 已经讲过流程。再细化:

```
Editor 当前 World = "Editor_World" (EWorldType::Editor)
   ↓ 玩家点 Play
   ↓
UEditorEngine::PlayInEditor
   ├─ 1. UEditorEngine::DuplicateWorldForPIE
   │     - 把 Editor_World 整个复制(每个 Actor / Component / 字段)
   │     - 复制后的 World "PIE_World",WorldType = EWorldType::PIE
   │     - 复制是**深拷贝**,运行时改 PIE 不影响 Editor
   │
   ├─ 2. NewObject<UGameInstance>
   │     - 新 GameInstance(独立于 Editor)
   │     - 走 UGameInstanceSubsystem::Initialize
   │
   ├─ 3. PIE_World->InitWorld
   │     - UWorldSubsystem::Initialize(包括 UMassEntitySubsystem)
   │     - 创建 NetDriver(如果 PIE 多 client)
   │
   └─ 4. PIE_World->BeginPlay
         - 创建 GameMode(server)
         - Actor::BeginPlay 链
         - 创建 PlayerController + Pawn

[此时 Editor_World 与 PIE_World 共存于 GEngine->WorldList]

玩家点 Stop:
   ├─ PIE_World->BeginTearingDown
   ├─ PIE_World 销毁(GC 回收)
   ├─ GameInstance 销毁
   └─ Editor_World 完整保留(用户的修改)
```

### 7.4.4.1 PIE 的"陷阱"

PIE 复制 World 时,**某些非 UPROPERTY 字段不会被复制**:
- 裸 C++ 字段(没标 UPROPERTY)
- 全局静态变量
- 引擎单例的状态

**实战 bug**:你 Subsystem 用全局 `static int32 GCounter = 0`,Editor 跑了几次 PIE 后 `GCounter` 累积。重启 Editor 才清。**永远用 Subsystem 字段,不用全局静态**。

### 7.4.4.2 PIE 多 client 模式

Editor PIE 配置 → "Number of Players: 4" → 启动时**4 个独立的 PIE World**(1 server + 3 client),共 4 个 GameInstance。

```cpp
for (FWorldContext& Ctx : GEngine->GetWorldContexts())
{
    if (Ctx.WorldType == EWorldType::PIE)
    {
        UWorld* PIEWorld = Ctx.World();
        // 这是其中一个 PIE world
    }
}
```

每个 PIEWorld 有自己的 Mass Subsystem 实例(50K entity × 4 instance = 200K!不要在 Editor 测试 50K 单位的 4-player split-screen)。

## 7.4.5 Standalone Game from Editor

Editor 里有"Standalone Game"按钮 — 启动**独立进程**跑你的项目:

```
Editor 进程
   ↓ 点 Standalone Game
   ↓ Editor 调 fork / spawn 子进程
   ↓
新进程 = 像 Game build 一样启动
   ├─ WinMain → GuardedMain → PreInit → Init
   ├─ GEngine = UGameEngine(不是 UUnrealEdEngine!)
   ├─ LoadDefaultMap(从 cooked? 不,从 Editor 同样的 .umap)
   └─ 进 Tick
```

差别 vs PIE:
- 独立进程(crash 不连累 Editor)
- GEngine 类型不同(GameEngine vs UnrealEdEngine)
- 不复制 Editor World,直接加载

### 7.4.5.1 何时用 Standalone vs PIE

| 测试目的 | 推荐 |
|---|---|
| 快速迭代游戏逻辑 | PIE(快,Editor 集成) |
| 测试启动期问题 | Standalone(完整启动) |
| 测试 GEngine 类型分支 | Standalone(跑 GameEngine) |
| 调试 PIE 特有 bug | PIE |
| 多人测试 | PIE 多 client / Standalone 多实例 |

## 7.4.6 Cooked Game(玩家版本)

`MyRTS.exe`(打包后)启动:

```
WinMain → GuardedMain → PreInit → Init
   ↓
GEngine = UGameEngine
   ↓
LoadDefaultMap
   ├─ 读取 .pak 文件
   ├─ 反序列化 UWorld(从 cooked 二进制,非源 .umap)
   ├─ 反序列化所有 ULevel + Actor
   ├─ World->InitWorld
   └─ World->BeginPlay
   ↓
进 Tick
```

### 7.4.6.1 Cooked .uasset 与 .umap 差异

Editor 里:
- `.uasset` / `.umap` 是文本-二进制混合,含 Editor 元数据(选中状态、Outliner 顺序)
- 字段全完整

Cook 后:
- 仅二进制
- 移除 Editor-only 数据(`WITH_EDITORONLY_DATA` 字段)
- 优化加载顺序
- 打包到 `.pak`

打包工具(`UnrealEditor-Cmd.exe -run=cook ...`)处理。

### 7.4.6.2 Cooked 测试

```
# Editor 里 Build → Cook Content
# 然后启动打包后的 .exe
MyRTS.exe -log
```

不要总在 PIE 测试就交付。**至少打包测试一次**确保 cook 流程没问题。

## 7.4.7 Dedicated Server

`MyRTSServer.exe`(Server target build)启动:

```
WinMain → GuardedMain → PreInit → Init
   ↓
GEngine = UGameEngine(但 IsRunningDedicatedServer() == true)
   ↓
跳过 Slate / Renderer 初始化(NullRHI)
   ↓
LoadDefaultMap = 服务器关卡
   ↓
开 Listen Port,等 Client 连接
   ↓
进 Tick(无渲染)
```

### 7.4.7.1 Server 特有判断

```cpp
if (IsRunningDedicatedServer())
{
    // 仅服务器
}

if (GetNetMode() == NM_DedicatedServer)
{
    // 同上
}

if (GetWorld()->IsServer())
{
    // 服务器(包括 Listen Server)
}
```

注意区分:
- **Dedicated Server**:无图形,无玩家本地角色
- **Listen Server**:Game build 玩家自己开服 + 其他人 join

### 7.4.7.2 Server 的 World Subsystem

`UWorldSubsystem` 默认在所有 World 创建。如果你某 Subsystem 是"客户端 UI 状态",Server 不需要:

```cpp
class URTSClientUIStateSubsystem : public UWorldSubsystem
{
public:
    virtual bool ShouldCreateSubsystem(UObject* Outer) const override
    {
        if (IsRunningDedicatedServer()) return false;     // server 不要
        return Cast<UWorld>(Outer)->IsGameWorld();
    }
};
```

## 7.4.8 Cook commandlet

```
UnrealEditor-Cmd.exe MyRTS.uproject -run=cook -targetplatform=Windows
```

启动一个**特殊 Editor 进程**:
- `IsRunningCommandlet() == true`
- `IsRunningEditor() == true`
- `GEngine = UCookCommandlet` 或类似
- 加载所有 .umap / .uasset
- 序列化为 cooked 格式
- 写 .pak

### 7.4.8.1 Commandlet 中的 World

Cook 时 World 被加载但**不**进 BeginPlay。仅触发"加载 + 序列化"路径。

某些 Subsystem 在 commandlet 里不应工作(Mass entity 不应 spawn 到 cooked 资产里):

```cpp
virtual bool ShouldCreateSubsystem(UObject* Outer) const override
{
    if (IsRunningCommandlet()) return false;     // cook 时不要
    return Cast<UWorld>(Outer)->IsGameWorld();
}
```

## 7.4.9 总结表:启动判断 API

```cpp
GIsEditor                  // Editor 模式(包括 commandlet)
IsRunningGame()            // GameEngine 跑(Standalone Game / Cooked Game)
IsRunningClientOnly()      // 纯客户端(无 server)
IsRunningDedicatedServer() // 专用服务器
IsRunningCommandlet()      // commandlet 模式(cook 等)
IsInGameThread()           // GameThread

WITH_EDITOR                 // 编译期:Editor build 才编译
WITH_EDITORONLY_DATA        // 编译期:Editor build 才编译此字段
WITH_SERVER_CODE            // 编译期:server 代码(server / Editor / Game 都有)
UE_BUILD_SHIPPING           // 编译期:Shipping 构建
```

## 7.4.10 World 创建路径速查

```
PIE:           UEditorEngine::DuplicateWorldForPIE
Standalone:    UGameEngine::LoadMap → 反序列化 .umap
Cooked Game:   同上,但 .umap 来自 .pak
Server:        同上,GameEngine + IsRunningDedicatedServer == true
Cook:          UCookCommandlet 加载 .umap 后序列化为 cooked
```

---

## 7.4.11 RTS 项目的"调试矩阵"

新加任何 game logic,**至少**测试:

```
[ ] PIE 1 player                  常规
[ ] PIE 多 player(2-4)           网络
[ ] Standalone Game from Editor    完整启动路径
[ ] 打包 Game build 启动           cook + .pak
[ ] 打包 Server build              专用服务器
```

PIE 通过 ≠ 通过。打包流程能暴露大量 PIE 不暴露的 bug:
- Editor-only 资产引用(cook 时 dropped)
- BP 在 cook 时优化掉的字段
- AsyncLoad 顺序差异
- DLC / pak 顺序
