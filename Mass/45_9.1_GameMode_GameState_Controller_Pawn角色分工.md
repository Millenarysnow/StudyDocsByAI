# §9.1 GameMode / GameState / Controller / Pawn 角色分工

> **本节地图**:模块二第 9 章第 1 节。前面 §6-§8 看了引擎启动 / World / Tick。这一节看 UE Gameplay 框架的"四大金刚"——`AGameModeBase` / `AGameStateBase` / `APlayerController` / `APawn`(加上 `APlayerState`)。它们的**协作模式**决定了 RTS 项目的高层架构。
>
> Mass 不替代它们,而是**寄生**在它们之间。理解这五者的角色分工,你才知道 RTS 命令路由 / 选择器 / 战斗逻辑该挂在哪。
>
> **预备知识**:§7.1(UWorld 字段)、§3.4(CDO)。
>
> **读完之后你能做到**:
> - 区分这五个类的"职责墙",一句话说清谁干什么
> - 知道哪些只在 server 存在,哪些 client 也有
> - 看到 `GetWorld()->GetAuthGameMode<>()` 等 API 立刻知道它返回什么
> - 在 RTS 项目里**精确放置**命令路由 / 玩家选择 / 战斗状态各模块

## 9.1.1 浅入:五个类的"网络存在性"墙

最重要的认知:**这五个类在网络下不对称存在**。

```
                  Server     Listen Server   Client
─────────────────────────────────────────────────────
AGameModeBase      ✓          ✓               ✗(永远 nullptr!)
AGameStateBase     ✓          ✓               ✓(replicated)
APlayerController  各自一个    本地 + 远程     仅本地玩家的
APlayerState       ✓ (每玩家)  ✓               ✓ (replicated,所有玩家的)
APawn              ✓          ✓               所有玩家的(replicated)
```

**最关键**:**`AGameMode` 在 client 永远 nullptr**。这是新人最容易踩的坑。

## 9.1.2 `AGameModeBase` —— 服务器的"裁判"

`Engine/Source/Runtime/Engine/Classes/GameFramework/GameModeBase.h:47`:

```cpp
class AGameModeBase : public AInfo
{
public:
    // 玩游戏要用的所有 class
    TSubclassOf<AGameSession> GameSessionClass;
    TSubclassOf<AGameStateBase> GameStateClass;
    TSubclassOf<APlayerController> PlayerControllerClass;
    TSubclassOf<APlayerState> PlayerStateClass;
    TSubclassOf<APawn> DefaultPawnClass;
    TSubclassOf<AHUD> HUDClass;
    TSubclassOf<ASpectatorPawn> SpectatorClass;
    
    // 当前 GameState 实例
    UPROPERTY(Transient)
    TObjectPtr<AGameStateBase> GameState;
    
    // 当前 GameSession 实例
    UPROPERTY(Transient)
    TObjectPtr<AGameSession> GameSession;
    
    // 关键 hooks
    virtual void InitGame(const FString& MapName, const FString& Options, FString& ErrorMessage);
    virtual void StartPlay();
    virtual void Logout(AController* Exiting);
    virtual void RestartPlayer(AController* NewPlayer);
    
    // 网络流程
    virtual APlayerController* Login(...);
    virtual void PostLogin(APlayerController* NewPlayer);
    
    // ...
};
```

### 9.1.2.1 GameMode 的职责

GameMode = **"游戏规则 + 玩家管理"**:

- 玩家登录 / 退出处理
- spawn 玩家 PlayerController + Pawn
- 决定 GameState / PlayerState / Controller / Pawn 类
- 游戏开始 / 结束逻辑(`HasMatchStarted` / `HasMatchEnded`)
- 自定义规则(谁赢、谁输)

### 9.1.2.2 GameMode 仅在 server 存在

```cpp
AGameModeBase* GM = GetWorld()->GetAuthGameMode<ARTSGameMode>();

if (GM)
{
    // 我是 server,可以改游戏规则
}
else
{
    // 我是 client(或 GameMode 还没 spawn)
}
```

**RTS 实战**:把"谁赢谁输"逻辑放 GameMode。**不要**放 client 端(client 不可信,可能作弊)。

### 9.1.2.3 `AGameMode` vs `AGameModeBase`

UE 提供两个类:
- **`AGameModeBase`**:精简的基础(基本 spawn 玩家 + 配置类)
- **`AGameMode`**:`AGameModeBase` 子类,**加了 MatchState 状态机**(WaitingToStart → InProgress → WaitingPostMatch)

RTS 项目通常用 `AGameMode`(自带回合 / 倒计时 / 准备阶段框架)。

```cpp
    float ServerWorldTimeSeconds;
    
    // ...

```

### 9.1.3.1 GameState 的职责

GameState = **"server 与 client 共享的 game-level 状态"**:

- 当前比赛阶段
- 所有玩家的 PlayerState 列表
- 服务器世界时间(同步用)
- 全局分数 / 胜负条件
- 共享的"全局倒计时"

**网络复制**:server 改 → client 自动看到。

### 9.1.3.2 GameState 在所有端都存在

```cpp
ARTSGameState* GS = GetWorld()->GetGameState<ARTSGameState>();
// server / client 都不为 null(等到 GameState 复制完成)
```

**RTS 实战**:全局倒计时 / 玩家分数 / 当前游戏阶段 → GameState。客户端 UI 直接读取。

## 9.1.4 `APlayerController` —— 玩家本人 + 命令分发

```cpp
class APlayerController : public AController
{
public:
    UPROPERTY()
    TObjectPtr<APawn> Pawn;       // 当前控制的 Pawn
    
    UPROPERTY()
    TObjectPtr<UPlayerInput> PlayerInput;
    
    UPROPERTY()
    TObjectPtr<UInputComponent> InputComponent;
    
    // 网络
    UPROPERTY()
    TObjectPtr<APlayerCameraManager> PlayerCameraManager;
    
    // 关键 hooks
    virtual void SetupInputComponent();
    virtual void Possess(APawn* InPawn);
    virtual void UnPossess();
    
    // RPC 网络通信
    UFUNCTION(Server, Reliable, WithValidation)
    void ServerSomeAction(...);
    
    UFUNCTION(Client, Reliable)
    void ClientSomeAction(...);
};
```

### 9.1.4.1 PlayerController 的职责

PlayerController = **"玩家的代理人"**:

- 接收输入(键鼠 / 手柄)
- 控制 Pawn(possess / unpossess)
- 管理相机
- 玩家本地 UI 状态
- Server-Client RPC 入口(玩家命令传到 server)

### 9.1.4.2 PlayerController 在不同端的存在

```
Server:
   ├─ 每玩家一个 PlayerController(包括本地玩家 + 所有连入的 client)
   └─ Server 有所有玩家的 PC

Listen Server:
   ├─ 本地玩家 PC(Local + Authority)
   └─ 远程玩家 PC(Authority,Remote 端在他自己的 client)

Pure Client:
   └─ 仅本地玩家 PC(其他玩家的 PC 不存在于本 client)
```

**关键差异**:
- Server 看所有 PC
- Client 仅本地 PC

Client 上 `GetWorld()->GetFirstPlayerController()` 永远是本地玩家。Server 上是第一个连接的(取决于顺序)。

### 9.1.4.3 PlayerController 与 Pawn 的关系

```cpp
APlayerController* PC = GetWorld()->GetFirstPlayerController();
APawn* P = PC->GetPawn();          // 当前控制的 Pawn

PC->Possess(NewPawn);              // 切换控制
PC->UnPossess();                    // 解除控制
```

`Possess` 改 `PC->Pawn`,反向也设 `Pawn->Controller`。从此 PC 接收的输入路由到 Pawn。

## 9.1.5 `APlayerState` —— 玩家维度的 replicated 数据

```cpp
class APlayerState : public AInfo
{
public:
    UPROPERTY(Replicated)
    FString PlayerNamePrivate;      // 玩家名
    
    UPROPERTY(Replicated)
    int32 Score;                    // 分数
    
    UPROPERTY(Replicated)
    int32 Ping;                     // 网络延迟
    
    UPROPERTY()
    TObjectPtr<APlayerController> OwningController;
    
    // ...
};
```

### 9.1.5.1 PlayerState 的职责

PlayerState = **"每玩家的可复制公开数据"**:

- 玩家名 / Steam ID / 头像
- 分数 / 等级 / 经验
- Ping / 队伍

**关键**:PlayerState **所有 client 都能看到所有玩家的 PlayerState**。这就是为什么 PC 通过 PlayerState 显示"队友的分数 / 等级"。

### 9.1.5.2 PlayerController vs PlayerState

```
PlayerController:
   ├─ 玩家本地行为(输入、UI 状态)
   └─ Server 管所有,Client 仅自己

PlayerState:
   ├─ 玩家"公开档案"(名字、分数)
   └─ 所有 client 看所有 PlayerState
```

实战:**显示"队友血条 / 名字"** → 用 PlayerState(replicated 全可见)。**响应"按 W 前进"** → 用 PlayerController(本地输入)。

## 9.1.6 `APawn` —— 被 possess 的"身体"

```cpp
class APawn : public AActor, public INavAgentInterface
{
public:
    UPROPERTY()
    TObjectPtr<AController> Controller;       // 谁在控制我
    
    UPROPERTY()
    TObjectPtr<APlayerState> PlayerState;     // 我属于哪个玩家
    
    virtual void PossessedBy(AController* NewController);
    virtual void UnPossessed();
    
    virtual void SetupPlayerInputComponent(UInputComponent* PlayerInputComponent);
    
    // ...
};
```

### 9.1.6.1 Pawn 的职责

Pawn = **"游戏世界中的玩家身体"**:

- 物理位置(Transform)
- 移动逻辑(MovementComponent)
- 动画 / 视觉(MeshComponent)
- 输入响应(`SetupPlayerInputComponent`)

### 9.1.6.2 Pawn 与 Controller 关系

```
APlayerController.Pawn  ←──→  APawn.Controller
                                       │
                                       └── APlayerState
                                              ↑
                          APlayerController.PlayerState
```

三者互相引用(Controller / Pawn / PlayerState)。

### 9.1.6.3 ACharacter —— 增强 Pawn

`ACharacter`(Pawn 子类)预包:
- `UCapsuleComponent`(碰撞)
- `USkeletalMeshComponent`(动画)
- `UCharacterMovementComponent`(网络化移动)

99% FPS / TPS 用 `ACharacter`。RTS 玩家不需要"身体"(玩家是俯视相机),所以**RTS PlayerController 经常 possess 一个空 Pawn 或 SpectatorPawn**。

## 9.1.9 命令路由的设计:Mass 之外的"框架部分"

```
玩家点击屏幕选中单位
   ↓
ARTSPlayerController::HandleClick(本地)
   ↓
PC->SelectedUnits 更新(本地选择)
   ↓
玩家右键命令"移动到 X"
   ↓
PC::ServerIssueCommand(MoveCmd, SelectedUnits) (RPC)
   ↓
Server 端 ARTSPlayerController::ServerIssueCommand_Implementation
   ↓
URTSCommandSubsystem::EnqueueCommand(WorldSubsystem,server only)
   ↓
Mass Processor 下一帧消费命令,移动 entity
```

**关键架构**:
- 玩家本地选择 → PlayerController(本地状态)
- 命令 RPC → Server → CommandSubsystem(WorldSubsystem)
- CommandSubsystem 把命令塞给 Mass

PC 不直接操作 Mass。CommandSubsystem 是中介。

## 9.1.10 服务器权威 vs 客户端预测

### 9.1.10.1 经典模式:Server 权威

```cpp
// Client 端(ARTSPlayerController)
void ARTSPlayerController::HandleClick(...)
{
    if (HasAuthority()) {
        // 本地是 server
        ServerIssueCommand_Implementation(Cmd);
    } else {
        // 本地是 client,通过 RPC 发到 server
        ServerIssueCommand(Cmd);
    }
}

// Server 端
void ARTSPlayerController::ServerIssueCommand_Implementation(const FRTSCommand& Cmd)
{
    // 验证权限(玩家是否拥有这些 unit?)
    if (!ValidateOwnership(Cmd, GetPlayerState())) return;
    
    // 走 CommandSubsystem
    GetWorld()->GetSubsystem<URTSCommandSubsystem>()->EnqueueCommand(Cmd);
}
```

### 9.1.10.2 客户端预测(可选,RTS 较少用)

为减小延迟感,client 立刻显示移动:

```cpp
// Client
void HandleClick(...)
{
    // 本地预测移动(显示效果)
    LocalPredictMove(SelectedUnits, TargetLoc);
    
    // 发 RPC
    ServerIssueCommand(Cmd);
}

void ClientReconcile(const FRTSCommandResult& Result)
{
    // server 返回真实结果,如果与预测不一致,纠正
    if (DivergesFromPrediction(Result)) {
        SnapToServerState(Result);
    }
}
```

RTS 不像 FPS 那么注重预测,因为命令延迟可接受(玩家点 → 几百 ms 后单位响应,正常)。
