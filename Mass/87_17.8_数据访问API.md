## 17.8.1 五种访问 API

```cpp
// 1. 单 entity Get,assert 必有
FMyFragment& F = EM.GetFragmentDataChecked<FMyFragment>(E);
   // assert(entity 有 FMyFragment),否则 crash
   // ~100-200 ns(archetype lookup + offset)

// 2. 单 entity Get,可能 null
FMyFragment* F = EM.GetFragmentDataPtr<FMyFragment>(E);
   // null = entity 没这个 fragment
   // 同 ~100-200 ns

// 3. 检查
bool bHas = EM.HasFragment<FMyFragment>(E);
   // 仅 BitSet 检查 ~10 ns

// 4. Processor 内 chunk 级访问(★ 推荐)
auto MyView = Ctx.GetMutableFragmentView<FMyFragment>();
   // 取 chunk 内 fragment 数组,O(1)
   // 然后 MyView[i] ~ 1 ns

// 5. Processor 内单 entity(慢)
Query.ForEachEntity(EM, Ctx, [](FMassExecutionContext& Ctx, FMassEntityHandle E) {
    // 每个 entity 调一次回调,慢
});
```

---

## 17.8.2 性能对比表

| API | 调用代价 | 适用 |
|---|---|---|
| `GetFragmentDataChecked<T>(E)` | ~100-200 ns | 偶尔单 entity |
| `GetFragmentDataPtr<T>(E)` | ~100-200 ns | 偶尔,可能 null |
| `HasFragment<T>(E)` | ~10 ns | 检查存在 |
| **`Ctx.GetMutableFragmentView<T>()` + `[i]`** | **~1 ns / entity** | ★ Processor 主路径 |
| `Query.ForEachEntity(...)` | 较慢(per-entity 调用) | 不推荐 |

## 17.8.3 EntityBuilder(创建友好 API)

```cpp
UE::Mass::FEntityBuilder Builder(EM);
Builder.Add<FPositionFragment>();
Builder.Add<FVelocityFragment>(FVelocityFragment{ FVector(1,0,0) });   // 带初始值
Builder.AddTag<FActiveTag>();

FMassEntityHandle E = Builder.Commit();
```

比直接 `CreateEntity(Archetype)` 友好,自动管理 archetype。

## 17.8.4 跨 Fragment 访问(Processor 内)

```cpp
Query.ForEachEntityChunk(EM, Ctx, [](FMassExecutionContext& Ctx)
{
    auto Positions = Ctx.GetMutableFragmentView<FPositionFragment>();
    auto Velocities = Ctx.GetFragmentView<FVelocityFragment>();
    auto Healths = Ctx.GetMutableFragmentView<FHealthFragment>();
    
    const int32 N = Ctx.GetNumEntities();
    const float DT = Ctx.GetDeltaTimeSeconds();
    
    for (int32 i = 0; i < N; ++i) {
        Positions[i].Position += Velocities[i].Velocity * DT;
        if (Healths[i].HP <= 0) {
            Ctx.Defer().DestroyEntity(Ctx.GetEntity(i));
        }
    }
});
```

`Ctx.GetEntity(i)` 取当前 entity handle(用于命令缓冲)。

## 17.8.5 SharedFragment 访问

```cpp
// 在 Processor:
const FUnitTypeData& Type = Ctx.GetSharedFragment<FUnitTypeData>();
   // chunk 内所有 entity 共享一个 instance
```

不像 Fragment 有数组,SharedFragment **每 chunk 一个**。

## 17.8.6 Mutex 保护(Mass 5.x)

某些场景多 worker 都想修改同 fragment(典型:伤害累加):

```cpp
auto Healths = Ctx.GetMutableFragmentView<FHealthFragment>();

// ❌ 多 worker 同 chunk 同时改 Health → 数据竞争(虽然 Mass 默认避免,但极端场景可能)
Healths[i].HP -= Damage;

// ✅ Atomic
std::atomic<int32>* HPAtomic = (std::atomic<int32>*)&Healths[i].HP;
HPAtomic->fetch_sub(Damage, std::memory_order_relaxed);
```

通常 Mass query Required 标 ReadWrite 时,**只有一个 Processor 能写该 chunk** → 不会冲突。

## 17.8.7 第 17 章 + Mass 内存模型总结

到这里第 17 章完整闭环。Mass 内存模型核心:

```
FMassEntityHandle (8 字节,Index + SN)
   ↓
FMassEntityManager
   ├─ Entities array (FEntityData → Archetype + chunk + index)
   └─ AllArchetypes
        └─ Each FMassArchetypeData
              ├─ FragmentBitSet / TagBitSet / ...
              ├─ FragmentConfigs (offset / size)
              └─ Chunks (each 128KB,SoA layout)

Query 内部:
   FMassFragmentRequirements (BitSets)
      → match archetype
      → match chunk
      → ForEachChunk callback
            access via Ctx.GetMutableFragmentView<T>()
```
