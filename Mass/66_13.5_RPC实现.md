## 13.5.1 三种 RPC

```cpp
// Client 调,Server 执行
UFUNCTION(Server, Reliable, WithValidation)
void ServerIssueCommand(const FRTSCommand& Cmd);

// Server 调,目标 Client 执行
UFUNCTION(Client, Reliable)
void ClientShowMessage(const FString& Msg);

// Server 调,所有 Client 执行
UFUNCTION(NetMulticast, Reliable)
void MulticastPlayExplosion(FVector Loc);
```

### 13.5.1.1 Server RPC

```cpp
// 头文件
UFUNCTION(Server, Reliable)
void ServerIssueCommand(const FRTSCommand& Cmd);

// .cpp 你写 _Implementation
void ARTSPlayerController::ServerIssueCommand_Implementation(const FRTSCommand& Cmd)
{
    // 在 server 上运行的代码
}

// 调用
void ARTSPlayerController::OnUserInput()
{
    ServerIssueCommand(Cmd);   // ← UE 自动:client 调时,RPC 包发到 server
                                // server 调时,直接调 _Implementation
}
```

UHT 自动生成 `ServerIssueCommand` 函数(包装),它检测当前是 server / client,如果 client 就发包 server,如果 server 直接调 Implementation。

### 13.5.1.2 Client RPC

```cpp
UFUNCTION(Client, Reliable)
void ClientShowMessage(const FString& Msg);

void ARTSPlayerController::ClientShowMessage_Implementation(const FString& Msg)
{
    // client 端 UI 显示消息
}
```

`Client` RPC 必须在**有 Owner 的 Actor 上**(典型:PlayerController)。Server 调时,RPC 发给该 actor 的 owner connection。

### 13.5.1.3 Multicast RPC

```cpp
UFUNCTION(NetMulticast, Reliable)
void MulticastPlayExplosion(FVector Loc);

void ABomb::MulticastPlayExplosion_Implementation(FVector Loc)
{
    SpawnExplosionFX(Loc);
    PlayExplosionSound(Loc);
}

// 调用
void ABomb::Detonate()
{
    if (HasAuthority())
    {
        MulticastPlayExplosion(GetActorLocation());   // server 调,所有 client 收到 + 执行
    }
}
```

## 13.5.2 Reliable vs Unreliable

| | Reliable | Unreliable |
|---|---|---|
| 保证到达 | ✓ | ✗ |
| 顺序保证 | ✓ | ✗ |
| 带宽 | 多(ack 重传) | 少 |
| 用例 | 关键命令(下命令) | 频繁更新(实时位置) |

```cpp
UFUNCTION(Server, Reliable)         // 关键命令
UFUNCTION(Server, Unreliable)        // 高频但允许丢包(语音)
```

**纪律**:命令用 Reliable,效果用 Unreliable。

## 13.5.3 Validation

```cpp
UFUNCTION(Server, Reliable, WithValidation)
void ServerIssueCommand(const FRTSCommand& Cmd);

bool ARTSPlayerController::ServerIssueCommand_Validate(const FRTSCommand& Cmd)
{
    // server 端先调 _Validate,返回 false 即拒绝并踢玩家
    if (Cmd.Targets.Num() > 1000) return false;   // 防作弊:命令选择超过 1000 个 entity
    return true;
}

void ARTSPlayerController::ServerIssueCommand_Implementation(const FRTSCommand& Cmd)
{
    // _Validate 通过后才调
}
```

5.x 默认 RPC 不带 Validation。**关键 RPC** 加 `WithValidation` 防作弊。

## 13.5.4 RPC 实际怎么工作

```
[Client]
ServerIssueCommand(Cmd)
   ↓ UHT 生成的 wrapper:
   ↓ 检测我是 client → 序列化参数 → 发包到 server
   ↓
[Server]
   ↓ NetDriver 收包,反序列化
   ↓ 调 _Validate(若 WithValidation)→ true 才继续
   ↓ 调 _Implementation
```

底层走 ActorChannel(§12.2)。RPC 包加密 + 压缩。

## 13.5.5 RTS 项目的 RPC 设计

```cpp
class ARTSPlayerController
{
public:
    // Client → Server:玩家命令
    UFUNCTION(Server, Reliable, WithValidation)
    void ServerIssueCommand(const FRTSCommand& Cmd);
    
    UFUNCTION(Server, Reliable, WithValidation)
    void ServerCancelCommand(int32 EntityID);
    
    // Server → Client:战况通知
    UFUNCTION(Client, Reliable)
    void ClientShowKillFeed(const FString& Killer, const FString& Victim);
    
    UFUNCTION(Client, Reliable)
    void ClientShowMatchEnd(int32 WinnerTeam);
    
    // Multicast:全员看到
    UFUNCTION(NetMulticast, Unreliable)
    void MulticastShowExplosion(FVector Loc);
};
```

## 13.5.6 RPC 与 Mass

Mass entity 不是 UObject,**没有 RPC 能力**。命令必须通过 PC RPC 中转:

```
Client (玩家选 entity)
   ↓ ServerIssueCommand RPC 到 PC
   ↓
Server PC._Implementation
   ↓ 转给 URTSCommandSubsystem
   ↓ 入队
   ↓
Mass Processor 消费
```

PC 是"网络代理人"。Mass 永远不直接收 RPC。

---

## 13.5.7 RPC 性能与限制

```
RPC 大小限制 ~64 KB / call(默认)
RPC 频率限制(Server RPC):每 connection ~30 次 / 秒(防 DDoS)
```

不能滥用 RPC。每帧调几十次 RPC → 网络爆炸 / 防 DDoS 拦截。

**RTS 命令 ~ 1-5 次 / 秒 / 玩家**,完全可以走 RPC。
