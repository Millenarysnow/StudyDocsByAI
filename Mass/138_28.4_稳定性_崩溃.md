   CrashReportClientVersion=...
   DataRouterUrl=https://yourcrashserver.com/upload

## 28.4.2 Mass 常见崩溃模式

```
1. EntityHandle 失效访问:
   持有 entity → 几帧后 entity 已销毁 → IsEntityValid 返回 false
   解决:每次访问前 IsEntityValid 检查

2. ParallelFor 写冲突:
   并行 chunk 各自写不同 entity OK
   但若两 chunk 都改"全局共享数据"(例如 SharedFragment 写)→ race
   解决:Sub-system 加 critical section,或用 deferred command

3. Archetype 切换在 ForEach 中:
   ForEach 时 AddTag/RemoveTag 改 archetype → entity 移动 → 迭代器失效
   解决:用 ExecutionContext.Defer().AddTag(...),帧末执行
```

## 28.4.3 Server 健壮性

```
单点崩溃 → 整局战斗中断 → 玩家恼火

防御:
   - Server tick 用 try-catch(crit section)包关键路径
   - 周期性 Snapshot 持久化(每 30s 写盘)
   - Server crash 后从 Snapshot 恢复(部分丢帧但局没断)
   
具体实现:
   class URTSPersistenceSubsystem
   {
       FTimerHandle Timer;
       
       void StartPeriodicSnapshot()
       {
           World->GetTimerManager().SetTimer(Timer, this,
               &URTSPersistenceSubsystem::SaveSnapshot, 30.0f, true);
       }
       
       void SaveSnapshot()
       {
           // 序列化 Mass entity + GameState + 玩家状态到磁盘
           FArchive Ar = ...;
           SaveMassState(Ar);
       }
   };
```

## 28.4.4 客户端健壮性

```
- 断线重连:玩家 client 网络抖动 → 重连后从 server 拉最新 Snapshot
- Iris 自带 reliable queue,丢包重传
- UI / 渲染 异常:不要让 UI 崩溃影响游戏逻辑(check + fallback)
```
