## 14.4.1 Mass + Iris 的整体架构

```
[Server]
Mass Subsystem 持有所有 entity
   │
   ├─ UMassReplicationProcessor 每帧扫描 entity
   │      │
   │      ├─ 按"重要性"排序(距离玩家 / 状态变化)
   │      │
   │      ├─ 推送 dirty 给 Iris ReplicationBridge
   │      │
   │      ↓
   │   Iris ReplicationSystem
   │      │
   │      ├─ Filtering(空间索引,每 client 看自己附近)
   │      ├─ Pri/Bandwidth(预算管理)
   │      ├─ 量化序列化
   │      └─ 发包
   │
   ↓ 网络

[Client]
   Iris 接收
   ↓
   Mass entity 镜像创建 / 状态更新 Fragment
   ↓
   Client 端 RepresentationProcessor 渲染
```

## 14.4.2 `UMassNetworkingTrait`

Trait 让 entity "网络可见":

```cpp
UCLASS()
class URTSReplicatedTrait : public UMassEntityTraitBase
{
    virtual void BuildTemplate(...) const override
    {
        BuildContext.AddFragment<FMassReplicatedFragment>();
        BuildContext.AddTag<FMassReplicatedTag>();
    }
};
```

加上 Trait 的 entity 会被 ReplicationProcessor 选中复制。

## 14.4.3 Replication Fragment

```cpp
USTRUCT()
struct FMassReplicatedFragment : public FMassFragment
{
    GENERATED_BODY()
    
    // Iris 用的 net ID(server 分配)
    int32 NetID = INDEX_NONE;
    
    // 关联的 LOD bubble(详 §21)
    int32 BubbleID = INDEX_NONE;
};
```

每 entity 一个紧凑 NetID(几字节),不是 full UObject NetGUID。

## 14.4.4 兴趣管理(Bubble)

Mass replication 用"bubble"概念:
- 每 client 有一个或多个 bubble(围绕玩家位置)
- bubble 内的 entity 复制
- bubble 外不复制

```cpp
URTSPlayerController::Tick(...)
{
    UMassReplicationSubsystem* MS = GetWorld()->GetSubsystem<UMassReplicationSubsystem>();
    MS->RegisterBubble(GetPlayerBubble(this));
}
```

每帧更新 bubble 位置,Iris 自动按 bubble 过滤。

## 14.4.5 量化序列化

Mass 自定义 NetSerialize(§3.5.7.1)实现量化:

```cpp
USTRUCT()
struct FMassPositionFragment : public FMassFragment
{
    FVector Position;
    
    bool NetSerialize(FArchive& Ar, UPackageMap* Map, bool& bOutSuccess)
    {
        if (Ar.IsSaving()) {
            int16 X = (int16)(Position.X * 100);
            int16 Y = (int16)(Position.Y * 100);
            int8 Z = (int8)(Position.Z * 10);
            Ar << X << Y << Z;
        } else {
            int16 X, Y; int8 Z;
            Ar << X << Y << Z;
            Position = FVector(X * 0.01f, Y * 0.01f, Z * 0.1f);
        }
        bOutSuccess = true;
        return true;
    }
};
```

5 字节 / position(替代 12 字节 raw)。

## 14.4.6 RTS 性能估算(综合)

```
50K Mass entity + 10 client + Mass + Iris:

Server 每帧 (60 fps):
   - UMassReplicationProcessor 扫描:50K × 几十 ns = 2-3 ms
   - 兴趣管理(bubble query): 10 × 50K × 几 ns = 0.5 ms
   - Iris dirty push:  几百 KB / 帧
   - 序列化 + 发包:  1-2 ms
   总:~ 4-5 ms / 帧 ✓
   
带宽:
   - 每 client 看 ~5K entity(可见)
   - 5K × 5 字节 × 5% dirty / 帧 = ~1 KB / 帧
   - 60 fps × 1 KB = 60 KB/s ✓ 在 512 KB/s 预算内
   
Server CPU:
   - Mass tick(50K 单位)~7-8 ms
   - Replication ~ 4-5 ms
   - 总:~12-13 ms / 帧 ✓ 在 16.6 ms 预算内
```

可行!

## 14.4.7 Mass + Iris 的 RTS 实战流程

```
1. RTS 战场启动:
   Server spawn 50K Mass entity + Replicated Trait
   每 entity 分配 Mass NetID

2. 玩家加入:
   Server 注册 player bubble(位置 + 半径)
   Iris 自动 broadcast 玩家 bubble 内 entity 状态

3. 每帧 server:
   Mass tick → 更新 fragment
   ReplicationProcessor → push dirty 到 Iris
   Iris → 序列化 + 量化 + 发包

4. 每帧 client:
   Iris 接收 → 反序列化
   创建 / 更新本地 Mass entity 镜像
   RepresentationProcessor → ISMC 渲染

5. 玩家移动相机:
   Bubble 位置更新
   Iris 重新计算可见 entity
   新 entity 进入 bubble → 创建 client 端 entity
   旧 entity 出 bubble → 销毁 client 端 entity
```
