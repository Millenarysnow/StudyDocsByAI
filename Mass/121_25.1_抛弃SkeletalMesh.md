# §25.1 抛弃 SkeletalMesh / StaticMesh Component 的内存代价

> **本节地图**:模块五第 25 章第 1 节。RTS 50K 单位**绝不能**每个有 USkeletalMeshComponent。这一节量化代价 + 解释为什么。
>
> **预备知识**:§8.2 RegisterAllComponents。
>

---

## 25.1.1 Component 的"重量"

```
USkeletalMeshComponent:
   - 数百字节 base 字段
   - SkeletalMesh* 引用(几 KB asset)
   - SceneProxy(GameThread + RenderThread 镜像)
   - Bone TransformArray(每帧更新,几十骨骼 × 几百字节)
   - PhysicsBodies(每 bone 可有 collision body)
   - 总计:~5-50 KB / SkeletalMeshComponent
   
50K × 30KB = 1.5 GB 仅 component 内存
```

**直接破内存预算**。

---

## 25.1.2 UStaticMeshComponent 也不行

```
UStaticMeshComponent:
   - ~1-2 KB / instance
   - SceneProxy(GameThread + RenderThread)
   - 50K × 1.5 KB = 75 MB(可接受)
   - 但:50K SceneProxy → RenderThread 处理 50K primitive ⇒ 慢
   
渲染开销:
   - 50K DrawCall(若不 batched)→ 几十 ms / 帧 GPU
   - 即使 GPU instancing,RenderThread 提交 50K primitive 也几 ms
```

---

## 25.1.3 解法:ISMC + VAT

```
1 个 UInstancedStaticMeshComponent:
   1 个 SceneProxy
   50K instance(每 instance 一个 transform)
   GPU 端 GPUScene 紧凑存储
   1 个 DrawCall(GPU instancing)
   
内存:1 KB(component)+ 50K × 64 字节 (instance) = 3 MB
渲染:1 ms / 帧
```

**几个数量级改善**。
