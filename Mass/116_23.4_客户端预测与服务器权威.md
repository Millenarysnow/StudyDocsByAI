# §23.4 客户端预测与服务器权威 — 切分

> **本节地图**:模块五第 23 章压轴。RTS 通常**不预测**,但有些场景需要可见反馈。
>
> **预备知识**:§14.3。

---

## 23.4.1 三种"反馈级别"

```
1. 严格 server 权威(无任何客户端反应):
   ✓ 玩家点 → 等几百 ms server 响应 → 单位才动
   - 简单
   - 玩家觉得"卡"
   
2. 立即视觉反馈 + server 权威(★ 推荐 RTS):
   ✓ 玩家点 → 本地立刻显示"点击波纹"+"目标线"
   ✓ 单位移动等 server 决定(几百 ms 后开始动)
   - 玩家觉得"响应"+ server 仍权威
   
3. 完整客户端预测 + reconcile(FPS 风格):
   ✓ 玩家点 → 本地立即开始移动(预测)
   ✓ Server reconcile,如果不一致则纠正
   - 复杂
   - 大规模 entity 难以维护
   - RTS 极少用
```

---

## 23.4.2 RTS 推荐:级别 2 的实现

```cpp
void ARTSPlayerController::OnCommand(...)
{
    FRTSCommand Cmd = ...;
    
    // 1. 立即视觉反馈(本地)
    SpawnCommandIndicator(Cmd.TargetLocation);   // 绿色目标圈
    DrawSelectionLine(Cmd.Targets, Cmd.TargetLocation);
    PlaySound("CommandConfirm");
    
    // 2. 发 server
    ServerIssueCommand(Cmd);
    
    // 3. 不预测移动 — 等 server 通过 Mass replication 把单位状态传回
}
```

**关键**:UI / 视觉反馈本地立即,**实际 entity 状态等 server**。

## 23.4.3 视觉反馈的资产

```cpp
// 命令指示器(本地 spawn,client only,无网络复制)
UFUNCTION(BlueprintCallable)
void SpawnCommandIndicator(FVector Loc)
{
    AActor* Indicator = GetWorld()->SpawnActor<ACommandIndicatorActor>(
        IndicatorClass, FTransform(Loc));
    
    // 几秒后自动销毁
    Indicator->SetLifeSpan(2.0f);
}
```

仅本地 spawn,**不**网络复制。

## 23.4.4 高延迟下的反馈

```
玩家延迟 200ms 时:
   t=0:    玩家点
   t=0:    本地视觉反馈(立即)
   t=100:  command 到 server
   t=100:  server 入队,Mass tick 处理
   t=130:  server 单位状态变(开始移动)
   t=160:  状态 replicate 到 client
   t=200:  client 看到单位开始移动
   
玩家感受:点击立即有反馈,200ms 后单位真正动 → 可接受
```
