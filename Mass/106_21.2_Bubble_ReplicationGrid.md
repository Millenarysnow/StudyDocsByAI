## 21.2.1 Bubble(玩家关注的"球")

```cpp
struct FMassBubble
{
    FVector Center;
    float Radius;
    UNetConnection* Connection;   // 哪个 client
};
```

每 client 一个 bubble(围绕玩家相机)。Server 仅复制 bubble 内 entity。

```cpp
// 每帧更新 bubble
URTSPlayerController::Tick()
{
    UMassReplicationSubsystem* MS = GetWorld()->GetSubsystem<UMassReplicationSubsystem>();
    MS->UpdateBubble(MyConnection, GetCameraLocation(), 5000.0f);
}
```

## 21.2.2 ReplicationGrid(空间索引)

50K entity 不能每帧查 "在 bubble 内吗" — 需要空间索引(grid / octree)。

```
ReplicationGrid:
   World 分 100m × 100m 网格
   每 entity 进对应 cell
   
查询 "Bubble 内 entity":
   遍历 bubble 范围内的 cells (~9-25 个)
   收集 cells 内 entity
   = 几千 entity / bubble(远少于 50K)
```

---

## 21.2.3 EntityView(client 端镜像)

server 决定一个 entity 进入 client 的 bubble → client 端创建 entity 镜像(称 "view")。entity 出 bubble → 销毁 view。

```cpp
USTRUCT() struct FMassEntityViewFragment : public FMassFragment
{
    int32 ServerNetID;       // 关联 server 端原始 entity
};
```

Client 端 entity 不**必**有所有 fragment,只复制必要的(Position + 状态枚举)。

## 21.2.4 RTS 兴趣管理估算

```
50K Mass entity
   ↓ ReplicationGrid 索引
   
每 client bubble (玩家相机半径 5km):
   ~5K-10K entity 在范围内
   
每帧复制变化:
   只发"position + state 变了的"~5% × 5K = 250 entity
   每 entity 5 字节量化 = 1.25 KB / 帧
   60 fps × 1.25KB = 75 KB/s ✓ 可行
```
