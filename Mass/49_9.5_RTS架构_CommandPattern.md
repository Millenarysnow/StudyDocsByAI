## 9.5.1 中央问题:RTS 不是 FPS

UE 文档 + 教程偏 FPS / TPS。RTS 几个根本不同:

```
FPS / TPS                              RTS
─────────────────────────────────────────────────
玩家是 Pawn(移动 / 射击)               玩家是相机(没有"身体")
单 player 控制 1 个角色                 单 player 控制 100+ 单位
单位有玩家直接驱动                       单位 AI 自主,玩家下命令
PC 主要做"Movement Input"               PC 主要做"Selection + Command"
1 个玩家 1 个 GameMode 实例             同上
```

所以经典 UE 教程把"运动逻辑"放 Pawn,RTS 把它放别处(Mass)。其它差异类推。

## 9.5.2 RTS Class 层次图

```
进程级:
   URTSAssetCacheSubsystem (UEngineSubsystem)
      └─ 全局共享资产(单位模型、声音库)
      
一局游戏级:
   URTSPlayerProfileSubsystem (UGameInstanceSubsystem)
      └─ 玩家档案、登录会话、跨关卡数据
   
关卡内(World):
   ARTSGameMode (server only)
      ├─ 决定胜负
      ├─ Spawn PC + Pawn
      └─ 玩家加入 / 退出处理
   
   ARTSGameState (replicated)
      ├─ 游戏阶段(Setup / InGame / GameOver)
      ├─ 全局倒计时
      └─ 队伍胜负
   
   关卡内 Subsystem:
   URTSCombatSubsystem (UWorldSubsystem,server only)
      └─ Mass entity 战斗状态汇总
   URTSCommandSubsystem (UWorldSubsystem)
      └─ 命令队列(玩家命令 → Mass)
   URTSFogOfWarSubsystem (UTickableWorldSubsystem)
      └─ 可见性矩阵
   URTSPathfindingSubsystem (UWorldSubsystem)
      └─ 流场寻路
   URTSEconomySubsystem (UWorldSubsystem,server only)
      └─ 资源(replicate 到 client)
   UMassEntitySubsystem (UE 自带)
      └─ Mass entity 框架
   
   每玩家:
   ARTSPlayerController (per-player,client + server)
      ├─ 接收输入
      ├─ 维护本地选择
      ├─ 发送命令到 server(RPC)
      └─ 控制相机 Pawn
   
   ARTSPlayerState (per-player,replicated)
      ├─ 队伍 ID
      ├─ 资源
      ├─ APM / 分数
      └─ 玩家名
   
   ARTSCameraPawn (per-player)
      └─ 俯视相机
   
   每本地玩家:
   URTSSelectionSubsystem (ULocalPlayerSubsystem)
      └─ 当前选中的 Mass entity 集合
   URTSUIStateSubsystem (ULocalPlayerSubsystem)
      └─ Mini-Map / Tab / 鼠标光标状态
   UEnhancedInputLocalPlayerSubsystem (UE 自带)
      └─ Enhanced Input 上下文
```

## 9.5.3 决策表:某功能放哪

| 功能 | 推荐位置 | 理由 |
|---|---|---|
| 谁赢谁输 | ARTSGameMode | server 权威 |
| 比赛阶段 / 倒计时 | ARTSGameState | replicated,所有 client 看到 |
| 玩家阵营 / 颜色 | ARTSPlayerState | replicated 显示队友信息 |
| 玩家分数 / APM | ARTSPlayerState | 同上 |
| 输入处理(WASD 移动相机) | ARTSCameraPawn::SetupPlayerInputComponent | Pawn 是输入接收者 |
| 鼠标点击选择 | ARTSPlayerController::HandleClick | PC 是 input chain 顶层 |
| 当前选中单位 | URTSSelectionSubsystem (ULocalPlayer) | 仅本地需要 |
| 命令发起 | ARTSPlayerController → RPC → server | 网络分发 |
| 命令路由到 Mass | URTSCommandSubsystem (WorldSubsystem) | 中心化处理 |
| Mass 单位状态 | Mass Fragment | 不需 UObject |
| 单位 AI | UMassProcessor | Mass 框架 |
| 战斗结果统计 | URTSCombatSubsystem | server 汇总 |
| 资源(经济) | URTSEconomySubsystem + ARTSPlayerState | server 计算,replicate |
| 雾战可见性矩阵 | URTSFogOfWarSubsystem | 服务器 + client(都需要 LOD/可见性) |
| HUD UI | URTSHUD + UMG widget | 标准 |
| 工具菜单 / 主菜单 | URTSUIStateSubsystem (ULocalPlayer) | 跨关卡持久 |
| 玩家档案 / 进度存档 | URTSPlayerProfileSubsystem (GameInstance) | 跨关卡 |
| 通用资产缓存 | URTSAssetCacheSubsystem (Engine) | 进程级 |

## 9.5.4 数据流详解:玩家发命令

```
玩家鼠标点击屏幕
   ↓
APlayerController::InputKey 接收
   ↓
ARTSPlayerController::OnLeftClick
   │ 走射线到地面
   ↓
URTSSelectionSubsystem::HitTest 命中某 Mass entity
   ↓ 加入选择集
   ↓
玩家右键 + 目标位置
   ↓
ARTSPlayerController::OnRightClick
   │ 取 SelectionSubsystem 当前选择
   │ 取目标地点
   ↓
ARTSPlayerController::ServerIssueMoveCommand RPC
   │ (从 client 跨网络到 server)
   ↓
[Server 端]
ARTSPlayerController::ServerIssueMoveCommand_Implementation
   │ 验证(玩家是否拥有这些 entity?)
   │
   ↓
URTSCommandSubsystem::EnqueueCommand
   │ 入队(MPSC,§5.4 lock-free)
   ↓
[下一帧 Mass tick]
URTSCommandProcessor::Execute
   │ 从队列取命令
   │ 修改 Mass entity 的 FMovementGoalFragment
   ↓
URTSMovementProcessor::Execute
   │ 读 FMovementGoalFragment
   │ 计算路径,设 Velocity
   ↓
[实际移动 + 网络复制 entity 位置回 client]
```

7 步链。每步在不同类 / Subsystem,职责清晰。

## 9.5.5 服务器权威 vs 客户端预测

### 9.5.5.1 RTS 通常用 Server 权威(无预测)

理由:
- RTS 命令延迟感不强(玩家点 → 单位响应几百 ms,可接受)
- 预测会让"反作弊"复杂(client 可能伪造预测)
- 50K 单位预测同步成本高

### 9.5.5.2 客户端可视化反馈(不是预测)

```cpp
void ARTSPlayerController::OnRightClick(...)
{
    // 1. 立刻播放点击特效(本地 visual feedback)
    SpawnClickIndicator(TargetLoc);
    
    // 2. 发 RPC 到 server
    ServerIssueMoveCommand(SelectedUnits, TargetLoc);
    
    // 3. 不预测移动 — 等 server 响应
    //    单位真正动起来要等 server 状态 replicate 回来(~50-200ms)
}
```

特效是即时反馈,但**单位本身不预测**。这平衡了响应感与一致性。

## 9.5.6 网络模式选择(简单总览)

```
RTS 网络架构选择:

[Authoritative Snapshot 模式]                    [Lockstep 模式]
   ├─ Server 模拟所有单位                          ├─ 所有 client 都模拟所有单位
   ├─ Server 状态 replicate 到 client              ├─ Client 之间只同步输入(命令)
   ├─ 简单(不需 determinism)                     ├─ 需要严格浮点 determinism
   ├─ 反作弊容易(server 权威)                    ├─ 反作弊难(client 可伪造)
   ├─ 带宽:50K 单位 × 状态                        ├─ 带宽:仅命令(几 KB / s)
   └─ ★ 大多数 RTS 推荐                           └─ 古典 RTS(StarCraft 1)用
```

§14 / §26 详讲。RTS 项目通常 Authoritative Snapshot + Mass + Iris。

## 9.5.7 Mass 与 Gameplay 框架的接口

Mass 在框架里的"接口点":

```
GameMode (server) → 决定何时 SpawnEntity
   │ 调用
   ↓
UMassSpawnerSubsystem::SpawnEntities(Config, Count)
   │ 创建 entity
   ↓
Mass Subsystem 持有 entity 数据
   │
   ↓
[Mass tick]
   ├─ Movement Processor 等读 / 写 Fragment
   └─ ...
   ↓
[网络复制]
UMassReplicationProcessor → Iris 系统 → client
   │
   ↓
[Client 端]
Mass Subsystem 收到 replicated 数据
   ↓
[渲染]
URepresentationProcessor → ISMC / VAT
```

Mass entity 几乎"不出现在 GameMode / GameState / PlayerController" — 这些经典 Gameplay 类只**协调**,真正的单位逻辑在 Mass 内部。

## 9.5.8 BP 接入点

设计 RTS 时考虑"哪些走 C++,哪些 BP":

| 类 | C++ 还是 BP |
|---|---|
| ARTSGameMode | C++(关键规则,不希望 BP 改) |
| ARTSGameState | C++ 或 BP(数据复制) |
| ARTSPlayerController | C++(命令派发逻辑要稳) |
| ARTSPlayerState | C++(数据) |
| ARTSCameraPawn | BP(相机控制 BP 友好) |
| ARTSHUD | BP(UI 主要 BP / UMG) |
| Mass Trait | BP(策划配置) |
| Mass Processor | C++(性能关键) |
| Mass Fragment | C++ + USTRUCT(数据,无 BP 函数) |
| URTSCombatSubsystem | C++(server 逻辑) |

总原则:**性能关键 / 网络逻辑 → C++,UI / 配置 / 策划脚本 → BP**。

### 9.5.10.1 RTS 项目"高层架构 cheat sheet"

每次添加新功能,问自己:

```
1. 数据是 server 权威吗?
   ✓ → GameState / Subsystem (server only)
   ✗ → ULocalPlayerSubsystem
   
2. 数据要 replicate 吗?
   ✓ + per-player → PlayerState
   ✓ + global → GameState
   ✗ → 看下面
   
3. 要 Tick 吗?
   ✓ → UTickableWorldSubsystem 或 Actor::Tick
   ✗ → 普通 UWorldSubsystem 或 ULocalPlayerSubsystem
   
4. 跨关卡持久?
   ✓ → UGameInstanceSubsystem
   ✗ → UWorldSubsystem
   
5. 进程级共享?
   ✓ → UEngineSubsystem
```
