# §3.4 CDO / Archetype / Instance — 三态对象的关系

> **本节地图**:模块一第 3 章第 4 节。§3.3 反复提到 CDO,这一节单独把它揪出来讲清。
>
> UE 里**同一个 UClass**对应的 UObject 有**三种身份**:
>
> - **CDO**(Class Default Object)— 每个 UClass 一个,记录"这个类的默认值长什么样"
> - **Archetype**(模板对象)— 比 CDO 更灵活,Blueprint / 实例资产引用
> - **Instance**(实例)— 真实游戏中的对象
>
> 三者的关系决定了:
> - Editor Property panel 改"默认值"是改谁
> - Blueprint 类的 default 怎么来
> - 网络复制的 baseline 是谁
> - 序列化为什么只存"与 archetype 不同的字段"
>
> **预备知识**:§3.1(对象 flag)、§3.3(NewObject / InitProperties)。
>
> **读完之后你能做到**:
> - 区分 CDO、Archetype、Instance 三者的身份与关系
> - 解释"在 BP 编辑器里改 Health = 200 后所有实例 Health 跟着变"的机制
> - 看到 `RF_ClassDefaultObject` / `RF_ArchetypeObject` flag 知道含义
> - 理解 `Object->GetArchetype()` 的返回值规则
> - 调试"为什么我的实例某字段没拿到默认值"
> - 在 RTS 视角下评估"靠 BP 配置 vs DataAsset 配置"的代价

## 3.4.1 浅入:为什么需要"模板对象"?

考虑一个简单场景:

```cpp
UCLASS()
class UMyComp : public UActorComponent
{
public:
    UPROPERTY(EditAnywhere)
    int32 Health = 100;
};
```

代码里 `Health = 100` 是 default。Editor 里你看 BP 类 `BP_MyComp`,Property panel 显示 `Health: 100` —— 因为它继承自 C++ 类的 default。

现在你在 Editor 改 BP 类的 `Health = 200`。你**没改任何 .cpp**,只在 Editor 操作。Editor 关掉再开,Health 还是 200(资产保存了)。运行游戏 NewObject<UMyComp>(...),实例的 `Health = 200`(继承 BP 类)。

**问题**:`200` 这个值存哪里?C++ 类没动,所有 UMyComp 实例怎么自动拿到 200?

答案:Editor 在你改字段时改的不是 Instance,也不是 .cpp 默认值,而是**BP 类的"模板对象"**。这个模板对象就是这一节的主角。

UE 里模板对象有两种身份:**CDO** 和 **Archetype**。

---

## 3.4.2 CDO(Class Default Object)— 每个 UClass 一个

### 3.4.2.1 CDO 是什么

打开 `Engine/Source/Runtime/CoreUObject/Public/UObject/Class.h:3928`:

```cpp
class UClass : public UStruct
{
    // ...
    UE_DEPRECATED(5.6, "ClassDefaultObject will be made private in the next release. ...")
    TObjectPtr<UObject> ClassDefaultObject;
    // ...
};
```

每个 `UClass` 实例都有一个 `ClassDefaultObject` 字段,**指向一个该类的实例对象**。这个实例就是 CDO。

CDO 的特点:
- 每个 UClass 有且仅有 1 个 CDO(单例)
- 它的 `ObjectFlags` 含 `RF_ClassDefaultObject`(§3.1.4)
- 名字格式 `Default__<ClassName>`(例 `Default__MyComp`)
- 它的 `GetClass()` 就是它属于的那个 UClass

### 3.4.2.2 CDO 何时被创建

§2.2 讲过:`UClass` 在反射注册阶段(`Z_Construct_UClass_*`)末尾,**会创建一个 CDO**:

```cpp
// 简化伪代码
UClass* Z_Construct_UClass_UMyComp()
{
    UClass* Cls = ...;       // 构造 UClass 对象
    
    // 反射元数据(字段、函数)就绪后
    Cls->ClassDefaultObject = StaticAllocateObject(Cls, ...);   // 创建 CDO
    Cls->ClassConstructor(FObjectInitializer(CDO));              // 调 ctor
    
    return Cls;
}
```

**CDO 也走完整 NewObject 流程**(§3.3):分配内存 + ctor + InitProperties + PostInitProperties。但有几个特殊:
- CDO 自己**没有 archetype**(它是终极祖先),InitProperties 阶段从父类的 CDO 拷
- CDO 的 PostInitProperties 通常是空操作或 noop
- 创建 CDO 后,UClass 反射注册才算完成

### 3.4.2.3 CDO 的字段值来自哪里

CDO 创建时 ctor 跑一遍。所以 ctor 里写的初始化值落到 CDO:

```cpp
UMyComp::UMyComp(const FObjectInitializer& OI) : Super(OI)
{
    Health = 100;       // CDO.Health = 100,后续所有实例从 CDO 拷 100
}
```

如果 ctor body 没写,默认成员初始值也会进 CDO:

```cpp
UCLASS()
class UMyComp
{
    UPROPERTY()
    int32 Health = 100;     // 字段默认值,CDO ctor 跑后 CDO.Health = 100
};
```

### 3.4.2.4 用 `GetDefault<T>()` 访问 CDO

```cpp
// 通用模板(读取)
const UMyComp* CDO = GetDefault<UMyComp>();
int32 DefaultHealth = CDO->Health;     // 100

// 修改(罕见,通常通过 Editor)
UMyComp* MutableCDO = GetMutableDefault<UMyComp>();
MutableCDO->Health = 999;
// 之后所有 NewObject<UMyComp> 实例都从 999 开始
```

`Engine/Source/Runtime/CoreUObject/Public/UObject/Class.h:4373`:

```cpp
UObject* GetDefaultObject(bool bCreateIfNeeded = true) const
{
    if (ClassDefaultObject == nullptr && bCreateIfNeeded)
    {
        // 第一次访问时 lazy 创建(对于 BP 类等场景)
        ...
    }
    return ClassDefaultObject;
}
```

### 3.4.2.5 CDO 不会被 GC 回收

CDO 创建时 flags 含 `RF_ClassDefaultObject` + `RF_RootSet`(等价的内部标记)。GC 跳过 CDO,所以 CDO 在进程整个生命周期内存在。

这是为什么 `GetDefault<T>()` 永远是合法操作。

## 3.4.3 Archetype —— 比 CDO 更灵活的"模板"

### 3.4.3.1 BP 类的"默认值"

考虑 BP 类 `BP_MyHero` 继承自 `UMyComp`。Editor 里你在 BP 类编辑器修改 `Health = 200`。

这个 `200` 存在哪?

- **不**改 C++ CDO(那是只读的、来自 .cpp)
- **改**了 BP 类的"自己的 CDO"——每个 BP 类也是一个 UClass(BP 编译产物),有自己的 CDO

BP 编辑器实际上做的是:

```cpp
// 大致流程
BP_MyHero_Class = NewObject<UClass>(BlueprintGeneratedClass);
BP_MyHero_Class->SuperClass = UMyComp::StaticClass();
BP_MyHero_Class->ClassDefaultObject = NewObject<UObject>(BP_MyHero_Class, ...);   // BP 类的 CDO
// 把 BP 编辑器里改的字段值写到这个 CDO
GetMutableDefault<UMyComp>(BP_MyHero_Class)->Health = 200;
```

所以 `BP_MyHero` **有自己的 CDO**,字段值 = C++ CDO + BP 编辑器覆盖。

后续 SpawnActor / NewObject 用 `BP_MyHero_Class` 时,InitProperties 从 BP 类的 CDO 拷字段 → 实例 Health = 200。

### 3.4.3.2 Archetype 一般化

BP 类 CDO 是**Archetype 的特例**。更一般地,Archetype 是"任何被实例引用为模板的对象"。包括:

1. **C++ 类的 CDO** —— 上面讲过
2. **BP 类的 CDO** —— BP 配置默认值
3. **关卡里 Actor 实例** —— 关卡 Actor 拖到关卡里,可作为其它实例的模板(罕见)
4. **Instanced Component 模板** —— Actor 内嵌 Component 的"原型"
5. **Subobject Default Override** —— BP 类里覆盖默认 Component 配置

每种 archetype 都有 `RF_ArchetypeObject` 或 `RF_ClassDefaultObject` flag(后者是 CDO 这个特殊子集)。

### 3.4.3.3 `GetArchetype()` 怎么找到模板

`Engine/Source/Runtime/CoreUObject/Private/UObject/UObjectArchetype.cpp:283`:

```cpp
UObject* UObject::GetArchetype() const
{
    return GetArchetypeImpl(this, nullptr);
}
```

内部 `GetArchetypeImpl` 的逻辑(简化):

```cpp
UObject* GetArchetypeImpl(const UObject* InObj, ...)
{
    UClass* Class = InObj->GetClass();
    UObject* Outer = InObj->GetOuter();
    FName Name = InObj->GetFName();
    
    // 1. 在 Outer 的 archetype 树里找同名同类型的"模板"
    if (UObject* OuterArchetype = Outer->GetArchetype())
    {
        if (UObject* Result = StaticFindObjectFastInternal(Class, OuterArchetype, Name))
        {
            return Result;       // 找到 → 这个对象的 archetype 是 OuterArchetype 下的同名子对象
        }
    }
    
    // 2. fallback:用 Class 的 CDO
    return Class->GetDefaultObject();
}
```

### 3.4.3.4 一个完整的 archetype 链示例

考虑:`AMyHeroBP`(BP 类继承自 C++ 的 `AMyHero`)在关卡里放了一个实例 `MyHero_1`,`MyHero_1` 含 component `MeshComp_0`。

这个 `MeshComp_0` 实例的 archetype 链:

```
MeshComp_0 (Instance)
    │
    │ GetArchetype() 找 MyHeroBP_CDO 下的 MeshComp_0
    ↓
MyHeroBP_CDO.MeshComp_0 (BP 类 CDO 的子对象 archetype)
    │
    │ 它的 archetype 是 父类 CDO 的 MeshComp_0
    ↓
AMyHero_CDO.MeshComp_0 (C++ 类 CDO 的子对象 archetype)
    │
    │ AMyHero_CDO 没有更上层 archetype,但 MeshComp_0 类是 UStaticMeshComponent
    │ 所以 MeshComp_0 的最终 archetype fallback 到
    ↓
UStaticMeshComponent::CDO
```

每层都可能"覆盖"上层的字段值。InitProperties 时按链拷字段(实际是直接从最近的 archetype 拷)。

### 3.4.3.5 `RF_ClassDefaultObject` vs `RF_ArchetypeObject`

```cpp
RF_ClassDefaultObject = 0x00000010      // 是某 UClass 的 CDO
RF_ArchetypeObject    = 0x00000020      // 是某种 archetype(BP CDO / 关卡 Actor / Component 模板)
```

CDO 特殊性(子集):
- 由 UClass 直接持有(`UClass::ClassDefaultObject`)
- 名字 `Default__<ClassName>`
- 整个进程内最多 1 个 / UClass

普通 archetype:
- 不被 UClass 直接持有
- 通过 Outer 链查找
- 例子:嵌入 Actor 的 Component 模板

### 3.4.3.6 检测对象身份

```cpp
if (Obj->HasAnyFlags(RF_ClassDefaultObject))
{
    // 它是某 UClass 的 CDO
}

if (Obj->HasAnyFlags(RF_ArchetypeObject))
{
    // 它是某种 archetype(包括 CDO,因为 archetype 是更宽的概念)
}

if (!Obj->HasAnyFlags(RF_ArchetypeObject | RF_ClassDefaultObject))
{
    // 它是普通 instance
}
```

## 3.4.4 Instance —— 真正在游戏里跑的对象

普通的 `NewObject<T>` 或 `SpawnActor` 创建的就是 Instance。它的特点:
- 有特定的 Outer(关卡 / Actor / Subsystem)
- ObjectFlags **不包含** RF_ClassDefaultObject 和 RF_ArchetypeObject(通常)
- GC 会扫它的引用,不可达就回收
- 字段值 = 从 archetype 拷过来 + 运行时修改

### 3.4.4.1 Instance 的字段初始化路径

```
NewObject<T>(Outer, ...)
   ↓
StaticAllocateObject:分配内存 + 调 ctor(字段拿到 ctor 默认值)
   ↓
FObjectInitializer 析构期 InitProperties:
   ↓
   找到这个 Instance 的 archetype:
     - 如果 Outer 链没有匹配,用 T::CDO
     - 如果 Outer 是某 archetype,递归找子对象 archetype
   ↓
   逐字段从 archetype 拷:
     for FProperty P in Class->PropertyLink:
        if (P->ShouldDuplicateValue())
            CopyValue(Instance.P, Archetype.P)
```

### 3.4.4.2 InstanceField 数据流图

```
[C++ 类编译期默认值]
   ↓
[C++ 类 CDO 的字段值]            ←── 由 UHT 生成 + ctor body 写入
   ↓ (BP 类继承时拷)
[BP 类 CDO 的字段值]              ←── BP 编辑器修改这一层
   ↓ (NewObject 时 InitProperties 拷)
[Instance 的字段值]
   ↓ (运行时游戏逻辑修改)
[Instance 的运行时值]
```

每一层都能 override 上一层。**Editor 改 BP 默认值** = 改第二层。**游戏代码 `Comp->Health = X`** = 改第四层。

## 3.4.5 三态对象的标志比较

| 维度 | C++ CDO | BP CDO | Archetype(嵌入 Component) | Instance |
|---|---|---|---|---|
| 数量 | 每 C++ UCLASS 1 个 | 每 BP 类 1 个 | 看嵌入数量 | 任意 |
| Outer | 通常 Class 的 Package | BP 资产 Package | 父对象 archetype | 父对象实例 |
| Flags | RF_ClassDefaultObject + RF_ArchetypeObject | 同左 | RF_ArchetypeObject | 通常无这两 flag |
| GC | 不回收(CDO 永生) | 不回收(只要类还在) | 跟父 archetype | 正常 GC |
| 由谁创建 | 反射注册期 | BP 编译时 | BP 编辑期 | NewObject / SpawnActor |
| 用途 | C++ 默认值源头 | BP 默认值源头 | Component 模板 | 游戏对象 |

## 3.4.6 序列化与 Archetype —— "delta 序列化"

UE 资产的 .uasset 文件**只存"与 archetype 不同的字段"**。这是典型的 delta serialization:

```cpp
// 简化伪代码
void UObject::Serialize(FArchive& Ar)
{
    UObject* Archetype = GetArchetype();
    
    for FProperty P in Class->PropertyLink:
        if (P 在我的实例的值 != P 在 archetype 的值):
            序列化"这个字段"和"我的值"
        else:
            跳过(加载时从 archetype 拿默认即可)
}
```

好处:
- **资产文件小**:99% 字段没改 → 不存
- **修改默认值能传播**:你改 archetype 后,旧资产加载时还会从新 archetype 拿到默认 — 自动适配

代价:
- 加载顺序依赖:加载 instance 之前必须先加载 archetype
- BP 编辑器改 archetype 后,旧资产可能"莫名其妙地"字段值变了

§3.5 详讲序列化机制。

## 3.4.7 网络复制中的 archetype baseline

`UNetConnection` 第一次复制一个对象时,**只发"与 archetype 不同的字段"**:

```cpp
// 简化
for FProperty P in Class:
    if (Object.P != Archetype.P):
        序列化 P 到网络包
```

加上后续帧的 dirty diff 复制,这就是 §13 / §14 讲的 RepLayout 机制。**不理解 archetype,你读不懂 NetSerialize**。

### 3.4.7.1 Mass 怎么应付这个

Mass 网络复制(`UMassNetworkingTrait` + `Iris`)**不**走传统 RepLayout(那是 UObject 专属)。Mass 自己定义复制策略,用 BitSet + delta encoding,完全绕过 archetype baseline 概念。

但你 RTS 的"重要 Actor"(英雄、GameState)仍走传统复制 → archetype 概念有效。

## 3.4.8 RTS / Mass 视角下的纪律

### (1)Mass Fragment **无 archetype 体系**

Fragment 是 USTRUCT(POD 数据),**没有 CDO,没有 archetype**。Fragment 的"默认值"由 UScriptStruct 的字段默认值决定(代码里 `int32 X = 0;` 那种),通过 UHT 反射注册时存入 UScriptStruct 元数据。

Mass entity 创建时,Fragment 数据从 USTRUCT 的 ctor 默认 + Trait 配置覆盖,**不**走 NewObject/CDO 链。

### (2)Trait 配置走 BP 类 archetype 路径

`URTSMovementTrait` 是 UCLASS,可作为资产配置:

```cpp
UCLASS(BlueprintType)
class URTSMovementTrait : public UMassEntityTraitBase
{
    UPROPERTY(EditAnywhere)
    float MaxSpeed = 5.0f;
};
```

Editor 里你给 `URTSMovementTrait` 创建一个 BP 子类 `BP_FastMovementTrait`,改 `MaxSpeed = 10`。这就是 BP 类 CDO 的修改。

Mass Spawner 引用 `BP_FastMovementTrait` 时,拿到的是其 BP CDO,`MaxSpeed = 10`。Spawner 把这个值写到 Fragment 数据里。

**所以 Trait 这一层**仍然走传统 archetype 体系,**Fragment 这一层**完全跳过。两层语义清晰。

### (3)永远不要在 hot path 调 `GetArchetype()`

```cpp
// ❌ Mass Processor 内
for (Entity in Chunk)
{
    UObject* A = Obj->GetArchetype();    // 慢,微秒级
    // ...
}
```

`GetArchetype` 内部要遍历 Outer 链 + StaticFindObject。HotPath 上累积成本巨大。

```cpp
// ✅ 启动期一次性查
UObject* CachedArchetype = SomeObj->GetArchetype();
// 后续直接用 CachedArchetype
```

### (4)RTS 配置数据:用 DataAsset 而不是 BP 类

如果你 RTS 有大量"配置数据"(单位属性、技能数值、武器特性),两种存储姿势:

**姿势 A:BP 类继承**(传统)
```cpp
// 每种单位一个 BP 类继承自 URTSUnitConfig
BP_UnitConfig_Knight : URTSUnitConfig    Health=100, Damage=20
BP_UnitConfig_Archer : URTSUnitConfig    Health=80, Damage=30
```

**姿势 B:UDataAsset 实例**(推荐)
```cpp
UCLASS()
class URTSUnitConfig : public UDataAsset
{
    UPROPERTY(EditAnywhere) int32 Health;
    UPROPERTY(EditAnywhere) int32 Damage;
};
// 资产实例:DA_UnitConfig_Knight, DA_UnitConfig_Archer ...
```

差异:
- BP 类:每种单位 = 一个 UClass(反射注册)+ 一个 CDO + BP 字节码
- DataAsset:每种单位 = 一个 UDataAsset 实例(只是普通对象,不是新类)

**RTS 数百种单位 → 姿势 B 远胜**:
- 启动期反射注册量小(几十个 BP 类 vs 几百个 DataAsset)
- 内存占用小(没 CDO + 字节码)
- 代码改动易(改 DataAsset 字段不重编)

### (5)`GetMutableDefault<T>()` 的运行时危险

```cpp
GetMutableDefault<UMyComp>()->Health = 50;   // ★ 改 CDO 在游戏中
// 后果:之后 NewObject 的实例 Health 默认 50
```

**绝不**在游戏运行时改 CDO!你看似只改一个数,实际:
- 影响所有未来 NewObject 的实例
- 资产保存时会变,因为存的是"和 archetype 不同的部分"
- 跨网络可能不一致(每个客户端 CDO 改不改?)

CDO 修改只在**Editor 工具**或**启动期**做。运行时绝对禁止。

## 3.4.9 调试:看你某个对象的 archetype 链

```cpp
static FAutoConsoleCommand CmdInspectArchetype(TEXT("rts.InspectArchetype"),
    TEXT("rts.InspectArchetype <ObjName>"),
    FConsoleCommandWithArgsDelegate::CreateLambda([](const TArray<FString>& Args)
    {
        if (Args.Num() == 0) return;
        UObject* Obj = FindFirstObject<UObject>(*Args[0]);
        if (!Obj) { UE_LOG(LogTemp, Warning, TEXT("Not found")); return; }
        
        UE_LOG(LogTemp, Display, TEXT("=== Archetype Chain for %s ==="), *Obj->GetFullName());
        
        UObject* Cur = Obj;
        int32 Depth = 0;
        while (Cur && Depth < 10)
        {
            FString Tag;
            if (Cur->HasAnyFlags(RF_ClassDefaultObject))   Tag = TEXT(" [CDO]");
            else if (Cur->HasAnyFlags(RF_ArchetypeObject)) Tag = TEXT(" [Archetype]");
            else                                             Tag = TEXT(" [Instance]");
            
            UE_LOG(LogTemp, Display, TEXT("  %d: %s%s (Class=%s)"), 
                Depth, *Cur->GetFullName(), *Tag, *Cur->GetClass()->GetName());
            
            UObject* Archetype = Cur->GetArchetype();
            if (Archetype == Cur || !Archetype) break;
            Cur = Archetype;
            ++Depth;
        }
    }));
```

跑 `rts.InspectArchetype YourObject`,你能看到完整链条。这是理解"为什么 BP 类的字段不是我代码里设的值"的最直接工具。

## 3.4.10 实操提示与下一节预告

  ```cpp
  UClass* C = UMyComp::StaticClass();
  UObject* CDO = C->GetDefaultObject();
  // 用 §2.3.13 的 dump 函数打印
  ```

- **诊断"修改 BP 默认值后实例没变"**:
  - 检查实例的 `GetArchetype()` 是不是你改的那个 BP CDO
  - 旧实例(已 spawn)不会重读 archetype,只在创建时拷
