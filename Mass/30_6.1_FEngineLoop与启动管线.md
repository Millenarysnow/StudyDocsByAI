## 6.1.1 浅入:`FEngineLoop` 是什么

UE 的"主循环"不是一个简单 `while(true) { ... }`。它是一个**对象**:

```cpp
// LaunchEngineLoop.h:48
class FEngineLoop
{
public:
    int32 PreInit(int32 ArgC, TCHAR* ArgV[], const TCHAR* AdditionalCommandLine = nullptr);
    int32 PreInit(const TCHAR* CmdLine);
    int32 PreInitPreStartupScreen(const TCHAR* CmdLine);
    int32 PreInitPostStartupScreen(const TCHAR* CmdLine);
    
    virtual int32 Init() override;
    virtual void Tick() override;
    void Exit();
    // ...
};
```

进程内有**全局唯一**的一个 `FEngineLoop` 实例 `GEngineLoop`(`Launch.cpp` 文件作用域)。整个生命周期:

```
WinMain
   ↓
GuardedMain
   ↓
EnginePreInit (调 GEngineLoop.PreInit)
   ↓
EngineInit (调 GEngineLoop.Init)
   ↓
while (!IsEngineExitRequested())
{
    EngineTick (调 GEngineLoop.Tick)
}
   ↓
EngineExit (调 GEngineLoop.Exit)
   ↓
return 0
```

**`FEngineLoop` 不是引擎逻辑的"中央",而是"启动 + 调度"的协调者**。具体游戏逻辑在 `UEngine` / `UWorld` / `AGameMode` 里。

## 6.1.3 `PreInit` 的"前后两半"为什么拆开

`PreInit` 在 `LaunchEngineLoop.cpp:4332` 被定义为:

```cpp
int32 FEngineLoop::PreInit(const TCHAR* CmdLine)
{
    int32 ErrorLevel = PreInitPreStartupScreen(CmdLine);
    if (ErrorLevel != 0) return ErrorLevel;
    
    // 中间:启动 Splash Screen / Loading Movie
    
    return PreInitPostStartupScreen(CmdLine);
}
```

中间夹一个**Splash Screen**显示。把 PreInit 拆成两半的原因:

- **PreInitPreStartupScreen**:Splash Screen 出现**之前**必须做完的事(读 INI、创建 GMalloc、加载 CoreUObject 等)。这一阶段越快越好,玩家看到黑屏。
- **PreInitPostStartupScreen**:Splash Screen 显示后做的"重活"(加载几百个模块、初始化反射、初始化渲染)。玩家有 splash 看,可以慢点。

**实战意义**:RTS 项目想"启动尽快显示 Logo",把 logo 显示放在 PreInit 中间(splash screen 阶段)。`-LoadingScreen` 命令行让你定制。

## 6.1.4 LoadingPhase 在启动期的位置

§0.2.3.4 讲过 `ELoadingPhase`。每个 Plugin / Module 的 LoadingPhase 决定它在启动哪个时机被加载:

```
EarliestPossible          ← 比 PostConfigInit 还早(罕见,平台底层 hook)
        ↓
PostConfigInit            ← Config 已就绪,GMalloc 已就绪,但 CoreUObject 未必
        ↓
PostSplashScreen          ← splash 显示后
        ↓
PreEarlyLoadingScreen     ← 早期 Loading 之前
        ↓
[CoreUObject 加载完成,UClass 反射注册]
        ↓
PreLoadingScreen          ← 可以挂正式 Loading Screen 钩子
        ↓
PreDefault                ← Default 之前(基础设施模块)
        ↓
Default                   ← 大多数游戏模块(默认值)
        ↓
PostDefault               ← Default 之后
        ↓
[FEngineLoop::Init 开始]
        ↓
PostEngineInit            ← Engine 完整初始化后(Editor 工具典型用)
        ↓
None                      ← 不自动加载,代码手动 LoadModule
```

### 6.1.4.1 RTS 项目的 LoadingPhase 决策表

```json
{
    "Modules": [
        {
            "Name": "MyRTSCore",
            "LoadingPhase": "PreDefault"     ← Fragment 类型注册到反射先于 Mass 子系统
        },
        {
            "Name": "MyRTSMass",
            "LoadingPhase": "Default"         ← 主游戏模块
        },
        {
            "Name": "MyRTSEditor",
            "LoadingPhase": "PostEngineInit"  ← Editor 工具,所有 Editor 子系统就绪后
        }
    ]
}
```

如果 LoadingPhase 选错:
- **过早**(PostConfigInit 加载 Editor 模块)→ 依赖的子系统还不存在,崩
- **过晚**(PostEngineInit 加载游戏模块)→ Engine 已经在创建 GameInstance,你的模块来不及注册 Subsystem

**纪律**:**99% 用 Default 即可**,基础设施模块用 PreDefault,Editor 工具用 PostEngineInit。

## 6.1.5 `GEngine` —— UEngine* 全局变量

`#include "Engine/Engine.h"`,`extern UEngine* GEngine;` 是个全局指针。它**指向**当前进程的 UEngine 实例。

但 UEngine 有多态:
- **Game build** → `UGameEngine`(`Engine/Source/Runtime/Engine/Classes/Engine/GameEngine.h`)
- **Editor build** → `UEditorEngine`(`Engine/Source/Editor/UnrealEd/Classes/Editor/EditorEngine.h`)

两者继承自 `UEngine`,行为差异巨大。`GEngine` 实际指向哪个,看构建配置。

### 6.1.5.1 UEngine 的核心职责

```cpp
class UEngine : public UObject, public FExec
{
public:
    virtual void Init(IEngineLoop* InEngineLoop);         // 启动期初始化
    virtual void Tick(float DeltaSeconds, bool bIdleMode); // 主循环 tick
    virtual void PreExit();
    
    // GameInstance 管理
    UGameInstance* GetGameInstance() const;
    
    // World 管理
    UWorld* GetWorld() const;
    
    // ... 等等 ...
};
```

`UGameEngine` 主要补充"游戏视口、GameInstance 创建、关卡加载"。`UEditorEngine` 补充"Editor 启动、PIE、资产管理"。

### 6.1.5.2 取 GEngine 的姿势

```cpp
if (GEngine)
{
    GEngine->AddOnScreenDebugMessage(-1, 5.f, FColor::Yellow, TEXT("Hi"));   // 屏幕 debug
    UWorld* W = GEngine->GetWorld();
}

// 类型转换(很少需要)
if (UEditorEngine* EE = Cast<UEditorEngine>(GEngine))
{
    // Editor 特定操作
}
```

### 6.1.5.3 何时 `GEngine` 有效

```
PreInitPreStartupScreen    GEngine == nullptr
PreInitPostStartupScreen   GEngine 在中段被创建,后段已存在
Init                        ✓
Tick                        ✓
Exit                        最后才 nullptr
```

**纪律**:模块 `StartupModule()` 里**不要**假设 GEngine 存在(取决于 LoadingPhase)。如果你必须用,改用 `FCoreDelegates::OnPostEngineInit` 委托延迟到 `PostEngineInit` 之后。

## 6.1.6 Tick 的整体管线

`FEngineLoop::Tick`(LaunchEngineLoop.cpp:5536)结构(简化):

```cpp
void FEngineLoop::Tick()
{
    SCOPED_NAMED_EVENT_TEXT("FEngineLoop::Tick", FrameColor);
    
    // 1. 退出请求 / 错误检测
    BeginExitIfRequested();
    
    // 2. Heartbeat(死锁检测)
    FThreadHeartBeat::Get().HeartBeat();
    FGameThreadHitchHeartBeat::Get().FrameStart();
    
    // 3. RHI / RenderingThread 同步
    LatchRenderThreadConfiguration();
    
    // 4. Movie player 阻塞(loading screen)
    FMoviePlayerProxy::BlockingForceFinished();
    
    // 5. 计算 DeltaTime
    UpdateTimeAndHandleMaxTickRate();
    
    // 6. 每帧 stat 更新
    GLog->FlushThreadedLogs();
    GFrameCounter++;
    
    // 7. ★★★ 核心:GEngine 的 Tick(World tick 走这里)
    GEngine->Tick(FApp::GetDeltaTime(), bIdleMode);
    
    // 8. RHIThread 命令推送
    GEngine->TickDeferredCommands();
    
    // 9. RenderThread / GPU 同步
    EndOfFrameUpdates();
    
    // 10. 下一帧 BeginFrame
    RHIBeginFrame();
}
```

### 6.1.6.1 `GEngine->Tick` —— 真正的游戏 tick 入口

这一步内部调:
- `UWorld::Tick`(对每个活的 World)
- `UGameInstance::Tick`
- `UEngine::TickPerformanceMonitoring`
- 各种 Subsystem tick

**这是整个游戏每帧逻辑的入口**。第 7 章 / 第 8 章会详细拆 `UWorld::Tick`。

### 6.1.6.2 三线程时间线

```
GameThread:       [Tick A]    [Tick B]    [Tick C]
                    │           │           │
                    ▼ enqueue   ▼           ▼
RenderThread:     [Frame A]   [Frame B]   [Frame C]
                              │           │
                              ▼ enqueue   ▼
RHIThread:                  [GPU A]      [GPU B]      [GPU C]
                                          │           │
                                          ▼ submit    ▼
GPU:                                    [Render A] [Render B]
```

GameThread tick 把命令塞给 RenderThread,RenderThread 处理后塞给 RHIThread,RHIThread 提交给 GPU。**三线程错帧**,典型延迟 2-3 帧。

`FEngineLoop::Tick` 的"BeginFrame / EndFrame"边界控制这种错帧的同步。

## 6.1.7 退出与清理

```
游戏代码调 RequestExit
   ↓
FEngineLoop::Tick 检测 IsEngineExitRequested,准备退出
   ↓
跳出 while 循环
   ↓
FEngineLoop::Exit
   ├─ GEngine->PreExit()
   ├─ 卸载所有 Plugin
   ├─ 关闭 World / GameInstance
   ├─ 触发 PreExit / OnExit 委托
   ├─ 清理 GMalloc(进程退出时跳过 free,加速退出)
   └─ 返回控制给 GuardedMain
```

**关键事**:Editor 退出时,UEngine 会做完整 Cleanup;Game build Shipping 退出时,有时**故意跳过**清理(进程反正要 exit,OS 会回收内存,跳过加速退出)。

## 6.1.8 `Standalone` / `PIE` / `Dedicated Server` 启动差异

### 6.1.8.1 Standalone Game(`MyGame.exe`)

```
WinMain → GuardedMain → PreInit → Init
   ↓
LoadDefaultMap(默认关卡,从 DefaultEngine.ini 读)
   ↓
SpawnPlayerController + Pawn
   ↓
进 Tick 循环
```

### 6.1.8.2 PIE(Editor 里 Play)

```
Editor 已启动(GEngine = UEditorEngine)
   ↓
玩家点 "Play"
   ↓
UEditorEngine::PlayInEditor
   ├─ 复制当前 Editor World 到一个新 PIE World
   ├─ 启动 GameInstance(可能 share Editor 进程或独立进程)
   ├─ 创建 PlayerController
   └─ tick PIE World
   ↓
玩家点 "Stop"
   ├─ 销毁 PIE World
   └─ 回 Editor World
```

PIE 在同一进程内**多 World 共存**(Editor World + PIE World)。`GEngine` 仍是 UEditorEngine,各 World 独立 tick。

### 6.1.8.3 Dedicated Server(`MyGameServer.exe`)

```
WinMain → GuardedMain → PreInit → Init
   ↓
绕开图形初始化(NullRHI)
   ↓
LoadDefaultMap (服务器关卡)
   ↓
开 Listen Server / 绑端口
   ↓
进 Tick 循环(无渲染)
```

服务器启动时 `IsRunningDedicatedServer() == true`,绕开 Slate / Renderer 初始化。

## 6.1.9 RTS / Mass 视角下的接入时机

### 6.1.9.1 启动期接入选择

| 场景 | 接入点 | 备注 |
|---|---|---|
| Fragment 类型注册到反射 | UHT 自动 + LoadingPhase=PreDefault | 模块加载即注册 |
| 创建全局 Subsystem | `Initialize` 重写 | 由 GameInstance / World 自动调 |
| 接 GEngine 钩子 | `FCoreDelegates::OnPostEngineInit` | LoadingPhase=PostEngineInit 也可 |
| Editor 工具注册 | `IModuleInterface::StartupModule` 在 PostEngineInit 模块里 | |
| 第一帧 tick 前的初始化 | `UEngineSubsystem::Initialize` / `UWorldSubsystem::Initialize` | 各 Subsystem 入口 |

### 6.1.9.2 Mass 在启动期的位置

`UMassEntitySubsystem` 是 `UWorldSubsystem`,在每个 World 创建时**自动**初始化:

```
LoadDefaultMap
   ↓
UWorld 创建
   ↓
UWorld::InitializeSubsystems → UMassEntitySubsystem::Initialize
   ↓
UMassEntitySubsystem 收集所有 UScriptStruct 子类(已通过 LoadingPhase=PreDefault 注册)
   ↓
分配 BitSet 索引(§2.4.3)
   ↓
就绪
```

**RTS 项目**:你的 `MyRTSCore` 模块加载阶段必须**早于** Mass 子系统初始化时机。`PreDefault` 是稳妥选择 —— 在 Engine 自身初始化之前你的 Fragment 已经注册到反射,Mass 启动时能找到它们。

### 6.1.9.3 RTS 接入 Tick 的位置

```
FEngineLoop::Tick
   ↓
GEngine->Tick
   ↓
UWorld::Tick(PrePhysics / DuringPhysics / PostPhysics / FrameEnd)
   ├─ TickActorComponents
   ├─ TickActors
   └─ Mass Processor 调度(挂在某个 TickGroup)
   ↓
RenderingThread submit
```

**Mass Processor 挂在哪个 TickGroup**?默认 `TG_PrePhysics` 或 `TG_DuringPhysics`,取决于 Processor 的 ExecutionPhase 设置。详 §8.4 / §18.4。

## 6.1.11 调试启动期问题

### 6.1.11.1 启动慢诊断

启动加 `-LogTimes -BootProfile`,LogInit 输出每个 boot timing point 耗时:

```
LogInit: ... FEngineLoop::PreInitPreStartupScreen took 1.234s
LogInit: ... FEngineLoop::PreInitPostStartupScreen took 5.678s
LogInit: ... LoadStartupModules took 3.456s
```

如果某项异常长,要么**模块过多**,要么**模块 StartupModule 阻塞**。

### 6.1.11.2 Insights boot trace

```
UnrealEditor.exe MyProject.uproject -trace=cpu,frame,bookmark,loadtime
```

Insights 加载完 trace,选 "Loading Insights" tab,看启动期每个模块加载时间。一目了然。

### 6.1.11.3 `BOOT_TIMING_POINT` 宏

引擎和你的代码都可以加 boot timing point:

```cpp
SCOPED_BOOT_TIMING("MyRTSEarlyInit");
// 你的初始化代码
```

输出会进 BootProfile,与引擎自带 timing point 同等显示。

### 6.1.11.4 启动期崩溃定位

启动期 crash 通常在:
- **全局静态构造**(`Z_CompiledInDeferFile_*` 出问题)
- **PreInitPreStartupScreen**(命令行错误、INI 错误)
- **CoreUObject 加载**(反射注册冲突)
- **某个 Plugin StartupModule**

VS 调试启动,完整调用栈可见。**断点 `FEngineLoop::PreInit` 第一行**,逐步走能定位。

## 6.1.12 实操:观察自己代码的接入位置

```cpp
// 你某个 Module 的 StartupModule
void FMyRTSCoreModule::StartupModule()
{
    UE_LOG(LogRTSCore, Display, TEXT("MyRTSCore StartupModule called"));
    UE_LOG(LogRTSCore, Display, TEXT("  GEngine = %p"), GEngine);
    UE_LOG(LogRTSCore, Display, TEXT("  GUObjectArray.Num = %d"), GUObjectArray.GetObjectArrayNum());
    UE_LOG(LogRTSCore, Display, TEXT("  IsInitialLoad = %d"), GIsInitialLoad);
    
    FCoreDelegates::OnPostEngineInit.AddRaw(this, &FMyRTSCoreModule::OnPostEngineInit);
}

void FMyRTSCoreModule::OnPostEngineInit()
{
    UE_LOG(LogRTSCore, Display, TEXT("OnPostEngineInit:"));
    UE_LOG(LogRTSCore, Display, TEXT("  GEngine = %p"), GEngine);
    UE_LOG(LogRTSCore, Display, TEXT("  GUObjectArray.Num = %d"), GUObjectArray.GetObjectArrayNum());

```

跑 Editor 看输出,你会看到:
- `StartupModule` 时 `GEngine` 可能 nullptr(LoadingPhase=PreDefault)
- `OnPostEngineInit` 时 `GEngine` 已就绪

帮你建立"何时拿到 GEngine"的肌肉记忆。
