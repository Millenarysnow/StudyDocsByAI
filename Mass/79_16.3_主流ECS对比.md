## 16.3.1 三种 ECS 内存模型

```
1. Sparse Set ECS(EnTT 经典)
   - 每 component 类型一个 sparse array(索引 → 数据)
   - 查询时 join sparse set
   - 优点:add/remove component 极快(O(1))
   - 缺点:多 component 查询有 cache miss

2. Archetype ECS(Mass / Unity DOTS / Flecs)
   - 同 component 组合的 entity 在同一 archetype
   - 同 archetype 内 SoA 排布
   - 优点:cache friendly,SIMD friendly
   - 缺点:add/remove component 触发 archetype 迁移(慢)

3. Hybrid(Bevy)
   - 默认 archetype,可选 sparse(per-component)
   - 灵活
```

Mass 是 **archetype 模型**。

---

## 16.3.2 Mass vs Unity DOTS

Mass 与 Unity DOTS 高度相似(都 archetype):

```
Unity DOTS              Mass
─────────────────────────────────────
Entity (4 字节)          FMassEntityHandle (8 字节)
IComponentData          FMassFragment(USTRUCT)
Tag(空 component)       FMassTag
Archetype                FMassArchetypeData
Chunk(16KB)             FMassArchetypeChunk(默认 128KB)
EntityQuery              FMassEntityQuery
SystemBase               UMassProcessor
EntityCommandBuffer      FMassCommandBuffer
ParallelFor              ParallelForEachEntityChunk
Burst Compiler           ❌(Mass 没 Burst,但 SIMD friendly)
Job System               UE TaskGraph
```

**关键差异**:
- DOTS 用 Burst(LLVM-based,无 GC,极致优化),Mass 用普通 C++(无 Burst)
- DOTS 与 Unity GameObject 完全分离,Mass 与 UObject 共存(WorldSubsystem)
- DOTS 静态 schedule,Mass 动态 ProcessingPhase

经验迁移:Unity DOTS 经验**直接可用**,API 重命名即可。

---

## 16.3.3 Mass vs EnTT

```
EnTT                  Mass
────────────────────────────────────────
entt::registry        FMassEntityManager
entity = uint32        FMassEntityHandle (Index + SerialNumber)
组件添加 emplace<T>    EM.AddFragment<T>
view<...>             EntityQuery + ForEachChunk
组件迭代              ForEachEntity
```

**关键差异**:
- EnTT sparse set,Mass archetype。EnTT add/remove 快,Mass 查询快。
- EnTT 是 header-only C++ 库,Mass 与 UE 反射深度集成
- EnTT 无 networking / debug 工具,Mass 有完整生态

经验迁移:**心智模型类似,API 大不同**。

---

## 16.3.4 Mass vs Bevy ECS(Rust)

Bevy 是 Rust 写的现代 ECS。

```
Bevy                  Mass
─────────────────────────────────────
Entity                FMassEntityHandle
Component             FMassFragment
Tag(zero-size)        FMassTag
Resource              UWorldSubsystem
Query<&T, &mut U>     EntityQuery + Read/Write Required
System fn             UMassProcessor::Execute
SystemSet             ProcessingPhase
Schedule              ExecutionOrder DAG
Commands              FMassCommandBuffer
```

**关键差异**:
- Bevy 用 Rust borrow checker,Mass 没静态保证(运行时检查 RW 冲突)
- Bevy 系统是 fn,Mass 系统是 UClass(BP 友好)
- Bevy 调度静态分析,Mass 动态拓扑排序

---

## 16.3.5 Mass vs Flecs

Flecs 是 Sander Mertens 开发的 C ECS,Hybrid 模型。

```
Flecs                  Mass
─────────────────────────────────────
ecs_entity_t          FMassEntityHandle
ecs_query_t           FMassEntityQuery
Pipeline              UMassCompositeProcessor
Module                Mass Module(ECS Module 概念较弱)
Relationships         ❌(Mass 5.x 加了 Relations,实验)
```

**Flecs 独有**:Relationships(实体关系,如 ChildOf)。Mass 5.x 引入但**实验阶段**(`Engine/Source/Runtime/MassEntity/Public/Relations/`)。

---

## 16.3.6 Mass 独有特性

Mass 与其它 ECS 的差异化:
- **与 UE 反射深度集成**:Fragment 是 USTRUCT,可反射、可 Editor 编辑、可序列化
- **Trait 概念**:`UMassEntityTraitBase` 把"Fragment + Tag + 初始化逻辑"打包成 BP 可配置的资产
- **Spawner 资产驱动**:`UMassEntityConfigAsset` 可视化配置 Trait 组合
- **5+ 种 Fragment 类型**:Fragment / Tag / SharedFragment / ConstSharedFragment / ChunkFragment(其它 ECS 通常 1-2 种)
- **生态**:LOD / Representation / Movement / Replication 等开箱即用

代价:相比 EnTT / Bevy 的 zero-overhead,Mass 有 UObject Subsystem 开销 + UE 反射开销。但收益 = Editor / BP / 网络 / Debug 工具完备。

---

## 16.3.7 心智校准

如果你来自 **Unity DOTS**:Mass 心智几乎一样,API 重命名。注意 Mass 没 Burst,SIMD 靠编译器自动向量化。

如果你来自 **EnTT**:习惯 sparse set 的"add/remove 极快",Mass archetype 迁移有成本(几微秒)。设计时少 add/remove component。

如果你来自 **Bevy**:Mass 没静态借用检查,RW 冲突运行时检测。Trait + EntityConfig 是 Mass 独有,接近 BP 配置。

如果你**从没接触 ECS**:Mass 是你的"第一 ECS",可以放心从这里学起,不用先去看其它框架。
