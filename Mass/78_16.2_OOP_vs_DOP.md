# §16.2 OOP vs DOP — 范式对比

> **本节地图**:模块四第 16 章第 2 节。Mass 是 **DOP(Data-Oriented Programming)**框架,与 UE 主流 OOP 完全不同。这一节用具体例子对比两种范式。
>
> **预备知识**:§3 / §8 / §16.1。
>
> **读完之后你能做到**:
> - 用 cache miss 的具体数字对比 OOP 与 DOP
> - 看到 Mass Fragment 立刻识别 SoA(Structure of Arrays)
> - 知道为什么 SIMD 友好

## 16.2.1 OOP:对象就是世界

```cpp
// OOP
class AUnit : public AActor
{
    FVector Position;
    FVector Velocity;
    int32 Health;
    UStaticMeshComponent* Mesh;
    
    void Tick(float DT)
    {
        Position += Velocity * DT;
        if (Health <= 0) Die();
    }
};

TArray<AUnit*> AllUnits;     // 50K
for (AUnit* U : AllUnits) U->Tick(DT);   // 每个 Tick 一次虚函数 + 散落访问
```

每 Tick:
- 虚函数派发(几纳秒)
- AUnit 对象散落在堆 → cache miss
- Position / Velocity / Health 字段在同一对象,但其它字段(Mesh 等)塞在中间,污染 cache line

**50K × 几百纳秒 = 几十毫秒 / 帧**。

---

## 16.2.2 DOP:数据就是世界

```cpp
// DOP(Mass 风格)
struct FPositionFragment { FVector Position; };
struct FVelocityFragment { FVector Velocity; };
struct FHealthFragment { int32 Health; };

// 在 chunk 内:
TArray<FPositionFragment> Positions;     // 紧密连续
TArray<FVelocityFragment> Velocities;    // 紧密连续
TArray<FHealthFragment> Healths;         // 紧密连续

// 处理:
for (int32 i = 0; i < N; ++i) {
    Positions[i].Position += Velocities[i].Velocity * DT;
}
```

每次循环:
- **顺序访问**(prefetcher 预读后续 cache line)
- 没虚函数(直接调用 / 内联)
- 编译器**自动 SIMD**(循环 + 简单算术)

**50K × 几纳秒 = 几百微秒 / 帧**。

差**几百倍**。

---

## 16.2.3 SoA vs AoS

**AoS**(Array of Structures):

```cpp
struct Unit { FVector Pos; FVector Vel; int32 HP; };
TArray<Unit> Units;       // [Pos, Vel, HP, Pos, Vel, HP, ...]
```

如果只关心 Position(物理 tick),要 cache 加载整个 Unit struct。

**SoA**(Structure of Arrays):

```cpp
TArray<FVector> Positions;  // [Pos, Pos, Pos, ...]
TArray<FVector> Velocities; // [Vel, Vel, Vel, ...]
TArray<int32>  HPs;          // [HP, HP, HP, ...]
```

只关心 Position 时,**只**load Position 数组,cache 命中率 100%。

Mass chunk 用 SoA(§17 详讲)。

---

## 16.2.4 Cache Locality 实证

CPU L1 cache line = 64 字节。

```
AoS Unit (32 字节 / 个):
   一次 cache line load 拿 2 个 Unit
   只用 12 字节(Position)→ 浪费 75%

SoA Position (12 字节 / 个):
   一次 cache line load 拿 5+ 个 Position
   全部用上 → 浪费 ~6%
```

**SoA 的 cache 利用率高 10 倍**。

---

## 16.2.5 SIMD-friendly

SoA 让"循环对相同字段的连续元素"成为可能,编译器自动向量化:

```cpp
// 编译器看到:
for (i = 0; i < N; ++i)
    Positions[i].X += Velocities[i].X * DT;

// 等价于(SSE / AVX):
__m256 dt8 = _mm256_set1_ps(DT);
for (i = 0; i < N; i += 8) {
    __m256 P = _mm256_load_ps(&Positions[i].X);
    __m256 V = _mm256_load_ps(&Velocities[i].X);
    P = _mm256_fmadd_ps(V, dt8, P);
    _mm256_store_ps(&Positions[i].X, P);
}
```

**8 个元素并行处理**。AVX-512 还更快。

AoS 难自动 SIMD(字段不连续)。

## 16.2.6 Mass 的 chunk 内布局(预览)

```
Archetype A 的 Chunk(128 KB):
   ┌────────────────────────────────────────┐
   │ [N Position]                            │ 12 × N 字节
   ├────────────────────────────────────────┤
   │ [N Velocity]                            │ 12 × N 字节
   ├────────────────────────────────────────┤
   │ [N Health]                              │  4 × N 字节
   ├────────────────────────────────────────┤
   │ [N CommandQueue]                        │  ...
   └────────────────────────────────────────┘
   
N = 几百到几千(看 fragment 大小)
```

每个 chunk SoA 排布。Processor 扫一个 chunk = 顺序 SIMD-friendly 处理 N 个 entity。

## 16.2.7 OOP 的"难度"

新人看 Mass 觉得"反直觉":
- 没有"AUnit 类"
- 状态是 Fragment 散在多个数组
- 行为是 Processor(无对象方法)

但**习惯后**:
- 数据 / 行为分离更清晰
- 性能预测容易
- 并行天然(Processor 之间 RW 不冲突可并行)

## 16.2.8 实操与下一节预告

### 实操

写一个 micro-bench 对比:

```cpp
// 创建 50K 元素
TArray<FVector> Positions;
TArray<FVector> Velocities;
const int32 N = 50000;
Positions.SetNumZeroed(N);
Velocities.SetNumZeroed(N);

// AoS 版
struct PV { FVector P; FVector V; int32 HP; };
TArray<PV> AoS;
AoS.SetNumZeroed(N);

const float DT = 0.0166f;

double T1 = FPlatformTime::Seconds();
for (int32 i = 0; i < N; ++i) Positions[i] += Velocities[i] * DT;
double SoA = FPlatformTime::Seconds() - T1;

double T2 = FPlatformTime::Seconds();
for (int32 i = 0; i < N; ++i) AoS[i].P += AoS[i].V * DT;
double AoSTime = FPlatformTime::Seconds() - T2;

UE_LOG(LogTemp, Display, TEXT("SoA: %.3fms, AoS: %.3fms"), SoA*1000, AoSTime*1000);
```

实测 SoA 通常快 2-5 倍。
