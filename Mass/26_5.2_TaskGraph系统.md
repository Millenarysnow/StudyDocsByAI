# §5.2 TaskGraph 系统源码

> **本节地图**:模块一第 5 章第 2 节。TaskGraph 是 UE 主流的"任务依赖图调度系统"。Mass Processor 调度、渲染线程命令、网络分发、AsyncTask 都跑在它上面。
>
> 但**重要变化**:**5.x 的 TaskGraph 实质上是 `UE::Tasks` 的兼容层封装**。打开 `Engine/Source/Runtime/Core/Public/Async/TaskGraphInterfaces.h:470`:
>
> ```cpp
> class FBaseGraphTask : public UE::Tasks::Private::FTaskBase
> ```
>
> TaskGraph 没消失,但底层引擎已经替换。新代码倾向直接用 `UE::Tasks`(§5.3),老代码继续用 TaskGraph 兼容接口。
>
> 这一节我们讲 TaskGraph 的**心智模型**(任务 + 依赖图 + Named Threads)和**接口**,因为引擎大量代码、文档、Mass 调度仍然用这套术语。
>
> **预备知识**:§5.1 FRunnable / 线程,§1.5 TLS / 多线程。
>
> **读完之后你能做到**:
> - 看到 `TGraphTask<>::CreateTask().ConstructAndDispatchWhenReady()` 知道发生了什么
> - 区分 `ENamedThreads::GameThread / ActualRenderingThread / RHIThread / AnyThread`
> - 用 `FGraphEventRef` 构建任务依赖图
> - 看 Insights 任务时间线,理解 worker 线程负载分布
> - 知道 Mass Processor 的并行执行底层走 TaskGraph

## 5.2.1 浅入:为什么需要"任务依赖图"

考虑一个典型并发场景:

```
[加载贴图]                   [加载模型]
    │                           │
    └──────────┬─────────────────┘
               ↓
        [上传到 GPU]
               │
               ↓
        [渲染场景]
```

四个 task,有 dependency:`上传 GPU` 等加载完,`渲染` 等上传完。

你**不能**简单用线程池:线程池是"任务独立"模型,无法表达这种 DAG。

TaskGraph 让你**直接表达 DAG**:

```cpp
auto LoadTexTask    = TGraphTask<FLoadTex>::CreateTask().ConstructAndDispatchWhenReady();
auto LoadMeshTask   = TGraphTask<FLoadMesh>::CreateTask().ConstructAndDispatchWhenReady();
auto UploadTask     = TGraphTask<FUpload>::CreateTask({ LoadTexTask, LoadMeshTask }).ConstructAndDispatchWhenReady();
auto RenderTask     = TGraphTask<FRender>::CreateTask({ UploadTask }).ConstructAndDispatchWhenReady();
```

`{ LoadTexTask, LoadMeshTask }` 是 prerequisite list。`UploadTask` 直到两个 prerequisite 都完成才被调度执行。**TaskGraph 自动管理调度**,你只声明依赖。

## 5.2.2 三个核心概念

### 5.2.2.1 Task —— 一个工作单元

每个 task 是 `FBaseGraphTask` 子类(通常通过 `TGraphTask<TTask>` 模板特化)。它有:
- `DoTask(TArray<FBaseGraphTask*>& NewTasks, ENamedThreads::Type CurrentThread)` —— 实际工作
- prerequisites 列表(谁完成后我能跑)
- subsequents 列表(我完成后谁可以跑)
- 期望执行的线程(`GetDesiredThread()`)

### 5.2.2.2 Graph Event —— 任务的"完成信号"

`FGraphEventRef` 是 task 的引用计数句柄。可:
- 加 prerequisite 给后续 task
- 用 `WaitUntilTaskCompletes` 在另一线程等它
- `GraphEvent->IsComplete()` 查询

`FGraphEventRef` = 智能指针 + 任务节点。

### 5.2.2.3 Named Thread —— "我要在哪个线程跑"

`TaskGraphInterfaces.h:54`:

```cpp
namespace ENamedThreads
{
    enum Type : int32
    {
        UnusedAnchor = -1,
        RHIThread,                                   // RHI 命令提交线程
        GameThread,                                  // 主线程
        ActualRenderingThread = GameThread + 1,      // 渲染线程
        
        AnyThread = 0xff,                            // 任意 worker(并行)
        
        // Queue / 优先级位掩码(打到高位)
        MainQueue       = 0x000,
        LocalQueue      = 0x100,
        NormalTaskPriority = 0x000,
        HighTaskPriority   = 0x200,
        NormalThreadPriority = 0x000,
        HighThreadPriority   = 0x400,
        BackgroundThreadPriority = 0x800,
        
        // 组合
        GameThread_Local = GameThread | LocalQueue,
        AnyHiPriThreadNormalTask = AnyThread | HighThreadPriority | NormalTaskPriority,
        AnyBackgroundThreadNormalTask = AnyThread | BackgroundThreadPriority | NormalTaskPriority,
        // ...
    };
}
```

**Named threads** 是**有"身份"的特定线程**,任务可指定在它上跑。**AnyThread** 是 worker pool,任务在空闲 worker 上跑。

#### 三类常用 Named Threads

| Named Thread | 用途 | 例子 |
|---|---|---|
| `GameThread` | 主线程,游戏逻辑 | `UWorld::Tick`、玩家输入处理 |
| `ActualRenderingThread` | 渲染线程 | `FScene::AddPrimitive` 等 RHI 准备 |
| `RHIThread` | RHI 提交线程 | 真正调 D3D12/Vulkan API |

#### `AnyThread` 的修饰符

```cpp
ENamedThreads::AnyThread                                    // 任意 worker,正常优先级
ENamedThreads::AnyHiPriThreadNormalTask                     // 高优先级 worker
ENamedThreads::AnyBackgroundThreadNormalTask                // 低优先级 worker(后台)
```

**Background priority** 给"我可以慢慢跑,别影响 GameThread"的任务用(资产解压、日志归档)。

## 5.2.3 写一个 Task

```cpp
class FMyTask
{
public:
    int32 InputData;
    int32 Result;
    
    FMyTask(int32 InData) : InputData(InData), Result(0) {}
    
    // ★ TGraphTask 要求的接口
    FORCEINLINE TStatId GetStatId() const
    {
        RETURN_QUICK_DECLARE_CYCLE_STAT(FMyTask, STATGROUP_TaskGraphTasks);
    }
    
    static ENamedThreads::Type GetDesiredThread()
    {
        return ENamedThreads::AnyThread;     // 跑在任意 worker
    }
    
    static ESubsequentsMode::Type GetSubsequentsMode()
    {
        return ESubsequentsMode::TrackSubsequents;   // 维护 subsequents 列表
    }
    
    void DoTask(TArray<FBaseGraphTask*>& NewTasks, ENamedThreads::Type CurrentThread)
    {
        // 真正的工作
        Result = InputData * 2;
    }
};

// 启动
FGraphEventRef Event = TGraphTask<FMyTask>::CreateTask().ConstructAndDispatchWhenReady(42);
// Event 引用一个还没完成的 task
```

### 5.2.3.1 `ESubsequentsMode`

```cpp
enum class Type
{
    TrackSubsequents,        // 默认。跟踪后续任务,可被作为 prerequisite
    FireAndForget,           // 不可被等,执行完即丢弃
};
```

`FireAndForget` 略快(省 subsequents 列表),但不能用作其它 task 的 prerequisite。日志类任务适合。

### 5.2.3.2 `GetDesiredThread` 选项

```cpp
static ENamedThreads::Type GetDesiredThread()
{
    return ENamedThreads::GameThread;        // 必须在 GameThread 跑
    // 或
    return ENamedThreads::ActualRenderingThread;
    // 或
    return ENamedThreads::AnyThread;          // 任意 worker
    // 或带优先级
    return ENamedThreads::AnyHiPriThreadNormalTask;
}
```

实战:
- 改 UObject 状态 → `GameThread`
- 渲染数据更新 → `ActualRenderingThread`
- 数学计算、SIMD、纯数据处理 → `AnyThread`

## 5.2.4 依赖图构造

### 5.2.4.1 Prerequisites(我等谁)

```cpp
FGraphEventRef A = TGraphTask<FTaskA>::CreateTask().ConstructAndDispatchWhenReady();
FGraphEventRef B = TGraphTask<FTaskB>::CreateTask().ConstructAndDispatchWhenReady();

// C 等 A 和 B 都完成
FGraphEventArray Prereqs = { A, B };
FGraphEventRef C = TGraphTask<FTaskC>::CreateTask(&Prereqs).ConstructAndDispatchWhenReady();
```

### 5.2.4.2 同步等待

```cpp
// 在调用线程阻塞,直到 task 完成
A->Wait(ENamedThreads::GetCurrentThreadIfKnown());

// 或带超时(微秒)
A->Wait(ENamedThreads::GetCurrentThreadIfKnown(), 1000);
```

**`Wait` 在 GameThread 调要谨慎** —— 阻塞主线程意味着卡帧。

### 5.2.4.3 嵌套任务(`DontCompleteUntil`)

`TaskGraphInterfaces.h:510`:

```cpp
void DontCompleteUntil(FGraphEventRef NestedTask)
```

意思:本任务在 DoTask 返回后**不**完成,要等 NestedTask 也完成。常用于"task A 启动 task B,A 的 subsequents 应该等 B 完成":

```cpp
void FParentTask::DoTask(...)
{
    // 启动子任务
    FGraphEventRef Child = TGraphTask<FChildTask>::CreateTask().ConstructAndDispatchWhenReady();
    
    // 让我的 subsequents 等 Child
    Self->DontCompleteUntil(Child);
}
```

## 5.2.5 `FGraphEvent` —— 手动 trigger 的同步原语

```cpp
FGraphEventRef Event = FGraphEvent::CreateGraphEvent();   // 创建一个无 task 的事件

// 把它作为其它 task 的 prerequisite
FGraphEventRef LaterTask = TGraphTask<FMyTask>::CreateTask({ Event }).ConstructAndDispatchWhenReady();

// 在某个时机手动 trigger
Event->DispatchSubsequents();
// 这时 LaterTask 才被允许执行
```

`FGraphEvent` 是"我要协调,但不一定有任务体"的场景。`FBaseGraphTask::CreateGraphEvent`(`TaskGraphInterfaces.h:535`)创建。

## 5.2.6 工作内幕:`QueueTask` 与调度器

`TaskGraphInterfaces.h:275`:

```cpp
virtual void QueueTask(FBaseGraphTask* Task, bool bWakeUpWorker, 
                       ENamedThreads::Type ThreadToExecuteOn,
                       ENamedThreads::Type CurrentThreadIfKnown = ENamedThreads::AnyThread) = 0;
```

每个 task 完成时,**自动**把所有 subsequents 入队到对应队列(GameThread 队列、AnyThread worker 池等)。

### 5.2.6.1 GameThread 任务执行时机

GameThread 任务**不**自动跑 —— 必须 GameThread tick 主循环里处理。`UWorld::Tick`、`FEngineLoop::Tick` 等地方有:

```cpp
// 简化伪代码
FTaskGraphInterface::Get().ProcessThreadUntilIdle(ENamedThreads::GameThread);
// 跑完所有 GameThread 队列里的 task
```

**含义**:你 dispatch 一个 `ENamedThreads::GameThread` task,它**不立刻执行**,要等 GameThread 下次 ProcessThreadUntilIdle。如果 GameThread 在等 task,task 又在等 GameThread,**死锁**。

### 5.2.6.2 RenderThread / RHIThread 同样

`ProcessThreadUntilIdle(ENamedThreads::ActualRenderingThread)` 在 RenderThread 主循环里调。RHIThread 类似。

### 5.2.6.3 AnyThread 任务由 worker 池跑

`AnyThread` task 进 worker 队列(全局共享),空闲 worker 弹出执行。Worker 数 = `FPlatformMisc::NumberOfWorkerThreadsToSpawn()`(通常物理核 - 1)。

---

## 5.2.7 worker 线程的工作模型

每个 worker 线程跑这个循环:

```cpp
void Worker::Run()
{
    while (!bShouldExit)
    {
        FBaseGraphTask* Task = WorkerQueue.PopOrSteal();
        if (Task)
        {
            Task->Execute(...);
            Task->DispatchSubsequents();      // 唤醒后续 task
        }
        else
        {
            WaitForWork();                     // 队列空,挂起
        }
    }
}
```

5.x 的 worker 池基于 `UE::Tasks::Private::FScheduler`(§5.3),实现 work-stealing(每个 worker 私有队列,空闲偷他人的活儿)。

## 5.2.8 优先级与队列

### 5.2.8.1 Task priority

```cpp
ENamedThreads::HighTaskPriority         // 高优先级:在队列前面
ENamedThreads::NormalTaskPriority       // 默认
```

队列内排序,先出高优先级 task。

### 5.2.8.2 Thread priority(worker pool)

```cpp
ENamedThreads::HighThreadPriority         // 高优先级 worker(可能少几个,只跑紧急任务)
ENamedThreads::NormalThreadPriority       // 默认
ENamedThreads::BackgroundThreadPriority   // 后台 worker
```

**Background workers** 用于"长任务,允许被抢占"。它们在 OS 层面是低优先级线程,GameThread / 高优 worker 永远先调度。

### 5.2.8.3 实战:RTS 项目的优先级建议

| Task 类型 | 优先级 |
|---|---|
| Mass Processor 主 tick | NormalTask + NormalThread |
| 战斗动画 | HighTask(必须及时) |
| 资产异步加载 | NormalTask + BackgroundThread |
| 日志归档 | NormalTask + BackgroundThread |
| 网络包处理 | HighTask |

## 5.2.9 TaskGraph 与 Mass 调度的关系

Mass `UMassProcessor` 内部,`ParallelForEachEntityChunk` 这种并行 API 底层走 TaskGraph:

```cpp
// 简化的 Mass 并行实现
void ParallelForEachEntityChunk(EntityManager, Context, Func)
{
    // 1. 找出所有匹配的 archetype chunks
    TArray<FArchetypeChunk*> Chunks = FindMatchingChunks(Query);
    
    // 2. 每个 chunk 一个 TaskGraph task
    FGraphEventArray TaskList;
    for (FArchetypeChunk* Chunk : Chunks)
    {
        FGraphEventRef T = TGraphTask<FChunkTask>::CreateTask().ConstructAndDispatchWhenReady(Chunk, Func);
        TaskList.Add(T);
    }
    
    // 3. 等所有完成
    FTaskGraphInterface::Get().WaitUntilTasksComplete(TaskList);
}
```

每个 chunk 在 `AnyThread` worker 上独立跑。50K entity / 几百个 chunk → 几百个 task → 8 worker 并行。

### 5.2.9.1 Mass Processor 间的依赖

```
PrePhysics 阶段:
   ProcessorA (TaskGraph)
        ↓
   ProcessorB (depends on A)
        ↓
   ProcessorC (depends on B)
DuringPhysics:...
PostPhysics:...
```

Processor 之间的"我读这个 fragment、你写那个"关系 → Mass 自动构建 TaskGraph 依赖,保证读写不冲突。

## 5.2.10 调试 TaskGraph

### 5.2.10.1 Insights 任务时间线

启动加 `-trace=cpu,task,frame`,Insights 主面板下方有"Tasks"sub-panel,显示每个 worker / Named thread 上的 task 块。

健康表现:
- worker 线程**几乎齐头并进**(work stealing 平衡)
- GameThread 不被某个超长 task 卡住
- 没有空白(线程一直有活儿)

### 5.2.10.2 检查 task 当前状态

```cpp
FGraphEventRef T = ...;

if (T->IsComplete()) { /* 完成了 */ }
```

**注意**:`IsComplete` 只是查询,**不阻塞**。要阻塞用 `Wait`。

### 5.2.10.3 死锁诊断

GameThread 等 task → task 等 GameThread = 死锁。

```cpp
// ❌ 死锁
FGraphEventRef T = TGraphTask<FGameThreadTask>::CreateTask().ConstructAndDispatchWhenReady();   
//                                                              ↑ 这 task 要 GameThread 跑
T->Wait(ENamedThreads::GameThread);   // 但我现在就在 GameThread,等自己
```

**修复**:`Wait` 第一参传 `ENamedThreads::GetCurrentThreadIfKnown()`,UE 内部检测到等的是当前线程会"局部 yield"——继续 process GameThread 队列直到 task 完成,而不是真正阻塞。

## 5.2.11 5.7 实情:TaskGraph 是 UE::Tasks 的兼容层

打开 `TaskGraphInterfaces.h:470`:

```cpp
class FBaseGraphTask : public UE::Tasks::Private::FTaskBase
```

`FBaseGraphTask` 继承自 `UE::Tasks::Private::FTaskBase`!这意味着:
- TaskGraph 接口仍然存在(向后兼容)
- 但实际**调度引擎**是 `UE::Tasks` 的(§5.3)
- 5.x worker 池、work stealing、优先级都是新一代实现

含义:
- 老代码(用 `TGraphTask` / `FGraphEventRef`)继续可用
- 新代码倾向直接用 `UE::Tasks::Launch` / `UE::Tasks::Pipe`
- 性能特性两者一致(都用同一调度引擎)

**实战**:看 Mass 内部调度时,你会看到 `UE::Tasks::*` API 而不是 `TGraphTask` —— 是新一代写法。但底层"任务依赖图 + worker pool" 模型完全相同。

## 5.2.12 RTS / Mass 视角下的纪律

### (1)项目代码默认用 UE::Tasks(§5.3)

新写的并发代码用 `UE::Tasks::Launch`。TaskGraph 接口仅在你**继承 / 重写引擎已有 TaskGraph 代码**时使用。

### (2)Mass Processor 内部不直接调 TaskGraph

```cpp
// ❌ 不要这样
class UMyMassProcessor : public UMassProcessor
{
    virtual void Execute(...) override
    {
        TGraphTask<FMyTask>::CreateTask().ConstructAndDispatchWhenReady();   // 太底层
    }
};

// ✅ 用 Mass 自带的并行 API
ParallelForEachEntityChunk(EntityManager, Context, [](...) { /* 处理 */ });
```

Mass 的 `ParallelForEach` 内部已经处理 TaskGraph + 等待 + 错误传播。直接用更安全。

### (3)避免 GameThread 上长 task

GameThread 是单一,一个 10ms 的 task 卡住就丢一帧。**Long task 必须**:
- 拆成多个小 task(每个 < 1ms)
- 移到 AnyThread(worker)
- 跨帧(下一帧再跑剩余)

### (4)RTS 雾战 / AI 全局计算用 TaskGraph

雾战可见性矩阵更新、玩家全局 AI 决策这些"每帧一次的中等计算":

```cpp
// 在某 Subsystem 的 Tick
FGraphEventRef FogTask = TGraphTask<FFogUpdateTask>::CreateTask().ConstructAndDispatchWhenReady();
// 不阻塞,继续 GameThread tick
// 下一帧或后续逻辑用 FogTask->IsComplete() 检查
```
