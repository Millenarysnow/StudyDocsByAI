# 整体设计哲学

为什么 LuaJourney 这样设计？

## 核心理念：逐步揭示复杂性

一个工业级 C++/Lua 绑定系统涉及的概念：

- Lua 虚拟机生命周期、栈、GC
- C 函数注册、metatable、userdata
- 类型转换双向协议
- 对象所有权、弱引用、句柄
- 对象池、缓存、内存分配器
- 模板元编程（参数包展开、SFINAE、index_sequence）
- 反射系统、代码生成
- 构建系统集成
- 热更新协议、调试钩子

如果一次性丢给你，会崩溃。LuaJourney 把它**切成 19 个小问题**，每个问题对应一个阶段：

- **只引入一个新概念**
- **只解决一个具体痛点**
- **给出一个能跑的完整代码**

---

## 原则 1：每一步都可运行

每个 `step-XX/` 目录都是一个**完整独立的工程**，有自己的：
- `CMakeLists.txt`
- `src/`（可能还有 `scripts/`）
- `README.md`（这一步的目标和原理）

你可以：
```bash
cd step-05-bind-a-class
cmake -B build -G Ninja
cmake --build build
./build/step05
```

直接看到效果。没有"跑完一整个项目才看到一个结果"。

---

## 原则 2：每一步只改一个地方

从 step-N 到 step-(N+1) 的 diff，通常是：

- 新增 1~2 个文件
- 修改 1~2 个现有文件
- 总变化 100~300 行

例外是重构型步骤（比如 step-03 引入 TypeConverter，会重写 step-02），但重构的目的永远清楚地写在 README 里。

---

## 原则 3：解释 Why，不只是 What

每个 step 的 README 包含：

1. **你在上一步看到了什么不舒服的地方？**（动机）
2. **这一步我们怎么解决？**（方案）
3. **关键代码在哪？为什么这么写？**（原理）
4. **新概念点**（知识增量）
5. **下一步会遇到什么新问题？**（预告）

---

## 原则 4：架构演进可见

同一个概念在不同阶段会**不断演化**。比如"C++ 对象传给 Lua"：

| 阶段 | 做法 |
|-----|------|
| 05 | userdata 里直接存 T* |
| 06 | 用模板展开把 T* 自动转 userdata |
| 09 | userdata 里改存 InstanceDelegate |
| 10 | Delegate 持有 Handle 而不是裸指针 |
| 11 | Delegate 从对象池取 |
| 12 | 加弱表缓存避免重复创建 |

你会**亲眼看到**同一个数据结构在不同压力下如何演化。这是读完书也学不到的。

---

## 原则 5：最终追上工业级引擎的完成度

业内成熟的商业引擎是参考终点。走完 19 步后，你应该有：

- 一个支持模板绑定的 Lua 运行时（步 06-08）
- 对象生命周期抽象（步 09-12）
- 工业级内存管理（步 13, 19）
- 自动反射代码生成（步 14-16）
- LuaJIT 集成（步 17）
- 热更新调试（步 18）

这就是工业级 Lua 系统的缩影。

---

## 什么不做

- **不做游戏逻辑**。LuaJourney 是 Lua 系统本身，不是一个引擎。你学到的东西直接搬到你自己的引擎。
- **不做全部 Lua 特性**。协程、元编程高级玩法这些不是核心，会在文档里简单提一下。
- **不做跨平台**。只保证 Windows/Linux 两个平台，Mac 基本也能过。
- **不做 C#/Python 之外的其他前端**。Frontend 架构支持扩展，但示例就两个。

---

## 怎样最高效地用它？

1. **跑每一步**。读代码不如跑代码。
2. **对比 diff**。`git diff step-05 step-06` 看清楚增量。
3. **自己动手改**。README 末尾有"挑战"，动手改。
4. **跳着读也行**。比如你已经熟悉 Lua API 了，可以直接从 step-06 开始。

---

## 学习曲线预期

```
难度
 ↑
 │                            step 18 ⋄
 │                         ╱
 │                  step 09-11 ⋄⋄⋄
 │              step 06 ⋄
 │          step 05 ⋄
 │      step 03-04 ⋄⋄
 │   step 01-02 ⋄⋄
 └─────────────────────────→ 阶段
```

前 4 步是"入门"，大约 1-2 天能过。
第 5-8 步是"理解核心"，大概 3-5 天。
第 9-13 步是"工程化"，一周左右。
第 14-19 步是"生产级"，取决于你钻研程度，一周到一个月都有可能。

---

## 从 Codecrafters 学到的：

1. **限定范围** —— 每步只解决一件事
2. **逐步放松约束** —— 早期允许粗糙，后期再优化
3. **测试可见** —— 每步都有可见产物
4. **文档和代码同等重要** —— README 不是附属，是核心材料
